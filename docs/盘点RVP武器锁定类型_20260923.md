# 当前RVP武器可用锁定类型有几种？他们的作用和游戏内表现如何？

如果你说的是武器 JSON 里的 `guidance_data.guidance_type`，当前结论是：

- 配置层公开了 **16 个值**。
- 真正具有可运行制导逻辑的有 **12 种**。
- 再算上 `NONE` 无制导状态，共 **13 种可正常运行状态**。
- `MCLOS`、`TV`、`ATV` 目前只是占位，运行时会直接判定制导失败。
- `IOG` 是内部历史枚举，新配置会加载报错。

## 当前实际可用的12种制导

| 类型           | 作用                                                         | 游戏内表现                                                   |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `IR`           | 发射前红外锁定，跟踪目标实体；也可作为末制导                 | 显示红外大导引头圈；锁定后目标圈变红并持续播放锁定音。可启用 IR HMD 头瞄大离轴锁定。目标会收到红外导弹告警；热焰弹、烟雾、DIRCM可以造成脱锁或偏转。 |
| `AIR`          | 名义上是发射后开机的主动红外末制导                           | 导引头进入开机距离后自主搜索，HUD 目前画雷达式小双圈，但目标收到的是红外告警。需要特别注意：当前代码的自主搜索走了雷达目标/箔条扫描，而反制和告警又按红外处理，属于“雷达搜索＋红外告警/热焰反制”的混合现状，疑似需要后续纠正。 |
| `SARH`         | 半主动雷达制导，需要发射载具或外置雷达持续照射目标           | 必须保持手动雷达硬锁；TWS 自动航迹不算照射。HUD 有雷达小双圈及双绿色实心硬锁框。载机丢锁、主动 ECM 阻断照射后，导弹失去制导；箔条可诱骗。 |
| `ARH`          | 主动雷达制导；前段接受指定目标，进入开机距离后弹载雷达自主捕获 | 典型“发射后不管”主动弹。导引头开机会给射手动作栏提示；目标收到雷达制导导弹告警。HUD 为雷达小双圈，雷达硬锁时有双绿色框。受箔条、主/被动 ECM 和目标 RCS 影响。 |
| `ARM`          | 反辐射制导，搜索工作中的雷达或主动 ECM 辐射源                | 可以发射前预选雷达，也可发射后自主抓辐射源；雷达停机后会向最后已知位置飞一段时间。HUD 使用 ARM 自有绿色离轴框，预选时显示红色双小圈。主动 ECM 可能成为更高优先级诱饵。 |
| `GPS`          | 飞向预先写入的世界坐标                                       | 不锁定实体、不会追随移动目标，也没有导引头圈。通常由目标指示吊舱或系统写入 GPS 点；可设置散布，并可做上升—巡航—俯冲弹道。到目标约 5 格内停止继续制导。 |
| `LH`           | 跟踪载具激光器实时照射点                                     | 玩家需要持续打开激光并把照射点放在目标上；导弹跟随世界照射点。没有普通实体锁定圈，被照射载具会出现激光告警，烟雾可阻断。 |
| `SALH`         | 半主动激光制导                                               | 名义上表示跟踪目标反射的激光点，但当前运行代码与 `LH` 共用同一个照射点逻辑，因此实际游戏表现基本相同。必须持续照射，失去有效照射点就失导。 |
| `LBR`          | 激光驾束，导弹努力保持在操作手瞄准光束中心                   | 玩家只要持续把准星压在目标上，导弹便不断向光束中心修正。它不吸附锁定实体，移动鼠标会直接带动光束和弹道。文档还写着“预留”，但当前运行时已经实现。 |
| `SACLOS`       | 半自动视线指令制导                                           | 玩家持续用准星跟踪目标，导弹根据武器站瞄准线飞行；没有寻的器锁定圈。可配置弹性修正与轻微摆动，表现为导弹逐渐压回瞄准线。它不属于激光照射，因此不会产生激光告警。 |
| `HITL_TV`      | 人在回路电视指定制导，可指定实体或地面点                     | 发射后进入导弹电视画面，可使用彩色、黑白或热像模式并重新指定目标。退出视角后，导弹继续追踪最后实体或最后指定点。移动实体可能因速度过高脱锁；烟雾、DIRCM和无线电遮挡可干扰。目标会收到电视制导导弹告警。 |
| `HITL_CLOS_TV` | 人在回路电视鼠标直控/指令线制导                              | 玩家从导弹视角用鼠标虚拟摇杆直接控制弹体转向，不是点一下目标后自动追踪。具有控制距离、控制超时、无线电/光纤链路和视频模式；可配置右键提前引爆。DIRCM干扰时画面会出现白闪并暂时失控。 |

## 公开但目前不能真正使用的3种

| 类型    | 当前状态                                                     |
| ------- | ------------------------------------------------------------ |
| `MCLOS` | 文档定义为人工指令线制导，但运行时注册的是“不支持”实现；需要这种玩法应使用 `HITL_CLOS_TV`。 |
| `TV`    | 普通电视寻的占位；当前不会产生有效制导意图。应使用 `HITL_TV`。 |
| `ATV`   | 主动电视末制导占位。虽然允许写进 `terminal_guidance`，但运行时尚未实现，实际会失导。 |

另外，`NONE` 表示完全无制导，通常就是按初始弹道直飞；只有启用惯性制导并已有最后目标点时，才会继续向记忆点飞。

这里还有一个容易混淆的概念：`fire_control_sensor_type_override` 的 `none/ir/rf/eo/loc/ccip` 是 **6种武器站火控传感器模式**，不是导弹制导类型；`fire_data.require_lock` 才决定开火前是否必须有锁。也就是说，GPS、SACLOS、HITL 等即使能制导，也不一定属于传统意义上的“先锁后射”。

# `fire_control_sensor_type_override` 的 `none/ir/rf/eo/loc/ccip`  **6种武器站火控传感器模式**  。

`fire_control_sensor_type_override` 决定的不是“弹体采用什么制导”，而是：

> 当这件武器被选中时，所属 `WeaponUnit` 用哪套火控逻辑取得射前目标、坐标或弹着点，并采用哪套HUD反馈。

字段不写时继承武器站自身的静态传感器类型；写入后会随当前武器切换而动态替换。同一武器站可以因此做到“切红外弹变 IR、切半主动雷达弹变 RF、切炸弹变 CCIP”。

```
{
  "fire_control_sensor_type_override": "rf"
}
```

## 六种模式总览

| 模式   | 火控处理对象              | 能否锁实体 | 主要HUD                                  | 常见用途                     |
| ------ | ------------------------- | ---------- | ---------------------------------------- | ---------------------------- |
| `none` | 无专用传感器              | 否         | 普通准星                                 | 机炮、无制导弹、独立指令制导 |
| `ir`   | 红外可见实体              | 是         | 红外导引头圈、红色目标圈、锁定音         | IR 导弹                      |
| `rf`   | 雷达航迹实体              | 是         | 雷达航迹框、双绿色硬锁框、雷达导引头双圈 | SARH、ARH、雷达机炮          |
| `eo`   | 光学瞄准线上的实体/世界点 | 是         | 绿色光电锁定框、观瞄准星                 | 激光弹、电视弹、光电反坦克弹 |
| `loc`  | 玩家输入的固定坐标        | 否         | 坐标装订反馈                             | GPS、巡航弹、远程坐标打击    |
| `ccip` | 实时预测的弹着点          | 否         | 地面弹着点准星                           | 无制导炸弹、火箭弹           |

------

## `none`：关闭专用火控传感器

### 作用

`none` 表示当前武器不启用 IR、RF、EO、LOC 或 CCIP 中的任何一种专用处理。

它不会：

- 自动搜索红外目标；
- 从雷达航迹中选目标；
- 用瞄准线抓取光电目标；
- 要求输入坐标；
- 计算并显示 CCIP 弹着点。

但普通武器站瞄准、炮塔转动、准星、射线弹着点以及武器站自身的 `focus_locker` 仍可能工作。`none` 不是“关闭整个武器站”。

### 游戏内表现

- 没有红外导引头圈；
- 没有雷达航迹和雷达硬锁框；
- 没有 EO 绿色目标框；
- 没有坐标输入要求；
- 没有 CCIP 落点圈；
- 仍显示普通准星和武器自身HUD。

### 适用武器

- 普通机炮；
- 无制导火箭；
- 无制导导弹；
- SACLOS、LBR、HITL_CLOS_TV 等自己管理瞄准线/控制链的武器；
- 不希望继承武器站原有雷达或红外模式的武器。

### 注意

显式写 `"none"` 和“不写字段”不同：

- 不写：继承武器站配置；
- 写 `none`：主动压掉武器站原来的传感器。

如果导弹同时配置了：

```
"fire_data": {
  "require_lock": true
}
```

却又将传感器设为 `none`，通常会出现没有渠道取得实体锁、因而无法发射的问题。指令制导、GPS等不需要射前实体锁的武器通常应设 `require_lock: false`。

------

## `ir`：红外火控

### 作用

`ir` 让武器站按红外导引头逻辑搜索和保持目标。

普通流程是：

1. 玩家开启导引头；
2. 等待锁定冷却；
3. 在导引头视场、距离、高度及视线范围内搜索目标；
4. 选择最接近导引头中心线的有效实体；
5. 将目标写入 `WeaponUnit.lockedEntity`；
6. 发射时把这个目标传给导弹。

本体红外搜索有约 512 格基础搜索上限；RVP还会继续应用武器自己的距离、高度、离轴角和视场配置。

### 游戏内表现

- 导引头开启后显示较大的 IR 搜索圈；
- 未锁定时，圈位于当前导引头瞄准位置；
- 锁定成功后目标位置出现红色圆圈；
- 播放持续锁定音；
- 目标移动时，火控和武器站会尝试继续跟踪；
- 被地形、视觉遮挡物或烟雾挡住后可能脱锁；
- 若武器启用了 IR HMD，头瞄捕获由RVP独立通道处理，锁定圈可出现在较大离轴范围内。

### 适用武器

- 发射前锁定的红外空空弹；
- 红外反坦克弹；
- 红外对地导弹；
- 要求传统“开导引头—等待锁定—发射”的武器。

### 与 `EO` 的特殊关系

RVP允许部分 IR 武器配置成 `eo` 而不是 `ir`。条件是：

- 武器本身是 IR 发射武器；
- `enable_ir_hmd` 关闭；
- 有效传感器为 `EO`。

这时按火控锁定键，RVP仍会使用 IR 锥形搜索取得目标，而不是普通 EO 的单条视线点击。现有 YJ-80 一类武器就使用这种设计。

因此：

- `ir` 更偏向传统自动红外导引头模式；
- `eo + IR guidance` 更偏向操作手通过光电瞄具触发红外捕获。

------

## `rf`：雷达火控

### 作用

`rf` 让武器站使用关联的 `RadarUnit` 航迹表进行发现、选择和锁定。

它区分两种状态：

- 软跟踪/TWS：雷达已经发现目标，并可能给 ARH 提供中段目标更新，但不代表玩家建立了硬锁；
- 硬锁/STT：玩家按火控锁定键明确选择目标，目标被写入 `RadarUnit.lockedEntity`。

RVP的 SARH 特别要求手动硬锁或外置雷达硬锁；单纯TWS扫到目标不算持续照射。

### 游戏内表现

- 已发现目标显示绿色角框；
- 航迹可显示距离、接近率、速度线和敌我信息；
- 硬锁目标显示内外两层绿色实心方框；
- 雷达导引头开启时显示小型双圆圈；
- 建立雷达硬锁后，被锁载具会收到雷达锁定告警；
- ARH可以使用TWS软跟踪完成中段引导；
- SARH必须保持雷达硬锁；
- 支持外置雷达航迹和外置雷达锁定。

### 适用武器

- `SARH` 半主动雷达导弹；
- `ARH` 主动雷达导弹；
- 需要雷达预选的 ARM；
- 雷达炮瞄或需要提前量解算的机炮；
- 需要外置雷达提供目标的武器。

### 必要条件

`rf` 只改变火控路由，**不会凭空给载具增加雷达**。武器站或载具必须实际关联有效 `RadarUnit`，否则会出现：

- 没有雷达航迹；
- 无法建立硬锁；
- SARH无法取得照射目标；
- RF HUD空白。

此外，RVP机炮的软吸附、提前量和火控稳定模式还要求武器站额外配置 `rvp_fire_control_mode: rvp_rf` 或 `rvp_ballistic_lead`；仅写传感器 `override: rf` 不会自动启用全部机炮高级火控。

------

## `eo`：光电火控

### 作用

`eo` 即 Electro-Optical，按玩家当前光学瞄准线获取目标。

普通 EO 锁定不是在一个大锥体内自动找最近目标，而是：

1. 从光学观瞄位置出发；
2. 沿玩家当前瞄准方向发射检测射线；
3. 锁定射线首先命中的有效实体；
4. 后续持续检查目标和观瞄之间是否被方块或视觉遮挡物隔断。

这使它更接近“准星压住目标后按锁定键”。

### 游戏内表现

- 按火控锁定键后，准星下的实体被选中；
- 锁定目标显示绿色方框；
- 武器站会持续朝目标中心跟踪；
- 目标被山体、建筑或视觉遮挡物挡住后脱锁；
- 不产生雷达锁定告警；
- 不显示雷达航迹表；
- 本身没有IR锁定音，除非当前武器通过RVP特殊逻辑同时作为IR捕获武器。

### 适用武器

- 激光制导导弹、炸弹；
- 电视制导武器；
- 光电反坦克导弹；
- 对地导弹；
- 需要玩家通过光学观瞄选择实体的武器。

### 需要特别区分

`eo` 只表示火控选择渠道，不等于自动开启激光，也不等于弹体采用电视制导。

例如：

```
"fire_control_sensor_type_override": "eo",
"guidance_data": {
  "guidance_type": "SALH"
}
```

含义是：

- EO负责玩家怎么瞄准/选目标；
- SALH负责导弹发射后怎么跟踪激光照射点。

两者是上下游关系。

RVP的射击门控还对非IR的 EO 武器提供了无实体锁豁免，因此激光点、世界点等工作流可以在没有 `lockedEntity` 的情况下发射。IR武器若 `require_lock: true`，则仍须取得有效IR目标。

------

## `loc`：坐标装订火控

### 作用

`loc` 即 Location。它不锁定实体，而是让玩家输入一个固定的世界坐标。

本体流程是：

1. 按“预设坐标输入”键，默认键位为 `N`；
2. 打开坐标输入界面；
3. 初始值取当前瞄准射线落点，玩家可以修改；
4. 保存为该武器的 `targetLocation`；
5. 发射时把固定坐标写入瞄准上下文。

如果没有预设坐标，武器会拒绝发射并提示先输入坐标。

### 游戏内表现

- 不显示红外圈、雷达框或 EO 实体框；
- 按坐标输入键弹出坐标设置界面；
- 未装订坐标时按开火键会提示缺少预设坐标；
- 装订后，武器以固定世界位置为目标；
- 目标不会随载具或实体移动。

### 适用武器

- GPS导弹；
- GPS制导炸弹；
- 巡航导弹；
- 远程火箭炮；
- 预先规划坐标的弹道导弹。

### 注意

`loc` 只负责“得到一个坐标”，不会自动让弹体追踪坐标。弹体仍需配置：

```
"guidance_data": {
  "guidance_type": "GPS"
}
```

反过来，GPS武器也不一定必须使用 `loc`：RVP还可以通过目标指示吊舱、战术地图或专用GPS状态写入目标点。

------

## `ccip`：连续计算弹着点

### 作用

`CCIP` 是 Continuously Computed Impact Point，即连续计算弹着点。

它不锁定敌人，而是根据当前状态实时预测：

- 出弹位置；
- 炮口方向；
- 弹体初速；
- 载具速度继承；
- 重力；
- 阻力；
- 地形碰撞；
- 弹体种类和RVP弹道参数。

载具速度、俯仰、滚转或高度变化时，预测落点也会立即移动。

### 游戏内表现

- HUD在预计命中地面的位置绘制绿色弹着点准星；
- 俯冲角增大时落点向近处移动；
- 平飞或速度提高时落点向远处移动；
- 准星落到目标上只是“按当前状态预计会打中”，不是目标锁定；
- 发射后弹药仍按真实弹道飞行，不会因为CCIP准星而自动转向。

### 适用武器

- 无制导航空炸弹；
- 火箭巢；
- 榴弹、低速炮弹；
- 需要弹道落点预测但不需要实体锁定的武器。

RVP炸弹会使用自己的初速、重力、阻力和载具速度继承参数计算CCIP，不会简单套用本体固定炸弹公式。RVP火箭也有单独的弹道CCIP显示。

### 与GPS的区别

- `CCIP`：预测“现在投放会落在哪里”；
- `LOC/GPS`：指定“我要弹药飞去哪里”。

CCIP是瞄准辅助，GPS是目标装订和制导。

## 与 `guidance_type` 的推荐搭配

| 弹体制导           | 常见传感器                | 说明                                                   |
| ------------------ | ------------------------- | ------------------------------------------------------ |
| `NONE` 机炮/直射弹 | `none`                    | 普通直射                                               |
| `NONE` 炸弹/火箭   | `ccip`                    | 用预测落点辅助投放                                     |
| `IR`               | `ir`、`eo`                | 传统导引头用IR；光电瞄具触发捕获可用EO                 |
| `IR` + HMD         | `none`、`rf`、`eo` 均可能 | HMD有独立捕获通道，传感器取决于是否还需要雷达/光电辅助 |
| `SARH`             | `rf`                      | 必须保持雷达硬锁照射                                   |
| `ARH`              | `rf`                      | 雷达TWS中段更新，末端弹载雷达自锁                      |
| `ARM`              | `rf` 或 `none`            | RF用于雷达预选；允许自主搜源时也可不用传统锁定         |
| `GPS`              | `loc`、`ccip`、`eo`       | 取决于目标点来自坐标输入、投放预测还是光电/吊舱        |
| `LH` / `SALH`      | `eo`                      | 光电瞄准并持续激光照射                                 |
| `LBR` / `SACLOS`   | `eo` 或 `none`            | 玩家持续保持瞄准线，不依赖实体寻的锁                   |
| `HITL_TV`          | `eo`                      | 光电指定实体或世界点                                   |
| `HITL_CLOS_TV`     | `none` 或 `eo`            | 发射后由玩家在弹载画面中直接控制                       |

这只是推荐组合，不是代码自动推断。RVP不会看到 `guidance_type: ARH` 就自动把火控改成 `rf`。

## 与 `require_lock` 的关系

这两个字段相互独立：

```
fire_control_sensor_type_override
        ↓
如何取得目标/坐标/HUD走哪套逻辑

fire_data.require_lock
        ↓
没有满足锁定条件时是否禁止发射

guidance_data.guidance_type
        ↓
弹体离架后如何飞行
```

常见错误包括：

- `sensor: none + require_lock: true`：无目标来源，导弹不能发射；
- `sensor: rf` 但载具没有雷达：没有航迹，无法锁定；
- `sensor: ccip + guidance: GPS`：CCIP只预测当前落点，不会自动写入GPS目标；
- `sensor: eo + guidance: SALH` 但没开启激光：能瞄准，但导弹得不到激光照射点；
- `sensor: ir` 配给非IR弹：会出现IR火控HUD，但不会把弹体变成红外制导。

## `eo_ccip` 不是第七种枚举

项目还有独立字段：

```
"rvp_fire_control_sensor_mode": "eo_ccip"
```

它是组合模式：

- 普通/第三人称视角：按 `CCIP` 工作；
- 进入 `SCOPE` 观瞄：按 `EO` 工作；
- 退出观瞄：恢复 `CCIP`；
- 服务端统一按 `CCIP` 处理。

适合既需要外部HUD弹着点、又需要开镜光电观瞄的对地武器。

不建议同时配置 `eo_ccip` 和 `fire_control_sensor_type_override`。RVP辅助解析会优先返回 `eo_ccip` 的动态结果，而本体部分消费点又可能直接读显式 override，容易让不同系统看到不同传感器类型。

当前权威载具包里，显式覆盖实际主要使用：

- `eo`：YJ-80、AGM-65、激光弹药等；
- `rf`：AIM-7P、R-27R、YJ-91等；
- `ccip`：Mk84等无制导投弹；
- `none/ir/loc` 当前没有发现显式武器级示例，但仍可用，也可能由武器站静态配置提供。

# RVP的火控传感器

  严格来说，RVP并没有另外定义一套“RVP火控传感器枚举”。上一条的 `none/ir/rf/eo/loc/ccip` 确实是本体 `ywzj_vehicle` 的枚举；RVP复用它，然后在上面增加动态覆盖、复合模式、软火控和独立锁定通道。

可以理解成三层：

```
本体传感器类型
NONE / IR / RF / EO / LOC / CCIP
              ↓
RVP武器级覆盖与复合模式
fire_control_sensor_type_override / eo_ccip
              ↓
RVP高级火控
rvp_rf、HMD、外置雷达、GPS装订、ARM预选等
```

## 一、RVP武器级火控字段

### 1. `fire_control_sensor_type_override`

这是RVP提供的“按当前武器动态覆盖本体传感器”功能，但值仍然使用本体六种枚举。

```
"fire_control_sensor_type_override": "rf"
```

作用是：同一个武器站切换不同RVP武器时，传感器类型随武器变化。

例如一个复合挂架可以实现：

- 切 AIM-7P：覆盖成 `rf`；
- 切红外弹：覆盖成 `eo` 或 `ir`；
- 切 Mk84：覆盖成 `ccip`；
- 切指令制导弹：覆盖成 `none`。

所以它是RVP功能，但不是RVP新定义的传感器种类。

### 2. `rvp_fire_control_sensor_mode`

这是RVP自己定义的武器级复合模式。目前真正公开使用的只有：

| 值        | 行为                                     |
| --------- | ---------------------------------------- |
| 空/不写   | 不启用复合模式                           |
| `eo_ccip` | 普通视角使用CCIP，进入观瞄视角后切换为EO |

示例：

```
{
  "fire_control_sensor_type_override": "eo",
  "rvp_fire_control_sensor_mode": "eo_ccip"
}
```

游戏内表现：

- 第三人称、驾驶员视角：持续显示弹着点；
- 进入 `SCOPE`：关闭CCIP表现，改用光电观瞄；
- 退出 `SCOPE`：恢复CCIP；
- RVP炸弹使用自己的速度、重力、阻力计算落点。

现有 `j10c_gb3_ir`、`j10c_gb3_laser`、`lavad_hydra70` 都在使用这个模式。

从“RVP自己新增的武器级传感器模式”这个口径看，目前其实只有 **1种：`eo_ccip`**。

------

## 二、RVP武器站级火控模式

### `rvp_fire_control_mode`

它写在载具的武器站部件中，而不是武器JSON里。

目前支持：

| 值                   | 含义                                                         |
| -------------------- | ------------------------------------------------------------ |
| 空/不写              | 使用本体默认火控                                             |
| `rvp_rf`             | 启用RVP雷达火控：机炮提前量、RVP导弹硬锁三态跟踪与其他武器软修正，仅RF传感器生效 |
| `rvp_ballistic_lead` | 为RVP机炮启用通用弹道提前量火控，可消费IR、EO或RF实体锁定目标 |

示例：

```
{
  "fire_control_sensor_type": "rf",
  "rvp_fire_control_mode": "rvp_rf",
  "rvp_rf_off_axis_deg": 10
}
```

`rvp_rf` 生效还要求当前有效传感器为 `RF`。当前选中武器为RVP导弹时，三态只消费本车或外置雷达的正式硬锁，不把TWS/导引头软航迹当成自动跟踪授权。

通用弹道提前量火控示例：

```
{
  "fire_control_sensor_type": "eo",
  "rvp_fire_control_mode": "rvp_ballistic_lead",
  "rvp_fire_control_off_axis_deg": 10
}
```

`rvp_ballistic_lead` 还要求当前选中武器为RVP `machinegun`。模式自身不搜索目标、不改变锁定规则，也不自动开火；它消费本体IR、EO或RF传感器已经建立的实体锁定，并将炮塔辅助中心切换到按真实弹道参数计算出的预瞄点。

它主要增加：

- 雷达目标软跟踪；
- 机炮运动目标提前量解算；
- 提前量瞄准标记；
- 武器站向提前量点修正；
- 火控稳定器三态切换；
- 离轴辅助限制；
- 雷达硬锁、TWS软跟踪和普通瞄准之间的状态区分。

火控稳定器三种状态是：

| 状态        | 表现                                             |
| ----------- | ------------------------------------------------ |
| `STABLE`    | 机炮严格跟随弹道预瞄点；RVP导弹严格跟随雷达硬锁目标中心 |
| `SEMI_AUTO` | 机炮与RVP导弹都使用“移动基准方向＋玩家局部双轴偏置”锁存跟随；其他 `rvp_rf` 武器保留旧软修正 |
| `OFF`       | 关闭RVP自动瞄准辅助，由玩家直接操纵 |

`rvp_rf_off_axis_deg` 控制 `rvp_rf` 允许火控辅助介入的离轴范围，默认 `10°`；机炮有效解算沿用历史的 `0.1` 倍缩放，RVP导弹双轴锁存按原值生效。`rvp_fire_control_off_axis_deg` 控制 `rvp_ballistic_lead` 的离轴范围，默认 `10°`，按配置原值生效。

目前 Buk-M3、CSSA-5、IRIS-T SLM TEL、铠甲-S1等武器站在使用 `rvp_rf`；因此它们选中RVP导弹时均获得上述完整三态。SACLOS/LBR导弹仍沿操作手视线制导，火控只负责转动该视线，不向弹体注入实体寻的目标。

因此，从“RVP自己新增的武器站火控模式”口径看，目前有 **2种**：RF专用的 `rvp_rf`，以及传感器解耦、机炮专用的 `rvp_ballistic_lead`。两者内部复用同一个通用火控执行器。

当前Mi-28的2A42与AH-64的M230在根观瞄武器站配置 `rvp_ballistic_lead`，继续使用各自的EO实体锁定链。

## 三、RVP雷达角色

RVP还给雷达部件增加了 `radar_role`。它不是传感器模式，而是解决一台载具有多部雷达时“谁负责搜索、谁负责锁定”。

| 角色           | 搜索 | 锁定     | 用途                         |
| -------------- | ---- | -------- | ---------------------------- |
| `all`          | 是   | 是       | 普通一体化雷达，默认值       |
| `search`       | 是   | 否       | 搜索雷达、预警雷达、搜索中继 |
| `fire_control` | 是   | 是，优先 | 火控雷达、照射雷达           |

例如一套防空系统可以配置：

```
搜索雷达 radar_role=search
    ↓ 提供远距离航迹
火控雷达 radar_role=fire_control
    ↓ 目标进入火控扇区后建立硬锁
SARH/ARH武器获得发射与制导条件
```

具体表现：

- 搜索雷达可以发现目标，但不能形成最终硬锁；
- 玩家要求锁定后，如果火控雷达暂时没扫到目标，会进入 pending 状态；
- 目标进入火控雷达扇区后，pending升级为真正硬锁；
- `fire_control` 雷达优先承担锁定；
- 不会错误地让搜索雷达绕过火控雷达的方位、高度或扇区限制；
- SARH只认可真正的手动/外置雷达硬锁，不认可普通搜索航迹。

## 四、RVP独立火控通道

下面这些也是RVP火控系统的一部分，但都不是 `FireControlSensorType` 枚举值。

### IR HMD

- 由当前IR武器的 `enable_ir_hmd` 控制；
- 使用玩家头部/视角方向扫描；
- 有独立IR锁定目标和锁定圈；
- 必须通过距离、高度、LOS和离轴终检；
- 不依赖武器站静态配置为 `IR`；
- 因此PL-10所在武器站即使是 `NONE`，仍可通过IR HMD锁定。

### Radar HMD

- 使用头瞄方向从雷达已经发现的航迹中捕获目标；
- 捕获成功后建立真正雷达硬锁；
- 若当前选择的是IR HMD武器，还会把同一目标交给IR通道确认；
- 雷达HMD和IR HMD可以同时开启。

### 外置雷达火控

分成两种：

- 搜索中继：只共享航迹，不提供最终发射授权；
- 火控中继：可以提供外置硬锁，供SARH、ARH等武器使用。

外置锁会作为本机雷达锁的补充，但仍受雷达角色和武器要求限制。

### GPS火控

当前武器为GPS制导时，RVP会接管火控锁定键：

- 对玩家瞄准位置做地形射线；
- 设置GPS目标点；
- 不调用普通 `WeaponUnit.fireControlLock()`；
- 支持单点/多点GPS模式；
- 目标是坐标，不是实体锁。

所以RVP GPS并不一定依赖本体 `LOC` 模式。

### ARM预选

ARM使用自己的辐射源预选链：

- 玩家预选雷达辐射源；
- 记录载具ID、雷达索引和最后已知位置；
- `require_lock: true` 时要求存在ARM预选；
- 发射后在预选独占窗口内优先攻击该辐射源；
- 主动ECM仍可能以高优先级诱骗ARM。

它也不是普通RF实体锁。

### 激光/视线指令通道

包括：

- `LH`、`SALH`：激光照射点；
- `LBR`：驾束轴线；
- `SACLOS`：操作手视线；
- `HITL_TV`：实时指定实体/世界点；
- `HITL_CLOS_TV`：弹载视角鼠标直控。

这些模式通常借助 `EO` 提供观瞄界面，但真实制导目标由RVP自己的照射点、视线或控制链维护。

## 最准确的数量结论

如果问“RVP目前有几种自己的火控传感器类型”，答案是：

- **独立传感器枚举：0种**，RVP复用本体六种枚举；
- **武器级RVP复合传感器模式：1种**，即 `eo_ccip`；
- **武器站级RVP高级火控模式：1种**，即 `rvp_rf`；
- **雷达角色：3种**，`all/search/fire_control`；
- 另外有 IR HMD、Radar HMD、外置雷达、GPS、ARM、激光/指令制导等独立火控通道，它们不是传感器枚举。

也就是说，`fire_control_sensor_type_override` 不是“RVP火控传感器类型表”，而是RVP用于动态选择本体六种传感器的桥梁。RVP真正新增的是围绕这些传感器构建的复合模式和锁定通道。
