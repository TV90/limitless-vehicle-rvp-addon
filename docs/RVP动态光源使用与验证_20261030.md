## 1. 已实现的功能

爆炸、载具成功开火和火箭发动机共用一套屏幕光管理器。屏幕光是在世界画面已经生成后，按深度找出可见表面，再给这些表面叠加有颜色的光；它不改变 Minecraft 的方块光等级。

- 默认爆炸从白热偏黄快速过渡到橙红，随年龄衰减。核爆等很大的伤害半径不会变成无限大的屏幕光，自动视觉半径上限为 32 格。
- 成功开火沿用本体 `ServerVehicleFire → VehicleFireEvent.Post` 广播，追踪载具的远端客户端也能看到。没有增加开火网络包。炮口烟和光共用 `RVP_FiringMuzzleResolver`，按真实齐射/轮射炮口和类型化口径计算。
- 发动机按弹体 UUID（每枚实体的唯一标识）保留一盏持续光，和粒子数量无关。喷口使用 `projectile_data.engine_nozzle_offset` 和现有模型相同的俯仰/朝向变换；本地使用插值位置，远端使用克隆的渲染位置。二脉冲阶段更暖、更弱，一级保持最亮，环境光与广域光晕半径保持口径规则。
- 上轮圆形喷口核心与发光气团保留但暂停，当前改用 RVP 自有定向收尖喷流，纯天空中可见；不依赖附近墙面或空气散射开关。一级原始 HDR 峰值仍为 **60000**，核心达到显示白点，周围保持橙色光晕。HDR 指显卡内部可保存高于普通画面亮度的数值，不是 Minecraft 的方块光等级。
- 本地燃尽、实体移除和世界卸载立即取消持续光；远端必须有不超过 10 tick 的有效燃烧快照，快照的剩余燃烧时间也必须尚未耗尽。没有新心跳的持续光最多保留 2 tick。
- 同源连射在代码规定的窗口内只更新/续期，不累加亮度；匿名的相邻同类爆炸也会合并。内存最多保留 128 条，提交显卡最多 8 盏，可进一步调低。
- 无可见活动环境光及程序喷焰时，不复制场景。新喷焰使用独立预算与可见范围，环境光总开关、距离和八灯限制不取消弹体喷焰视觉。
- 可选 Bloom：仅提取本系统灯光的亮部，半分辨率横向、纵向各做一次加宽模糊，再合成。提取门槛从 0.55 降到 0.08，0.04 的平滑过渡接上较弱的橙色边缘；合成强度从 0.22 提到 2.0，并保持光晕色相。Bloom 是亮部扩散形成的光晕，可以整体关闭或逐光源关闭；关闭后喷口核心仍能保持高亮。
- 可选空气散射：沿相机射线穿过球形光体的可见部分做 12 点积分。默认关闭；这是简化的均匀介质雾光，没有读取烟尘粒子的实际密度，不是烟雾自阴影或完整光线追踪。
- P5 真实方块光已固定关闭：爆炸、重炮、发动机都不会创建新的不可见光源方块。保留上轮临时光源的安全恢复逻辑。

## 2. 客户端画质和 P5 关闭状态

客户端首次正常启动后，Forge 生成 `config/ywzj_rvp-lighting-client.toml`。屏幕空间光**逐项**可开关，默认值与代码现状一致（只有空气散射默认关闭）：

```toml
# 总开关：关闭后照亮、光晕、白热核心、天空散射与烟雾受光全部不绘制
screenLight = true
explosionLight = true    # 爆炸照亮（表面受光）
muzzleLight = true       # 炮口照亮
engineLight = true       # 发动机照亮（只控表面受光）
explosionCore = true     # 爆炸白热核心
explosionHalo = true     # 爆炸广域光晕（需要 bloom）
skyScatter = true        # 天空散射
smokeLight = true        # 烟雾与炮口特殊贴图受光
plume = true             # 程序喷焰（独立通道，不受八灯预算/距离限制）
# 通道级总开关与预算
bloom = true
missileHalo = true       # 发动机广域橙晕（只控外圈，不再控表面照亮）
eoJammerGlow = true      # 光电干扰机玻片夜间红光
volumetric = false       # 空气散射（默认关闭）
maxLights = 8
maxDistance = 5012.0
intensity = 1.0
airBurstClearance = 100.0   # 爆炸光源离地门槛（格），0 = 不限制
```

| 开关 | 关闭后的效果 |
|---|---|
| `screenLight` | 整个屏幕光层不绘制（所有分项一起失效）；粒子、喷焰、声音照常 |
| `explosionLight` / `muzzleLight` / `engineLight` | 只停对应来源对环境（地面/墙面/实体/烟雾）的照亮 |
| `explosionCore` | 只去掉炸点白热核心，照亮与光晕保留 |
| `explosionHalo` | 只去掉爆炸世界空间光晕；仍需 `bloom=true` 才有光晕 |
| `skyScatter` | 天空像素完全不受爆炸光影响 |
| `smokeLight` | 烟雾与炮口贴图不再接收环境光 |
| `plume` | 程序喷焰不绘制，回到旧尾焰粒子；核心喷焰灯光仍按 `engineLight`/`missileHalo` 决定 |
| `bloom` | 所有光晕/橙晕消失，基础照亮保留 |
| `missileHalo` | 只去掉发动机广域外圈橙晕与它的模糊来源，发动机表面照亮由 `engineLight` 控制 |
| `eoJammerGlow` | 干扰机玻片完全保持原贴图 |
| `volumetric` | 关闭球形空气散射（默认就是关） |
| `airBurstClearance` | 不是开关：爆炸屏幕光源的离地高度门槛（格），默认 100，0 = 不限制；服务端只下发离地高度，判定在本机 |

分项开关全关的灯不会占用八灯预算槽位，也不做遮挡查询；`/rvplight` 的会话开关只对 `screenLight`、`bloom`、`missileHalo` 这三个总开关生效，分项开关只读 TOML；`airBurstClearance` 既读 TOML，也可用 `/rvplight set global airBurstClearance` 会话覆盖。

`maxLights` 范围 0～8，0 关闭。`intensity` 范围 0～2，0 关闭。`airBurstClearance` 范围 0～32768 格、默认 100，允许小数（如 12.5）。距离单位为格，`maxDistance` 范围 16～32768、默认 5012（旧配置文件不会自动迁移，需要手动改成同一数值）。低配置可先把灯数调至 4、关闭 `bloom`，不影响现有尾焰、烟尘和声音。

P5 由 `RVP_LightingConfig.P5_ENABLED=false` 在 Java 中固定关闭，已停止注册服务端光源 TOML。即使磁盘上已有 `ywzj_rvp-lighting-server.toml` 并写着 `blockLight=true`，也不能开启真实方块光；不会修改或删除用户的这个旧文件。

爆炸发布端已断开真实光请求，所有代码光预设的 `blockLightLevel` 都为 0。屏幕光合成不再应用两层光同时开启时的 0.65 倍亮度补偿。

## 3. 光源参数统一由代码控制

颜色、半径、亮度、寿命、衰减和合并窗口的基础预设统一写在 `src/main/java/org/ywzj/rvp/light/RVP_LightParameters.java`。亮度、半径、颜色和衰减等可直接用 `/rvplight` 临时调参，完整列表见 [调参指南](RVP视觉工厂架构/RVP光照与光晕游戏内调参.md)；无需重新构建或给载具、武器补 JSON。下表是未覆盖时的代码默认值。

| 代码入口 | 自动产生条件 | 当前主要参数 |
| --- | --- | --- |
| `explosion(radius)` | 现有爆炸事件允许闪光 | RGB（红绿蓝）`[1,0.82,0.48]`；半径 `min(32,4+2×爆炸半径)` 格；强度 1.25；8 tick |
| `muzzle(caliber,false)` | 机枪/机炮成功开火，含本体火炮 | 口径 ≥45 mm 为重炮：强度 1.4、3 tick；较小口径强度 0.45、2 tick；半径按口径平方根推导，最大 18 格 |
| `muzzle(caliber,true)` | 火箭/导弹成功发射 | 强度 0.8、2 tick；偏橙色，半径按口径推导 |
| `engine(caliber)` / `enginePhase(...)` | 有发动机且实际处于燃烧期 | RGB `[1,0.48,0.12]`；表面光强度 **4**；共同半径 `clamp(20+口径毫米数×0.1,20,500)` 格，二脉冲减亮但不缩范围，燃尽立即清理 |
| `engineEmission(radius,intensity)` | 保留旧圆形喷口，当前代码暂停 | 留存核心 HDR 峰值 **60000**、物理半径上限 0.28 格；该旧通道不决定当前广域半径 |
| `RVP_RocketPlumeParameters` | 当前真实发动机与 `/rvplight engine` | 长度 `10×flame_scale`、最大直径 `3×flame_scale`；原始核心峰值 60000；光晕输入软压缩峰值 12；亮度不随几何缩放增加 |

一个 tick 是游戏的一次逻辑更新，通常每秒 20 次。持续发动机光按真实燃烧事实更新，不能靠增加寿命越过燃尽窗口。

喷口核心只在局部达到显示的最高亮度，发动机环境光和广域光晕按同一口径扩展到 20～500 格。细喷焰仍按原几何尺寸采样，广域层先用一像素求真实发光可见度，再按世界半径投影，不把几百格范围送进完整二十步喷流采样。显卡使用的 RGBA16F 浮点纹理最大有限值为 65504，统一贡献写入前限制为 60000，给模糊和舍入保留余量；8 盏发动机和全局 2 倍强度叠加也不产生无穷大。高于显示白点的内部亮度用于产生局部光晕，上屏核心可以达到白热亮度，外晕保持橙色。

口径仍复用既有 `effects_data.caliber`，喷口仍复用既有 `engine_nozzle_offset`；它们本来就分别描述武器口径和模型喷口，不是新的光源配置。炸弹、鱼雷、激光和吊舱不生成炮口火药闪光。

已撤回 `fire_data.muzzle_light`、`effects_data.rocket_engine_light` 和 `visual_effect_data[].screen_light` 三个读取入口，不再向现有视觉事件追加灯光 JSON。误写这些对象不会覆盖代码光参数，也不会因此启用其它爆炸特效。Shader 自身的 JSON 是程序加载描述，继续保留，不用于给武器配置光源。

本任务此前创建的 JSON 专用类与旧测试已移入 `_recycle_bin/20261030_003059/`，保留原目录结构及 `MOVE_LOG.md` 记录，没有执行文件删除。

## 4. 渲染顺序与兼容性

灯光在 `AFTER_TRIPWIRE_BLOCKS` 的 `HIGHEST` 优先级保存真实世界观察矩阵、投影与不含粒子烟的深度，在 `AFTER_LEVEL` 的 `HIGHEST` 优先级复制一次完整颜色并合成。已有 CRT/过载普通优先级和 TV 的 `LOWEST` 优先级随后处理最终结果，HUD 此时尚未绘制。

Forge 1.20.1 的 `AFTER_LEVEL` 位于 `LevelRenderer.renderLevel` 返回之后；Iris/Oculus 的光影最终合成在该方法返回前完成。因此灯光读取光影的最终颜色，不写光影的材质缓冲，也不会被其世界最终合成覆盖。

近景和 DH 各保留自己的深度纹理、投影、观察矩阵与空深度方向。程序先把两者还原到同一个相机空间，再按实际距离选择最近表面；不是直接比较两张图的 0～1 数值。DH 的视野、内部分辨率、near/far（最近/最远裁剪距离）与正反深度可以不同。

现有冲击波的资源位于其私有合成器内，没有可直接借用的公共输入；灯光因此使用独立 `RVP_ScreenFrameResources`。所有光共用一次近景深度、可选的一次 DH 深度和一次最终颜色复制。**这些次数只指灯光管线自身**，没有改写既有冲击波每层折射所需的读取逻辑。

有发动机时，在基础光/光晕完成后增加一次喷口峰值叠加，解除普通表面光的 0.9 曝光上限；使用显卡混合读取当前颜色，不增加颜色复制或新的帧缓冲。RGB 按 `1-(1-源)*(1-背景)` 混合，Alpha 完全保留。源光心和当前像素都检查同一份近景/DH 深度，墙后被完整遮住的喷口不会向墙外绘制光团；光影提前绘制的手持物也继续遮罩。混合因子、RGB/Alpha 混合方程均在退出时恢复。

| 环境 | 当前行为 |
| --- | --- |
| 原版世界，主目标、深度与矩阵可用 | 基础光和可选光晕 |
| CRT、CRT UI Lite、TV 黑白处理 | 先灯光、后相应全屏处理 |
| 热成像启用 | 关闭彩色屏幕光，保留现有热源通道 |
| Iris/Oculus 存在但无活动光影包 | 使用主画面近景深度，正常合成 |
| 有活动光影包 | 使用光影记录的场景矩阵与主画面深度，在光影最终颜色上合成；手持物压缩深度作为遮罩 |
| DH 原生 OpenGL，API 7.0.1～7.x | 复用现有 before-apply/cleanup 公开事件取得当帧远景深度和配对矩阵，近景与远景共同参与表面受光和遮挡 |
| DH+Iris/Oculus 光影 | 由 DH 事件证明本帧确实绘制远景，再通过当前光影管线的公开方法读取其实际 DH 深度和投影；不依赖远距载具是否存在或载具实验性光影选项 |
| 外部 MRT、偏移视口或主颜色的别名 FBO | 从明确归属的主目标只读复制，不再因当前绑定不同而关闭；MRT 指一次绘制使用多张颜色缓冲 |
| 本帧 DH 来源缺失或不可读 | 本帧只处理可信近景，不复用上一帧远景；状态命令明确显示缺失情况 |
| 缺近景深度或矩阵无效 | 仅跳过无法重建的当前帧，日志限频诊断 |
| Bloom 程序或半分辨率目标不可用 | 回退直接合成基础光 |

可选桥只读取公开方法，支持 Iris 新旧包名；没有新增 Mixin、访问器、私有字段反射或光影包补丁。方法缓存不保存具体光影管线实例，切换光影后会读取新管线。当前按实际测试客户端的 DH 3.2.0-b / API 7.0.1、Oculus 1.8.0、Embeddium 0.3.31 核对方法与绘制时序；这不等于所有光影包已经做过实机观感验收。

每次显示帧开始清空 DH 来源，游戏暂停时也不复用旧深度。外部深度只在自有读取 FBO 中短暂挂接，复制后立即解除引用；每次重新挂接，避免窗口重建后纹理编号复用却读到旧对象。FBO 是显卡中的绘制/读取目标。绑定 FBO 和恢复程序都经过 Minecraft 引擎入口，使 Oculus 的状态缓存和实际 GL 保持一致；输出附件、纹理、采样器、模板测试、颜色写掩码及视口都会恢复。

Iris/Oculus 的手持物将裁剪空间 Z 缩放到 `0.125`，对应纹理深度上限是 `(1+0.125)/2=0.5625`，不能直接把 `0.125` 当成纹理深度上限。桥读取公开 `HandRenderer.DEPTH`，这些像素不当作地面受光。实现依据可查 [Iris 手持物代码](https://github.com/IrisShaders/Iris/blob/1.20.1/src/main/java/net/irisshaders/iris/pathways/HandRenderer.java) 与 [Iris DH 深度说明](https://github.com/IrisShaders/docs/blob/main/src/content/docs/current/Reference/Mod%20Support/distant_horizons.mdx)。

表面法线（表面朝向）由相邻深度近似取得。每盏光还执行相机到光心的真实方块碰撞检查，并在像素到光心的路径上采样深度。不可见或离屏遮挡采取保守策略，可能少照一些表面。屏幕深度无法完整表示隐藏几何，不能替代完整三维阴影。

烟雾现通过独立材质受光：按真实面片位置计算爆炸/炮口/发动机光，乘以原贴图和粒子的 Alpha，不再用背景表面代替烟的位置。所有光照遮挡读取粒子前快照，烟后来即使写入主深度也不会遮光。方块、实体、DH 和手持物遮罩继续保留；原贴图、正常烟雾绘制与场景透明度不变。

2026-10-30 修复尾焰自遮挡：真实发动机尾焰原先使用会写深度的半透明通道，导致喷口核心把自己的火焰表面误判成前景；天空预览没有绘制该模型，所以预览正常。现将尾焰方块面和三角网格都改为只写颜色，继续接受地形和实体的深度遮挡，保留实体阶段立即绘制与全亮动画。详见 [技术文档 §9.5](RVP视觉工厂架构/RVP屏幕空间光照与实体遮挡实现详解_20261030.md#95-真实尾焰为什么会挡住自己的高亮以及本次修复)。
