# RVP 座舱屏幕功能使用指南（雷达屏 / RWR 屏 / 战术地图屏）

> 版本：2026-10-14　适用：ywzj_rvp 0.0.1_alpha_0.6.1+
> 功能：把雷达、RWR（雷达告警）、战术地图三类动态界面**实时绘制在载具模型的屏幕骨骼上**（座舱仪表屏/MFD）。
> 实现：纯客户端，零渲染 Mixin、零本体改动；性能开销三类屏全开 <0.5ms/帧 + 3MB 显存。

---

## 1. 快速上手（三步）

1. **建模**：在载具模型里建屏幕骨（mesh 或 cube 均可，mesh 任意曲面也支持），UV 展开，骨名建议 `illum_` 前缀（自发光，屏面不受环境光变暗）；
2. **配置 display 文件**：在 `assets/rvp/display/vehicle/<车id>.json` 加 `special_bone_effects` 条目（见下节）；
3. **进游戏**：乘坐该载具，屏幕骨上即出现对应动态画面。

## 2. display 配置

display 文件 = `assets/rvp/display/vehicle/<车id>.json`（与 `data/rvp/vehicles/<车id>.json` 同名约定，需带 `animation_controller`）。

```json
"special_bone_effects": [
  { "bone": "illum_cockpit_radar", "texture": "rvp:cockpit/radar", "type": "transparent" },
  { "bone": "illum_cockpit_rwr",   "texture": "rvp:cockpit/rwr",   "type": "transparent" },
  { "bone": "illum_cockpit_map",   "texture": "rvp:cockpit/map",   "type": "transparent" }
]
```

| 字段 | 说明 |
| --- | --- |
| `bone` | 屏幕骨名。mesh（poly_mesh）与 cube 均原生支持 |
| `texture` | **固定三选一**：`rvp:cockpit/radar`（雷达屏）/ `rvp:cockpit/rwr`（RWR 屏）/ `rvp:cockpit/map`（战术地图屏）。RL 即屏型标识，对应 RVP 注册的三张 512² 动态纹理 |
| `type` | **推荐 `muzzle_flash`（加法混合恒亮，不受光照）**——屏幕是自发光设备；`transparent`（半透明+光照）会让屏在暗处随环境变暗、且半透明混合对纹理 alpha 敏感，**不建议用于屏幕**。代码无感，改字段即切换 |

规则：
- 同车多块同类屏 = 多条目同 `texture`（内容车级共享，天然一致）；
- **不配置 = 该车无屏幕**，零开销；
- 已配车辆：suav、j16d（屏骨名 `illum_cockpit_*` 为占位约定，建模后对齐骨名或改配置）。

## 3. 建模规范（屏骨 UV = 取景框）

> **2026-10-15 语义变更（用户定案）**：**一切按模型 UV 采样**，不再自动铺满。
> 屏骨的 UV 展面**就是取景框**——展到 0~1 就是整张画面，只展 0.2~0.4 就只显示画面中间那一块
> （等效放大），UV 顺序翻转即镜像。旧版"包围盒归一化铺满"已降级为可选逃生舱
> （display 条目写 `"ywzj_rvp_screen_uv_mode": "fill"`）。

| 你想达到的效果 | 做法 |
| --- | --- |
| 画面铺满整块屏 | 屏骨 UV 展满 `0~1` |
| 画面只占屏的一部分（留黑边） | 把 UV 收进子区间；屏骨几何保持原大小（几何决定物理尺寸，UV 只决定取景） |
| 把画面放大/裁切（画中画） | UV 收得更小，例如 `0.25~0.75` 取画面中心 50% |
| 画面镜像 | 反转 UV 的 u 或 v 顺序 |
| 一张 RT 分到两块屏 | 两块屏骨各展 `0~0.5` / `0.5~1` 的不同子区 |

注意事项：
- 屏骨 UV **必须落在 0~1**（RT 纹理 wrap=CLAMP_TO_EDGE，超界会采到边缘像素 ⇒ 拉丝/渗色）；
- 画面上下方向：模型 UV 的 v 方向按常规建模习惯（0=贴图顶部）即可，画布侧已由
  `RVP_CockpitCanvas.FLIP_DRAW_Y` 补偿；
- 内容自身在画面里的大小（圆盘直径 70%/75%/地图铺满）仍由渲染器顶部常量控制
  （`RVP_RadarScreenRenderer` / `RVP_RwrScreenRenderer` 的 `outer`、`RVP_MapScreenRenderer`），
  **与模型 UV 无关**——那两个"占比常量"指的是画布内图形占短边比例（术语沿用 HUD 的 MCHR）。

调试：诊断日志每秒的特殊骨行末尾会打 `uv=uMin~uMax/vMin~vMax UV模型|UV铺满`，
可直接核对模型 UV 的实际范围是否符合预期。

## 4. 行为与性能

- **仅本地玩家乘坐的载具绘制动态内容**；其它载具（含别人的同款配屏车）的屏骨**整块不渲染**（不显示原建模贴图）；
- 下车后屏骨同样不渲染（屏随乘载出现/消失）；
- 性能：纯客户端。三类屏全开 <0.5ms/帧 + 3MB 显存（动态纹理 512²、雷达/RWR 20Hz、地图 5Hz 降频重绘，RT 直采样零回读零上传）；服务端与网络零新增。

## 5. 已知限制

1. 内容方向（上下颠倒）由 `RVP_CockpitCanvas.FLIP_DRAW_Y` 开关控制，首次部署实机校验一次；
2. 雷达屏扫描线为匀速旋转简化版，HUD 雷达的三态相位逻辑（HMD/相控阵/机械）未接入；
3. 战术地图屏固定 2 格/像素（视野 1004 格），无缩放交互；
4. 屏骨若在极端视角下有轻微深度空洞感（半透明通道写深度所致），反馈后可切 cutout RenderType。

## 6. 实机验证清单

- [ ] 三屏内容出现、方向正确（`FLIP_DRAW_Y`）
- [ ] 20Hz 流畅度、暗处亮度（transparent 语义）
- [ ] 非本车配屏车屏骨不可见
- [ ] 下车后原车屏消失（预期行为）

## 屏内文字/元素大小配置（2026-10-15 新增）

display 条目 `special_bone_effects` 的屏骨条目（texture=rvp:cockpit/*）可加两个可选字段，
**按屏纹理 RL 生效**（同 RL 多载具共享时取最大值）：

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `ywzj_rvp_text_scale` | float | 2.0 | 屏内文字字号绝对值（NO RADAR/量程/RWR 标题/告警/威胁标注均按比例派生） |
| `ywzj_rvp_element_scale` | float | 1.0 | 屏内元素缩放倍率：雷达屏目标方块/速度矢量/扫描线/锁定虚线、RWR 射线/虚线段/端点方块、地图屏探测点/本车图标 |

示例（屏大想看清就放大）：
```json
{
  "bone": "illum_radar_screen",
  "texture": "rvp:cockpit/radar",
  "ywzj_rvp_screen_size": 512,
  "ywzj_rvp_text_scale": 3.0,
  "ywzj_rvp_element_scale": 1.5
}
```
未配置 = 历史默认行为（逐像素一致）。两值都限幅 0.5~8.0，F3+T 或重进世界生效。
