# RVP 座舱屏幕功能使用指南（雷达屏 / RWR 屏 / 战术地图屏）

> 版本：2026-10-14　适用：ywzj_rvp 0.0.1_alpha_0.6.1+
> 功能：把雷达、RWR（雷达告警）、战术地图三类动态界面**实时绘制在载具模型的屏幕骨骼上**（座舱仪表屏/MFD）。
> 实现：纯客户端，零渲染 Mixin、零本体改动；性能开销三类屏全开 <0.5ms/帧 + 3MB 显存。

---

## 1. 快速上手（三步）

1. **建模**：在载具模型里建屏幕骨（mesh 或 cube 均可，mesh 任意曲面也支持），UV 展开，骨名建议 `illum_` 前缀（自发光，屏面不受环境光变暗）；
2. **配置 display 文件**：在 `assets/rvp/display/vehicle/<车id>.json` 加 `special_bone_effects` 条目（见下节）；
3. **进游戏**：乘坐该载具，屏幕骨上即出现对应动态画面。

## 2. display 配置

display 文件 = `assets/rvp/display/vehicle/<车id>.json`（与 `data/rvp/vehicles/<车id>.json` 同名约定，需带 `animation_controller`）。

```json
"special_bone_effects": [
  { "bone": "illum_cockpit_radar", "texture": "rvp:cockpit/radar", "type": "transparent" },
  { "bone": "illum_cockpit_rwr",   "texture": "rvp:cockpit/rwr",   "type": "transparent" },
  { "bone": "illum_cockpit_map",   "texture": "rvp:cockpit/map",   "type": "transparent" }
]
```

| 字段 | 说明 |
| --- | --- |
| `bone` | 屏幕骨名。mesh（poly_mesh）与 cube 均原生支持 |
| `texture` | **固定三选一**：`rvp:cockpit/radar`（雷达屏）/ `rvp:cockpit/rwr`（RWR 屏）/ `rvp:cockpit/map`（战术地图屏）。RL 即屏型标识，对应 RVP 注册的三张 512² 动态纹理 |
| `type` | `transparent`（推荐，半透明+光照：暗处屏随环境变暗，真实 CRT 感）或 `muzzle_flash`（加法恒亮：暗处醒目，白天亮背景过曝）。代码无感，改字段即切换 |

规则：
- 同车多块同类屏 = 多条目同 `texture`（内容车级共享，天然一致）；
- **不配置 = 该车无屏幕**，零开销；
- 已配车辆：suav、j16d（屏骨名 `illum_cockpit_*` 为占位约定，建模后对齐骨名或改配置）。

## 3. 建模规范（UV 占比）

内容只保证覆盖**纹理中心区域**，四周留边防出血（对齐 MCHR 惯例）：

| 屏型 | 内容占纹理直径 | 建模建议 |
| --- | --- | --- |
| 雷达屏 | 70%（直径/短边） | UV 展面留 15% 边距，或展满后接受黑边框 |
| RWR 屏 | 75% | 留 12.5% 边距 |
| 战术地图屏 | **98%（尽可能铺满）** | 展满 0-1，仅 1% 防边缘采样渗色 |

占比常量在对应渲染器类顶部（`UV_DIAMETER_RATIO` / `outer` 计算处），可调。

## 4. 行为与性能

- **仅本地玩家乘坐的载具绘制动态内容**；其它载具（含别人的同款配屏车）的屏骨**整块不渲染**（不显示原建模贴图）；
- 下车后屏骨同样不渲染（屏随乘载出现/消失）；
- 性能：纯客户端。三类屏全开 <0.5ms/帧 + 3MB 显存（动态纹理 512²、雷达/RWR 20Hz、地图 5Hz 降频重绘，RT 直采样零回读零上传）；服务端与网络零新增。

## 5. 已知限制

1. 内容方向（上下颠倒）由 `RVP_CockpitCanvas.FLIP_DRAW_Y` 开关控制，首次部署实机校验一次；
2. 雷达屏扫描线为匀速旋转简化版，HUD 雷达的三态相位逻辑（HMD/相控阵/机械）未接入；
3. 战术地图屏固定 2 格/像素（视野 1004 格），无缩放交互；
4. 屏骨若在极端视角下有轻微深度空洞感（半透明通道写深度所致），反馈后可切 cutout RenderType。

## 6. 实机验证清单

- [ ] 三屏内容出现、方向正确（`FLIP_DRAW_Y`）
- [ ] 20Hz 流畅度、暗处亮度（transparent 语义）
- [ ] 非本车配屏车屏骨不可见
- [ ] 下车后原车屏消失（预期行为）

【功能】座舱屏幕（已实现，你维护/扩展它）：把三类动态界面绘制在载具模型的屏幕骨骼上——
雷达屏（rvp:cockpit/radar，20Hz）、RWR 告警屏（rvp:cockpit/rwr，20Hz）、战术地图屏（rvp:cockpit/map，5Hz，去按钮去照射扇形）。

【架构四件套】全部在 src/main/java/org/ywzj/rvp/client/cockpit/：
1. RVP_CockpitScreenManager：客户端注册三张 512² DynamicTexture（RL rvp:cockpit/{radar,rwr,map}，RL path 即屏型）；
   ClientTickEvent END 降频驱动（每 kind 按 intervalTicks：雷达/RWR 1t、地图 4t）；仅本地玩家乘坐的载具绘制
   （非乘载→三张纹理填全透明，视觉=屏骨不渲染）。
2. RVP_CockpitCanvas：RT（TextureTarget 512²）离屏渲染封装——bindWrite+清屏+GUI 正交投影
   （Matrix4f.setOrtho(0,w,h,0,1000,21000)）+new GuiGraphics(mc, renderBuffers().bufferSource()) 绘制+endBatch；
   回灌=NativeImage.downloadTexture(0,false)→DynamicTexture.setPixels+upload。FLIP_DRAW_Y 静态开关控制
   绘制侧 pose 翻转（内容上下颠倒时改它）。NativeImage 在 com.mojang.blaze3d.platform 包；
   TextureTarget 构造第 4 参是 boolean(isColor)。
3. RVP_RwrScreenRenderer / RVP_RadarScreenRenderer / RVP_MapScreenRenderer：三屏内容（绘制原语搬自
   client/gui/RVP_RadarOverlay；地图屏=RVP_TacticalMapCache 瓦片 blit+图标层，按用户定案去按钮/去照射扇形；
   UV 占比常量在各渲染器顶部：雷达 0.70/RWR 0.75/地图 0.98，对齐 MCHR）。
4. 贴面渲染：本体 VehicleBedrockModel.renderSpecialBones 已被 RVP @Overwrite
   （mixin/VehicleBedrockModelCockpitRenderMixin）——渲染循环在 RVP 代码里，屏骨按
   special_bone_effects.texture 的 RenderType 渲染（TextureStateShard 按 RL 实时 bind 动态纹理）；
   非本车（!isLocalPlayerVehicle）且 effect.texture 为 rvp:cockpit/* 时 continue 跳过=屏骨整块不渲染。

【配置层】= display 文件（assets/rvp/display/vehicle/<车id>.json，与 data/vehicles 同名约定）的
special_bone_effects 数组：{bone:屏骨名, texture:"rvp:cockpit/radar|rwr|map", type:"transparent"}。
type=transparent 半透明受光照（V1 定案）/muzzle_flash 恒亮加法可选。display 需带 animation_controller。
display 属 assets 不进 git（gitignore），配置改动由用户同步游戏目录。

【数据源】纯客户端既有状态：RWR=本体 WarningReceiver.targets（Map<实体id, WarnTarget{warnType,info,receivedTime}>，
vehicle.warningReceiver 公开字段）+RVP_ClientLockWarningState；雷达=RadarUnit.getDetectedEntities()
（HashMap<实体id, DetectedObject{entity,detectedPosition,detectedTime}>，经 WeaponUnit.getMainRadarUnit()）；
地图=RVP_TacticalMapCache（getVisibleTiles(minX,minZ,maxX,maxZ)→List<TilePos{rx,rz}>，getTileTexture(pos)→RL，
TILE_SIZE=256 即 1 瓦片 256 格 1 纹素 1 格）。方位解算用 vehicle.relativeRotDirection(方向, true)（车体系，车头朝上）。

【硬约束】不改 ywzj_vehicle；不新增 Mixin（屏骨跳过已走既有 @Overwrite 循环）；公共代码禁引 @OnlyIn(CLIENT)
（本功能全在 client 包无此问题）；字段/方法中文注释+调用他方方法注释调用目的；改动前 git status 重探并行改动；
CRLF 文件（部分 Java 是 CRLF）用 python 字节替换并复核 \r\n 计数。

【当前状态与待办】已实现+构建通过（822/0/0）+冒烟通过；未实机验证：三屏方向（FLIP_DRAW_Y）/清晰度/20Hz 流畅度/
暗处亮度/非本车不渲染效果。已知简化：雷达扫描线匀速旋转（HUD 三态相位未接）、地图固定 2 格/px 无缩放。
未来可能迭代：三态扫描线接入、屏内容按需加新屏型（新增 ScreenKind+渲染器+RL 即可）。
