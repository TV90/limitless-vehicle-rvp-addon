# 座舱屏幕（雷达/RWR/战术地图）—— 功能说明与 bug 交接文档

> 更新：2026-10-14 凌晨　状态：**功能已实现，但存在一个未解决的显示 bug（详见 §4），正在排查**
> 本文供：①使用者/配置者；②接手排查 bug 的开发者或 AI（文末 §7 有可直接粘贴的交接提示词）。

---

## 1. 功能是什么

把三类动态界面**实时绘制在载具模型的屏幕骨骼上**（座舱仪表屏/MFD）：

| 屏型 | display 引用的纹理 RL | 刷新率 | 内容 |
| --- | --- | --- | --- |
| 雷达屏 | `rvp:cockpit/radar` | 20Hz（每 tick） | 探测罗盘：量程圈+旋转扫描线+探测方块+速度矢量 |
| RWR 告警屏 | `rvp:cockpit/rwr` | 20Hz | 威胁罗盘：同心圆+方位射线+距离映射+机型文字+导弹/锁定告警闪烁 |
| 战术地图屏 | `rvp:cockpit/map` | 5Hz | 地形瓦片+本车/探测图标（去按钮/去照射扇形） |

- **仅本地玩家乘坐的载具绘制动态内容**；非乘载/其它载具相关状态见 §4 现状；
- 纯客户端实现：数据全部来自既有客户端本地状态（本体 `WarningReceiver.targets`、`RadarUnit.getDetectedEntities`、`RVP_TacticalMapCache` 瓦片），服务端与网络零新增；三类屏全开 <0.5ms/帧 + 3MB 显存。

## 2. 配置层（使用者操作）

**唯一配置层 = display 文件的 `special_bone_effects`**，无 RVP 自有配置：

```json
"special_bone_effects": [
  { "bone": "illum_cockpit_radar", "texture": "rvp:cockpit/radar", "type": "transparent" },
  { "bone": "illum_cockpit_rwr",   "texture": "rvp:cockpit/rwr",   "type": "transparent" },
  { "bone": "illum_cockpit_map",   "texture": "rvp:cockpit/map",   "type": "transparent" }
]
```

- `bone` = 建模的屏幕骨名（mesh/poly_mesh 原生支持，cube 亦可）；
- `texture` 三选一固定填上表 RL（**RL 的 path 就是屏型**，对应 RVP 注册的 512² DynamicTexture，本体 `TextureStateShard` 每帧按 RL 实时 bind）；
- `type`：`transparent`（半透明+光照，暗处屏暗，真实 CRT 感）或 `muzzle_flash`（加法恒亮），可随时改字段切换；
- 同车多块同类屏 = 多条目同 texture（内容车级共享）；
- display 需带 `animation_controller`（baked 特殊骨前置）；
- **不配置 = 该车无屏幕**。

**建模规范**：屏骨 mesh/cube 皆可；UV 展面参考内容占比（雷达 70%/RWR 75%/地图 98%，直径/短边，居中）；骨名建议 `illum_` 前缀（自发光，不受环境光变暗）。

**已配车辆**：suav、j16d、z10（直10，屏骨 `illum_rwr_screen`/`illum_map_screen` 为用户建模并命名）。

## 3. 实现架构（维护者参考）

新包 `rvp/client/cockpit/`（+1 个 Overwrite Mixin，**零新增 Mixin 注入点**）：

| 类 | 职责 |
| --- | --- |
| `RVP_CockpitScreenManager` | 注册三张 512² DynamicTexture；ClientTick END 降频驱动（雷达/RWR 每 tick、地图每 4t）；载具解析（`resolveLocalVehicle`：武器站链优先、`lvp.vehicle` 回退） |
| `RVP_CockpitCanvas` | RT（TextureTarget 512²）离屏渲染封装：bindWrite+清屏+**ModelView 单位矩阵重置**+GUI 正交投影+GuiGraphics 绘制+endBatch；回灌 `downloadTexture`→`setPixels+upload` |
| `RVP_RwrScreenRenderer` / `RVP_RadarScreenRenderer` / `RVP_MapScreenRenderer` | 三屏内容（原语搬自 `RVP_RadarOverlay`；地图屏=TacticalMapCache 瓦片 blit+图标层） |
| `mixin/VehicleBedrockModelCockpitRenderMixin` | **既有** @Overwrite（cockpit_depth_fix 批所建，非本次新增）——渲染循环在 RVP 代码里，本次在其中加"非本车屏骨跳过"判断 |

贴面渲染由该 Overwrite 循环完成：对屏骨按 special_bone_effects.texture 的 RenderType 渲染（`renderSingleBone` 双 RenderType，mesh 骨走 meshType 通道）。

## 4. 未解决 bug：用户客户端屏幕不显示

**预期效果**：乘坐配屏载具（如直10 z10）时，屏幕骨显示对应动态画面。

**现状**：用户客户端（单机世界，jar 为 `ywzj_rvp-1.20.1-0.0.1_alpha_0.6.1-all.jar` 诊断版）乘坐直10，屏骨**始终不显示任何内容**（既无动态画面，也无建模原贴图/花屏——视觉上屏骨"消失"）。

**已排除项**（全部核对过）：
1. display 配置正确：`z10.json` 有 `illum_rwr_screen`/`illum_map_screen` 两条（texture=rvp:cockpit/*，type=transparent）、animation_controller 存在；
2. 模型骨名完全匹配：`z10.json` 模型（format_version 1.12.0）bones[13]/[14] 即两屏骨，poly_mesh 结构完整（normalized_uvs=true、uvs 0-1 四角、positions 正常）；
3. 用户客户端 jar 字节级验证含全部修复（ModelView/诊断/钳制移除等）；
4. CameraTVMissileMixin 启动崩溃已修（改方法 Shadow；且该崩溃系"只跑 jarJar 未全量构建"的 refmap 中间态，与座舱屏逻辑无关）；
5. 专用服路径（Noop）与本车路径行为一致性已核对。

**当前主嫌疑（按优先级）**：
1. **z10 屏骨为 poly_mesh 且该骨未被 SBM 烘焙进渲染**：现象"连原贴图都不显示"指向该骨在 `renderToBuffer` 主渲染与 `renderSpecialBones` 特殊渲染**两条路径都未产出顶点**——需验证 SBM 2.5.1 对该 poly_mesh（含 normalized_uvs/positions/normals/uvs/polys）的解析与 `renderSingleBone` 对 mesh 骨的实际产出；对照样本：abramsx 等既有模型同样含 poly_mesh 且正常显示，需 diff 两者的 poly_mesh 字段形态差异；
2. DynamicTexture 回灌像素 alpha 通道问题（transparent 材质 alpha=0 → 完全透明）——诊断日志的"中心像素RGBA"可直接证伪；
3. `isLocalPlayerVehicle` 判定链在 z10 上失真（此前钳制误杀本车已旁证该链在直10 上可能异常）。

**排查工具（已内置，见 §5）**：诊断专有日志会输出 Manager 驱动状态、每次回灌的中心像素 RGBA、以及回灌失败的完整堆栈——按数据三分支定位。

## 5. 诊断工具（命令式，专有文件）

| 命令 | 作用 |
| --- | --- |
| `/cockpitdiag on` | 开启自动记录（开启时 Manager 每 20t 写驱动状态；每次回灌写像素采样；失败写完整堆栈） |
| `/cockpitdiag off` | 关闭 |
| `/cockpitdiag`（无参） | 显示当前开关状态 |

**输出文件**：`logs/rvp_cockpit_diag.log`（客户端 gameDir/logs 下，独立于 latest.log，追加式）。**latest.log 不再被诊断内容污染**（本体的 Gunner schema ERROR 与 rvp.zip CEN header 报错为既有噪音）。

## 6. 已知限制（非 bug）

1. 非本车的配屏车屏骨不渲染（动态纹理仅承载本车内容，按用户定案）；
2. 雷达屏扫描线为匀速旋转简化版（HUD 三态相位未接）；
3. 战术地图屏固定 2 格/像素（1004 格视野），无缩放交互；
4. 内容 Y 方向由 `RVP_CockpitCanvas.FLIP_DRAW_Y` 开关控制（实机校验一次）。
