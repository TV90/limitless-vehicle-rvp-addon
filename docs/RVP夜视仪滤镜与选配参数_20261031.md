# RVP 夜视仪滤镜与选配参数（2026-10-31）

> 参考本体热成像（`ywzj_vehicle` / `ThermalHandler` + `shaders/post/thermal.json`）的写法实现，
> 但**不依赖本体改动**：参数走 RVP 的 weapon unit mixin，滤镜走 RVP 自己的 PostChain。

## 一、参数：`with_night_vision`

写在载具 JSON 的 **weapon unit** 里，与本体 `with_thermal_imager` 同层级：

```json
{
  "id": "rvp:xxx_cannon",
  "optical_sight_type": "crt_ui",
  "with_thermal_imager": true,
  "with_night_vision": true,
  ...
}
```

- 默认 `false`，未配置的存量载具行为完全不变。
- 兼容别名 `rvp_with_night_vision`（`@SerializedName` 的 alternate），避免将来与本体撞名。
- 承载链路：`WeaponUnitPojoMixin`（`@SerializedName`）→ `WeaponUnitDataMixin`（构造时透传）→ `WeaponUnitDataExt#ywzj_rvp$withNightVision()`。

## 二、开关逻辑：两个完全独立的状态位

**键位复用本体热成像键（KEY_4），不新增按钮。** 但观瞄态与第三人称是**两个独立状态**，
只是共用键位：切视角不联动、不自动同步。

| 场景 | 按 KEY_4 谁处理 | 显示 |
|---|---|---|
| 观瞄态 + 该站有热成像 | 本体 `InputHandler`（RVP 让位，不翻两次） | 热成像（本体管线） |
| 观瞄态 + 该站无热成像、有夜视仪 | RVP（`RVP_NvgState.toggleScope()`） | 夜视滤镜 |
| 第三人称 + 有夜视仪 或 有热成像 | RVP（`toggleThirdPerson()`） | 夜视滤镜 |
| 都没有 | 无反应 | 无 |

派生实现：`RVP_ClientEvents#ywzj_rvp$applyNvgState()`（每 tick）。

```java
if (viewType == SCOPE) {
    nvg = !hasThermal && hasNightVision && RVP_NvgState.isScopeEnabled();
} else {
    nvg = RVP_NvgState.isThirdPersonEnabled() && (hasNightVision || hasThermal);
}
```

- **互斥**：同一时刻只有一个滤镜生效；观瞄态热成像优先，夜视让位。
- **不联动**：观瞄开热成像 → 切第三人称不会自动开夜视，需手动按一次；第三人称关夜视不影响观瞄态。
- **第三人称为什么能开**：本体热成像只在 `viewType == SCOPE && optical_sight_type == CRT` 才激活
  （`LocalVehiclePlayer#checkState` + `InputHandler:126`），第三人称根本不存在热成像，因此那里一律是夜视滤镜。
- **换车/下车清零**：`RVP_NvgState.bindVehicle(vehicleId)`，避免状态跨车残留。
- **HITL 让位**：`HITL_SWITCH_VIDEO_MODE` 也绑 4 键，遥控导弹期间不抢（`RVP_ClientHitlState.isActive()` 时返回）。
- **按键实现**：走 `AllKeys.TOGGLE_THERMAL_IMAGING.consumeClick()` 轮询（`RVP_ClientEvents#ywzj_rvp$handleNvgToggleKey`），
  **不要**用 `InputEvent.Key + KeyMapping.matches`——后者在玩家改绑键位后不跟随（2026-10-31 实测仍按默认 4 键生效）。
  `consumeClick` 读的是 KeyMapping 自身维护的点击队列，改键立刻跟随；本体走 `InputEvent.Key` 且不消费该队列，两边不互抢。
- 本体 CRT 观瞄后处理（`crt.json`）仍会叠加在观瞄态夜视之上；不需要时用现成的 `rvp_disable_crt_effect` 关掉。

## 三、滤镜实现（5 pass）

`assets/ywzj_rvp/shaders/post/night_vision.json`：

| pass | 输入 → 输出 | 作用 |
|---|---|---|
| `nvg_light` | main → `nvg_light` | 光源提取（眩光源） |
| `nvg_blur_h` | `nvg_light` → `nvg_blur` | 横向高斯（5 tap 近似 9 tap） |
| `nvg_blur_v` | `nvg_blur` → `nvg_light` | 纵向高斯 |
| `nvg_composite` | main + `nvg_light` → swap | 像增强 + 绿荧光 + 眩光 + 烧白 |
| `blit` | swap → main | 回写 |

### 光源判据（`nvg_light.fsh`）

三条并行取最大值，缺任何一条都会漏光源：

1. **绝对亮** `luma > 0.62` —— 原版火把、岩浆、爆炸白闪、枪口火花核心
2. **局部亮峰** `luma 明显高于 8 邻域均值` —— 暗场景里的小光点
3. **高饱和彩光** `饱和度 > 0.16 且 max 通道 > 0.06 且是局部峰` —— 光电干扰机那类暗处红光
   （绝对亮度只有 0.3，单靠 1、2 抓不到）

### 合成（`nvg_composite.fsh`）

1. **像增强指数取中间值**（2026-10-31 第四版）：`pow(luma, 1.22) * Gain(2.05)`，再减 0.015 黑电平。
   历史教训：第一版 `pow(0.42)`、第二版 `pow(0.62)` 是**抬暗部**⇒整屏发白；第三版 `pow(1.55)` 压过头⇒整屏死黑。
   1.22 让星光下的地面（luma≈0.1）落在能看清轮廓、又不刺眼的区间。
2. **锁死在绿色系**：不再掺真实色彩（`ColorMix` 默认 0）。色相在两支相近的荧光绿之间
   （偏黄绿 `(0.36,1.00,0.34)` ↔ 偏青绿 `(0.10,0.92,0.58)`）按颗粒噪声摆动，
   宏观纯绿、微观有"荧光粉颗粒"的层次，比灰噪点更像真实像增强管。
3. 管壁暗角衰减
4. 亮度噪点（`0.10` 强度，暗部也有细颗粒）
5. **加性叠加模糊后的光源** → 越亮越溢出，形成直视光源的眩光核心
6. 过曝区去色烧白（`Whiten`）—— 模拟像增强管强光饱和

### 可调参数（`program/nvg_composite.json` 的 uniform 默认值）

| uniform | 默认 | 说明 |
|---|---|---|
| `PhosphorColor` | `[0.30, 1.0, 0.42]` | 荧光基色（只在 `ColorMix>0` 时用到） |
| `Gain` | `2.05` | 像增强增益，整体亮度缩放 |
| `BloomIntensity` | `1.9` | 眩光强度，直接影响"刺眼"程度 |
| `Whiten` | `0.85` | 过曝去色力度 |
| `ColorMix` | `0.0` | 原色保留比例：0=纯绿系（默认），1=完全真实色彩（会出戏） |

亮度主控是 `nvg_composite.fsh` 里的 `pow(luma, 1.22)` 指数：调大更黑，调小更亮。
绿系色相的摆动幅度在 `mix(greenWarm, greenCool, 0.22 + hueNoise * 0.56)` 里改。

## 四、时序要求（重要）

`RVP_NvgHandler` 必须**晚于** `RVP_ScreenLightPass`（后者在 `AFTER_LEVEL` 用 `EventPriority.HIGHEST`）。
枪口火花光影、爆炸光源、光电干扰机暗处红光都是那个 pass 合成进主目标的；夜视用 `LOWEST` 才能把它们
一起纳入眩光提取。**若把优先级改成 HIGHEST/NORMAL，这些自发光会全部漏掉。**

## 五、光影包（Iris/Oculus）策略

**2026-10-31 修订：不再"检测到光影就跳过"。** 早先的实现是 `shadersActive()` 为真就直接走 GUI 降级，
过于一刀切——Iris 下 PostChain 有时其实还能工作。现在改为：

1. 先让 PostChain 真跑（不再看 `shadersActive()`）
2. 只有在**构造或 `process()` 真抛异常**时才置 `postChainFailed`，转 `RVP_NvgGuiFallback`
   （全屏 P43 绿罩 + 四边暗角，没有像增强和眩光）
3. 资源重载（F3+T）或重新开关夜视会复位该标志，允许再试一次

若实测光影下画面异常（PostChain 与 shaderpack 的 final pass 打架），把 `RVP_NvgHandler.onRenderLevel`
里的 `postChainFailed` 判断换回 `RVP_LightingCompatibility.shadersActive()` 即可回到旧行为。

## 六、干扰机光斑（夜视专用）

夜视激活时，光电干扰机的玻片自发光**不再走原来的红玻璃渲染**，改由 `RVP_NvgGlowPass` 在
`AFTER_LEVEL` 末尾自绘一个"白热核心 + 红外软晕"的椭圆光斑：

- `RVP_EoJammerGlowRenderer` 在遍历玻片骨骼时把世界坐标上报给 `RVP_NvgGlowPass`
  （同一位置 0.5 格内合并，避免一 tick 多帧把亮度叠成两倍），然后提前 return 跳过原红光与持久光源。
- 光斑着色器 `core/nvg_glow.{json,vsh,fsh}`：核心半径 0.24~0.34 平滑过渡，颜色从中心白热
  `(1.0,0.96,0.88)` 连续过渡到边缘红 `(0.95,0.14,0.05)`，**不是纯色**；外围用 `pow(1-r, 2.4)` 做发散晕。
- 屏幕尺寸按透视缩放（`WORLD_RADIUS 1.85` 格、横 1.25 倍纵 0.85 倍），远处自动变小，贴脸时 NDC 半径封顶 1.15。
- **叠加**：加性混合 `ONE/ONE`，两台干扰机靠近时两层光斑直接累加，重叠处更亮并烧白，
  不需要额外的叠加分支。
- 光斑走自绘 quad 而不是 PostChain，因此**即使在光影下、即使夜视 PostChain 失败，光斑依然会画出来**。

## 七、验证载体（已配置）

`limitless_vehicle/rvp/data/rvp/vehicles/m1a1hc.json` 的两个武器站都加了 `with_night_vision: true`：

| 武器站 | 配置 | 可验证场景 |
|---|---|---|
| 主炮（`crt_ui`） | 热成像 + 夜视仪 | 观瞄态开热成像、第三人称开夜视、互斥让位 |
| 机枪（`operator`） | 只有夜视仪 | 观瞄态开夜视（本体热成像不存在，RVP 接管 KEY_4） |

## 八、已知边界

- 观瞄态热成像仍受本体限制：只对 `optical_sight_type == CRT` 的站生效（非 CRT 站即使 `with_thermal_imager: true` 也不会出热成像）。
- 夜视滤镜只作用于世界画面，HUD/GUI 不上色（与本体热成像一致）。
- 打空爆/雨雪天气未单独适配：雨天画面会因噪点+增益略显发灰，属正常像增强表现。
