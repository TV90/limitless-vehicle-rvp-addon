## 1. 架构与实际入口

- `build.gradle:146` 当前依赖本体 `0.6.2-all`，`:165` 依赖 SimpleBedrockModel `2.6.0-forge-mc1.20.1`。
- 当前不是完全独立于本体的 SBM 渲染链。`RVP_VehicleRender.render` 先调用 `super.render`，之后追加光电干扰机玻片红光；主体仍执行本体 `VehicleRender` 及 RVP 对它的 Mixin。

## 2. 直接修改 SBM 类的两个入口

### 2.1 poly_mesh 默认单面材质

`BedrockModelRenderTypesMixin` 在 SBM `BedrockModelRenderTypes.polyMeshCutout` 的 HEAD 返回 `RVP_RenderTypes.polyMeshCutout`。

- 已用本地实际 2.6.0 mapped 依赖的 `javap` 核对：SBM 原材质为 `NO_CULL`，RVP 替换材质为 `CULL`。
- 此入口没有命名空间或 backend 判断，因此影响所有调用该 SBM 方法的模型，不仅限于 RVP 包。
- 当前普通及座舱专用透明材质也保持 `CULL`。不得把它们当成需要恢复的双面遗漏。
- `no_cull_bones` 是既有显式例外：普通主体绘制后，再用 `polyMeshCutoutNoCull` 绘制指定骨骼。当前该路径仅替换 poly_mesh 材质；cube 参数仍使用 `RenderType.entityCutout`。
- 尾焰、光晕、座舱屏幕的专用 `NO_CULL` 材质有各自用途，不能据此认定普通机体被改回双面。

证据：`mixin/BedrockModelRenderTypesMixin.java:12`、`client/render/RVP_RenderTypes.java:18`、`mixin/VehicleBedrockModelNoCullRenderMixin.java:48`（均相对 `src/main/java/org/ywzj/rvp/`）。

### 2.2 零缩放骨骼不可见优化

`BoneTreeInstanceInvisibleBoneMixin` 在 SBM `BoneTreeInstance.applyPose` 结束后检查骨骼：三个缩放分量均为 0 时，将该骨及子骨标记为不可见，避免仅缩成 0 仍提交绘制。它记录由自己隐藏的骨，并在缩放恢复时恢复可见性。此入口同样没有 RVP backend 限制。

证据：`src/main/java/org/ywzj/rvp/mixin/BoneTreeInstanceInvisibleBoneMixin.java:41`。

## 3. 修改本体 SBM 使用方式的入口

当前 `ywzj_rvp.mixins.json` 仍注册以下六个主要渲染 Mixin：

| Mixin | 当前职责 |
| --- | --- |
| `VehicleBedrockModelCockpitRenderMixin` | Overwrite 本体 `renderSpecialBones`，分流普通透明、座舱透明、炮口和屏幕骨 |
| `VehicleBedrockModelNoCullRenderMixin` | 对配置的 `no_cull_bones` 追加 poly_mesh 双面绘制 |
| `VehicleRenderCockpitPassengerContextMixin` | 为当前载具建立渲染上下文，并在首帧初始化模型实例 |
| `VehicleRenderCustomMountMixin` | 在本体渲染流程中追加自定义挂架 |
| `VehicleRenderStateHiddenBoneMixin` | 主体绘制前应用状态隐藏和距离隐藏规则 |
| `VehicleRenderLodMixin` | 按距离替换模型、实例及贴图，并在整模型 LOD 激活时跳过原动画 |

此外，`WeaponUnitDataMixin` 利用 SBM 结构骨补充 `rvp_structure_bolt_bones` 发射点；这属于结构数据与挂点扩展，不是对 SBM 渲染器本身的修改。当前实现已经不为空。雷达循环动画由 `RVP_RadarLoopSwitchableRunner` / `RVP_SwitchableRunnerFactory` 提供。

## 4. 半透明、座舱及屏幕的现行行为

- 普通透明：`cubeTransparent` / `polyMeshTransparent` 为透明混合 + `CULL`，未覆盖默认 write mask，仍写深度。
- 显式座舱修正：`special_bone_effects` 内配置 `ywzj_rvp_transparent_mode: "cockpit_depth_fix"`，且模型识别为 RVP backend 时，改用 `CULL + COLOR_WRITE + VIEW_OFFSET_Z_LAYERING`，保留深度测试但不写深度。
- 本地第三人称乘员：修正路径尝试先补画玩家，再画座舱玻璃；正常玩家绘制由 `RVP_RenderLivingHandler` 取消。
- 座舱屏幕：识别专用屏幕纹理，读取屏骨 mesh chunk，将 RenderTarget 纹理直接绘制到几何上。当前按模型 UV 采样，只有显式 `ywzj_rvp_screen_uv_mode: "fill"` 才归一化铺满。绘制关闭混合、使用正常深度测试并允许深度写入；附带剪裁、颜色等状态防御和 `/cockpitdiag` 取证。
- `RVP_VehicleBedrockModel` 另在开火照明生效时包装炮口材质的顶点消费者，提供烟雾受光几何；没有在该子类中重新实现整套玻璃排序。

证据：`client/resource/RVP_DisplayTransparentModeManager.java:32`、`mixin/VehicleBedrockModelCockpitRenderMixin.java:62`、`client/render/RVP_RenderTypes.java:60`、`client/render/RVP_CockpitPassengerRenderer.java:40`、`client/handler/RVP_RenderLivingHandler.java:31`。

## 5. 骨骼隐藏和 LOD

- `state_hidden_bones`：按状态及延迟隐藏骨骼，例如收起起落架。
- `distance_hidden_bones`：按距离隐藏细节，阈值受变焦状态影响。特殊透明骨被该规则命中时，目前改用 cutout 材质，并非直接让座舱表面消失。
- `lod_models`：远处采用独立的静态模型、贴图及绑定姿态，支持空中模型和变焦阈值；模型缓存，常规距离判断有 tick 节流。
- 规则缓存会检测本体 display map 的实例变化后重建；自定义挂架及 backend 缓存另有资源重载清理入口。

证据：`client/render/RVP_DistanceBoneHider.java:119`、`client/render/RVP_LodModelManager.java:229`、`mixin/VehicleRenderLodMixin.java:40`、`client/resource/RVP_CustomMountReloadListener.java:35`。

## 7. 已确认的维护问题与边界

1. **旧迁移文档与现行代码不一致。** `docs/plan/SBM迁移当前状态.md` 的最后提交为 2026-07-21，称若干 Mixin 已移除且完全由 RVP 原生渲染链替代；当前注册表和源码与此冲突。不能据此删除当前入口。`SBM迁移后续计划.md` 所称结构 bolt 扩展为空，也不符合当前实现。
2. **本地乘员补画存在事件取消冲突。** `RVP_RenderLivingHandler` 对需要自定义绘制的本地乘员取消 Pre 事件，而 `RVP_CockpitPassengerRenderer.java:94` 的补画仍调用正常 `PlayerRenderer.render`，没有补画上下文豁免。满足条件时补画也会被同一规则取消。此结论仅覆盖本地乘员分支，不能外推为所有远端玩家和生物消失的根因。
3. **当前没有完整的全局半透明排序修复。** 普通透明写深度，实际提交顺序仍能影响后方实体显示；座舱专用材质不能套用普通透明写深度的归因。已检查实际 Forge 47.4.13 mapped Minecraft 类：`BufferBuilder.setQuadSorting` 只在 `mode == QUADS` 时启用排序，而 `poly_mesh` 使用 `TRIANGLES`，所以单独设置 `sortOnUpload=true` 不会使三角面自动按远近重排。
4. **历史回退必须保留。** 2026-11-02 的交接已记录撤回两轮座舱排序实现并保留 `CULL`；本轮确认现行代码符合该回退形态，没有重新引入那套延后透明阶段。源码仍存在旧问题，不应把回退理解为已经解决所有座舱显示问题。

本轮未取得新的游戏帧事件和 draw 顺序记录，未将静态排序风险认定为用户某一实机场景的完整根因。
