# RVP 雷达搜索告警重构方案（每轮扫描响一声 + RWR 文字常亮 + 删除 RVP 机械扫描支持）

> 状态：已实施（2026-09-06），待实机验证
> 关联：`docs/RVP告警系统_地载与空载告警状态.md`、`docs/plan/RVP武器数据模型/RVP包新增参数字段说明.md` §3.2

---

## 1. 问题与根因

**症状**：玩家驾驶载具被 F-14（phase 雷达，`scan_period_tick=50`）照射时：

1. 搜索告警音 **1 秒 1 响**，与敌方雷达实际扫描周期无关；
2. RWR 上接触点的机型文字（如 "F14"）**1 秒一亮**（1000ms 线性淡出随刷新节奏闪烁）。

**根因（同源）**：本体 `RadarUnit.tickScan` 服务端固定 `vehicle.tickCount % 20 == 0`
（`RadarUnit.java:120`）每秒做一次独立扫描并向受害者发 `ServerVehicleWarn(RADAR_SEARCH)`，
客户端 `WarningReceiver.handle:55` 每包都播一次性告警音并写 targets：

- 该独立扫描**只有方位判定**（无高度窗/俯仰扇区门控）——受害者低于
  `scan_min_height`（25 格 AGL）或俯仰扇区外时，RVP 探测表（有门控）看不到它，
  RVP 中继不发包，targets 只有本体每秒一包在刷新 → 声音 1 秒 1 响 + 文字按
  1000ms 淡出窗每秒从全亮衰减到熄（`RVP_RadarOverlay.java:210-214`、本体
  `VehicleRadarOverlay.java:152` 同款公式 `alpha = 1 - min(1000, now-receivedTime)/1000`）。
- 即使在扫描体积内，本体每秒的"节拍"也与 phase 雷达的 `scan_period_tick` 脱节。

**附带问题**：RVP 对非 phase（mechanical）雷达的客户端支持（补 RVP 弹体/接触保活）
半吊子——不合并 `serverEntities`（BVR 盲区），体验不如纯本体雷达。

## 2. 用户决策（2026-09-06）

1. 搜索告警节奏 = **敌方雷达每轮扫描响一声**（首次接触立即响 + 仍在扫描体积内每
   `scan_period_tick` 再响；脱离即停）。
2. **保留 `scan_animation_mode` 参数**（`phase` 是 RVP 雷达路线的唯一开关，删参数会
   误伤本体包/其他载具包的雷达）；删除的是 **RVP 对机械扫描雷达的支持**——未配置
   phase 的雷达回到**纯本体行为**，RVP 客户端完全不干预。
3. 允许使用"不碰带毒类的 mixin"（公共 API 无法根治：`PlaySoundEvent` 只能截声音、
   截不了 targets 写入）。

## 3. 实施（零公共数组 Mixin）

### 3.1 删除 RVP 机械扫描支持

| 文件 | 改动 |
| --- | --- |
| `radar/RVP_ClientRadarTickHandler.java` | 非 phase 雷达（mechanical/默认）**完全跳过**：不再补 RVP 弹体/箔条/接触保活，保持纯本体 vanilla `tickDetect`/`tickTargets`；phase 雷达全扇区扫描+保活+`scan_period_tick` 节流不变；箔条锁定干扰判定保留对所有雷达生效 |

- 数据层（`RadarUnitPojoMixin`/`RadarUnitDataExt`/`RadarUnitPojoExt`/`RadarUnitDataMixin`）、
  服务端 `RVP_RadarScanService`（制导/告警基础设施）、`RVP_ExternalRadarSyncService`、
  渲染三处 phase 门控、调试命令 `mode=` 输出：**均不动**。
- 载具包 JSON：**均不动**（19 个 phase 配置原样）。

### 3.2 搜索告警全链路 RVP 接管

| 文件 | 改动 |
| --- | --- |
| `mixin/WarningReceiverSearchWarnMixin.java`（**新增**，注册于 `ywzj_rvp.mixins.json` client 数组） | `@Inject(HEAD, cancellable)` 于本体 `WarningReceiver.handle`：`warnType == RADAR_SEARCH` 直接 cancel（声音+targets 写入一并截流）；RADAR_LOCK/MISSILE_LAUNCH 不受影响 |
| `network/S2CRvpWarn.java` | 新增 `audible` 布尔字段（保留 4 参构造器重载默认 true，`RVP_MissileEntity` 旧调用点零改动） |
| `server/warn/RVP_WarnRelayService.java` | 响声调度器：静态状态表 `载具id:雷达id:目标id → 上次响声tick`。目标首次进入该雷达探测表 → `audible=true` 立即响；仍在表内每过一个扫描周期再响（phase = `scan_period_tick`，下限 10 tick；非 phase = 20 tick parity）；其余 5 tick 轮询 `audible=false` 仅刷新 targets；出探测表/雷达关机清状态自动停响 |
| `client/state/RVP_ClientWarnRelay.java` | 仅 `audible=true` 播一次性搜索音（500ms/源防御间隔兜底；保留"已有更高级告警不降级"守卫）；`audible=false` 只写 targets |
| `client/gui/RVP_RadarOverlay.java` | 机型文字淡出改**平顶曲线**：`receivedTime` 后 600ms 恒全亮（`SEARCH_TEXT_STEADY_MS`），600→1600ms 渐隐——中继每 5 tick 刷新后文字常亮不闪 |

## 4. 带毒安全与回退

- **Mixin 安全**：client 数组仅物理客户端应用，服务端不转换 `WarningReceiver`、无帧重算；
  目标方法 `handle` 本身 `@OnlyIn(Dist.CLIENT)`。新增前已逐级排除替代方案（本体 Channel
  无公共拦截事件；PlaySoundEvent 公共事件只能截声音）。
- **回退**：从 `ywzj_rvp.mixins.json` client 数组移除 `WarningReceiverSearchWarnMixin`
  即恢复本体原始告警链路（每秒响+闪烁回归，RVP 中继仍有 500ms 去重）。

## 5. 语义变化（同步记入《调试与修复规范.md》§4）

1. 搜索告警严格跟随敌方雷达真实扫描体积：体积外（如低于 25 格 AGL、俯仰扇区外）
   **不再收到假"被照射"**（不响也不闪）；体积内首次接触立即一声 + 每轮扫描一声。
2. 本体原生载具（非 phase 雷达）回到纯本体雷达行为；RVP 弹体不再显示在其雷达上
   （RVP 武器锁定/导弹告警链路不受影响）。
3. RWR 机型文字常亮（中继独家刷新 targets 后淡出恒在平顶区）。
