# 雷达车部署回归：只读排查（2026-11-02）

用户询问当前远程相机加载数量，以及 BUK-M3、IRIS-T SLM 雷达车无法部署是否与辅助载具改动有关。本轮只读核对代码和根配置，未修改载具包或发布源码。

## 已确认原因

根包 `data/rvp/vehicles/bukm3.json:79` 和 `irist_slm_tel.json:55` 的唯一 `deployable_uav_options` 候选均写 `initial_speed: null`。雷达模板分别为 `rvp:96l6`、`rvp:irist_slm_tads`，根包对应模板存在，role=radar_relay 本身可正常解析。

`RVP_DeployableUavOptionsParser.java:52` 使用 `GsonHelper.getAsDouble(option, "initial_speed", 0.0)`；默认值只处理缺少键，显式 JsonNull 报 `Expected initial_speed to be a Double, was null (json)`。第76行的异常兜底将整项返回null，导致两车候选列表均为空。客户端 `RVP_ClientEvents.java:552` 的 isConfigured 守卫因此阻止发送部署包；即使请求到服务端，`RVP_DeployableUavService.java:110` 仍会返回NO_CONFIG。

只读 Java 探针实际调用当前已编译解析器：

- BUK-M3：原件0项；仅内存副本 null→0.0 后1项，子车rvp:96l6、role=radar_relay。
- IRIS-T SLM：原件0项；仅内存副本 null→0.0 后1项，子车rvp:irist_slm_tads、role=radar_relay。

因此这是可确定复现的辅助载具候选配置迁移遗漏。最小修复为两处 initial_speed 改0.0，表示雷达车生成时不赋初速度；当前尚未执行修复。新候选解析器引入于55dfa6b0（2026-11-02 01:55 +0800）。不需要更改雷达角色、隐藏属性或本体源码。
