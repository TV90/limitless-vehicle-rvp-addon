# RVP 命中提示 UI：调研与设计方案

> 状态：调研完成，待评审
> 日期：2026-08-11
> 范围：仅修改 `ywzj_rvp`；`ywzj_vehicle` 只读参考（本方案不改本体代码）

## 1. 背景与目标

- 现状：RVP 弹药命中载具时，屏幕动作栏会弹出 `HBX <骨骼名> x倍率 (伤害前 -> 伤害后)` 的调试式消息（下称"动作栏 HBX"），体验偏 debug。
- 目标：做一个 RVP 自己的命中提示 UI，取代动作栏 HBX。功能与本体 `VehicleHitIndicatorOverlay`（被击中载具 3D 模型回放 + 受击部位射线 + 伤害文字）类似，但：
  1. 位置固定在**屏幕右上角**；
  2. 伤害显示为**百分比**（伤害 / 载具最大血量），而非真实伤害；
  3. 显示命中骨骼的**显示别名**（车辆 JSON `hitbox_display_name`，如 "炮塔"、"首上"）；
  4. 显示**受击弹药来源**（武器名）；
  5. 右上角加一块**展板**：黑边框、中间灰色 80% 不透明度，模型与射线在展板内显示、**不越界**（scissor 裁剪）；
  6. **展板比模型显示大一点**：模型展示尺寸与本体一致（scale 上限 10），展板相对模型显示区留白更足；
  7. 加一个参数（**载具 JSON 顶层配置**），**与本体的命中提示二选一**（启用 RVP 命中时本体命中提示不再显示）。

## 2. 现状调研

### 2.1 本体命中提示（VehicleHitIndicatorOverlay）完整链路

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 触发分级 | `ywzj_vehicle/vehicle/DamageSystem.java` L78-90 | `damageScale = amount / vehicle.getMaxHealth()`；`≥0.5` critical / `≥0.25` hurt / `>0` hit；不同级不同音效与 message |
| 事件构造 | `DamageSystem.java` L91-99 | `HitVehicleEvent(shooterUuid, vehicle.getId(), hitPos, projectile.getDeltaMovement(), caliber, amount, message)`，post 到 Forge 事件总线 |
| 网络包 | `network/message/ServerHitVehicleEvent.java` | 字段：shooterUuid / entityId / hitPosition / hitVector / caliber / damage / message |
| 客户端收包 | `ServerHitVehicleEvent.onServerMessageReceived` L72-121 | ①`AllConfigs.common.hitIndicator` 为 false 直接丢弃；②shooterUuid 匹配本地玩家才写入 `VehicleHitIndicatorOverlay.events`（>128 移除最旧）；③命中点生成白色 dust 粒子 + 弹孔（BulletHoleParticle，不受 events 影响） |
| 注册 | `client/ClientSetupHandler.onRegisterHud` L99 | `event.registerBelow(CHAT_PANEL, "vehicle_hit_indicator", new VehicleHitIndicatorOverlay())`，IGuiOverlay |
| 渲染 | `client/gui/VehicleHitIndicatorOverlay.render` L60-125 | 3 秒无新命中清空 events；取 `events[0]` 的实体（本地无则回退 `LocalVehiclePlayer.instance.serverEntities` 超视距实体）；`scale = min(10, 8/structureLength*10)`；由命中点相对载具位置算 pitch/yaw；锚点 `(screenWidth - screenWidth/8, screenHeight/2 + screenHeight/5)`；文字 + 红色总伤害数字；旋转缩放后 `EntityRenderDispatcher.render()` 渲染载具 3D 模型；每个事件用 `RenderType.lines()` 从命中点沿命中方向画 3 格红色射线 |

要点：
- 本体的"百分比"概念在服务端分级时已经用到（`amount / getMaxHealth()`），但 UI 显示的是真实伤害数字。
- 本体的 hitVector = 弹药的 `getDeltaMovement()`（入射方向）。
- 本体收包开关 `AllConfigs.common.hitIndicator` 是**本体 common 配置（服务端主控）**，RVP 无法也不应改动它。

### 2.2 RVP 现有命中显示

RVP 目前有两套"命中显示"，互相独立：

**A. 动作栏 HBX 消息（本次要取代的对象）**

- 发送方法：`RVP_VehicleHitboxFactorManager.maybeSendHitboxDebug`（L256-292），每玩家 250ms 限频，`player.displayClientMessage(msg, true)`，文本形如 `HBX 炮塔 x1.5 (10.0 -> 15.0) core=...`。
- 三处调用点：
  1. `RVP_BaseBullet.applyEntityHitDamage` L2229 —— RVP 弹体直击载具（主场景）；
  2. `RVP_VehicleHurtScalingHandler` L188 —— 通用伤害缩放挂钩（含近炸等非直击路径）；
  3. `RVP_LaserWeapon` L78 —— RVP 激光武器命中。

**B. F10 调试 Overlay（保留，与本次无关）**

- `S2CBulletVehicleHitDebug`（入射角/距离/各伤害倍率/骨骼原始名）→ `RVP_ClientBulletHitDebugState`（100 tick 存活）→ `RVP_BulletHitDebugOverlay`（屏幕上方居中文字）；由 `RVP_DebugOverlayState`（F10 键）控制。
- 发送点：`RVP_BaseBullet.applyEntityHitDamage` L2182-2195 → `RVP_BulletHitDebugNetworking.notifyVehicleHit`（NEAR 128 格）。

### 2.3 骨骼显示别名机制（已有，直接复用）

- 车辆 JSON 顶层配置块 `hitbox_display_name`：`{ "bone": "别名" }`。m1a2sep.json L64-93 已配置中文别名（如 `vehicle_body→车体侧面`、`turret→炮塔`、`Engine→发动机舱`、`aps_r→APS发射器(右)` 等）。
- 解析：`RVP_VehicleHitboxFactorManager.resolveHitboxDisplayName(vehicle, boneName)`（L294-306）→ 读 `VehicleHitboxConfig.aliasByBoneName`，无别名则回退原始骨骼名，null 回退 `"default"`。
- 服务端数据目录（`run/server/.../rvp/data/rvp/vehicles/*.json`）有该配置；**客户端无此数据**，因此骨骼显示名应在**服务端解析好后下发**。

### 2.4 弹药来源名

- `RVP_WeaponData extends BaseVehicleWeaponData`（`ywzj_vehicle/custom/weapon/data/`），`BaseVehicleWeaponData.getName()` 为翻译键（默认 `vehicle.weapon.unknown`）。
- 客户端用 `Component.translatable(weaponName)` 渲染即可本地化。

### 2.5 载具血量

- `AbstractVehicle` 继承 `LivingEntity`，客户端可直接 `entity.getMaxHealth()` 计算百分比。

## 3. 需求细化（来自用户确认）

1. 取代动作栏 HBX 命中显示。
2. 命中功能类似本体：显示被击中载具 3D 模型 + 受击部位射线 + 命中信息文字。
3. 位置：屏幕右上角。
4. 伤害显示：百分比（`伤害 / 载具最大血量`），不是真实伤害。
5. 显示命中骨骼的显示别名（复用 `hitbox_display_name`）。
6. 右上角展板：黑边框、中间灰色 80% 不透明度；模型和受击弹药来源在展板内显示，**不越界**。
7. 展示尺寸比本体钳制（`min(10, ...)`）**大一点**。
8. **新增参数：与本体命中提示二选一**（修正：此前"是否启用RVP的名称"表述错误，实为"是否启用RVP命中"）。

## 4. 设计方案

### 4.1 数据链路：新包 `S2CRvpHitIndicator`

沿用 RVP 网络注册（`RVP_Network.CHANNEL.messageBuilder` 递增 id）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| entityId | int | 被命中载具 id（客户端渲染模型） |
| hitPosition | Vec3 | 命中点世界坐标 |
| hitVector | Vec3 | 入射方向（`getDeltaMovement().normalize()`） |
| damage | float | 最终真实伤害（客户端算百分比） |
| boneDisplayName | String | 服务端用 `resolveHitboxDisplayName` 解析好的骨骼显示别名 |
| boneName | String | 骨骼原始名（备用显示） |
| ammoNameKey | String | 武器名翻译键（`resolveWeaponConfig().getName()`） |

发送：`RVP_BaseBullet.applyEntityHitDamage` 命中载具分支（L2182 附近），`owner instanceof ServerPlayer` 时用 `PacketDistributor.PLAYER` 仅发给射手本人（本体同款语义：只有自己打中自己看）。同时保留 F10 debug 包链路不动。

### 4.2 客户端状态：`RVP_ClientHitIndicatorState`

- 保存最近一次命中（与本体 `events` 列表不同，RVP 版取最近一次即可；多段伤害聚合可选，见 §6）。
- `DISPLAY_TICKS`（建议 100 tick，与 F10 debug 一致）；`clientTick()` 递减。
- 挂到 `RVP_ClientEvents.onClientTick`（现有 `RVP_ClientBulletHitDebugState.clientTick()` 旁）。

### 4.3 客户端 UI：`RVP_HitIndicatorOverlay`

- 渲染挂点：`RenderGuiEvent.Post`（RVP 现有 `RVP_BulletHitDebugOverlay` 同款模式，无需注册 IGuiOverlay）。
- 展板几何（建议，可调）：
  - 锚点：右上角，距右缘 12px、距顶缘 12px；宽 240、高 180。
  - 底色：`0xCC808080`（灰色 80% 不透明度）用 `GuiGraphics.fill` 填充。
  - 边框：黑框，四边各 1-2px 黑色 fill（或 `guiGraphics.fill` 描边）。
- 内容：
  1. **模型**：照抄本体渲染逻辑（`EntityRenderDispatcher.render` + pitch/yaw 旋转 + `Lighting.setupForEntityInInventory` + `RenderSystem.runAsFancy` + `guiGraphics.flush()`）；实体查找含超视距回退 `LocalVehiclePlayer.instance.serverEntities`。
  2. **尺寸**：模型展示尺寸与本体一致 `scale = min(10, 8/structureLength*10)`；展板 240×180，模型显示区（宽 224、高约 136）相对较小，留白更足、模型不会贴边（即"展板比模型显示大一点"）。
  3. **不越界**：渲染模型与射线前 `guiGraphics.enableScissor(展板矩形)`，渲染 + flush 后 `disableScissor()`。
  4. **红射线**：同本体 `RenderType.lines()`，从命中点沿入射反方向画 3 格。
  5. **文字**（展板内）：
     - 伤害百分比：`String.format("-%.1f%%", damage / entity.getMaxHealth() * 100)`，红色；
     - 骨骼显示别名：`boneDisplayName`（白/青）；
     - 弹药来源：`Component.translatable(ammoNameKey)`（白色）。
  6. 命中目标不存在（实体消失）时放弃渲染。

### 4.4 取代动作栏 HBX

- 删除 `RVP_VehicleHitboxFactorManager.maybeSendHitboxDebug` 方法及其私有依赖（`lastDebugAtMsByPlayer` 等）。
- 移除三处调用：`RVP_BaseBullet` L2229、`RVP_VehicleHurtScalingHandler` L188、`RVP_LaserWeapon` L78。
- **注意**：激光与通用伤害路径取消动作栏后暂无新 UI 反馈（新 UI 目前只覆盖 RVP 弹体直击）。是否把激光/通用伤害也接入新 UI 见 §6 决策点。

### 4.5 二选一参数：载具 JSON 顶层 `hit_indicator_rvp`

- **不做客户端 config**（用户确认放载具内），配置落在**被命中载具**的车辆 JSON 顶层：
  - `"hit_indicator_rvp": false` → 命中该载具时不发 RVP 命中包，走本体命中提示；
  - 缺省（默认 true）→ 命中该载具时发 RVP 命中包，客户端显示展板。
- 解析：`RVP_VehicleHitboxFactorManager.VehicleHitboxConfig` 新增 `boolean hitIndicatorRvp`，`parse` 读 `hit_indicator_rvp`（默认 true；其余字段全默认且该字段为 true 时才返回 null 配置）；新增 `isHitIndicatorRvpEnabled(vehicle)` 供服务端发包前查询。
- 服务端：`RVP_BaseBullet.applyEntityHitDamage` 命中载具分支，`isHitIndicatorRvpEnabled(targetVehicle)` 为 true 才向射手本人发送 `S2CRvpHitIndicator`。
- 客户端"二选一"：收到 `S2CRvpHitIndicator`（`RVP_ClientHitIndicatorState.push`）时**清空一次**本体 `VehicleHitIndicatorOverlay.events`，使本体命中提示不显示；未启用 RVP 命中的载具收不到包，本体照常显示。
  - 为什么用"清空 events"：本体收包开关 `AllConfigs.common.hitIndicator` 属本体 common 配置且在本体代码内检查，RVP 不可改；本体 UI 是已注册的 IGuiOverlay 无法拦截。清空其数据源是唯一不改本体的可行手段。
  - 副作用：本体 `ServerHitVehicleEvent` 收包生成的弹孔粒子/白色 dust 不受影响，仍正常工作。
- 注意：`hit_indicator_rvp` 由 `RVP_VehicleHitboxFactorManager`（ReloadListener）加载，修改载具 JSON 后需 `/reload` 生效；现有载具 JSON 缺省即默认开启，无需改动。

## 6. 待确认决策点

1. **多段伤害聚合**：本体会把同一次攻击的多次命中事件累加显示总伤害；RVP 版目前计划"最近一次命中"为准。若需要聚合，客户端 state 需改为事件列表并在 `DISPLAY_TICKS` 内合并。
2. **激光/通用伤害接入**：目前新 UI 只覆盖弹体直击；激光与近炸/通用伤害路径是否也要显示（需补 hitVector 数据源）。
3. **命中分级提示**：已按建议实现纯视觉分级——百分比 ≥50% 伤害数字红色、≥25% 黄色、其余白色（对应本体 critical/hurt/hit）。
4. **展板几何与显示时长**：240×180、100 tick 为初值，可后续按手感调。

## 7. 未完成问题记录（待修复）

> 记录日期：2026-08-11（提交时标注未完成，次日修复）

1. **直击且带爆炸的武器重复渲染弹体模型（BUG，未修）**
   - 现象：HE 等直击+爆炸武器命中载具时，展板内出现**两个弹体模型重叠**。
   - 根因分析：直击命中发一个命中包（bone 非空，weaponId 有值），爆炸波及同一载具时 [RVP_BaseBullet.triggerExplosion] 又补发一个爆炸命中包（bone 为空，weaponId 相同）。两个事件都处于飞行段且 `hasProjectileModel` 均为 true → 客户端对同一武器渲染两次弹体模型。
   - 修复方向（二选一，次日验证）：
     a. 客户端：爆炸事件（boneDisplayName 为空）飞行段不渲染武器模型，只渲染曳光；
     b. 服务端：爆炸补发包跳过直击载具（`directHitVehicleIds`），爆炸额外伤害并入直击包的 damage（需在直击发包后补充差值，改动较大）。
   - 涉及文件：`RVP_BaseBullet.java`（triggerExplosion 爆炸补发包）、`RVP_HitIndicatorOverlay.java`（renderHitAnimation 渲染分支）。
