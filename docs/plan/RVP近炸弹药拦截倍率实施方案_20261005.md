# RVP 近炸弹药拦截倍率实施方案与实施记录（2026-10-05）

> 状态：已实施，build+测试全绿+冒烟通过，已部署测试服，待实机验证。
> 需求（用户）：近炸对载具（AABB 膨胀相交，自身尺寸大）触发范围够用；对弹药目标（AABB 仅
> 1/16 格）等效触发距离太小，拦截几何窗口不足——加"对弹药的近炸拦截倍率"。

---

## 一、机制事实（调研结论，证据见代码行号）

- 近炸三处判定（锁定/探测盒/扫掠）全是 **AABB 膨胀相交**：`getBoundingBox().inflate(proximity_radius)`，
  半径来自 `fuse_data.proximity_radius`（回退 `explosion.proximity_radius`），无逐类差异。
- 载具"够用"纯因自身 AABB 大（半轴数格直接叠加触发距离）；弹药 AABB 1/16 格 → 等效≈radius 本身。
- **弹药目标触发即无条件强制引爆**（RVP_BaseBullet `detonateFuseAt` 弹药分支），无伤害数字结算——
  倍率只放大触发几何窗口，完全不碰伤害。
- `anti_torpedo` 分支（RVP_FuseData.java:69-70）是"按目标类别切换近炸行为"的结构先例，但无半径差异。

## 二、设计（用户定版）

- **新字段** `fuse_data.proximity_radius_ammo_factor`（float，缺键 = 1.0 = 全弹零变化）：
  目标为 **导弹/火箭/炸弹/鱼雷** 四类 RVP 弹药（`weapon_kind` 精确判）时，
  近炸触发半径 = `proximity_radius × factor`；载具/生物恒用原半径。**仅支持放大**（值域 ≥1，
  写入更小值按 1.0 生效——探测盒第一遍查询需保持旧版载具行为逐位一致，不支持缩小）。
- 用户定版：倍率目标口径 = RVP 弹药四类（不含机枪弹丸、不含本体 AmmoEntity）；
  现役配置 **仅 RIM-161（ddg51_rim161.json）与 HQ-9B（052d_hq9b.json）**（⚠️ RIM-161 是
  标准-3，不是 ESSM/RIM-162——实施中曾混淆，用户纠错），倍率 **2.0**（用户调定，初版 3.0
  经用户调整为"2 倍够了"）→ 对弹药等效触发距离 5 × 2.0 = **10 格**。

### 三分支改法要点（为什么这样保载具零变化）

1. **锁定分支**：本来就逐目标判定（`targetEntity.getBoundingBox().inflate(r).contains(弹体位置)`），
   直接换 `resolveProximityFuseRadius(targetEntity, radius)`——载具目标拿原值，零变化。
2. **探测盒分支**：命中即引爆、**无逐目标复检**——直接放大盒体会连带放大载具触发范围。
   故第一遍查询原样保留（载具+全部目标、原半径）；落空且 factor>1 时追加第二遍：
   放大半径构盒（`inflate(ammoRadius).move(lookAngle×-ammoRadius)`，向后偏移同口径放大，
   保留"捕获刚飞过目标"语义），谓词叠加"仅拦截类弹药"，诊断日志 `source=detection_box_ammo`。
3. **扫掠分支**：逐目标 `inflate` 天然支持（换单点解析）；外层 cull 盒按放大值预膨胀
   （`resolveProximityFuseMaxRadius`）防弹药候选被先剔除——载具候选多进循环但被原半径
   逐目标检查挡住，结果与旧版一致。
