# RVP PIP 攻角耦合：命中率下降根因与修复方案

日期：2026-10-11。审计基线：工作区 HEAD `55d8b100`，保留原有暂存改动。

状态：**用户已确认实施，2026-10-11 完成代码、自动化验证与专用服务端冒烟**。第 1～7 节保留审阅时的证据与方案，实际落地及验证见第 8 节。未修改武器 JSON、资源或本体，未提交 Git；尚未测量客户端实机交战命中率。

## 1. 结论

主因是 **PIP 输出语义与攻角执行器不匹配**：PIP 解出来的是期望速度方向，攻角接入后却把它直接当作期望机头方向，再依赖机头与速度之间的小攻角产生法向力。缺少“期望航迹 → 所需法向修正 → 机头攻角指令”的控制转换。

因此出现机头已经朝着预测点、速度却迟迟没有跟上的状态；目标横穿、转弯或末段预测点变化时，导弹来不及消除航迹误差。该机制由源码和隔离数学复现支持；具体用户场景中各因素的占比仍需实机逐 Tick 日志确认。

当前主配置盘点：`limitless_vehicle/rvp/data/rvp/weapons` 中有 87 个 `rvp:missile`，攻角上限全部为 60°；73 个主制导配置开启 PIP，其中 TOW-2B、TOW-2N、HJ-73E 三个 `turning_factor=1` 且无显式 G，常规飞行 Tick 豁免攻角。其余配置仍应结合制导阶段、智能引信和时序判断实际接入。当前已有 4 枚显式 G 配置，不能继续沿用早期“全体无 rvp_maxg”的统计。

建议先做 **PIP 专用的航迹到攻角控制适配**，保持气动模型与当前参数；随后独立修复无解回退。暂不全弹种改攻角/推力/G，也不把 PIP 整体改为比例导航 PN。

## 2. 源码证据链

### 2.1 回归入口：改了执行器，没有改制导输出契约

`b20084e9` 于 2026-10-07 接入攻角。

1. `RVP_GuidanceRuntimeMath.java:148`：开启攻角时令 `steeringFactor=1`，跳过旧速度预插值。
2. 同文件 `:160`：实体目标满足 PIP 门控时调用 `steerPredictiveIntercept`。
3. 同文件 `:553–597`：按当前弹速求解 `|r + v_target*t| = speed*t`，输出指向预测点的方向。这仍是恒速、可立即采用该航向的几何相遇解，没有使用机头状态、攻角响应或转弯时间。
4. 同文件 `:633–635` → `RVP_ProjectileMotion.java:46–59`：将这个方向直接交给 `RVP_AttackAngleModel.solve`，当前机头从 `getLookAngle()` 读取并持久保存。
5. `RVP_AttackAngleModel.java:43–60`：先插值机头，再计算 `λ=sin(α)/sin(α_limit)`，最后只施加 `availableG*λ` 对应的速度转角。

旧 RVP 的方向插值直接改变速度；新路径变为“插值机头 → 小攻角载荷 → 速度响应”。虽然已取消旧的速度预插值，却新增了具有状态的第二层响应。**这不是同一段 blend 被调用两次，而是控制对象改变后没有补偿。**

`turning_factor` 还同时参与两处计算：

- `RVP_AttackAngleModel.java:43`：未配显式 G 时，机头响应比例取 factor。
- `RVP_AeroSteeringModel.java:69–84,98–121`：factor 又通过 90° 离轴转角折算设计 G。

小误差、初始机头与速度同轴时，首步响应同时受这两处限制；低动压还会进一步缩小法向力。显式 G 弹不再由 factor 推导 G，机头响应固定 0.5，但期望速度方向被误当机头方向的问题仍然存在。

### 2.2 与本体对照：RVP 原先省略的一层现在变得必要

只读检查 `D:/WgameProject/ywzj_vehicle_fish/src/main/java/org/ywzj/vehicle/entity/weapon/MissileEntity.java`：

- `:681` 在算出 PIP 后调用 `calculateInterceptDirection`。
- `:690–705` 利用当前速度与推力加速度计算机头修正方向，正常分支为 `targetDir*k - missileVel`。
- 随后才求机头姿态。

RVP 的 `steerPredictiveIntercept` JavaDoc 也说明其早期适配省略了 thrust/mass，直接对速度 blend。对旧执行方式有意义，但不能原封不动延用于独立机头模型。

**不能直接复制本体补偿公式**：RVP 新模型同时有气动力转向与沿机头推力，本体的推力补偿公式不是现有 RVP 执行器的完整逆模型；滑翔时也必须可用。本体证据用于说明控制层缺失，而非要求修改或照搬本体。

### 2.3 60° 参数放大了弱响应

60° 在当前公式里既是姿态上限，也是升力归一化分母。对相同小攻角，放大上限会降低载荷，并不意味着更灵活。例如 α=1° 时，`λ=sin(1°)/sin(60°)=0.02015`，只使用约 2.0% 可用 G。

减小上限可能缓解小角度响应，但同时改变饱和范围、弹轴推力投影和诱导阻力，不能代替控制适配。也不建议全局提高 factor：它会同时改变机头响应和等效 G，并波及其他制导。

运行：

```powershell
python scripts/diagnostics/pip_attack_angle_diagnostic.py
```

## 4. 次要因素与独立问题

### 4.1 PIP 相遇时间不含转弯耗时：旧假设在新执行器下更脆弱

正根模型只使用当前弹速，未考虑当前航向、姿态响应、未来加减速或目标加速度。攻角后转弯路径更长，PIP 预估的相遇时间可能过短；推力加速则可能产生相反偏差，不能全局乘固定提前量倍数。

第一阶段先修控制契约；若日志仍显示系统性相遇时间偏差，再引入有限时域、限次数的动力学预测，避免一开始改预测器和执行器而无法归因。

### 4.2 无正根回退的 closingSpeed 重复计入弹速

`RVP_GuidanceRuntimeMath.java:587–589`：

```text
relVel = targetVelocity - missileVelocity
closingSpeed = missileSpeed - dot(relVel, LOS)
```

真正的瞬时径向闭速应为 `dot(missileVelocity-targetVelocity, LOS)`；当前式在这个量上又加了一次 missileSpeed。例如正向追击中弹速 5、目标速度 6，实际闭速是 -1，代码却得到 +4。它可能在不可追及时生成虚假的有限到达时间。

这是已有问题，本体当前同样存在，不是攻角提交新引入，也不是通常弹速大于目标速度、有正常正根时的主因。应独立修复：正闭速使用有界估计；闭速非正且无正根时明确返回不可解/纯追踪，不把 0.1 的分母下限当成物理可解证明。对于未来推进可能追上的情况，以受限前向预测作为后续增强。

### 4.3 制导门限和 PIP 暂停可放大脱靶，需要日志区分

- `passesGuidanceAngle` 仍按速度轴对当前目标/loft 点判定，超角时整个 Tick 拒绝常规自动制导。滞后导致近距 LOS 角迅速放大后，可能形成“来不及转 → 超角拒绝 → 更难追上”的链条。不能简单把轴全改为机头或放宽角度；要区分现有航迹限制与导引头视场的配置语义。
- `canUsePredictiveIntercept` 在诱饵干扰、起始 Tick 前、等待二脉冲时关闭 PIP。PL-15 等必须记录实际每 Tick 走的分支，避免把纯追踪段也算成 PIP 缺陷。
- loft 退坡/自主导引头截获会改变瞄准方向，攻角滞后可能放大接管误差。验收需同时有 loft 开/关场景。
- `predict_target_pos_gain` 虽被读入 active config，但未被当前 PIP 执行器消费；只调这个 JSON 值不会修复当前响应。

### 4.4 引信确有一处机头/速度假设，但不能泛化成主因

`RVP_BaseBullet.java:2814,2849` 的运动后补检盒用 `getLookAngle()` 向后偏移，攻角后它不再等于飞行反方向。因此该补检覆盖区域会变化。已有 `tryAmmoProximityFuze` 仍按运动线段扫掠，锁定目标的驻留检查也按位置工作，不能声称全部碰撞因机头偏转而失效。

建议在独立碰撞一致性检查中让“捕获刚飞过目标”的补检以实际位移/速度方向为基准，零速再回退机头；同时核对碰撞前路径与运动阶段沿机头推力后的实际位移。没有实机失败轨迹前，不把这一项与主修复捆绑。

## 5. 推荐方案：PIP 航迹控制适配，保留攻角物理

### 5.1 改动边界

仅在 `PIP 实际生效 && usesAttackAngle(projectile)` 时接入。数据门控，不硬编码弹种 ID。IR/AIR/ARH/SARH 以及 SACLOS STABLE 只要走同一实体 PIP 入口即可共同受益。

建议新增纯数学辅助类 `RVP_PIPAttackAngleController`，由 `RVP_GuidanceRuntimeMath.applyIntent` 的 PIP 分支调用。保留原 `RVP_AttackAngleModel` 的姿态、G、动压、转角、攻角锥和载荷裁决。普通追踪、GPS/PRESET、TV/HITL、干扰及无目标回正不在第一阶段改变。

当前虚拟积分器生成的是 GPS/PRESET 固定点方向，并未在该处调用实体 PIP。因此局部接入无需把虚拟固定点制导强行改为 PIP；若后续扩大至共享求解器语义，则必须同步虚拟积分与版本兼容策略。

无需新增 Mixin、Accessor、网络包或改本体；第一阶段无需新增 JSON 字段或改资产。

### 5.2 控制链的具体职责

1. **预测器只产出几何解**：PIP 返回预测点/期望航迹方向，保留 t 与有效性供诊断；这一层不改变机头或速度。
2. **外环决定本 Tick 所需航迹修正**：未配显式 G 时先按原 nlerp/factor 契约生成希望达到的速度方向，但仅作为请求，不提前写速度；显式 G 分支按既有 G 优先规则生成请求。按同 Tick 动压 G 与转角上限裁决请求，保持不同弹种机动预算。
3. **把速度修正换成所需攻角**：在速度轴与请求方向所成平面里，用现有执行器反解机头侧向偏角。滑翔、小转角的起始公式如下：

   ```text
   Δv_cmd = 2 * speed * sin(δ_cmd / 2)
   λ_cmd = clamp(Δv_cmd / (availableG * G), 0, 1)
   α_cmd = asin(λ_cmd * sin(α_limit))
   ```

   这是反解初值，不是可以无条件直接套用的最终公式：还要处理 0 G/零速，以及现模型“速度最多转到机头”的上限。动力段需将沿机头推力产生的法向增量纳入同一预测，不能先按气动力给足修正，再漏算推力额外转弯。优先使用当前纯数学执行器做有界单步试算，固定迭代上限，不扫描未来整条弹道。
4. **补偿机头内环响应**：不能再把 α_cmd 当方向直接送入原 0.1 响应并期望立即达到它，否则又削弱一遍。按当前 body 和原响应比例反解求解器输入方向；超过可达姿态范围时限幅，并用前向试算确认实际结果。三维近反向、零响应和饱和必须有确定性回退；第一阶段不引入积分项，避免饱和累积。
5. **只执行一次实际攻角积分**：试算不得写实体/载荷。选出的指令只调用一次正式攻角求解，按现有方式持久化机头、记录真实 λ，运动阶段沿机头推进并扣一次诱导阻力。不要再叠加一次旧速度 blend 或直接把速度强行对准 PIP。

这使 factor 在外环保有可解释的航迹响应基准，同时通过有界逆响应解决内环重复衰减；G、动压和姿态可达性仍决定实际能做到多少。具体有界反解的精度、推力期稳定性需以回归结果定稿，不能仅凭公式宣称命中率已恢复。

### 5.3 建议实施顺序

1. 先把本轮隔离场景转成直接调用 Java 纯数学模型的连续 Tick 回归，用失败案例固定基线；补 PIP 正根/退化/无根测试。
2. 实施局部控制适配，先验证滑翔，再覆盖点火、燃烧、燃尽和二脉冲接管；武器参数保持不变以便归因。
3. 单独修正 closing-speed 回退及不可解分支，不掺杂参数重平衡。
4. 扩展现有生命周期诊断，实机 A/B；若仍有 t 估计偏差，再评估有限预测。近炸补检和角门限按日志另案处理。

## 6. 备选与不推荐路线

| 路线 | 作用 | 代价 / 判断 |
| --- | --- | --- |
| 只关闭 `rvp_attack_angle_limit_deg` | 回到保留气动 G/阻力的无攻角路径，适合单弹 A/B 和临时回退 | 丢失机头/速度分离；仅在用户同意改测试配置后执行 |
| 关闭 `rvp_aero_steering` | 同时关闭攻角与气动模型 | 混入多个变量，不适合隔离攻角根因 |
| 全体 60° 改小 | 提高同一小攻角的 λ | 同时重定义升力斜率、姿态上限和能量，不是控制契约修复 |
| 加大 factor/G 或推力 | 部分场景修正更快 | 掩盖接口失配，改变全弹种机动/能量平衡 |
| 全局放大 PIP 的 t | 某些横穿场景提前更多 | 正负偏差不同，可能过度提前或振荡 |
| PIP 改为 PN/ZEM 类制导 | 后续可直接生成法向加速度请求 | 属于制导算法重构，仍需攻角执行器适配；不建议与此次最小修复捆绑 |

术语说明：当前 PIP 是预测拦截点算法，不是经典基于 LOS 角速度的比例导航 PN；文档里“比例引导 PIP”的旧称不能当作已有 PN 控制环。

## 7. 验收标准

- **数学闭环**：直接使用 Java 的相遇解、攻角和推进工具；首交会相对运动最小距离、终端航迹误差、G/角速率/攻角上限及诱导阻力次数同时验证。先要求恢复本报告可达、匀速横穿案例的旧基线量级，再对更大矩阵统计；不可达目标允许失败但不得 NaN、凭空增速或突破预算。
- **动态场景**：静止/横穿/迎头/尾追，目标平滑转弯与极端反转；距离 100/300/600/1000，高度 64/320/550/1000；多种弹目速比、初始离轴与残留机头偏角。极端反转用于稳定性，不作为必命中指标。
- **武器代表**：AIM-120D、PL-15、IR 近距弹、显式 G 的防空弹、SACLOS STABLE；包含有无 loft、主燃烧/滑翔/二脉冲等待与接管。旧无攻角分支、瞬转弹、GPS/PRESET 和手动 TV 不产生额外行为改动。
- **诊断字段**：实际制导分支、PIP 是否可用及拒绝原因、相遇时间/求根状态、PIP 点、速度方向误差、机头指令、实际攻角、请求/实际法向修正、availableG、速度、动力阶段、角门限、最近距离和最终引信事件。复用现有生命周期日志，诊断关闭不增加昂贵试算以外的日志成本。
- **实机命中与数学脱靶分开**：引信按真实半径、目标碰撞体和离地门限判定，不能用 `proximity_fuse_height` 充当近炸半径；同时记录碰撞/近炸/寿终/丢锁结果。
