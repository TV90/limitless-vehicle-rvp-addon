# RVP 船转向 depth 倍率因子 —— 方案与提示词（2026-10-01）

## 一、问题

`VesselVehicle.tickMove()` 用 `mainCubeOBB.depth`（结构模型主 cube 的 Z 尺寸）算转向角速度：

```java
// VesselVehicle.java:113-116
if (maxTurn > 0 && mainCubeOBB.depth > 0) {
    float yawStep = (float) Math.toDegrees(Math.atan2(
            motion * rudder / maxTurn * (forwardSpeed < 0 ? -1 : 1),
            mainCubeOBB.depth)) * 0.2f;
    yawStep = Mth.clamp(yawStep, -maxTurn, maxTurn);
    setYRot(getYRot() + yawStep);
}
```

但**`mainCubeOBB` 同时是碰撞体**，缩它会让整船碰撞一起缩：

| 职责 | 依据 |
|---|---|
| 方块碰撞采样 | `PhysicsEngine.collectContacts()` 的采样点 = `physicsCube().cubePoints()`，`physicsCube() == getMainCubeOBB()` |
| 载具 / 实体互撞判定 | `AbstractVehicle.push():1420` `OBB mainCubeOBB = getMainCubeOBB().obb();` → `OBB.isColliding(vehicle.getMainCubeOBB().obb(), mainCubeOBB)` |
| 实体包围盒 | `makeBoundingBox():818` 并入 `mainCubeOBB.obb()` |
| 流体采样 | `tickPower()` / `AbstractVehicle:571` |
| 转向 depth | `VesselVehicle.tickMove():114` |

⇒ 052D 主 cube 长 120.78 格，直接缩到 12 格会让"两艘船互相穿过、贴岸探不到方块"。**必须只缩放转向用的那个 depth，不动碰撞。**

## 二、方案

在 RVP 侧加一个**只影响转向计算的 depth 倍率**：

1. **配置项**：载具 JSON 的 `physics_info.turn_depth_scale`（float，缺省 `1.0`，≤0 视为 1.0）
2. **消费点**：`VesselVehicle.tickMove()` 里 `mainCubeOBB.depth` 的字段读取（**只有 113/114 两行**）
3. **实现方式**：MixinExtras 的 `@ModifyExpressionValue` 单点缩放该字段读取
   - ❌ 不用 `@Overwrite`
   - ❌ 不用整段 `@Redirect`
   - ✅ 不碰 `push()`、不碰 `collectContacts()`、不碰 `makeBoundingBox()` ⇒ **碰撞行为与不配时逐字节一致**

## 三、提示词（可直接复制）

```
【任务】在 RVP 侧实现「船的转向 depth 倍率因子」，要求只影响转向计算，完全不改变碰撞。

【背景】
- 本体类 org.ywzj.vehicle.entity.vehicle.VesselVehicle 的 tickMove() 里，转向角速度由
  mainCubeOBB.depth 决定（该字段只在方法内 113/114 两行被读取）。
- 但 mainCubeOBB 同时承担碰撞职责：PhysicsEngine.collectContacts() 的采样点、以及
  AbstractVehicle.push() 里载具互撞判定（OBB.isColliding(vehicle.getMainCubeOBB().obb(), mainCubeOBB)）。
- 所以绝对不能在结构模型上缩小这个 cube；只能缩放「转向计算里读到的那个 depth 值」。

【要实现的东西】
1. 新增 RVP 扩展配置项：载具 JSON 顶层 physics_info.turn_depth_scale（float，缺省 1.0）。
   - 解析位置：org.ywzj.rvp.config.RVP_VehicleExtendedConfigManager
     仿照现有 parsePhysicsOnlyBones(JsonObject) 的写法（在 physics_info 对象里取字段），
     加入 VehicleExtendedConfig（或等价的不可变配置载体），并提供按载具查询的静态入口。
   - ⚠️ 必须把该字段纳入 parseVehicle 的"全空即 EMPTY"早退判定
     （RVP_VehicleExtendedConfigManager.java parseVehicle）——否则只配 turn_depth_scale、
     无其它扩展配置的载具会被早退成 EMPTY，配置静默失效（2026-10-01 审计修正）。
   - 语义：实际用于转向的 depth = mainCubeOBB.depth × turn_depth_scale；值 ≤0 或缺省时按 1.0。
   - tickMove() 实测仅服务端执行（AbstractVehicle.tick 分端，服务端分支才调 tickPhysics(tickMove())），
     配置只需服务端可用，无客户端同步要求（2026-10-01 审计实证）。
2. 新增 Mixin（放在 org.ywzj.rvp.mixin 下，与现有 Mixin 风格一致）：
   @Mixin(value = VesselVehicle.class, remap = false)
   目标方法："tickMove"，用 MixinExtras 的
   @ModifyExpressionValue(at = @At(value = "FIELD", opcode = Opcodes.GETFIELD, remap = false,
        target = "Lorg/ywzj/vehicle/vehicle/structure/VehicleCubeOBB;depth:D"))
   把读到的 double 乘以该载具的 turn_depth_scale 后返回（handler 签名 double rvp$xxx(double)）。
   - ⚠️ depth 实测为 `public double`（VehicleCubeOBB.java:31，旁证 AbstractVehicle:627 的
     `(float) mainCubeOBB.depth` 显式窄化）——描述符必须是 D 不是 F，handler 必须是 double；
     写 F 会匹配失败直接 InjectionError 崩溃（2026-10-01 审计修正）。
   - @Mixin / @ModifyExpressionValue / @At 三处都要 remap = false（mod 类非混淆，
     现有 RVP mixin 同风格）。
   - 注意 tickMove 内 depth 有两处读取（`depth > 0` 判定 与 atan2 的分母），都会被这条规则覆盖，这是预期行为。
   - 允许使用 MixinExtras（本体已引入 mixinextras.init.mixins.json）。
3. 在 RVP 的 mixin 配置 json 里登记该 Mixin（参照现有条目的写法）。

【硬约束】
- 禁止 @Overwrite；禁止整段 @Redirect；改动限定在上面的单点表达式重写。
- 目标类必须双端安全：不得直接引用 @OnlyIn(CLIENT) 的成员（本方案不涉及）。
- 不得修改本体仓库（ywzj_vehicle）任何文件。
- 不得改动碰撞相关路径（collectContacts / push / makeBoundingBox / tickPower）。

【自测验收】
- 配 turn_depth_scale = 1.0（或不配）时，船转向手感与改动前完全一致。
- 052D（主 cube depth = 120.78 格，航速 0.75 格/tick）配 turn_depth_scale = 0.083：
  满舵掉头一圈从 5056 tick（253 秒）降到约 419 tick（21 秒），
  等效于 depth = 10 的手感。
- 碰撞不受影响：两艘同配置船相撞仍能正常判定碰撞；贴岸行驶时不会因
  depth 倍率而改变与方块的接触行为。
- 编译：rvp 侧 compileJava 通过；本体 jar 未改。
```
