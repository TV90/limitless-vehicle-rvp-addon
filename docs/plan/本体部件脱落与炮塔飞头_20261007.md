# 本体「部件脱落 / 炮塔飞头」机制 + 给 RVP 加上的做法（2026-10-07）

> 目的：给 RVP 载具加上「死亡爆炸 → 炮塔飞出去」的效果。
> 结论先行：**这是纯数据驱动的功能，本体已实现完整链路，RVP 没有任何拦截 —— RVP 看不到飞头，唯一原因是载具 JSON 里没写 `render_bone`。**

## 一、本体是怎么实现的（全链路 + file:line）

### ① 死亡入口（只服务端）

`ywzj_vehicle/src/main/java/org/ywzj/vehicle/entity/vehicle/AbstractVehicle.java:633-643`

```java
if (this.getHealth() <= 0) {
    if (isDestroyed()) {
        this.discard();                       // 已销毁 → 再被打就移除
    } else {
        this.getPassengers().forEach(Entity::stopRiding);   // 乘员全部下车
        setDestroyed();                       // :1402  进残骸态
        VehicleExplosion vehicleExplosion = new VehicleExplosion(
                level(), damageSource.getEntity(), this, this.position(),
                (float) mainCubeOBB.depth / 2,               // 半径 = 主物理 cube 的 depth/2
                AllConfigs.common.vehicleExplosionHurtPassengerDamage.get().floatValue(),
                false, false);                                // 不破坏方块、不掉落
        vehicleExplosion.explode(Collections.singletonList(this));
        VehiclePartSpawner.spawnDestroyedParts(this);          // ★ 飞头在这
    }
}
```

- `setDestroyed()`（`:1402-1405`）：置 `DESTROYED=true`、`destroyedTick=0`。残骸**存活 60 秒**后 `discard()`（`:539-541`）。
- 爆炸**不破坏地形**、只对实体结算杀伤（半径只跟主 cube 的 depth 相关，跟观瞄/模型尺寸无关）。

### ② 脱落派发

`ywzj_vehicle/.../util/VehiclePartSpawner.java:12-28`

```java
for (PartUnit<?> partUnit : vehicle.getPartUnits()) {
    if (!partUnit.isDetachable()) continue;          // ★ 只有"可脱落"的部件才飞
    VehiclePart vehiclePart = partUnit.detach();     // 生成独立实体
    if (vehiclePart == null) continue;
    vehiclePart.setDestroyed();                      // 残骸态（冒烟、亮度变暗）
    vehiclePart.setDeltaMovement(flingVelocity(vehicle, partUnit));   // ★ 初始速度
    vehicle.level().addFreshEntity(vehiclePart);
}
```

**初速度**（`VehiclePartSpawner.java:33-48`）：

```
方向 = normalize( 部件枢轴世界坐标 − 载具中心世界坐标 + 小随机 )
速度 = physics_info.destroy_explosion_velocity + random(0..0.2)     // 单位：格/tick
```

### ③ 部件怎么"拆"出来

`ywzj_vehicle/.../vehicle/part/PartUnit.java:497-527`（`detach()`）

- 取该部件的**最大 cube**，算出它在世界坐标里的**底面中心**作为新实体落点；
- 朝向：`RotatableUnit`（炮塔/武器站）用 `worldRot()` ⇒ **炮塔保持死前的朝向飞出去**；其它部件用载具朝向；
- 新建 `VehiclePart` 实体 —— 它 `extends AbstractVehicle`，**自带 OBB / 重力 / 摩擦 / 渲染**，是一个完整载具实体（`VehiclePart.java:85-88` 给它 mass=1000、friction=2000）；
- 原部件标记 `detached = true`。

⇒ 视觉上：**炮塔从底座处断开，沿"载具中心 → 炮塔枢轴"方向被抛出去，然后自由落体/翻滚、落地成为残骸**（`tickMove()` 返回 0，但不影响重力，物理引擎照常施加重力）。

### ④ 客户端表现

| 位置 | 作用 |
| --- | --- |
| `client/render/entity/vehicle/VehicleRender.java:162-180` `applyDetachedPart()` | 已脱落的部件 → 把它的 render bone 在主载具模型上 `visible = false`（主车身上不再画炮塔）。正常态 `!isDetached() && !rendersBone()` ⇒ 仍可见，**没副作用** |
| `client/render/entity/vehicle/VehiclePartRender.java:50-79` | `modelInstance.renderSingleBone(boneIndex, ...)` —— **只画 render bone 的整棵子树**；`excludedBoneNames` 里那些"挂在它下面、且自身也可脱落"的子部件骨会被隐藏（它们自己会变成独立实体）；残骸态亮度 ÷1.5 |
| `VehiclePart.java:237-257` `collectExcludedBoneNames()` | 递归决定哪些子部件骨要从这个残件里排除 |
| `VehiclePart.java:160-180` `tickParticle()` | 残骸前 5 秒喷尘云，之后每 20 tick 冒残骸烟 |

## 二、开关在哪（判定式）

`PartUnit.isDetachable()` —— `PartUnit.java:538-539`

```java
return data.isDetachable()          // ← JSON: "detachable"     缺省 true
    && renderBoneName != null
    && !renderBoneName.isBlank()    // ← JSON: "render_bone"    缺省 null ★唯一开关
    && structureGroup != null;      // ← 由 "structure_bone" 在结构模型里解析得到
```

| 要素 | JSON 字段 | 缺省 | 定义处 |
| --- | --- | --- | --- |
| 可脱落开关 | **`detachable`** | **`true`** | `custom/part/data/PartUnitPojo.java:35-36` |
| 渲染骨 | **`render_bone`** | **`null`** | `custom/part/data/PartUnitPojo.java:29-30` |
| 结构骨 | `structure_bone` | — | `PartUnitData.initStructureModel()` |

**两个硬前提**：

1. `render_bone` 必须非空 —— **这是 RVP 唯一缺的东西**；
2. `structure_bone` 指向的骨**必须在结构模型里存在、且该骨下有 cube**（`detach()` 靠"最大 cube"算落点，拿不到 cube 直接 `return null`，不生成实体）。

⚠️ `render_bone` 填的是**渲染模型**里的骨名，不是结构骨名：
- 本体 m1a2 的渲染骨就叫 `turret` ⇒ 填 `"turret"`；
- **RVP 坦克的炮塔渲染骨是 `$weapon0`** ⇒ 要填 `"$weapon0"`；
- 填错名字不会报错：实体照样生成，但客户端 `modelInstance.getIndex()` 返回 -1 ⇒ **隐形残件**（看不见但会撞/会挡），加完必须核对骨名。

## 四、给 RVP 加飞头的具体做法（零代码、零 Mixin）

### 1. 给要飞的部件补 `render_bone`

在 `limitless_vehicle/rvp/data/rvp/vehicles/<车>.json` 里，找到对应 part 条目加一行：

| 部件 | `render_bone` 填什么 | 效果 |
| --- | --- | --- |
| `turret`（主炮站） | **`$weapon0`** | 炮塔 + 炮管整棵子树一起飞出去（经典飞头）|
| `commander_machine_gun`（二号位） | **`$weapon1`** | 二号位机枪站单独飞 |
| `commander_laser`（激光站，ZTZ100/ZTZ99B） | **`$weapon2`** | 激光站单独飞 |
| `turret_machine_gun`（同轴机枪） | 一般**不填** | 它没有独立渲染骨，跟着 `$weapon0` 走 |

> 骨名一律来自该车的**渲染模型**（`assets/rvp/models/bedrock/entity/<车>.json`）；可用 `scripts/parse_bone_tree.py` 或直接读 json 核对。

### 2. 保持 / 关闭 detachable

- 想飞：`detachable` **不用写**（缺省就是 true）；
- 不想飞（例：轮子、不想乱飞的观瞄件）：显式 `"detachable": false`。

### 3. 调飞行距离

`physics_info.destroy_explosion_velocity`（缺省 `0.5`，单位格/tick，`PhysicsInfo.java:33`）：

```jsonc
"physics_info": {
  "mass": 54000,
  "friction": 108000,
  "can_destroy_block": true,
  "destroy_explosion_velocity": 0.5     // 0.4 偏含蓄 / 0.8~1.2 飞得很夸张
}
```

### 4. 已验证的兼容性（不需要改代码）

- RVP 载具死亡**同样走**本体 `AbstractVehicle.hurt()`（`RVP_BaseBullet` 内部也是调 `DamageSystem.hurt`，`RVP_VehicleHurtScalingHandler` 只在 `VehicleAttackEvent` 里做伤害折算）⇒ 死亡分支必然执行，`VehiclePartSpawner` 必然被调用；
- RVP 的 `RVP_WreckSmokeEmitter` / `RVP_WreckCookoffController` **只作用于载具本体**，脱落的 `VehiclePart` 继续用本体自己的尘云 + 残骸烟；
- `RVP_RemoteVehicleVisibilityPolicy` 已把 `VehiclePart` 归类为地面载具（超视距可见性有处理）；
- `AbstractVehicleClientMixin` 注释明确：脱落残件 `VehiclePart` 覆写了该方法且不调 super，**不受 RVP 注入影响**。

### 5. 建议的落地顺序

1. 先只给 **1 台**加（建议 ZTZ99B 或 VT4），进游戏打爆验证：炮塔是否带正确朝向飞出、落点/翻滚是否自然、`destroy_explosion_velocity` 是否合适；
2. 确认后批量铺到坦克族（vt4 / ztz100 / ztz99b / t90m / t84bm / m1a2sep / abramsx / bmpt72 …）；
3. 顺手决定那 4 台轮式车（cssa5/lav25/lavad/zbl08a）的轮子**要不要飞** —— 现在的行为是"飞轮子"，与本体 m1a2 的 `detachable: false` 不一致。

### 飞头时不渲染 `turret_muzzle_flash`（VT4 已落地）

**问题**：脱离的 `VehiclePart` **不跑动画控制器** —— `VehiclePartRender` 只调 `applyVehicleRotation` + `renderSingleBone`，而 `VehiclePart` 并未实现 `IAnimationEntity`；所以平时靠 `static` 动画压成不可见的 `turret_muzzle_flash`（96×96 / 128×128 的贴图面片）会在飞头后按静置姿态显示出来。RVP 的 `state_hidden_bones` 也救不了：它是注入在 `VehicleRender.render` 上的，`VehiclePartRender` 是另一个 `EntityRenderer`。

**本体没有"排除某根骨"的字段**，但有一条纯数据迂回路线 —— **幽灵部件**：

```jsonc
// vt4.json  parts 末尾新增（不动原有座位序）
{
  "id": "muzzle_flash",
  "name": "muzzle_flash",
  "type": "ywzj_vehicle:generic",
  "detachable": true,                      // 必须 true（false 会改走递归，不产生排除项）
  "render_bone": "turret_muzzle_flash",    // 要排除的渲染骨
  "structure_bone": "ERA_PAOTA2",          // turret 的"零 cube"直接子骨
  "is_seat": false
}
```

原理（本体源码）：`VehiclePartRender` 会隐藏 `VehiclePart.getExcludedBoneNames()`，该表由 `VehiclePart.collectExcludedBoneNames(被脱离部件)` 遍历**它的 `attPartUnits`**（= 结构骨层级上的直接子骨）生成；子部件 `isDetachable()` 为真就把它的 `render_bone` 加进排除表。

三个必要条件（缺一不可）：
1. `structure_bone` 在结构模型里**存在**（→ `structureGroup != null` → 才可能 `isDetachable()`）；
2. 该结构骨是 **turret 的直接子骨**（→ 进 `attPartUnits`）；
3. 该结构骨 **零 cube**（→ `detach()` 的 `getLargestCube()` 为 null → **返回 null，不生成多余实体**，只贡献排除项）。

**已逐行模拟验证（VT4）**：
- turret 的 `attPartUnits` = `[smoke_l, smoke_r, commander_machine_gun, aps_r, aps_l, top, turret_bellow, turret_side, muzzle_flash]`
- **飞头时 `excludedBoneNames = ['turret_muzzle_flash']`** ✅
- `isDetachable` 的部件只有两个：`turret`（2 cube → **会飞出**）、`muzzle_flash`（**0 cube → 不生成实体**）✅
- 座位序不受影响 ✅


### 为什么 VT4 / ZTZ99B 能做、T-90M 不能？（根因：结构模型里有没有"零 cube 的 turret 直接子骨"）

幽灵部件要求 `structure_bone` 同时满足 **①turret 的直接子骨 ②零 cube**，而这两点完全取决于建模时怎么组织结构骨：

| 车 | turret 直接子骨（cube 数） | 零 cube 子骨 |
| --- | --- | --- |
| VT4 | `aps_radar(0)`、**`ERA_PAOTA2(0)`**、`top(1)`、`turret_bellow(1)`、`turret_side(4)`、`turret_barrel(1)`、`smoke_r(1)`、`smoke_l(1)`、`commander_machine_gun(1)`、`aps_r(1)`、`aps_l(1)` | ✅ 有 2 个 |
| ZTZ99B | **`ERA_PAOTA2(0)`**、`top(1)`、`ERA13(1)`、`ERA14(1)`、`turret_bellow(1)`、`turret_side(2)`、`turret_barrel(1)`、`smoke_r(1)`、`smoke_l(1)`、`weapon2(1)`、`weapon1(1)` | ✅ 有 1 个 |
| T-90M | `top(2)`、`turret_bellow(1)`、`ERA6~ERA12(各1)`、`turret_side(4)`、`turret_barrel(1)`、`smoke_r(1)`、`smoke_l(1)`、`commander_machine_gun(1)` | ❌ **无** |

**差别就一处**：VT4 / ZTZ99B 的炮塔爆反多了一层**分组骨 `ERA_PAOTA2`**（自己不放 cube，只给 `ERA3~ERA12` 当父节点）；而 T-90M 的 ERA 块**直接挂在 `turret` 下**，没有这层分组骨 —— 于是它 14 个子骨全带 cube，找不到"零 cube 的 turret 直接子骨"。

> 这也解释了为什么"零 cube"是硬条件：非零 cube 的骨头会让幽灵部件在死亡时真的 `detach()` 成功，凭空多飞出一个渲染炮口焰的残件。

## 七、谁会被炸飞？（当前实测 + 想做"分散飞"的改法）

### 现状：只飞一整块主炮塔

判定只看一条：**该部件有没有 `render_bone`**（`isDetachable()`）。目前三车只有 `turret` 配了 ⇒ 只会生成 1 个残件实体；炮塔上挂的东西**全都跟着它一起飞**，不分散：

| 部件 | 有 render_bone？ | 结果 |

### 想让它"分散炸飞"：给对应部件补 `render_bone` 即可

同样是纯数据，而且**会自动从主炮塔残件里排除**（因为它变成了 turret 的可脱落子部件，进 `excludedBoneNames`）。模拟结果：

| 车 | 现状：飞出实体 / 炮塔残件额外排除 | 加 `commander_machine_gun:"$weapon1"`（+ 99B 激光 `$weapon2`）后 |
| --- | --- | --- |
| VT4 | `turret` ／ `[turret_muzzle_flash]` | `turret` + `commander_machine_gun` ／ `[$weapon1, turret_muzzle_flash]` |
| T-90M | `turret` ／ `[]` | `turret` + `commander_machine_gun` ／ `[$weapon1]` |
| ZTZ99B | `turret` ／ `[turret_muzzle_flash]` | `turret` + `commander_machine_gun` + `commander_laser` ／ `[$weapon1, $weapon2, turret_muzzle_flash]` |

要件都满足（三车的二号位结构骨 `commander_machine_gun` / `weapon1` 都是 **turret 的直接子骨且各带 1 cube**）⇒ 会真的各自生成独立残件实体。
代价：每多一个残件 = 多一个带 OBB + 物理的实体（开销很小）。
