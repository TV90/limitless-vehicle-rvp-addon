## 1. 故障机制

OpenGL 是显卡当前实际采用的状态；Minecraft 的 `RenderSystem` / `GlStateManager` 另外保存一份状态记录，用于省略重复操作。DH、RVP 的离屏模型绘制和屏幕特效都会使用这些状态。

旧 `RVP_DhGlStateScope.close()` 通过原生 OpenGL 恢复深度、混合、纹理等，却没有同步引擎记录。例如：

1. 进入 DH 作用域前，实际深度写入开启。
2. 作用域内通过引擎关闭深度写入，实际值与缓存都变为关闭。
3. 旧实现退出时只恢复实际值为开启，缓存仍记录关闭。
4. 后续再次请求“关闭深度写入”，引擎认为已经关闭，省略调用；显卡仍然开启。

旧冲击波作用域也存在同类恢复缺口，并且没有保存混合方程和独立采样器。混合方程决定新旧颜色是相加、相减还是取最大值；独立采样器可以覆盖纹理自身的过滤规则。

光照与冲击波都会输出**已经包含背景的完整颜色**，应该关闭混合直接写回。旧实现只调用 `RenderSystem.disableBlend()`；如果缓存记为关闭、实际却开启，这次关闭会被跳过。残留减法混合可以把相同的源背景和目标背景相减成黑色。纹理或深度状态不一致也会进一步干扰场景复制和后续绘制。

这个机制依赖此前各绘制通道的调用顺序，符合偶发、特效活跃时出现的表现。不过，没有采集到用户故障帧的实际混合方程，不能把测试构造的减法方程当作现场记录。

## 6. 高度变化后的根因：过载滤镜与两份不同的混合状态

### 用户现象与本体生命周期对应

新增反馈：同一载具平地开火不黑；高度发生变化后再开火，DH 远景或未加载地形外的背景变黑，天空有黑块；下车再上车恢复。

只读核对本体 `LocalVehiclePlayer.tickOverload()`：载具不在地面时激活 `OverloadHandler`；后续回到地面时直接返回，没有关闭已经激活的滤镜。离车时才调用 `setActive(false)`，并清理后处理链。这解释了“改变高度后开始触发”和“上下车恢复”，不需要把根因归为 DH 数据或某种武器。

本体 `OverloadHandler.onRenderLevel()` 在普通优先级 `AFTER_LEVEL` 执行。RVP 光照在同一事件的高优先级运行，冲击波也会在世界结束阶段运行，因此它们会与本体后处理连续交接。

只读依据：`D:/WgameProject/ywzj_vehicle_fish/src/main/java/org/ywzj/vehicle/vehicle/LocalVehiclePlayer.java:149`（地面提前返回）、`:159`（激活）、`:607`（离车关闭）；`D:/WgameProject/ywzj_vehicle_fish/src/main/java/org/ywzj/vehicle/client/shader/OverloadHandler.java:70`（滤镜事件）。本次没有修改这些本体文件。

### 为什么近景正常，而天空和 DH 黑

`BlendMode.lastApplied` 是 Shader/Effect 共同使用的“上次申请了哪种混合模式”的 Java 记录，**它不等于显卡现在是否开启混合**。Minecraft 的 RenderType 会在 Shader 之外开关实际混合，因此两者本来就可能不同。

RVP 默认不透明 Shader 的 `apply()` 会改变这份记录。先前只恢复了真实 GL 和 RenderSystem 缓存，却没有归还进入作用域前的原始记录。本体过载程序随后发现模式变化，重新启用了 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` 混合。

Alpha 是透明度通道。天空、未绘制地形外的背景及部分 DH 合成像素可以有正常 RGB 颜色、但 Alpha 为零；不透明近景通常 Alpha 为一。过载 pass 的输出目标刚被清成黑色，错误地开启 Alpha 混合后：

```text
Alpha=0 的背景：原颜色 × 0 + 黑色 × 1 = 黑色
Alpha=1 的近景：原颜色 × 1 + 黑色 × 0 = 原颜色
```

这与用户描述的空间分布一致。即使 `Progress=0`、并没有真实黑视，也能发生；关闭 DH 后仍有 Alpha 为零的背景，因此不是只有 DH 才会触发。
