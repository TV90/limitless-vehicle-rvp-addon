# RVP APS（主动防护系统）骨骼属性改造方案

> 阶段：实施（方案 B：传感器/发射器分离）。将现有「载具顶层 `rvp_aps` 配置 + 载具级全局系统」的 APS 改造为
> 「`bone_modules` 骨骼模块 + 骨块存活判定」的骨骼属性，与已落地的干扰器（JAMMER）同一套框架。
> 文档时间：2026-08-10（v2：传感器与发射器骨骼分离、发射器不设失效、新增探测范围可视化 debug）
>
> 需求确认记录：
> - 左右独立模块 + 扇区化扫描（每个模块有自己的探测扇区：facing + fov + range）。
> - **方案 B（双模块独立）**：传感器骨块（探测、失效点）与发射器骨骼（拦截弹火焰起点/动画锚点）分离。
> - **发射器骨骼暂不设失效**：发射器骨块被打掉不影响 APS，仅作拦截弹火焰起始点与开火动画锚点。
> - 新增 debug 命令：低频粒子可视化干扰机干扰范围与 APS 扫描锥体轮廓。

## 1. 背景与需求

用户需求（APS 骨骼化 + 探测/发射分离）：

- APS 做成骨骼属性：载具 JSON 的 `bone_modules` 里声明 APS 传感器模块，传感器骨块被击毁（APS 模块失效）后该侧探测能力丢失。
- **左右独立模块 + 扇区化**：每个传感器模块（左/右）各自拥有独立的探测扇区，左侧模块只负责左侧来袭的弹药，右侧模块只负责右侧来袭的弹药。左侧传感器被打掉后，左侧扇区失去拦截能力，右侧仍正常工作。
- **传感器与发射器骨骼分离**：传感器骨块（探测失效点）与发射器骨骼（拦截弹火焰起始点/开火动画锚点）是两个不同骨骼。发射器骨骼暂不设失效。
- **探测范围可视化 debug**：输入命令后，干扰机干扰范围与 APS 扫描范围的锥体低频生成粒子显示轮廓，便于调参。
- 删除旧的 `rvp_aps` 顶层配置链路，避免双配置源。

架构约束（与干扰机一致）：

- 纯 Forge 服务端可运行，不新增实体 mixin，不触碰本体 ywzj_vehicle。
- 复用已泛化的模块状态/持久化/同步链路（`BoneModuleType` 枚举 + `RVP_BoneModuleStateTable` + `RVP_EraStateSavedData` + `S2CBoneModuleState` + `RVP_ClientBoneModuleState`）。

## 2. 现状调研摘要

### 2.1 现有 APS（旧链路，待删除）

- 配置：载具 JSON **顶层** `rvp_aps` 对象 → `VehicleDataManagerMixin.ywzj_rvp$parseApsConfig` → `RVP_ApsConfig` → `RVP_ApsConfigCache`（按载具 id 缓存）。
- 运行期：`RVP_ApsEventHandler.onServerTick` 服务端每 tick 遍历所有 `AbstractVehicle` → `RVP_ApsRuntimeManager.tick`。
  - `tick`：冷却递减 → 装填 → HUD 同步 → 扫描 `findTarget`（`detect_radius` AABB + 速度区间过滤 + 按速度排序取最快）→ 可选 `intercept_delay_tick` 延迟 → `fireInterceptor`。
  - `fireInterceptor`：取 `spawn_part_id` 武器部件 → 校验 `indexedWeapons[0]` 为 `VehicleGrenade` 且 `grenade=="aps"` → 出膛位置 `worldCurrentBoltPosition()` → `interceptProjectiles`（目标位置 `intercept_radius` 球内全部消灭）→ `S2CApsFlameLink` 特效 + `ServerVehicleFire` 动画。
  - `neutralizeProjectile`：RVP 弹体 → `rvp$detonateByAps()`；HBM 导弹 → `RVP_RadarContactHelper.neutralizeHbmMissile`；其余 → `discard()`。
- 状态：载具级 `ApsState`（ammoCurrent / reloadProgress / cooldownRemaining / animationCursor / pendingTargetId）→ `RVP_ApsStateSavedData`（SavedData `rvp_aps_state`，按 UUID 侧表）→ `S2CApsHudSync` → 客户端 `RVP_ApsHudState` + `RVP_ApsHudOverlay`。
- 注意：现有 APS 不真正发射 `ActiveProtectionGrenadeEntity` 实体，发射器只当"挂架锚点 + 类型校验"，拦截是「直接半径消灭 + 纯特效」。

### 2.2 骨骼模块系统（干扰机已落地，改造模板）

- 配置：载具 JSON 顶层 `bone_modules` → `RVP_VehicleHitboxFactorManager.apply` → `VehicleHitboxConfig.parse` → `parseBoneModuleMap` → `BoneModuleConfig.parse`（含 `BoneJammerConfig.parse(obj.get("jammer"))`、`BoneApsConfig.parse(obj.get("aps"))`）。
- 状态：`RVP_BoneModuleStateTable`（UUID → 骨块名 → 失效模块类型集合，只存失效），`isModuleActive(vehicleId, boneName, type)`；失效来源：直击 `tryDestroyBoneModules`（全类型）、爆炸 `destroyModulesByExplosionRadius`（仅 `participatesInBlastDestruction()`，当前仅 ERA）。
- 同步：`RVP_EraStateSavedData` 持久化 + `S2CBoneModuleState` 网络包 + 客户端 `RVP_ClientBoneModuleState` + `EntityContextEraStateMixin.rvp_isModuleActive(bone, type)`（动画脚本接口，已按类型泛化）。
- 干扰机运行期：`RVP_JammingRuntime.tickAndResolve` → `resolveJammerDevices(vehicle)`（按 `vehicle.getVehicleId()` 取 `moduleByBoneName` 中 `jammer()!=null` 的条目）→ `isModuleActive(..., JAMMER)` 判存活。干扰范围几何 = `resolveFacing(facing_part + facing_yaw)` 前向 + `fov` 半角 + `range` 距离，与 APS 扫描锥同构。

### 2.3 本体 APS（武器型）动画联动机制（调研结论）

本体 APS 是**武器**（`launcher_aps_grenade`，`grenade:"aps"`），发射真实 `ActiveProtectionGrenadeEntity` 实体，其模型动画联动链路：

```
客户端开火 → ClientVehicleAction(shoot) → 服务端 WeaponUnit.shoot()
→ VehicleGrenade.shoot 生成 APS 拦截弹实体（40mm 手雷小模型 + 烟尾迹 + 整车物理后坐）
→ 广播 ServerVehicleFire → 客户端 post VehicleFireEvent.Post
→ VehicleRender.onFire → offerEvent("{部件id}_fire") → 控制器 event_animations 映射
→ 播放 bedrock 开火动画（骨骼后坐 position/rotation + 炮口火焰骨骼 scale 闪烁）
→ 每帧 applyAnimationPose blend 到模型
```

要点：

- 开火动画由 bedrock 骨骼动画驱动（无 fireTick 字段），事件名为 `{部件id}_fire`（如 `aps_right_fire`）。
- 炮口火焰是模型特殊骨骼（如 `turret_muzzle_flash`，控制器 `special_bone_effects` 声明），由开火动画控制 scale 显隐，加法混合贴片渲染。
- 本体 APS 现状：m1a2sep/vt4/abramsx 控制器 `event_animations` 未配置 `aps_right_fire`/`aps_left_fire`，APS 发射时实际无发射器骨骼动画，视觉全靠拦截弹实体。
- RVP 侧已复用通用链路：`fireInterceptor` 发送 `ServerVehicleFire` → 客户端会 offer `aps_right_fire`/`aps_left_fire`；火焰起点 = `WeaponUnit.worldCurrentBoltPosition()`（发射器骨骼 bolt 位置），**正好满足「拦截弹火焰起始点设在发射器骨骼」**。若需发射器开火动画，在控制器 `event_animations` 增加 `"aps_right_fire": [...]` 即可，属模型侧资源调整，本方案不改。

### 2.4 RVP debug 命令现状

服务端命令统一挂在 `/rvpdebug`（`RVP_ServerDebugCommands.onRegisterCommands`，`RegisterCommandsEvent`），已有 `dualpulse`/`bonehide`/`projectilelife`/`uav`/`radar`/`topattack` 子命令。可视化范围轮廓命令按同风格追加。

## 3. 改造设计

### 3.1 模块类型

`BoneModuleType` 枚举新增 `APS`：

- 不参与爆炸百分比破坏（与 JAMMER 一致：仅被直击 `tryDestroyBoneModules` 打掉；爆炸只波及 ERA）。
- 模块状态/持久化/网络/客户端侧表已按类型泛化，新增枚举值即自动兼容。

### 3.2 新建 `BoneApsConfig`（仿 `BoneJammerConfig`）

位于 `org.ywzj.rvp.vehicle`，record 结构，从 `bone_modules` 骨块条目的 `aps` 子对象解析。

**模块语义（方案 B）**：`bone_modules` 条目挂在**传感器骨块**名下（如 `aps_sensor_right`），该骨块是被命中打掉后的失效点；`launcher_part` 引用**发射器武器部件**（如 `aps_right`），仅作为拦截弹火焰起始点与开火动画锚点，**不参与失效判定**。

字段表（JSON key → record 字段 → 默认值）：

| JSON key | 字段 | 默认 | 说明 |
|---|---|---|---|
| `launcher_part` | `launcherPart` | null | 发射器武器部件 id（如 `"aps_right"`），必填；缺省视为未启用 |
| `facing_part` | `facingPart` | null（车体朝向） | 探测扇区朝向跟随的部件 id（如 `"turret"`），取 `WeaponUnit.worldVec()`；未配置/不存在退回车体朝向 |
| `facing_yaw` | `facingYawDeg` | 0.0 | 扇区朝向水平偏置角（度，正值向左）。右侧模块 `-90`、左侧模块 `+90` 分覆盖左右扇区 |
| `scan_fov` | `scanFovDeg` | 120.0 | 探测扇区**全角**（度），半角 = fov/2，用于 `withinAngle` 判定 |
| `detect_radius` | `detectRadius` | 32.0 | 探测距离（格） |
| `intercept_radius` | `interceptRadius` | 8.0 | 拦截球半径（格），目标位置周围 |
| `ammo_max` | `ammoMax` | 0 | 弹药上限；0 → 模块未启用（`isEnabled` 判定） |
| `reload_one_tick` | `reloadOneTick` | 600 | 每发装填所需 tick |
| `cooldown_tick` | `cooldownTick` | 20 | 拦截后冷却 tick |
| `intercept_delay_tick` | `interceptDelayTick` | 0 | 锁定到拦截的延迟 tick（0 = 立即） |
| `scan_interval_tick` | `scanIntervalTick` | 10 | 扫描节流间隔 tick |
| `projectile_speed_min` | `projectileSpeedMin` | 1.0 | 可拦截弹体速度下限 |
| `projectile_speed_max` | `projectileSpeedMax` | 80.0 | 可拦截弹体速度上限 |
| `exclude_owner_projectile` | `excludeOwnerProjectile` | true | 排除本车发射的弹体 |

解析规则（同 `BoneJammerConfig.parse`）：非 JsonObject/null → null；数值 `GsonHelper.getAsDouble/getAsInt` 取默认；非负钳制；`isEnabled()` = `launcherPart != null && ammoMax > 0`。

### 3.3 解析接入

- `RVP_VehicleHitboxFactorManager.BoneModuleConfig`：新增 `@Nullable BoneApsConfig aps` 字段；`parse` 处追加 `BoneApsConfig.parse(obj.get("aps"))`。
- 新增 `resolveApsDevices(AbstractVehicle)`（仿 `resolveJammerDevices`）：按 `vehicle.getVehicleId()` 取配置 → 遍历 `moduleByBoneName` 收集 `aps()!=null` 的条目为 `Map<骨块名, BoneApsConfig>`；无则 null。**骨块名 = 传感器骨块名**，即失效锚点。

### 3.4 运行期改造 `RVP_ApsRuntimeManager`

保留：载具级 `ApsState`（弹药/冷却/装填/动画游标）、`RVP_ApsStateSavedData` 持久化、`S2CApsHudSync` → 客户端 HUD、`rvp$detonateByAps`/`neutralizeHbmMissile`/`discard` 拦截链、`S2CApsFlameLink` + `ServerVehicleFire` 特效动画。

改造点：

1. **配置来源**：`RVP_ApsConfigCache.get(vehicle.getVehicleId())` 替换为 `resolveApsDevices(vehicle)`。
2. **存活过滤**：对 `devices` 逐骨块（传感器骨块名）查 `isModuleActive(vehicle.getUUID(), boneName, BoneModuleType.APS)`，得到「存活传感器模块列表」；为空 → `maybeNotifyDisabled` 推送禁用快照（HUD 隐藏）并 return。
3. **系统参数**：弹药/冷却/装填仍载具级共享；配置参数（`ammo_max`、`reload_one_tick`、`cooldown_tick`、`detect_radius`、`intercept_radius`、速度区间等）取「存活模块中第一个」（按骨块声明顺序）。
4. **扇区归属**：对每个存活传感器模块：`resolveFacing`（`facing_part` + `facing_yaw`，复用 `RVP_JammingRuntime` 的 public 静态方法）得到模块前向 `front`；目标相对车体位置需满足 `dist <= detect_radius` 且 `withinAngle(front, toTarget, scanFov/2)` 才归该模块。目标归第一个命中扇区的存活模块；无命中扇区 → 不拦截。
5. **拦截发射**：`fireInterceptor` 使用「归属模块」的 `launcherPart` 武器部件出膛（火焰起点）+ 动画，固定归属发射器；`getGrenadeWeapon` 的 `grenade=="aps"` 校验保留。**发射器骨块不参与 APS 失效判定**（打掉不影响）。
6. **HUD**：有存活模块才推送 `S2CApsHudSync`；模块全灭时停止推送（服务端节流推送 0/0/1/0 禁用快照），客户端 `RVP_ApsHudOverlay` 在 `ammoMax<=0` 时隐藏。

### 3.5 删除旧链路

- `VehicleDataManagerMixin`：删除 `rvp_aps` 解析块（`ywzj_rvp$parseApsConfig`、`RVP_ApsConfigCache.put` 调用），mixin 其余部分不动。
- 删除文件：`RVP_ApsConfig.java`、`RVP_ApsConfigCache.java`。
- `RVP_ApsRuntimeManager` 内不再引用上述两类。

### 3.6 载具 JSON 迁移

三处运行数据包目录同步修改（`run/server`、`run/client_1`、`run/client_2` 下 `limitless_vehicle/rvp/data/rvp/vehicles/`）：

- **m1a2sep.json / vt4.json / abramsx.json**：删除顶层 `rvp_aps` 对象；`bone_modules` 新增**传感器骨块**条目 `aps_sensor_right` / `aps_sensor_left`（abramsx 另含 `aps_sensor_right2` / `aps_sensor_left2`），通过 `launcher_part` 关联发射器部件。
- 发射器部件 `aps_right`/`aps_left`（及 abramsx 的 `*2`）**不再挂 `aps` 模块** → 骨块被打掉不导致 APS 失效。
- 各车保留原有数值（m1a2sep/vt4：`scan_interval_tick 1`、`projectile_speed_max 6.0`、`intercept_delay_tick 0`；abramsx：`scan_interval_tick 1`、`projectile_speed_max 8.0`、`intercept_delay_tick 6`）。

```json
    "modules": ["aps"],
    "aps": {

      "facing_part": "turret",

```

### 3.7 客户端

- `EntityContextEraStateMixin.rvp_isModuleActive(bone, "aps")` 已泛化：被打掉的传感器骨块可直接在动画脚本中隐藏。
- `RVP_ApsHudOverlay`：模块全灭（服务端推送 ammoMax=0）时隐藏 HUD。
- 发射器开火动画：如需，在控制器 JSON `event_animations` 加 `"aps_right_fire": [...]`、`"aps_left_fire": [...]`（模型侧资源，本方案不涉及）。

### 3.8 探测范围可视化 debug 命令（新增）

在 `/rvpdebug` 下新增子命令 `scanviz`，三态：`/rvpdebug scanviz on` / `off` / `status`。

- 服务端按玩家 UUID 保存开关状态（`RVP_CoverageDebug` 静态侧表）。
- 启用后，服务端每 `COVERAGE_REFRESH_INTERVAL`（建议 20 tick ≈ 1 秒）遍历启用玩家，对玩家所在载具：
  - **APS 扫描锥体**：`resolveApsDevices(vehicle)` 每个传感器模块 → `resolveFacing(facing_part, facing_yaw)` 前向 + `scan_fov/2` 半角 + `detect_radius` 距离 → 锥体轮廓撒粒子（类型 `END_ROD` 或 `SOUL_FIRE_FLAME`，与干扰机区分）。
  - **干扰机干扰锥体**：`resolveJammerDevices(vehicle)` 每个干扰机模块 → 同构几何（`fov/2` + `range`）→ 锥体轮廓撒粒子（类型 `FLAME`）。
  - 仅给启用玩家本人发送（`sendParticles` 指定接收者或使用 `player.level().sendParticles(...)`），不广播。
- 锥体轮廓绘制：顶点 = 载具位置（或部件锚点），底面圆心 = 顶点 + `facing * range`，底面半径 = `range * tan(halfAngle)`。在底面圆周取 N 点（短距离 12 点、长距离按比例降密），母线（顶点→圆周点）插值若干粒子；每帧刷新时起始角递增，形成低频流动轮廓。
- 干扰机 `range` 默认 2000 格，粒子密度按距离自适应（避免超远距离粒子过密）。
- 命令注册在 `RVP_ServerDebugCommands.onRegisterCommands`；tick 驱动可挂 `ServerTickEvent`（服务端）。

## 4. 行为验证要点

1. 左/右侧来袭弹药：左侧传感器拦截左侧扇区目标、右侧拦截右侧扇区目标，互不越界。
2. 左侧传感器骨块被直击打掉（APS 模块失效）→ 左侧扇区不再拦截（左侧来袭弹穿过），右侧仍正常拦截。
3. 发射器骨块（`aps_right`/`aps_left`）被打掉 → **不**影响 APS 拦截，火焰起点/动画锚点失效但功能保留（当前设计：发射器不设失效）。
4. 两侧全灭 → HUD 隐藏、APS 完全失效。
5. 弹药载具级共享：左右模块共用 `ammo_max` 弹药池，拦截消耗后按 `reload_one_tick` 补充。
6. `/rvpdebug scanviz on` 后，玩家乘载具时看到干扰机（FLAME）与 APS（END_ROD/SOUL_FIRE_FLAME）锥体轮廓粒子；`off` 后停止。
7. 持久化：载具重进世界后弹药/冷却/装填恢复；模块失效状态已由既有骨骼模块链路持久化。
8. 服务端安全：无新增实体 mixin；旧 `rvp_aps` 配置从所有载具 JSON 移除后，无残留引用。
