# 战术地图雷达整合调研方案

## 1. 结论

可以做到，而且现有代码基础已经足够支撑大部分需求，不需要改 `ywzj_vehicle` 本体。

本轮需求可以拆成两部分：

1. **战术地图显示本机/当前武器站雷达的扫描扇面、扫描线、锁定连线**
2. **战术地图上的敌对/中立目标与弹药改为“必须被雷达探测后才显示”，友军与友军弹药仍实时显示**

其中第 1 部分的可行性很高，因为现有 `RVP_RadarOverlay` 已经有完整的雷达扇区、扫描线、锁定线、扫描动画频率与颜色逻辑；战术地图只需要把同一套参数投影到世界地图坐标即可。

第 2 部分也可以做，但它不是简单改渲染，而是要给战术地图增加一层“**探测门控**”：

- 友方/己方：继续实时显示
- 敌方/中立载具：只有进入本机雷达 `detectedObjects` 后才显示
- 敌方/中立弹药：只有进入本机雷达 `detectedObjects` 后才显示
- 若目标脱离探测，则按雷达 `contact_hold_tick` 或默认 hold 时间短暂保留，再从战术地图消失

## 2. 现有代码基础

### 2.1 战术地图现状

战术地图主界面在：

- `src/main/java/org/ywzj/rvp/client/screen/RVP_TacticalMapScreen.java`

当前 `renderMap()` 的主要绘制顺序是：

1. 地形图块
2. 网格
3. GPS 弹药虚线
4. 本地弹药
5. 远程弹药缓存
6. 本地载具
7. 远程实体
8. 玩家与己方载具
9. GPS 点与 HUD

对应代码入口：

- `renderMap()`
- `renderLocalProjectiles()`
- `renderRemoteAmmoCache()`
- `renderLocalVehicles()`
- `renderRemoteEntities()`

当前问题是：战术地图会直接枚举本地实体和远程缓存，因此**敌方/中立目标默认就是“全图实时可见”**，还没有雷达探测门槛。

### 2.2 雷达 UI 现状

雷达 HUD 主逻辑在：

- `src/main/java/org/ywzj/rvp/client/gui/RVP_RadarOverlay.java`

它已经实现了：

- 雷达扇区绘制：`drawRadarSector(...)`
- 扫描线绘制：`drawScanLine(...)`
- 扫描角度计算：`ywzj_rvp$computeScanAngle(...)`
- 锁定目标时取消扫描线，改为目标连线
- 雷达颜色、透明度、半径缩放
- 多雷达支持
- `NCTR` 标签显示

换句话说，**你要的视觉语义其实已经在 HUD 雷达里有一套成熟实现了**。

### 2.3 雷达探测数据现状

雷达探测与保持逻辑在：

- `src/main/java/org/ywzj/rvp/mixin/RadarUnitMixin.java`

当前已经具备：

- 雷达周期扫描
- 目标高度限制
- 扇区限制
- `detectedObjects` 保持时间
- 锁定目标
- 对 `rvp:missile` / `rvp:bomb` 的扫描纳入

也就是说，战术地图想做“只有被雷达扫到才出现”，**不需要自己重新算一遍雷达扫描**，而是直接读取 `RadarUnit.getDetectedEntities()` 即可。

## 3. 需求拆解

### 3.1 战术地图上的雷达扇面

目标效果：

- 在小飞机/直升机图标机头前，绘制一片与真实雷达一致的扇面
- 扇面半径取 `max_scan_distance`
- 扇面角度取 `y_rot_min ~ y_rot_max`
- 扇面方向取当前雷达朝向
- 颜色和透明度与正式雷达一致
- 缩放随小地图 `blocksPerPixel` 自动变化

这部分本质是把雷达 HUD 的“屏幕极坐标圆”改成“战术地图世界坐标扇形”。

### 3.2 战术地图上的扫描线动画

目标效果：

- 扫描线频率与正式雷达一致
- 如果雷达正在扫描，则在战术地图扇面里显示扫描线
- 如果雷达已经锁定目标，则取消扫描线
- 改为绘制“己方载具 -> 锁定目标”的实线

这部分也可以直接复用 `RVP_RadarOverlay` 的扫描角度计算逻辑，避免出现 HUD 和战术地图不同步的问题。

### 3.3 探测门控显示

目标效果：

- 友军载具：实时显示
- 友军弹药：实时显示
- 敌对载具：必须被雷达扫到后才显示
- 中立载具：必须被雷达扫到后才显示
- 敌对弹药：必须被雷达扫到后才显示
- 中立弹药：必须被雷达扫到后才显示

这个需求本质上要求战术地图从“世界态势图”改成“**雷达态势图 + 友军实时图层**”。

## 4. 推荐实现架构

## 4.1 新增一层战术地图雷达接触集

建议在 `ywzj_rvp` 客户端新增一个轻量雷达接触快照层，例如：

- `RVP_TacticalRadarContactCollector`

职责：

- 从当前玩家载具的全部 `RadarUnit` 读取 `detectedObjects`
- 归并成战术地图可直接消费的接触对象列表
- 为每个接触对象保留：
  - `entityId`
  - `entityRef`
  - `detectedPosition`
  - `fromRadarId`
  - `detectedTime`
  - `isLocked`
  - `isAmmo`
  - `relation`

这样战术地图就不用直接碰 `RadarUnit` 细节，只消费统一的“可见接触目标”集合。

## 4.2 战术地图新增雷达扇面层

建议在 `RVP_TacticalMapScreen.renderMap()` 中，在 marker 层之前插入：

1. `renderRadarCoverage(guiGraphics, partialTick)`
2. `renderRadarLockedLinks(guiGraphics)`

推荐绘制顺序：

1. 地形图块
2. 网格
3. **雷达扇面**
4. **雷达扫描线 / 锁定线**
5. GPS 弹药虚线
6. 实际 marker
7. 选中高亮与 HUD

原因：

- 扇面是背景信息，应该在 marker 下方
- 锁定线应该在扇面之上、marker 之下
- marker 本体仍保持最高辨识度

## 4.3 战术地图扇面绘制方法

每个雷达单元按以下参数生成扇形：

- 原点：载具在地图上的屏幕坐标
- 半径：`radarUnit.getMaxScanDistance() / blocksPerPixel`
- 起止角：
  - 若扫描范围 `< 360`，使用 `yRotMin ~ yRotMax`
  - 若扫描范围 `>= 360`，视为全向圆
- 朝向：
  - 使用 `radarUnit.getYRot()` 或与 HUD 同步的扫描方向基准

注意：战术地图是世界俯视图，角度基准和 HUD 局部坐标不同，因此需要做一次变换：

- HUD 用的是“雷达局部坐标”
- 战术地图要变成“世界 yaw -> 地图平面角度”

推荐做法是抽一个公共数学工具，把 `RVP_RadarOverlay` 的扫描角度与扇面角度换算抽到独立 util，避免两边各写一套。

## 4.4 扫描线动画同步

战术地图的扫描线不应自己新发明一套 tick 逻辑，否则会和 HUD 雷达不同步。

建议把以下逻辑抽为公共方法：

- `computeRadarScanAngle(radarUnit, partialTick)`

由：

- `RVP_RadarOverlay`
- `RVP_TacticalMapScreen`

共同调用。

这样可以保证：

- 雷达 HUD 扫描线扫到哪
- 战术地图扇面里的扫描线就扫到哪

两边视觉完全一致。

## 4.5 锁定连线

当前 HUD 雷达里，锁定目标后会在小雷达圆内画一条中心到目标的线。

战术地图版本建议改为：

- 从本机载具屏幕坐标
- 连到锁定目标的屏幕坐标
- 使用与 HUD 相同的颜色
- 不使用虚线，直接用实线

如果目标当前不在地图可视范围内：

- 可以只画到地图边缘夹取点
- 或直接不画

第一版建议先用“超出视野不画”，逻辑更稳。

## 4.6 目标显示门控

建议把现有 marker 渲染逻辑改为三类：

### A. 永远显示

- 玩家
- 玩家当前载具
- 友方玩家
- 友方载具
- 友方弹药
- 己方弹药
- GPS 标记与己方 GPS 虚线

### B. 必须被雷达探测后才显示

- 敌方载具
- 中立载具
- 敌方导弹
- 中立导弹
- 敌方炸弹
- 中立炸弹

### C. 可选扩展

- 敌方/中立地面人员
- 假目标 / 干扰物

第一阶段可以不做。

## 4.7 远程缓存与本地实体统一门控

当前战术地图同时用两路源：

- 本地实体：`mc.level.entitiesForRendering()`
- 远程缓存：`RVP_ClientRemoteAmmoState`

门控时必须统一，否则会出现：

- 本地实体没被探测，不显示
- 远程缓存还在，反而显示出来

推荐规则：

- 对敌对/中立对象，只有当 `entityId` 在雷达接触集里时才允许绘制
- 无论它来自本地实体还是远程缓存，都走同一个 `isRadarVisible(entityId)` 判断

## 5. 可行性判断

## 5.1 可以做到的部分

以下功能可直接复用现有能力，实施风险较低：

- 战术地图雷达扇面
- 扫描线动画同步
- 锁定后取消扫描线并改画连线
- 雷达参数与颜色完全同步
- 敌方/中立目标基于 `detectedObjects` 门控显示
- `rvp:missile / rvp:bomb` 在战术地图按“被探测后才显示”

## 5.2 需要注意的点

### 1. 多雷达叠加

如果一架载具有多个雷达：

- 战术地图需要决定是否全部画出
- 或只画当前武器站主雷达

建议第一版：

- **只画当前武器站 `weaponUnit.getRadarUnits()` 的雷达**

这样与 HUD 语义一致，也最符合你现在的交互模型。

### 2. 本地玩家未乘坐载具时

如果玩家不在载具内：

- 没有当前 `WeaponUnit`
- 也就没有当前雷达态势源

建议：

- 战术地图退化为当前的“友军实时图 + 无雷达扇面”
- 不强行做“全局 AWACS 视图”

### 3. 扫描线与地图缩放

战术地图缩放变化后：

- 扇面半径要随 `blocksPerPixel` 变化
- 线宽、透明度、扫描线厚度不能线性放太大

建议：

- 距离按地图比例缩放
- 线宽和扫描线厚度使用 UI 常量，不随世界比例线性放大

### 4. 接触保持与地图闪烁

雷达的 `detectedObjects` 有 hold 逻辑，但战术地图若直接读，会在边缘目标处仍有轻微闪烁风险。

建议：

- 战术地图再做一层短时缓存
- 例如额外保留 `200~400ms`
- 用于平滑显示，不改变真实雷达锁定逻辑

## 6. 推荐实施顺序

### Phase 1：纯显示层整合

目标：

- 战术地图显示本机雷达扇面
- 扫描线与锁定连线同步
- 不改任何 marker 门控

优点：

- 低风险
- 最快能看到视觉结果
- 便于校准扇面角度、半径和颜色

### Phase 2：敌方/中立目标探测门控

目标：

- 敌方/中立载具必须被雷达扫到才显示
- 敌方/中立弹药必须被雷达扫到才显示
- 友军与己方目标保持实时显示

优点：

- 完整实现“战术地图 = 雷达态势图”的语义

### Phase 3：增强功能

可选增强：

- 多雷达叠加
- 雷达接触历史尾迹
- ECM/假目标在战术地图上的特殊符号
- NCTR 标签同步到战术地图
- 雷达丢失后淡出动画

## 7. 建议新增的数据与方法

建议新增：

- `client/state/RVP_TacticalRadarState.java`
  - 汇总当前雷达接触集
  - 提供 `isVisible(entityId)`、`getLockedTargetIds()`、`getRadarSweeps()`

- `client/gui/RVP_RadarRenderMath.java`
  - 统一雷达扇区角度换算
  - 统一扫描线角度计算
  - 供 `RVP_RadarOverlay` 与 `RVP_TacticalMapScreen` 共用

建议在 `RVP_TacticalMapScreen` 中新增：

- `renderRadarCoverage(...)`
- `renderRadarScanLines(...)`
- `renderRadarLockLinks(...)`
- `isRadarVisibleOnMap(entityId, relation)`

## 8. 最终建议

从技术上看，这个需求**完全可做**，而且非常适合落在 `ywzj_rvp` 侧完成。

最关键的原因有三点：

1. 雷达探测结果已经存在于 `RadarUnit.detectedObjects`
2. 雷达扇面与扫描线绘制已经存在于 `RVP_RadarOverlay`
3. 战术地图本身已经有成熟的地图坐标换算、marker 与世界线绘制能力

所以这不是“从零做雷达地图”，而是“把现有雷达 HUD 语义移植到战术地图，并给战术地图加探测门控”。

推荐执行策略：

1. 先做 **Phase 1**
   - 把扇面、扫描线、锁定连线先画出来
2. 你确认视觉风格、扇面大小和动画频率正确后
3. 再做 **Phase 2**
   - 把敌对/中立目标改成必须被探测后才显示

这样风险最低，也最容易调手感。
