# HQ9B 终端炮火拦截与 TWS 自动捕获视角修复

## 结论与根因

- 本轮暂存的 PPN（比例导航，即根据目标视线变化计算转向）主要修改已发射弹体的制导计算，没有改写发射按键、射程、离轴角或 `require_lock` 门槛。
- HQ9B 只能打载具、不能打自己终端呼叫的火箭弹：`c8c4c976c` 新增的 `RVP_SeekerTargetFilter` 把弹药 `owner` 相同一律视为己方弹。终端无载具炮火的 `owner` 是呼叫者，用于伤害和击杀归属；玩家随后操作 052D，服务端 `prepareShot` 因此以 `FRIENDLY_AMMO` 静默拒射，与导引头开关无关。飞行中的雷达/主动红外搜索还保留了相同的重复检查。
- 开导引头自动捕获后鼠标被锁住：TWS（边扫描边跟踪）的自动航迹写入 `WeaponUnit.lockedEntity`，本体下一刻自动执行 `aim(center)`。既有执行器仅在 `rvp_rf` 导弹模式中排除了无硬锁的跟踪；052D 普通 RF（雷达）站没有配置该模式，返回 `false` 后回退本体瞄准，反复覆盖鼠标方向。

## 必要修改

1. `RVP_SeekerTargetFilter`：拦截方有发射载具、目标没有发射载具时，不仅因伤害归属人相同排除目标。本车前一发、同射手有载具弹药、手持自弹及友方载具弹药继续排除；不添加武器 ID 分支。
2. `RVP_RuntimeSeekerSupport`：雷达/主动红外搜索复用统一归属门，删除重复的 `owner` 判断，保留原信号、角度、距离、遮挡及反制条件。否则会出现允许出弹、导引头随后又拒绝捕获的问题。
3. `RVP_BallisticLeadFireControlExecutor`：在模式解析之前消费纯自动 RF 航迹的瞄准请求。保留站级目标供 HUD、发射及数据链使用，不升级成雷达硬锁；手动硬锁、待定手动锁和外置锁继续原路径。

未修改本体、载具包配置、结构模型或 Mixin 注入点。

## 验证

- 先补回归：普通 RF 自动航迹落入本体瞄准回退、同归属人的无载具炮火被拒，两项均在修复前失败。
- 实际加载项目根 `limitless_vehicle/rvp/data/rvp/weapons/052d_hq9b.json`，直接执行服务端发射前检查；导引头开/关都允许已锁定的终端火箭弹，无锁和本车前一发仍拒射。
- 执行真实导引头的搜索、指定目标、捕获和持续跟踪；单独修发射门后，搜索回归仍因重复归属检查失败，统一后再次验证。
- 针对上述路径的 13 项测试通过；本轮新增 8 项回归。
- 按仓库要求设置 Java 17 与 `JAVA_TOOL_OPTIONS` 后，在项目根运行 `./gradlew build`：构建成功，1763 项测试全部通过（0 失败、0 错误、0 跳过）。日志为 `build/rf-intercept-build.log`。

## 实机复核

1. 用自己的炮火支援终端生成来袭火箭弹，在 052D 操作 HQ9B 分别以导引头开/关状态手动雷达锁定并发射。
2. 只开导引头等待自动捕获 TWS 航迹，观瞄鼠标应可自由移动，目标框仍保留；随后按 R 建立手动雷达锁，应保持原来的跟踪行为。
3. 连续发射时不能把本车上一发拦截弹作为新的寻的目标。
