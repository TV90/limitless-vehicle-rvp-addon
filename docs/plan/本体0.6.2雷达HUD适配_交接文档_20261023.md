## 三、挂起注入的精确技术问题（防重复踩坑，逐条已实测）

`modifyScanAngle` 要做的：拦截 L102 的 `drawScanLine(...)` 调用，把第 5 实参 angleDeg（index 4）改写为 HMD ping-pong 角或 phase 周期角（逻辑见挂起前最后的实现，完整保留在 git 历史 `72bfeb80` 版 `VehicleRadarOverlayMixin.java`，约 200 行处；算法本身没任何问题，纯注入机制问题）。

### 已实测失败方案（勿重复）

| 方案 | 失败现象 | 失败原因（已实证） |
|---|---|---|
| `@ModifyArg(index=4)`（旧写法原样保留） | Critical injection failure: Argument modifier (F)F failed injection check, (0/1) succeeded. Scanned 1 target(s) | 未定位到根因——@At 描述符正确、handler 静态性正确仍 0/1。**怀疑 Mixin 0.8.5 对 `(float) Mth.lerp(...)` 表达式实参 + index 的组合有缺陷，不要在此继续烧时间** |
| `@WrapOperation`（MixinExtras 0.3.6）包同类调用点 | 同样 (0/1) failed injection check | 同上，MixinExtras 亦不过 |
| `@Redirect` handler **非静态**、参数不含接收者 | InvalidInjectionException: Found unexpected argument type Matrix4f at index 0, expected VehicleRadarOverlay | **Mixin 0.8.5 对私有实例方法 invokespecial 调用的重定向，要求 handler 为 static 且首参显式接收者** |
| `@Redirect` handler **static + 首参 VehicleRadarOverlay self** | 编译期：drawScanLine 是 private 访问控制 | static handler 里 `self.drawScanLine(...)` 被 Java 拒绝（mixin 类与目标类是两个类）；须走 @Invoker 桥或内联复制方法体 |
| `@Invoker("drawScanLine")` 接口桥 | **编译期** AP 报 Could not locate @Invoker target drawScanLine | **Mixin AP 对私有目标误报**（运行时本可工作）；即使 mixin 未注册进 json，只要源码在 src 下 AP 就校验。绕法见 §5 |

### 已验证可行的事实

- `@Redirect(method="renderInstruments", at=@At(INVOKE, target="...drawScanLine(...IIFFFI)V"))` + `static` handler + 首参 `VehicleRadarOverlay self`：**通过了目标匹配与 handler 校验**（19.55 轮的失败是当时还带 @Shadow 私有调用编译错，注入本身已走到 validateParams）；
- 同文件 `@Redirect` 包 Math.sin(D)D、包 getLockedEntity 的写法（static/非 static 均有）全部 apply 成功；
- 现成参照：`VehicleAimAtOverlaySeekerColorMixin` 的锁框接管 @Redirect（static INVOKE + 非 static handler）与本 mixin 的 captureRadarUnit（instance INVOKE + 非 static handler）都在 0.6.2 上 apply 成功。

## 四、推荐修复路径（按序尝试，首选 A）

### 路径 A（推荐）：@Redirect static+receiver ＋ 内联 drawScanLine 方法体

1. handler 保持 `private static void ywzj_rvp$modifyScanAngle(VehicleRadarOverlay self, Matrix4f matrix, int cx, int cy, float radius, float angleDeg, float thickness, int lineColor)`（现状已是）；
2. 先读本体 `VehicleRadarOverlay.java:250` 起的 `drawScanLine` 方法体（约 10-15 行：enableBlend → translate/rotate → 按 thickness 画 4 边），把方法体**内联**进 handler 末尾，用修饰后的 angleDeg 绘制；
3. 方法体里的 `RenderHelper.fill/drawRectByCorner` 等是本体公开工具，直接 import 调用；
4. 注释标注「内联自本体 drawScanLine L250，本体若改此处需同步」。
- 优点：零 @Invoker、零合成类、一次编译即过；缺点：本体改 drawScanLine 需人工同步（可接受，10 行）。

### 路径 B（备选）：@Invoker 桥绕 AP 误报

- AP 误报的绕法（任选）：
  a) 把 @Invoker 方法挪进**同文件的主 mixin 类**作为 `@Shadow`……不行（Shadow 无法从 static 调私有实例）；改为主 mixin 内的抽象方法也不行（mixin 类不可 abstract）；
  b) **编译时移除 invoker 接口的 @Mixin 注解**、以纯 Gradle task 在 processResources 阶段注入——过度工程；
  c) **最实用**：invoker 接口文件先写好但不放 src，构建脚本（build.gradle 加一个 task）在 compileJava 前把它生成到临时源目录，绕开 AP 对主源集的校验——同样过度工程；
- 结论：除非路径 A 的内联体超过 30 行，否则不走 B。

### 完成后

1. `./gradlew build --offline -x test --no-daemon`（必须 --no-daemon，见 §6）；
2. `./gradlew runClient --offline --no-daemon`——**验证标准：日志出现 `Sound engine started` 且 client_1/crash-reports 无新文件**（client mixin 只有真启动才校验；服务端 runServer 冒烟测不到）；
3. 进游戏打一架有相位雷达的车（如 052d/ea18g），确认扫描线按 phase 周期扫；
4. 提交推送（当前 master 已含全部其余适配）。

## 六、环境坑清单（每一条都实际咬过人）

1. **JAVA_HOME 指向 JRE 8**：直接 `./gradlew` 构建本体（ywzj_vehicle，gradle 8.14.5）会报 foojay-resolver 需要 17+。先 `export JAVA_HOME="/c/Program Files/Java/jdk-21.0.11"`。rvp（gradle 8.8）不受影响。
2. **gradle 守护进程间歇吞 javac 错误明细**：`compileJava` 失败但日志只有「N 个错误」没有明细行。用 `--no-daemon` 重跑（慢但全量），且日志可能是 **GBK 编码**——`grep 错误` 匹配不到时用 `iconv -f GBK -t UTF-8 日志 | grep 错误`。
3. **服务端冒烟测不到 client mixin**：runServer 永远全绿不代表 client mixin 能 apply。client mixin 的唯一验证方式 = `runClient` 真启动到 `Sound engine started`（约 2 分钟）。
4. **rvp 消费本体的方式**：`build.gradle:139 fg.deobf("libs:ywzj_vehicle-1.20.1:0.6.2-all")`——flatDir jar，本体更新后必须重编本体并把 jar 拷到 `rvp/libs/`（`-all` 后缀 = 本体普通 jar 的别名，md5 相同）。本体 jar 不入库（gitignore），其它开发者自备。
5. **vehicles JSON 与 pack meta 不入 git**（.gitignore:61 只豁免了 weapons 老批次）：载具包数据改动随 `build/rvp-pack` 文件走，不进提交。
6. **build/libs 里的 `-all` jar**：rvp 自身的 `-all` 是 dev/devFull 变体；给玩家测试拷 `-all` 或 `full`（full 含依赖 267MB）。
