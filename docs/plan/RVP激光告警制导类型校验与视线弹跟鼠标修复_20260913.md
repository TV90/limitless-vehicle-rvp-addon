# RVP 激光告警制导类型校验与视线弹跟鼠标修复（2026-09-13）

> 状态：已落码，编译与 dev 服务端冒烟通过，**待实机行为回归**。
> 需求来源：用户澄清——①激光告警只应针对激光系弹（LBR/LH/SALH），SACLOS 触发属越界；
> ②视线类弹（SACLOS/LBR，经确认两者行为对齐）制导方向应严格跟随鼠标瞄准线，雷达锁定后
> 追锁定目标属 bug。要求精确按制导类型修复，不污染其他武器。

---

## 一、根因（调查结论）

### 1.1 SACLOS 触发激光告警
- 客户端 `RVP_ClientSaclosState.isAutoLaserWeapon` = `RVP_WeaponData.isOperatorGuided()`
  （LH/SALH/**LBR/SACLOS** 四类）——SACLOS 与激光系共用"自动激光"开关，会话点每 tick 同步；
- 服务端 `RVP_LaserWarnService` 每 5 tick 扫描 `RVP_SaclosOperatorSession` 活跃照射会话，
  敌车被照射（点距 ≤10 格或连线穿 AABB）即广播 `TYPE_LASER` 告警——**会话数据不含武器类型**，
  无法区分激光照射与 SACLOS 视线瞄准。

### 1.2 SACLOS/LBR 锁定后追目标
- **主因**：客户端 HUD 瞄准点（=会话点=制导视线源）在武器站有锁定实体时**直接取锁定目标中心**——
  `RVP_SaclosPodAim.resolvePodAimPoint` 单参重载 `allowLockedEntity=true`；
  雷达锁定后锁定实体持续存活 → 视线恒指向锁定目标 → SACLOS 沿视线飞 / LBR 光束骑在目标上。
  服务端口径（`RVP_SaclosDesignation.resolveDesignationPoint:89-90`）本就只允许 SACLOS-TV 用锁，
  客户端权威输入与服务端口径不一致；
- **加重 1**：`RVP_ProjectileSpawner.applyLockTarget:167-173` 发射时把锁定目标无差别写进所有弹型
  的 `targetEntity`；
- **加重 2**：`RVP_BaseBullet.tickGuidance` 实体追踪（`allowEntityTracking`）对视线类弹为 true，
  每 5 tick 把 `targetPos/lastGuidancePos` 刷成锁定目标实时位置——制导评估失败时惯性分支
  （`enableInertialGuidance`）直追锁定目标；
- LBR 与 SACLOS 视线输入完全同构（`RVP_RuntimeLbrGuidanceSource:38-41` 同调会话点），
  故 LBR 同样跟随雷达锁定（用户确认两者一并修复）。

## 二、修复（全部按制导类型数据驱动判定，零武器 ID 特判，零协议改动）

### 2.1 新增判定 helper（`RVP_WeaponData`）
- `isLaserGuidanceType()`：LBR / LH / SALH——激光告警仅对这类武器生效；
- `isLineOfSightGuided()`：SACLOS / LBR——光束与视线严格跟鼠标，锁定不吸附。

### 2.2 修复一：告警面收窄（服务端权威）
`RVP_LaserWarnService.scanLevel` 对每个照射玩家解析当前操作武器
（`getVehicle()` → `AbstractVehicle.getOwnOperatorUnit(player)` → `WeaponUnit.getCurrentWeapon()`
→ `RVP_WeaponData.isLaserGuidanceType()`），非激光系跳过该会话。
解析失败 fail-closed 跳过（宁漏不误）；AI 炮手照射现状本就不进扫描（非 ServerPlayer），维持。
不动 `C2SSaclosDesignation` 协议、不动会话结构、不动 SACLOS/LBR 制导视线源（LBR 照射仍告警）。

### 2.3 修复二：视线类弹回归纯鼠标视线（三处，仅命中 `isLineOfSightGuided()`）
1. **主修｜客户端 HUD 点禁锁定吸附**：`RVP_ClientSaclosState.resolvePodAimPoint` 按当前武器分支——
   视线类弹调 `resolvePodAimPoint(unit, false)`（跳过 `getLockedEntity()` 吸附，focus lock 优先级保留），
   视线回到 `aimHitPosition()`（准星落点）；LH/SALH 等保持吸附（锁定=照射承诺）。
2. **次修｜发射不传锁**：`RVP_ProjectileSpawner.applyLockTarget` 对视线类弹跳过
   `setTargetEntity(lockTarget)`（`data` 声明提前复用）；其他弹型传锁不变。
3. **次修｜实体追踪收紧**：`tickGuidance` 的 `allowEntityTracking` 追加
   `&& !rvpData.isLineOfSightGuided()`；LH/SALH 锁定追踪与 HITL_TV 实时跟随保持原逻辑。

### 2.4 影响面复核（`getTargetEntity` 消费点逐一排查，视线类弹去锁后）
- `RVP_ProjectileMotion` coast 判定：视线类弹 `targetPos` 由制导源每 tick 写入（非 null），行为不变；
- 双脉冲（`:167`）：仅 IR/ARH/SARH/ARM，视线类弹不走；
- `RVP_GuidanceTransitionContext.resolveTarget`：回退 `targetPos/lastGuidancePos`（视线点），
  相位转换参考跟随视线，语义更正确；
- `RVP_VirtualMissileEligibility`：静态配置硬性要求 GPS 制导（`:88`），视线类弹
  在 `INELIGIBLE_GUIDANCE` 即返回，不会因去锁新获得虚拟飞行资格；
- 近炸锁定分支：视线类弹去锁后走探测盒/扫掠路径（等价，且制导跟鼠标后"发射锁优先"语义本已失效）；
- 诱饵干扰：SACLOS 走 `RVP_JammingRuntime`，不依赖 targetEntity。

- 修复一：删除 `isLaserGuidanceOperator` 校验即恢复全量告警；
- 修复二主修：`resolvePodAimPoint` 恢复单参调用即恢复锁吸附；
- 次修 1/2：删除 `isLineOfSightGuided()` 两个分支即恢复传锁与实体追踪。
