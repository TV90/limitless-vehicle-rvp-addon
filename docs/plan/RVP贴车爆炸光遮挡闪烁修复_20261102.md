# RVP 贴车爆炸光的遮挡闪烁修复

日期：2026-11-02。范围：爆炸光贴住载具结构碰撞盒时，车体后方受光区域反复亮暗；相机、载具和爆心均静止也能触发。

## 1. 根因与复现证据

问题来自两个判定串联：

1. `RVP_LightGeometryPass.collectBodies` 原先无条件在上一刻与当前刻的旋转之间做球面插值，即用四元数计算帧间旋转。两端姿态完全相同时，浮点乘加仍可能改变结果的末位数值，盒子没有实际转动也会产生数值抖动。
2. `rvpTraceGeometry` 原先在显卡中把爆心换到盒内坐标，再用无容差的 `abs(z) <= extents` 判断光心是否在盒内。盒内就整盒豁免，盒外就正常挡光。爆心恰好贴面时，前述极小误差足以让同一车体盒反复切换“挡光/不挡光”。

这解释了为什么亮暗跳变主要出现在该盒投影的方向，而其它方向可以保持稳定。爆炸短光登记后位置固定；复现不需要重复创建光源、不需要多灯竞争，也不依赖烟雾。

修复前使用正式 `smoke_light_occlusion` 材质及与表面光共用的遮挡核心，固定相机、盒中心和贴面光源，仅重放原来的相同姿态插值：80种静止朝向，每种121帧，27种朝向出现亮暗开关，合计358次。

记录：`build/occlusion-audit/vehicle-contact-before.log`。临时复现入口保留在 `build/occlusion-audit/VehicleContactAudit.java`，其中使用的是修复前插值调用方式；不作为修复后生产路径的验收入口。

## 2. 当前实现

| 位置 | 修复行为 |
| --- | --- |
| `RVP_LightGeometryPass.interpolateBodyRotation` | 相同姿态直接复制，变化的姿态正常插值；输出统一归一化，即恢复标准长度的四元数。不会修改本体保存的上一刻/当前刻姿态 |
| `RVP_LightGeometryPass.sourceTouchesBody` | 在 CPU 上先用 double 世界坐标计算光心与盒中心的差，再换到盒内坐标；不经过相机矩阵或相机相对 float 坐标 |
| `RVP_LightGeometryPass.addBody` | 光心在盒内或距离盒面不超过0.002格（2毫米）时，该盒不写入这盏灯的遮挡标记；其它灯、其它不接触光心的盒照常判断 |
| `rvp_light_visibility.glsl`，`rvpTraceGeometry` | 只读取 CPU 已确定的灯位标记；删除显卡对光心是否在盒内的重复判断，避免同一决定被低精度坐标再次翻转；受光起点在盒内的原有豁免仍保留 |

接触带延续原先“光心在盒内时允许发光”的行为，只吸收盒面附近的微小数值误差；没有扩大实体遮挡体积。光源明确离开盒面后，穿过车体的光路仍被阻断。方块遮挡、光源强度/寿命、载具包、本体源码、结构模型均未修改，没有新增 Mixin。

## 4. 游戏内验收边界

尚未在用户实际游戏世界中验收。更新构建产物后，在原先会闪烁的载具与爆点保持相机、载具静止，确认原投影方向不再反复亮暗；再移动相机、转动车体并在其它车辆后方起爆，确认正常遮挡仍存在。

此次修复针对贴面光心的数值开关。正常的多次爆炸、八灯预算变化、活动部件实际转动，以及碰撞盒数量上限引起的遮挡变化，仍按各自既有规则处理。
