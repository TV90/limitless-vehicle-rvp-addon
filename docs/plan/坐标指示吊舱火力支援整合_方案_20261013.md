# 坐标指示吊舱 × 火力支援整合方案（2026-10-13）

> 需求（用户）：给坐标指示吊舱（`rvp:targetingpod` 的 block 款）整合火力支援终端能力——
> ① 吊舱武器 JSON 可内联配置火力支援数据（**多种，使用时选一种**）；② 标记坐标 = 写 GPS 点（原功能）+ **自动呼叫火力打击**；
> ③ 选中吊舱武器打开战术地图出现火力配置界面（**只能选配置并保存，不能直接打击**）；④ 之后吊舱指示坐标自动触发。
> 三项裁定（用户）：配置**内联完整**（与终端 profile 文件独立）；保存选择**服务端持久化**（玩家 NBT）；**每次方块标记即触发**（受冷却/距离/发数上限约束）。

---

## 1. 核心设计：内联条目 → 运行时隐藏 profile

吊舱内联条目在数据包加载期被"编译"为 `RVP_FireSupportProfileManager` 的**运行时 profile**（id 前缀 `rvp:pod/<weaponPath>/<entryId>`），从而**完整复用任务生态**：CALLING 引导期 / SchedulePlanner 排程 / 三种投送 / 冷却 / nonce 幂等 / 发数限流 / 区块预算，全部零重写。仅两处开 `POD` 来源分支：

| 耦合点 | 现状（终端） | POD 分支 |
| --- | --- | --- |
| `RVP_FireSupportRequestValidator` :37-51 手持终端校验 | 主/副手 ItemStack 必须 isTerminal+profileId 匹配 | `source=POD` 跳过；改为校验"profileId 为 pod 前缀 ∧ 玩家已保存选择=该 profile" |
| `MissionManager.guardCalling` terminalLost | 扫全背包找终端实例，丢失即取消 | `source=POD` 跳过 terminalLost（死亡/断线取消照旧）——标记后火力在途，不依赖终端 |
| 终端 UI profile 下拉 | 显示快照全部 profiles | 过滤 `rvp:pod/` 前缀（终端玩家不可见不可选） |

## 2. 数据层

`RVP_TargetingPodData` + 字段（数组，每条目=一份精简 profile；单武器/单投送/单点落区；**不支持** patterns/fire_modes/multi-munition——吊舱单点指示语义不需要）：

```json
"rvp_fire_support": [
  {
    "id": "precision",
    "display_CN": "精确打击",
    "call_duration_ticks": 200,
    "cooldown_ticks": 600,
    "max_target_distance_m": 2048,
    "max_rounds": 4,
    "weapon": "rvp:f14d_mk84",
    "rounds_per_call": 2,
    "interval_ticks": 40,
    "delivery": { "type": "rvp:vertical_projectile", "data": { "...": "投送参数，形态与终端 profile 的 delivery 完全一致" } }
  }
]
```

注册：数据包 reload 后 `RVP_PodFireSupportRegistry` 扫描全部武器 JSON 的该字段，逐条目转 ProfileManager 运行时 profile。**玩家 UI 只选条目**（三层下拉消失）。

## 3. 服务端

- **触发链**：`RVP_TargetingPodWeapon.performBlockMark` 尾部——方块标记命中（局部 `target` 坐标，**不碰 GPS 管理器**）∧ 该武器配置非空 ∧ 玩家已保存选择 → 服务端自组 `RVP_FireSupportRequest`（新 `source` 字段=POD；targetXZ=标记坐标；revision 服务端自取快照；nonce 随机）→ `MissionManager.submit` → 结果 actionbar 反馈操作者（成功引导中/冷却剩余/超距/未选配置）。
- **选择持久化**：`RVP_PodFireSupportSelectionStore`——`ServerPlayer.getPersistentData()`（键含武器 path），`C2SSavePodFireSupportSelection` 保存、`S2CPodFireSupportSelection` ACK+登录同步。
- **校验**：Validator POD 分支（见 §1 表）；距离以玩家水平坐标（复用）；冷却/发数/幂等照常。
- **GPS 解耦**：`write_gps_target` 独立控制写点；火力触发只看内联配置+已保存选择，二者互不绑定。

## 4. 客户端

- **`RVP_PodFireSupportMapTool`**（新战术地图工具）：选中吊舱武器（当前武器 data 的 fireSupport 非空，`LocalVehiclePlayer` 先例）打开地图时注入（`RVP_ClientEvents` 分流）。侧栏=内联条目下拉（从武器 data 读）+当前已保存选择显示+**保存按钮**；无提交/落点/锚点手柄/任务跟踪。复用 `RVP_FireSupportMapTool` 的下拉/草稿代码结构。
- 注意：`mapTool != null` 时 GPS/雷达侧栏隐藏（既有行为，pod 工具同样适用）。

## 6. 数据侧纪律

1. 内联条目 `id` 在同一武器内唯一；跨武器可重复（运行时 profile id 含 weaponPath 隔离）。
2. 内联条目变更在数据包 reload 后生效；已保存选择指向不存在的条目时触发链静默跳过并在 UI 标"已失效"。
3. `write_gps_target` 与火力触发互不绑定；只要配置了内联条目且已保存选择，标记即触发。
