## 用户目标与实现

用户希望热成像时关闭光影，退出恢复此前光影，已授权执行“保留已编译资源、临时暂停”的方案。

- `ywzj_rvp-client.toml` 新 `[thermal] pauseShaders = true`，默认启用。配置未加载、未装 Oculus/Embeddium 或接口不匹配时不接管。设置 false 可恢复上轮光影+热成像叠加通道。
- 从本体 `ThermalHandler.isActive()` 判断，覆盖沿用该通道的观瞄和 TV 热成像；并非硬编码某辆车/武器。RenderTick.START 最后优先级借用原版管线，END 交还，下一 START 和客户端 LevelEvent.Unload 均兜底收尾。
- 原来未开光影就保持关闭，用户在热成像期间手动开关/重载仍受尊重。不调用 setShadersEnabled/save/reload，不改 Oculus 的配置、光影包选择或光影参数。
- 热成像只是暂停绘制，BSL 的 shader/FBO 显存仍保留；首次准备三个轻量地形程序和 mesh 缓存有一次性开销，不应承诺首次零尖峰。

## 代码关键点与禁止误改

1. `RVP_ThermalPipelineManager` 继承并组合原 PipelineManager，通过既有管理器字段安装，所有真实维度缓存、代号与销毁仍委托原实例。只在借用帧的渲染线程返回 VanillaRenderingPipeline；后台区块线程始终看见真实 BSL，防止新建地形的颜色/顶点格式混乱。不能换成全局 areShadersEnabled=false 或全局 WorldRenderingSettings=false。
2. 空管线/基类构造会改 WorldRenderingSettings，所以只在标题界面构造，并在 finally 逐字段恢复。世界内开关期间不改变地形格式，不全量重建区块。
3. `RVP_EmbeddiumThermalPrograms` 复用 Embeddium 自带 block_layer_opaque.vsh/fsh，按 Iris 已有 VAO 的 **1～4** 号位置链接一次。Embeddium 默认程序用 0～3，直接切原版管线会导致地形不绘制、热源穿墙。新程序存回原渲染器自己的表，由它销毁；弱引用只记录已验证渲染器，不建平行 GPU 池。
4. `RVP_RetainedPrograms` 在单帧内借走 Iris 地形覆盖表，使其走原版地形程序；普通退出归还同一组句柄，原所有者重载/换实例则释放被暂时隐藏的旧句柄，不覆盖新程序或重复释放。
5. 仍保留全局扩展地形格式时，小网格 CPU 回退会多算 Iris 切线。`RVP_ThermalFallbackBuffer` 对明确接管的主体小网格调用 Iris 公开 iris$beginWithoutExtending，再用原 RenderType.end 提交；只在提交作用域中还原 ImmediateState。不要用覆写 BufferBuilder.begin 的版本：测试中自定义消费者未被实际使用，收益无效。大块共享阈值、透明/特效骨及 no_cull_bones 语义未变。
6. `RVP_VehicleBedrockModel` 仅给现有 shared body 小网格回退套上述作用域，普通帧走原消费者。`RVP_ThermalShaderPause` 的公共接口不引用 Iris 类型，Native 桥只在确认装有模组后反射加载。
7. build.gradle 增加 Oculus **compileOnly**：`curse.maven:oculus-581495:6020952`，不嵌入、不自动安装。官方工件与实际测试 jar SHA256 相同：`0945df0cba0f62b3901dd80c3268e5311b770ece78c78037a45db12ac0425fef`。离线首次缺工件，联网解析一次成功；最终全部离线构建。
