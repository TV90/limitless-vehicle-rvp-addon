## ⚠️ 必读：冒烟测试新方法（旧方法会留杀不掉的服务端进程）

`./gradlew runServer` 后台启动 → 每 5 秒轮询日志（grep "Done ("）→ **见到 Done 立即**：
`wmic process where "name='java.exe' and commandline like '%ywzj%'" get processid` 取 PID →
`taskkill //PID <pid> //F` → **全路径** `/c/Windows/System32/tasklist.exe` 复验 java 进程为 0
（Git Bash 里 `tasklist`/`$SystemRoot`/`/FO` 都会静默假阴性，必须用 `/c/Windows/System32/` 全路径）。
不要等 stdin EOF 自退。后台 gradle 包装任务在服务端被杀后 exit 1 属正常。

## 二、过穿 bug：根因链与当前状态（⚠️ 未完任务主线）

**用户实测现象**：瞄 F3+B 绿色 OBB 打 052D，导弹/机炮弹有几率完整穿过不爆；卸 RVP 仍复现；
小块 OBB 命中正常；船越大越容易过穿。

**根因（原版 1.20.1 字节码实锤，javap 反编译验证）**：原版实体存储是**单分节注册**
（`PersistentEntitySectionManager.addEntityWithoutEvent` 只用 `blockPosition()` 定一个
16³ 分节），查询只遍历查询盒 X/Z ±2 分节、Y 下方扩 4 上方扩 0 范围内的分节——120 格的
052D 只注册在船中/尾部一个分节，弹的段盒落在艏部（2.3 分节外）/艉部远端（5 分节外）/
俯冲高处（Y 上方不扩）时 `getEntities` **确定性返回空** → 命中链无候选 → 过穿。
关键实证：watch 与真实命中链共用同一查询，"没命中的弹没有 watch 信息"即根因表现。

**已修（RVP 侧，§48）**：新增 `util/RVP_ServerVehicleIndex`（Join/Leave 事件维护每维度
载具注册表 + `mergeWithVehicleIndex` 按包围盒补筛合并）；`RVP_BaseBullet` 三处命中候选
查询（直击/近炸扫掠/攻顶）接补筛——原版查得到的照旧、盲区里的巨型载具兜底，谓词零变化。
**修复的是真实命中链，非仅日志。**

**遗留（新会话主线）**：
1. **用户实机验收**（第三十九轮清单，§48 末）：打 052D 任意部位应全部命中爆炸；
   `/rvpobb querytest` 看★盲区分布；watch 不再有"无声消失"弹；
2. **缺陷 B 未修：主物理块盲区**——`main_structure` 骨被本体 `BaseVehicleData.buildOBBs`
   （L204-207）排除在 `getOBBs()` 命中列表外（只构成 mainCubeOBB 主物理块，F3+B 蓝框），
   052D 艏部 +36~39.6 格段只有它覆盖 → 直击仍会穿过该段。修法已设计：RVP 侧
   `findEntityOnPathForSegment` 补测 `getMainCubeOBB()`（与 OBB 命中取最近），或本体作者
   在 `getOBBs()` 加主块（一行）。**待用户定版后实施**；
3. **转给本体作者的结论**（均字节码/运行时实锤，RVP 已修本体未修）：
   a) 原版 `AABB.clip` 起点在盒内永远未命中（`getDirection` 每轴只测入射面 + `clipPoint`
      拒绝 t≤0）——`EntityUtil.getHitResult` 非载具分支无 contains(start) 处理
      （瞄准链 `VectorUtil.hitEntity` L108 有同款处理，命中链漏了）；
   b) `getEntities` 单分节盲区——`EntityUtil.findEntityOnPath`（L71/103）需同款注册表补筛
      （`RVP_ServerVehicleIndex` 可直接移植）；
   c) main_structure 主块不在 `getOBBs()` 命中列表；
   d) `MissileEntity` tick 顺序 tickGuidance→tickMove→tickHit：检测段是"新位置出发的幽灵段"。
