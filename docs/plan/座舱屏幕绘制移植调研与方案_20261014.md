# 座舱屏幕绘制移植调研与方案（RWR/雷达画上载具模型）— 2026-10-14

> 目标：把 MCH-Reforged（用户自研 mod，源码 `D:\MCHR\MCH-Reforged`）的"RWR/雷达界面动画直接绘制在载具模型上"移植进 RVP。
> 本文只做调研结论与实施计划，**不含代码改动**。

---

## 1. MCHR 现实现考古（为什么像素糊）

| 环节 | MCHR 做法 | 清晰度瓶颈 |
| --- | --- | --- |
| 目标面 | 模型约定命名部件（`$rwrdisplay`/`$radardisplay`，OBJ group，UV 展成 0-1 整面），载具渲染时按组双 Pass：Pass1 关纹理画黑底+polygonOffset，Pass2 绑动态纹理 alpha 叠加（`MCH_RenderAircraft.java:1507-1583`） | 双 Pass 思路可继承 |
| 纹理 | 每载具一张 `DynamicTexture(256,256)`，CPU 逐像素写 `int[]` 后 `updateDynamicTexture()` 全量上传（`MCH_RWRDisplayTextureManager.java:107,81`） | **256² 上限**；GL_NEAREST 无 mipmap → 马赛克 |
| 文字 | 3×5 像素点阵手绘字体（仅大写+数字，`MCH_TextureRenderUtil.java:216`） | 无矢量文字，放大即糊 |
| 线条 | 1px Bresenham 硬边（`setPixel`） | 无抗锯齿 |
| 动画 | 每帧重绘全纹理+全量上传（雷达按 phase 桶去重） | 高分辨率下上传开销会爆炸 |

**结论**：糊的根源是"CPU 栅格化到低分纹理"，不是"画在模型上"这个思路本身。

## 2. 本体（ywzj_vehicle）渲染挂点（全部零本体改动可用）

- 渲染主循环：`VehicleRender.render`（`client/render/entity/vehicle/VehicleRender.java:53-108`）——动画 pose 烘入 → `model.renderToBuffer` → `renderSpecialBones`；`applyVehicleRotation/applyAnimationPose` 均 public static 可复用；
- **骨定位 API（v2 runtime）**：`BakedModelInstance.getGlobalTransform(boneIndex):Matrix4f`、`mulGlobalTransform(PoseStack,int)`、`getLocatorTransform(String)`；实例取 `AbstractVehicle.getVehicleModelInstance()`。先例：`BulletHoleParticle.renderOnVehicle:116`（弹孔 quad 贴骨面，手写 vertex）、`DecorationUnit.render:147`（骨上挂子模型）；
- **全亮度先例**：骨名 `illum_*` 前缀 = illuminated（渲染时 light→MAX）——**屏幕骨命名 `illum_` 即自发光**；
- RenderType：本体 `ModRenderTypes.java` 自建 additive/emissive/translucent 先例，RVP 照抄模式自建；
- 模型侧：bedrock 模型 per-cube 独立纹理**不支持**，但 display JSON 有 `special_bone_effects`（bone+texture+type[muzzle_flash/transparent/**cockpit**]）——屏骨做独立子骨+占位贴图即可。

**动手位置（RVP 侧）**：① `Mixin` 注入 `VehicleRender.render` TAIL（公共 Mixin 需过 Mixin 纪律审查；更轻的是 **RenderLevelStageEvent AFTER_TRANSLUCENT** 自画，不碰本体渲染器，代价是需自行复刻旋转/动画变换——`applyVehicleRotation` public 可调）；② 屏显绘制器全部放 `rvp/client/cockpit/` 新包。

## 3. 清晰手段选型（核心问题）

| 方案 | 原理 | 清晰度 | 实现量/风险 | 结论 |
| --- | --- | --- | --- | --- |
| A. MCHR 直改 | DynamicTexture 提到 1024²+脏矩形上传+TTF 光栅化 | 中（仍 CPU 栅格） | 中；本质仍是预烤纹理 | 不推荐 |
| **B. world-space GUI 直绘（推荐）** | 不预烤纹理：每帧把标准 GUI 绘制调用（`Font.drawInBatch` 文字 / blit / 手写线面顶点）经 `mulGlobalTransform` 变换到屏幕骨局部坐标系直接画；emissive RenderType 全亮 | **屏幕原生分辨率，矢量文字+几何线条无损**，任意动画零上传 | 中高：需自建"3D 骨面画布"层（PoseStack 变换+裁剪自控）；绘制原语可从 RVP_RadarOverlay 搬 | **主屏方案** |
| C. 离屏 RenderTarget | 真 Screen 渲到小 FBO 再贴模型 | 最高（整屏复用） | 高（FBO 管理/混合链/兼容）；仅战术地图全屏上屏才值得 | 远期可选 |

## 4. RVP 屏显内容源（可直接搬）

- **RWR**：本体 `WarningReceiver.targets`（`WarnType{RADAR_SEARCH,RADAR_LOCK,MISSILE_LAUNCH}`，500ms 过期）+ `RVP_ClientLockWarningState`（追踪 1.5s 窗口）；表盘绘制原语在 `RVP_RadarOverlay.java:163-238`（同心圆+方位射线+距离映射+机型文字）。注：告警数据无现成方位/距离字段，按 `RVP_RadarOverlay:202` 同法实时计算；
- **雷达屏**：`RadarUnit.getDetectedEntities()`（`RVP_ClientRadarTickHandler:82` 每 tick 保活）+外置雷达快照（5t）；扇形/扫描线（机械 ping-pong/相控阵三态逻辑 `RVP_RadarOverlay:399`）+目标框+速度矢量原语同文件；
- 数据更新：告警 10t/探测 1t/外置 5t——3D 屏每帧重绘零缓存，与现状一致。

## 5. 实施计划（分阶段，均零本体改动）

1. **基建：3D 屏幕画布层**（`rvp/client/cockpit/`）：骨定位（`mulGlobalTransform`）+ emissive quad（黑底 Pass1+绘制 Pass2 继承 MCHR 双 Pass 思路）+ GuiGraphics 语义的最小绘制子集（`drawInBatch` 文字/线/多边形/圆弧）+ 自建 RenderType；
2. **RWR 屏**：接 `WarningReceiver.targets`+`LockWarning`，画 RWR 罗盘（搬 RadarOverlay 同心圆/方位射线/符号原语，含闪烁周期）；
3. **雷达屏**：接探测表+扫描线三态逻辑，画雷达罗盘（扇形+目标框+速度矢量）；
4. **声明与美术规范**：RVP 侧新增屏骨声明（载具 JSON `rvp_cockpit_screens`：骨名/屏类型 RWR|RADAR/尺寸/绑定雷达站；或先硬编码到具体载具验证）+ 给美术的屏骨建模规范（独立子骨、UV 0-1 整面、`illum_` 前缀）；
5. **远期可选**：完整战术地图上屏（方案 C RenderTarget）。

suav 或 mi28（有座舱且 RVP 配置成熟）先做一块 RWR 屏打样，验证清晰度后再铺开。

## 7. 分屏实施定案（2026-10-14 与用户对齐）

1. **三种屏**：雷达屏 / RWR 屏 / 战术地图屏（地图屏**不画**雷达照射范围与按钮侧栏，仅地图瓦片+图标层）；
2. **绘制范围：仅本地玩家乘坐的载具**。其它载具的屏骨显示建模静态"熄屏"贴图（美术出一张灰屏），零动态开销；可见性判断=一行 `vehicle == 本地玩家的车`；
3. **架构：现代化 UV 方案**——三类屏各一张 512² RenderTarget（本车共享；雷达/RWR 20Hz、地图 5Hz 降频重绘），内容用标准 GuiGraphics 绘制（真字体/抗锯齿/中文），UV 贴面双 Pass（黑底+内容，MCHR 骨架保留）；纹理采样走**路径 b：渲染器直接采样 RT 的 GL 纹理 id（`setShaderTexture(0, colorTextureId)`+手写顶点，BulletHoleParticle 先例）——零回读零上传**；
4. **屏骨工作流（mesh 版定稿）**：用户模型风格为 mesh（现有载具模型 abramsx/052d/ah1z 等即 poly_mesh，simplebedrockmodel 原生 `BedrockPolyMesh`+`meshChunks`+`poly_mesh_translucent` 双通道；`renderSingleBone` 公开方法带 quad/mesh 双 RenderType 参数）——屏面按习惯用 mesh 建、UV 自展（同 MCHR OBJ vt 直觉），渲染器对该骨双 Pass 动态纹理替换；尺寸规范=屏骨建模尺寸+自展 UV；
5. **性能定案**：三类屏全开 <0.5ms/帧+3MB 显存（对比 MCHR 单屏即 400 万像素写/秒+15MB 上传/秒）；同车同类型共享 RT、仅本车绘制进一步锁死开销；
6. **world-space 直绘降级为备选**（准星投影类需求再说）；清晰度策略：512² 对座舱屏典型投影为 2~5 倍超采样，贴脸场景可单屏升 1024²。
