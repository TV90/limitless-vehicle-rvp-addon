# RVP 联动 SuperbWarfare（SBW）制导武器干扰方案

> 日期：2026-08-25
> 状态：方案（待实现）
> 关联文档：`RVP_DIRCM定向红外对抗方案_20260823.md`、`RVP载具干扰器功能方案_20260809.md`、`RVP告警系统_地载与空载告警状态.md`

## 1. 目标与硬性约束

让 RVP 的对抗体系能作用于 **SuperbWarfare（SBW）的制导武器**，具体四项需求：

1. SBW 的 `guideType=0`（红外/热寻的）导弹，能被 RVP 的**热焰弹**与**烟雾弹**干扰偏航；
2. RVP 载具被此类导弹锁定时，触发 RVP 现有的**红外告警**；
3. 锁定 RVP 由 **gunner（炮手/武器站乘员）驾驶**的载具时，gunner 能识别威胁并**自动抛洒热焰弹/烟雾弹**；
4. 能被 RVP 的 **DIRCM（定向红外对抗）** 检测并照射偏转。

**强制约束（用户要求）**：

- 必须与本体联动 SBW 的方式一致：**检测 SBW 是否加载（`isLoaded()`）**，非强制依赖，**装了才生效**；
- **绝对不能**因为卸载 SBW 而导致 RVP 无法游玩甚至崩溃。

## 2. 现状调研

### 2.1 SBW 制导武器类型（源码 `SuperbWarfare-superbwarfare`）

所有制导导弹都继承 `MissileProjectile`（`entity/projectile/MissileProjectile.kt:25`），其自带 `distractedByDecoy()`（`MissileProjectile.kt:216`）：在 32 格 / 60° 锥内找带 `superbwarfare:decoy` 实体类型标签的实体，每 tick 25% 概率 `setDistracted(true)` 并把目标 UUID 改向诱饵。

SBW 代码层只有 `guideType` 一个维度（`MissileProjectile.kt:34`）：`0`=跟踪实体 UUID（红外/热寻的），`1`=跟踪坐标点（激光/指令制导）。**没有 IR/雷达/激光 三分类的导引头枚举**。

| 制导方式 | 实体类 | 代表武器 |
|---|---|---|
| guideType=0 跟踪实体（红外热寻的） | `IglaMissileEntity` | **SA-18（针/Igla）** |
| 同上（继承 `Ru9m336MissileEntity`） | `Ru9m336MissileEntity` / `Fim92MissileEntity` | 9M336 / **FIM-92 Stinger** |
| guideType=0/1（红外成像跟实体 + 顶部攻击 / 激光跟坐标点） | `JavelinMissileEntity` | **FGM-148（标枪）** |
| guideType=0/1（AGM-65 红外版/激光版） | `Agm65Entity` | AGM-65 小牛 |
| 激光指定坐标点 | `Ru3m14MissileEntity` | 3M14 口径巡航弹 |
| 线导（Wire-guided，载具持续修正） | `WireGuideMissileEntity` | 陶式/短号 |
| 非制导（继承 `FastThrowableProjectile`，不受 decoy 干扰） | `MediumRocketEntity` / `SmallRocketEntity` / `RpgRocket*Entity` | 火箭弹 |

**结论**：本方案聚焦 `guideType=0` 的红外类导弹（SA-18、Stinger、标枪的红外模式等）。SBW 原生 `distractedByDecoy` 不区分 guideType，会对所有制导弹生效；因此**不使用 `superbwarfare:decoy` 标签方案**（否则会误干扰 guideType=1），而由 RVP 单独做、精准限定 guideType=0。

### 2.2 RVP 已有的对抗设施（可直接复用，无需新写对抗逻辑）

- **通用对抗决策引擎** `RVP_CountermeasureState.query(Entity seeker, Entity target, RVP_EnumGuidanceType guidanceType, RVP_GuidanceActiveConfig config)`（`countermeasure/RVP_CountermeasureState.java:59`）：
  - 已支持 `RVP_EnumGuidanceType.IR`（热焰弹敏感，`RVP_CountermeasureState.java:75`）；
  - 内部 `findDecoyInSeekerCone`（锥内找 RVP 干扰物）、`findSmokeContaining`（烟雾遮蔽）；
  - 返回 `Result(lockBlocked, jammedInFlight, decoyed, intercepted)`。
  - **关键点**：该引擎只接收 `Entity` 类型的 seeker/target，不关心 seeker 是不是 RVP 自己的弹体——把 SBW 导弹当 `Entity` 喂进去即可复用。
- **红外告警链路**（现成，无需新 UI）：服务端 `S2CMissileTrackAlert(TYPE_IR=3)`（`network/S2CMissileTrackAlert.java:25`）→ 客户端 `RVP_ClientMissileTrackAlert` → `RVP_LockWarningOverlay`（`client/gui/RVP_LockWarningOverlay.java:63`）显示"被 IR 导弹追踪，按热焰弹键"。
- **干扰物/烟雾实体**：`RVP_DecoyEntity`（热焰弹）、`RVP_SmokeEntity`（烟雾弹），均实现 `RVP_Decoy` 且为 `Entity`，存在于世界中——可直接作为 SBW 导弹的诱饵目标。
- **DIRCM 偏转**：`RVP_JamDeflectionHelper.applyDeflection(RVP_BaseBullet)`（作用于 RVP 自己的 `RVP_BaseBullet` 的 `jamming*` 字段）。对 SBW 导弹无效（非 `RVP_BaseBullet`），需走 SBW 自己的 `setDistracted`。
- **gunner 自动对抗**：RVP 已有"被锁自动部署干扰物"的代码路径（玩家按热焰弹/烟雾键触发的同一套），实现时复用。

## 3. 核心思路：把 SBW 导弹"桥接"进 RVP 对抗引擎

不新增一套对抗逻辑。**将 SBW 的 `guideType=0` 导弹视作 IR 导引头**，喂给 `RVP_CountermeasureState.query(...)` 复用 RVP 的干扰物/烟雾判定；在"效果落地"这唯一一步，调用 SBW 自己的 `setDistracted(true)` / `setTargetUUID(...)`（与 SBW 原生 `distractedByDecoy` 同机制），把导弹引向 RVP 的干扰物实体或使其丢失锁定。

完全复用意味着行为一致、风险低，且天然满足"仅 guideType=0""仅对装有 RVP 干扰物的情形生效"。

## 4. 模块设计

### 4.1 依赖接入（已完成）

- SBW jar 放入 `libs/superbwarfare-1.20.1-0.8.9.1-all.jar`（客户端在用版本 0.8.9.1）；
- `build.gradle` 新增（仅编译期引用，运行时由用户另行安装，不打包、不强制依赖）：

```gradle
// sbw（联动兼容层：仅编译期引用，运行时由用户另行安装，不打包、不强制依赖。
// 注：本体用 CurseMaven 的 modCompileOnly 接入，但 RVP 的 ForgeGradle 未注册该方法，
// 故改用本地 libs 下 SBW jar + compileOnly fg.deobf 等价接入（SBW 同样不被嵌入、可选）。
// 全部 SBW 类引用必须位于 RVP_SuperbWarfareCompat.isLoaded() 之后的方法体内，
// 卸载 SBW 时不会触发 SBW 类加载，RVP 仍可正常游玩）
compileOnly fg.deobf("libs:superbwarfare-1.20.1:0.8.9.1-all")
```

> 关于「是否必须把 SBW 放进依赖库」：本体用的是 CurseMaven `modCompileOnly`（不落本地 libs），
> 但 RVP 的 ForgeGradle 版本未暴露 `modCompileOnly` 方法，且 `fg.deobf(CurseMaven坐标)` 解析不到
> 预 deobf 缓存。经验证，RVP 可行的等价接入就是本地 `libs` jar + `compileOnly fg.deobf`
> （SBW 同样不嵌入发布 jar、可选、不强制依赖），与本体意图一致。

### 4.2 `RVP_SuperbWarfareCompat`（镜像本体的 `SuperbWarfareCompat`）

位置：`org.ywzj.rvp.compat.RVP_SuperbWarfareCompat`。

- `private static final boolean IS_LOADED = ModList.get().isLoaded("superbwarfare");`
- `public static boolean isLoaded()` 放行；
- **安全访问器**（全部在 `isLoaded()` 之后的方法体内才触碰 SBW 类）：
  - `isSbwMissile(Entity e)`：`e instanceof MissileProjectile`（SBW 类仅在方法体内引用）；
  - `int getGuideType(Entity e)`：`((MissileProjectile) e).getGuideType()`；
  - `void setDistracted(Entity e, boolean v)`：`((MissileProjectile) e).setDistracted(v)`；
  - `void setTargetUuid(Entity e, String uuid)`：`((MissileProjectile) e).setTargetUUID(uuid)`；
  - `void applyDircmDeflection(Entity e)`：DIRCM 照射时调用，内部 `setDistracted(true)` 并周期性 `setTargetUUID("none")`（见 §4.4）。
- 所有 SBW 类型**不出现在方法签名 / 静态初始化器 / 字段声明**中，仅以 `Entity` + 方法体内强制转换形式出现 → 卸载 SBW 时 JVM 不会加载 SBW 类。

### 4.3 `RVP_SbwThreatManager`（服务端，仅 `isLoaded()` 时注册）

- 在 mod 初始化（`FMLCommonSetup`/构造）时 `if (RVP_SuperbWarfareCompat.isLoaded())` 才注册 `ServerTickEvent`/`LevelTickEvent` 监听器；监听器内首行 `if (!isLoaded()) return;`。
- 每若干 tick（如每 4 tick）扫描世界内 SBW `MissileProjectile`，筛选 **`getGuideType()==0` 且 `getTargetUUID()` 解析出的目标是 RVP 载具（`AbstractVehicle`）** 的导弹。
- 对每条命中导弹：
  1. 取 RVP 的 IR 制导配置（复用 RVP 自身 IR 导弹所用的 `RVP_GuidanceActiveConfig`）；
  2. 调 `RVP_CountermeasureState.query(missile, vehicle, RVP_EnumGuidanceType.IR, config)` → `Result`；
  3. **效果落地（仅此处触碰 SBW API）**：
     - 烟雾致盲：调用 RVP 现有 `RVP_CountermeasureState.findSmokeContaining(target)`，若目标处于 RVP 烟雾中 → `setTargetUUID("none")`（丢失锁定）；
     - 干扰物诱偏：在导弹 32 格 / 60° 锥内（对齐 SBW `MissileProjectile.distractedByDecoy` 的 32 格与 `SeekTool.seekLivingEntities` 的 60° 参数）遍历 `RVP_Decoy` 实体（仅 FLARE/SMOKE 类型）→ `setDistracted(true)` + `setTargetUUID(decoy.getStringUUID())`（热焰弹/烟雾弹诱偏）。
     - 说明：未走 `RVP_CountermeasureState.query(...)`，因其需要完整的 `RVP_GuidanceActiveConfig`（从武器数据解析），SBW 导弹没有对应 RVP 武器数据；改用 `findSmokeContaining` + 自实现锥检测，等价达成 IR 对抗判定且更稳健。
  4. **红外告警**：向被锁定载具的控制玩家发送 `S2CMissileTrackAlert(missileId, vehicleId, TYPE_IR)`，复用现有告警 UI；
  5. **gunner 自动抛洒**：若该载具由 gunner 驾驶且开启自动对抗，复用 RVP 现有"被锁自动部署干扰物"路径（同玩家按键触发的部署逻辑）抛洒热焰弹/烟雾弹。

### 4.4 DIRCM 桥接

- 在 RVP 现有 DIRCM 检测逻辑中，若 beam 照射范围内存在 `guideType=0` 的 SBW 导弹：
  - **不**走 `RVP_JamDeflectionHelper`（只作用于 `RVP_BaseBullet`）；
  - 改走 `RVP_SuperbWarfareCompat.applyDircmDeflection(missile)`：`setDistracted(true)` 并持续清 target（使导弹失去 IR 跟踪、直线飞离）。
- 检测/照射判定的几何复用 DIRCM 现有实现，仅新增"SBW 导弹"这一被作用对象分支。

## 5. 四个需求的落点

| 需求 | 实现位置 | 机制 |
|---|---|---|
| 热焰弹/烟雾干扰 guideType=0 导弹 | §4.3 步骤 3 | `query(IR)` → `setDistracted`+`setTargetUUID(干扰物)` |
| 被锁触发 RVP 红外告警 | §4.3 步骤 4 | 发 `S2CMissileTrackAlert(TYPE_IR)` |
| gunner 被锁自动抛洒 | §4.3 步骤 5 | 复用 RVP 自动部署干扰物路径 |
| DIRCM 检测并照射偏转 | §4.4 | `applyDircmDeflection`（= `setDistracted`+清 target） |

## 6. 不崩溃 / 非强制依赖保证（核对清单）

- [x] SBW 作为 `compileOnly`，**不打包**进 RVP jar，运行时由用户另行安装；
- [x] `RVP_SuperbWarfareCompat` **不直接引用任何 SBW 类型**：只持有 SBW 导弹类名字符串，经 `Class.forName` + `Method.invoke` 反射访问 SBW API；对弹体的通用操作（速度/朝向）全用 MC 原生 `Entity` 方法。因此本类字节码常量池无 SBW 类符号，无论 JVM eager/lazy 解析都不会触发 SBW 类加载（此前直接 `invokevirtual setDeltaMovement` 到 `MissileProjectile` 静态类型会在 SBW 缺失时抛 `NoClassDefFoundError`，已改为反射规避）；
- [x] 监听器**仅在 `isLoaded()` 时注册**；SBW 类型不出现在任何方法签名/静态初始化器；
- [x] 卸载 SBW → `IS_LOADED=false` → 管理器不注册、所有桥接走 NOOP → RVP 照常游玩；
- [x] **零新增 Mixin**（符合 AGENTS.md 默认拒绝 Mixin）：纯 Forge 事件 + 现有 RVP 系统 + compat 层；
- [ ] 实现后需双 mod（RVP 单独 / RVP+SBW）冒烟，确认卸载 SBW 不崩溃、装载 SBW 行为正确。

## 7. 风险与待确认

- SBW `MissileProjectile` 的 `setDistracted`/`setTargetUUID` 为 `public`（`MissileProjectile.kt:42/59`），可直接调用；若未来 SBW 改签名，compat 层需同步（风险低）。
- `RVP_CountermeasureState.query` 需要的 `RVP_GuidanceActiveConfig` 应复用 RVP 自身 IR 导弹配置，避免新造参数。
- 不将 RVP 干扰物打 `superbwarfare:decoy` 标签（避免误干扰 guideType=1），严格由 RVP ticker 限定 guideType=0。

## 8. 实现进度（2026-08-25）

- **Phase 1（干扰+告警）已完成**：`RVP_SuperbWarfareCompat` + `RVP_SbwThreatManager`（服务端每 4 tick 扫描 SBW `guideType=0` 导弹 → 红外告警 + 烟雾致盲 + 热焰弹/烟雾弹诱偏）。编译通过、无 SBW 冒烟无崩溃、已部署客户端。
- **Phase 2（gunner 自动抛洒）已完成**：在威胁管理器中，被 SBW 红外导弹锁定的载具若由 gunner 驾驶（`vehicle.getDriver() instanceof GunnerEntity`，对齐本体 `isGunnerDriven`），复用 `RVP_CountermeasureRuntimeManager.fire` 抛洒热焰弹与烟雾弹（2s 冷却去重）。
- **Phase 3（DIRCM 照射偏转）已完成并重做**：SBW `guideType=0` 导弹**并入 RVP DIRCM 通道状态机**（不再走独立并行扫描）——`tickChannel` 在通道空闲且充能完毕时经 `findSbwTarget` 扫描前方探测扇区内的 SBW 红外导弹，占用 `busyTargetId`、进入光束照射期并调用 `RVP_SuperbWarfareCompat.deflectSbwMissile` 每 tick 偏转；光束结束或脱出范围 → 释放通道并进入 `chargeTick` 冷却，与 RVP 导弹的 DIRCM 状态机几乎一致。偏转实现为：清空原锁定（禁用 SBW 自身制导修正）+ 用 SBW 自有 `turn(away, 3°/tick)` 把弹体朝向转向「远离载具 + 下坠」方向，使航线被推离（**非直线飞离**）。`guideType=1` 激光/指令制导不受影响；卸载 SBW 时 `isLoaded()` 短路，不占用通道、不触碰 SBW 类。
- 全部经 `compileJava` / `build` / 无 SBW `runServer` 冒烟验证（无崩溃）。实机效果需在装有 SBW 的客户端验证。
