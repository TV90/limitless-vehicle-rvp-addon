## 一、调研结论

### 1.1 RVP 水中能力现状

**已有的**：

1. **水中运动字段已预留**：`RVP_ProjectileData.java:31-41` 有 `gravity_in_water`（水中 Y 加速度）
   与 `drag_in_water`（水中线性阻力），默认均 0。143 个现有武器 JSON 无一使用。
2. **三条无推力路径有水分支**：机炮弹（`RVP_ProjectileMotion.tickCannonBullet` :44-51，入水
   friction=0.4 + 重力×0.6）、无推力简化弹道（`RVP_BaseBullet.tickBallisticMotion` :2464-2489）、
   子母弹分量化部署弹道（:2393-2408）——水中用 `gravity_in_water`/`drag_in_water`。
3. **近炸引信与水无关**：`findProximityTargetOnSegment`/`tickProximityFuse`
   （RVP_BaseBullet.java:2694-2761、3227-3267）候选收集是 AABB 查询（含 §48 注册表补筛），
   过滤条件无任何流体判断——**鱼雷水下对水面舰船近炸起爆天然可用**。
4. **爆炸伤害与水无关**：本体 `VehicleExplosion.hurt`（:399-427）纯距离衰减，无流体检测——
   水下爆炸对实体（舰船）伤害全额；客户端视觉已有水下分支（按爆心方块 `Blocks.WATER`
   出水花/气泡）。
5. **§48 注册表补筛已接**：RVP 弹三条命中链候选收集走 `RVP_ServerVehicleIndex.mergeWithVehicleIndex`，
   巨型载具（船）分节盲区已兜底——鱼雷命中链直接受益，无需额外处理。

**缺失的（鱼雷核心体验缺口）**：

1. **无入水/出水边沿事件**：方块碰撞 `ClipContext.Fluid.NONE`（RVP_BaseBullet.clipBlockSegment
   :3351、本体 AmmoEntity.java:107），弹体穿越水面无任何感知点。
2. **推进段不判水**：`RVP_ProjectileMotion.tickMissileMove`（:60-148）的二次平方阻力
   `RVP_QuadraticAirDrag.apply` 不判水，重力分支 `applyPropulsionGravity`（:380-394）水中只有
   `gravity_in_water` 替换——没有水中定速、没有垂直阻尼摆平。
3. **constant_speed 与水无关**：`RVP_ProjectileSpeedMath.resolvePeakSpeed` 峰值回填会把入水后的
   弹体拉回空气段速度，无法表达"水中巡航速度"这一独立基准。
4. **无水中尾迹/入水花**：仅机枪弹 4 粒气泡（RVP_BulletEntity.java:272-279）。
5. **雷达天然探不到水下目标**：`RVP_RadarScanHelper.isWithinScanHeight`（:46-63）以
   MOTION_BLOCKING 高度图（含水面）为基准的离地门（默认 min 25），水下目标离地为负被过滤。
   对鱼雷属"正确副作用"（真实鱼雷也不被雷达探测），见 §3.8。

### 1.2 MCH-Reforged 鱼雷参考要点

`D:\MCHR\MCH-Reforged`（MC 1.7.10，`mcheli.weapon.MCH_EntityTorpedo`）。机制可借鉴，数值不搬
（单位制不同：MCH 是自家速度标度，RVP 是格/tick）：

1. **水中定速模型极简有效**：入水后速度矢量归一化重设模长 = `accelerationInWater`（巡航速度），
   加速斜率 0.1/tick 收敛；空气中走常规重力+阻力弹道。入水即"重置速度"天然解决入水减速。
2. **深度保持 = 垂直阻尼**：水中 `motionY *= 0.8`/tick 自然摆平到水平直航，无定深舵。
3. **制导**（仅两种，RVP v1 均不采）：非制导直航；`GuidedTorpedo=true` 时发射瞬间沿瞄准线
   raycast（150 格内必须命中水方块，否则拒绝发射），把命中点作为固定目标点直航（瞄准点自航，
   不追活动目标）。
4. **水下爆炸独立参数**：`ExplosionInWater` 与水面/空中 `Explosion` 分开配；水下爆炸对方块
   阻力打折（MCH 特有，MC1.20 原版行为是水抗性 100 天然挡破坏，见 §3.6）。
5. **特效三件套**：入水花（客户端逐 tick 对比水方块找入水点生成 splash 粒子）、水中气泡拖尾
   （原版 bubble，弹后 1/4 格）、水中烟雾尾迹（仅水中生成，插值 prevPos→pos）。
6. **发射**：出管初速 = 瞄准方向×初速 + 载具速度（继承舰船航速）；无发射深度限制；舰船武器站
   照常挂载（鱼雷管=静态模型部件 + 武器站扇面限位）。

### 1.3 缺口对照表（鱼雷需要 vs RVP 现状）

| 鱼雷需要 | RVP 现状 | 处置 |
|---|---|---|
| 入水检测与边沿事件 | 无（ClipContext.Fluid.NONE） | **新增**：逐 tick 对比 `isInWater()` 上一 tick 状态 + 有效深度消抖 |
| 水中定速直航 | 无（constant_speed 与水无关） | **新增**：`RVP_TorpedoEntity` 专属运动分支，独立速度基准 waterSpeed |
| 深度摆平 | 无 | **新增**：depthDamping 垂直速度衰减 |
| 出管段空中弹道 | ✅ 现有 projectile_data 字段 | 复用 velocity/gravity/drag/inherit_vehicle_velocity |
| 入水花/水中尾迹 | 仅机枪 4 粒气泡 | **新增**：effects_data 水中扩展字段，客户端本地生成（零网络包） |
| 水下爆炸独立威力 | 无（伤害/半径一套值） | **新增**：explosion_data 加 damage_in_water/radius_in_water（null=复用） |
| 瞄水发射门 | 无 | **新增**：require_aim_water 服务端射线（可选，默认关） |
| 水下对舰近炸 | ✅ 引信不判水 | 复用 fuse_data |
| 命中巨型船（§48 盲区） | ✅ 注册表补筛已接 | 复用 |
| 雷达探测鱼雷 | 天然探不到（离地门） | 不处理（属预期，§3.8） |

## 三、实现方案

### 3.1 运动状态机（`RVP_TorpedoEntity`）

RVP 单位制：**速度=格/tick（20 tick=1 秒），1 格=1 米**。四态：

```
出管(空中) ──入水边沿──▶ 入水过渡 ──lerp完成──▶ 水中巡航 ──出水边沿──▶ 出管(空中)
    │                        │                     │
    └── 命中/近炸/延时/寿终自爆 ◀─────────────────────┘
```

1. **出管段（空中）**：完全复用现有弹道——`velocity` 初速 + `inherit_vehicle_velocity`
   继承船速 + `gravity`/`drag` 弹道；`rotate_to_motion` 姿态跟速。此段鱼雷与普通火箭无异。
2. **入水检测（边沿 + 消抖）**：每 tick 对比 `isInWater()` 与上一 tick 值；由"干"转"湿"且
   **实体中心上方 `water_entry_min_depth`（默认 0.5 格）处仍为水**才判定有效入水——防止贴水皮
   反复切换（浪区/水面掠飞抖动）。入水瞬间把 `waterEntryLerpProgress` 清零。
3. **入水过渡（`water_entry_lerp_tick`，默认 10t）**：速率从入水瞬间实际值向 `water_speed`
   线性过渡（模拟入水减速 + 螺旋桨起转）；方向保持不变（不产生入水转向）。
4. **水中巡航**：方向保持（直航，v1 无转向）；速率恒为 `water_speed`（**独立速度基准，与
   `constant_speed`/峰值回填体系完全无关，鱼雷 JSON 不应配 `constant_speed`**）；垂直速度每
   tick 乘 `depth_damping`（默认 0.8，MCH 同款自然摆平到水平）后重新归一化到巡航速率——
   即"摆平"不改变速率只收敛俯仰。水中姿态 `rotate_to_motion` 跟速（雷头朝速度方向）。
   实现注意：水中**不走** `RVP_ProjectileMotion.tickMissileMove` 的推力/二次阻力/气动路径
   （`has_rocket_engine` 对 `rvp:torpedo` 无意义，鱼雷是螺旋桨巡航模型，不出水花不点尾焰）。
5. **出水（跃出水面）**：回到出管段（受 `gravity` 弹道），再次入水再次进过渡——出管段与水中
   状态天然可循环，无需额外参数。

状态只需两个实例字段（`inWater` 布尔 + 过渡进度），无 SynchedEntityData、无生成包改动
（客户端特效自判 `isInWater()`，见 §3.5）。

### 3.2 实现落点

- `RVP_TorpedoEntity.tickMotion()` override（分派点 `RVP_BaseBullet.tick()` :2335-2355 之后
  的 `tickMotion`）：入水边沿检测 → 按状态分派"空中=super（现有弹道）/ 过渡 / 巡航"。
- 命中链/近炸/攻顶/自毁/寿命/跳弹/伤害衰减**全部不 override**——直击
  `findEntityOnPathForSegment`、近炸 `findProximityTargetOnSegment`（不判水）、爆炸
  `triggerExplosion`（:3921-4059）直接复用；水下命中链与 §48 补筛自动生效。
- 水下爆炸伤害分流（`damage_in_water`/`radius_in_water`）在 `RVP_BaseBullet.triggerExplosion`
  解析 `RVP_Explosion` 参数处按**爆心 `isInWater()`** 选值（爆心在水下→用水下组，否则常规组），
  只影响参数选择，不碰本体 `VehicleExplosion`。

### 3.3 发射门（瞄水判定，可选）

- `torpedo_data.require_aim_water=true` 时：服务端 `RVP_ProjectileWeapon.dispatchShots`
  （:156-200，现有离轴终检同位置）沿武器站瞄准方向 `ClipContext` 射线（流体模式取任意流体），
  `require_aim_water_range`（默认 150 格）内命中流体方块才放行。
- 未瞄水拒绝不耗弹，向射手发动作栏提示（新 lang 键 `ui.rvp.torpedo_not_aiming_water`，
  zh："未瞄准水面" / en："Not aiming at water"）。
- 默认 `false`：不配不门控（飞机空投鱼雷、甲板炮射直航均可）。

### 3.4 引信（全部复用 fuse_data，零新字段）

- **碰炸（触发引信）**：直击命中即爆（`collision_data.direct_damage` +
  `detonate_data.explosion_data.explode`）。注意 `fuse_data.delay_tick` 是**定时引信**
  （飞行 N tick 后在当前位置引爆，`RVP_FuseData.java:10`），不是出管解保——鱼雷必须配 0，
  否则会在升空段/入水瞬间自爆（2026-10-02 实机踩坑）。命中链排除射手载具
  （`canDamageEntity`），出管不会打到自己船，无需解保字段。
- **触发**：直击命中即爆（`detonate_data.explosion_data.explode`）。
- **近炸**：`fuse_data.proximity_radius` 水下可用（候选收集不判水）——非触发引信鱼雷
  （磁性/感应引信的近似）配近炸即得；`proximity_fuse_tick` 解保、`proximity_fuse_height`
  贴地保护照常语义。
- **寿终**：顶层 `life`（总寿命 tick）+ `fuse_data.detonate_on_life_end`；航程限制 =
  `life × water_speed`（例：航程 5000 格 @1.5 格/tick → life 3400）。
  `projectile_data.self_destruct_distance` 可作距离上限补充。
- 已知边界：`isProximityFuseTargetTooLow` 基于 MOTION_BLOCKING 离地高度，水下贴水底的
  目标（假想潜艇）可能被近地门误杀——v1 无此目标类型，记录不处理。

### 3.5 特效（客户端本地生成，零网络包）

- **入水花**：客户端 `RVP_TorpedoEntity` tick 中检测入水边沿（与 §3.1 同款判定），在入水点
   生成 `water_entry_particle`（默认 `minecraft:splash`）粒子簇 + 播 `water_entry_sound`
  （默认空=无声；推荐 `minecraft:entity.player.splash`）。客户端可本地判定故无需服务端事件。
- **水中尾迹**：水中巡航段每 tick 沿弹后位置生成 `water_trail_particle`（默认
  `minecraft:bubble`）× `water_trail_count`（默认 2）——原版 bubble 水下自然上浮消散，
  观感即"雷迹气泡带"；空气中不生成。
- **尾焰/发射烟**：鱼雷不配 `has_rocket_engine`、不配 `missile_native_trail_*`——出管段只有
  `effects_data.trajectory_particle`（可配烟迹，默认 `minecraft:cloud`），入水后轨迹粒子
  自动停用（水中换 §3.5 水中尾迹通道）。
- **水下调色**（MCH colorInWater 同款）：不做，bedrock 模型+贴图已够；列为二期可选。

### 3.6 爆炸（水下语义）

- 参数分流：`explosion_data.damage_in_water`/`radius_in_water`（默认 null=复用
  `damage`/`radius`）。MCH `ExplosionInWater` 语义对齐：鱼雷入水后爆炸（含近炸触发、寿终
  自爆、直击）按爆心位置选水下组。
- **方块破坏的物理现实**：原版水爆炸抗性 100——本体 `VehicleExplosion.processRay`（:732-750）
  逐格扣射线能量时水中方块几乎耗尽射线，**水下爆炸基本炸不动固体方块**（本项目原样继承原版
  行为）。因此鱼雷 `destroy_block` 建议直接 `false`（省一枚"配了不生效"的疑惑）；若未来要
  "水下爆破破坏"属本体侧行为变更，不在 RVP 侧解决。
- 对实体（舰船/生物）伤害不受水影响（§1.1 现状 4）——反舰杀伤核心通道，配
  `explosion_damage_factor` 可调对载具倍率（现有字段）。

### 3.7 发射平台

- 船载具武器站照常挂载：载具 JSON 武器站配 `rvp:torpedo` 武器 id + 扇面限位（侧舷/舰艏
  yaw 限位、小俯仰限位），无新概念（与 MCH `AddWeapon` 鱼雷管同构）。
- 出管初速方向 = 武器站朝向；`inherit_vehicle_velocity=true` 继承船速（动对动射击的初速
  合成，MCH 同款）。
- 无发射深度限制参数：`require_aim_water=true` 已隐式覆盖"必须对水发射"；空中/水面均可发射。

### 3.8 雷达/告警联动（不处理，记录语义）

- 鱼雷发射后在雷达上**不可见**：`isWithinScanHeight`（RVP_RadarScanHelper.java:46-63）的
  MOTION_BLOCKING 离地门（默认 min 25）把水下目标滤掉——与真实鱼雷不被雷达探测一致，属预期。
- 被动告警（RWR/LWR）天然不触发（鱼雷无辐射源）。
- "反鱼雷预警/声呐"是全新探测概念（非现有雷达参数可表达），列二期外观察项，不在本方案。

## 四、参数清单概览

  `depth_damping`(0.8)、`water_entry_min_depth`(0.5)、`require_aim_water`(false)、
  `require_aim_water_range`(150)。
- **复用 projectile_data（出管段）**：`velocity`、`gravity`、`drag`、
  `inherit_vehicle_velocity`、`rotate_to_motion`、`max_speed`/`min_speed`；
  **不要配** `constant_speed`/`has_rocket_engine`/`gravity_in_water`/`drag_in_water`
  （水中动力学由 torpedo_data 接管，前两者对鱼雷无意义）。
- **复用 fuse_data（全引信）**：`proximity_radius` 族（感应）、`detonate_on_life_end`（寿终）；
  `delay_tick` 是定时引信必须保持 0（碰炸不用，见 §3.4）。
- **explosion_data 扩展（2 字段）**：`damage_in_water`/`radius_in_water`（null=复用）。
- **effects_data 扩展（4 字段）**：`water_trail_particle`(`minecraft:bubble`)、
  `water_trail_count`(2)、`water_entry_particle`(`minecraft:splash`)、`water_entry_sound`("")。
- **顶层复用**：`name`/`name_CN`、`life`（航程=life×water_speed）、`shoot_interval`、
  `max_capacity`、`reload`、`velocity`、`damage`、`misc_data.ammo_radar_rcs_factor`（发射段
  空中可被雷达看到的窗口按此收缩）、`show_msl_indicator`。

## 六、验证计划（实现轮次执行）

1. **构建**：`JAVA_HOME`=JDK21，`./gradlew build` 通过、零新增编译警告级问题。
2. **服务端冒烟（新方法，交接文档必读条目）**：`./gradlew runServer --console=plain >
   server_smoke_torpedo_<日期>.log 2>&1` 后台启动 → 每 5 秒轮询 `grep -a "Done ("` → 见 Done
   立即 `wmic process where "name='java.exe' and commandline like '%ywzj%'" get processid`
   取 PID → `taskkill //PID <pid> //F` → `/c/Windows/System32/tasklist.exe` 全路径复验 java
   进程为 0。对照基线只看新增错误（11 条 bedrock 缺失等既有噪音不算）。
   注意：run 目录载具包暂不同步，冒烟只验代码启动（type 注册/实体注册/JSON 解析器空跑）。
3. **实机清单（用户执行，第 N 轮）**：
   - 052D/船只挂鱼雷武器站，向水面发射：出管段弹道正常（继承船速）；
   - 入水瞬间有水花+音效、速率在 ~0.5 秒内收敛到 water_speed、不再受重力下沉；
   - 水中直航：深度自然摆平、气泡尾迹连续、模型雷头朝速度方向；
   - 命中船体爆炸：水下爆炸伤害入账正常（设备/引擎面板可见），命中点位与直击/近炸一致；
   - `require_aim_water=true` 时瞄陆地拒绝发射并提示，瞄水放行；
   - 寿终（life 耗尽）自爆；**入水不再自爆（delay_tick=0，定时引信不启用）**、
     直击船体才爆（碰炸）；
   - 发射后雷达上鱼雷接触消失（离地门，属预期）；
   - 回归：同船导弹/机炮行为不变，`rvp:torpedo` 未配置时其他武器 JSON 解析不受影响。
