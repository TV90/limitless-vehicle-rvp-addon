# RVP ARM 锁定框本体风格与自渲染离轴圈（2026-09-13）

> 状态：已落码，编译与 dev 服务端冒烟通过，**待实机行为回归**。
> 需求来源：①ARM 锁定框观感差，要求换成本体雷达弹（RF）的锁定风格；②ARM 开导引头后
> "大圈"时有时无——用户方案：屏蔽本体 RF 传感器大圈，改为 ARM 武器自渲染（参照 RVP 红外弹
> 的自渲染模式：一个头瞄圈、一个离轴圈）。

---

## 一、根因（"大圈时有时无"）

导引头大圈由**本体** `VehicleAimAtOverlay:110-137` 绘制，硬门槛是**武器站**的
`fire_control_sensor_type ∈ {ir, rf}`（载具 JSON 站级配置）：

- su57 `kh_58` 站配 `"rf"`（su57.json:161）→ 打 KH58 有大圈；
- j16d `variable_agm` 站（挂 LD10/LD8A/YJ91）配 `"eo"`（j16d.json:479）→ 永远没有大圈。

换载具打 ARM 即表现为"时有时无"——**非概率问题，是各载具武器站 sensor 配置不一致**。
RVP 的 `WeaponUnitGetSeekerFovMixin` 负责修正 RVP 弹的圈半径（`2.8 × getSeekerFov()`），
该部分工作正常。

## 二、修复（用户方案：ARM 圈全面自渲染）

### 2.1 锁定框换本体 RF 雷达锁定风格（`RVP_ArmOverlay` 重写）
- 未锁定辐射源：单层绿框 `RenderHelper.drawSquare(15, GREEN)`（本体"雷达可锁定的目标"同款）；
- 预选锁定辐射源：**双层绿框 `drawSquare(15) + drawSquare(10)`**（本体"雷达锁定目标"同款，
  `VehicleScopeOverlay.renderAimLockTarget:275-283`）；
- 删除旧版手绘 14px 矩形描边与红双圈（r10/7）。纯客户端渲染类，零 Mixin。

### 2.2 屏蔽本体大圈（`WeaponUnitGetSeekerFovMixin`，零新增注入点）
当前武器为 RVP 导弹且主相位制导类型为 **ARM** 时 `cir.setReturnValue(0f)`——
本体大圈半径 `2.8 × 0 = 0` 不可见。已核实 `WeaponUnit.getSeekerFov()` 全工程唯一消费方即
本体 `VehicleAimAtOverlay:137` 大圈半径（其余 `getSeekerFov()` 调用为武器数据层同名方法，
不受影响）；SARH/ARH/IR 走原 fov 逻辑不变。

### 2.3 ARM 自渲染（`RVP_MissileOverlay` 新增 ARM 分支）
`seekerOn` 且离轴角 ≥5° 时绘制（与 IR 分支同款门控/呼吸节奏）：
- **离轴圈**：IR 离轴圈同款投影算法（武器站 pivot ± (rot.x ∓ fov) 求屏幕半径，中心=武器站
  指向），fov = `resolveLaunchOffAxisLockAngle()`（ARM 的 `guide_head_max_angle`）；
- **头瞄圈**：预选锁定雷达位置（`RVP_ClientArmState` 锁定 contact 投影）上画 RF 导引头锁定
  风格**红双小圈 r=5/4**（闪烁节奏复刻 IR 头瞄圈），与 2.1 的双层绿框叠加成完整
  "本体雷达弹锁定"观感。

效果：任何载具打 ARM，导引头圈全部由 RVP 自渲染，不再依赖武器站 sensor 配置
（j16d"无圈"与 su57"本体圈"的不一致一并消除，且无双圈叠加）。

### 2.4 保留边界
- 本体 RF 导引头小圈（sensor=rf 站、未锁定时 r5/r4 白圈）保留；实机观感若冲突再评估屏蔽；
- SARH/ARH 各载具仍走本体大圈（分支仅命中 ARM）。

## 二·B（2026-09-14 迭代）离轴圈改四角框 + 锁定雷达型号文案

1. **离轴圈 → 四角托架框**（`RVP_MissileOverlay.renderArmCircles`）：离轴圈半径 `r` 照常计算
   但不渲染圆；改画本体 `RenderHelper.drawSquareCorners(gg, cx, cy, size=2r, corner=max(r/4,4))`——
   (不可见的) 离轴圆内接于四角托架方框（圈缘=框边），呼吸节奏不变。
2. **锁定雷达型号文案**（`RVP_ArmOverlay`，仅预选锁定目标）：双层绿框下方 22px、0.8 缩放、
   绿色 `drawCenteredString` 渲染目标雷达的 `radar_type`（`RadarUnitData.getRadarType()`，
   载具 JSON 雷达单元配置），排版对齐本体 NCTR 文案、`StringUtils.abbreviate(…, 14)` 截断；
   解析失败 / 未配置 / ECM 伪脉冲（radarIndex=-1 无真实雷达）不渲染。

## 二·C（2026-09-14 迭代 2）离轴框绿色内接 + 双白圈抑制 + 导引头轴解耦

1. **离轴四角框改绿色 + 内接尺寸**：白色呼吸 → **绿色**（保留呼吸透明度）；
   `size = 2r`（外切）→ **`size = r√2`**（内接，四角落在离轴圆上）。
2. **本体 RF 导引头双白圈对 ARM 抑制**：复用 `VehicleAimAtOverlaySeekerColorMixin` 的
   RF 双圈既有 WrapOperation（ordinal 1/2）——当前操作武器为 RVP ARM 时跳过绘制；
   `RVP_MissileOverlay` ARM 分支在无预选锁定时于武器站瞄准点（IR 小圈同款插值位置）
   补画**绿色小四角框**（size=10/corner=3）替代。eo 站（本就不画双圈）与 rf 站观感统一。
3. **捕获门控定版（2026-09-14 修正，撤销 180° 全向误改）**：
   `RVP_RuntimeArmGuidanceSource` 扫描视场 = **离轴圈**（`max_off_axis_lock_angle`，弹轴为中心）——
   仅弹轴周围离轴圈内的辐射源可被捕获，离轴圈外（含侧后方）一律不抓；与武器站轴无关
   （飞行中转武器站不影响导弹捕获）。曾短暂实现的 180° 全向扫描已撤销（会导致
   "有辐射源就一定被打"）。`resolveArmScanHalfAngle` 删除。
    注意：`guide_head_max_angle`（离轴角）即捕获门控参数，同时决定 HUD 四角框大小。
    `parent_weapon_unit_aim` / 观瞄准星随动不受影响。
   客户端预选扫描锥角改用 `max_lock_angle` 全值（"打出去时的扫描范围"，与离轴捕获同口径，
   不再减半）。ARM 参数定版：`max_lock_angle=40`、`max_off_axis_lock_angle=40`、
   `max_guidance_angle=60`（后者当前对 ARM 无消费，预留）。
