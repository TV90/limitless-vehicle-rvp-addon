# RVP 反辐射导弹预选独占窗口（2026-09-13）

> 状态：已落码，编译与 dev 服务端冒烟通过，**待实机行为回归**。
> 需求来源：用户报告"锁 A 雷达打 B 雷达"——ARM 预选优先级实战经常不生效；用户提出"预选独占
> 窗口"方案并确认（窗口内仅预选+ECM 可参与选择，窗口结束恢复自主捕获）。

---

## 一、根因（调查结论）

预选优先级的实现是**逐 tick 重选**（`RVP_RuntimeArmGuidanceSource.selectEmitter` 每次扫描重跑），
预选分支的条件是"预选雷达**此刻在可见名单里**"。可见性规则不对称导致预选天然吃亏：

- **正在锁人的雷达恒可见**（`locked=true` 无条件可见）——每 tick 都在名单里；
- **机械扫描雷达间歇可见**——仅波束扫到导弹的 tick 可见 + `radiationPulseMemoryTick` 余留窗口。

锁 A（扫描雷达）而 B 正在锁人时：A 不可见的 tick 预选分支落空，导弹朝恒可见的 B 转；
A 只在波束扫过的少数 tick 夺回——观感即"锁 A 打 B"。叠加因素：客户端预选 UI 扫描中心是
车体炮塔、服务端是导弹自身（可见集脱节）；`evaluate:68` 的"朝预选快照飞"分支带
`!hasAntiRadiationSignalAcquired()` 门槛，一旦咬过其它源即永久失效。

**与记忆时间无关**：`arm_memory_tick` 只服务"信号丢失后追多久"，与选目标优先级无关（用户猜测排除）。

## 二、修复：预选独占窗口（用户方案）

发射带预选时进入**独占窗口**（时长 = 记忆时间同源取值：`arm_memory_tick` > 0 用之，否则 20 tick
——与 `getDefaultMemoryTick(null)` 兜底一致）。窗口内：

- `selectEmitter` 新增 `exclusive` 参数：**跳过"最高分"分支**——可选源仅剩
  **ECM 干扰机（arm_priority 5 秒窗口，最高优先，用户确认保留）∪ 预选雷达**；
- 预选可见 → 现有咬住逻辑 + 更新弹体新增字段 `armPreselectLastPos`（预选最后已知位置，
  ECM 伪脉冲与其它源不更新，防污染）；
- 预选不可见 → 朝 `armPreselectLastPos` 飞（不改选其它源）；窗口内保持每 tick 急扫描
  （interval=1），不放过预选雷达间歇波束扫过的短窗口；
- 窗口耗尽 → 恢复现有全逻辑：ECM > 预选可见优先 > 最高分；曾咬住过的信号丢失走现有
  `antiRadiationMemoryLeftTick` 记忆分支——**现有代码路径全部保留**。

### 改动点
| 文件 | 改动 |
| --- | --- |
| `RVP_BaseBullet` | 新增纯服务端字段 `armPreselectExclusiveLeftTick` / `armPreselectLastPos`（+getter/setter），不同步客户端 |
| `RVP_RuntimeArmGuidanceSource` | tick 0 `copyPreselectedEmitter` 后初始化窗口（预选存在时）；每 tick 递减；`selectEmitter` 加 `exclusive` 参数（窗口内跳过最高分分支）；咬住预选刷新 `armPreselectLastPos`；预选追踪分支改造（窗口内独占追踪 / 非窗口保留原快照行为）；窗口内 interval=1 急扫描 |

零协议改动、零 JSON 字段、零 Mixin。无预选发射 / LH/SALH/IR/ARH/TV 等其他弹型零变化
（窗口仅由预选存在触发，字段仅 ARM source 消费）。

## 四、回退

删除 `evaluate` 中窗口初始化/递减与 `exclusive` 参数透传（`selectEmitter` 恢复无条件最高分）、
预选追踪分支恢复 `!acquired` 原条件，删除 `RVP_BaseBullet` 两个新字段即完全恢复原行为。
