# HITL 观察半径 32 测试（2026-11-02）

用户已澄清要扩大导弹相机周围能看多远，而非缩小窗口总块数。本轮选择半径32区块，目标窗口65×65=4225块，沿轴预取1块时4290个中心，斜向4354个中心。此前未执行半径2修改；基线仍为半径6。

## 实施范围与影响

- 统一武器参数、窗口几何、窗口网络包和服务端配置的硬上限至半径32。
- 服务端以专用 max_radius_chunks 控制远程窗口，解除与玩家身体普通服务端视距的耦合；普通身体区块仍由原版管理。客户端的实际绘制仍受本地渲染距离限制，测试需设32。
- 单会话加载/发送参数硬上限均提高到32；全服新增票据允许上限提高到32。常规默认半径6、全服默认预算4/8及服务器默认半径上限8保留。
- 七种已启用HITL武器改为测试配置：半径32、每tick新增中心24、完整包32；其余武器参数保持基线语义。
- 提供单相机测试用 ywzj_rvp-hitl-remote.toml：max_sessions=1、max_radius_chunks=32、new_chunk_tickets_per_tick=24、chunk_packets_per_tick=32、max_pending_chunks=64。其余距离/实体上限保持原值。已有配置文件不会因jar升级自动改值，测试需同时应用此配置。
- 版本0.1.0n→0.1.0o，协议36→37，避免旧客户端把半径32静默截成12；双端同版。
- 不增加Mixin或注入点；原客户端渲染、单面剔除和UAV流程不变。

## 性能边界与回退

目标观察块数约为原来的25倍；实际邻域依赖会带来更多工作。分批预算和未就绪中心上限保留。半径32也不保证未生成地形在高速移动时始终补齐；本轮将用隔离平坦世界实际验证缓存范围、远端目标及退出释放，并记录构建/启动结果。

代码备份见 `_tmp_hitl_radius32_state_20261102.json` 所列路径。包文件修改前先在根包_bak保留七份原件，build副本也备份并正向同步。回退只需恢复本轮备份的七个包文件和测试TOML，或将半径/预算恢复6与原分组值；不进行真删除。

BUK-M3/IRIS-T SLM雷达候选的initial_speed=null问题已只读确诊，尚未修复，不属于本次窗口调整。
