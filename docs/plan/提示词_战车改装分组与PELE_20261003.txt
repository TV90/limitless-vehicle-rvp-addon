【实现要点（照做，不要自己换方案）】

■ C-1　放宽分组槽的 ids 数量约束
文件：src\main\java\org\ywzj\rvp\config\RVP_VehicleExtendedConfigManager.java，方法 parseModdingOnlyMulti
把这一行里的数量判断：
    || weaponObj.getAsJsonArray("ids").size() < 2) {
改为：
    || weaponObj.getAsJsonArray("ids").isEmpty()) {
理由：单弹种的「组」也必须被认作分组载体（AP 组只有 1 个弹种）。该方法只影响判定表内容，其余逻辑（getModdingGroupEntries 只遍历这张表）不变。
注意：getModdingGroupEntries 只遍历 moddingOnlyMultiByPartId，所以这处不改，改装界面里整组（含后续 merge 组）都不会出现。

■ C-2　新增子母弹触发器 ON_PENETRATE（穿透方块后）
文件 1：src\main\java\org\ywzj\rvp\weapon\data\RVP_EnumSubmunitionTrigger.java
  - 枚举新增一项（放在 ON_BLOCK_HIT 之后、ON_ENTITY_HIT 之前均可，需带 javadoc）：
        /** 穿透方块成功后（在撞击处理继续/终止之前）。 */
        ON_PENETRATE,
  - fromString 新增分支：
        case "on_penetrate", "penetrate", "penetration", "after_penetration" -> ON_PENETRATE;
文件 2：src\main\java\org\ywzj\rvp\entity\projectile\RVP_BaseBullet.java，方法 handleBlockImpact
  位置：穿墙成功之后 —— 即 wallPenetrationLeft--; applyPenetrationSpeedDecay(); penetrationEventCount++; 这三行之后、BlockPos penetratedPos = blockPos; 附近（约 3341-3344 行）。
  插入：
        if (trySubmunitionTrigger(RVP_EnumSubmunitionTrigger.ON_PENETRATE)) {
            compensateImpactTrail(RVP_WallPenetrationUtil.positionPastBlockFace(hit, getDeltaMovement(), result));
            discard();
            return true;
        }
  ⚠️ 关键语义（务必理解，别改错）：trySubmunitionTrigger 的返回值 = 子母弹 runner 的 fireTrigger 返回值 = 「是否应立刻丢弃母弹」，由配方的 parent_action 决定：
      - parent_action: "continue"          → 返回 false → 上面 if 不进入 → 母弹穿墙后继续飞（这是 PELE 想要的）
      - parent_action: "discard_after_release" / "discard_on_first_spawn" → 返回 true → discard()
  ⚠️ 不要照抄 on_block_hit 那段（约 3369 行）：那里是【无条件】discard()（不看返回值），因为撞击必然终结弹体；穿透路径必须用返回值，否则母弹会被误丢、穿墙后飞不出去。
  ⚠️ 为什么必须新增：穿墙成功后若墙后无方块，代码会 return false 让弹体继续飞（约 3354 行），所以「穿透一格墙」这件事当前没有任何可挂钩的时机。

■ C-3　跳弹计入伤害衰减
文件：src\main\java\org\ywzj\rvp\entity\projectile\RVP_BaseBullet.java，方法 tryApplyBounce（约 3728 行）
在 bounceLeft--; / bouncesConsumed++; （约 3741-3742 行）之后加一行：
        penetrationEventCount++;      // 跳弹计入伤害衰减计数
理由：伤害倍率 penetrationDamageFactor() = penetration_damage_multiplier ^ penetrationEventCount，而该计数原先只在穿墙/穿透生物时递增，跳弹不衰减。
零影响依据（实施前请在代码里再确认一次）：penetrationDamageFactor() 首行是
    if (penetrationDamageMultiplier >= 0.999f || penetrationEventCount <= 0) { return 1f; }
而 collision_data.penetration_damage_multiplier 默认 1f ⇒ 所有未配置该字段的武器仍恒为 1 倍伤害。
配好后：子弹药写 "penetration_damage_multiplier": 0.6 ⇒ 每弹射一次伤害 ×0.6。
