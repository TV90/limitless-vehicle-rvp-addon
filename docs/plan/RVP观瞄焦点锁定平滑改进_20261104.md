# RVP 观瞄焦点锁定平滑改进

日期：2026-11-04。状态：代码已实施，构建与自动测试通过，游戏内画面待实机验收。

## 问题与对照依据

本体 `LocalVehiclePlayer.handlePlayerTurn` 的焦点分支每次从实际炮口方向重新叠加本次鼠标输入。
一个游戏刻（正常为 50 毫秒）内炮口方向尚未更新，多次输入会覆盖，而不是连续累加。
固定的 `0.33` 输入系数也未适配放大倍率。

本地 `create-fire-control-1.0.2` 为 Minecraft 1.21.1 / NeoForge 编译产物。
对照其 `ClientAimState.turnStableFirstPerson`、`PodAimController` 与
`ClientAimState.followOpticalLockMotion` 后，借鉴独立输入方向、按有效倍率缩放和逐帧锁点补偿。
其网络目标预测不用于本次焦点保持；不直接照搬不同版本的注入代码。

### 视距外锁定随车移动下飘的根因与补修

用户实测补充：主要在车辆移动时发生。首次按 R 仍沿用本体
`scopeAimPos → cameraAimHit → renderDistance`，即“设置的区块视距 × 16 方块”。
`VectorUtil.hitPosition` 返回的只是坐标，未命中时也返回射线末端，命中类型已经丢失。
上一版将这个坐标无条件接收为真实世界点，而且后续射线落空继续保留该距离，
所以车辆实际上在追踪近处空气点，而非画面中的远处地形。

几何复现：八区块视距产生 128 格远的临时点，初始向下 5 度；车辆前进 100 格而高度不变，
朝向该空气点的下俯角变成约 22.07 度。这与用户所述“主要移动时持续下飘”一致。

对照项目没有用设置视距作为选点距离：普通射线长度为 4096 格，保留显式 `hit` 标记；
无普通命中时，`SightRaycastResult.withLodFallback` 还会查询 48000 格内的 Voxy 远景数据。
RVP 本次使用已经接入的 Distant Horizons（DH，缓存的简化远景地形）官方 API 补上同类能力。

补修后的语义：真实普通表面或远景表面命中才锁世界坐标；完全查不到距离时锁世界方向。
不能仅把有限距离末端拉长，就声称已经测到了地面点。

## 实际处理流程

1. R 键仍沿原有雷达、光电、GPS 和焦点分流建立/解除锁定。
   既有 HEAD / TAIL 注入增加桥接转发，在焦点切换完成后保留真实命中语义。
2. 已有焦点时，鼠标在独立世界锁点上累加。输入没有额外死区，也不再乘帧间时间。
3. 一倍视野保留 `0.33` 输入尺度；用实际显示视野角的正切比例计算有效倍率倒数，
   跟随本体已有的倍率渐变。非法视野才回退到武器站配置倍率。
4. 首次按 R 与拖动共用 `RVP_FocusLockRaycast`，从实际观瞄位置检查普通方块/实体，
   不再把未命中的临时末端当成真实点。普通查询长度不受画面视距设置截断。
   没有普通命中时，后台查询最多 48000 格内已有的 DH 远景地形，不强制加载原版区块。
5. 本体 `tickFireControl` 继续让炮塔按原限速转向焦点并发送原有旋转消息。
6. Forge `ComputeCameraAngles` 每帧按类型解析：真实点补偿车辆移动带来的视差；
   未知距离始终保持世界方向，其供本体火控使用的位置代理随观察位置平移。
   相机事件使用 HIGH 优先级，后续原有横滚与震屏处理继续叠加。
7. 解锁后用 50 毫秒时间常数衰减镜头相对炮口的偏移，避免炮塔未跟上时瞬间跳回。
   换车、换座、退出观瞄、切世界、暂停或打开菜单时清理显示会话；仍有效焦点的命中类型
   由弱键状态表保留，避免暂停后再次把未知距离误判成真实地面。

远景扫描不在渲染线程执行；客户端最多保留一个在途任务，不逐帧堆积请求。
结果按世界、武器站、状态对象和输入代次核对；继续拖动、重新锁定或切世界后拒绝旧结果。
查询始终使用选点当时的原始射线，车辆在等待期间移动不会偷偷改变最初选中的地面位置。
DH 返回的 `pos.y` 是地形柱底部，必须用原始视线与柱体求交，不能直接锁住柱底而再次往下偏。

## 准星与其他操控的衔接

- `RVP_ScopeOverlay` 先在世界坐标插值实际弹着点，再用当前相机投影；
  焦点请求点不会替代实际弹着点。
- 无 UI 预设的 CRT 瞄具复用本体样式，通过外层绘制位置补偿得到相同投影；
  不临时改写 `weaponHitPos`，不平移光学瞄具的屏幕遮罩。
- 独立镜头不覆盖本体 `cameraAimRot`，该逻辑状态继续代表实际炮口。
  已有焦点时，GPS 改从观瞄位置沿世界焦点方向取点，避免切到 GPS 武器后标在旧炮口方向。
- 电视导弹输入保持最高优先级；原有鼠标驾驶和指定视角逻辑移到客户端桥实现，语义不变。
- 新增业务放在 `RVP_ClientFocusLock` / `RVP_FocusLockAim` / `RVP_FocusLockRaycast`，
  远景查询使用已有 DH 强类型桥，只调用其公开 API。
  复用 `LocalVehiclePlayerTVMissileTurnMixin` 与 `WeaponUnitFireControlLockMixin` 的既有注入，
  新入口只调用双端安全桥；
  未增加 Mixin 类、注入点、访问器、网络消息或 JSON 字段。

## 实机验收

自动测试验证输入和几何计算，不能代替实际瞄具画面。使用根目录权威载具包实测：

1. 地面静止时按 R 锁点，慢速微调、快速拖动、立即反向，比较不同帧率下的相同鼠标行程。
2. 低倍/高倍之间切换，倍率变化途中继续拖动，确认没有突然加速或减速。
3. 行驶、转弯或飞行中锁住静止地面点；松开鼠标后镜头持续指向该点。
4. 从墙面移向天空、跨越正负 180 度及接近正上/正下方时观察是否跳变。
5. 炮塔尚在追赶时解锁，确认短暂回交平滑，实际落点仍能反映机械追赶。
6. 分别检查带 UI 预设、无预设 CRT 和光学瞄具；焦点中切 GPS，确认标点与画面方向一致。
7. 切换电视导弹鼠标操控/指定视角、换座、退出观瞄、暂停后继续，确认旧焦点会话没有串入。
8. 用较低普通视距瞄准 DH 远景地面，按 R 后持续前进、横移和升降；确认锁定的是同一世界点。
   在 DH 尚无数据或未安装 DH 时重复，确认只保持观察方向，不出现追逐近处空气点的下飘。

能力边界：远景地面选点依赖 DH 已有的简化地形数据及其精度；没有数据时保持方向，
不声称已测得真实地面距离。不会为了选点生成远处原版区块。

实机客户端及其载具包由用户自行同步，本次不改游戏目录和 `run/**`。
