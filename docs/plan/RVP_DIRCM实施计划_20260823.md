## 1. 分阶段任务

### 阶段 A：数据层（骨骼模块系统接入）

1. **`BoneModuleType`** 增加枚举 `DIRCM`（`RVP_BoneModuleStateTable` 自动获得失效判定，无需改表）。
2. **新建 `BoneDircmConfig`**（record，仿 `BoneApsConfig`）：
   - `laserPart`（`ywzj_vehicle:weapon` 型部件 id，照射骨骼兼光束起点/失效锚点/动画联动锚点）
   - `facingPart`、`facingYawDeg`、`scanFovDeg`、`detectRadius`、`approachAngleDeg`
   - `beamTick`（光束美术特效时长，默认 20 = 1 秒）
   - `chargeTick`（充能，默认 300 = 15 秒）
   - `scanIntervalTick`（默认 5）
   - `excludeOwnerProjectile`（默认 true）
   - `parse(JsonElement)` 仿 `BoneApsConfig.parse`
3. **`RVP_VehicleHitboxFactorManager`**：
   - `BoneModuleConfig` record 增 `@Nullable BoneDircmConfig dircm` 字段；
   - `parse` 里加 `BoneDircmConfig.parse(obj.get("dircm"))`；
   - 新增 `resolveDircmDevices(AbstractVehicle)` getter（仿 `resolveApsDevices`，返回
     `Map<String, BoneDircmConfig>`，key=骨块名）。

### 阶段 B：服务端运行期

4. **新建 `RVP_DircmRuntimeManager`**（仿 `RVP_ApsRuntimeManager`）：
   - 每载具状态 `DircmState`（按 UUID 侧表）：每通道一个槽位
     `{ busyTargetId, beamRemainTick, chargeRemainTick }`；
   - 公共 tick 接入：参照 `RVP_ApsEventHandler`（若无则新建 `RVP_DircmEventHandler`），
     每 tick 调 `tick(AbstractVehicle)`（仅服务端）；
   - 流程：存活模块 → 空闲通道 → 扫描扇区（`facingPart/facingYaw/scanFov/detectRadius/
     approachAngle`，复用 `RVP_JammingRuntime.resolveFacing` 与 `withinAngle`）→
     锁最近 `RVP_BaseBullet` → **立即干扰判定**（§3.5）→ 建光束并进入 `beamTick` 跟踪 →
     tick 归零/目标脱出/命中 → 释放通道 → `chargeTick` 充能；
   - 干扰判定：当前有效制导类型 ∈ {IR, AIR, ARH, HITL_TV, HITL_CLOS_TV} → 可干扰；
     其余（含无制导火箭/普通炸弹）→ 仅占通道不干扰。
5. **新建 `RVP_DircmStateSavedData`**（仿 `RVP_ApsStateSavedData`）持久化各通道状态。

### 阶段 C：干扰/偏转通用化

6. **`RVP_BaseBullet`** 增被干扰状态字段（建议 `dircmJammedTick` / `dircmSourceVehicleId`，
   或复用现有 `jamming*` 字段族）。
7. **抽公共偏转工具 `RVP_JamDeflectionHelper`**：把
   `RVP_RuntimeSaclosGuidanceSource` 里的 `applyVelocityRotation` + `offsetDir`（横向+向下）
   数学抽成公共方法，供 SACLOS 与 DIRCM 共用；偏转强度建议 DIRCM 单独一套更强参数。
8. **制导源接入「被干扰 → 去制导」**：`RVP_GuidanceRuntimeController` / 相关 runtime source
   的 `evaluate` 在弹体处于被干扰状态时返回 `NONE` 意图（脱锁/直飞）——先做 NONE 意图，
   不触碰各制导源内部锁定状态（开放问题 #2）。

### 阶段 D：人在回路（HITL）临时干扰

9. **`RVP_MissileEntity`** 增 `dircmHitlJamTick`（默认 60 = 3 秒，可配置）：
   - 被 DIRCM 干扰瞬间：与普通弹一样走「丢制导 + 强制偏转」；
   - 每 tick 递减，归零后**恢复制导能力**（重新锁定/允许驾控）；
   - 与现有 `hitlLinkBlocked`（物理链路阻断）互斥独立。
10. **HITL 白闪滤镜**：新建 `RVP_DircmHitlFilter`（仿本体 `OverloadHandler`）：
    - PostChain + 新 fsh（`overload.fsh` 的 `distFromCenter` 反向：中心→四周变白）；
    - 10~15 tick 满屏扩散 → 保持（随干扰时长）→ 20~40 tick 消退；
    - 与雪花滤镜互斥（HITL 被 DIRCM 干扰时走白闪，不走 `drawSnow`）。

### 阶段 E：客户端渲染 + 网络

11. **网络包**：
    - `S2CDircmHudSync`（各通道照射/充能状态）；
    - 光束同步包（照射中骨骼 + 目标弹体 id）；
    - `S2CDircmHitlJamSync`（HITL 弹被干扰状态 → 驱动白闪滤镜）。
12. **客户端状态/HUD**：`RVP_DircmHudState` + `RVP_DircmHudOverlay`
    （显示左右通道照射/充能）。
13. **激光光束渲染**：接入现有 `RVP_ClientLaserState` / `RVP_LaserBeamRenderer` /
    `RVP_LaserVisualData`，DIRCM 专用 visual（红/橙、pulsate），起点=laserPart 世界位置、
    终点=弹体位置、逐 tick 跟踪。

### 阶段 F：载具包（AH64）接入

14. **载具 JSON** `vehicles/ah64.json`：
    - 新增两个 `ywzj_vehicle:weapon` 型部件：`dircm_l`（structure_bone `dircm_l` +
      bolts 指向 `dircm_l_barrel`）、`dircm_r`（对应右）；rot_info 可转向；
    - `bone_modules` 增加 `dircm_l` / `dircm_r` 两条目（各自 `dircm` 子对象，左右扇区
      `facing_yaw ±90` 或按需）；左右 = 2 通道。
15. **实体渲染模型**：`entity/ah64.json` 增加 `dircm_l`/`dircm_l_barrel`/
    `dircm_r`/`dircm_r_barrel` 骨骼（带朝向几何，供随动/出光动画锚点）。
16. **动画脚本** `ah64.js`：`getPartXRot/getPartYRot("dircm_l"/"dircm_r")` 让发射器骨骼
    随动指向来袭目标（左右各一个）。

## 3. 验证要点

1. 普通火箭进入扇区 → 光束建立、占通道、不干扰 → 命中，通道进充能；
2. IR/AIR/ARH/HITL 弹 → 光束建立瞬间丢制导 + 偏转；
3. HITL 弹 → 白闪滤镜（中心→四周）随干扰出现，3 秒后恢复制导（区别于永久干扰）；
4. 单骨骼单通道：同时只照射 1 发；多发 → 其余突防；
5. 饱和玩法：普通弹占满通道 → IR 弹突防；多发 IR 齐射突破单通道；
6. 充能 15 秒、光束 1 秒跟踪、脱出范围提前断开；
7. 骨骼被击毁 → 该通道失效（`RVP_BoneModuleStateTable`）；
8. `dircm_l/dircm_r` 随动指向来袭（ah64.js），光束从对应 barrel 出射。

## 4. 风险与依赖

- **偏转通用化**触碰各制导源 `evaluate`：先以「NONE 意图 + 公共偏转」最小侵入，避免大改锁定链路；
- **HITL 恢复制导**：需与现有 HITL 锁定/驾控状态机配合，确认「恢复」= 重新锁定原目标 or 允许
  重新驾控（开放问题 #8）；
- **白闪滤镜**：PostChain 需随 HITL 视角启停，且不能与本体过载滤镜冲突；
- **实体渲染骨骼**：AH64 结构模型已备好，实体模型加骨骼属模型资产改动，按铁律先请示再动。

## 5. 实施修正记录（2026-08-23 实测后）

| # | 问题 | 根因 | 修正 |
|---|---|---|---|
| 1 | 干扰方向错误（左通道显示正前方、右通道正常） | `BoneDircmConfig.parse` 对 `facingYawDeg` 误加 `Math.max(0.0, …)`，负值被钳成 0（dircm_l=-90 → 0 朝正前）；APS 未钳制故正常 | 去掉钳制，保留原值（负值=左，正值=右） |
| 2 | 干扰方向左右反了 | 首次配置 dircm_l=+90/r=-90 与坐标系符号约定相反 | 互换为 l=-90 / r=+90（+90 朝右、-90 朝左） |
| 3 | 激光束不可见（旁观视角） | `RVP_DircmBeamRenderer` 只渲染玩家自己驾驶的车；而 DIRCM 常由敌方载具照射玩家导弹 | 改为遍历 `RVP_DircmHudState.vehicleIds()` 所有车 + 世界实体查找 |
| 4 | 激光发射点不随载具移动 | `resolveLaserPartPos` 误用 `weaponUnit.worldVec()`（返回瞄准方向向量，非位置） | 改用 `part.worldPivotPosition()`（结构骨枢轴世界坐标，随载具移动） |
| 5 | DIRCM HUD 不常态化显示 | HUD 同步只在通道状态变化时发送，空闲（就绪）态永远不发首包 | `tick()` 增加低频兜底同步（每 40 tick），空闲也推状态 |
| 6 | DIRCM 干扰同阵营/己方弹药 | 仅按 `bullet.getOwner()==vehicle` 排除本车 | 新增 `isFriendlyProjectile`：排除本车/乘客发射/同队伍联盟/友方 gunner（参照 GunnerBrain 语义） |
| 7 | 方向排查 | 数学符号易错 | 保留 `[DIRCM DEBUG]` 日志（每 64 tick 打印载具 yaw、facingYaw、解析后的 front 向量），后续可删 |

### 5.1 方向符号结论（供复用）

`RVP_JammingRuntime.resolveFacing(vehicle, null, facingYawDeg)`：
- base = `rotToVec(xRot, yRot)`（载具前向）；
- `facingYawDeg=+90` → 旋转到 **-X（朝车头右侧）**；`-90` → **+X（朝车头左侧）**（载具朝 +Z 时验证）。
- AH64 当前：`dircm_l: facing_yaw=-90`（左）、`dircm_r: facing_yaw=+90`（右），扇区跟随车体（不随观瞄站）。
