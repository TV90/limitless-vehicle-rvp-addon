# RVP DIRCM（定向红外对抗）骨骼状态级设备方案

> 状态：**调研完成，待评审**（本文件仅调研+设计，未实现）
> 日期：2026-08-23
> 关联实现模板：[RVP_APS骨骼属性改造方案_20260810.md](./RVP_APS骨骼属性改造方案_20260810.md)、
> 光电干扰机（`RVP_JammingRuntime`）、激光武器（`RVP_LaserBeamRenderer`/`RVP_LaserVisualData`）

---

## 1. 背景与需求

为直升机（后续可扩展至其它载具）提供 **DIRCM（定向红外对抗，Directed Infrared Countermeasure）** 状态级设备：
- 检测范围内**所有 RVP 导弹/火箭弹/炸弹**（含无制导火箭等，均可触发）；
- 对目标发射**激光照射**，照射期间可干扰 **IR / AIR / ARH / HITL_TV / HITL_CLOS_TV** 制导的弹体；
- 被干扰弹体**失去制导 + 被扭转弹道远离载具**；
- 受**火力通道限制**：1 个激光照射骨骼同时只能照射 1 个目标；可配置多个骨骼获得多通道；
- 照射时长、充能时长均可配置（默认照射 1 秒、充能 15 秒）；
- 允许**饱和突防**玩法：普通导弹消耗干扰通道 → 红外/光电导弹突防；或多发红外弹同时攻击突破通道限制。

与 APS/干扰机一致：**骨骼级模块**（挂载在 `bone_modules`），被击毁后失效。

## 2. 现状调研摘要

### 2.1 状态级设备公共框架：骨骼模块系统（`BoneModuleType`）

文件：`src/main/java/org/ywzj/rvp/vehicle/BoneModuleType.java`

```java
public enum BoneModuleType { ERA, TRACK, JAMMER, APS, COUNTERMEASURE; }
```

- 一个骨骼可挂多个模块（`bone_modules.<bone>.modules` 数组），各模块独立判定失效；
- 挂载点：载具 JSON 顶层 `bone_modules.<骨骼名>`，子对象按模块类型命名
  （`aps` / `jammer` / `countermeasure` …）；
- 失效判定：`RVP_BoneModuleStateTable`（骨块被击毁 → 该骨块上的模块失效）；
- 消费点按类型分派：APS→`RVP_ApsRuntimeManager`，JAMMER→`RVP_JammingRuntime`。

**载具 JSON 示例（abramsx）**：
```json
"bone_modules": {
  "aps_sensor_right": {
    "modules": ["aps"],
    "aps": {
      "launcher_part": "aps_right", "facing_part": "turret",
      "facing_yaw": -90.0, "scan_fov": 120, "detect_radius": 32.0,
      "intercept_radius": 8.0, "ammo_max": 4, "reload_one_tick": 600,
      "cooldown_tick": 20, "intercept_delay_tick": 6, "scan_interval_tick": 1,
      "projectile_speed_min": 1.0, "projectile_speed_max": 8.0,
      "exclude_owner_projectile": true
    }
  }
}
```

### 2.2 APS 状态级设备运行时（DIRCM 的直接模板）

文件：`RVP_ApsRuntimeManager.java` / `BoneApsConfig.java` / `RVP_ApsStateSavedData.java`

- **探测扇区**：`facing_part`（随部件旋转，null 随车体）+ `facing_yaw`（水平偏置）+ `scan_fov`（全角），
  用 `RVP_GuidanceRuntimeGeometry.withinAngle(front, toTarget, halfAngle)` 判定；
- **探测距离**：`detect_radius`，用 `vehicle.getBoundingBox().inflate(detectRadius)` 收集候选实体；
- **目标过滤**：`instanceof Projectile` + 速度区间 `projectile_speed_min/max` + 排除本车弹；
- **节流**：`scan_interval_tick`；
- **每 tick 驱动**：`RVP_ApsEventHandler`（公共 tick 处理器）→ `tick(AbstractVehicle)`；
- **状态持久化**：`RVP_ApsStateSavedData`（载具加入世界恢复/离开写回）；
- **客户端 HUD**：`S2CApsHudSync`（服务端→客户端状态）+ `RVP_ApsHudState` + `RVP_ApsHudOverlay`。

### 2.3 光电干扰机（强制偏转效果参照）

文件：`BoneJammerConfig.java` / `RVP_JammingDeviceType.java` / `RVP_JammingRuntime.java`

- 检测：`fov`（前方锥）+ `range` + `approach_angle`（来袭角，只干扰朝本车飞来的弹）+ `facing_part/facing_yaw`；
- 干扰能力由 `RVP_JammingDeviceType.interferesWith(guidanceType)` 决定：
  `OPTICAL → SACLOS`；`ELECTRONIC → ARH/SARH`（预留）；
- **干扰效果写入弹体字段**（`RVP_BaseBullet`）：
  `jammingHeadingRate`、`jammingOffsetDownBlocks`、`jammingOffsetDir`、`jammingSideSign`、
  `jammingExpireTick`、`jammingNextScanTick`、`jammingSourceVehicleId`、`jammingStrength`；
- **效果消费点**：目前**仅** `RVP_RuntimeSaclosGuidanceSource` 消费
  （`applyVelocityRotation` 每 tick 把弹体水平速度方向旋转 `heading_rate×强度` 度，
  `offsetDir = 水平横向 + 向下分量`，合成「左下/右下」斜向拉偏远离干扰机）。

> 关键缺口：干扰偏转效果目前只在 SACLOS 制导源里生效。DIRCM 要干扰 IR/ARH/HITL，
> 需把「被干扰 → 丢制导 + 强制偏转」做成**独立于制导源**的通用机制（见 §3.5）。

### 2.4 激光美术样式（DIRCM 激光照射参照）

文件：`RVP_LaserVisualData.java` / `RVP_LaserBeamRenderer.java` / `RVP_LaserBeamPose.java`

- `RVP_LaserVisualData` 配置字段：
  `color`（RGBA 列表）、`width`、`duration_tick`、`pulsate`、`render_start_distance`、`segment_length`；
- 渲染：`RVP_LaserBeamRenderer.renderBeamModel` — 用 **Bedrock 模型 + `RenderType.energySwirl(texture,15,15)`**
  纹理，顶点色 `r/g/b/a` 取自 `visual.toArgb(chargeRatio)`（充电比缩放透明度），宽度可脉动；
- 光束由武器/设备的激光数据驱动（`RVP_ClientLaserState` 按 tick 记录起终点 + 平滑插值）。

> DIRCM 照射可直接复用这套「光束模型 + energySwirl + visual」渲染管线，只需构造一条
> 起点=照射骨骼位置、终点=目标弹体的临时光束，并配 DIRCM 专用 `laser_visual` 参数。

### 2.5 弹体与制导体系

- **弹体类**：`RVP_MissileEntity` / `RVP_BombEntity` / `RVP_RocketEntity` 均继承 `RVP_BaseBullet`
  （导弹/炸弹/火箭都在其体系内）；
- **武器种类**：`RVP_EnumWeaponKind` → `MISSILE / ROCKET / BOMB / MACHINEGUN / LASER / DISPENSER`；
- **制导类型**：`RVP_EnumGuidanceType`：
  `NONE IOG MCLOS SALH SACLOS LBR LH TV HITL_TV HITL_CLOS_TV ATV GPS IR AIR ARH SARH ARM`；
- **制导源注册表**：`RVP_RuntimeGuidanceSourceRegistry`（guidance_type → runtime source），
  每个 source 实现 `evaluate(context) → RVP_GuidanceIntent`，由
  `RVP_GuidanceRuntimeController` 调度 → `RVP_GuidanceRuntimeMath.applyIntent`；
- **制导阶段**：`RVP_GuidancePhase` `MAIN → TERMINAL`（单向），
  `RVP_GuidanceModelResolver.resolveActive` 按当前阶段解析当前有效制导类型。

## 3. DIRCM 设计

### 3.1 模块类型

在 `BoneModuleType` 增加枚举项 `DIRCM`（消费点：新建 `RVP_DircmRuntimeManager`）。

### 3.2 新建 `BoneDircmConfig`（仿 `BoneApsConfig` / `BoneJammerConfig`）

```java
public record BoneDircmConfig(
    @Nullable String laserPart,      // 激光照射骨骼（ywzj_vehicle:weapon 型部件 id，兼作照射起点、失效锚点与动画联动锚点）
    @Nullable String facingPart,     // 探测扇区朝向跟随的部件 id；null/空=随车体
    double facingYawDeg,             // 扇区水平偏置角（度，正值向左）
    double scanFovDeg,               // 探测扇区全角（度），半角= fov/2（默认 120）
    double detectRadius,             // 探测距离（格）（默认 2000）
    double approachAngleDeg,         // 来袭角判定（度，半角）：只干扰朝本车飞来的弹（默认 60）
    int beamTick,                    // 激光光束美术特效持续时长（tick）（默认 20 = 1 秒）；
                                     // 干扰在光束建立瞬间即生效，本字段只控制特效跟踪时长
    int chargeTick,                  // 一次照射后充能时长（tick）（默认 300 = 15 秒）
    int scanIntervalTick,            // 扫描节流间隔（默认 5）
    boolean excludeOwnerProjectile   // 排除本车发射弹体（默认 true）
) {}
```

- **通道数**：1 个 `BoneDircmConfig`（1 个照射骨骼）= **1 个火力通道**；
  载具可配多个骨骼（如 `dircm_turret` + `dircm_tail`）获得多通道，各通道独立照射/充能；
- 解析沿用 `GsonHelper` 风格（参照 `BoneApsConfig.parse`）；
- 必填 `laserPart`（缺失视为未启用，类似 `BoneApsConfig.launcherPart`）；
- **`laserPart` 必须是 `ywzj_vehicle:weapon` 型部件**（带 `structure_bone`、`rot_info`、`bolts`），
  与 APS 的 `launcher_part` 同型：既作为光束起点，也可被动画脚本（如 `ah64.js`）经
  `getPartXRot/getPartYRot` 联动旋转（激光发射器随动指向来袭方向）。

### 3.3 探测扇区与目标收集（参照 APS）

- 扇区：`resolveFacing`（复用 `RVP_JammingRuntime.resolveFacing` 语义）+ `withinAngle`；
- 候选：`vehicle.getBoundingBox().inflate(detectRadius)` 内 `instanceof RVP_BaseBullet`
  （或 `Projectile`）+ 速度过滤 + 排除本车弹；
- 可触发 DIRCM 的目标：**所有 RVP 导弹/火箭/炸弹**（`RVP_BaseBullet`，含 `RVP_MissileEntity`/
  `RVP_BombEntity`/`RVP_RocketEntity`，无制导火箭亦可）；
- 节流：`scanIntervalTick`。

### 3.4 运行期 `RVP_DircmRuntimeManager`

参照 `RVP_ApsRuntimeManager` 结构：

- 每载具运行时状态（`DircmState`，按载具 UUID 存侧表）：
  - 每通道（每骨骼）一个槽位：`busyTargetId` / `irradiateRemainTick` / `chargeRemainTick`；
- 每 tick（`RVP_ApsEventHandler` 同款公共 tick 处理器或新建 handler）：
  1. 对每个存活 DIRCM 模块：若通道空闲（无照射、充能中则跳过）→ 扫描扇区内最近的可干扰目标；
  2. 分配目标后**立即执行干扰判定**（见 §3.5）——干扰**瞬间完成**，不等待光束结束；
  3. 同时建立激光光束并进入 `beamRemainTick = beamTick` 的美术特效跟踪期：
     每 tick 把光束终点更新到目标当前位置，**持续跟踪直至 tick 归零**；
     跟踪期内若目标脱出照射范围/扇区/死亡 → 提前断开光束，释放通道进入充能；
  4. 光束特效结束（或提前断开）→ 进入 `chargeRemainTick = chargeTick` 充能；
  5. 目标被干扰成功/脱出扇区/命中 → 释放通道；
- 模块失效：骨骼被击毁（`RVP_BoneModuleStateTable` 判定该骨块 DIRCM 模块失效）→ 该通道禁用；
- 持久化：`RVP_DircmStateSavedData`（仿 `RVP_ApsStateSavedData`）；
- 客户端 HUD：`S2CDircmHudSync` + `RVP_DircmHudState` + `RVP_DircmHudOverlay`
  （显示各通道照射/充能状态、当前照射目标）。

### 3.5 干扰判定与「丢制导 + 强制偏转」（核心扩展）

**干扰时机**：**光束建立瞬间即完成干扰判定**——通道锁定目标并建立激光连线的那一刻，
若目标当前有效制导类型（`RVP_GuidanceModelResolver.resolveActive`，含 MAIN/TERMINAL 阶段解析）
属于 `IR / AIR / ARH / HITL_TV / HITL_CLOS_TV` 之一 → 立即「丢制导 + 强制偏转」；
否则（SALH/SACLOS/IOG/GPS/无制导…）不干扰——但同样占用照射通道、消耗一次充能，
实现「普通导弹消耗通道」的饱和玩法。

> 说明：`RVP_JammingDeviceType` 现仅 `OPTICAL→SACLOS`、`ELECTRONIC→ARH/SARH`。
> DIRCM 的干扰集合是「红外系 + 主动雷达系 + 人在回路系」五个类型，建议新增独立的判定方法
> （如 `RVP_DircmGuidanceSupport.canJam(type)`），不动现有 `RVP_JammingDeviceType`。

**丢制导 + 强制偏转机制**：现有偏转效果只挂在 SACLOS 制导源内。为让 IR/ARH/HITL 也能被偏转，
需要把「被干扰」做成**弹体级通用状态**：

- 在 `RVP_BaseBullet` 增加标志（如 `dircmJammedTick` / `dircmSourceVehicleId` / 复用现有
  `jamming*` 字段亦可）；
- 弹体处于被干扰状态时：
  - 制导评估（`RVP_GuidanceRuntimeController` / 各 runtime source 的 `evaluate`）**返回去制导意图**
    （如 `RVP_GuidanceIntent.NONE` 或脱锁意图），使弹体失去追踪能力；
  - 速度方向按「远离 DIRCM 载具」持续偏转（复用 `RVP_RuntimeSaclosGuidanceSource` 里
    `applyVelocityRotation` + `offsetDir` 的数学，抽成公共工具 `RVP_JamDeflectionHelper`）；
- 偏转方向语义：远离本载具 + 向下分量（参照光电干扰机「左下/右下」拉偏）。
- **光束特效与干扰解耦**：光束只负责美术表现与目标跟踪（§3.6），干扰效果一旦生效即为
  弹体级持久状态（直到命中/脱锁）；光束提前断开不影响已生效的干扰。

#### 3.5.1 人在回路（HITL）导弹的 DIRCM 干扰语义（临时性，效果与普通弹一致）

调研结论（`RVP_MissileEntity` / `RVP_ClientHitlState` / `RVP_TVMissileOverlay`）：

- **现有无线电链路阻断**：`hitlLinkBlocked`（地形/视距阻断）→ 客户端 `RVP_TVMissileOverlay`
  显示「黑底 + 雪花噪点纹理」（`drawSnow`，每 4 tick 重绘噪点），持续 40 tick 未恢复则
  `hitlLinkSevered` 彻底断链。这是用户所指的「无线电制导模式被干扰时的雪花纹理和 UI」。
- **HITL 控制模式**：`VIEW / MOUSE（指令线无线驾控）/ DESIGNATE（目标指定）`；
  相机 `RVP_ClientHitlCamera` 焊接在弹体轴线上（弹头视角）。

**DIRCM 对 HITL 的设计**：
1. **效果与普通弹一致**：被 DIRCM 干扰的 HITL 弹**同样丢制导 + 强制偏转**（退出导引头、
   清目标、弹道被扭离载具），不是「只失控制权」——与 IR/ARH 弹走同一套「丢制导 + 偏转」
   机制（§3.5）；
2. **不同之处是临时性**：干扰是**临时**的——干扰生效后 **3 秒（60 tick）恢复控制权**
   （可配置），恢复后弹体**重新获得制导能力**（重新锁定原目标或允许操作员重新驾控）；
   而普通 IR/ARH 弹被干扰是永久性（直到命中/脱锁不再恢复）；
3. **不用雪花滤镜**：不触发现有 `hitlLinkBlocked` 雪花效果（那属于物理链路阻断）；
4. **新滤镜（中心向外白闪）**：在被干扰期间，HITL 操作员视角叠加一个「从屏幕**中心**向
   **四周**迅速扩散的白色滤镜」——直接参考本体过载滤镜 `OverloadHandler` + `overload.fsh`
   （PostChain + `distFromCenter` 边缘暗角），但把方向反过来：
   - 本体过载：四周 → 中心变暗（`darkness = 1 - k*progress - distFromCenter*1.5*progress`）；
   - DIRCM：中心 → 四周变白（`whiteness = 1 - progress*… + distFromCenter*progress`，或
     `smoothstep(0.5 - progress/2, 0.5 + progress/2, distFromCenter)` 反向，中心优先白）；
   - 扩散速度「迅速」：建议 progress 在 10~15 tick 内从 0 → 1 满屏；
   - 2 秒（40 tick）后**逐渐消退**（progress 反向淡出，建议再 20~40 tick 回到 0）；
   - 白闪期间覆盖在 HITL 相机画面之上（与现有雪花一样走 `RenderGuiOverlayEvent` / PostChain）；
   - 白闪滤镜持续时长 = 干扰持续时长（3 秒恢复控制，滤镜同时消退）。
5. **服务端状态机**：`RVP_MissileEntity` 增 `dircmHitlJamTick`（剩余干扰 tick，默认 60）：
   - 被 DIRCM 干扰瞬间 → 置位并触发「丢制导 + 强制偏转」；
   - 每 tick 递减，归零后**恢复制导**（重新锁定/允许驾控）；
   - 客户端：`hitlLinkBlocked` 不置位，新增 `dircmJam` 状态驱动白闪滤镜（与雪花互斥）。

### 3.6 激光美术（复用现有激光管线 + 动画联动骨骼）

- **光束特效**：照射（美术）期间客户端构造一条**临时激光光束**：
  起点 = `laserPart` 对应武器部件世界位置，终点 = 目标弹体当前位置，**每 tick 更新终点实现
  持续跟踪**，直至 `beamTick` 归零或目标脱出范围/死亡（提前断开）；
- 复用 `RVP_LaserBeamRenderer` + `RVP_LaserVisualData`（DIRCM 专用 visual：
  建议红/橙高亮 `color`、`pulsate: true`、`width` 适中，表示照射中）；
- 数据流：服务端经网络包把「照射中骨骼 + 目标」推给客户端 → `RVP_ClientLaserState` 记录 →
  渲染器按现有管线绘制；或仿现有激光武器直接走 beam 数据；
- **渲染模型骨骼联动（仿 APS `launcher_part`）**：`laserPart` 是 `ywzj_vehicle:weapon` 型部件
  （有 `structure_bone` / `rot_info` / `bolts`），因此：
  - 光束起点直接取该部件 `bolts`/骨骼世界位置（`weaponUnit.worldVec()` 等）；
  - 动画脚本（如 `ah64.js`）可像 APS 发射器一样用 `getPartXRot/getPartYRot("dircm_turret")`
    让激光发射器骨骼随动指向来袭目标，实现「发射器转向 + 出光」的联动表现；
  - 部件被打掉（模块失效）→ 骨骼不可用，通道停用，光束消失。

## 4. 行为验证要点

1. **触发**：普通火箭弹/无制导火箭进入探测扇区 → 建立光束（占通道）但**不干扰**（瞬间判定
   不可干扰）→ 仍命中，且该通道进入充能；
2. **干扰瞬间生效**：IR/AIR/ARH/HITL 弹进入扇区 → **光束建立瞬间即丢制导 + 弹道扭离载具**，
   不需等 1 秒照射结束；
3. **光束跟踪**：照射 1 秒内光束终点持续跟随导弹；导弹飞出照射范围 → 光束提前断开进入充能；
4. **通道限制**：单骨骼（1 通道）→ 同时只照射 1 发；多枚同进 → 其余不受干扰直接命中；
5. **饱和玩法**：先发普通导弹占满通道 → 跟进 IR 弹突防命中；或多发 IR 弹齐射突破单通道；
6. **充能**：一次照射后进入 15 秒充能，期间不响应新目标；
7. **失效**：照射骨骼被击毁 → 该通道立即停止工作（另一侧独立）；
8. **骨骼联动**：`dircm_turret` 部件随动指向来袭方向（动画脚本联动），光束从该骨骼发出；
9. **激光表现**：照射期间可见 DIRCM 光束（起点=骨骼、终点=弹体，红/橙脉动，持续跟踪）。
10. **HITL 干扰**：HITL 弹（TV/指令线）被 DIRCM 干扰 → **同样丢制导 + 强制偏转**（弹道被扭离），
    不用雪花滤镜，HITL 视角出现中心→四周白闪滤镜，白闪随干扰时长（3 秒）消退；
11. **HITL 恢复**：干扰结束后（3 秒）弹体**恢复制导能力**（重新锁定/继续驾控）——
    区别于普通弹的永久丢制导。

## 6. 开放问题

1. **干扰对炸弹的适用**：炸弹（`RVP_BombEntity`）制导多为 GPS/滑翔，IR/AIR/ARH 弹头的炸弹是否
   只干扰其末端？需要按当前有效制导阶段（MAIN/TERMINAL）判定，建议确认哪些炸弹会用到
   IR/AIR/ARH/HITL 制导。
   
   末端制导启用时被干扰
   
   
2. **「去制导」的具体实现**：是让 `evaluate` 返回 `NONE` 意图（弹体直飞）+ 独立偏转，还是需要
   让弹体显式脱锁（清 `lockedEntity`）？建议先做成「返回 NONE 意图 + 强制偏转」，避免触碰各
   制导源内部锁定状态。
   
    返回 `NONE` 意图（弹体直飞）+ 独立偏转
   
   
3. **偏转强度**：复用光电干扰机的 `heading_rate`/`offset_*` 参数体系，还是 DIRCM 单独一套更强
   的偏转（激光烧蚀效果更强）？默认建议单独一套（更硬偏转），但可复用数学工具。
   
   复用光电干扰机
   
4. **多骨骼同源载具**：直升机若配 2 骨骼，HUD 是否要区分左右通道？参照 APS HUD 多模块显示。

   是的，需要区分左右通道

   
5. **是否需要对 MACHINEGUN 类弹药触发**：用户需求只覆盖导弹/火箭/炸弹；机炮弹不触发。

   不对机炮弹触发
   
6. **光束断开的判定**：跟踪期导弹「脱出照射范围」的阈值如何定（复用 `detect_radius` 还是
   单独更小的锁定半径）？建议复用探测距离，避免光束频繁闪烁。
   
   复用探测范围
   
7. **干扰生效后再来的导弹**：同一目标被干扰后，是否允许其它通道/后续照射重新干扰？
   建议已干扰弹体不再重复触发（已有弹体级状态），通道转向新目标。
   
   不允许多通道重复照射，避免挤占不必要的火力通道
   
8. **HITL 干扰时长与恢复**：3 秒恢复是否可配（建议 `dircm_hitl_jam_tick`）；恢复「制导能力」
   的具体实现（重新锁定原目标 or 允许操作员重新驾控，需与现有 HITL 锁定/驾控链路配合）。
   
   暂时硬编码吧
   
9. **白闪滤镜实现路线**：PostChain 全屏后处理（仿 `OverloadHandler`）还是 Gui 层叠色
   （仿雪花）？PostChain 能盖住 HITL 相机画面且性能好，但需随 HITL 视角启停；建议 PostChain。
   
   gui叠层吧，最好不要盖掉scope的滤镜
   
10. **白闪消退曲线**：2 秒保持 + 消退时长与扩散速度（10~15 tick 扩散、20~40 tick 消退）是否
      需要参数化，还是先按固定曲线实现。
   
   先固定吧
