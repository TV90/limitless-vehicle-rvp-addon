# RVP 载具「二号位无座舱视角」（数据驱动）方案与实施记录

> 状态：已实施（2026-09-10），编译 + 服务端冒烟通过，待实机验证
> 权威字段说明：[RVP包新增参数字段说明.md](./RVP武器数据模型/RVP包新增参数字段说明.md) §3.4「通用部件扩展」

## 1. 需求

通用机制：任何载具的某个座位（典型为双座战机后座/武器官二号位）可经数据字段标记为「无座舱视角」——该座位玩家视角只能 THIRD_PERSON / SCOPE(观瞄 CRT)，VIEW 键循环与自动降级均**不可进入 OPERATOR（座舱第一人称）**。零硬编码载具/座位名，配置作者按需逐座位启用。

## 2. 审计结论（对原始任务书的修正）

1. **注入点成立但必须 `opcode = Opcodes.PUTFIELD`**：`LocalVehiclePlayer.switchViewType` 体内 `viewType` 有 5 处读引用（302/308/310/330/332 行），不加 opcode 会在读点提前 cancel、跳过本体 `thirdPersonCameraAimAt` 与旋转保存副作用。加 PUTFIELD 后精确命中 337 行唯一 OPERATOR 写入路径。
2. **"337 唯一写入点"不实但无碍**：类内另有 66 行（字段初始化）与 583 行（`checkState()` 下车重置 THIRD_PERSON）——均只写 THIRD_PERSON（安全方向），OPERATOR 写入全部经过 337，拦截设计成立。
3. **`tickAim():288` 自动降级**（SCOPE 状态下无光学瞄具时显式传 OPERATOR）流经注入点 → 被拦，符合"标记座位不自动进座舱"。
4. **`operator_view_offset` 省略时默认 `Vec3.ZERO` 而非 null**（`WeaponUnitPojo.java:34`）——"留空退化视角但不能禁用"结论不变，佐证必须做本功能。
5. **数据通道定案**：座位无独立 Pojo，`is_seat` 在基类 `PartUnitPojo:38`（默认 true）→ 采用基类 mixin 路线（common 数组；目标类双端安全，WeaponUnit/RadarUnit 有同类先例），比"载具级座位 id 列表"少一层易错 id 匹配。
6. **j16 为单座机**：唯一座位 `sighting_system`，无后座（任务书要求落地 j16 二号位不成立）。按用户决定：先交付通用机制，j16 双座改装由用户自行完成后再打标。

## 4. 行为边界

- 标记座位：VIEW 键循环**顺延为 THIRD↔SCOPE 连续可达**——OPERATOR 落点被改写为 THIRD_PERSON（2026-09-10 修复：最初实现为简单取消，导致本体循环 SCOPE→OPERATOR→THIRD 断裂、卡死在 SCOPE）；无光学瞄具时 THIRD 的下一站原地为 THIRD（无可用替代视角）；SCOPE 下 `tickAim` 自动降级被改写落 THIRD（瞄具丢失回第三人称）。
- 未标记座位：完全不受影响（viewType 为全局字段，切到无标记座位即可正常进座舱）；SWITCH_SCOPE 键、下车重置 THIRD、非 WeaponUnit 座位两态循环均与本体一致。
- 回退方式：从 mixins.json 移除 `LocalVehiclePlayerViewTypeRestrictMixin` 即恢复本体原始视角循环；数据字段无侵入。
