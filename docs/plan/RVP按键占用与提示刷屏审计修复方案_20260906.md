## 1. 背景（用户实际报告）

1. 单兵状态按 **N**（放飞无人机），RVP 弹"未在载具中"并**覆盖 SBW 火箭筒切弹头的 actionbar 反馈**（表现为抢键/阻断）；
2. 无无人机的载具里按 **N/M**，弹"当前载具没有无人机"类提示（刷屏）；
3. **地面无人机**（Buk-M3 / IRIS-T SLM 的子机 `rvp:96l6`、`rvp:irist_slm_tads`，均为轮式雷达车、无 `rvp_loiter_*` 配置）按 **F**，误报"未配置盘旋参数"；
4. 头瞄键（**5**）单兵状态疑似同类问题 → **审计实锤且未修**。

## 2. 机制澄清（重要结论）

**当前代码不存在真正的按键阻断。** 1.20.1 的 `KeyMapping.click` 对绑定同一物理键的每个 KeyMapping（RVP 与 SBW 各自的映射）独立计数，`consumeClick()` 只消费自己的计数器。历史上真正的阻断源是 `InputHandler.handleVehicleAction` Mixin，已被 **T 键 ClientTick 轮询替代**（见 `RVP_ClientEvents` 火控稳定器注释）；现存 `InputHandlerAirburstMixin`/`InputHandlerMagnificationGuardMixin` 只拦本体自身方法，不拦原版键路由。

用户感知的"阻断 SBW"实为：单兵按 N → RVP 发无效包 → 服务端回 actionbar"未在载具中"→ **actionbar 只有一条，覆盖了 SBW 自己的反馈**。故修复方向 = 消灭无效发包与无效提示，而非键位路由。

## 4. 问题清单与修复方案

### A1【主案】N/M/F 无客户端守卫 + 服务端"不适用必回提示"

**现状**（审计时点）：
- `RVP_ClientEvents#onClientTick` :257-265 三键无条件 `sendToServer`；
- `C2SDeployDeployableUav#handle`：switch 把**所有结果**（含 `NO_PARENT_VEHICLE`"未在载具中"）转 actionbar；
- `C2SSwitchDeployableUav#handle`：不在载具(:34)、切子机失败(:60) 均回提示；
- `C2SToggleUavLoiter#handle`：不在载具(:39)、无配置(:55) 均回提示。

**修复**：
1. 客户端守卫（新增 `ywzj_rvp$uavKeyGuard` 辅助方法，约 15 行）：
   - N：`lvp != null && lvp.onVehicle() && RVP_DeployableUavConfigCache.get(lvp.vehicle.getVehicleId()).enabled()` 才发包。该缓存由 `VehicleDataManagerMixin`（公共 mixin，双端各自解析载具包 JSON）在 `VehicleDataManager.apply` TAIL 填充，客户端可读，无同步成本；
   - M：仅 `onVehicle()`——客户端无法区分"当前载具是无人机实例"（`RVP_LinkedUavStateTable` 为服务端 UUID 表，无 S2C 同步），驾驶 suav 按 M 切回母车必须放行；
   - F：`onVehicle()` + （自身 `RVP_LoiterConfigCache.get(vehicleId).isConfigured()` 或 子机 `RVP_LoiterConfigCache.get(子机id).isConfigured()`；子机 id 取自 `RVP_DeployableUavConfigCache`）。地面子机无 loiter 配置，天然被挡。
2. 服务端兜底（"**不适用静默，结果保留**"，约 10 行）：
   - `C2SDeployDeployableUav`：`NO_PARENT_VEHICLE`、`NO_CONFIG` → 静默 return；SUCCESS / COOLDOWN / ALREADY_DEPLOYED / SPAWN_FAILED / INVALID_TEMPLATE / SEAT_NOT_ALLOWED 保留；
   - `C2SSwitchDeployableUav`：不在载具、`switch_to_child_failed` → 静默；`switch_back_failed` 保留（真失败）；
   - `C2SToggleUavLoiter`：不在载具、`no_config` → 静默；enabled/disabled 保留。

**服务端同步修改**：是（3 个包处理器）。**优先级：最高**。

### A2【误报】地面无人机按 F 报"未配置盘旋参数"

**现状**：`C2SToggleUavLoiter#resolveTargetUav` 把关联子机无条件作为盘旋目标；96l6 / irist_slm_tads 为 `wheeled_vehicle` 且无 loiter 配置 → 落入 `no_config` 提示。空中子机 `rvp:suav`（fixed_wing + `rvp_loiter_enabled:true`）不受影响。

**修复**：`resolveTargetUav` 各分支统一加判型 `instanceof FixedWingVehicle || RotaryWingVehicle`，地面载具静默 return（约 6 行）。本体车型恰好只有这四类 + custom，判型可靠。

**服务端同步修改**：是。**优先级：高**。

### A3【未修实锤】头瞄键单兵误弹 "HMD 关闭"

**现状**：`RVP_ClientEvents#onClientTick` HMD 循环守卫仅 `LocalVehiclePlayer.instance == null`——`instance` 为恒非空单例（本体 `LocalVehiclePlayer` :40/:73），守卫形同虚设。单兵走 else 分支：`RVP_ClientHmdState#toggle` 因无武器站返回 false，但外层 :202-204 **无条件显示** `on ? "hmd.on" : "hmd.off"` → 单兵每次按 5（原版快捷栏键）都刷一条。状态无泄漏（`checkIrHmd`/`tick` 均自动 disable），纯刷屏。

**修复**（约 5 行）：
```java
LocalVehiclePlayer lvp = LocalVehiclePlayer.instance;
if (lvp == null || !lvp.onVehicle() || lvp.getWeaponUnit() == null) continue;
```
且 else 分支仅在 `toggle()` 返回 true（雷达 HMD 真开启）时提示。

**服务端同步修改**：否。**优先级：高**（5 键使用频率高，体感最强）。

### B【已修✅】RenderGuiOverlayEvent.Post 未锚定 overlay id（每帧 40+ 次）

**用户已自行修复并提交**（提交 "SARH 制导修复 + GUI overlay 锚定 + TV 弹转向率 UI…"）。机制备忘：Forge 对每个 overlay 渲染完各广播一次 Post（每帧 40+ 次），处理器须锚定每帧必渲染的 `VanillaGuiOverlay.CHAT_PANEL.id()`。审计发现的 8 处遗漏（均已修）：`RVP_GPSOverlay`（射线检测，最重）、`RVP_ClientEvents#onRenderGuiOverlayPost`（HMD HUD）、`RVP_GunnerOverlay`、`RVP_TVMissileOverlay`、`RVP_DircmHitlFilter`（半透明叠 40 层致视觉错误）、`RVP_TargetingPodMarkerRenderer`、`RVP_RocketCcipOverlay`、`RVP_ClientArmTickHandler#onRenderGuiOverlay`。

### C【记录不修】无效包残余

载具内未配对应弹种时 `C2SFireCountermeasure` 仍会发出，服务端静默过滤（无提示无副作用）。客户端判"配了哪种干扰物"需读 countermeasure 配置缓存，收益低 → **保留现状**。

## 5. 验收标准（对应 §1 四条抱怨）

1. 单兵按 N/M/F：**无任何 actionbar 提示、无网络包发出**；SBW 同键反馈不再被覆盖；
2. 无无人机配置的载具内按 N/M：无提示；有配置的载具内正常放飞/切换/回切，提示照旧；
3. 地面无人机（96l6 / irist_slm_tads）按 F：无提示；suav 及 AC130 类固定翼盘旋功能不受影响；
4. 单兵按 5：无提示；载具内无 HMS 雷达按 5：无提示；正常开启/关闭提示照旧；
5. `./gradlew build` 通过；服务端冒烟 `Done (Xs)!`（agents.md §服务端冒烟）。
