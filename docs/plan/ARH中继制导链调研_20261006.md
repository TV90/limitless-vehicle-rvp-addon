# ARH/AIR 导弹中继制导链调研（2026-10-06）

> 实测现象（用户）：ddg51 4km 外发射 RGM-84 弹群，052d 逐一锁定来袭弹并发射 HQ-9B（ARH）拦截
> 全部脱靶；只有"持续锁定到 HQ-9B 主动导引头开机再脱锁"才能命中；脱锁后**重锁同一目标也不
> 恢复中继**。期望：雷达照射/TWS 跟踪（无需硬锁）即可中段数据链修正，且重锁可恢复。
> 结论：**单向锁存 + 发射时快照，双结构缺陷叠加**。详见 §三根因。

---

## 一、目标来源链（现状）

- **发射快照**：`RVP_ProjectileWeapon.dispatchShots`（:156-229）仅在发射瞬间读一次锁目标
  （RF 语义走 `getEffectiveRfLockedEntity`，其余 `rootUnit.getLockedEntity()`）；
  `RVP_ProjectileSpawner.applyLockTarget`（:244-270）写入弹体：
  `setTargetEntity(lock)` + ARH/AIR 另存 `rvp$setActiveSeekerDesignatedTarget(lock)`。
- **designated 存储**：`RVP_MissileEntity` :92 `activeSeekerDesignatedTargetId`（int 实体 id）。
  写点全工程仅两处：发射（ProjectileSpawner:261）与 DIRCM 清除（:485-497 置 null）。
  **发射后无任何刷新通道**——换锁/换靶不更新在飞弹。
- **每 tick 重绑**：`tickGuidance` → `tickActiveSeekerTargetManagement`（RVP_MissileEntity:260-335）：
  未截获且 designated 有效且"支持链可用"时每 tick `setTargetEntity(designated)`（:274-281）。
  targetEntity 是重绑的，**但 designated 本身是死快照**。

## 二、脱锁路径与重锁不恢复

1. 脱锁：本体 `WeaponUnit.fireControlLock`（:673-678）→ `ClientRadarAction LOCK -1` →
   `ClientRadarActionMixin:44-48` 清服务端雷达硬锁。
2. **单向锁存**：支持链断**一 tick** → `activeSeekerSupportReleased = true`（RVP_MissileEntity:270-272）。
3. 锁存后果（双重封死中继）：:278-280 每 tick 强制 `setTargetEntity(null)`；
   :524-528 `canActiveSeekerFreeAcquire()` 恒 true → `RVP_RuntimeActiveSeekerGuidance:27`
   中继分支永久短路 → 退化**固定记忆点** point intent（:38-43，targetPos 冻结在脱锁前最后
   修正位置，不随目标运动外推）→ 打死点必脱靶。
4. **锁存唯一复位点** = `rvp$setActiveSeekerDesignatedTarget(非null)` 内 :492，而该方法只在
   发射时调用——**重锁不经过任何能复位锁存的代码**，故重锁无效。
5. "锁到导引头开机再脱锁能命中"：截获标志/目标存弹体自身（`markAutonomousSeekerCatch`，
   RVP_BaseBullet:1601-1609，entityData 双端同步），`RVP_MissileEntity:274 if (!activeRadarCatch)`
   使截获后中继链彻底退出，脱锁无所谓。

## 三、根因清单

| # | 根因 | 位置 |
|---|---|---|
| 1 | **支持链断一 tick 即永久锁存**，无宽限/去抖/复位 | RVP_MissileEntity:270-272 |
| 2 | **重锁无重绑通道**：latch 复位只在发射注入里；重锁只写 RadarUnit/WeaponUnit.lockedEntity | :492 唯一复位点 |
| 3 | **designated 发射定格**：飞行中不随雷达当前锁刷新 | ProjectileSpawner:261 |
| 4 | **支持链覆盖窄**：只查发射武器站的子雷达 + 单个外置中继，不查同车其它武器站雷达 | RVP_MissileEntity:534-578 |
| 5 | **TWS 支持依赖服务端探测表质量**：脱锁后雷达碟回扫掠，`RVP_RadarScanService` 按扇区/超时修剪 → 接触瞬时消失 → 一 tick 判死（无去抖） | RadarScanService:95-137 |
| 6 | 退化制导是冻结记忆点，无目标外推 | RuntimeActiveSeekerGuidance:38-43 |

**关键发现**：`radarCurrentlyDetects`（=探测表 containsKey，**无需硬锁**）本来就在支持链判据里
（RVP_MissileEntity:558/569）——"TWS 跟踪即可维持中继"的通道**已存在**，只是被"瞬时断即永久
锁存 + 探测表修剪"废掉了。SARH 照射源与近炸门 `isRadarIlluminatedTarget` 则是纯硬锁口径
（注释明说排除 TWS），是另一条链（RVP_RuntimeSarhGuidanceSource:42-47、RVP_BaseBullet:3061-3090）。

## 四、修复方向（待用户定版后实施）

- **方向 A（最小改）**：latch 加去抖宽限（如支持链断 20~40 tick 才置锁存）+ 重锁即复位
  （每 tick 若 designated 目标重新被任何支持源覆盖 → 清 latch + 重绑）。
- **方向 B（用户期望的完整语义）**：在 A 之上，把"支持/中继"判据升级为
  `硬锁 ∨ TWS 探测表命中 ∨ 外置雷达（同条件）`，并允许飞行中 designated 跟随发射站的
  当前雷达硬锁刷新（换靶即换中继目标）——需定版"多弹分靶时换锁会不会抢已经在飞的弹"
  （建议：designated 只在弹未截获且站内有唯一锁时跟随，或引入 per-弹 绑定表）。
- **方向 C（SARH 同步放宽，可选）**：SARH 照射源同样接受 TWS 探测表命中（半主动照射门限
  放宽为"被雷达跟踪"），需用户确认是否符合强度预期。
- 附带：退化 point intent 加目标最后速度外推（脱锁窗口内仍趋近预测位置）。

## 六、实施规格（2026-10-06 用户定版，已实施）

- **锁存删除**：中继支持每 tick 实时评估无记忆——支持可用（本车任意武器站雷达/外置中继，
  TWS 探测 ∨ 硬锁）→ 重绑 designated 持续修正；失援 → 清 targetEntity 冻结最后已知点滑行；
  恢复跟踪**立即**恢复中继（瞬时断一拍自愈，无需去抖）。
- **滑行自毁上限**：`guidance_data.relay_lost_self_destruct_ticks`（默认 300=15 秒，≤0 关闭），
  连续失援达上限自爆。
- **DIRCM 保持**：`rvp$setActiveSeekerDesignatedTarget(null)` 补 `clearTarget()`（每 tick 强制
  清空删除后对抗清除需显式）。
- **支持链扩整车**：支持源从发射站子雷达扩为整车全部 PartUnit 雷达（同判据）；ECM 短路、
  截获豁免保留。
- **不做 designated 飞行中跟随**（弹群逐一锁定发射换锁不抢靶）；**不碰 SARH**（管理路径
  ARH/AIR-only 已证隔离，SARH 硬锁照射语义保留）。
- 决策纯函数 `guidance/runtime/RVP_ActiveSeekerRelayPolicy`（截获豁免/重绑/冻结/LOAL 不计/
  滑行自毁阈值）+ 6 用例。
