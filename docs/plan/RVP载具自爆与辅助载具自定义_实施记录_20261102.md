## 用户确认与范围
- 用户要求先规划，后明确授权 Luna 实现、主线程审核，并可多子智能体并行修改。
- 普通有人载具按 MCH 自爆语义处理，不保护乘员。
- 母车部署的辅助载具必须先完成真实玩家回传，再结算自爆；不以 child.uav 布尔值代替部署身份。
- 辅助载具从配置候选中选一种，保持单个部署实例；只在未部署、无返回/终结事务且冷却结束时可应用选择。
- 改装工具本体 AUI 的载具档案区域加入入口；独立选择页右侧预览所选辅助载具。

## 开始时的事实
- HEAD: ff77db119b6961be07908ce866896a9afbb7c8f3，mod_version=0.1.0c_beta_0.6.2。
- 原自然致毁链：AbstractVehicle.hurt -> stopRiding -> setDestroyed -> VehicleExplosion.explode/hurt。
- 原 RVP handleDismount 只 scheduleAutoRide，notBeforeTick=serverTick+1；死亡玩家随后被移出 pending。
- 因而子机击毁爆炸判伤早于回传。上一轮避免下车回调重入时延后回传，遗漏此衔接。
- suav 未配置本体 uav:true，使用隐藏真乘客与持久区块租约；本体原生假玩家返回不能作为保护保证。
- MCH_WeaponBomb.destruct 分支对 UAV 先爆炸再 destruct；其操作者由控制站代理。普通分支的大额伤害目标为飞机，不是玩家。
- 原重部署冷却只存静态 Map，以服务器 tick 计数计算，重启不保留。
- 工作区另有导弹、创造栏、灯光等修改；开始前保存到临时基线 rvp_auxiliary_baseline_20261102，禁止覆盖。

## 设计与验收要求
### 返回及自爆
1. 将“安全返回位置”与“恢复母车座位”分离，母车不可用/座位占用不延迟离开爆心。
2. 返回锚包含维度、位置、母车 UUID 与原座位；跨维 teleport 只能在 stopRiding 返回之后执行。
3. 本体 ExplosionEvent.Start 在致毁 stopRiding 返回后、hurt 前触发，可完成已毁部署子机的待返回事务。
4. 主动自爆：请求锁定 -> 记录爆心/武器/操作者 -> 解除骑乘 -> 确认所有相关玩家回传 -> 单次爆炸 -> 清理/冷却。
5. 返回失败不得引爆；重复请求、中途击毁不能造成重复爆炸、重复扣弹或重复冷却。
6. 普通载具不回传/不获无人机保护；避免本体 protectPassenger 意外免除自爆乘员伤害。
7. 复用现有爆炸配置与效果链，不能将战斗部与普通致毁爆炸叠加两遍。
8. 返回保护仅限对应事务，不能创建广域或永久无敌。

### 配置与状态
- 新候选字段 deployable_uav_options，默认候选 deployable_uav_default_option，使用稳定选项 id。
- 每项保存 vehicle_id、role、spawn_offset、spawn_yaw_mode、initial_speed；公共策略继承与覆盖由类型化解析明确处理。
- 初速单位保持 blocks/tick，1=20 格/秒；偏移与朝向沿用原部署计算，不悄悄改变坐标系。
- 六份待转换母车：zbl08a、lav25、m142、9k720、bukm3、irist_slm_tel；先备份，只变辅助配置结构，保留原参数。
- 当前 schema 唯一；旧配置用脚本一次性转换，Java 不提供旧字段别名或运行时迁移。
- 选择按母车实体 UUID 持久化；部署使用配置快照；时间统一采用 overworld 持久 gameTime。
- 已部署但实体卸载仍然占用；现存 linkedChild 但无新 SavedData 的记录不能开放更换。
- 状态与选择都由服务端校验，含工具、距离、实体 UUID、停车/无人门、合法候选、部署/终结/冷却状态。
- 新网络协议需客户端/服务端同版。

### AUI
- 入口位于原 profile-copy 与 profile-actions 之间，同排靠近改装武器按钮。
- 使用 mode=browser、固定字号与百分比 flex；DOMRect 只乘 renderScale 一次。
- init 建完整 DOM，运行时更新既有节点；不用 Document.refresh 反复重建。
- 预览为独立客户端实例，不加入世界、不修改母车；仅切候选时构建，不每帧初始化。
- 部署/冷却时可浏览、不可应用；等待服务端回包，不乐观显示更换成功。

## 配置示例（通用功能，不代表已经制作 FPV 资产）

母车顶层配置片段如下。`yourpack:your_fpv` 是待用户制作的载具 ID 占位，必须替换成实际存在的载具；本批不向现有包添加该 ID。位置是生成偏移，初速是沿生成朝向的水平速度，示例数值不替换现有六车参数。

```json
{
  "deployable_uav_enabled": true,
  "deployable_uav_default_option": "recon",
  "deployable_uav_redeploy_cooldown_tick": 1200,
  "deployable_uav_options": [
    {
      "id": "recon",
      "name": "侦察无人机",
      "vehicle_id": "rvp:suav",
      "role": "uav",
      "spawn_offset": [0, 100, 0],
      "spawn_yaw_mode": "parent",
      "initial_speed": 1
    },
    {
      "id": "fpv",
      "name": "FPV",
      "vehicle_id": "yourpack:your_fpv",
      "role": "uav",
      "spawn_offset": [0, 3, 0],
      "spawn_yaw_mode": "parent",
      "initial_speed": 0.5
    }
  ]
}
```

自爆炸弹在一份合法的 `rvp:bomb` 武器配置中合并以下片段。爆炸数值只是配置示例，不是新增武器的平衡定案；完整武器仍需正常的弹量、装填、显示配置及载具武器站引用。`self_destruct_vehicle` 缺省为 false，只在炸弹武器生效，与弹体寿程自毁字段不同。

```json
{
  "type": "rvp:bomb",
  "fire_data": {
    "self_destruct_vehicle": true
  },
  "detonate_data": {
    "explosion_data": {
      "explode": true,
      "damage": 100,
      "radius": 4,
      "destroy_block": false
    }
  }
}
```

新网络协议为 35，客户端与服务端需使用同版代码；默认开发 jar 不含载具包，安装时同时更新新 schema 的母车数据。

## 主线程复审结果
- 自爆只进入一次性事务，绕过 BURST 和多出弹点；回传与位置回读通过后扣一枚弹药，失败不推进武器热量/冷却。
- 战斗部复用现有 RVP 炸弹爆炸链；排除载体并直接置毁，避免再走本体 hurt 叠加第二次死亡爆炸。
- 自然致毁在本体 ExplosionEvent.Start 同步回传；临时保护只匹配同一服务器 tick、同一个子机作为 directEntity 的爆炸伤害。此保证针对子机自身致毁爆炸，不是对敌方爆炸或任意外部伤害的全局免疫。
- 回传目的地优先活母车当前侧方，其次持久化放飞锚点；缺少目的地不猜测高空坐标。自爆前和回传后都核验同维返回点是否落在爆炸范围。
- 未确认的回传按玩家 UUID 持久化，离线/重启继续重试；重新入座可超时，物理回传不会用超时代替完成。真正死亡后的重生取消旧回传。
- 终结租约阻挡选择和再次部署直到所有回传完成；子机已经移除时按 UUID 收尾，冷却只在终结起点记一次。
- 选择页已修正当前候选标记、冷却倒计时、服务端拒绝文案和独立预览对象释放；原武器入口接管与烟雾操作保留。
- 六台母车已与任务开始备份逐字段对照，除候选结构外保持不变；源包正向复制到 `limitless_vehicle_authoritative/rvp`，排除 `_bak`/`_backups` 和备份文件，共 1140 文件、568860716 字节，六台母车字节一致。
- 未覆盖任务开始时已有的导弹/灯光/创造栏等源文件修改，非共享文件 SHA-256 对照一致。按仓库提交纪律，最终 `src/` 整体提交包含这些既有源代码修改；载具包和计算器的其它改动保留原工作区状态。
