# RVP 拒射扣弹与弹体消失排查修复（2026-10-25）

## 现象与证据

用户报告：J-10C 的 GB-3 红外制导炸弹在无锁定时提示“红外导引头尚未锁定”，弹药减少，投放后立即消失；`rvp_projectile_lifecycle_debug.log` 没有弹体记录。雷达弹偶尔也有类似脱锁/消失表现。

本轮证据来自当前源码和执行真实调度代码的回归测试；没有连接玩家客户端复现实射。

1. `j10c_gb3_ir.json` 为 `rvp:bomb`，`guidance_type=IR`、`require_lock=true`。客户端 `requiresEntityLock` 原先只接纳 `MISSILE`，制导炸弹绕过锁定检查。
2. 服务端 `RVP_ProjectileWeapon.shoot` 和点射首发先 `consumeAmmo`，然后调用返回类型为 `void` 的 `dispatchShots`。后者遇到未完成红外锁定、离轴越界、鱼雷未瞄水或反舰目标雷达反射不足时直接返回。
3. 外层仍推进 `lastShootTime`、热量并返回 `true`。本体 `WeaponUnit.shoot` 收到 `true` 后发 `VehicleFireEvent.Post` 和 `ServerVehicleFire`，让客户端表现得像成功发射。这里没有真实弹体，不能解释成“实体生成后被删除”。
4. 旧生命周期日志从 `initFromWeapon` 开始追踪；发射前就返回的请求没有实体/UUID，因此没有日志。
5. 连发控制器使用 `Runnable`（没有成功/失败返回值的回调），续发拒射也加热并消耗连发次数。
6. 载具出弹器忽略 `RVP_ProjectileSpawnResult.status`，即使 `addFreshEntity` 拒绝入世，也把已构造的对象返回给调用方。

## 修复与影响

- 客户端锁定门纳入使用寻的制导的 `BOMB`，普通炸弹保持原样；已有多武器组入口复用该检查，无须新增 Mixin。
- 服务端先生成 `ApprovedShot`（本次已获准的目标快照），所有目标拒射检查都在扣弹和消费蓄力之前完成。
- 普通发射、点射首发、续发共用返回成功/失败的调度入口；至少一个出弹点实际加入世界才返回成功、启动冷却、记录热量并施加对应后坐力。
- 扣弹使用出弹点列表的副本，避免弹量不足时本体裁剪调用方列表。每个完全失败的出弹点退还一枚弹药；全部失败时恢复蓄力，不广播成功。
- 雷达弹按 `require_lock` 在服务端复查有效目标，保留已有 EO（光电直瞄）豁免。IR 仍只认服务端导引头授权，显式 `require_lock=false` 时允许无目标出弹，不把普通站级锁冒充红外锁。
- 连发回调改为返回布尔结果；失败立即结束该轮，不给失败发射加热。
- 生命周期日志新增实体生成前的 `SHOT_REJECTED` / `SHOT_FIRED`，含武器、发射站、原因、剩余弹药和成功出弹点数。未生成实体的请求只写文件，不建立永远等不到销毁事件的弹体追踪记录。

没有修改本体源码、武器 JSON、资源文件或 Mixin。GB-3 当前配置仍要求锁定；正确结果是无锁定时拒绝投放并保留弹药，而不是无锁也投出一枚炸弹。

## 雷达弹在飞行中消失的边界

普通脱锁本身不直接删除实体；ARH（主动雷达制导）中继丢失先滑行，达到 `relay_lost_self_destruct_ticks` 才进入既有寿命终止流程。当前默认 300 Tick，即游戏正常速度下 15 秒。硬拦截也会移除实体，箔条干扰导致脱锁不是同一分支。

为区分这几种情况，补充 `RADAR_RELAY_LOST`、`RADAR_RELAY_RESTORED`、`RADAR_RELAY_TIMEOUT`、`COUNTERMEASURE_INTERCEPTED` 原因记录；原有飞行与自毁规则未调整。没有实射日志时，不能断言用户看到的每一次雷达弹消失都由扣弹顺序造成。
