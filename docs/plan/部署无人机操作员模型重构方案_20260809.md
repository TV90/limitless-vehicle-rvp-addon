# 部署无人机操作员模型重构方案（去假玩家化）

> 日期：2026-08-09
> 范围：`ywzj_rvp` 车载部署无人机的"操作员/玩家身份"模型重构，以及雷达开关同步的非 Mixin 落地。
> 状态：设计评审稿（未实施）

## 1. 背景与目标

### 1.1 用户诉求

1. 部署无人机的操作员模型不应采用"假玩家"方案——玩家应该**开载具**（骑乘驾驶），不应该在母车旁生成假玩家实体（假玩家易被击杀，且本体会把假玩家受到的伤害转移给真玩家）。
2. 应**赋予当前载具"玩家属性"**：无人机载具本身携带玩家身份，而不是靠一个独立假玩家实体来代表玩家。
3. 重构不得影响既有行为：**无人机死亡传送回母车**、**母车锁车逻辑**。

### 1.2 附加要求

- 雷达开关同步（外置雷达随开关停用）不再用 Mixin：先查本体是否暴露公共 API，没有则自写等效方法，实在不行才允许 Mixin。
- 本方案全程**不新增 Mixin**。

## 2. 现状分析

### 2.1 本体遥控器无人机：真·假玩家方案

本体 `AbstractVehicle` 对 `uav=true` 的载具（遥控器物品 `UavControllerItem` 配对/骑乘）在 `onEnterVehicle` 中：

```java
if (uav) {
    if (livingEntity instanceof ServerPlayer serverPlayer && tickCount != 0) {
        fakeOperatorPosition = livingEntity.position();
        fakeOperator = new FakePlayer(AllEntities.FAKE_PLAYER.get(), level());
        fakeOperator.spawn(serverPlayer);
        fakeOperator.setPos(fakeOperatorPosition);
        level().addFreshEntity(fakeOperator);   // ← 在玩家原位置生成假玩家实体
        livingEntity.teleportTo(this.position().x, this.position().y, this.position().z);
    }
}
```

`FakePlayer.hurt()` 会把伤害转移给真玩家并把他拉回假玩家位置——这就是"假玩家容易被击杀、击杀连累真玩家"的来源。

### 2.2 RVP 部署无人机：现状

- 部署：`RVP_DeployableUavService.deployLinkedUav` 在母车旁生成子载具实体，建立 `RVP_LinkedUavStateTable` + `RVP_DeployableUavLinkRegistry` 链接；配置了 loiter 则自动盘旋。
- 切换：`switchToLinkedUav` → `player.startRiding(child)`，玩家**真正骑乘**无人机；同时锁定母车座位。
- **部署模板的 `uav` 标记不一致**（实测 `run/server/.../rvp/vehicles/*.json`）：
  - `irist_slm_tads`（母车 `irist_slm_tel`）、`96l6`（母车 `bukm3`）：**未标** `"uav"` → `child.uav == false`，RVP 走 `EntityMountEvent` 的 `!vehicle.uav` 分支（记录上车前位置 + teleport），**不生成假玩家**。
  - `suav`（母车 `m142` / `lav25` / `zbl08a`）：**标了 `"uav": true`** → 骑乘时本体 `onEnterVehicle` 的 uav 分支**会在玩家原位置（母车旁）生成 FakePlayer 假玩家**，并把玩家传送上机。
- 离机/死亡：`resolveReturnPosition`（母车实体位置 → 母车位置快照 → 上车前位置）→ teleport 回母车旁 → `tryAutoRideParent` 自动坐回母车座位。
- 母车被毁 → 无人机联动自毁（`checkParentDestroyed`）；无人机被毁 → 玩家被踢下并回传。

### 2.3 结论：suav 部署实例当前**确实**生成假玩家

`suav.json` 第 43 行 `"uav": true`，`m142`/`lav25`/`zbl08a` 部署 suav 后，玩家 M 键骑乘时母车旁会生成本体 `FakePlayer`（复制玩家名字/手持/装备，可被攻击，被击中会把玩家从无人机上拉回并转移伤害）。`irist_slm_tads`、`96l6` 不生成。这印证了用户"在母车旁边生成假玩家、假玩家容易被击杀"的描述。

额外欠账：

1. **命名残留**：状态表字段叫 `fakeOperatorPosition`（"假操作员位置"），与本体假玩家方案语义混淆，概念上仍是"假操作员"模型。
2. **无防呆**：`suav` 已实际触发本体假玩家分支，任何模板误配 `"uav": true` 都会重蹈覆辙。
3. **玩家身份未显式绑定载具**：目前靠座位/operator 隐式持有，缺一个"这架无人机属于谁"的显式状态（死亡回传、将来告警/归属判断都依赖它）。

## 3. 新方案设计

### 3.1 核心原则

- 玩家 = 骑乘（开）无人机，不生成任何假玩家实体。
- 无人机载具自身携带玩家身份（`operatorPlayerId`）。
- 部署实例**永不**走本体 `uav=true` 分支（强制 `child.uav = false` 防呆）。
- 死亡传送、母车锁车、盘旋、区块强载全部保留。

### 3.2 状态表语义重构（`RVP_LinkedUavStateTable`）

| 现状 | 改动 |
|---|---|
| `Vec3 fakeOperatorPosition` | 更名 `Vec3 entryPosition`（语义=上车前位置，仅作离机回传兜底） |
| —（无） | 新增 `int operatorPlayerId`（无人机所属玩家实体 ID，-1 表示无人驾驶/自动盘旋阶段） |

对应 getter/setter 同步改名/新增：`getEntryPosition/setEntryPosition`、`getOperatorPlayerId/setOperatorPlayerId`。

### 3.3 事件处理（`RVP_LinkedUavEventHandler`）

- `handleMount`：`setFakeOperatorPosition(...)` → `setEntryPosition(...)`；同时 `setOperatorPlayerId(vehicle, serverPlayer.getId())`。
- `tickVehicles`：`getFakeOperatorPosition` → `getEntryPosition`（强载上车前位置区块逻辑不变）。
- `resolveReturnPosition`：`getFakeOperatorPosition` → `getEntryPosition`（兜底优先级不变）。

### 3.4 部署服务（`RVP_DeployableUavService`）

- `deployLinkedUav`：构造 `child` 后、`configureLink` 前，强制 `child.uav = false`（防呆：模板即使配了 `uav:true`，部署实例也绝不触发本体假玩家分支）。
  - 依据：`AbstractVehicle.uav` 为 public 可变字段（[AbstractVehicle.java#L141](file:///d:/ywzj/ywzj/ywzj_vehicle/src/main/java/org/ywzj/vehicle/entity/vehicle/AbstractVehicle.java#L141)），且 **`uav` 是普通字段、不走 SynchedEntityData**——服务端强制为 `false` 只影响服务端实体，**客户端实体的 `uav` 仍按 JSON 读取（suav 仍为 `true`）**。
  - 副作用评估（本体 `uav` 全部使用点）：
    | 使用点 | 端 | 强制 `false` 后 |
    |---|---|---|
    | `onEnterVehicle` uav 分支（生成 FakePlayer + teleport） | 服务端 | **不再生成假玩家**（目标达成）；teleport 由 RVP `handleMount` 的 `!vehicle.uav` 分支接管 |
    | `FakePlayer.tick` 保留条件 | 服务端 | 玩家骑乘 uav=false 载具 → 旧假玩家 discard（顺带清理） |
    | `UavControllerItem` 配对/骑乘门槛 | 服务端 | 部署实例不再能被遥控器物品配对（本就不该，无副作用） |
    | `LocalVehiclePlayer` G 力过载判断 | 客户端 | **不变**（客户端实体 `uav` 仍为 true，无人机机动不产生 G 力过载） |
    | `RenderLivingHandler` 乘客渲染取消 | 客户端 | **不变**（客户端实体 `uav` 仍为 true，隐藏骑乘玩家模型，保持无人机观感） |
- `configureLink`：operator 为 `ServerPlayer` 时 `setOperatorPlayerId(child, operator.getId())`。
- `switchToLinkedUav`：骑乘成功后 `setOperatorPlayerId(child, player.getId())`。
- `switchBackToParent` / `handleDeployableUavRemoved` / `RVP_LinkedUavStateTable.remove`：离机/移除时清理 `entryPosition` 与 `operatorPlayerId`（防止状态残留）。

### 3.5 保留（不动）

- 死亡传送：`handleDismount` / `onEntityLeaveWorld` → `resolveReturnPosition` → `tryAutoRideParent`（含母车卸载时 60 tick 延迟重试队列）。
- 母车锁车：`PARENT_SEAT_LOCKS` + `setSeatLock/clearSeatLock/shouldRejectMount` + `enforceSeatLocks` 每 tick 踢入侵者 + 重生/下线解锁。
- 盘旋/切换/区块强载/`AbstractVehicleUavClientSwitchMixin`（既有 mixin，不在本次范围）。

### 3.6 不新增 Mixin

本方案全部改动落在 RVP 自有类（状态表、事件处理器、服务类），不触碰本体字节码。

## 4. 雷达开关同步（非 Mixin 方案）

### 4.1 公共 API 调查结论

| 候选 | 结果 |
|---|---|
| 本体 `ClientRadarAction.Action` | 仅有 `DETECT, LOCK`，**无**开关 action |
| 本体 `org.ywzj.vehicle.api` 包 | **无** Radar 相关公共接口 |
| 本体 `RadarUnit` | `toggle(Boolean)` / `isOn()` 为 public，**服务端可直接调用**（作接收端） |
| 本体 `InputHandler` TOGGLE_RADAR 键 | 纯客户端本地翻转 `on`，无任何网络同步 |

**结论：本体没有"客户端开关 → 服务端同步"的现成公共 API**，但自写等效方法完全可行，**不需要 Mixin**。

### 4.2 方案：客户端 tick 状态检测 + 复用 `C2SRadarPowerToggle`

- 接收端已就绪：`C2SRadarPowerToggle` 服务端 `handle` 遍历 `vehicle.getPartUnits()` 找到对应雷达，`isOn() != msg.on` 时调用 public `toggle(msg.on)`（该报文为非 Mixin 普通报文，保留）。
- 发送端（新）：在现成的客户端雷达 tick 处理器 `RVP_ClientRadarTickHandler.onClientTick` 中：
  1. 以 `vehicleId + radarId` 为 key 缓存每颗雷达的 `isOn()` 快照。
  2. 每 tick 对比当前状态，**变化时**发送 `C2SRadarPowerToggle(vehicle.getId(), radarUnit.getId(), radarUnit.isOn())`。
  3. 车辆切换（`vehicle.getId() != lastVehicleId`，已有逻辑）时清空快照。
- 覆盖入口：本体 `InputHandler` TOGGLE_RADAR 键、`RVP_ClientHmdState.ensureRadarOn` 等所有客户端 toggle 路径（不依赖调用点，状态变化必然被 tick 捕获）。
- 无需 Mixin，不依赖本体事件时序。

## 6. 验证用例

1. 部署 `irist_slm_tads`（或 m142→suav）后 M 键切换：玩家骑乘无人机，母车旁**无**假玩家实体。
2. 无人机被击毁：玩家回母车旁并自动坐回原座位。
3. 无人机飞行中按雷达开关键：母车外置雷达共享随即停用（服务端 `isOn()` 正确）。
4. 玩家驾驶无人机期间，他人无法登上母车（锁车）；切回后解锁。
5. 模板误配 `"uav": true` 的部署实例：仍不生成假玩家（防呆生效）。

## 7. 风险

- 低：`entryPosition` 改名纯内部引用；`child.uav = false` 与现状一致。
- 中：雷达 tick 检测每 tick 比对一次 `isOn`，仅状态变化时发包，开销可忽略；需确保只在客户端物理侧发送（`vehicle.level().isClientSide()`）。
- 中：`operatorPlayerId` 若未来需要同步到客户端（HUD 归属显示），需另加 S2C 同步字段——本期仅服务端使用。
