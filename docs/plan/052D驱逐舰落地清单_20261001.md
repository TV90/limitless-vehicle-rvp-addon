## 〇、单位纠正（最先确认，影响所有数值）

本体在 `af6a437` 把默认载具包的**质量与推力换成真实物理量**，现行单位：

| 字段 | 单位 | 证据 |
|---|---|---|
| `physics_info.mass` | **千克 (kg)** | `VehicleDebugOverlay:70` 打印 `"curbWeight (kg)"`；`DamageSystem:141` 用 `mass / KILOGRAMS_PER_TONNE` 算动能 |
| `attributes.forward_force` / `backward_force` | **牛顿 (N)** | `PhysicsHelper.accelerationPerTick(double forceNewtons, double massKilograms) = force / mass / 400` |
| `physics_info.friction` | 同力单位 | 突击艇 `500 = mass(250) × 2` |
| `physics_info.density` | 无量纲比值 | `VesselVehicleData:44` `if (density > 1) density = 0.3f` ⇒ **必须 ≤ 1** |
| `energy_info.energy_capacity` | **千克（燃油质量）** | `AbstractVehicle:183` `physicsInfo.mass = curbWeight + entityData.get(ENERGY)` ⇒ **燃油计入总质量** |

自洽验证（突击艇）：`3000 N / 250 kg = 12 m/s²`，`accelerationPerTick` 再 `/400` 得每 tick 速度增量。

> ⚠️ **上一轮口头给的 `mass 7500` / `forward_force 4500` 小了 1000 倍**，以本清单为准。

## 一、结构模型：必须改的一处

### 1.1 现状实测

| 项 | 值 |
|---|---|
| 整体包围盒 | **14.69 × 25.31 × 120.78 格**（宽 × 高 × 长） |
| `main_structure` | **单个 cube**：14.69 × 8.93 × **120.78 格**（origin z = -1298.5，size z = 1932.5 px） |
| ⇒ `depth` | **120.78** |

### 1.2 为什么必须改

船转向公式（`VesselVehicle.tickMove()`，满舵时 `rudder/max_turn` 抵消）：

```
yawStep = toDegrees(atan2(motion, mainCubeOBB.depth)) × 0.2    （度/tick）
```

按当前 depth、航速 0.75 格/tick：`toDegrees(atan2(0.75, 120.78)) × 0.2 = 0.071°/tick`
⇒ 掉头一圈 **5056 tick ≈ 253 秒（4 分钟）—— 转不动**。

### 1.3 改法（只改 main_structure 的 cube）

把那个 cube 的 **Z 缩到 160~192 px（10~12 格）**，`origin.z` 调整到**保持中心 z = -332.25 不变**：

| 主 cube Z | 新 origin z | depth | 满舵掉头 |
|---|---|---|---|
| 192 px（12 格） | `-332.25 − 96 = -428.25` | 12 | **25 秒** ← 推荐 |
| 160 px（10 格） | `-332.25 − 80 = -412.25` | 10 | 21 秒 |
| 128 px（8 格） | `-332.25 − 64 = -396.25` | 8 | 17 秒 |

宽高（235.0 × 142.9 px）保持不变。保持中心不变是因为 `tickPower()` 拿 `mainCubeOBB.obb().center()` 采流体，中心必须落在船中、水线附近。

### 1.4 缩小后碰撞会不会丢？—— ⚠️ **会丢，必须加倍率因子**（2026-10-01 修正）

> 初版此处写"不影响碰撞、不需要倍率因子"是**错的**（只查了 `getOBBs()`，漏了 `push()`）。以下为修正结论。

`mainCubeOBB` 并不只服务转向，它同时承担：

| 职责 | 依据 |
|---|---|
| **方块碰撞采样** | `PhysicsEngine.collectContacts()` 的采样点是 `physicsCube().cubePoints()`，而 `physicsCube() == vehicle.getMainCubeOBB()` |
| **载具 / 实体互撞判定** | `AbstractVehicle.push():1420` `OBB mainCubeOBB = getMainCubeOBB().obb();` → 对方是载具时 `OBB.isColliding(vehicle.getMainCubeOBB().obb(), mainCubeOBB)`；是普通实体时也用它 |
| 实体包围盒 | `makeBoundingBox():818` 把 `mainCubeOBB.obb()` 并入 `getOBBs()` 的结果 |
| 流体采样 | `tickPower()`、`AbstractVehicle:571` 用 `mainCubeOBB.obb().center()` |
| 转向 depth | `VesselVehicle.tickMove():114` |

⇒ 把主 cube 的 Z 缩到 192 px，等于**把整船碰撞体压成 12 格长的盒子**：两艘船相撞判定失效（互相穿过）、贴岸时首尾探不到方块。

### 1.5 正解：模型不动，给「转向用的 depth」加倍率（RVP 侧）

`depth` 在 `VesselVehicle.tickMove()` 里只在两行被读（113 判定 / 114 计算），用 MixinExtras 的 `@ModifyExpressionValue` 单点缩放即可，**不碰 `push()`、不碰碰撞、不是 `@Overwrite`**：

```java
@Mixin(VesselVehicle.class)
public abstract class RVP_VesselTurnDepthMixin {
    @ModifyExpressionValue(
        method = "tickMove",
        at = @At(value = "FIELD", opcode = Opcodes.GETFIELD,
                 target = "Lorg/ywzj/vehicle/vehicle/structure/VehicleCubeOBB;depth:F"))
    private float rvp$scaleTurnDepth(float original) {
        float scale = RVP_VehicleExtendedConfigManager.turnDepthScale(this);  // 新增配置项
        return scale > 0 ? original * scale : original;
    }
}
```

- **配置来源**：仿 `RVP_VehicleExtendedConfigManager.parsePhysicsOnlyBones` 的写法，在 `physics_info` 加 RVP 扩展字段 `turn_depth_scale`（缺省 1.0，只影响转向，不影响碰撞）。
- **效果**：052D 主 cube 保持 120.78 格（碰撞完整），把 `turn_depth_scale` 设成 `10 / 120.78 ≈ 0.083` 即可拿到 depth=10 的转向手感（21 秒掉头）；想更灵活继续调小。
- **代价**：这是 RVP 侧唯一为"船转向"引入的 Mixin，按项目约定 Mixin 默认拒绝，需要你确认；好处是所有船共用一套配置、模型永远不用为手感而改。

### 2.1 推力推导（`VesselVehicle.tickMove()` + `PhysicsHelper`）

```
每 tick 速度增量 = forward_force × (power/100) / mass / 400        （格/tick）
到满速 tick 数   = max_speed_forward × 400 × mass / (forward_force × powerScale)
```

`mass = 空重 7.0e6 + 燃油 5.0e5 = 7.5e6 kg`（满载 7500 t，与你给的一致）：

| 目标满速时间 | `forward_force` |
|---|---|
| 15 秒 | 7,500,000 |
| 20 秒 | 5,625,000 |
| **25 秒** | **4,500,000** ← 采用 |
| 30 秒 | 3,750,000 |

突击艇对照：`1.0 × 400 × 250 / 3000 = 33.3 tick ≈ 1.7 秒`（小艇就该这么窜）。

### 2.2 燃油与续航

`energy_capacity` 是燃油**质量**（kg）且计入总质量，所以"7500 t"要拆成空重 + 油：

- 空重 `7,000,000` + 油 `500,000` = 满载 `7,500,000` ✅
- 续航 = `energy_capacity / energy_consumption_per_tick` tick，`0.87` ⇒ `575,000 tick ≈ 8 小时`
  （突击艇参照：`40 / 0.000208333 = 192,000 tick = 2.67 小时`）
