# Gunner 制导武器行为系统方案

> 状态：**方案稿 v2**（尚未实现）
> 范围：让 gunner 会合理使用 RVP 制导武器：提高制导武器优先级、SEAD 复仇、全导弹 5s 冷却、扩大空对地索敌范围。
> 配置方式：**全部硬编码默认值**（不引入 JSON 配置字段），后续需要再抽。
> 本版新增：**服务端适配**与 **TPS 性能开销**专项考虑（见第七、八节）。

---

## 〇、先讲人话：我们要让 gunner 变成什么样

现在这个 gunner（AI 飞行员/炮手）其实**已经会用大部分导弹**，但有两个明显毛病：

1. **不爱用导弹，爱用机炮**——即使身上带导弹，也常拿机炮去打，浪费了导弹的射程。
2. **被打不会"记仇反击"**——被雷达锁定就抛个干扰物，不会回头干那个锁定我的人。

我们想让它在关键场景下表现得像个会打仗的飞行员：

- **被雷达锁定**（敌方雷达咬住我）→ 我**先逃**（抛干扰物 + 调头远离那个锁定我的敌人）→ 跑出安全距离后**回头** → **锁死那个雷达** → **射它一枚反辐射弹** → 打完收手。这就是"SEAD 复仇"。
- **身上带着导弹就优先用导弹**（射程远、效率高），机炮只在够近/拦截近距弹药时才用。
- **任何导弹发射后都要等 5 秒冷却**，不能连续乱射。
- **飞机在空中能发现很远的对地目标**（空对地索敌范围大幅扩大）。
- **飞机由 gunner 自己开**，全程自主完成"逃→回头→打"，不需要玩家接管。

## 一、现状盘点（gunner 现在已有什么 / 缺什么）

| 能力 | 现状 |
| --- | --- |
| 识别导弹种类 | 已能区分 SARH/ARH/IR/AIR/SACLOS/SALH/LBR/GPS/ARM/HITL_TV |
| 选武器 | 有 `selectWeaponIndex`，但**偏好逻辑导致爱用机炮**（见下方"病根"） |
| 锁定门控 | 已按 `lock_target_distance_range` / `lock_altitude_range` / `max_lock_angle` 判定"能不能打" |
| 对空纪律 | 打飞机须持锁满 5 秒才发射，发射后 5 秒不重复（硬编码 100 tick） |
| 对抗措施 | 会抛烟（IR/激光/近距导弹）、抛 flare/chaff（近距弹药 / 按制导类型自动） |
| ARM 预选 | 已能挑一个雷达发射源来打 |
| 空中阶段 | 已有"攻击/脱离"两相，但**与威胁事件无关**（定时器驱动，不会记仇） |

### ★ 病根：为什么 gunner 爱用机炮不爱用导弹

看 `GunnerBrain.selectWeaponIndex`（GunnerBrain.java:1244）：

```java
boolean preferMissile = (targetIsAmmo && dist > 200.0) || (!targetIsAmmo && targetHighAlt);
// targetHighAlt = altitudeAgl(target) >= 200
```

- 只有**高空目标（AGL≥200）**或**远距弹药（>200m）**才会走进 `preferMissile` 分支；
- 对**普通地面/低空目标**（坦克、低空直升机），`preferMissile` 和 `preferGun` 都是 false → 落到**兜底循环**（GunnerBrain.java:1300），**直接挑武器索引里第一个有弹能打的**——通常就是机炮。

**结论**：机炮被选，不是"机炮更优"，而是"导弹没被优先"。修复方向：**只要目标能用某把 RVP 制导武器打到，就优先制导武器**；机炮只在没导弹可用 / 近距 CIWS 时兜底。

## 三、武器选择优先级（核心改造）

把 `selectWeaponIndex` 的偏好逻辑改成**"先导弹后机炮"**，并给制导武器按类型打分：

```
选择流程（新）：
1. GPS 优先（保留，远程点目标）
2. 若目标可用某把 RVP 制导武器（canSelectForTarget 通过）：
     → 按"武器类型打分"选分最高的制导武器（见下表）
3. 否则（无制导武器可用/在冷却）：
     → 机炮 / 其它武器兜底
4. CIWS 近距（≤200m 弹药）仍优先机炮（近防拦截要快）
```

**制导武器类型打分（由高到低，硬编码）**——解决"该不该优先用"：

| 优先级 | 武器 | 大白话 |
| --- | --- | --- |
| 1 | ARM（反辐射） | SEAD 复仇专用，专治开雷达的敌人 |
| 2 | IR / AIR | 近距自卫，射后不管 |
| 3 | ARH / SARH | 中远程，打远目标 |
| 4 | GPS | 远程点地面目标 |
| 5 | SACLOS / LBR / LH | 持续照射型 |
| 6 | HITL_TV | 高价值目标专用 |

**评分规则（打分不看"武器索引顺序"，看"类型"）**：遍历所有武器，过滤出 `canSelectForTarget` 通过的制导武器，取类型优先级最高者。机炮不再靠"排前面"抢占。

## 四、空对地索敌范围（大幅扩展）

现状：`getTargetSearchRadius`（GunnerTargeting.java:70）对飞机只是 `search_radius × 2`，对地目标没有专门扩大。

改造：
- 新增硬编码 **`AIR_GROUND_SEARCH_MULTIPLIER`（如 ×6）**：飞机搜**对地目标**（非高空、非弹药）时，搜索半径 = 基础搜索半径 × 该倍率，或直接 = 雷达最大扫描距离（取两者较大）。
- `findBestTarget` 里对"对地目标"走扩大后的半径；`score` 的"距离+角度×32"惩罚保留（保证先打朝向本机的）。
- 注意 AABB 膨胀框 `collectTargetEntities` 用半径膨胀，扩大半径即可覆盖更远地面目标。

## 五、SEAD 复仇（反辐射）—— 主案例

**触发**：仅在被雷达锁定（`WarnType.RADAR_LOCK` 或扫描到敌 `RadarUnit.getLockedEntity()==本机`）且带反辐射弹时进入。

### 入口判定（触发瞬间，先看能不能立刻打）

被锁定的**同一瞬间**，先判定锁定我的雷达发射源是否**已经在反辐射弹的射击门控内**（`resolveArmPreselect` 的范围 / 高度 / 锥角通过）：

| 情况 | 行为 |
| --- | --- |
| **已在门控内** | **立即发射 1 枚反辐射弹**（不等、先打），随后进入 SEAD 复仇阶段，复仇阶段结束前**再补 1 枚** → 本轮共 2 枚 |
| **未入门控**（太远 / 角度不对） | 直接进 SEAD 复仇阶段（逃 → 回头 → 门控过即打 1 枚） → 本轮共 1 枚 |

> 大白话：跑路前能顺手打一发就先打一发，别浪费好角度；打完再拉开距离进复仇机动。

### 复仇阶段四步动作（gunner 自己开飞机）

| 阶段 | 大白话 | 硬编码默认（tick） | 说明 |
| --- | --- | --- | --- |
| **FLY_AWAY**（逃） | 抛 CHAFF/SMOKE，调头背对锁定者飞远 | `200`（10 秒） | 原 80 太短，飞机转向+脱离需要时间 |
| **REVERSAL**（回头） | **边回头边索敌**：转向对准锁定我的雷达，同时每 tick 检查该雷达是否已进入导弹攻击门控 | `160`（8 秒，**上限**） | 原 40 太短；**门控一通过立即提前进入 LOCK_AND_FIRE**，不等 8 秒走完 |
| **LOCK_AND_FIRE**（锁&打） | 用 ARM 挑发射源逻辑锁定该雷达，射 1 发 | 打到即走 | 复用 `resolveArmPreselect` |
| **退出** | 射完复仇阶段的 1 枚 / 超时 | 总超时 `500`（25 秒，**保险上限**） | 见下方"总超时语义" |

**REVERSAL 的关键语义**：这 8 秒不是"只转向不干活"。每一 tick：
1. 继续转向对准发射源；
2. **同时**用 `resolveArmPreselect`（范围 / 高度 / 锥角 / 发射源有效）判定目标是否已进入攻击门控；
3. **门控通过 → 立即切 LOCK_AND_FIRE**，提前退出 REVERSAL。
160 tick 只是最长时间上限（防止目标雷达关机/跑远导致永远进不了门控而卡死）。

### 总超时（500 tick）的语义——它是保险，不是时间预算

- 500 是**总保险上限（failsafe）**，不是"逃+回头要占满 25 秒"。
- 正常流程：触发立即打（若有）→ 逃(200) → 回头(≤160，门控过即早退) → 打 1 枚 → **打完即退出**。正常总时长约 **≤360 tick（18 秒）**，远到不了 500。
- 500 只在**异常**时兜底：目标雷达关机 / 跑远 / 永远进不了门控时，强制退出复仇，防 gunner 卡死追着不放。

**关键**：整个复仇有**总超时保护**（防 gunner 一直追一个跑掉的雷达卡死）；超时或打完后回 STRIKE/IDLE。

## 六、全导弹 5 秒冷却

现状：`tickCombat` 里 `missileCooldown = 30`（1.5s），且只对 RVP 导弹设；对空另有 100 tick 的"打飞机纪律"。

改造（统一）：
- **`MISSILE_COOLDOWN_TICK = 100`**（5 秒），对所有 RVP 制导武器发射后统一设置。
- 与对空纪律（持锁 100 tick、同目标间隔 100 tick）**并存但不重复叠加**：冷却从"发射时刻"起算，对空纪律从"锁定时刻/上次发射"起算，二者取更严格者即可。
- 对空纪律保留（它管"锁定后不能立刻射"，冷却管"射完不能连续射"）。

## 七、服务端适配

- **gunner 逻辑只在服务端跑**（`GunnerEntity.tick` 服务端早期返回，GunnerBrain 是纯服务端工具类）。SEAD / 索敌 / 冷却全在服务端完成，客户端只做渲染。
- **新增状态全部放 `GunnerEntity`**（非同步字段，服务端私有）：`engagementMode`、`engagementModeTicks`、`revengeTargetId`、`revengeStage`。**不新增 S2C/C2S 包**，无需客户端参与。
- **被雷达锁定检测**在服务端：扫描敌 `RadarUnit` 的 `getLockedEntity()` 是否 == 本机，或读本机 `warningReceiver.targets`（服务端也有 `WarningReceiver`）。与现有 `tickRadarLock`/`RVP_LaserWarnService` 语义一致。
- **无 Mixin**：全部走 Forge 事件 / 现有工具类，不碰本体字节码（符合项目铁律）。

## 八、TPS 性能开销专项（重点）

### 现状的服务端开销源

| 扫描 | 频率 | 代价 |
| --- | --- | --- |
| `collectTargetEntities`（GunnerTargeting.java:422） | 每 `scan_interval_tick` | **遍历所有已加载实体** O(N)，逐实体做 AABB+谓词过滤 |
| `scanMissileThreats`（GunnerBrain.java:652） | 每 tick（地载 AI） | 遍历所有实体，过滤导弹 |
| `findLasingEnemy` | 每 tick | 遍历 activeDesignations 表 |
| ARM `scanVisibleEmitters`（AntiRadiationSeekerHelper） | 每扫描间隔 | 遍历所有载具的 RadarUnit |
| `RVP_LaserWarnService.scanLevel` | 每 5 tick | 遍历所有实体 + 照射点表 |

**关键风险**：`getEntities().getAll()` 是**全量遍历**。多个 gunner / 大世界 / 高实体数时，任何新增的全量扫描都会推高服务端 TPS 压力。SEAD 与空对地索敌**不能**再随意加全量扫描。

### 新方案的开销控制（硬约束）

1. **复用现有扫描，不新增全量 pass**：
   - SEAD 的"被雷达锁定"检测，**并入**现有的 `tickRadarLock` / `GunnerExternalRadarController` 每扫描间隔的雷达遍历，**不另开全实体遍历**。
   - 空对地索敌扩大，走**现有** `findBestTarget` 的 `collectTargetEntities`（只是把半径调大），**不新增第二个遍历**。
   - 复仇锁定打用现有 `resolveArmPreselect`（已是按扫描间隔的脉冲式 ARM 扫描）。

2. **节流（throttle）**：
   - 威胁/SEAD 判定**不每 tick**跑，改成与 `scan_interval_tick` 同频（如每 10~20 tick 一次），中间帧复用上一次结果。
   - `scanMissileThreats` 目前每 tick 跑（地载），建议**降频**（如每 5~10 tick）并提前 `break`（已有提前结束）。
   - 被雷达锁定状态**缓存**：锁定者 id 存到 `GunnerEntity`，不是每次全扫，而是"确认仍锁→复用；丢失→重新扫"。

3. **尽早退出 + 稀疏遍历**：
   - 所有扫描保留"命中即 `break`"（`scanMissileThreats` 已有）。
   - `collectTargetEntities` 用 AABB 相交先粗筛（已有），命中才做谓词（友我判定较重，只在粗筛通过后跑）。

4. **一次遍历多用**：
   - 若一次 `getAll()` 已经发生（索敌），把"威胁检测/SEAD 雷达锁定检测/空对地目标收集"合并进**同一次遍历**，避免多份 O(N)。

### 目标

- 单 gunner 新增逻辑**每扫描间隔 ≤1 次全实体遍历**（与现状持平），且威胁/SEAD 判定不逐 tick。
- 多 gunner 时总量 O(gunner × 扫描间隔 × N)，靠降频 + 合并遍历控制，不出现 O(每tick × N × 多扫描)。

## 十一、待办 / 风险

- 空对地索敌半径调大后，`collectTargetEntities` 的 AABB 膨胀框会更大 → 命中更多实体 → 谓词（友我判定）开销上升。**必须**靠节流 + 一次遍历复用 + 粗筛兜底。
- SEAD"逃→回头"航线复用 `tickFixedWingDriving` 大转弯/爬升逻辑，需扩展成"背向/朝向指定点"的驾驶。
- SARH 发射后需持续照射，与"逃"冲突——复仇阶段若装 SARH 需保持面向目标。
- 全部参数先硬编码，避免一次引入大量配置字段。
