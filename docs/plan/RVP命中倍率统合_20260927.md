# RVP 命中倍率统合记录（2026-09-27，用户定版）

> 结论：**每骨直击伤害倍率唯一来源 = `hitbox_damage_factor`**；`bone_modules` 条目
> 不再携带 `damage_factor`（字段已从解析器删除）。`bone_modules` 只管模块功能：
> `modules` / `min_damage`（失效门槛）/ `explosion`（ERA 爆炸档位）/ 各设备子对象。
> `vehicle_explosion_damage_factor`（爆炸侧分骨倍率）不动。

## 一、背景

`hitbox_damage_factor`（2026-08 B1 恢复的伤害系数体系）与 `bone_modules.damage_factor`
（0925 模块体系，条目自包含带了一份倍率）语义重复；解析时模块条目优先（manager resolve），
形成"给已有倍率的骨加模块条目忘抄值 → 旧倍率被 1.0 静默覆盖"的陷阱（2026-09-26 配置
雷达/引擎骨时靠人工照抄现值规避）。经用户裁决统合为方向 B：倍率归 hitbox 单处。

## 二、全包扫描结果（迁移前）

| 分类 | 数量 | 处置 |
|---|---|---|
| 同值（条目=hitbox，死配置） | 65 | 直接删条目字段 |
| 缺键（hitbox 无该骨键） | 27 | 值≠1.0 搬入 hitbox（bmpt72 ERA0-9：0.5×6/0.25×4）；=1.0 靠默认值覆盖（16 飞机 radar + bukm3 scan_radar，免补键） |
| 值冲突 | 11（全在 vt4） | **用户裁决：以 hitbox 旧值为准** |
| hitbox_era 旧字段 | 0 文件使用 | 兼容解析代码一并删除 |

## 三、vt4 平衡变化点（用户裁决，唯一非零行为变化）

- ERA0-6：0.55（模块化后实际生效值）→ **0.3**（hitbox 旧值，更硬）
- aps_radar_ne/nw/se/sw：0.55 → **0.6**

即 vt4 的 ERA/APS 雷达受击倍率回到模块化之前的更早版本；其余 27 台载具迁移前后
每骨有效倍率逐一相等（脚本断言保证，零平衡变化）。

## 四、改动明细

### 载具包 JSON（28 文件，不进 git）
- 删除全部 bone_modules 条目的 `damage_factor` 字段（92 骨）；
- bmpt72 hitbox_damage_factor 补 ERA0-5=0.5、ERA6-9=0.25；
- vt4 不改 hitbox（保留 0.3/0.6 旧值）；其余同值/缺 1.0 的不动 hitbox。

### 代码（`RVP_VehicleHitboxFactorManager`）
- resolve() 倍率取值：删除"模块条目 damageFactor 优先"分支，恒取
  `hitbox_damage_factor.getOrDefault(骨, defaultFactor)`；
- `BoneModuleConfig` record 移除 `damageFactor` 组件（parse 同步）；
- `hitbox_era` 兼容路径（parseEraCompat/parseEraCompatMap）全包零使用，连同删除；
- tryFloat 仍被 parseFactorMap 使用，保留。

## 五、配置规范（今后）

1. **倍率只写 `hitbox_damage_factor`**：模块骨（ERA/Engine/雷达/APS 传感器…）与纯倍率骨
   （track/vehicle_body/炮塔各面…）一视同仁，统一写顶层映射；
2. **`bone_modules` 只写模块面**：`modules` / `min_damage` / `explosion` / 设备子对象；
3. 条目里写 `damage_factor` 会被忽略（解析器已删字段，写了无效）；
4. `hitbox_damage_factor` 键本身决定该骨是否参与命中判定——新模块骨如果不想改倍率，
   可不写 hitbox 键（走 default 1.0），写了即显式指定。

## 六、验证

- `./gradlew build` 通过；runServer 冒烟 `Done!` 无新增错误；jps 复验干净；
- 实机抽查（用户）：t84bm ERA 分档（0.2~0.65）与 Engine 1.3、vt4 ERA0-6=0.3 变硬后手感。
