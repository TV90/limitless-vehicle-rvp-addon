## 一、本窗口会话主线（按提交顺序，`git log --oneline -14` 可复核）

### A. gunner 本地锁俯仰射界门修复 + gunnerlock 诊断（`cbaf5fac`，触发：Su-57 贴脸锁不了）
- 根因：`RVP_GunnerRadarActions.maintainLocalLock` 把雷达 `rot_info` 的 `x_rot`（`x_rot_min=0`，
  本体仅用作碟面动画钳制）误当 MC 俯仰硬门（负=向上）→ 视轴上方一切仰角目标恒 GATED 清锁；
  玩家手动锁走 `ClientRadarAction.LOCK` 不经此门 → "玩家能锁、AI 锁不了"。与 RCS 无关
  （三条 RCS 消费链只收缩探测外边界，贴脸恒通过）。
- 修复：删 `aimRot.x` 俯仰判定、保留方位 ±45°（无死区，对齐本体"扫描/探测只查方位"语义）；
  新增 `/rvpdebug gunnerlock on|off|status` 诊断（`RVP_GunnerLockDebug`，专用日志
  `logs/rvp_gunner_lock_debug.log`，事件：LOCK/FIRE/SENSE/RELAY/AI 五通道，节流记录）。

### B. 创造保护最终定版（方案A，`120d2a31` → `3f006bc7` 两轮，触发：创造+和平驾驶被打）
- **最终矩阵**：创造·步行 ❌任何难度不被打；创造·驾驶载具 困难→✅被打/非困难→❌保护；
  生存·任何状态 ✅被打；旁观 ❌永不。
- 判定位置：`GunnerTargeting.isProtectedCreativePlayer`（仅步行玩家分支，无条件保护）
  + `hasProtectedCreativePassenger`（载具分支，**难度只在此参与**：非困难才保护）。
- 沿革（防再踩）：09-15 无条件保护 → 09-17 上午恢复困难例外 → 同日用户澄清后定版方案A。
  行为基线 `RVP_GunnerBehaviorBaselineTest` 已冻结两分支语义（改判定必须同步基线）。

### C. 低空对空弹可选性修复（`120d2a31`）
- `GunnerWeaponSuitability.isAirTarget`：FixedWing/RotaryWing **恒为空中目标**（原 AGL>25
  硬判据使 ≤25 格低空掠飞的固定翼被"仅对空弹"门整个拒出索敌候选池）；
  地面载具/步行玩家维持 AGL>25 判据（对空弹不打地面单位语义保留）。

### D. 乘员随载具隐身（`e6544754`，触发："gunner 老远探测到隐身战机/AA 车看不见 AI 隐身机"不对称）
- 根因：`collectTargetEntities` 不排除骑乘者——驾驶隐身战机时玩家 Player 实体作为独立
  候选进入索敌（"player" 命中），而 `passesAspectPerception` 对非载具实体直接放行 → AI
  在全索敌半径（有 96L6 中继 3500 格）"感知到驾驶员"。
- 修复：`passesAspectPerception` 对骑乘候选按**所乘载具** `combinedFactor` 判定
  （`entity.getVehicle()` 解析）；步行玩家/弹药维持放行。基线已冻结。

### H. 激光致盲系统（`69d6dbbb`，**默认关闭**）

  `blind_duration_tick`(200)。命中玩家/gunner/其骑乘载具累计；窗口内攒满触发，
  **触发后计数清零、窗口重开、重新累计**（再次攒满刷新时长；超窗清零重计）。
- 玩家：`S2CLaserBlind`（新包，**协议 11→12**）→ 客户端 `RVP_ClientLaserBlindState` +

  → 炮塔转动落点扫动蓄力条乱跑。改为**固定屏幕准星正下方 72px**，与其它辅助 HUD 对齐。

### J. 松开蓄力快速衰减 + 同轴误驱动修复（`ad97a757` → `8d0eb6e3` → `4abb1da8` → `d8adaaa6`）
- **松开冻结根因**：`syncClientInput` 中 RAILGUN/CHARGE 松开只置停止标志，客户端
  chargeTick 不再更新 → 蓄力条冻结在松开瞬间值（服务端有 charge_decay_tick 衰减，
  纯客户端显示断层）。修复：松开后客户端按 `charge_decay_tick` 衰减到 0（MINIGUN 原有）。
- **同轴误驱动根因**：`isFireKeyDown` 回退分支（武器未选中时任意开火键都算开火，多管
  齐射设计）使打同轴时同站 railgun 蓄力条同涨。修复：蓄力类模式积累只认"玩家当前操作
  单位==本武器单位 且 currentPrimary(解包)==本武器"（`chargeOwnInput`）。
- **两次返工教训**：①chargeOwnInput 首版用 `getCurrentWeapon()==weapon` 恒等比较——
  多武器站返回 `VehicleMultiWeapons`/`VehicleWeaponAgent` **包装对象**，恒等比较恒假 →
  主炮无法蓄力（用户报"主炮蓄力不了"）；必须经 `RVP_WeaponResolveHelper.currentPrimary/
  unwrap` 解包后比对。②第二版比较"玩家操作单位"仍漏 LocalVehiclePlayer 判定，已补。
  ③编译错误：WeaponUnit 类型在 FireController 原先未被显式引用，需补 import。
- ztz100_dtc251/dtb251（railgun，仅本地包有）`charge_decay_tick: 4`（跌回 0.2 秒定版）。

## 五、已知边界与坑

1. **getCurrentWeapon() 返回包装对象**：多武器站为 VehicleMultiWeapons/Agent，任何
   "当前武器==某实例"比较必须先经 `RVP_WeaponResolveHelper.currentPrimary/unwrap` 解包；
2. **rot_info x_rot 语义陷阱**：雷达部件 x_rot 是碟面动画钳制（phase+speed=0 时无效），
   不是目标俯仰包线，禁止再当锁门/探测门用；
3. **toDegrees(acos(0)) = 90.00000000000001 浮点伪影**：恰好 90° 的分支归属断言不可靠
   （RVP_AmmoRadarRcsTest 曾因此失败）；
4. **行为基线测试** `RVP_GunnerBehaviorBaselineTest` 是源码文本断言，改被钉方法必须同步基线；
5. **client_1/client_2 陈旧副本**缺 j16_akf98a/f14d_mk84/f14d_maodie_yeshenggounai 三个
   武器 JSON（迁移时 6 个"缺少文件"失败即此因，非错误）；
6. **docs/README.md 有另一工作线未提交改动**（本体更新接入），勿动勿提交；
7. **多会话共用同一工作区**：动手前 `git status` 核对，他人 WIP 用 stash push/pop 保护；
8. 本地包与 run 副本不是严格镜像（client_1/2 落后），同步以本地主包为准。
