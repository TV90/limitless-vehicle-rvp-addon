# 1. 任务 A：`eo_ccip` 武器在 SCOPE 视角下锚定母武器站（准星随动）

## 1.1 需求

对配了 `rvp_fire_control_sensor_mode: "eo_ccip"` 的武器，**只在 SCOPE（开镜）视角**把 `parent_weapon_unit_aim` 当 `true` 用（弹着点/准星锚定母武器站 ⇒ 随动）；其他视角保持武器站静态配置。

## 1.2 现状与根因（已核对）

链路：`LocalVehiclePlayer.tickAim → tickHit` → `WeaponUnit.currentWeaponHitPosition()`（`ywzj_vehicle/.../WeaponUnit.java:824-889`）

```java
WeaponUnit currentWeaponUnit = vehicleWeapon.getWeaponUnit();   // = rocket 站
if (currentWeaponUnit.isParentWeaponUnitAim()) {               // ← 关键开关
    currentWeaponUnit = currentWeaponUnit.getRootParentWeaponUnit();  // 换成观瞄站
}
...
if (getFireControlSensorType() == CCIP) { ... 沿 currentWeaponUnit 方向算 CCIP ... }
if (aimHitPosition == null) aimHitPosition = currentWeaponUnit.aimHitPosition();
```

- `false` ⇒ 沿 rocket 站**自身**方向（其 `rot_info` 转速为 0 ⇒ 方向恒定 ⇒ 定死）。开镜时 `eo_ccip` 会把传感器切成 `EO`，直接跳过 CCIP 分支落到 `aimHitPosition()`，所以现象最明显。
- `true` ⇒ 换成**观瞄站**方向 ⇒ 随动。

**已有机制（勿重造）**：RVP 早已有武器级 `parent_weapon_unit_aim_override`（`rvp/weapon/data/RVP_WeaponData.java:150`），解析在 `rvp/util/RVP_WeaponResolveHelper.java:55-62`，并被**两个既有 Mixin**调用：

| 既有 Mixin | 数组 | 覆盖的调用点 |
|---|---|---|
| `mixin/WeaponUnitParentAimOverrideMixin.java` | 公共 | `WeaponUnit.currentWeaponHitPosition` 内那次 `isParentWeaponUnitAim()` |
| `mixin/VehicleAimAtOverlaySeekerColorMixin.java:137-153` | client | `VehicleAimAtOverlay` HUD 准心同款调用 |

⇒ **只改解析函数一处，两个消费点同时生效；两个 Mixin 一个字都不动。**

### (4) `src/main/java/org/ywzj/rvp/util/RVP_WeaponResolveHelper.java`
把 `resolveParentWeaponUnitAimOverride`（约 55-62 行）改成三段式：

```java
/**
 * 解析武器级 parent_weapon_unit_aim_override（弹着点/准心锚定方向）。
 *
 * <p>优先级：① 武器显式 parent_weapon_unit_aim_override（写了就以它为准，保证可预测）
 * → ② eo_ccip 动态语义：SCOPE 视角按"电视/激光指示"处理，弹着点锚定母武器站（准星随动）
 * → ③ 返回 null，由调用方回退武器站静态 parent_weapon_unit_aim。</p>
 *
 * <p>传入武器建议先经 {@link #currentPrimary} 解包（Agent/Multi → 具体武器）。</p>
 */
@Nullable
public static Boolean resolveParentWeaponUnitAimOverride(@Nullable AbstractVehicleWeapon<?> weapon) {
    if (!(weapon instanceof RVP_WeaponBase rvpWeapon)) {
        return null;
    }
    // 调用本项目武器数据模型，读取覆盖配置与传感器模式。
    RVP_WeaponData data = rvpWeapon.getData();
    // ① 显式配置优先。
    Boolean explicit = data.getParentWeaponUnitAimOverride();
    if (explicit != null) {
        return explicit;
    }
    // ② eo_ccip + 开镜 ⇒ 锚定母武器站；经桥接查询避免公共代码引用客户端类型。
    if ("eo_ccip".equalsIgnoreCase(data.getFireControlSensorMode())
            && RVP_ClientActionsAccess.isLocalOperatorInScopeView()) {
        return Boolean.TRUE;
    }
    // ③ 回退武器站静态值。
    return null;
}
```

新增 import：`org.ywzj.rvp.client.bridge.RVP_ClientActionsAccess`；用显式类型时再补 `org.ywzj.rvp.weapon.data.RVP_WeaponData`。

## 1.4 边界与红线

1. **不得**新增 Mixin 或注入点；**不得**改 `WeaponUnitParentAimOverrideMixin` / `VehicleAimAtOverlaySeekerColorMixin`。
2. **不得全局改写 `WeaponUnit.isParentWeaponUnitAim()` 本体**。旁路消费点须保持原行为：`RVP_ClientSaclosState:151`（SACLOS 驾束）、`RVP_CommandGuidanceAim:124`（指令制导）、`RVP_RuntimeLbrGuidanceSource:34`（激光驾束起点）、`WeaponUnitBombCcipMixin:49`（炸弹 CCIP）、本体 `VehicleScopeOverlay:210`（炮兵射击诸元）。
3. 优先级：显式 `parent_weapon_unit_aim_override` > `eo_ccip`+SCOPE 动态 > 武器站静态值。某武器若既要 `eo_ccip` 又不想要开镜随动，写 `override: false` 即可关掉。
4. 纯客户端表现：不动弹道、不动发射方向、不动服务端逻辑。
5. 影响面 = 全包 10 个 `eo_ccip` 武器，需回归开镜表现：`lavad_hydra70`、`f16_gbu39`、`f16_gbu53`、`f16_spice1000`、`f18f_specialweapon`、`j10c_gb3_ir`、`j10c_gb3_laser`、`j16_akf98a`、`m142_atacms`、`rafale_storm_shadow`。

## 1.5 备选方案 C：**完全不依赖 Mixin**（纯公共 API）

仅当"连既有 Mixin 都不允许依赖"时选用；此时 §1.3 的 4 处改动**全部不做**，改为：

**新增 1 个客户端 tick 处理器**（`@Mod.EventBusSubscriber(modid = RVP_MOD.MOD_ID, bus = FORGE, value = Dist.CLIENT)`，或并入 RVP 已有的客户端 tick 处理器），每 tick 幂等重算：

```java
// 伪代码：对本地操作载具的全部武器站的全部武器，凡是 RVP 且 eo_ccip 的，
// 把其所属武器站的 parentWeaponUnitAim 置为 static || (SCOPE && eo_ccip)。
boolean scope = LocalVehiclePlayer.instance.viewType == LocalVehiclePlayer.ViewType.SCOPE;
for (WeaponUnit unit : 本地载具全部武器站) {
    // 原始静态值从数据层取，天然幂等，无需自己记账
    boolean staticValue = unit.getData().isParentWeaponUnitAim();
    boolean wantsScopeFollow = scope && unitHasEo_ccipWeapon(unit);
    unit.setParentWeaponUnitAim(staticValue || wantsScopeFollow);
}
```

用的全是公共 API：`AbstractVehicle.getPartUnits()`、`WeaponUnit.getIndexedWeapons()`、`WeaponUnit.getData().isParentWeaponUnitAim()`、`AbstractVehicleWeapon.getWeaponUnit()`、公开 setter `WeaponUnit.setParentWeaponUnitAim(boolean)`（`ywzj_vehicle/.../WeaponUnit.java:1223`，本体自带车 `Z10.java:95` 即此用法）。该字段已核实**无网络同步、无序列化**，客户端本地改写安全。

**代价（必须知情）**：

1. 该 flag 是**站级**、非武器级：同站换到非 `eo_ccip` 武器时必须靠每 tick 重算回退，漏 tick 会残留状态。
2. 该 flag 是**客户端全局字段**：客户端上**所有**读 `isParentWeaponUnitAim()` 的地方都会跟着变——比方案 A 只影响 2 个调用点**面更大**（含 `RVP_ClientSaclosState:151` 等）。
3. 属"运行时状态注入"，后续若有人改 tick 顺序/站点归属，容易再次错位。

**两方案取舍**：

| | 新增 Mixin | 依赖既有 Mixin | 作用面 | 状态注入 |
|---|---|---|---|---|
| **A（推荐）** | 0 | 是（既有，不改动） | 只影响准心/弹着点锚定 2 处 | 无 |
| C | 0 | 否 | 客户端全部读该 flag 处 | 有 |

# 2. 任务 B：多弹种槽 `selectedIndex` 越界防护

## 2.1 事故（2026-10-12，已复现）

配了多弹种槽（`ids` + `save_id` + `modding_only_multi`）的载具，**缩短 `ids` 条数**后，旧存档进世界**秒崩**：

```
java.lang.IndexOutOfBoundsException: Index 2 out of bounds for length 2
  at org.ywzj.vehicle.vehicle.weapon.VehicleMultiWeapons.getSelectedWeapon(VehicleMultiWeapons.java:44)
  at org.ywzj.rvp.util.RVP_WeaponResolveHelper.unwrap(RVP_WeaponResolveHelper.java:22)
  at org.ywzj.rvp.weapon.core.RVP_WeaponSwitchSyncHelper.hasResolvedSeeker(:152) → syncSeekerOn(:137) → tick(:86)
  at org.ywzj.rvp.weapon.core.RVP_WeaponBase.tick(:531)
  at org.ywzj.vehicle.vehicle.part.WeaponUnit.tick(:450)   // 服务端载具 tick
```

## 2.2 根因

本体 `VehicleMultiWeapons`：

- `selectedIndex` **存进载具 NBT**（`serializeNBT/deserializeNBT` 的 `SelectedIndex`，**无夹取**）；
- `getSelectedWeapon()` = `subWeapons.get(selectedIndex)`，**无边界检查**。

⇒ 缩短 `ids` ⇒ 旧存档中的 `SelectedIndex` 超出新列表长度 ⇒ 载入即越界；且 `RVP_WeaponBase.tick` 每 tick 都走 `unwrap → getSelectedWeapon` ⇒ **每 tick 抛异常 ⇒ 进世界即崩**（不可自救）。

**临时规避（已落地）**：给该槽换 `save_id`（本次 `missile_r`→`missile_r2`、`missile_l`→`missile_l2`）。代价：该槽选中项/子武器弹药重置；`save_id` 同时是改装界面分栏标题。

## 2.3 改动清单（新增 1 个文件）

新增 `src/main/java/org/ywzj/rvp/vehicle/RVP_MultiWeaponsIndexClampHandler.java`（包名可按实际调整，但要落在 RVP 自己的包下）：

```java
package org.ywzj.rvp.vehicle;

import net.minecraftforge.event.entity.EntityJoinLevelEvent;
import net.minecraftforge.eventbus.api.SubscribeEvent;
import net.minecraftforge.fml.common.Mod;
import org.ywzj.rvp.RVP_MOD;
import org.ywzj.vehicle.entity.vehicle.AbstractVehicle;
import org.ywzj.vehicle.vehicle.part.PartUnit;
import org.ywzj.vehicle.vehicle.part.WeaponUnit;
import org.ywzj.vehicle.vehicle.weapon.AbstractVehicleWeapon;
import org.ywzj.vehicle.vehicle.weapon.VehicleMultiWeapons;

/**
 * 多弹种槽选中索引越界防护（2026-10-12 崩服事故后订立）。
 *
 * <p>背景：本体 {@code VehicleMultiWeapons} 把 {@code selectedIndex} 存入载具 NBT 且
 * {@code deserializeNBT} 不夹取，而 {@code getSelectedWeapon()} 直接
 * {@code subWeapons.get(selectedIndex)} 无边界检查。一旦缩短某槽的 {@code ids} 条数，
 * 旧存档里的 {@code SelectedIndex} 就会越界；RVP 侧 {@code RVP_WeaponBase.tick}
 * 每 tick 都会经 {@code RVP_WeaponResolveHelper.unwrap} 读到它，导致服务端载具 tick
 * 每 tick 抛 {@code IndexOutOfBoundsException}，**进世界即崩**。</p>
 *
 * <p>处理：载具加入世界（反序列化后、首次 tick 前）时，把越界的
 * {@code selectedIndex} 夹回 {@code [0, subWeapons.size()-1]}。全部使用本体公开 API
 * （{@code AbstractVehicle.getPartUnits()} / {@code WeaponUnit.getIndexedWeapons()} /
 * {@code VehicleMultiWeapons.getSubWeapons/getSelectedIndex/setSelectedIndex}），
 * 不新增 Mixin、不改本体源码。</p>
 */
@Mod.EventBusSubscriber(modid = RVP_MOD.MOD_ID, bus = Mod.EventBusSubscriber.Bus.FORGE)
public class RVP_MultiWeaponsIndexClampHandler {

    private RVP_MultiWeaponsIndexClampHandler() {}

    @SubscribeEvent
    public static void onEntityJoinLevel(EntityJoinLevelEvent event) {
        // 目的：仅服务端执行（服务端权威，夹取结果随后经同步下发客户端），与既有
        // RVP_EcmActiveEventHandler / RVP_CountermeasureEventHandler 的端判定保持一致。
        if (event.getLevel().isClientSide()) {
            return;
        }
        if (!(event.getEntity() instanceof AbstractVehicle vehicle)) {
            return;
        }
        clampMultiWeaponsIndex(vehicle);
    }

    /**
     * 遍历载具全部武器站，把多弹种槽越界的选中索引夹回合法范围。
     *
     * @param vehicle 已从存档载入的载具实体
     */
    private static void clampMultiWeaponsIndex(AbstractVehicle vehicle) {
        for (PartUnit<?> part : vehicle.getPartUnits()) {          // 调用本体公开 API，遍历部件
            if (!(part instanceof WeaponUnit unit)) {
                continue;
            }
            for (AbstractVehicleWeapon<?> weapon : unit.getIndexedWeapons()) {   // 调用本体公开 API，遍历该站全部武器
                if (!(weapon instanceof VehicleMultiWeapons multi)) {
                    continue;
                }
                int size = multi.getSubWeapons().size();
                if (size <= 0) {
                    continue;
                }
                int index = multi.getSelectedIndex();
                int clamped = Math.max(0, Math.min(size - 1, index));
                if (clamped != index) {
                    // 调用本体公开 setter，把越界索引夹回合法值，避免 getSelectedWeapon 抛异常。
                    multi.setSelectedIndex(clamped);
                }
            }
        }
    }
}
```

要点：
- 时机：`EntityJoinLevelEvent` 在实体反序列化之后、首次 tick 之前 ⇒ 早于任何 `getSelectedWeapon()` 调用。
- 幂等：合法索引时不做任何写入。
- 客户端由服务端同步覆盖，无需单独处理。

## 2.4 数据侧纪律（零代码，长期有效）

1. **缩短**任何多弹种槽的 `ids` 条数 ⇒ **必须同时改该条目的 `save_id`**（加后缀即可）。
2. **扩容**（增加条目）**安全**，不会越界，但也可能让已存索引指向不同弹种，必要时一并换 `save_id`。
3. 本防护只是兜底：即使有了它，也不要在载具包发布版上随意缩减 `ids`。
