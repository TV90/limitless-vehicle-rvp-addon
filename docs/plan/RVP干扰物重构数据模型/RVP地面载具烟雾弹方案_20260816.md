# RVP 地面载具烟雾弹方案

> 阶段：方案稿。为 RVP 地面载具设计第三套干扰物子系统「烟雾弹 SMOKE」，
> 与热焰弹（FLARE）/箔条（CHAFF）同为**载具状态（Vehicle State）**实现，复用现有
> `RVP_CountermeasureRuntimeManager` 状态机、C2S 触发、HUD 同步链路。
> 文档时间：2026-08-16

## 0. 本体烟雾弹调研（ywzj_vehicle）

本体的烟雾弹是**武器**（不是载具状态机），整套链路如下：

| 环节 | 实现 |
| --- | --- |
| 触发 | 按键 `SMOKE_GRENADE_LAUNCH`（默认 H）→ `InputHandler` → 发射对应武器 |
| 武器 | `VehicleGrenade`（`VehicleGrenadeWeaponData`，`"grenade": "smoke"`）挂在 `WeaponUnit` 上（例：`Ztz99a` 的 `smoke_grenade` 发射装置，`FiringMode.RIPPLE`，多 bolt 齐射） |
| 弹体 | `SmokeGrenadeEntity extends GrenadeEntity implements SightObstruction`：弹跳榴弹，落地（首次撞块）置 `EXPLODED=true` → `makeBoundingBox()` 返回 **10×10×10** 大 AABB；`life` tick 后 `discard()` |
| 客户端 | 每 tick 在半球内撒 48 个 `SmokeCloudOption` 灰烟粒子 |
| 遮蔽机制 | 实现空标记接口 `org.ywzj.vehicle.api.entity.SightObstruction` + 10³ 大碰撞箱。本体导引头在弹目射线上做实体命中检测，命中 `SightObstruction` 即判定目标被遮挡：`Infrared.checkTarget` / `ElectroOptical.checkTarget·findTarget` / 飞行中 `MissileEntity`（IR/EO 段 `VectorUtil.hitEntity` 命中 `SightObstruction` → `targetEntity = null`） |
| 对雷达 | 不生效：雷达走 `TargetObstruction` 接口（烟雾未实现），烟雾不影响雷达锁定 |

**对 RVP 侧的启示**：
- 烟雾对抗光学制导的机制就是「**实现 `SightObstruction` + 大 AABB**」，本体与 RVP 共用同一判定——
  RVP `RVP_CountermeasureState.hasSightObstruction`（光学制导路径）同样识别 `SightObstruction`。
- RVP 地面载具若直接配本体 `smoke_grenade` 武器，**无需任何新检测代码**即可遮蔽 RVP 光学制导
  （SALH/LH/LBR/SACLOS/HITL_TV/IR/AIR）。但那是"武器"维度（占用武器位、装填走本体弹药），
  不满足"类似热诱/箔条的载具状态机"诉求——故本方案仍做成第三套 `countermeasure.smoke` 子系统，
  生成 RVP 自己的 `RVP_SmokeEntity`（同样实现 `SightObstruction` + 可配置半径大 AABB）。

  只是实现空标记接口，不碰本体字节码。
- 干扰物实体 / 状态机 / 数据模型纯逻辑，可 JUnit 单测（对齐 `RVP_CountermeasureStateMachineTest`）。

## 1. 背景与目标

当前干扰物体系（`countermeasure` 块，仅固定翼/直升机配置）：

| 干扰物 | 对应制导 | 机制 |
| --- | --- | --- |
| 热焰弹 FLARE | IR、AIR | 导引头视场内计数超 `seekerJamLimit` → 脱锁转锁诱饵 |
| 箔条 CHAFF | SARH、ARH | 同上 + 雷达锁定目标周围箔条超阈值 → 脱锁 + 禁锁 |

**缺口**：RVP 地面载具（t90m / abramsx / m1a2sep / bmpt72 / 96l6）无任何干扰手段，
而它们的主要威胁——**光学制导**（SALH 激光半主动、LH/LBR 激光驾束、SACLOS 线导、
HITL_TV 人在环电视、TV）——目前完全没有被动对抗手段。

目标：为地面载具新增第三套干扰物「烟雾弹 SMOKE」，通过**遮蔽弹目光学视线**来对抗光学制导，
按与 flare/chaff 相同的"载具状态"机制落地（各自独立弹药、独立状态机、bone_modules 失效联动）。

## 2. 现状复用点

- 载具侧状态机：`RVP_CountermeasureRuntimeManager.VehicleCountermeasureState`（flare / chaff 两套）
  + `RVP_CountermeasureStateMachine`（total / per_round / burst_rounds / launch_interval / reload）。
- 数据模型：`RVP_CountermeasureData`（flare / chaff 子系统）→ `RVP_CountermeasureSystemData`
  （launcher_parts / total / perRound / burstRounds / launchIntervalTick / reloadTick / bone_modules）。
- C2S 触发：`RVP_ClientEvents` 按键 → `RVP_CountermeasureRuntimeManager.fire(player, vehicle, type)`，
  类型即 `RVP_EnumCountermeasureType`，**天然支持新增枚举**。
- 光学视线遮蔽：`RVP_CountermeasureState.hasSightObstruction(seeker, target)` 对
  `usesOpticalLineOfSight` 类型（IR/AIR/LH/SALH/SACLOS/HITL_TV/LBR）生效，
  判据含 `entity instanceof SightObstruction`——**烟雾实体实现空标记接口
  `org.ywzj.vehicle.api.entity.SightObstruction` 即可接入**，无需改武器侧检测主链。
- 干扰物实体底线（复用于烟雾）：不触发近炸、不与弹药碰撞、可被 `RVP_Decoy` 类型化。

## 3. 设计

### 3.1 类型与数据模型

- `RVP_EnumCountermeasureType` 新增 `SMOKE`。
- `RVP_CountermeasureData` 新增 `smoke` 子系统（复用 `RVP_CountermeasureSystemData`：
  launcher_parts / total / per_round / burst_rounds / launch_interval_tick / reload_tick / bone_modules）。
- 新增 `RVP_CountermeasureSmokeData`（`decoy` 同级子对象 `smoke`）：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `lifetime_tick` | int | 100 | 烟雾云存活 tick（有效遮蔽窗口，建议 ≥ 热焰弹） |
| `radius` | float | 10.0 | 烟雾云最终半径（格），随时间从 0 膨胀到该值 |
| `rise_speed` | float | 0.03 | 烟雾上升速度（格/tick），`gravity` 为负的语义更直观 |
| `opacity` | float | 0.0~1.0 | 遮蔽强度（预留，后续可做分级遮蔽 / 视线衰减） |
| `drift` | float | 0.0 | 风/随机飘移幅度（格/tick，预留）（漂移只影响视觉效果，不影响实际干扰范围） |

复用 `RVP_CountermeasureDecoyData` 的 `glow_color` / `halo_scale` 作为烟雾云外观参数
（灰色系，halo_scale 大值表示大云团）。

### 3.2 烟雾实体

新增 `RVP_SmokeEntity`（implements `RVP_Decoy` + `SightObstruction`），双端安全：

- **服务端**：生成于发射装置出膛点；`radius` 随时间膨胀（AABB 同步增长）；`rise_speed` 缓慢上浮；
  `lifetime_tick` 到期 `discard()`；不参与碰撞 / 近炸 / 雷达扫描（`rvp$decoyType() == SMOKE`，
  雷达扫描过滤规则沿 `RVP_RadarScanHelper`：SMOKE 与 FLARE 同样不可被雷达扫描）。
- **雷达规则（已定）**：烟雾**不可被雷达扫描**，也**不影响**烟雾内目标被雷达/雷达弹扫描和锁定
  ——ARH/SARH 全程不受烟雾干扰（雷达弹有箔条体系）。
- **客户端**：渲染大范围半透明灰色烟云（多片叠加 billboard / `AreaEffectCloud` 风格 + 灰烟粒子），
  不逐 tick 同步（外观数据经 `SynchedEntityData` 随生成包同步）。
- **遮蔽判定**：因实现 `SightObstruction`，`hasSightObstruction` 会把它当作弹目视线阻挡物。
  需把现有 `entity.distanceTo(target) < 12.0`（中心距）改为 **AABB 相交**判定——
  烟雾是大体积云，中心可能距目标 >12 但云体已罩住目标/视线。

### 3.3 检测集成（烟雾克制哪些制导）

| 干扰物 | 制导武器侧 | 机制 |
| --- | --- | --- |
| 热焰弹 FLARE | IR、AIR | 视场内计数脱锁 |
| 箔条 CHAFF | SARH、ARH | 视场内计数脱锁 + 雷达脱锁/禁锁 |
| 烟雾 SMOKE | **IR、AIR** 及光学制导（SALH/LH/LBR/SACLOS/HITL_TV/TV） | ①**载具处于烟雾 OBB 内 → 脱锁进惯导**；②烟雾云 `SightObstruction` 遮蔽弹目光学视线 |

**机制①（载具处于烟雾 OBB 内）——IR/AIR 直接进惯导，沿用本体"大 AABB 罩住目标"的思路**：
- `RVP_SmokeEntity` 的 AABB 随时间膨胀到 `radius`，成为一块**禁视区**。
- 目标载具（导弹当前锁定目标）若其中心点处于任一存活烟雾云的 AABB 内，`query` 对该目标返回
  `lockBlocked + jammedInFlight`（拒绝锁定/跟踪）→ `validateEntity` 返回 null → 导弹失去目标
  → 进入**惯导**（`inertialOrFailed`），导引头按 `seekerShutOffTime` 关闭、之后才重新索敌。
- 判定实现（`RVP_CountermeasureState` 新增，O(小范围)）：

```java
/** 目标是否处于任一存活烟雾云的 AABB（禁视区）内（按目标中心点判定）。 */
private static boolean isTargetInsideSmoke(Entity target) {
    if (target == null) {
        return false;
    }
    Vec3 center = target.getBoundingBox().getCenter();
    return target.level().getEntities(target, target.getBoundingBox().inflate(1.0),
                    e -> e instanceof RVP_SmokeEntity && e.isAlive())
            .stream().anyMatch(e -> e.getBoundingBox().contains(center));
}
```

**机制②（弹目光学视线遮蔽，本体同款）**：`RVP_SmokeEntity` 实现 `SightObstruction`，
`hasSightObstruction` 会把它当视线阻挡物。改动集中在 `RVP_CountermeasureState.hasSightObstruction`：
- 现有 `new AABB(seeker, target).inflate(2.0)` 走廊过窄，烟雾需更宽的相交判据；
- 改 `entity.getBoundingBox().inflate(2).intersects(losBox)`（对点状 `SightObstruction` 与云状烟雾都成立）；
- `queryPoint` 同改。

### 3.3.1 逐制导克制设计（已定稿）

> 烟雾云 = 一块 `radius` 半径的禁视区（AABB）。各制导对其反应如下（首版范围，ARH/SARH 不受影响）：

| 制导 | 判定（按导弹状态/位置） | 行为 |
| --- | --- | --- |
| **IR / AIR** | 目标（载具）中心在烟雾 OBB 内 | 直接**进惯导**（丢失目标，导引头按 `seekerShutOffTime` 关闭后重搜） |
| **SACLOS** | ①导弹自身进入烟雾 OBB；②导弹与发射载具连线被烟雾穿过 | 无法制导；持续到导弹脱离烟雾 / 弹射连线不再穿烟 |
| **SALH / LH** | 目标在烟雾 OBB 内 | **激光点无法在烟雾内生成** → 导弹失去激光点 → 进惯导盲飞 |
| **LBR** | 导弹自身进入烟雾 OBB | 无法制导，直到导弹脱离烟雾；弹射连线穿烟**不影响**（驾束制导，连线穿烟仍可） |
| **人在回路·指令线 HITL** | 导弹进入烟雾 OBB，且信号源为**无线电** | 无法制导，直到导弹脱离烟雾；信号源为**光纤** → 烟雾内仍可制导 |
| **人在回路·电视 HITL_TV** | 锁定目标在烟雾中（或后续对烟雾覆盖区尝试锁定） | 强制把锁定点改为**烟雾中心半径 5 格内的随机点**（无论最初锁的是实体还是方块，持续到目标脱离烟雾 / 命中判定） |

- 判定时机：对在飞导弹，由 `RVP_CountermeasureState.query` / `queryPoint`（弹体侧）与
  SACLOS/HITL 指令链路的制导源（`RVP_GuidanceController` 相关）按各自"判定点"检查
  `isTargetInsideSmoke` 或"弹目/弹射连线穿烟"。
- 连线穿烟判定：对弹射两点连线，用 `RVP_SmokeEntity` 的 AABB 与线段相交检测
  （逐段 `AABB` 与线段最近距离，或对连线做分段 `getEntities` 采样）。
- 共同原则：**ARH/SARH 完全不受烟雾影响**（雷达弹仍可扫描/锁定烟雾内目标）。

### 3.4 "基于载具状态" 的含义（大白话）

一句话：**烟雾弹是"焊死在车上的自带功能"，不是"装在武器架上的武器"**。它和热焰弹/箔条是一类东西，
只是车载第三套。

| 维度 | 武器 | 载具状态（干扰物） |
| --- | --- | --- |
| 占用 | 占武器站 + 弹药位 | **不占**：`launcher_parts` 只借用那几个部件当"出膛点 + 发射动画锚点"，不是装炮 |
| 弹药 | 武器自己的弹药池 | 车自己的独立弹仓（剩余/装填挂在车 UUID 下，与热焰弹/箔条互不共享） |
| 触发 | 火控瞄准 + 开火键 | 专属热键（H），不经过火控/准星 |
| 显示 | 武器 HUD | 干扰物 HUD 第三行（剩余/装填进度） |
| 生效前提 | 有弹药、可射击 | 车有电、没被摧毁；配了 `bone_modules` 则对应骨块模块全被打坏 → 该系统失效（像 APS 被打掉就没了一样） |
| 数据 | `weapon_data` / `fire_data` | `countermeasure` 顶层块自己的模型，武器模型完全不管它 |

具体落地（与 flare/chaff 完全对齐）：
- `RVP_CountermeasureRuntimeManager.VehicleCountermeasureState` 增 `smoke` 字段（一台车一套独立状态）。
- `RVP_CountermeasureData` 增 `smoke` 子系统；`ensureState` / `tickSystem` / `spawnOne` 增 SMOKE 分支
  （生成 `RVP_SmokeEntity` 而非 `RVP_DecoyEntity`）。
- 键/联动/持久化全部复用现有链路（`RVP_CountermeasureStateSavedData` 持久化剩余/装填）。

可选扩展（预留，不在首版强制）：
- **运动态烟雾**：载具移动时，已布烟雾留在原地形成拖尾烟幕（现行烟雾实体即原地滞留，天然满足）；
- **状态门控**：可要求载具引擎开启 / 特定骨块展开（复用 `isSystemActive` + `bone_modules`）才能抛洒。

### 3.6 烟雾弹状态机（大白话）

每台车自己的"烟雾弹弹仓"，和热焰弹/箔条完全同款的三段状态：**待机 → 齐射 → 装填**。

**台账（每台车记这几个数）**
| 名字 | 是什么 |
| --- | --- |
| 剩余 | 弹仓里还剩几发 |
| 齐射中? | 是不是正在一轮一轮地往外打 |
| 剩几轮 | 这轮齐射还没打完的轮数 |
| 轮间隔计时 | 距下一轮还有几 tick（防止一轮全打出去，错峰成烟墙） |
| 装填中? | 是不是在慢慢装弹 |
| 装填进度 | 装到几 tick 了 |

**按一下烟雾键**
- 正在齐射？正在装弹？弹仓空了？→ 忽略，不理会。
- 否则开打：`齐射中 = 开`；`剩几轮 = 一次按键最多能打的轮数`（但弹不够就只算够打几轮）。

**每 tick 走一遍（服务端）**
- 装填中：进度 +1；加满 → 剩余=总弹量，装填结束，回到待机。
- 齐射中：轮间隔计时 -1，没到 0 就等；到 0 → 打一轮（每轮打"一轮发数"发，不够就打剩下的），
  剩余减掉打掉的；`剩几轮 -1`。轮子打完了：
  - 若剩余变成 0 → 开始装填（慢慢回满）；
  - 否则回到待机，等你再按键。

**打出来的烟雾弹去哪了**
- 每发在发射装置出膛点生成一团 `RVP_SmokeEntity` 云：半径随时间涨到配置值、缓缓上浮、
  到 `lifetime_tick` 就消散。
- 云团实现 `SightObstruction`，且 AABB 就是"禁视区"。

**烟雾云怎么让导弹吃瘪**
- **躲进云里**：目标载具中心落在任一存活云团的 AABB 内 → IR/AIR（及光学制导）导弹 `query`
  判它被遮蔽 → 拒绝跟踪 → 导弹丢目标 → **进入惯导**（按原方向惯性飞，导引头关一会儿再重启）。
- **被云挡住视线**：烟雾在导弹和目标之间（射线穿过云团）→ 同样判被遮蔽（激光/TV 制导主要靠这个）。

**供电/被打坏**
- 车没电 / 车被摧毁 → 不能抛洒。
- 配了 `bone_modules`：对应骨块的 COUNTERMEASURE 模块全被打坏 → 该子系统失效（和热焰弹/箔条一致）。

### 3.5 按键与 HUD

- `RVP_Keys` 新增 `FIRE_SMOKE`，**默认 `GLFW_KEY_H`**（与本体 `SMOKE_GRENADE_LAUNCH` 一致）；
  与热焰弹（H）/箔条（Left Alt）不冲突——地面载具不配热焰弹/箔条，同一 H 键各车各用。
- `RVP_ClientEvents` 按键循环 `RVP_CountermeasureRuntimeManager.fire(player, vehicle, SMOKE)`。
- `RVP_CountermeasureHudOverlay` + `S2CCountermeasureHudSync` 增加第三行烟雾弹药/装填进度。

## 6. 烟雾系统参数一览（全部参数）

> 三层：**系统级**（复用 `RVP_CountermeasureSystemData`，与热焰弹/箔条同款）→ **烟雾云级**
> （新增 `RVP_CountermeasureSmokeData`，`smoke` 子对象）→ **外观级**（复用 `RVP_CountermeasureDecoyData`，`decoy` 子对象）。

### 6.1 系统级（JSON 键与热焰弹/箔条同款）

| 参数 | JSON 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 类型 | `type` | string | 由键决定 | `SMOKE`（大小写不敏感） |
| 发射装置 | `launcher_parts` | string[] | 必填 | 借用的本体 WeaponUnit 部件，仅作出膛点 + 发射动画锚点 |
| 弹舱容量 | `total` | int | 4 | 烟雾弹总数，0=禁用该系统 |
| 一轮发射数 | `per_round` | int | 2 | 每轮打几发 |
| 一次按键轮数 | `burst_rounds` | int | 2 | 一次按键最多打几轮 |
| 轮间隔 | `launch_interval_tick` | int | 4 | 轮间错峰间隔（tick） |
| 装填时间 | `reload_tick` | int | 250 | 打空后从 0 装到 `total` 的 tick |
| 骨块联动 | `bone_modules` | string[] | 空 | 对应骨块 COUNTERMEASURE 模块全被打坏 → 该系统失效 |

### 6.2 烟雾云级（`RVP_CountermeasureSmokeData`，`smoke` 子对象）

| 参数 | JSON 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 存活时长 | `lifetime_tick` | int | 100 | 弹体总存活 tick（含弹道飞行段），到点消散 |
| 云团半径 | `radius` | float | 10.0 | AABB 最终半径（格），爆炸后从 0 膨胀到该值；需显著大于导弹近炸半径 |
| 出膛初速 | `speed` | float | 1.0 | 弹道飞行初速（格/tick，沿发射装置瞄准方向，叠加载具速度） |
| 下落加速度 | `gravity` | float | 0.05 | 弹道飞行段下落加速度（格/tick²） |
| 爆炸延迟 | `explode_tick` | int | 10 | 出膛后延迟该 tick 爆炸生成烟幕 |
| 上升速度 | `rise_speed` | float | 0.03 | 爆炸后烟雾上升速度（格/tick） |
| 遮蔽强度 | `opacity` | float | 0.0~1.0 | 预留：后续分级遮蔽 / 视线衰减 |
| 飘移 | `drift` | float | 0.0 | 预留：风/随机飘移幅度（格/tick） |

## 7. 决策记录（2026-08-16 批注确认）

1. **克制范围（逐制导定稿，见 §3.3.1）**：IR/AIR 目标进烟雾 → 直接惯导；SACLOS 导弹进烟雾或弹射连线穿烟 → 无法制导；
   SALH/LH 目标在烟雾内 → 激光点无法生成 → 进惯导盲飞；LBR 导弹进烟雾 → 无法制导（弹射连线穿烟不影响）；
   人在回路指令线（无线电）进烟雾 → 无法制导（光纤仍可）；人在回路电视 → 锁定目标在烟雾中强制改为锁定
   烟雾中心半径 5 随机点（实体/方块皆然，后续对着烟雾区锁定也如此）。**ARH/SARH 不受烟雾影响。**
2. **烟雾形态**：大云实体（每发一个 `RVP_SmokeEntity`，半径膨胀），实体数少。
3. **按键**：默认 `H` 键，与本体一致；与热焰弹不冲突（地面载具不配热焰弹/箔条）。
4. **"基于载具状态"**：即"第三套载具状态机"（见 §3.4 大白话详解），不做运动态烟幕/引擎门控附加语义。
5. **雷达**：烟雾**不可被雷达扫描**，也**不影响**烟雾内目标被雷达/雷达弹扫描和锁定（ARH/SARH 全程不受烟雾干扰）。
6. **OBB 判定**：按目标**中心点** `contains` 判定。

> 改动点映射、推荐参数见 §5 / §6；检测判定点（弹体侧 / SACLOS / HITL 指令链）按 §3.3.1 落点实现。
