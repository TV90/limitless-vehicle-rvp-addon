## 1. 背景与目标

此前开发因只按客户端思路写、未考虑纯 Forge 服务端，导致服务端启动崩溃，花费大量精力修复
（`RuntimeDistCleaner` 拒绝 `@OnlyIn(CLIENT)` 类型 + 公共 mixin 改脏目标类触发帧重算）。

本次干扰物重构目标：

1. **服务端优先**：先保证纯 Forge 服务端可启动、逻辑全部走服务端安全路径；服务端兼容了，客户端一般不会有大问题。
2. **双端解耦、独立包名**：仿视觉工厂（`weapon/visual` + `server/visual` + `client/visual` + `network/visual`），
   干扰物独立成 `countermeasure` 包族，公共代码零客户端类型引用。
3. 一次性整合三块需求：**发射机制（载具状态）** + **武器干扰属性**（`RVP_InterferenceData`，IR/AIR 吃热焰弹、SARH/ARH 吃箔条） + **雷达干扰属性**（箔条计数 → 脱锁 + 短暂禁锁）。
4. 不新增公共 mixin，全部走事件 / 网络包 / 接口 / 数据层。

## 2. 教训与硬约束（服务端优先）

从 `docs/修复方向` 与 `docs/调试与修复规范.md` 提炼的纪律：

1. **公共代码禁止直接引用 `@OnlyIn(CLIENT)` 类型**（`LocalVehiclePlayer`、`Minecraft`、`ClientLevel`、
   `org.ywzj.vehicle.client.*`、`org.ywzj.rvp.client.*`）；必须经公共接口/事件/网络包，服务端 NOOP、客户端真实现。
2. **服务端会执行到的公共方法**（`tick`、事件监听、网络包 handler）**绝对禁止引用客户端类型**；
   确需客户端逻辑的方法标注 `@OnlyIn(Dist.CLIENT)` 让 dist cleaner 剥离。
3. **公共数组 mixin 目标类必须双端安全**；纯客户端行为放 `client` 数组；**本规划零新增公共 mixin**。
4. 对扩展接口一律 `instanceof`，禁止强转（mixin 缺失静默降级，不崩溃）。
5. **优先服务端兼容**：每个里程碑都跑一次纯 Forge `runServer`，`Done (Xs)!` 通过再进下一步。

## 3. 总体架构（双端解耦，仿视觉工厂）

### 3.1 包结构

```
org.ywzj.rvp.countermeasure           公共（双端安全）：数据模型 / 发射状态机 / 干扰物实体 / 状态查询
org.ywzj.rvp.countermeasure.api       公共接口（业务方只依赖接口，不依赖网络/客户端实现）
org.ywzj.rvp.countermeasure.server    服务端实现：发射执行 / 雷达箔条判定 / 持久化 / 事件发布
org.ywzj.rvp.countermeasure.client    客户端实现：渲染 / 粒子 / 声音 / HUD / 按键
org.ywzj.rvp.countermeasure.network   网络包：C2S 发射 / S2C 状态 / S2C 视觉事件
```

### 3.2 一句话设计原则（对齐视觉工厂）

> 客户端按"发射键 / 状态 / 视觉事件"三种信息驱动：按键只发一个 C2S；服务端状态机推进并**只广播一次小状态/事件**；
> 客户端本地实例负责渲染、粒子、声音、HUD。不逐 tick 同步实体、不硬编码武器 ID、不用客户端类型推断干扰物类型。

### 3.3 数据流

```
按键（客户端）
  └─ C2SFireCountermeasure（flare / chaff 分键）
        ▼
服务端 RVP_CountermeasureRuntimeManager（公共状态机驱动，服务端安全）
  ├─ 推进发射状态机（§载具侧数据模型：n 轮 × m 发、间隔、装填）
  ├─ 在 launcher_parts 的 WeaponUnit 出膛点生成 RVP_FlareDecoy / RVP_ChaffDecoy 实体
  ├─ 广播 ServerVehicleFire（发射动画，复用本体）+ S2C 状态/HUD
  └─ 持久化 RVP_CountermeasureStateSavedData
        ▼
武器侧 seeker（公共）── 经 api 查询 → 统计对应类型干扰物（IR/AIR→FLARE、SARH/ARH→CHAFF）
        ▼
雷达侧（公共 + server）── 经 api 查询 → 锁定目标周围箔条计数 → 超阈值脱锁 + 目标禁锁期
```

## 4. 各层职责

### 4.1 公共层 `org.ywzj.rvp.countermeasure`

| 类 | 职责 | 双端安全说明 |
| --- | --- | --- |
| `RVP_CountermeasureData` / `RVP_CountermeasureSystemData` / `RVP_CountermeasureDecoyData` / `RVP_EnumCountermeasureType` | 数据模型 + JSON 解析（字段见数据模型文档） | 纯数据，无 MC 客户端类型 |
| `RVP_CountermeasureStateMachine` | 发射状态机（remaining / firing / roundsLeft / roundTimer / reloading），`onKeyPress` / `onTick` 纯逻辑 | 无 MC 引用，可 JUnit 单测 |
| `RVP_FlareDecoy` / `RVP_ChaffDecoy` + `RVP_Decoy`（接口，`decoyType()`） | 干扰物实体：服务端运动（speed/drag/gravity/spread）、`lifetimeTick` 存活、类型标记 | 实体类双端安全；客户端只渲染 |
| `RVP_CountermeasureQuery` | 公共查询入口：`countDecoysNear(target, type, radius)` / `countChaffNearLockedTarget(...)`；`isTargetInChaffJamCooldown(targetId)` | 供 seeker / 雷达侧调用，纯查询 |

### 4.2 API 层 `org.ywzj.rvp.countermeasure.api`

对齐视觉工厂 `weapon/visual/api`，业务方只依赖接口：

| 接口 | 说明 |
| --- | --- |
| `RVP_CountermeasureSink` | 客户端消费端（HUD / 视觉），服务端实现为 NOOP，客户端实现真渲染 |
| `RVP_CountermeasureEventPublisher` | 服务端事件发布端口；业务方不直接依赖网络通道 |
| `RVP_CountermeasureStateView` | 只读状态视图（剩余 / 装填进度 / 禁锁期），供 HUD 与查询 |

### 4.3 服务端层 `org.ywzj.rvp.countermeasure.server`

| 类 | 职责 |
| --- | --- |
| `RVP_CountermeasureRuntimeManager` | 载具级运行时（按 vehicle UUID），处理 C2S 按键、驱动 `RVP_CountermeasureStateMachine`、生成干扰物实体、广播 `ServerVehicleFire` 与 S2C 状态；`tick` 由 ServerTickEvent 驱动 |
| `RVP_CountermeasureStateSavedData` | 载具加入/离开世界时持久化剩余与装填进度（对齐 `RVP_ApsStateSavedData`） |
| `RVP_RadarChaffJamRuntime` | 雷达箔条判定：对每台有锁定目标的雷达，统计锁定目标周围 `radarJamRadius` 内 `CHAFF` 数；≥ `radarJamCount` → 脱锁（清 `radarUnit`/`weaponUnit`/`RVP_WeaponLockStateTable`）并写目标禁锁期 |
| `RVP_NetworkCountermeasureEventPublisher` | 实现 `RVP_CountermeasureEventPublisher`，用公共通道向同维度/追踪实体广播（对齐 `RVP_NetworkVisualEventPublisher`） |

### 4.4 客户端层 `org.ywzj.rvp.countermeasure.client`

| 类 | 职责 |
| --- | --- |
| `RVP_DecoyRenderer`（`RVP_FlareDecoyRenderer` / `RVP_ChaffDecoyRenderer`） | billboard 渲染（`glowColor` 倍乘、`haloScale` 缩放、`FULL_BRIGHT`），对齐本体 `DecoyFlareEntityRenderer` |
| `RVP_DecoyClientTick` | 客户端粒子（热焰弹 FLASH + 后段浓烟 + 拖尾音；箔条灰色 `SmokeCloudOption` 云）与声音 |
| `RVP_CountermeasureHudOverlay` | 干扰物剩余 / 装填进度 HUD |
| `RVP_CountermeasureKeyHandler` | 拦截发射键（flare / chaff 分键）→ 发 `C2SFireCountermeasure` |

### 4.5 网络层 `org.ywzj.rvp.countermeasure.network`

| 包 | 说明 |
| --- | --- |
| `C2SFireCountermeasure` | 客户端 → 服务端：`(vehicleId, type)` 触发一次齐射 |
| `S2CCountermeasureHudSync` | 服务端 → 客户端：剩余 / 装填 / 禁锁状态（对齐 `S2CApsHudSync`，变化节流推送） |
| `S2CCountermeasureVisualEvent` | 服务端 → 客户端：干扰物生成视觉事件（可选；也可直接复用实体渲染，不逐 tick 同步） |

## 5. 功能清单（三块结合）

### 5.1 发射机制（载具状态）

- 载具 JSON 顶层 `countermeasure`，`flare` / `chaff` 独立状态机；分键抛洒。
- 发射逻辑：充足 n×m；不足 `ceil(R/m)` 轮耗尽、末轮不足 m；耗尽进装填；齐射/装填中按键忽略。
- 状态字段与推荐参数见数据模型文档（`total=32`、`perRound=4`、`burstRounds=8`、`interval=4`、`reload=200`）。
- 顶层 + `bone_modules` 联动：对应 `bone_modules` 全部被击毁 → 失去抛洒功能。

### 5.2 武器干扰属性（seeker 侧，对齐 `RVP_InterferenceData`）

- 跟踪期间以弹体指向为轴、`maxLockAngle * seekerFovShrinkFactor` 为 FOV、`guidanceTargetDistanceRange` 为距离
  检测对应类型干扰物；视场内干扰物 > `seekerJamLimit` → 脱锁并飞向最近对应干扰物；脱锁按 `seekerShutOffTime` 重启。
- 类型过滤：IR/AIR 只查 `FLARE`，SARH/ARH 只查 `CHAFF`（替代现有 `RVP_CountermeasureState` 无差别 `TargetObstruction` 判定）。
- 干扰物实体不触发近炸、不与弹药碰撞（`RVP_BaseBullet` 引信/命中判定忽略干扰物实体）。

### 5.3 雷达干扰属性（箔条 vs 雷达）

- 雷达只吃箔条；统计**当前锁定目标**周围 `radarJamRadius` 内 `CHAFF` 数；≥ `radarJamCount` → 脱锁；
  目标进入 `radarJamCooldownTick` 禁锁期（可被扫描、不可被选中/锁定）；禁锁期结束恢复。
- phase 相控阵与机械雷达共用同一锁定模型（`RadarUnit` / `RVP_RadarRoleHelper`），无需按雷达类型区分。
- 雷达可扫描性：`CHAFF` 实体补入雷达探测表（可被看到），`FLARE` 不补入。

### 5.4 干扰物实体（真实实体 + 外观）

- `RVP_FlareDecoy`：红光（`glowColor` 红）、大光圈（`haloScale` 1.6）、缓缓下落、FLASH + 后段浓烟 + 拖尾音。
- `RVP_ChaffDecoy`：白光（`glowColor` 白）、小光圈（`haloScale` 0.7）、低速铺开悬浮、灰色粒子云。
- 运动：`speed` 出膛 + 载具速度，`drag` 减速，`gravity` 下落，`spread` 散布，`lifetimeTick` 存活后消失。

## 6. 双端解耦要点（行为 × 端 × 机制）

| 行为 | 端 | 机制 |
| --- | --- | --- |
| 按键触发 | 客户端 | `RVP_CountermeasureKeyHandler` → `C2SFireCountermeasure` |
| 发射状态机推进 | 服务端 | `RVP_CountermeasureRuntimeManager`（ServerTickEvent）+ 公共 `RVP_CountermeasureStateMachine` |
| 干扰物实体生成/运动/存活 | 服务端（公共实体） | 实体在服务端 tick；客户端只渲染 |
| 发射动画 | 服务端 | 复用本体 `ServerVehicleFire`（借用 launcher_parts 的 WeaponUnit） |
| HUD 状态 | 服务端→客户端 | `S2CCountermeasureHudSync`（节流推送） |
| 渲染 / 粒子 / 声音 | 客户端 | `RVP_DecoyRenderer` / `RVP_DecoyClientTick`（本地实例，不逐 tick 同步） |
| 武器侧干扰检测 | 公共（服务端） | `RVP_CountermeasureQuery` 经 api 查询，seeker 源（`RVP_RuntimeIrGuidanceSource` 等）消费 |
| 雷达箔条判定 | 服务端 | `RVP_RadarChaffJamRuntime`（锁定侧扫描）+ `RVP_CountermeasureQuery` |
| 目标禁锁期 | 服务端侧表 | `RVP_WeaponLockStateTable` 扩展或独立 `RVP_ChaffJamStateTable` |
| 持久化 | 服务端 | `RVP_CountermeasureStateSavedData` |

## 7. 实施顺序（服务端优先里程碑）

> 每个里程碑结束都 `gradlew build` + 纯 Forge `runServer` 验证 `Done (Xs)!`，功能先服务端、后客户端。

| 里程碑 | 内容 | 验证 |
| --- | --- | --- |
| M0 | 公共数据模型（`RVP_CountermeasureData` 等）+ 发射状态机（纯逻辑）+ JUnit 单测 | `./gradlew test` |
| M1 | 服务端运行时：C2S 按键、状态机推进、生成干扰物实体、发射动画、持久化、雷达箔条判定（脱锁+禁锁） | 纯 Forge 服务端启动 + `rvpdebug` 命令验证状态 |
| M2 | 网络层：`C2SFireCountermeasure` / `S2CCountermeasureHudSync`；客户端按键 + HUD | 客户端按键 → 服务端发射 → HUD 显示 |
| M3 | 客户端视觉：`RVP_DecoyRenderer` + 粒子/声音（热焰弹红光大光圈、箔条白光小光圈） | 双端观察干扰物外观 |
| M4 | 武器侧 seeker 接入（IR/AIR→FLARE、SARH/ARH→CHAFF）+ 雷达可扫描性（CHAFF 入表、FLARE 不入） | 导弹被热焰弹/箔条正确干扰 |
| M5 | 双端回归 + 服务端验证 + 文档收尾 | 功能清单全过 + 服务端日志无 RuntimeDistCleaner |

## 8. 测试与验证

1. **服务端**：纯 Forge `runServer`（JDK 21 全路径）`Done (Xs)!`，`logs/latest.log` 无 RuntimeDistCleaner / mixin 错误。
2. **单测**：`RVP_CountermeasureStateMachine`（充足/不足/耗尽装填/按键忽略边界）。
3. **功能**：
   - 发射：充足恰好 n 轮；不足 `ceil(R/m)` 末轮不足 m；耗尽装填；分键抛洒。
   - 武器干扰：IR/AIR 只被热焰弹、SARH/ARH 只被箔条；干扰物不触发近炸、不与弹药碰撞。
   - 雷达干扰：锁定目标周围箔条 ≥ 阈值脱锁；禁锁期可扫描不可锁；期到恢复；phase/机械一致。
   - 外观：热焰弹红光大光圈、箔条白光小光圈。
4. **持久化**：载具重进世界后剩余/装填进度正确恢复。

## 9. 风险与降级

| 风险 | 缓解 |
| --- | --- |
| 干扰物实体数量多（一轮 n×m） | `lifetimeTick` 短、发射散布大；必要时按"假目标记录 + 客户端本地粒子"降级（不生成实体） |
| 雷达箔条判定频率开销 | 只在"有锁定目标"时统计（锁定侧），按扫描节流，非逐 tick |
| 服务端启动回归 | 每个里程碑纯 Forge `runServer` 验证；公共代码零客户端类型引用 |
| 本体 `WeaponUnit` 借用发射装置差异 | 只取 `worldCurrentBoltPosition` 与 `ServerVehicleFire`（与 APS 相同路径），失败静默降级 |
