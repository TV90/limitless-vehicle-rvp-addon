# RVP 载具告警系统方案（飞行器 vs 地面载具分支 + 激光告警）

> 阶段：方案稿（含已落地项）。目标：把锁定告警文案按**机型分支**（飞行器/地面载具），
> 并为地面载具补"红外/雷达锁定"与"激光照射"告警，配套音效。
> 文档时间：2026-08-16

## 1. 现状与已落地项

当前 `RVP_LockWarningOverlay`（血条上方红闪文案）对所有载具显示热焰弹/箔条规避提示：

| 触发 | 文案（lang） |
| --- | --- |
| IR/AIR 追踪 | `rvp.lock_warning.ir` = "战机被红外导弹锁定，按[热焰弹键]释放热焰弹规避" |
| ARH 追踪 | `rvp.lock_warning.arh` = "战机被雷达制导导弹锁定，按[箔条键]释放箔条规避" |
| 雷达锁定 | `rvp.lock_warning.radar` = "战机被雷达锁定，按[箔条键]释放箔条规避" |

触发数据源：`S2CMissileTrackAlert`（TYPE_IR/AIR/ARH → `RVP_ClientLockWarningState.irTrack/arhTrack`）、
本体 `WarningReceiver`（RADAR_LOCK）。

**已落地（2026-08-16）**：上述文案改为**飞行器专用**——`RVP_LockWarningOverlay.render`
开头增加 `isAircraft(vehicle)`（`FixedWingVehicle || RotaryWingVehicle`）判断，非飞行器直接返回。
地面载具不再显示热焰弹/箔条规避提示，改走坦克告警分支（见 §3）。

## 2. 告警系统结构（按机型分支）

### 2.0 双端解耦与服务端优先（开发纪律）

> 关联：`docs/修复方向/修复方案总结.md`（纯 Forge 服务端崩溃教训）、
> `docs/RVP视觉工厂架构/RVP visual_effect_data视觉效果开发指南.md`（双端解耦范式）。

告警系统**横跨多包**，按"服务端判定推送 / 网络传输 / 客户端呈现"三层解耦，公共代码零客户端类型：

```
服务端（判定+推送，禁止 @OnlyIn(CLIENT) 引用）
  ├─ RVP_MissileEntity.tickMissileTrackAlert / tickRwrMissileLaunchWarn  已有：发射/锁定告警
  ├─ RVP_LaserIrradiationTable（新增，guidance/saclos）                  激光照射登记+判定
  └─ 广播 S2CMissileTrackAlert / S2CLaserIrradiated（network 包，纯数据）
        ▼
network  S2CMissileTrackAlert（已有）/ S2CLaserIrradiated（新增）        纯字段，双端安全
        ▼
客户端（仅 client 包，@OnlyIn(CLIENT) 安全）
  ├─ client/state/RVP_ClientLockWarningState       提示状态（ir/arh/laser 窗口）
  ├─ client/state/RVP_ClientMissileTrackAlert      IR/AIR 告警音（VehicleSound 本地播放）
  ├─ client/state/RVP_ClientLaserIrradiatedHandler 激光告警音循环（laser_alert.ogg）
  └─ client/gui/RVP_LockWarningOverlay             文案渲染（按机型分支）
```

- 服务端判定只写"谁被照射/锁定 + 类型"，不引用任何客户端类型；
- 客户端只负责呈现（声音/HUD），不推导威胁逻辑；
- 新网络包沿用 RVP 频道（`RVP_Network.CHANNEL`），同 `S2CMissileTrackAlert`；
- 零新增公共 mixin；每个里程碑先跑 `runServer` 验证。

### 2.1 按机型分支

```
RVP_LockWarningOverlay.render
   ├─ isAircraft? ──▶ 飞行器分支：IR/AIR→按[热焰弹]；ARH/雷达→按[箔条]（现有文案）
   └─ 地面载具分支（新）：IR/AIR→按[烟雾弹]；雷达/ARH→按[ECM]（预留文案）；激光→按[烟雾弹]（§4）
```

触发状态共用：IR 锁定（`S2CMissileTrackAlert` TYPE_IR/AIR）、雷达锁定（ARH 追踪 / 本体 RADAR_LOCK）、
激光照射（§4 新增）。仅**文案与按键**按机型区分。

## 4. 激光告警（新增）

### 4.1 触发条件

当满足任一条件时，被照射载具收到激光告警：

1. **激光点距载具 ≤ 7 米**：存在一个活跃激光照射，其激光点位置与载具距离 ≤ 7。
2. **载具 AABB 处于激光点与发射者的连线上**：载具碰撞箱与"激光点→发射者"线段相交。

### 4.2 判定与数据源

现状：激光点按弹体即时解析（`RVP_SaclosDesignation.resolveDesignationPoint(projectile)`），
无全局"活跃激光点"表。为此需新增**服务端激光照射登记**：

- 新增服务端 `RVP_LaserIrradiationTable`（或并入 SACLOS 会话）：记录
  `发射者UUID → (激光点位置, 最近刷新 tick)`，当玩家用激光指示吊舱（`TOGGLE_LASER_DESIGNATION`）
  照射时写入 / 每 tick 刷新 / 停照超时清除。
- 服务端周期性对每台载具判定 §4.1（激光点 7m 近距 / AABB 与"激光点→发射者"线段相交），
  命中则向该载具发送 `S2CLaserIrradiated` 包（含发射者 id、激光点）。
- 客户端收到后：
  - **循环播放** `laser_alert.ogg`（`RVP_Sounds.LASER_ALERT`，ogg 已存在于
    `assets/ywzj_rvp/sounds/misc/laser_alert.ogg`，仅需注册 SoundEvent）；
  - 写 `RVP_ClientLockWarningState.laserTrackAt`，驱动文案显示；照射停止（包停发）后窗口过期自然停止。

### 4.3 文案

| 机型 | 文案（建议 lang 键） |
| --- | --- |
| 地面载具 | `rvp.lock_warning.tank.laser` = "载具周围有激光照射，按[烟雾弹按键]释放热能烟雾" |
| 飞行器 | `rvp.lock_warning.laser` = "载具周围有激光照射，请注意机动规避" |

优先级：激光告警与导弹锁定告警可同时显示（各自一行）；如挤压可设优先级（导弹锁定 > 激光）。

## 8. 待确认项

1. **激光点数据源**：建议新增服务端 `RVP_LaserIrradiationTable`（从 SACLOS 激光会话登记）。
   是否直接复用 `RVP_SaclosOperatorSession` 的既有激光会话（若其已含全局发射者→激光点表）？
2. **激光告警循环时长**：照射持续期间循环播放；停止后窗口（建议 1.5s）内收尾。
3. **ECM 文案触发**：雷达锁定（ARH/雷达）对坦克显示 ECM 文案——但 ECM 未做，是否"显示但无实际效果"（提示会误导），
   还是"先不显示雷达文案、只留 IR/激光"？（用户原话：预留，先只配文案以后用。）
4. **文案与按键联动**：坦克 IR/激光文案引用的 `FIRE_SMOKE` 键，随烟雾系统一起落地。
5. **激光判定节流**：服务端每 tick 对全载具判定是否过重？建议按 5~10 tick 节流 + 事件驱动。
