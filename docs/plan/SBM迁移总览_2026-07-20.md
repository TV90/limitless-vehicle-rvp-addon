# SBM迁移总览（2026-07-20）

## 本次先收口的子目标

本次优先完成的不是“把底层 `simplebedrockmodel` 全部复制进 `RVP`”，而是先完成下面这个更现实、也更关键的子目标：

- `RVP` 自己接管车辆渲染入口
- `RVP` 自己接管 `custom mount` / 可变挂架渲染
- `RVP` 自己接管 `special bone` 渲染
- 不再依赖旧的 `SBM render mixin` 托底

也就是：

- 车辆主渲染链由 `RVP_VehicleRender` 接管
- `custom mount` 主链由 `RVP_CustomMountRenderLogic` 接管
- `special bone` / `cockpit transparent` 主链由 `RVP_VehicleBedrockModel` + `RVP_RenderTypes` 接管

## 当前仍然不是“底层 SBM 全迁完”的部分

上面这个子目标完成，不等于底层 `SBM` 已经整体迁完。

下面这些仍然属于后续更深层的迁移内容：

### 1. 资源与数据加载入口仍借用了本体资产系统

当前 `RVP` 仍通过 `ClientAssetsManager` 读取：

- model
- animation
- display

这意味着：

- `RVP` 现在已经拥有自己的 display type / renderer / backend 分流
- 但资源装载容器本身还不是一套完全独立的 `RVP SBM`

### 2. Bedrock 基础类仍然直接复用现有 SBM

当前仍直接依赖的底层类包括但不限于：

- `BedrockModelPOJO`
- `BedrockAnimation`
- `BedrockBone`
- `BedrockModel`

也就是说：

- 当前是“上层渲染接管”
- 不是“底层 Bedrock runtime 全部重写”

### 3. 结构数据扩展仍有本体数据入口耦合

当前还存在这类耦合点：

- [VehicleDataManagerMixin.java](D:/ywzj/ywzj/ywzj_rvp/src/main/java/org/ywzj/rvp/mixin/VehicleDataManagerMixin.java)
  - 负责把 `custom_mounts` 读进 `RVP_CustomMountConfigCache`
- [WeaponUnitDataMixin.java](D:/ywzj/ywzj/ywzj_rvp/src/main/java/org/ywzj/rvp/mixin/WeaponUnitDataMixin.java)
  - 负责发射点 / 结构额外 bolt 扩展

这两块不再属于“老的 `SBM render mixin` 托底”，但它们确实还不是完全独立的数据系统。

## 完整底层迁移的后续阶段

如果以后继续做“把底层 `SBM` 尽量迁到 `RVP`”的大目标，建议按下面顺序推进。

### 阶段 1：资源链独立化

目标：

- 让 `RVP` 有更明确的资源装载入口
- 尽量少依赖本体 `ClientAssetsManager` 的隐式行为

重点：

- display 装载
- model / animation 装载
- custom mount attachment display 查询链收敛

### 阶段 2：结构扩展入口独立化

目标：

- 逐步减少 `VehicleDataManagerMixin` / `WeaponUnitDataMixin` 这种数据入口耦合

重点：

- `custom_mounts`
- 额外 `bolt`
- 挂架 / 发射架结构扩展

### 阶段 3：Bedrock runtime 深层独立化

目标：

- 把 `RVP` 需要的 Bedrock runtime 逐步内聚成自己的实现层

重点：

- model runtime
- animation runtime
- render type / transparent / depth fix
- special bone effect runtime

### 阶段 4：彻底形成 `simplebedrockmodel_rvp` 内核

目标：

- 形成对外不暴露、仅供 `RVP` 内部使用的渲染内核
- 与本体内置 SBM 并存，但不再共享太多关键实现
