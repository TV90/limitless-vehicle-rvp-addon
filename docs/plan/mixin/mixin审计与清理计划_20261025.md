## 1. 总览

- mixin 总数 **81**，目标类 **51** 种，合计 **6136** 行
- 命中最多：`WeaponUnit` 14 个、`VehicleRender` 5 个、`LocalVehiclePlayer` 4 个、`InputHandler` 3 个
- 分类：**A 类（可换公共 API）6 个** / **B 类（可迁入 RVP 自维护）25 个** / **C 类（建议长期保留）50 个**

| 类 | 定义 | 处理方式 |
|---|---|---|
| **A** | 目标行为在 Forge 事件/数据重载/输入事件/声音事件里有等价入口，Mixin 只是挂钩子 | 换事件监听后直接删，**零渲染改动** |
| **B** | 改本体已有绘制/算法/数据字段，但 RVP 能接管该职责 | 先迁到 RVP（自绘 HUD / 自有数据类 / 自有火控），再用 `RenderGuiOverlayEvent.Pre` 按 id 取消本体 HUD |
| **C** | MC 原版或第三方库内部、本体私有局部变量、一次性小改且无替代入口 | 保留，本体升版时复核 |

## 6. 单条清理 SOP

1. 读 mixin 全文，确认注入点、`@Shadow` 依赖、是否与同目标其它 mixin 有先后耦合。
2. 在 RVP 侧实现替代逻辑（事件监听 / 自绘 / 自有数据类 / 自有火控）。
3. 删除 mixin 文件：移到 `_recycle_bin/<时间戳>_mixin_cleanup/`，在 `_recycle_bin/MOVE_LOG.md` 记一行（**逻辑删除，不真删**）。
4. 从 `ywzj_rvp.mixins.json` 的 `mixins` 或 `client` 数组移除条目，保持合法 JSON。
5. `./gradlew compileJava --offline --project-cache-dir=build/_gpc_tmp` 编译（`.gradle` 锁会被沙箱拒，必须用独立缓存目录）。
6. 进游戏按排期表"验收要点"过一遍，并确认同目标其它 mixin 未被连带影响。
7. 在 `docs/plan/mixin/mixin清理记录.md` 追加「日期 | 名称 | 替代方式 | 验收结果」。

## 7. 注意事项

- 同目标混入会互相影响（`WeaponUnit` 14 个、`VehicleRender` 5 个）：同一目标的清理尽量连续几天完成，避免出现"半自绘 + 半混入"的中间态。
- `VehicleExplosion` 系列 6 个已于 2026-10-25 内联进 `RVP_VehicleExplosion`，是 B 类的样板（含 tick 驱动、视觉抑制、配置项迁移）。
- `FirstPersonHandlerExplosionShakeMixin` 可单独评估：爆炸已自主，震屏钳制可直接在自己发起震屏处做，不必再拦本体。
- 灰区（先做原型再定）：`WarningReceiverSearchWarnMixin`、`LocalVehiclePlayerViewTypeRestrictMixin`、`EntityContextEraStateMixin`。
- 统计原始数据：`_tmp_mixin_inventory.json`（本机临时文件）。
