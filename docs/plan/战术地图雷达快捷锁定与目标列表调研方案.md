# 战术地图雷达快捷锁定与目标列表调研方案

## 1. 需求理解结论

我理解你的意思，而且这套交互在现有架构上是可以做的。

你要的是把战术地图从“态势显示器”继续升级成“雷达火控操作台”，新增两组能力：

1. **地图直接交互火控**
   - 双击左键雷达范围内目标：直接尝试雷达锁定
   - 右键点击已锁定目标：若当前武器是 `rvp` 主动雷达导弹，则直接开导引头、尝试锁定并发射
   - 若当前是地面载具，还要让炮塔朝目标对准

2. **抽屉式雷达详细面板**
   - 风格参考 `D:\ywzj\ywzj\ywzj_rvp\示例1.jpg`
   - 作为和 GPS 面板一样的抽屉式侧边栏
   - 展示“雷达已探测目标”的列表
   - 每行显示：距离、高度、速度、NCTR 名称、敌我识别、锁定状态
   - 支持“隐藏友方”筛选
   - 支持滚动
   - 支持双击左键锁定、双击右键发射

## 2. 可行性结论

结论：**可以做到，而且主要放在 `ywzj_rvp` 侧实现即可。**

不需要改 `ywzj_vehicle` 本体业务逻辑的原因：

- 现有 `RadarUnit` 已经有 `detectedObjects`、`lockedEntity`
- 现有 `ClientRadarAction` 已经支持 `LOCK`
- 现有 `WeaponUnit` 已经有：
  - 雷达锁定目标后的自动火控指向
  - `toggleSeeker(Boolean on)`
  - `shoot(...)`
- 现有战术地图已经有：
  - marker hit-test
  - 右键上下文菜单
  - 抽屉式 GPS 面板
  - 小按钮 `TerminalButton`
  - Scissor 裁剪与小地图局部绘制

所以这不是重做一整套系统，而是在已有战术地图和雷达/武器站之间增加一层“战术地图火控交互层”。

## 3. 现有基础梳理

### 3.1 战术地图点击入口

文件：

- `src/main/java/org/ywzj/rvp/client/screen/RVP_TacticalMapScreen.java`

当前 `mouseClicked(...)` 已实现：

- 左键：
  - 选中 marker
  - 无 marker 时拖地图
- 右键：
  - 对 marker 打开上下文菜单
  - 对空白地图打开地图上下文菜单

当前没有双击语义，因此新需求需要新增一层：

- 左键双击判定
- 右键双击判定
- 区分“单击选中”和“双击锁定/发射”

### 3.2 雷达锁定链路

文件：

- `ywzj_vehicle/.../ClientRadarAction.java`
- `ywzj_vehicle/.../WeaponUnit.java`

现有能力：

- `ClientRadarAction.Action.LOCK` 已经存在
- 服务端收到后会：
  - 找到当前玩家操作的 `WeaponUnit`
  - 拿到主雷达 `mainRadarUnit`
  - 调用 `mainRadarUnit.setLockedEntity(toEntity)`

也就是说，**“从战术地图直接锁定某个已探测目标”这件事本身已经有网络动作支撑**，不需要另造包。

### 3.3 武器发射链路

文件：

- `ywzj_rvp/.../RVP_ProjectileWeapon.java`
- `ywzj_rvp/.../RVP_WeaponBase.java`
- `ywzj_vehicle/.../WeaponUnit.java`
- `ywzj_vehicle/.../ClientVehicleAction.java`

现有关键点：

- `WeaponUnit.shoot(...)` 已经是统一发射入口
- `RVP_WeaponBase.doClientShoot()` 已经处理：
  - 是否需要锁定
  - 是否有 seeker
  - 发射前把锁定状态同步到服务器
- `RVP_ProjectileWeapon.dispatchShots(...)` 会把当前 `unit.getLockedEntity()` 传给弹体

这意味着：

- 若当前武器本身就是 `ARH` 主动雷达导弹
- 且当前 `WeaponUnit` / `RadarUnit` 已经锁住目标
- 那么“地图上直接发射”复用现有发射链即可

### 3.4 地面载具炮塔指向

在 `WeaponUnit.tickAim()` 中，若 `lockedEntity != null`：

- 武器站会自动 `aim(center)`
- 也就是会朝锁定目标中心持续指向

所以对于地面载具，“先锁定再发射”天然就会带来：

- 炮塔转向目标
- 武器站火控修正跟随目标

也就是说，这部分不需要专门重写一套炮塔转向逻辑。

### 3.5 抽屉式面板基础

战术地图目前已有：

- `SidebarMode`
- `toggleSidebar(...)`
- `renderSidePanel(...)`
- `TerminalButton`

GPS 面板已经证明：

- 抽屉式侧边栏是现成交互模式
- 按钮/标题/说明文字/表单布局也都已有风格模板

因此雷达详细面板最合适的做法就是：

- 继续走 `SidebarMode`
- 新增一个 `RADAR`
- 和 GPS 共用同一套抽屉式容器

## 5. 推荐实现方案

## 5.1 新增侧栏模式 `RADAR`

建议在 `RVP_TacticalMapScreen.SidebarMode` 中新增：

- `RADAR`

并在工具栏新增一个与 GPS 面板并列的按钮，例如：

- `RDR`
- 或直接显示 `RADAR`

建议按钮文案走 i18n。

打开后：

- 左侧或右侧抽屉式展开
- 不覆盖地图主区域
- 样式复用 GPS 面板现有外框和终端色

## 5.2 新增雷达目标视图模型

建议不要在渲染列表时临时从 `RadarUnit.getDetectedEntities()` 直接拼 UI，而是新增一个轻量视图模型，例如：

- `RadarContactRow`

字段建议：

- `entityId`
- `entityRef`
- `distance`
- `altitude`
- `speed`
- `nctrName`
- `relation`
- `locked`
- `isVehicle`
- `isAmmo`
- `detectedTime`

来源：

- 主雷达 `mainRadarUnit.getDetectedEntities()`
- 如果未来支持多雷达，可扩展为多个雷达合并

这样好处是：

- 面板列表
- 地图双击逻辑
- 右键发射逻辑

都可以复用同一份雷达接触数据，而不是各自重新取数据。

## 5.3 地图双击锁定

### 语义

- 前提：
  - 鼠标点中的是地图上的 marker
  - 该目标当前在雷达探测范围内
- 操作：
  - 双击左键
- 结果：
  - 直接发送 `ClientRadarAction.Action.LOCK`
  - 把该目标设为主雷达锁定目标
  - 若锁定成功，同步刷新战术地图的锁定线和列表锁定状态

### 需要新增的本地判定

在 `RVP_TacticalMapScreen` 内新增：

- `lastLeftClickTime`
- `lastLeftClickEntityId`
- 双击时间阈值，例如 `250ms`

判定规则：

- 同一目标
- 同一按键
- 时间差小于阈值

才算双击锁定。

### 为什么不用单击直接锁定

因为当前单击左键已经承担：

- marker 选中
- 地图拖动入口

如果改成单击锁定，会严重干扰现有地图浏览体验。

因此双击是合理的。

## 5.4 地图右键发射

### 语义

- 前提：
  - 当前目标已经被雷达锁定
  - 当前武器为 `rvp` 主动雷达导弹
- 操作：
  - 右键点击该已锁定目标
  - 或右键双击该目标（更安全）
- 结果：
  - 开启 seeker
  - 保证锁定实体仍是该目标
  - 调用客户端发射流程

### 推荐交互

为了避免和现有右键上下文菜单冲突，我建议第一版不要用“单次右键直接发射”，而采用：

- **双击右键发射**

原因：

- 当前右键已绑定实体上下文菜单
- 如果单击右键直接发射，会和现有地图交互完全冲突
- 双击右键既满足“快速发射”，又不破坏现在的右键菜单体系

### 发射执行条件

建议仅在以下全部满足时执行：

- 当前 `WeaponUnit` 存在
- 当前 `WeaponUnit.getCurrentWeapon()` 存在
- 当前武器属于 `RVP_WeaponData`
- 当前武器 `isActiveRadar() == true`
- 当前武器弹种是 `MISSILE`
- 当前武器剩余弹药 > 0
- 当前目标就是 `mainRadarUnit.getLockedEntity()`

若条件不满足：

- 不发射
- 给出 HUD 提示文字，例如：
  - `当前武器不是主动雷达导弹`
  - `未锁定目标`
  - `无剩余弹药`

## 5.5 地面载具炮塔转向

这里不建议专门写“地图模式下炮塔特殊转向”。

正确做法是：

1. 先通过地图双击左键锁住目标
2. 由 `WeaponUnit` 现有锁定火控自动带动炮塔朝目标转向
3. 再地图双击右键执行发射

这样可以完全复用现有火控链，也能保证地面载具与飞机行为一致。

## 5.6 雷达详细面板内容

推荐列字段如下：

- `ID`
- `方位`
- `距离`
- `高度`
- `速度`
- `NCTR`
- `敌我`
- `锁定`

其中：

- `方位`：相对本机方位角
- `距离`：米或格，建议和地图其他单位保持一致
- `高度`：目标 Y 或相对高度，建议先显示绝对高度
- `速度`：优先显示实时速度
- `NCTR`：
  - `NONE` 模式显示 `?`
  - `EARLY` 显示 `JET/HELI/MSL/BOMB`
  - `MODERN` 显示 `nctr_name`
- `敌我`：
  - 敌
  - 我
  - 友
  - 中立
- `锁定`：
  - 当前主雷达锁定目标显示 `LCK`
  - 其他显示空白或 `-`

## 5.7 列表滚动与紧凑行高

这是可以做的，而且非常有必要。

建议：

- 单行高度控制在 `11~13 px`
- 表头固定
- 列表主体使用自定义滚动区域
- 右侧细滚动条
- 鼠标滚轮仅在列表区域内生效

实现方式有两种：

### 方案 A：继续在 `RVP_TacticalMapScreen` 内自绘

优点：

- 风格和 GPS 面板完全统一
- 不需要引入额外 widget 复杂度

缺点：

- 要自己处理滚动、双击命中、裁剪

### 方案 B：封装成一个轻量自绘列表组件

例如：

- `RadarContactListWidget`

优点：

- 后续可复用
- 逻辑更清晰

缺点：

- 需要多写一个组件类

建议：

- 如果只是先做这一处，用 **方案 A**
- 如果后面还会有武器列表/任务列表/接触历史列表，用 **方案 B**

## 5.8 列表筛选

用户要求的筛选是：

- “在列表上不显示友方单位，地图上还是显示”

这说明筛选只应作用于：

- 雷达详细面板列表

不应作用于：

- 地图 marker 层

建议第一版只做一个开关：

- `隐藏友方`

后续可扩展：

- 仅显示锁定目标
- 隐藏弹药
- 仅显示敌方

## 5.9 列表交互

建议列表支持：

- 单击左键：选中该行，并高亮地图对应目标
- 双击左键：对该目标执行雷达锁定
- 双击右键：若当前武器为 ARH 导弹，则执行快捷发射

这样地图与列表交互保持完全一致，用户不需要学两套操作。

## 7. 风险点与边界

## 7.1 右键菜单冲突

当前地图上右键已经绑定：

- marker 实体上下文菜单

因此如果改成“单击右键直接发射”，一定会冲突。

结论：

- **推荐改成双击右键发射**
- 单击右键仍保留现有上下文菜单

## 7.2 当前武器不一定是 ARH 导弹

即使目标被雷达锁定，也不代表当前武器适合快捷发射。

需要严格限制：

- 只允许 `RVP_WeaponData.isActiveRadar() == true`
- 只允许导弹类

否则地图发射操作应该拒绝。

## 7.3 武器站/雷达来源要统一

地图显示的雷达接触、锁定对象、发射动作，都必须使用同一个当前 `WeaponUnit / mainRadarUnit`，不能混用：

- 地图雷达扇面来自 A 雷达
- 列表数据来自 B 雷达
- 发射却走 C 武器站

否则用户会感觉“地图显示的不是当前火控站”。

## 7.4 发射时 aim context

地图快捷发射不应该自己伪造新制导逻辑，只应该复用当前武器站的正常发射链。

因此建议：

- 只负责把锁定状态和 seeker 状态准备好
- 最终还是走当前 `WeaponUnit` 的正常发射接口

## 7.5 友方筛选仅影响面板

必须避免把筛选误接到地图渲染层，否则会违背你的需求。

正确语义：

- 列表隐藏友方
- 地图继续按原规则显示友方

## 8. 推荐实施顺序

### Phase 1：雷达面板只读版

先做：

- 工具栏按钮
- 抽屉式雷达面板
- 目标列表
- 滚动条
- 友方隐藏筛选
- 锁定状态与 NCTR 展示

这样可以先把数据结构和 UI 骨架定下来。

### Phase 2：列表双击交互

再做：

- 双击左键锁定
- 双击右键发射

先在列表里做，原因是：

- 命中区域规则更稳定
- 比地图 marker 更容易调试双击逻辑

### Phase 3：地图 marker 双击交互

最后做：

- 地图 marker 双击左键锁定
- 地图 marker 双击右键发射

原因：

- 地图 marker 命中区域小
- 同时还承担拖拽、选中、右键菜单
- 更容易和现有交互冲突

## 9. 最终建议

这套需求是完全合理的，而且和你想要的“地图中心化火控交互”方向一致。

从技术上看：

- **抽屉式雷达详细面板**：低风险，可直接做
- **列表滚动/紧凑行高/筛选**：低风险，可直接做
- **列表双击锁定/双击发射**：中低风险，可做
- **地图 marker 双击锁定/双击发射**：中风险，可做，但要仔细处理与现有右键菜单/左键拖拽的冲突

因此最推荐的实际落地顺序是：

1. 先做雷达详细面板
2. 再做列表双击交互
3. 最后把同样的交互下放到地图 marker

如果你要开始实现，我建议就按这个顺序做，这样最稳，交互也最容易一步步验收。
