## 三、发现的问题（建议优先处理）

### 问题 1 ⚠️⚠️ `rgn109_barrel` 拼写错误 —— 16 管会退化成 1 管
结构模型里是 `rgm109` 骨 + **`rgn109_barrel`**（n 而非 m）。本体取的是 `structure_bone + "_barrel"` = `rgm109_barrel` ⇒ **取不到** ⇒ 走兜底分支：只造 **1 个**炮闩并**提前 return** ⇒ **16 个 cube 全白摆、永远同一管出弹**（052D 踩过一模一样的坑）。
**修法**：把 `rgn109_barrel` 改名为 `rgm109_barrel`。

### 问题 2 ⚠️ `rgn109_barrel` 的 pivot Y 可疑
`rgn109_barrel` pivot `[-11, 1067, 212]`，父骨 `rgm109` 是 `[-11, 44, 173]` ⇒ **Y 差 1023 格**。对比 `essm_barrel`（Y 与父骨同 44）、`rim161_barrel`（Y 71 vs 44，差 27）。`1067` 疑似手误（106.7？）。**请核对**。

### 问题 3 ⚠️ "一个武器两个站"要配 `full_salvo`，但主站那条也必须标
- 结构：`weapon0`/`weapon2`（前/后密集阵）、`rgm84_1`/`rgm84_2`（左右斜发）都是"一个武器对应两个站"。
- 做法：主站的 `weapons` 里写两条，第二条带 `part_unit_id` 指向另一个站，**两条都标 `full_salvo: true`**，站级写 `firing_mode: "full_salvo"`。
- ⚠️ **漏标主站那条 ⇒ 主站自己不开火**（FULL_SALVO 分支只遍历列表，不补当前武器）。
- ✅ 好消息：密集阵的 `weapon0_barrel` / `weapon2_barrel` 都只有 **1 个 cube** ⇒ `full_salvo` 连带造成的"多管一次全放"副作用**对密集阵无影响**。
- ⚠️ 但 `firing_mode: full_salvo` 是**站级**的 ⇒ 别在同一站混装多管武器。
- ⚠️ 服务端没有齐射分发 ⇒ **只有玩家手动左键会齐射**，AI/自动开火不走这条。

### 问题 4 ⚠️ ESSM 缺 `ignition_delay_tick`
`ddg51_rim161` / `ddg51_rgm109` / `ddg51_rgm84` 的 `projectile_data.ignition_delay_tick` 都是 20，**`ddg51_essm` 没写**（`ign=None`）。用户要求 ESSM 也冷发射 ⇒ 冷发射本身是站级参数（在载具 JSON 里配），但"弹射出筒后延迟点火"需要武器级的 `ignition_delay_tick`。**建议 ESSM 也补 20**。

### 问题 5 ⚠️ 座位 3/4 的观瞄 X 与武器站 X 符号相反
- 座位 3 用 `weapon7`（结构 pivot X = **−104.9**，左舷），但观瞄 bb 的 X = **+97**（右舷）；
