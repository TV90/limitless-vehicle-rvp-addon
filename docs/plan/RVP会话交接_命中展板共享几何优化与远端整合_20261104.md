## 用户反馈与本次实现

用户已实测前版 `634df63b`，反馈世界场景“优化好了很多”，进一步要求展板使用同样方法。不能再写成世界优化“用户尚未实测”。用户尚未实测本次展板版。

1. 在 RVP 命中展板的现有 dispatcher 调用外开启有 finally 收尾的绘制窗口，不修改 AR 的世界/GUI 阶段标记，也不新增 Mixin。
2. RVP 模型在窗口内用 SBM 公开骨骼变换遍历 mesh，大块不透明几何沿用世界的 StaticMeshRenderer OWNER 与 chunk + material 缓存键；每实例仍读取自己的炮塔/部件姿态、可见性与自发光。小块、不支持姿势、光影、热成像及未知缓冲包装回退原通道。cube、透明/特效骨、指定 no_cull_bones 白名单原语义保留。
3. GUI 顶点镜像与法线不一致，不能直接沿世界矩阵推导受光。分解 P = (P·N^T)·N^-T，把前项暂放 model-view，后项交给 SBM，恢复原光照方向并在 finally 还原 model-view。没有双面化、没有改透明排序，也没有平行 GPU 池。
4. AR/Oculus 即使无光影也会给 source 套 IrisEntityAcceleratableBufferSource；仅其 original 和 wrapped 都等于当前展板缓冲时认可透明转发，不解包 raw AR builder。此前防 GUI 混合提交的阶段检查保留。
5. 资源重载后旧回放实例可能仍绑定旧 baked 模型；绘制必须跟随 instance.baseModel，而非当前 display 的新骨索引。只缓存最近使用的静态索引，不共享动画状态。
6. 历史姿态、命中锚点、损坏部件与 **4 格/1 秒慢速飞入**均保留；服务端采样/回放时序无修改。
7. 沿用 mesh.sharedOpaqueMesh 与 acceleratedDenseMesh 总开关、32768 顶点阈值；关闭恢复原路径。
