# 新增船舶载具指南（基于本体 e513a11 的突击艇范本）

> 依据：本体 2026-09-16 提交 `e513a11`（"追加船舶类别载具;追加突击艇"）新增的 `VesselVehicle` 体系 + `assault_boat` 范本。
> **结论先行：加一艘船不需要写任何 Java** —— 本体已注册好 `ywzj_vehicle:vessel_vehicle` 类型，
> 全部工作在载具包里加文件即可。

---

## 一、本体已就绪的部分（不用改，也不该改）

| 层 | 类 / 注册点 | 说明 |
|---|---|---|
| 实体 | `entity/vehicle/VesselVehicle` ← `AllEntities.VESSEL_VEHICLE`("vessel_vehicle") | 船实体（继承 `AbstractVehicle`） |
| 数值 | `custom/vehicle/VesselVehicleData` + `VesselVehicleDataPojo` ← `AllVehicleDataTypes.VESSEL_VEHICLE` | 解析载具 JSON 的 `attributes` |
| 显示 | `client/resource/vehicle/VesselVehicleDisplay` ← `AllDisplayTypes.VESSEL_VEHICLE` | 仅做类型绑定（无额外逻辑） |
| 动画上下文 | `client/render/animation/context/VesselVehicleContext` | 比通用上下文多 `getForwardSpeed()` / `getTurnAngle()`，并扩展绑定变量 `steering_angle` |
| 渲染器 | `ClientSetupHandler` 里 `EntityRenderers.register(VESSEL_VEHICLE, VehicleRender::new)` | **通用渲染器**，无需专属 Renderer |

船专属的物理行为（`VesselVehicle` 内，约 203 行）：

- **`tickMove()`：水/陆二元**
  - **在水里**（`isInWater()`）：前进/后退推力按 `power/100 ÷ mass` 缩放；偏航由方向舵驱动；有横向阻尼（0.01）
  - **在陆上**：只做速度衰减（每 tick −0.1），**不会前进** → 船不是两栖载具
- **方向舵模型**：左右键累积 `rudder`（每 tick `turn_step`），夹在 `±max_turn`；松手后自动回正
- **偏航速率公式**（关键）：
  `yawStep = atan2(motion × rudder / max_turn × 方向, mainCubeOBB.depth) × 0.2`，再夹 `±max_turn`
  → **结构模型主立方体的"长度"直接决定转向灵敏度**：`depth` 越大越迟钝（像大船）
- **`inject()` 的浮力钳制**：`if (physicsInfo.density > 1) density = 0.3f`
  ⚠️ 注意这是**条件覆盖**，不是"统一限制到 0.3"：配 0.5 会保持 0.5，配 2.0 才会被压成 0.3
- **`build()` 强制 `canWade = true`**（覆盖 JSON 里的 `canWade`）→ 船的下水权限由代码保证，不用配
- **`tickSound()`：两套引擎音**，按 `engineSpeed` 以 60 为界切换 `engine_idle` / `engine_run`，运行时按转速调 pitch

```json
    "max_speed_backward": 0.5,
    "turn_step": 0.3,                             // 每 tick 舵角增量
    "max_turn": 3                                 // 最大舵角
  },
  "max_health": 200,
  "view_info": { "third_person_center_offset": [0,2,0], "third_person_distance": 6, "sound_distance": 3 },
  "energy_info": { "energy_capacity": 1, "energy_consumption_per_tick": 0.00001 },
  "physics_info": {
    "density": 0.2,                               // ★ 要小才浮得起来

    "center": [0, 0, -0.2]
  },
  "structure_model": "ywzj_vehicle:vehicle/assault_boat",
  "parts": [ /* 座位（is_seat:true）+ 可选的武器站，机制与陆地载具完全相同 */ ]
}
```

### 2.2 结构模型：必须有足够大的主立方体

`mainCubeOBB` 由 `BaseVehicleData:228` 的 **`largestVehicleCubeOBB(main)`** 取"最大 cube"得到
（**不要求特定骨名**）。突击艇的结构模型只有两个骨：

```
main_structure   1 个 cube ← 38.24 × 16 × 76.775 像素（= 2.39 × 1 × 4.8 格）  → 这就是主 OBB
vehicle_body     7 个 cubes（视觉化的船体分段，供后续做损伤/部件）
```

- 主 cube 的 **Z 向尺寸（`depth`）决定转向灵敏度**：越大越迟钝。
- 结构模型同时是**碰撞体**，尺寸要与渲染模型对得上。

### 2.4 动画控制器 + JS 脚本

控制器把 `graph` 直接指向脚本函数：

```json
{ "name": "assault_boat_controller",
  "script": "ywzj_vehicle:assault_boat",
  "graph": { "type": "script", "function": "updateBones" } }
```

脚本（突击艇原样，注意骨名对应的是**渲染模型**的骨）：

```js
function updateBones(context) {
    const control = context.getControlUnit()
    const direction = control.forward ? 1 : (control.backward ? -1 : 0)
    const deltaTime = Math.max(0, context.currentTimeMillis() - context.lastRenderTime()) / 1000
    // 跨帧持久状态：context.setFloat / getFloat
    const previousRotation = context.getFloat("propellerRotation", 0)
    const propellerRotation = (previousRotation + direction * deltaTime * 2000) % 360
    context.setFloat("propellerRotation", propellerRotation)

    const builder = createPoseBuilder()
    builder.setRotation("root3", 0, context.getTurnAngle() * 8, 0)  // 舵面随舵角偏转
    builder.setRotation("root4", 0, 0, propellerRotation)           // 螺旋桨自转
    return builder
}
```

突击艇渲染模型的骨名是：`root` / `root2` / `root3` / `root4` / `cylinder_selection`，
脚本用 `root3`（舵）与 `root4`（螺旋桨）。

**可用的上下文 API**：`getControlUnit()`（`forward`/`backward`/`left`/`right`）、`getTurnAngle()`、
`getForwardSpeed()`、`setFloat/getFloat`（跨帧持久）、`currentTimeMillis()`、`lastRenderTime()`、
`createPoseBuilder()` → `setRotation(bone, xDeg, yDeg, zDeg)`。

**另一种做法**：不用脚本，改用动画 JSON 的绑定变量 —— `VesselVehicleContext` 已扩展
`steering_angle` = `-turnAngle × 16`（度），可直接在 `animation.json` 里引用。

## 三、与陆地载具的差异对照（改配置时别照抄陆地载具）

| 维度 | 陆地载具（tank/wheeled 等） | 船（`vessel_vehicle`） |
|---|---|---|
| 载具 `type` | `ywzj_vehicle:tracked_vehicle` 等 | **`ywzj_vehicle:vessel_vehicle`** |
| 移动实现 | 履带/轮 + 悬挂 | **水/陆二元 + 方向舵**，陆上只能滑行衰减 |
| `canWade` | 由 JSON 配（默认 false） | **代码强制 true** |
| `physics_info.density` | 常规 | **要小（突击艇 0.2）**，>1 会被强制成 0.3 |
| 动画上下文 | `VehicleContext` | `VesselVehicleContext`（多 `steering_angle` 绑定） |
| 引擎音 | 通用引擎音 | **`engine_idle` + `engine_run` 两套**（60 转速分界） |
| 转向手感来源 | 履带/轮参数 | **结构模型主 cube 的 `depth`** |

## 四、坑与注意事项

1. **结构模型的主 cube 别做太小**：它是**"物理代表体"**——转向 `depth`、`tickPhysics()` 的表面点接触采样、
   `tickPower()` 的流体采样都用它。注意**对外碰撞体用的是全部 cube**（`getOBBs()`），所以缩短主 cube
   **不会漏碰撞**，但物理接触采样范围会跟着缩小（消费者只有 Create / VS 兼容）。大船如何靠调整主 cube
   拿到灵活转向，见 **§六**。
2. **`density` 钳制是条件式的**（`>1 才改 0.3`）——如果你的船配了 0.8，代码不会动它；配 2.0 会被静默改成 0.3，
   调试浮力时先确认自己配的值是否落在 `>1` 区间。
3. **船在岸上开不动**（`onGround` 分支只减速）→ 设计关卡/出生点时要考虑下水位置。
4. **JS 脚本的骨名对应渲染模型**（`models/bedrock/entity/<id>.json`），不是结构模型；改模型后脚本骨名要同步。
5. **`animation_controllers` 的 graph 用 `{"type":"script"}` 时完全没有内置动画** —— 所有骨骼姿态都要脚本返回，
   包括"静止时也要给出默认姿态"（否则骨骼可能停在上一次的旋转上）。
6. **载具物品不需要注册**，但**配方必须手写**，否则打印机里看不到。
7. 若在 rvp 侧加船，需额外确认 rvp 的挂架/渲染/武器逻辑是否默认假设"陆地载具"
   （例如挂架锚点、第三人称视点、HUD 判定），建议先跑一次实机再逐项排查。

## 五、动手顺序建议

1. **先复制突击艇的 10 个文件**改名改内容，能跑起来再改细节（最快拿到可下水的最小闭环）。
2. 优先调通**结构模型主 cube 尺寸**（碰撞 + 转向手感）与 **`attributes` 七参数**。
3. 再做模型/贴图/动画（这部分只影响观感，不影响能否开动）。
4. 最后补音效、配方、物品栏图标。
5. 实机回归清单：下水能否前进/后退、左右舵回正、岸上是否确实开不动、浅水/深水表现、
   成员上下船、引擎音在 60 转速处切换、多人下 `FORWARD_SPEED`/`TURN_ANGLE` 同步是否正常。

## 六、大船（驱逐舰级）转向专题 —— `depth` 的作用与对策

### 6.1 转向公式（`VesselVehicle.tickMove()`）

```java
if (maxTurn > 0 && mainCubeOBB.depth > 0) {
    float yawStep = (float) Math.toDegrees(Math.atan2(
            motion * rudder / maxTurn * (forwardSpeed < 0 ? -1 : 1),
            mainCubeOBB.depth)) * 0.2f;
    yawStep = Mth.clamp(yawStep, -maxTurn, maxTurn);
    setYRot(getYRot() + yawStep);
}
```

其中 `motion` = 水平速度模长，`rudder` = 当前舵角（累积值，夹 `±maxTurn`），`depth` = 主 OBB 的 **Z 向尺寸**。

**满舵时 `rudder == maxTurn`，分子分母抵消**，于是：

> **`yawStep ≈ degrees(atan2(motion, depth)) × 0.2`（度/tick）**

**推论（重要）**：
- 满舵转向角速度**只由 `motion`（航速）与 `depth`（主 cube 船长）决定**；
- **`max_turn` 不影响满舵角速度**（它只当 `yawStep` 的上限 clamp，以及舵角比例的分母）；
- **`turn_step` 只决定"多久打到满舵"**（约 `max_turn / turn_step` tick），也不改变满舵后的转速；
- 倒车时舵效反向（`forwardSpeed < 0` 时乘 −1）。

### 6.2 量级实测（`× 0.2` 系数已计入）

| 场景 | depth(格) | 航速(格/tick) | 转向速率(°/tick) | 掉头一圈 | 一圈耗时 |
|---|---|---|---|---|---|
| 突击艇 | 4.8 | 1.0 | 2.35 | 153 tick | **7.6 s** |
| 中型船 | 12 | 1.0 | 0.95 | 378 tick | 18.9 s |
| 大型船 | 20 | 1.0 | 0.57 | 629 tick | 31.4 s |
| **30 格驱逐舰** | 30 | 1.0 | 0.38 | 943 tick | **47.1 s** ← 基本转不动 |
| 30 格 + 提速 | 30 | 2.0 | 0.76 | 472 tick | 23.6 s |
| 30 格 + 大提速 | 30 | 4.0 | 1.52 | 237 tick | 11.9 s |
| **主 cube 缩到 8** | 8 | 1.0 | 1.43 | 253 tick | **12.6 s** |
| 主 cube 缩到 8 + 提速 | 8 | 2.0 | 2.81 | 128 tick | 6.4 s |

→ **担心成立**：按真实比例做 30 格驱逐舰，满舵掉头要 47 秒，等于转不动。

### 6.3 `depth` 是怎么来的（能不能调）

```
BaseVehicleData:228   mainCubeOBB = largestVehicleCubeOBB(main)      // 有 main_structure 骨时
BaseVehicleData:242   largestVehicleCubeOBB → findMaxRecursive：遍历该骨(含子骨)所有 cube，
                                                      取 volume() 最大者（严格 > 才替换）
BaseVehicleData:237   无 main_structure 骨时：对全部 vehicleBodyOBBs 按 depth×width×height 排序取第一
```

- **`depth` = OBB 的世界 Z 向尺寸**（`VehicleCubeOBB.depth = obb.extents().z * 2`），而船的局部 Z 轴正是船头方向
  （`tickMove` 里 `direction = axes()[2]`）→ **`depth` 就是船长**。
- **选取标准是"体积最大"而不是"最长"** → 这一点给了调节空间。

### 6.4 对策

**对策 1（纯配置，推荐）：让"体积最大"的那个 cube 在 Z 向尽量短**

既然比的是 `volume = depth × width × height`，就把主 cube 做成**"宽高够大、Z 短"**，船体其余部分用
一串**短分段**拼（每段体积都小于主 cube）。30 格驱逐舰示例：

```
main_structure：
  main  cube  [宽 8, 高 5, 长 10]   → volume 400（体积最大 → 选为 mainCubeOBB，depth = 10）
  hull1 cube  [宽 8, 高 5, 长 6]    → volume 240
  hull2 cube  [宽 8, 高 5, 长 6]    → volume 240
  ...（其余分段同理，每段 < 400）
```

→ 视觉上船长仍可 30 格，但 `depth` 只有 10，转向速率提升约 3 倍（见上表）。

**代价（已核实，很小）**：`tickPhysics()` 的**表面点接触采样**只用 `mainCubeOBB`，
但 `VehicleCollectCollisionEvent` 的消费者**只有 `CreateCompat` / `ValkyrienSkiesCompat`**
（装了 Create 或 Valkyrien Skies 才生效）。其余不受影响：
- `getOBBs()`（对外碰撞体）用**全部 cube** + 部件 → 碰撞完整；
- `makeBoundingBox()`（实体 AABB）用全部 cube + 主 cube → 包围盒正常；
- F3+B 调试框会显示"蓝框（主）小、绿框（全体）大"，属正常现象。

**唯一要注意**：`tickPower()` 用 `mainCubeOBB.obb().center()` 采流体 → 主 cube 的**中心**要落在船体中部、
水线附近的合理位置（否则会"人在水里却判定不在水里"）。

**对策 2（纯配置）：提高航速**。小角度下 `atan` 近似线性，`max_speed_forward` 翻倍 ≈ 转向速率翻倍。
但"30 格 + 1.0 格/tick"要提到 4.0 格/tick（≈288 km/h）才能到 12 s 一圈，不现实 → 单靠提速不够。

**对策 3（改行为，须在 rvp 侧写代码）**：用 mixin 覆盖 `VesselVehicle.tickMove()` 的转向段，
把 `mainCubeOBB.depth` 换成更合适的量（独立的"转向惯性"配置项，或全体船体 OBB 的 Z 向跨度）。
属改本体行为，先确认是否值得。

**组合结论**：驱逐舰级建议 **对策 1（主 cube 缩到 8~12）+ 适度提速（1.2~1.5 格/tick）**，
可把掉头压到 8~15 秒，配合舵角比例手感已经像船。

### 6.5 调参速查

| 想要的效果 | 调什么 |
|---|---|
| 转向更快 | 缩短主 cube 的 **Z 向**（同时保持它体积最大）／提高 `max_speed_forward` |
| 转向更迟钝（大船感） | 拉长主 cube Z 向／降航速 |
| 打舵更跟手（更快到满舵） | 提高 `turn_step`（或降 `max_turn`） |
| 限制最大转向速率上限 | 降低 `max_turn`（它同时是 `yawStep` 的 clamp 上限） |
| 舵角更"线性"更钝 | `max_turn` 越大，达到满舵所需 tick 越多（≈ `max_turn / turn_step`） |
