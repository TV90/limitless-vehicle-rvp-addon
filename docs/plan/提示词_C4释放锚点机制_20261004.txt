【背景（简版）】
1) RVP 弹体的 Tick 顺序是「先碰撞检测、后运动积分」（RVP_BaseBullet.tick():1845 tickHit() 早于 :1851 tickMotion()），所以碰撞处理期间 parent.position() 还是【本 Tick 的起点】。
2) 目前子母弹的生成点直接取 parent.position()（RVP_SubmunitionSpawner 的 :112 / :119 / :174 / :183）⇒ 破片会落在撞击点【前方】最多 |velocity| 格（30mm 的 velocity = 12~20 格/Tick）。
3) 需求：破片要出现在「**撞击命中点** + 沿弹道前推 N 格」（打墙 ⇒ 落在墙后）；命中**实体**时**不前推**；子弹药**不继承母弹速度**（这条是纯数据，数据侧已处理，不用你管）。
4) 做法：把「释放锚点」参数化 —— 触发点把命中点传下去，前推量由 release 的 `spawn_forward_offset` 决定。

■ 第 3 处　weapon\submunition\RVP_SubmunitionSpawner.java
spawnReleaseWave / spawnRvpWeapon / spawnEntity 各加一个 @Nullable Vec3 anchor 参数，并新增一个基准点解析方法：
    private static Vec3 resolveSpawnBase(RVP_BaseBullet parent, RVP_SubmunitionReleaseData release, @Nullable Vec3 anchor) {
        if (anchor == null) {
            return parent.position();                       // 旧行为：飞行中释放等
        }
        float offset = release.getSpawnForwardOffset();
        if (offset <= 0f) {
            return anchor;                                  // 命中点本身（实体就是这条）
        }
        Vec3 step = parent.getDeltaMovement();
        if (step.lengthSqr() <= 1.0E-12) {
            return anchor;
        }
        return anchor.add(step.normalize().scale(offset));   // 沿弹道前推 ⇒ 落到墙后
    }
然后把该路径里的 **两处** parent.position() 一起换成同一个 base：
  - :112  释放云中心：RVP_SubmunitionReleaseCloudUtil.samplePosition(parent.position(), release, random) → samplePosition(base, ...)

  - spawnEntity 路径的 :174 / :183 同样处理
