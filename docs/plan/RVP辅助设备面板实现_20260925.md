## 功能概述

O 键打开（乘载具时）AUI 辅助设备面板：
- **左上俯视图**：车体包络 + 骨模块块（ERA 绿/失效红、设备骨蓝/失效红），原生 GuiGraphics 绘制；
- **左下快速维修顺序设置**：爆反 / 辅助设备两条队列（自绘下拉切换），点右侧失效行入队、✕ 移除；**无开始按钮**——触发仍由玩家用快修工具完成；载具未配置快修时整栏隐藏；
- **右半页**：按设备类型分栏（ERA/APS/ECM 主动/干扰机/DIRCM/干扰物/部件血量，无设备不画），同屏四栏目 2×2 等高，卡内滚动+外层滚动；行=序号（载具 parts[] 顺序，1 起）+ 别名（`hitbox_display_name`，无别名回退骨名）+ 状态；**失效行置顶**、生效绿框/失效红框。

## 关键实现决策

1. **俯视图参考本体/RVP 本土化**：本体 `VehicleScopeOverlay.renderVehicleHeading` 已被 RVP 从观瞄 HUD 摘除（保留未启用），本实现复刻其投影数学但改为：OBB 8 顶点投影取包络（免欧拉角分解）、全图自动缩放居中、HTML 锚点 scissor 内原生绘制（`RVP_AuiVariantScreen` 的 renderScale 换算先例）。
2. **行序号语义**：`getPartUnits()` 严格等于载具 JSON `parts[]` 顺序（本体 LinkedHashMap 保序已核）；`bone_modules` 底层 HashMap 不保序，故以部件顺序为锚、无部件的配置骨（ecm_bone 等）按名排序追加。
3. **队列同步即编辑即发包**（服务端按 UUID 侧表，车组共享），触发与消费解耦：`recoverModules` 消费时才校验"骨确实失效+类型可修"，无效骨名自然跳过（服务端权威，无越权面）。
4. **AUI 引擎规避**：下拉框用自绘 DOM（原生 `<select>` 支持未知）；无新增 Mixin；HTML 无脚本（交互全 Java `addEventListener`）。

## 全载具默认快修（2026-09-25 用户定版追加）

- **所有载具默认可快修**：`resolveMaintenanceModule` 在未显式配置 `maintenance` 时回退
  `BoneMaintenanceConfig.defaults()`（挂在永不可毁虚拟骨 `__vehicle__` 上）；显式 JSON 配置（含绑实体骨的对抗性写法）仍优先。
- **默认数值**：冷却 300t（**15 秒**）、生效 20t × 1.5%/tick = **一次修复 30% 最大血量**；
  不回部件血量、无离地限制、模块恢复走缺省（设备 25% + ERA 25%/至少 1 块）。`parse()` 的字段缺省值同步对齐。
- **快修默认键 G → `;`**（`RVP_Keys.USE_MAINTENANCE`，CM HUD 键位提示走 `getTranslatedKeyMessage()` 自动跟随）。
- 连带效果：辅助设备面板的维修顺序栏在**所有载具**可见（不再有"未配置隐藏"分支）；
  `RVP_MaintenanceRuntimeManager.tick` 对全载具运行（未配置车早期返回改为默认配置，开销可忽略）。

## 实测迭代记录（2026-09-26）

- **俯视图显示**：scissor 原生绘制在 AUI 屏内三次尝试均不可见（flush/数据源修复后仍不显示），最终改为 **HTML div 注入**（Java 投影 → 绝对定位 div），本屏已实证可靠。★教训：**AUI 不渲染绝对定位 div 的子元素内联样式**——嵌套 div 做空心会退化成实心色块，线框必须用 **4 条边 div 平铺**拼装；div 注入后须调 `Document.refresh()` 强制重绘，否则要等一次交互才可见；锚点禁用 `inset` 简写。
- **投影方向**：`px = -(Δ·axisX)`（本机 X 轴指向车体左侧，实测左右反向后修正）、`py = -(Δ·axisZ)`（车首朝上）。
- **数据源**：`PartUnit.getPartCubeOBBs()`（客户端实证）；陈旧 OBB 距车心超 `结构长×2+16` 剔除（防垃圾坐标撑爆包络缩成像素点）。
- **同骨多角色捆绑修复（用户定版）**：`recoverModules` 改捆绑——ERA 配额选中的骨整骨恢复（ERA+同骨失效设备模块一起修回）；纯设备骨按骨掷骰一次、中了整骨设备一起恢复；含 ERA 的双角色骨不计入辅助设备数（面板预计行同步口径），其设备行标注"随爆反修复"、入队路由到爆反队列；ERA 行双角色标注"兼辅助设备"；`queueEntryStillFailed` 改骨级判定（骨上任一可修模块失效即待修，全好才踢除）。
- **全载具默认快修**（2026-09-25）：`resolveMaintenanceModule` 未显式配置时回退 `BoneMaintenanceConfig.defaults()`（冷却 300t=15 秒、生效 20t×1.5%/tick=一次修复 30% 最大血量，虚拟骨承载）；快修键 G→`;`；`parse()` 字段缺省值同步对齐。
- **性能**：俯视图 div 仅在模块状态签名变化时重建（签名含整车血量/各行生效态/双队列），根治 0.5s 周期无条件重建导致的滚动/悬停抖动。

## 已知边界

- APS 扇区锥未画（朝向随 facing_part 实时转动，静态锥误导；后续接 `resolveFacing` 画实时方向刻度）；
- 干扰物行不可入维修队列（countermeasure 无骨模块失效语义）；部件血量行同理（由快修 heal_parts 回血，默认配置不回部件）；
- 座位权限未接入面板（干扰物余弹对任何座位可见，现网 CM HUD 有 `allowed_seat_indexes` 过滤——是否跟进待定）；
- 协议 15→16：旧客户端无法连新服（惯例，已记入功能降级表）；
- 全载具默认快修后，"绑实体骨可被打掉维修能力"的对抗性写法仅对显式配置的载具生效（默认虚拟骨永不可毁）。
