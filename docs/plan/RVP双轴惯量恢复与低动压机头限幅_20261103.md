# RVP 双轴惯量恢复与低动压机头限幅

日期：2026-11-03。已实现，完整构建与无客户端仿真通过；未执行本轮实机发射验收。

## 1. 改了什么

按用户最新要求，把 `RVP_AttackAngleModel.INERTIA_ENABLED` 恢复为 `true`。双轴是俯仰和偏航；有效惯量是质量派生的响应系数，让机头需要逐步加速、制动，并记住上一刻的角速度，不是真实刚体惯量。

原有比例响应与动压机头转角上限取较小值：

```text
q = 共用气动模型的动压系数
baseResponse = 显式 rvp_maxg 时为 0.5，否则为当前 turning_factor
response = baseResponse × sqrt(q)
fullPressureTurn = 90° × baseResponse
maxTurn = fullPressureTurn × q

每一轴：
  targetRate = clamp(角度误差 × response, -maxTurn, maxTurn)
  nextRate = clamp(旧角速度 + (targetRate - 旧角速度) × 惯量增益, -maxTurn, maxTurn)
  nextAngle = oldAngle + nextRate
```

`q` 沿用 `clamp(密度倍率 × (速度/参考速度)², 0.05, 1)`；显式关闭参考速度时为 1。满动压上限从既有响应比例折算，不新增 JSON 配置或武器特判。例如 MICA-NG 的 factor=0.14，对应满动压 12.6°/刻，最低动压 0.63°/刻；实际首刻还要经过惯量响应，可能更小。

两轴推进后，再按新旧机头方向的三维总夹角限幅并同步修正角速度，防止斜向叠加或旧角速度突破预算。原有攻角锥、法向 G、沿机头推力、重力、诱导阻力与显式 0 G 语义保留。若外力已使输入姿态在攻角锥外，既有硬约束恢复仍优先，不将这种越界恢复计作普通指令转角。

## 2. PIP 与虚拟态

PIP 是预测拦截点：瞄准目标预计到达的位置。几何相遇点算法不变，姿态逆解同步读取动压转角预算，并扣除当前惯量中尚未消散的角速度；候选指令都从同一个不可变初态试算，不能把多次试算串成多刻飞行。最终只提交一次实际执行器结果。

预测的本刻速度使用实际可达姿态及同一冻结动力快照，再加入沿机头推力；不会把理想姿态冒充可达，也不会提前消耗燃料或重复施加推力。`responseLimited` 继续明确报告不可达请求。

响应受限的目标前视和 PRESET（预设飞行路线）响应时间，改为使用 `min(response, maxTurn/攻角上限)` 估计姿态建立比例，保留原有前视时间边界。实体和虚拟态调用同一姿态执行器，持续传递两轴角速度。

虚拟积分器版本 **12→13**，快照结构版本不变。版本不匹配的旧在途虚拟记录仍会按既有 `INCOMPATIBLE_INTEGRATOR` 规则结束；更新前应清空在途虚拟弹。

## 5. 范围与复现

生产改动集中于共用惯量执行器、总开关、PIP 逆解/响应估计、PRESET 前视和积分器版本。不修改权威武器参数、本体源码、Mixin 或模型资产。

重跑专项回放：

```powershell
./gradlew projectileSimulation "-PprojectileScenario=src/test/resources/projectile-inertia-simulation" "-PprojectileOutput=build/projectile-inertia-simulation/after"
```

环境是理想目标观测、固定地面和已就绪区块；不验证真实雷达/红外搜索锁定、反制、网络、引信和伤害。恢复前后转角及交会距离已经用真实运动入口验证，游戏里的观感和传感器效果仍需实机观察。
