## 3. 排查结论（本批已核验部分，均有 diff/字节码证据）

### 3.1 已核验「未变」清单

1. **本体 09e1d63 没碰**：`WeaponUnit.java`、`WeaponUnitData`（传感器字段）、`VehicleRocket`、`currentWeaponHitPosition()` 及其 CCIP 分支——`git diff cfd7e59 09e1d63 --stat` 全量核对过，改动面=gui 五件套（AimAtOverlay 64 行/DebugOverlay/HudLayout 新/HudText 新/Overlay 230/Radar 68/Scope 173/WeaponOverlay 537/GuiHelper 47）+ PhysicsEngine +110 + SuspensionUnit +3 + apricity HTML + lang；
2. **`VehicleAimAtOverlay.render` 的 CCIP 分支仍在**：`crosshairStyle != null` → 骨归属（`CCIP && getCurrentWeapon().isEmpty()` → 挂主站）→ `weaponHitPos != null` → drawCrosshair（GREEN）——与旧版逐行同构，仅新增 markerScale 缩放与 renderReloadProgress 加 partialTick；
3. **站位布局未变**：mi28（S13 在 sighting_system2）/ah64（hydra70 在 sighting_system）的站位结构与 10-20 20:32 客户端备份完全一致；
4. **受影响火箭弹的武器 JSON 近期改动全是平衡数值**（`explosion_damage_factor` 加 player/living、bounce 参数），无 sensor/ccip 字段变更；
5. **`hitbox_max_incidence_angle`（骨级入射角上界，本批新增）不影响 CCIP 准星显示**——它只钳制直伤角度衰减与跳弹门槛的入射角数值，不改变任何标记的显示门控。

### 3.2 CCIP 准星显示门控链（代码位置）

```
RVP_RocketCcipOverlay.onRenderOverlay（RenderGuiOverlayEvent.Post，锚 CHAT_PANEL）
  ├─ event.getOverlay().id() == CHAT_PANEL.id()            ← 锚点，vanilla，不受本体重制影响
  ├─ ywzj_rvp$enableForgeOverlayEvent
  ├─ getActiveRocketContext() → isBallisticRocketWeapon(weapon, activeWeaponUnit)
  │    ├─ RVP_WeaponSensorHelper.effectiveSensorType(activeWeaponUnit) == CCIP   ← 门 A
  │    └─ weapon: VehicleRocket+isBallisticEnabled 或 RVP_ProjectileWeapon+kind==ROCKET
  ├─ ensureTexture()
  └─ getCurrentScreenHitPos() != null
       ← weaponHitPos 由本体 tickHit→currentWeaponHitPosition() 计算（Client 侧），
         CCIP 分支要求站级静态 getFireControlSensorType()==CCIP                 ← 门 B
```

- `RVP_RocketCcipOverlay.java:68` isBallisticRocketWeapon、`:110` isBallisticRocketActive、`:161` getCurrentScreenHitPos、`:204` onRenderOverlay；
- 本体侧：`WeaponUnit.java:657-660`（tickHit→currentWeaponHitPosition）、`:837`（currentWeaponHitPosition，CCIP 分支要求站级静态==CCIP）。

### 3.3 已排除的原因

1. **本体 09e1d63 改坏 CCIP 链路**：上述核心类全不在 09e1d63 改动面内；
2. **RVP 0.0.2k/0.0.3 批改坏 CCIP 绘制**：`RVP_RocketCcipOverlay` 零改动；`RVP_HmdOverlay`/`RVP_MissileOverlay`/`RVP_ClientSeekerTone` 改的是 IR HMD 锁定框/红圈/锁定音，与火箭 CCIP 落点标记是不同绘制点；
3. **武器 JSON 字段变更**：受影响火箭弹的近期改动全是平衡数值（爆炸倍率/跳弹），无传感器/ccip 字段变更；
4. **站位布局变更**：与 10-20 备份逐项一致。

## 4. 未闭合的可疑点（下个 AI 的排查起点，按优先级）

### 4.1 【最优先】eo_ccip 的 SCOPE→EO 语义与用户测试视角的错位（用户纠正过的表述矛盾）

用户先说「scope 下无准星」，后纠正为「第三人称没火箭弹准星」。eo_ccip 模式设计上 SCOPE 视角=EO（不显示 CCIP）、其余视角=CCIP。**需实机确认**：用户报「没了」时是否在开镜；若用户预期开镜也显示，则这是行为变更需求而非 bug。z10_fs70a/b、ah1z_apkws/mpsm 的 `rvp_fire_control_sensor_mode: "eo_ccip"` 在 10-21 前后未变。

### 4.2 mi28/ah64 火箭弹所在站 `fire_control_sensor_type = None`

- mi28：S13 在 `sighting_system2`（sensor None）；ah64：hydra70 在 `sighting_system`（sensor None）；
- 按门控，effectiveSensorType=None ≠ CCIP → 这两站的火箭 CCIP 标记**从未生效过**（不是「适配后消失」，是「从来没亮过」——需与用户核对记忆基准）；
- 若用户确认「以前亮过」：用客户端 `limitless_vehicle_backup/rvp_20261020200439`（0.0.4_alpha 启动备份）里的 mi28/ah64 JSON 对比当时站位与传感器配置；
- 若用户要这两站的火箭 CCIP 亮起来：给这两站补 `fire_control_sensor_type: "ccip"`（数据一行/站）。

### 4.3 0.0.2k IR 批与用户 v2/v3 重构后，`effectiveSensorType` 消费链的行为核验

- `RVP_WeaponSensorHelper.effectiveSensorType` 本身未改；
- 消费方三处：`RVP_RocketCcipOverlay.onRenderOverlay`（isBallisticRocketWeapon→effectiveSensorType）、`RVP_DamageFactor`（无关）、`RVP_ScopeOverlay`（无关）；
- **待核**：`RVP_ClientHmdState.tickIrHmd` 的 HMD 通道激活条件（`enable_ir_hmd`+`isSeekerOn`）在 0.0.2k 前后的行为差异；`RVP_IrSeekerTracker.feedHmdCandidate`/`tickFor` 在 0.0.3c 的最终形态与 isBallisticRocketWeapon 门控的交互（尤其 HMD 武器 tickFor 早退后，无 HMD 通道时 CCIP 标记是否仍按 effectiveSensorType==CCIP 门控）。

### 4.4 用户 v3 未提交改动的交互

- `RVP_ClientHmdState.getIrTrackingEntity`（新增）、IR_ACQUIRING 标签（RVP_HmdOverlay）：追踪期 HUD 显示「截获中」，armed 后由锁定框取代——与 CCIP 落点标记是不同绘制点，需实机确认两者不互相遮挡/覆盖。
