# RVP 抗荷附魔实施方案与实施记录（2026-10-05）

> 状态：已实施，build+测试全绿+冒烟通过，待实机验证。
> 背景：用户想在 RVP 侧加"抗荷服"，但不想做穿戴装备——改为做**抗荷附魔**：附在胸甲上增加过载耐受。

---

## 一、设计

### 1.1 本体黑视机制（不可改，只读）

本体 `LocalVehiclePlayer.tickOverload()`（客户端，ywzj_vehicle LocalVehiclePlayer.java:127-179）：

- 每 tick：恢复 1/tick（向 100 靠拢）→ 扣减 `(currentG−1)×0.8` → 钳制 `[100−100M, 100+60M]`
  （M = 全局配置 `AllConfigs.common.overloadCapacityMultiplier`，默认 1.0，边界即 [0, 160]）；
- 触到任一端 → `lostControl=true` 持续 60 tick（3 秒），期间输入清零（InputHandler.java:222）；
- G 值来源：`AbstractVehicle.tickOverload()`（服务端权威）经 OVERLOAD 同步数据下发（adb4845 版）；
- 黑视着色器 `OverloadHandler`（灰视/红视后处理）由 stamina 连续驱动；
- 调用链：`PlayerTickEvent`（客户端 Phase.END，NORMAL 优先级，receiveCanceled=true）→
  `LocalVehiclePlayer.instance.tick()`（本体 LocalVehiclePlayerEvent.java:24-31）。
- **无 per-player 耐受钩子**：耐受倍率只有全局配置一处消费，无法按装备区分——这是 RVP 需要补位的原因。

### 1.2 RVP 方案（零 Mixin / 零网络包 / 零本体改动）

1. **附魔注册**：`RVP_Enchantments`（`DeferredRegister<Enchantment>`，`ForgeRegistries.ENCHANTMENTS`，
   namespace `ywzj_rvp`）注册 `anti_g`（抗荷）：UNCOMMON、`EnchantmentCategory.ARMOR_CHEST`（仅胸甲）、
   槽位 CHEST、maxLevel 3、费用曲线 minCost=12×level。注册后附魔书自动可用
   （附魔台出书/给胸甲附魔、铁砧"书+胸甲"合成、`/enchant` 直测），**无需任何新物品**。
2. **生效器**：`RVP_AntiGSuitHandler` 订阅**同一事件**（PlayerTickEvent 客户端 Phase.END）但
   **priority=LOWEST + receiveCanceled=true**——事件总线保证每 tick 在本体（NORMAL）扣完之后执行。
   逻辑：`event.player == instance.getPlayer()` 且 `!lostControl` 且本体过载总开关开启 →
   读胸甲附魔等级 → 返还 `stamina += (currentG−1)×0.8×rate` → 按本体同款边界钳制
   （M 现场读本体配置，不硬编码）。
3. **补偿数学**：`RVP_AntiGSuitLogic` 纯函数（零 MC 依赖），`RATES = {0.20, 0.35, 0.50}` 集中可调。
4. **生效部位收口（2026-10-05 追加，用户需求）**：效果端只读 **CHEST 槽位**
   （`EnchantmentHelper.getItemEnchantmentLevel` + `getItemBySlot(CHEST)`），不再用汇总全身装备的
   `getEnchantmentLevel`——原版**生存**模式铁砧本就拒绝不兼容的"书+物品"（canEnchant 检查），
   但**创造**模式铁砧会绕过检查把附魔书安到任意物品上；只读胸甲槽位保证误附物品不生效，
   与提示文本口径一致。
5. **悬停提示（2026-10-05 追加，用户需求）**：`onItemTooltip`（`ItemTooltipEvent`，
   Forge 1.20.1 包路径 `net.minecraftforge.event.entity.player.ItemTooltipEvent`）——携带抗荷附魔
   但物品不是合法胸甲目标（附魔书 / 被创造模式误附的装备）时追加灰色"仅胸甲可用"行；
   已附在合法胸甲上不提示。`EnchantmentHelper.getEnchantments` 对书读 StoredEnchantments、
   对装备读 Enchantments，两来源全覆盖。lang 键 `tips.ywzj_rvp.anti_g.chest_only`。
6. **为什么不用 Mixin**：stamina/currentG/lostControl 均为本体 public 字段（LocalVehiclePlayer.java:53-58），
   RVP 已有直接读写先例（RVP_ClientHitlState 写 instance.viewType）；"公共字段+同事件低优先级"可解则
   按纪律不用 Mixin。曾评估 `@ModifyExpressionValue` 改 endureG 的客户端数组 Mixin——可行但非必需。

### 1.3 数值（默认 M=1）

| 状态 | 返还率 | 稳态不黑视上限 | 5G 可撑 | −1G 可撑（红视） |
|---|---|---|---|---|
| 裸装 | 0% | 2.25G | 2.3 秒 | 5 秒 |
| 抗荷 I | 20% | 2.56G | ~2.9 秒 | ~6.3 秒 |
| 抗荷 II | 35% | 2.92G | ~3.9 秒 | ~7.7 秒 |
| 抗荷 III | 50% | 3.5G | 8.3 秒 | 10 秒 |

- 公式：稳态平衡点 `G = 1 + 1/(0.8×(1−率))`；可撑时间 = 预算/净速率（正向 100、负向 60）。
- 正负 G 对称生效（返还量带符号：负 G 时返还为负 → 上飘变慢 → 红视延后）。

## 二、行为边界

- HUD 的 G 读数与红色过载预警（endureTick/displayG）**不变**——表显示载具真实 G，抗荷服救人不改表。
- 黑视 3 秒失控与恢复节奏完全由本体控制，抗荷服只延后触底。
- 纯客户端模拟（本体 G 系统本就只在本地玩家客户端运行），无服务端校验/同步需求。
- 特殊分支：本体过载总开关关闭时**必须跳过补偿**——本体每 tick 复位 stamina=100，若照常返还会
  单调推高 stamina（着色器直接读 stamina，会出现"没开过载却渐渐红视"的视觉 bug，代码已处理）。
- UAV/地面载具：本体直接复位 G=1，返还量恒 0，自然空转。
