# RVP 载具干扰器（Jamming Device）功能方案

> 阶段：架构已就绪（BoneModuleType.JAMMER / 骨块模块状态 / 同步），本方案落地首个干扰器类型「光电干扰机」，
> 并抽象出通用「干扰器设备」框架，未来可直接扩展「电磁干扰机」等新类型，不写死 JAMMER。
> 文档时间：2026-08-09

## 1. 背景与需求

用户需求（光电干扰机）：

- 干扰器检测**自身前方一定 FOV 与距离**内的目标。
- 当前方出现**非自身发射的 SACLOS 导弹**时，向该导弹注入随机错误操纵分量，幅度**远大于**操纵者对导弹输入的操纵分量，使导弹偏离瞄准线。
- 被干扰者提示："导弹已被光电干扰"。
- 干扰者提示："已成功干扰敌方导弹"。

架构约束：

- 干扰器是**骨骼（骨块）的一种特殊功能**，被打坏（对应 JAMMER 模块失效）后失去功能。
- 支持叠加（如 t84bm 干扰机架在反应装甲上：ERA + JAMMER 双属性，独立失效）。
- **不能写死 "jammer"**：未来需要「电磁干扰机」（针对雷达制导等），框架必须支持多干扰器类型。
- 服务端安全：纯 Forge 服务端可运行，不新增实体 mixin，不触碰本体 ywzj_vehicle。

## 2. 通用干扰器抽象（核心设计）

不新增名为 "Jammer" 的单点类，而是建立两层抽象：

```
RVP_JammingDeviceType（干扰器类型枚举）
   ├── OPTICAL    光电干扰机：干扰光学视线制导（当前实现 SACLOS）
   └── ELECTRONIC 电磁干扰机：干扰雷达制导（预留，本阶段不实现）
```

- `RVP_JammingDeviceType.interferesWith(RVP_EnumGuidanceType)`：该类型可干扰哪些制导。OPTICAL → {SACLOS}；ELECTRONIC → {ARH, SARH}（预留占位）。
- 骨块级设备配置 `BoneJammerConfig`（record）：`type / fovDeg / range / strength / facingPart`，挂在 `bone_modules` 骨块条目的 `jammer` 子对象上（见 §3）。
- 运行期检测/注入统一由 `RVP_JammingRuntime`（新静态工具类，服务端安全）承担：
  - `findActiveJammingAgainst(projectile)` → 返回命中的干扰设备信息（含 strength）；
  - 干扰效果按设备类型分派（本阶段仅 OPTICAL 注入随机错误瞄准点）。

未来扩展电磁干扰机的改动点（本阶段只留结构）：
- `RVP_JammingDeviceType` 增枚举项 + `interferesWith` 映射；
- `RVP_JammingRuntime` 的注入策略按类型分派；
- `BoneJammerConfig` 仅解析字段扩展，调用链不变。

## 3. 配置格式

复用已就绪的 `bone_modules`（旧 `hitbox_era` 兼容层保留不动）。骨块条目新增 `jammer` 子对象：

```json
"bone_modules": {
  "JAMMER0": {
    "damage_factor": 1.0,
    "min_damage": 50.0,
    "modules": ["jammer"],
    "jammer": {
      "type": "optical",
      "fov": 90,
      "range": 2000,
      "strength": 1.0,
      "facing_part": "turret",
      "facing_yaw": 0.0
    }
  }
}
```

字段语义：

| 字段 | 默认 | 说明 |
|---|---|---|
| `type` | `optical` | 干扰器类型，大小写不敏感（`optical` / `electronic`，未知回退 optical） |
| `fov` | 90 | 前方锥形**全角**（度）。半角 = fov/2，用于 `withinAngle` 判定 |
| `range` | 2000 | 检测距离（格/方块） |
| `strength` | 1.0 | 干扰强度倍率，作用于随机错误分量幅度 |
| `facing_part` | 无（车体朝向） | 探测方向跟随的部件 id（如 `"turret"`）。干扰锥随该部件旋转（取 `WeaponUnit.worldVec()`）；未配置/部件不存在时退回车体朝向。适合干扰机挂在炮塔骨块上的车辆（如 T84BM 的 ERA1/ERA3） |
| `facing_yaw` | 0.0 | 在 facing_part/车体朝向基础上叠加的水平偏置角（度，正值向左）。用于左右分布式干扰机：两侧锥各自偏转、覆盖不同扇区，一侧被击毁后该扇区失去覆盖、总干扰范围变小（部分损失功能） |

解析位置：`RVP_VehicleHitboxFactorManager.BoneModuleConfig` 增加 `@Nullable BoneJammerConfig jammer()` 字段与解析；`VehicleHitboxConfig.moduleByBoneName` 随之携带。

设备-失效关联：干扰机设备即「骨块的 JAMMER 模块」。运行期查询 `RVP_BoneModuleStateTable.isModuleActive(vehicleId, boneName, JAMMER)`，任一关联 JAMMER 骨块失效则该设备失效——与 ERA 失效完全正交，天然支持 ERA+JAMMER 叠加。

**左右分布式干扰机（部分损失功能）示例**：T84BM 炮塔 ERA 左右各一块（右：`ERA1`，左：`ERA3`），各挂一个干扰机并朝外侧偏转，两个锥覆盖不同扇区：

```json
"ERA3": {
  "damage_factor": 0.2,
  "min_damage": 100.0,
  "modules": ["era", "jammer"],
  "jammer": { "type": "optical", "fov": 60, "range": 2000, "strength": 1.0, "facing_part": "turret", "facing_yaw": 30.0 }
},
"ERA1": {
  "damage_factor": 0.2,
  "min_damage": 100.0,
  "modules": ["era", "jammer"],
  "jammer": { "type": "optical", "fov": 60, "range": 2000, "strength": 1.0, "facing_part": "turret", "facing_yaw": -30.0 }
}
```

- 两块都在：左锥（偏左 30°）+ 右锥（偏右 30°），总覆盖 ~120° 扇区
- 只击毁 `ERA3`（左）：右锥 `ERA1` 仍正常干扰，但左侧扇区失去覆盖，总范围变小
- 两个都击毁：完全失去干扰能力
- 每个骨块的 JAMMER 模块独立失效，互不影响

## 4. 检测链路（弹体侧，服务端）

干扰检测放在**被干扰弹体侧**（而非载具每 tick 广播），理由：SACLOS 导弹数量极少，仅在导弹处于 SACLOS 制导时查询，开销可控；语义上等价于「干扰机照射导弹」。

位置：`RVP_RuntimeSaclosGuidanceSource.evaluate()`（`guidance/runtime/RVP_RuntimeSaclosGuidanceSource.java` L50-127），在计算瞄准点（非半修正 L66 / 半修正 L123）前后插入：

```
1. 若弹体处于干扰冷却缓存期内（jammingExpireTick > tickCount）→ 直接使用缓存结果；
2. 每 JAM_SCAN_INTERVAL（5 tick）刷新：
   for vehicle in level 内 4096 格 AbstractVehicle:
       if 自身（shooterVehicle == vehicle 或 owner 的载具 == vehicle）→ 跳过
       bones = 该车所有活跃 JAMMER 骨块（RVP_BoneModuleStateTable.isModuleActive）
       for each 活跃骨块（取 BoneJammerConfig）:
           jammerPos = 车辆位置（OBB 中心或位置）
           前方轴 = facing_part 配置了部件 → 该部件 worldVec()（随部件转）
                  否则 → 车辆朝向（getLookAngle 或 yaw 方向向量）
                  再叠加 facing_yaw 水平偏置角（正值向左，左右分布式覆盖不同扇区）
           toMissile = 弹体位置 - jammerPos
           withinAngle(frontAxis, toMissile, fov/2) && dist <= range → 命中
       命中 → 记录 (vehicleId, strength, jammingExpireTick = tick + 缓存期)
3. 命中 → 注入干扰（§5），并触发提示消息（§6）
```

检测工具（现成，无需新写数学）：
- `RVP_GuidanceRuntimeGeometry.withinAngle(axis, toTarget, maxAngle)`（`guidance/RVP_GuidanceRuntimeGeometry.java` L103-109）；
- 载具朝向：`AbstractVehicle.getLookAngle()`（若有）或 yaw → `VectorUtil.rotToVec`（按项目惯例）。

缓存与开销控制：
- 弹体新增轻量字段：`jammingSourceVehicleId`（int，-1 无）、`jammingStrength`、`jammingExpireTick`；
- 每 5 tick 刷新一次，缓存期 5 tick；未命中时写入「无干扰」缓存，避免连续扫描。

## 5. 干扰注入（瞄准点随机偏移）

「随机错误操纵分量，幅度远大于射手输入」的等价实现：**把 SACLOS 瞄准点随机偏移**。SACLOS 弹体每 tick 朝瞄准点收敛，瞄准点被甩动后弹体会大幅偏离瞄准线，且幅度由偏移量决定，天然远大于正常操纵。

注入点：`RVP_RuntimeSaclosGuidanceSource.evaluate()` 返回 `RVP_GuidanceIntent.point(...)` 之前（非半修正 L68 与半修正 L126 两处）：

```java
if (jammed) {
    double offsetMag = offsetBase(15) * strength;   // 基准 15 格 × 强度倍率
    Vec3 jitter = randomPerpVector(dir, projectile, offsetMag);  // 复用本类现有工具 L138-144
    point = point.add(jitter);
}
```

- 复用本类已有的 `randomPerpVector`（L138-144），无需新写随机垂直向量。
- 半修正分支额外建议：把振荡器速度项注入一个大脉冲（如 `saclosVelVec += jitter * 0.5`），模拟干扰甩动，与瞄准点偏移叠加。
- **仅修改 SACLOS 源**，不触碰 `RVP_WireGuidanceSteering.applyFromDirection`（HITL 鼠标转向共用，避免误伤）。

## 6. 提示消息（服务端直发，无新网络包）

| 对象 | 文案 | 发送方式 |
|---|---|---|
| 被干扰者（导弹 owner，若为 ServerPlayer） | "导弹已被光电干扰" | `player.sendSystemMessage(Component.translatable("message.ywzj_rvp.saclos_jammed"))` |
| 干扰者（干扰机载具驾驶员） | "已成功干扰敌方导弹" | 同上，键 `message.ywzj_rvp.jam_success` |

防刷屏策略：
- 被干扰者：弹体首次进入干扰态时发一次（进入缓存期的那一 tick）；
- 干扰者：干扰机载具记录 `lastJamNotifyTick`，每 JAM_NOTIFY_INTERVAL（200 tick = 10s）至多提醒一次。
- 语言键新增到 `ywzj_rvp` 的 lang 文件（中文文案），并预留英文键。

## 7. 服务端安全（延续既有教训）

- 检测/注入/提示全在服务端路径：SACLOS evaluate 仅服务端执行（客户端不跑制导）；`RVP_BoneModuleStateTable` 为服务端侧表；消息用 `ServerPlayer.sendSystemMessage`。
- 不新增 mixin、不修改本体、不新增网络包。
- 客户端无任何新状态（被干扰后弹体的飞行路径由服务端速度同步驱动）。

## 9. 测试要点

1. 服务端纯 Forge 启动无崩溃（runServer）。
2. 配置解析：`bone_modules` + `jammer` 子对象被正确读取；缺省值生效。
3. 干扰行为：敌车 TOW（SACLOS 线导）进入干扰机前方 fov/range 内 → 导弹明显偏离；脱离范围后恢复。
4. 非自身过滤：本方发射的 SACLOS 不受干扰；干扰机车辆自己的导弹不受干扰。
5. 失效联动：干扰机 JAMMER 骨块被击毁 → 干扰停止；ERA+JAMMER 叠加骨块：ERA 被打掉仍干扰，JAMMER 被打掉停止干扰。
6. 提示消息：双方收到且不刷屏。
