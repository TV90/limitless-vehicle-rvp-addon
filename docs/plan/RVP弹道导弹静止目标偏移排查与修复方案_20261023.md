# RVP 弹道导弹静止目标偏移排查与修复方案

日期：2026-10-23。范围：当前工作区 YJ20 及复用 GPS/PRESET 弹道的导弹。

## 结论与证据边界

静止目标也会明显打偏。

本次发现三处可以解释该现象的代码问题：坐标追踪与预设弹道没有补偿机头响应滞后；末段水平近距判定会主动保留朝外的速度；近距离发射时，实体入口绕过冷发射切段保护。另有末段雷达接管条件与自由选靶风险。

已经通过真实 Java 数学函数及状态机的隔离测试验证，不是仅凭配置猜测。但尚未取得用户失败那一发的轨迹日志，不能把某个问题认定为每次脱靶的唯一原因，也不能给出实机发生概率。用户批准后已实施 Java 修复，见文末实施记录；以下第 1～5 节保留修复前诊断证据。武器 JSON、本体源码和模型资源均未修改。

## 1. 最符合一般静止目标偏移的控制路径问题

涉及：

- `RVP_GuidanceRuntimeMath.applyIntent`：仅 `entity != null && canUsePredictiveIntercept(context)` 时进入预测拦截控制器。
- `applyPresetBallistic` 和普通坐标追踪最终走 `applyResolvedAeroSteering`。
- `RVP_ProjectileMotion.applyAttackAngleSteering` 直接调用 `RVP_AttackAngleModel.solve`。

人话解释：弹体的“机头朝向”与“实际飞行方向”已经分开。让机头指向目标，并不代表速度能立即转向目标。YJ20 开启 60° 攻角上限，转向比例为 0.1，质量为 1500；攻角是机头与速度方向之间的夹角。当前坐标与预设弹道路径只把目标方向交给机头执行器，没有像实体预测拦截路径一样反算需要多少机头偏转才能获得希望的转弯量。

PIP 即预测相遇点：计算导弹与目标将在哪里相遇。对于静止实体，其相遇点仍是静止位置，但该分支额外使用 `RVP_PIPAttackAngleController` 补偿机头响应。因此同一静止位置，走“坐标”还是“已捕获实体”，实际控制效果也不同。

### 隔离实测

调用项目真实控制器，固定距离 200 格、速度 11 格/刻、转向比例 0.1、参考速度 11、密度倍率 1.1、质量 1500、攻角上限 60°；机头初始与速度一致。关闭推力、重力、阻力、扫描、角度门与碰撞，按相邻位置之间的线段计算首次交会最小距离，避免把跨帧采样误差算成脱靶。

| 初始飞行偏角 | 当前坐标路径误差（格） | 现有机头反解控制器误差（格） |
| --- | ---: | ---: |
| 2° | 4.029 | 1.019 |
| 5° | 10.091 | 2.795 |
| 10° | 20.224 | 6.273 |
| 15° | 30.403 | 10.219 |
| 30° | 60.684 | 31.772 |

这些数值证明控制响应存在明显差异，不代表实际落地误差。反解明显改善，但不能单独保证命中，尤其是高速、大偏角、接管较晚的情况。

建议：把“希望获得的飞行方向 → 可实际执行的机头指令”抽成通用控制入口，供实体目标、固定坐标、PRESET 方向生成器共用；固定点使用零目标速度，不以是否有 Entity 决定是否补偿。保留现有攻角、质量、动压约束和每刻只积分一次的规则。不要把速度直接掰向目标，也不要简单扩大转向比例掩盖问题。

PRESET 前视距离还需适配速度和响应时间。当前前视距离为 `min(maxAscentLead, 水平剩余距离×0.3)`，YJ20 最大只有 60 格；以 11 格/刻计算最多约 5.45 刻即到达追点，靠近目标时该时间进一步缩短。需要用连续轨迹测试确定前视窗口与俯冲提前量，不能直接承诺复用反解控制器就全部解决。

## 2. 过顶处理主动制造水平漂移

涉及：

- `RVP_GuidanceRuntimeMath.steerPresetTerminal`。
- `RVP_BallisticTrajectoryMath.resolvePresetBallisticDirection` 内重复的同一分支。

当前 `veryClose` 只看水平距离：`horizontalSqr <= max(1, speed²×0.25)`。速度为 11 时，水平距离不超过 5.5 格就触发，即使导弹仍高于目标数百格。越过目标时也进入相同分支。

该分支输出“沿原水平方向 0.25 + 向下 1”的方向，不是停止水平漂移。即使理想执行，下降 H 格还会沿原方向前进约 0.25H 格。

真实实体函数隔离验证：位置 `(-1,300,0)`、目标原点、速度方向 `(0.25,-1,0)`、速度 11，输出指令延长线与目标高度平面的交点是 `x=74`。越过目标后该函数仍命令向正 X 飞行。该例不含实际气动、重力与末段 ARH 接管，不能作为完整 YJ20 落点；它足以否定注释中“水平偏差受 speed×0.5 约束”的说法。

建议：

1. 取消仅凭水平很近就放弃横向修正的规则；综合三维距离、目标高度差、预计到达目标高度的时间。
2. 根据预计落点是否偏离目标，生成横向消偏指令，仍受现有气动能力限制。高空越过目标时继续受限修正，不能主动锁死向外速度。
3. 防止绕圈应根据三维交会、是否已错过可达窗口判定。真正无法命中时按明确的失败策略处理，不能用永久朝外漂移伪装防绕圈。
4. 实体和纯数学路径统一函数，避免两份实现修复不一致。当前 YJ20 未启用虚拟中段，且虚拟资格检查拒绝带末段制导的武器，因此不能把虚实交接认定为本次 YJ20 根因。

## 3. 冷发射保护被另一个切段入口绕过

`RVP_MissileEntity.tickGuidance` 先无条件调用 `getGuidancePhaseState().update(...)`，随后才调用父类制导。`RVP_GuidanceRuntimeController.tick` 中的 `shouldDeferPresetTerminalTransition` 保护执行得更晚，已来不及阻止切换；状态机只允许 MAIN → TERMINAL，不允许返回。

YJ20 的末段切换距离为三维 200 格；052D 发射挂架设置 20 刻冷发射、竖直速度 2 格/刻，武器点火延迟也是 20 刻。在点火前已经进入切换距离的发射中，可能提前进入主动雷达末段，失去预设弹道控制。

末段没有显式配置 `max_guidance_angle`，实际默认 60°，不会继承主段的 90°。竖直飞行与侧下方目标的夹角可超过 90°，此时普通末段制导角度门直接拒绝转向；惯性记忆点回退也仍经过这道门。

隔离测试确认：第 5 刻、100 格距离，无条件入口立即进入 TERMINAL；之后即便距离增至 250 格也不恢复。现有测试只检查保护函数返回值，没有检查实体先切段的调用顺序，因此现有测试通过并不能排除此缺陷。

建议：阶段更新统一到一个入口，导弹实体与通用控制器都使用同一保护判定。主动雷达目标管理必须读取本刻已统一确定的阶段。保护不仅看计时结束，还需验证预设主段已经初始化、当前姿态和目标几何允许交接，避免计时刚到就从竖直飞行切入仍无法接管的末段。新增测试必须覆盖实体调用顺序，不能只测纯布尔函数。

## 4. 末段雷达是条件放大项，尚需失败日志确认

ARH 指主动雷达制导，即导弹自己的雷达找实体目标。YJ20 在 200 格切入该阶段，配置 `max_lock_angle=30` 的实际搜索半角为 15°；跟踪转向角默认 60°。切段后 `RVP_GuidanceModelResolver.resolveTerminal` 关闭 PRESET，并不以雷达已经捕获为条件。

未捕获实体时，惯性回退继续追记忆坐标，仍走第 1 节中响应较弱的坐标路径。已经捕获时才能进入实体预测拦截路径。这可以解释看起来“有时准、有时不准”，但需要记录失败发是否真正捕获才能归因。

此外，无指定实体或失去中继支持后允许自由搜索，`scanRadarTarget` 按机头夹角与距离评分，没有用原 GPS 点限定候选区域。如果现场有其他载具，有转向其他实体的可能；只有单个静止目标时不能据此认定换靶。

建议：把雷达开机/尝试捕获与飞行控制权交接区分开。未捕获时保留可靠的坐标末段控制；捕获合格目标后再平滑交接。GPS 末制导是否允许攻击原坐标外的其他目标应明确为数据策略，保留普通主动雷达弹的既有自由搜索行为。不能全局取消搜索，也不能硬编码 YJ20 武器 ID。

## 5. 已排除及验证顺序

`gps_spread_radius=5` 不会给当前 YJ20 加散布：`RVP_BaseBullet.usesGpsTargetSpread` 只允许 `weaponKind == BOMB`；YJ20 是 MISSILE。`fire_data.spread` 也是 0。无需先改这两个值。

YJ20 的中段蛇形机动幅度为 30 格，是确定性横向追点偏移，不是随机抽签。有限转向能力下它会改变末段进入姿态，因此适合做开/关对照，但尚未单独证明其为根因。不要直接删除此能力作为最终修复。

推荐实施顺序：

1. 统一阶段更新与冷发射交接保护，修复可确定的调用顺序错误。
2. 统一坐标/PRESET 的机头响应补偿，并按速度、响应时间调整前视与俯冲时机。
3. 修复水平近距/越顶后朝外漂移的规则，合并实体与纯函数实现。
4. 调整雷达接管流程；按实机日志决定是否需要新增 GPS 末段候选区域配置。

验收矩阵：固定目标射程 100、200、300、500、1000、2000、4000 格；不同发射高度、方位和目标高差；GPS SINGLE/MULTI/RADAR；单目标/多目标；雷达可捕获/不可捕获；中段蛇形开启/关闭。记录主段与末段切换时刻、目标身份、原始 GPS 点、机头/速度方向、转向拒绝原因、首次交会距离、首次地形碰撞位置及最终目标高度交点。先要求静止单目标稳定收敛，再验证移动目标和反制行为。

单元测试应包括：高空近水平距离、过顶、200 格交接边界、冷发射窗口边界、捕获失败回退、同一静止坐标/实体的控制一致性、不同方位旋转等价性，以及速度×单刻运动线段的碰撞检查。完整修复后按仓库要求运行 `./gradlew build`，服务端冒烟每 10 秒检查日志，以 `Done` 为成功依据；命中精度仍需客户端实机验证。

## 实施记录（2026-10-23，用户已批准）

1. **切段入口统一**：`RVP_MissileEntity` 与通用控制器均调用 `updatePhase`。GPS PRESET 必须过冷发射/点火计时、初始化、下降及末段转向角限制，才检查配置的阶段切换条件；重复调用不能绕过保护。
2. **固定点控制补偿**：新增 `RVP_PointGuidanceController`，先按距离和速度生成逐刻收敛的速度方向，再通过共享 `RVP_PIPAttackAngleController` 反算机头指令。仍由原有攻角、转向能力、推力和阻力模型执行，每刻只积分一次。普通实体预测路径保留。
3. **统一预设弹道**：实体和虚拟数学路径共用 `RVP_BallisticTrajectoryMath`。前视、短射程抬升、俯冲提前量加入转向响应路程；蛇形机动在靠近末段时提前淡出，短射程可能被完全抑制。高空水平过顶继续修正真实三维偏差；只有目标已在后方且三维距离不超过一刻路程时保持原方向。
4. **雷达捕获前回退**：GPS PRESET 切到 ARH/AIR 后，在启用惯性回退且当前没有实体制导意图时继续使用 PRESET 坐标控制。没有更改雷达候选筛选或自由搜索规则，多目标换靶仍需实机记录判断。
5. **连续测试发现的额外根因**：机头穿过正上/正下方向时，同一物理方向可以有两组俯仰/偏航角表示。旧表示会把很小的转动误读成 180° 掉头。共享姿态模型现选择更近的等价角度，跨竖直方向时同步转换角速度，保留原有转向限制。
