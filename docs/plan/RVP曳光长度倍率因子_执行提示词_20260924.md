在 Minecraft 1.20.1 Forge 模组项目 ywzj_rvp 里，为机枪曳光长度新增一个可配置的倍率因子。

工作区根目录：D:\ywzj\ywzj
要改的模组源码在：D:\ywzj\ywzj\ywzj_rvp\src\main\java\org\ywzj\rvp\
不要改 D:\ywzj\ywzj\ywzj_vehicle\（本体，只读、永不修改）。

【背景：现状】

机枪曳光长度目前是渲染时算的，只能靠 projectile_data.velocity 间接影响。
文件 client/render/VehicleProjectileRenderLogic.java 的 renderBullet(...)：

    float width = Math.min(0.04f * bullet.getCaliber() / 7.62f, 0.2f);   // 粗细
    double trailLength = 0.3 * bullet.getDeltaMovement().length();       // 长度 = 0.3 × 当前速度
    double disToEye = bulletPosition.distanceTo(bullet.getStartPos());
    trailLength = Math.min(trailLength, disToEye * 0.8);                 // 上限 = 已飞距离 × 0.8
    poseStack.scale(width, width, (float) trailLength);

目标：新增 effects_data.tracer_length_scale（默认 1.0），使
    长度 = min(0.3 × 当前速度 × tracer_length_scale, 已飞距离 × 0.8)
硬要求：默认值必须让现有 39 把机枪的行为与改动前完全一致（不写该字段 = 1.0 = 现状）。

【必须完成的 4 处改动】

① weapon/data/RVP_EffectsData.java — 加字段与访问器

在现有 tracer_b 字段（约 134-135 行）后面加：

    /**
     * 机枪曳光长度倍率，默认 1.0（= 现状）。
     * 生效公式：长度 = min(0.3 × 当前速度 × 本倍率, 已飞距离 × 0.8) 格。
     * 0 表示不显示曳光；非法值（NaN/无穷）按 1.0 处理；上限 8。
     */
    @SerializedName("tracer_length_scale")
    private Float tracerLengthScale;

在现有 getTracerB()（约 298-300 行）后加：

    public boolean hasTracerLengthScaleOverride() {
        return tracerLengthScale != null;
    }

    /** 曳光长度倍率；未配置或非法返回 1.0，下限 0、上限 8。 */
    public float getTracerLengthScale() {
        if (tracerLengthScale == null
                || Float.isNaN(tracerLengthScale)
                || Float.isInfinite(tracerLengthScale)) {
            return 1f;
        }
        return Math.max(0f, Math.min(tracerLengthScale, 8f));
    }

写法请对齐同文件里 getMissileNativeTrailParticleScale() 的既有风格（null/NaN/Inf → 默认值 + 钳制）。

② entity/projectile/RVP_BulletEntity.java — 字段 + 读入 + getter

- 字段区（约 43-46 行，caliber / tracerR 那一组）加：
      private float tracerLengthScale = 1f;
- initFromWeapon(...)（约 66-78 行）里，紧跟 this.tracerB = effects.getTracerB(); 加：
      this.tracerLengthScale = effects.getTracerLengthScale();
- getter 区（约 288-302 行）加：
      public float getTracerLengthScale() {
          return tracerLengthScale;
      }

③ 同文件 — spawn data 同步（最容易出错，务必成对）

渲染是客户端行为，JSON 只在服务端解析，所以新值必须像 caliber / tracer* 一样随实体生成包下发：

- writeSpawnData(FriendlyByteBuf buffer)（约 304-318 行）末尾（buffer.writeBoolean(bounceOnVehicle); 之后）加：
      buffer.writeFloat(tracerLengthScale);
- readSpawnData(FriendlyByteBuf buffer)（约 320-338 行）末尾（bounceOnVehicle = buffer.readBoolean(); 之后）加：
      tracerLengthScale = buffer.readFloat();

两个方法必须同时改，且新增位置在两端的相对顺序完全一致。
只改一侧会让其后所有字段错位（bounceLeft 等会读出垃圾值）。改完请逐行对照两边的读写顺序。

④ client/render/VehicleProjectileRenderLogic.java — 乘倍率

把 renderBullet 里那两行改成：

    double trailLength = 0.3 * bullet.getDeltaMovement().length() * bullet.getTracerLengthScale();
    double disToEye = bulletPosition.distanceTo(bullet.getStartPos());
    trailLength = Math.min(trailLength, disToEye * 0.8);

上限 disToEye * 0.8 保持不变（否则出膛瞬间就会出现一条长尾巴）。

顺手建议（可选）：把公式抽成包级静态方法便于单测：

    static double resolveTracerLength(double speed, double travelDistance, float scale) {
        double len = 0.3 * speed * scale;
        return Math.min(len, travelDistance * 0.8);
    }

并在 renderBullet 里调用它。
