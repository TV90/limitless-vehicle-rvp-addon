## 一、三个字段的真实语义（源码确认，非推测）

### 1. `defense_stats.damage_threshold` —— **小伤害免疫门槛**（不是减伤百分比）

本体 `DamageSystem.hurt` 载具段（`:74-89`）：

```java
if (amount < vehicle.defenseStats.damageThreshold) {
    amount = 0.1f;                       // ← 低于阈值：固定只吃 0.1
} else {
    scale = …核心距离衰减…;               // ← 达到阈值才走正常衰减
    amount *= scale;
}
```

- **阈值以下 → 固定 0.1 伤害**（相当于免疫，但不是 0，留了"擦伤"）。
- 达到阈值才进入正常的**核心距离衰减**（命中点离主 OBB 核心越远、伤害越低，最低 0.2×）。
- **注意副作用**：低于阈值时**不应用核心距离衰减**，直接 0.1 —— 所以调高阈值只会"扩大免疫范围"，不会让"打中之后更肉"。

**本体默认值是 `50`**（`DefenseStats.damageThreshold = 50`）。包里地面载具统一显式填 `15`，**比默认更脆**。

### 2. `defense_stats.impact_multiplier` —— **撞击（碰撞）伤害倍率**

本体 `DamageSystem.impactHurt`（`:138-142`）：
`damage = 0.5 × 质量 × (速度差×20)² × impactMultiplier`

**本体默认 `0.1`**。现状：**全部 16 台空中载具都配了**（固定翼 `3`、旋翼 `2`），**18 台地面载具一台都没配** → 全部吃默认 `0.1`。
也就是说地面载具的撞击伤害只有空中载具的 **1/30**。若你希望"装甲车撞墙/互相撞也掉血"，需要显式配这个字段。

### 3. `armor_min_damage` / `armor_max_damage` —— **RVP 侧更精细的装甲层**（全包 0 台使用）

RVP `RVP_VehicleHurtScalingHandler.applyArmor`（`:296-319`）的结算顺序：

```
×命中箱系数(≤1 的减伤)  →  −armor_min_damage  →  保底 0.1
  →  ×命中箱系数(>1 的增伤)  →  封顶 armor_max_damage  →  再保底 0.1
```

- `armor_min_damage`：**固定减伤**（先吃命中箱减伤，再减这个定值）→ 等效于"小伤害免疫 + 中等伤害削一刀"。
- `armor_max_damage`：**单发伤害上限**（在全部系数算完后封顶）→ 防"一发秒杀"。
- **与 `damage_threshold` 互斥**：`effectiveThreshold()`（`:278-285`）—— 只要配了任一 `armor_*`，本体的 `damage_threshold` 被屏蔽为 `0.1`，**只有装甲层生效**。

> 现状：**全包 0 台使用**。也就是说这套"固定减伤 + 单发封顶"的模型目前完全没启用。

## 四、调参用的"阈值分档锚点"

下表是**事实性的分档边界**（由武器伤害数据算出），不是平衡建议：

| 阈值落点 | 会免疫掉 | 备注 |
| --- | --- | --- |
| `≤ 5` | 无 | 最低档武器就是 5 |
| `6 ~ 9` | 7.62 机枪、8 档近炸 | 只挡步枪弹 |
| `10 ~ 11` | 上列 + 12.7 重机枪、10 档机炮弹 | **10 档不免疫 10（`<` 是严格小于）** |
| **`12 ~ 15`** | 上列 + 10/11 档全部（13 条） | **当前全包所处档位** |
| `16 ~ 20` | 上列 + ucav(15) | 但仍免疫不了 20 档机炮 |
| `21 ~ 30` | 上列 + **20mm 级机炮 12 条** | 跨过这条线会"机炮全面失效"，影响很大 |
| `31 ~ 40` | 上列 + 30 档（GAU-12 / 2A38 / AHEAD / M791） | 连 30mm 机炮都免疫 |
| `41 ~ 50` | 上列 + 40 档（gsh_30_1）+ 50 档（2A42 / 火箭弹） | 连火箭弹都免疫，一般不合理 |
| `> 50` | 逼近"只吃导弹/航弹" | 已超过本体默认 50 |

**三条容易踩的坑**：

1. **阈值是严格 `<` 判断**：`damage_threshold: 10` **不能**免疫伤害正好 10 的武器，要 `11` 才行。
2. **调高阈值不会让载具"变肉"**，只是扩大免疫清单；打中的伤害该多少还是多少。想让载具整体更耐打应该调 `max_health`，或启用 `armor_min_damage`。
3. **一旦配 `armor_min_damage` / `armor_max_damage`，`damage_threshold` 会被完全屏蔽**（`effectiveThreshold` 返回 0.1）。两者不要同时依赖。

### 7.2 ★ 为什么是「写 `0.1`」而不是「删掉键」

`armor_*` 与 `damage_threshold` 的互斥**是真实现的，但只覆盖一半路径**：

| 环节 | 实现 |
| --- | --- |
| 判定 | `RVP_VehicleHitboxFactorManager.isArmorConfigured()`（:146-148）：`armor_min` 或 `armor_max` 任一 > 0 |
| 预测 | `RVP_VehicleHurtScalingHandler.effectiveThreshold()`（:278-285）：配了装甲 → 返回 `DAMAGE_FLOOR = 0.1`，否则返回 `defenseStats.damageThreshold` |
| 重放屏蔽 | `hurtWithShieldedThreshold()`（:330-343）：把**本实体**的 `defenseStats` 字段临时指向 `damageThreshold = 0.1` 的副本，`finally` 还原；**只换引用**，不动按载具 ID 全局共享的那个对象 |

**但 RVP 弹体自己的路径没有被屏蔽**：

```
RVP_BaseBullet:3263   pushSkip(载具)
RVP_BaseBullet:3268   EntityUtil.hurt(...)
  → AbstractVehicle.hurt:653   post VehicleAttackEvent
  → RVP handler:99             shouldSkip → return   ← 注意：不取消事件
  → 本体 DamageSystem.hurt     读到【真实的】defenseStats.damageThreshold
```

推论：

1. **若删掉键** → `DefenseStats.damageThreshold` 回落到 Java 默认 **50**（`BaseVehicleDataPojo:28` 默认实例 `new DefenseStats()`）→ 弹体路径上"最终伤害 < 50 全变 0.1"：**40 伤的 gsh_30_1、50 伤的 m142_m30 火箭弹统统打不动**，只有 80 档以上才有效。
2. **写 `0.1`** → 本体那个判断永不触发，两条路径行为完全一致（`0.1` 正是 RVP 自己屏蔽时用的 `DAMAGE_FLOOR`）。

> 附带说明：迁移前"机炮打不动坦克"的体感，**纯粹就是阈值 15 在 RVP 算完的最终伤害上又滤了一遍**（因为当时没有车配装甲，不存在叠加）。
