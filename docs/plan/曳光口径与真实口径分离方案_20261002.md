# `effects_data.caliber` 与曳光口径字段分工（最终实施记录）

> 状态：**已实施并验证**（2026-10-02）。最终语义以本文“最终实施规则”为准；文中原“真实身管口径迁移”内容已被后续用户要求取代，仅保留作历史方案记录。
> 目标读者：执行代码改动的 agent
> 触发来源：需要同时表达炮口烟/殉燃阈值、曳光宽度和曳光长度，避免三个视觉消费点混用字段。

## 最终实施规则

| 字段 | 当前语义 | 当前消费点 |
|---|---|---|
| `effects_data.caliber` | 弹体口径，单位毫米；缺省或非正值回退 `7.62` | 炮口烟分档：`<45 mm` 灰色即时烟，`>=45 mm` 白色延迟烟；殉燃炮口喷火阈值：仅 `>=45 mm` 的弹道火炮允许 |
| `effects_data.tracer_caliber` | 曳光口径/弹体视觉口径，单位毫米；缺省或非正值回退 `caliber`，再回退 `7.62` | RVP 弹体 Renderer 的曳光宽度 |
| `effects_data.tracer_length_scale` | 曳光长度倍率，默认 `1.0`，有效范围 `0..8` | RVP 弹体 Renderer 的曳光长度 |

本次实现没有要求把 `caliber` 批量改成真实身管口径，也没有修改载具包资源；配置值仍按当前弹体口径语义解释。

---

## 一、背景与问题

RVP 武器 JSON 的 `effects_data.caliber` 恢复为**弹体口径/弹体直径**语义，不承担真实身管口径迁移。例如：

| 武器 | 弹名 | 实际身管口径 | 现填 `effects_data.caliber` |
|---|---|---|---|
| `t90m_3bm59` 等 | 3BM59 APFSDS | **125 mm** | **24.765** |
| `vt4_dtc10` | DTC-10-125 APFSDS | **125 mm** | **24.765** |
| `052d_hpj38` | H/PJ-38 130MM | **130 mm** | **40.765** |
| `ddg51_mk45` | MK-45 MOD4 127MM | **127 mm** | **40.765** |
| `052d_hpj12` | H/PJ-12 30mm | **30 mm** | **15.24** |
| `lav25_apfsds` | M919 25mm | **25 mm** | **19.05** |

这不是"填错了" —— 代码注释里写得很明确（`RVP_DelayedMuzzleSmokeEmitter` 的 javadoc）：

> RVP 的 `effects_data.caliber` 是**弹体直径**，不是身管口径；例如 T-90M 的 125 mm 主炮弹体配置为 24.765 mm。

24.765 这类值就是当前配置中的弹体口径值。炮口烟和殉燃阈值按该字段数值执行；如果需要单独调整曳光宽度，则使用 `tracer_caliber`，不再复用 `caliber`。

**最终诉求**：炮口烟/殉燃继续消费 `caliber`，曳光宽度消费 `tracer_caliber`，曳光长度消费 `tracer_length_scale`。

## 二、当前机制

### 2.1 字段定义

`src/main/java/org/ywzj/rvp/weapon/data/RVP_EffectsData.java`：

```java
/** 机枪弹口径覆盖，单位毫米，默认 null；未配置或非正值时按 7.62。 */
@SerializedName("caliber")
private Float caliber;

@SerializedName("tracer_r") / tracer_g / tracer_b          // 曳光颜色
@SerializedName("tracer_length_scale")                       // 曳光长度倍率（已存在）
```

getter：

```java
public boolean hasCaliberOverride() { return caliber != null; }

public float getCaliber() {
    return caliber != null && caliber > 0f ? caliber : 7.62f;   // 默认回退 7.62
}
```

### 2.2 消费点（当前实现）

| # | 文件 | 用途 |
|---|---|---|---|
| 1 | `client/visual/vehicle/RVP_MuzzleSmokeEmitter.java` | 读取 `effects_data.caliber`，负责小口径灰烟路径 |
| 2 | `client/visual/vehicle/RVP_DelayedMuzzleSmokeEmitter.java` | 读取 `effects_data.caliber`，负责 `>=45 mm` 白烟延迟路径 |
| 3 | `client/visual/cookoff/RVP_WreckCookoffResolver.java` | 读取 `effects_data.caliber`，传入殉燃口径策略 |
| 4 | `client/render/VehicleProjectileRenderLogic.java` | 读取 `bullet.getTracerCaliber()`，计算曳光宽度；长度另读 `tracerLengthScale` |

其中 #3 的下游 `RVP_WreckCookoffWeaponPolicy.accepts(...)` 使用 `45 mm` 硬阈值：

```java
return ballistic && Double.isFinite(caliber) && caliber >= 45.0; // ≥45 mm 才允许炮口喷燃
```

### 2.3 容易混淆的另一个 `caliber`（★ 不要动）

- **本体顶层 `BaseVehicleWeaponData.caliber`**（默认 `5.8f`）→ 传给 `BulletEntity` / `MissileEntity` → 影响**弹道线宽**（`BulletEntityRenderer`）、**弹孔大小**（`BulletHoleParticle`）、**导弹尾焰与屏幕震动**（`MissileEntity`）。
- `VehicleProjectileRenderLogic` 现在通过 RVP 弹体的 `getTracerCaliber()` 读取 `effects_data.tracer_caliber`，不再使用 `bullet.getCaliber()` 计算曳光宽度。
- `RVP_BulletEntity.getCaliber()` 仍保留给弹体物理/本体弹孔等既有逻辑；它与 `getTracerCaliber()` 是两个独立 getter。
- `client/render/RVP_BedrockProjectileEntityRenderer.java` 中与导弹模型缩放相关的本体 `caliber/1000` 逻辑不属于本次字段分工。

> 结论：`effects_data.caliber` 不参与 RVP 曳光宽度计算；它只负责炮口烟分档与殉燃口径阈值。`tracer_caliber` 负责曳光宽度，`tracer_length_scale` 负责曳光长度。

## 三、目标

1. 使用 `effects_data.caliber` 表达当前弹体口径，并恢复炮口烟/殉燃消费。
2. 新增并启用 `effects_data.tracer_caliber`，只承接 RVP 曳光宽度/弹体视觉口径。
3. 保持 `effects_data.tracer_length_scale` 作为曳光长度倍率。
4. 未配置 `tracer_caliber` 时回退到 `caliber`，保证旧数据仍有合理曳光宽度。

## 四、代码改动清单

### 4.1 `weapon/data/RVP_EffectsData.java`

**(1) 新增字段**（紧跟 `caliber` 之后）

```java
/**
 * 曳光/弹体视觉口径覆盖，单位毫米，默认 null。
 * 未配置或非正值时回退 {@link #caliber}，再回退 7.62。
 * 仅供 RVP 弹体 Renderer 计算曳光宽度，不参与炮口烟、殉燃或弹道物理判定。
 */
@SerializedName("tracer_caliber")
private Float tracerCaliber;
```

**(2) 新增 getter 与判定**

```java
public boolean hasTracerCaliberOverride() {
    return tracerCaliber != null;
}

/** 曳光/弹体视觉口径：优先 tracer_caliber，其次 caliber，最后 7.62。 */
public float getTracerCaliber() {
    if (tracerCaliber != null && tracerCaliber > 0f) {
        return tracerCaliber;
    }
    return getCaliber();
}
```

**(3) 保持 `caliber` 的弹体口径 javadoc**

```java
/**
 * 弹体口径，单位毫米，默认 null；未配置或非正值时按 7.62 回退。
 * 炮口烟与殉燃阈值直接消费该字段；曳光宽度另由 tracerCaliber 消费。
 */
@SerializedName("caliber")
private Float caliber;
```

### 4.2 消费点字段分工

| # | 文件 | 当前实现 |
|---|---|---|
| 1 | `RVP_MuzzleSmokeEmitter.java` | `sanitizeCaliber(rvpData.getEffectsData().getCaliber())`，低于 45 mm 走灰烟 |
| 2 | `RVP_DelayedMuzzleSmokeEmitter.java` | `rvpData.getEffectsData().getCaliber()`，达到 45 mm 走白烟延迟 |
| 3 | `RVP_WreckCookoffResolver.java` | `rvp.getEffectsData().getCaliber()`，交由 `RVP_WreckCookoffWeaponPolicy` 判断 `>=45 mm` |
| 4 | `VehicleProjectileRenderLogic.java` | `bullet.getTracerCaliber()` 计算曳光宽度；`bullet.getTracerLengthScale()` 计算曳光长度 |

⚠️ 炮口烟和殉燃必须继续读取 `caliber`，曳光宽度不能回退到 `bullet.getCaliber()`。三条最终规则必须保持一致：
- `caliber <45 mm`：灰色即时烟，且不触发炮口喷燃
- `caliber >=45 mm`：白色延迟烟，且允许弹道火炮炮口喷燃
- `tracer_caliber`：只改变曳光宽度；`tracer_length_scale`：只改变曳光长度

**(4) 注释状态**：已同步说明 `effects_data.caliber` 是弹体口径，`effects_data.tracer_caliber` 只用于曳光宽度；炮口烟与殉燃路径不再引用曳光口径字段。

## 六、顺序、兼容性与影响

### 6.1 当前字段兼容关系

| 顺序 | 结果 |
|---|---|
| 只配置 `caliber` | ✅ 炮口烟/殉燃读取该值；曳光宽度回退读取该值 |
| 同时配置 `caliber` 与 `tracer_caliber` | ✅ 炮口烟/殉燃使用 `caliber`，曳光宽度使用 `tracer_caliber` |
| 未配置 `tracer_caliber` | ✅ 自动回退 `caliber`，再回退 `7.62` |

### 6.2 历史阈值对比（仅供理解旧方案）

旧方案曾使用 `caliber >= 20`，当前实现已统一改为 `effects_data.caliber >= 45`：

| 组 | 原口径值 | 阈值结果 | 改真实值后 | 是否变化 |
|---|---|---|---|---|
| 坦克炮弹（24.765） | 24.765 | ✅ true | 105/120/125 | 不变 |
| 40.765 组（130/127） | 40.765 | ✅ true | 130/127 | 不变 |
| 30 组（M61A1 实际 20） | 30 | ✅ true | 20 | 不变 |
| **15.24 组**（20~35 mm） | 15.24 | ❌ false | 20/25/30/35 | ⚠️ **变 true** |
| **19.05 组**（25~30 mm） | 19.05 | ❌ false | 25/30 | ⚠️ **变 true** |
| 7.62 组 | 7.62 | ❌ false | 7.62 | 不变 |
| 11.43（12.7 mm） | 11.43 | ❌ false | 12.7 | 不变 |

⇒ 当前不再使用上述 `>=20` 判定，也不把 `tracer_caliber` 用作炮口烟或殉燃阈值。

### 6.3 向后兼容

- `tracer_caliber` 未配置 ⇒ `getTracerCaliber()` 回退 `caliber` ⇒ **存量未迁移数据零影响**
- 其它模组/数据包若只配 `caliber` 而不配 `tracer_caliber`，视觉行为与今天一致
