# Mi-28 机炮自动提前量修复记录（2026-09-23）

## 1. 问题与根因

- 高速固定翼、地面目标的预测点偏后：火控实际使用经过 EMA 的世界提前点，稳定滞后约
  1.17～3.35 tick；目标速度越高，空间误差越大。
- 低速地面目标弹着集中于车体下侧：Mi-28 火控运行在根 `sighting_system`，实际 2A42
  挂载于子 `auto_cannon`；旧解算从根观察点起算，而弹体从子炮口生成，存在约 1.3 格
  垂直视差。
- 地面目标 Y 预测不稳：旧速度估算以 65% 权重混入 `getDeltaMovement()`，其中包含悬挂、
  重力与接触修正的垂直分量。

## 2. 已实施改动

1. `RVP_MachinegunLeadSolver` 从当前武器对象解析实际 `WeaponUnit`，解算炮口、继承速度和
   弹体生成链统一使用实际挂载单元。
2. `RVP_BallisticLeadFireControlExecutor` 的方向原点同步改为实际发射单元炮口；仍通过根火控站
   调用本体递归瞄准，不修改本体。
3. `RVP_MachinegunLeadState` 将控制解和显示解拆开：
   - 火控保留世界提前点 EMA（`alpha=0.23～0.46`）以抑制锁定点和网络位置抖动；
   - 按 `(1-alpha)/alpha` 计算 EMA 理论滞后 tick，并直接补偿 115%；
   - 匀速情况下消除全部 EMA 滞后，并额外前置原理论滞后的 15%，约为 0.18～0.50 tick；
   - HUD 只在相邻两份 EMA 相位补偿解之间按 `partialTick` 插值，与火控使用同一控制点；
   - 不恢复固定米数前移或按目标朝向偏置。
4. 目标速度使用最多 5 个 tick 的目标中心实位移历史：
   - 空中目标以实位移为主、实体运动速度为辅；
   - 着地目标 XZ 只采用实位移，Y 也只采用实位移并限制到 ±0.25 格/tick；
   - 近零速度继续使用 0.01 格/tick 死区。
   - 历史表按执行线程隔离，避免单机客户端与集成服务端并发访问同一弱引用表。
5. AHEAD HUD 测距原点同步改为实际发射单元炮口。
6. 复用 `/rvpdebug weaponorigin verbose on` 诊断开关，新增 `lead-solution` 快照；默认关闭，
   不产生运行时日志。实机测试后执行 `/rvpdebug weaponorigin verbose off`。

## 4. Mi-28 实机回归矩阵

弹着评估采用 30～50 发点射的弹着质心，不以单发命中判断；2A42 自带散布应单独看待。

| 目标 | 距离 | 速度 | 重点观察 |
|---|---:|---:|---|
| 静止地面载具 | 100/200/300 格 | 0 | 弹着质心不再稳定落于履带/车底 |
| 横向地面载具 | 100/200/300 格 | 0.1/0.5/1.0 格/tick | 高速时不再系统性落后 |
| 直线固定翼 | 150/300/500 格 | 0.5/1.0/2.0 格/tick | 预瞄圈与弹着质心是否仍偏后 |
| 转弯固定翼 | 150/300 格 | 分别左/右转 | 仅记录转弯模型残差，不与匀速直线混算 |

同时覆盖 Mi-28 悬停与自身平移、稳定模式与辅助模式。若直线匀速目标仍存在稳定偏后，开启上述
诊断收集一段锁定与开火日志，先评估 EMA 的 115% 相位补偿比例；若仍存在独立于 EMA 的稳定网络
管线延迟，再按实测值补偿 `速度 × 延迟 tick`。不得恢复固定米数前移或按目标朝向偏置。
