## 一、本会话已完成（按主题）

### 1. 弹间直击拦截修复（`collision_box_size` 未生效根因，已实机验证✓）
`collision_box_size` 参数本身无错——**断点是直击候选过滤 `entity.isPickable()`**：基类恒 false 且 AmmoEntity/RVP 全系未覆写 → RVP 弹药被直击候选整类剔除，命中结算对导弹从不执行（0.7 只兑现近炸 +0.32m）。修复：候选过滤放开 `isInterceptableEnemyAmmo`（仅服务端 + canDamageEntity + `RVP_EcmIff.areVehiclesFriendly` 敌对判定，防己方弹幕自伤）；`handleEntityImpact` 命中敌对弹药即以其自身引信语义引爆 + 双方 discard。**用户确认生效。**

### 2. 残件"击毁前状态快照"自动隐藏（零 Mixin，偶发不触发随访中）
JS `pose.hideBone`（scale 0）已被既有 `BoneTreeInstanceInvisibleBoneMixin` 统一转写为源车实例 `BoneState.visible=false`——读源车实例 visible 集即涵盖全部隐藏来源，**无需解析 JS**。实现：`RVP_ClientWreckHiddenBonesCache`（残件 id→骨序号 Set；首次渲染**借源**=找同 vehicleId+已击毁+最近源车残骸，显式排除其它 VehiclePart；拍 `getBoneIndexes()` 中 visible==false 且非距离 LOD 假值）+ `RVP_VehiclePartRender` 与静态 `rvp_part_hidden_bones` 取并集应用。**⚠️ 用户报"偶发不触发、又自行恢复"——疑似首拍时机不稳定**（首帧借源时源车未进渲染集合/JS 首帧未跑，拍得空集即缓存不再重试）；复发时修法：空集不缓存、次帧重试；诊断日志实现可回溯 `b72bce1a`（已撤销）。

### 3. 自绘炮口烟接入热成像缓冲（用户实测"热成像下远处载具覆盖在烟之上"）
根因：炮口烟三轮深度修复后脱离 ParticleEngine 自绘于 AFTER_PARTICLES，而本体热成像=把热源重画进 thermal_buffer——自绘烟两条既有路径（登记表/引擎白名单捞取）都覆盖不到、也无 renderThermal 入口，**热缓冲里没有烟**。修复：`RVP_WreckMuzzleSmokeSelfRenderer.renderThermal(event)`（温压/HBM 同模式：自包含补视图+热成像白热混合+距离降序+贴图分组重画，target 还原由通道兜底）+ `RVP_ThermalParticleChannel` 追加调用。烟越浓越热，正确遮挡后方实体热像。

### 4. 战术地图点击 BVR 目标"转塔+等待锁定"链修复（pending 宽限）
考古结论：无单点改坏 diff——`tickPendingRadarLock` 的"getEntity(pendingId)==null 即同 tick 清 pending"自 07-06 如此，依赖目标在 512 格原生跟踪范围内；`0925a52d` 收紧克隆新鲜度后 512 外更脆 + 关图/80t assist 过期链断 + bukm3 SARH 无 TWS 补锁兜底。修复：pending 宽限 200t（`RVP_WeaponLockStateTable.PendingLockGrace`）——宽限内按 id 从整车雷达探测表捕获落锁（`radarCurrentlyDetects` 按 id 判，克隆/原生均可），未捕获用 `setFocusLockPos(最后已知位置)` 维持转塔；assist 重发刷新宽限。
