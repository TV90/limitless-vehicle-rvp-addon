## 一、背景与问题

RVP 的「载具超视距可见性」由一张 **观察者类型 × 目标类型** 矩阵控制，实现在上游作者 `fishking0721` 2026-08-18 的提交 `f6c0d8bf`（载具实体超远距离渲染重构·阶段 A）。

分类靠 `instanceof` 判断类，**没有船的专用分类**：

```java
public static Optional<VehicleCategory> classify(@Nullable AbstractVehicle vehicle) {
    if (vehicle == null || vehicle instanceof VehiclePart) return Optional.empty();
    if (vehicle instanceof RotaryWingVehicle) return Optional.of(VehicleCategory.HELICOPTER);
    if (vehicle instanceof FixedWingVehicle)  return Optional.of(VehicleCategory.AIRCRAFT);
    return Optional.of(VehicleCategory.GROUND_VEHICLES);   // ← 船也被兜底到这里
}
```

枚举里只有四类：`helicopter` / `aircraft` / `ground_vehicles` / `walking_players`。
**`ywzj_vehicle:vessel_vehicle`（舰船）被兜底归入 `ground_vehicles`。**

后果：想「只让船参与超视距可见性」时，只能连地面车辆（坦克 / 轮式）一起放行，无法精准控制。

> 说明：作者当年重构时，本体大概率尚无 `VesselVehicle`（现在已有：`org.ywzj.vehicle.entity.vehicle.VesselVehicle`），因此是历史遗留的兜底行为，非设计取舍。

## 二、现状机制（执行前必须理解，否则会改错地方）

### 2.1 一份授权，两个下游

```
selectTargets()   ← 矩阵 allowedTargetTypes + 距离 + 数量 三重裁剪
   │
   ├─→ S2CRemoteVehicleVisualSnapshot entries → 客户端 PROXIES → 【超视距渲染】
   │
   └─→ authorizationUnion → authorizedByDimension
                              → RVP_RemoteVehicleChunkLeaseService（提交区块 Ticket，保加载）
                                 → 服务端持续持有该实体
                                    → 本体 AllEvents 广播（全量已加载载具）
                                       → 客户端 LocalVehiclePlayer.serverEntities 克隆
                                          → 【雷达可见 / 可锁定】
```

**结论：矩阵同时决定「雷达能否扫到」和「能否渲染」。** 目标通不过矩阵 ⇒ 无租约 ⇒ 区块卸载后服务端不再持有该实体 ⇒ 雷达扫不到。

### 2.2 距离与数量硬条件（`selectTargets`）

| 条件 | 值 | 说明 |
|---|---|---|
| 下限 | `NATIVE_TRACKING_DISTANCE = 512` 格 | ≤512 走原版实体追踪，不进本机制 |
| 上限 | `maxDistance` 默认 4096 格 | |
| 数量 | `maxTargetsPerPlayer` 默认 32 | 按距离升序截断 |
| 观察者 | `mode == VEHICLE_OCCUPANTS/RADAR_DETECTED` 且 `observerCategory == null` | 直接返回空 ⇒ **必须坐在载具里** |
| 排除自身 | `entityId != observerVehicleId` | |

### 2.3 渲染的第二道独立门（与雷达无关）

`minHeightAboveGroundWithoutDH`（默认 25 格）**只在客户端** `RenderPolicy.allowsHeightAboveGround()` 被消费：

```java
return dhRenderingEnabled || 阈值 == -1 || heightAboveGround >= 阈值;
```

- `radar/` 目录零引用 ⇒ **只挡渲染，不挡雷达**
- ⚠️ 装了 DH 且开启地形渲染时 `dhRenderingEnabled == true` ⇒ 该门直接放行

### 2.4 区块租约

`RVP_RemoteVehicleChunkLeaseService`，`chunkLoadingMode` 默认 `VISIBLE_TARGETS`（为「至少向一名玩家授权」的载具提交租约）；`maxChunkLoadedVehiclesPerDimension` 默认 32。

## 三、目标

新增 **`ships`** 分类，使舰船成为**独立可配**的观察者与目标类型：

1. 船作为观察者：行键 `ships`
2. 船作为目标：token `ships`
3. **默认行为与改动前逐项等价**（不改变任何现有服务器的实际表现）
4. 从而可以只放行「船 → 船」，满足「舰船之间超视距雷达可见」，而不牵连地面车辆

## 四、改动清单（共 2 个 Java 文件，均为 `src/main/java/org/ywzj/rvp/`）

**(1) 补 import**

```java

```

**(2) 枚举新增 `SHIPS`（严格小写 token）**

位置：`GROUND_VEHICLES` 之后、`WALKING_PLAYERS` 之前。


**(3) `classify()` 增加船分支**

在 `FixedWingVehicle` 分支之后、兜底 `return GROUND_VEHICLES` 之前插入：

```java

    return Optional.of(VehicleCategory.SHIPS);
```

**(4) 同步类注释**

**(5) 顺带更新注释中的数量描述**（可选）：`normalizeConfiguredTypes` 的「集中解析并去重三类配置 token」→「四类」。

## 五、兼容性分析（逐个对照，务必核对）

### 5.1 默认行为与改动前等价

| 关系 | 改动前 | 改动后 | 等价？ |
|---|---|---|---|
| 直升机/固定翼 能否看到船 | 能（`all` 含 `ground_vehicles`） | 能（`all` 含 `SHIPS`） | ✅ |
| 船 能否看到直升机/固定翼 | 能（原属 `ground_vehicles`，该行允许两者） | 能（`ships` 行允许两者） | ✅ |
| 地面车辆 能否看到船 | 否（自己行不含 `ground_vehicles`） | 否（`ground_vehicles` 行**不加** `SHIPS`） | ✅ |
| 步行玩家 能否看到船 | 否 | 否（**不加** `SHIPS`） | ✅ |
| 船 能否看到地面车辆 | 否 | 否 | ✅ |
| 船 能否看到船 | 否 | 否（`ships` 行默认不含 `SHIPS`） | ✅ |

⇒ **默认矩阵严格等价**，仅"归属类别"换名 —— 这是本方案能安全默认交付的前提。

### 5.2 必须知晓的行为变化点

- ⚠️ **`ground_vehicles` 不再覆盖船**。此后配置 `ground_vehicles = [..., ground_vehicles]` 只影响坦克/轮式，**不影响船**。船必须由 `ships` 行单独放行。
- ⚠️ **老配置文件**（`config/ywzj_rvp-common.toml`）该段没有 `ships` 键，`defineListAllowEmpty` 会在加载时**自动补写默认值**。启动一次后复查文件，确认多出 `ships = ["helicopter", "aircraft"]`。
- ⚠️ **编译前提**：RVP 依赖的本体版本必须能解析 `VesselVehicle`。若 `compileJava` 报找不到类，说明本体依赖过旧，需先同步本体依赖，**不要**用字符串/注册名等迂回手段绕过（违反"禁止按车型/资源 ID 分类"的既定约束）。
- ⚠️ 改造后**必须重新构建 RVP**；仅数据包热载不够。

## 六、达到目标效果所需配置（Java 侧改完之后）

**需求：舰船之间在超视距下能被雷达扫到，但不做（或尽量少做）超视距渲染。**

`config/ywzj_rvp-common.toml`：

```toml
[remoteVehicleRendering.visibilityByObserverVehicleType]
    helicopter      = ["helicopter", "aircraft", "ground_vehicles", "ships"]
    aircraft        = ["helicopter", "aircraft", "ground_vehicles", "ships"]
    ground_vehicles = ["helicopter", "aircraft"]
    ships           = ["helicopter", "aircraft", "ships"]     # ← 关键：船互相可见 → 有租约 → 雷达框
    walking_players = ["helicopter", "aircraft"]
```

配套（保持不动即可）：

```toml
minHeightAboveGroundWithoutDH = 25    # 只挡渲染：水面舰船 AGL≈0 < 25 ⇒ 不画代理
chunkLoadingMode = "VISIBLE_TARGETS"  # 默认值，必须有租约
maxChunkLoadedVehiclesPerDimension = 32
```

⇒ 船被保区块（服务端持有 ⇒ 本体广播 ⇒ 雷达有框），但离地不足 25 格不渲染。

⚠️ **前提：未安装 DH 或关闭其地形渲染**。`dhRenderingEnabled == true` 时高度门直接放行，远处船会被画出来 —— 若坚持"只雷达不渲染"，则需另案改 Java 解耦「租约授权」与「快照授权」，**不在本方案范围内**。

## 九、替代方案对照（为何不选）

| 方案 | 做法 | 否决原因 |
|---|---|---|
| **A 纯配置放开地面车辆** | `ground_vehicles = ["helicopter","aircraft","ground_vehicles"]` | 船能扫到了，但**坦克/轮式也被一并放开**，无法精准控制；且属于"用更宽的口子办更窄的事" |
