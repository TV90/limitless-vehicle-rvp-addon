## 一、本轮完成的全部改动（按主题）

### 1. 出弹点数据层定版（挂骨方案，核心改动）

**废弃**了运行时队列劫持方案（`RVP_ShootBoltQueueApplier`/`S2CShootBoltQueueSync`/`resolver.rebuild` 查表），改为**数据层模板写入**：

- 数据包 apply TAIL 时，从 `RVP_CustomMountConfigCache` 读出弹骨条目，把出弹骨 bolts 直接写入 `WeaponUnitData` 模板的 bolts 列表；
- 实体构造时从模板拷贝 → 无运行时竞态、无 S2C 同步需求、存档重进天然正常；
- 双端数据包各自 apply（客户端 17:57 日志实证客户端也会跑同一 apply），无需额外同步。

**关键文件**：`RVP_ShootBoltQueueResolver.java`（挂骨方案重写版）——`applyTemplateBolts(resources)` + `computeStationBolts(...)` + 骨→Bolt 数学（`appendBoneBolts`/`appendChildBolts`/`bindPivot`）。

**语义**：
- 配置了 `shoot_structure_bones` → 出弹骨成为挂骨（数据层从出弹骨算 bolts），挂架+导弹显示模型渲染在挂骨（=出弹骨）上，视觉与实际出弹完全对齐；
- 未配置出弹骨 → 挂骨同时作为出弹骨与视觉挂骨（原语义）；
- 原 barrel 挂骨在配置出弹骨后不再参与出弹。

### 2. 有人载具改装屏蔽

`RVP_ClientArmState` + `RVP_ModdingInteractGuard`（Forge 事件 HIGHEST）：有人载具屏蔽"改装工具+潜行+主手"右键子武器站改装；`clear`/`ensureLocked` 发包前加连接防护（退出存档 NPE 第二层防护）。

### 3. 近炸机枪弹过滤 + 雷达锁定近炸

`RVP_FuseData` 新增 `engine_nozzle_offset`/`flame_scale` 字段（尾焰参数）；`RVP_ProjectileData` 同理；机枪弹丸不再触发近炸（按 `weapon_kind` 精确过滤）；新增 `fuse_data.proximity_fuse_require_radar_lock` 参数（默认 false）。

### 4. 激光告警收窄 + 视线弹跟鼠标

激光告警仅对 LBR/LH/SALH 生效（服务端校验照射者当前武器）；SACLOS/LBR 视线弹光束与视线严格跟鼠标（HUD 点禁锁定吸附+发射不传锁+实体追踪收紧）。

### 5. ARM 预选独占窗口

`RVP_RuntimeArmGuidanceSource` 加独占窗口：发射带预选进入窗口（时长=记忆时间同源），窗口内仅预选+ECM 可参与选择，预选不可见朝最后已知位置飞，窗口耗尽恢复自主捕获。

### 6. ARM HUD 本体风格

`RVP_ArmOverlay` 换本体 RF 雷达锁定风格（drawSquare 单/双层绿框 + radar_type 文案）；本体大圈经 `WeaponUnitGetSeekerFovMixin` 对 ARM 归零屏蔽（getSeekerFov 返回 0）；ARM 自渲染绿色内接四角框（`RVP_ShootBoltQueueResolver` 废弃后由 `RVP_ShootBoltQueueResolver` 数据层模板写入替代运行时劫持）。

### 7. 导弹尾焰动画（**未完成**）

`RVP_BedrockProjectileEntityRenderer` 复用本体 InternalAssets 尾焰三件套，`has_rocket_engine` + 燃烧期门控，渲染器侧 WeakHashMap 缓存 runner。**实机无尾焰，原因待排查**（见下文）。

### 8. 退出存档 NPE 防护（两层）

第一层：`getRoot` 加 `getPlayer()==null` 防护；第二层：`clear()` 内 `CHANNEL.sendToServer` 前加 `getConnection()!=null` 检查。退出存档不再崩。

## 二、出弹点方案演进（三代）

| 代 | 机制 | 状态 |
|---|---|---|
| 第一代（本体原生） | `rvp_structure_bolt_bones` 部件级配置 → 数据层追加 bolts | **仍在用**（未配置出弹骨的站） |
| 第二代（运行时队列，已废弃） | `RVP_ShootBoltQueueApplier` + `resolver.rebuild` 查表 + S2C 同步 | 已删除（代码在 gitee `709815d7` 存档） |
| **第三代（挂骨方案，现行）** | `VehicleDataManagerMixin` apply TAIL → 数据层从出弹骨直接写 `WeaponUnitData` 模板 bolts | **现行** |

**第三代为什么根治**：出弹 bolts 在数据层模板定型，实体构造时拷贝——不存在"运行时忘记应用"或"竞态导致回退"的可能。存档重进时数据包重载自动重建模板，天然正确。

**废弃原因（第二代）**：配置缓存/队列表就绪时序竞态导致"放置后不应用/重进回退挂点"；200 tick 放弃机制 + 配置缓存门控绑错数据源加剧了问题。

## 四、尾焰动画未完成——排查方向

> **2026-09-14 晚间更新：根因已定位**——渲染器门控 `data == null` 在客户端恒为真
> （`rvpData` 不传客户端），尾焰分支从未执行。详见
> `RVP导弹尾焰动画复用本体资源_20260914.md` §〇（含证据链、五条嫌疑逐条判定与候选修法）。
> 下文原始排查方向保留作过程记录。

**实机症状**：发射 `has_rocket_engine` 导弹，燃烧期内弹尾无尾焰渲染。

**代码逻辑**（`RVP_BedrockProjectileEntityRenderer.renderMotorFlame`）：
- 门控：`hasRocketEngine && isMotorBurningNow` → 写入 `WeaponUnitData` 模板 bolts；
- 资源：`InternalAssets` 三件套（模型/动画/贴图，命名空间 `ywzj_vehicle:effect/rocket_motor_flame`）；
- 变换：`-entityYaw` → `xRot` → 喷口平移 → 缩放。

**排查方向**：
1. `isMotorBurningNow()` 客户端判定——客户端 `rvpData` 可能为 null 时走同步数据分支，确认同步字段已就位；
2. `AnimationRunner` 创建时机——首帧创建后 `tick()/evaluate()` 姿态输出是否有效；
3. `InternalAssets` 三件套加载时机——数据包重载完成前可能为 null；
4. 渲染段是否被 `isParticleProjectileVisual()` 提前 return 跳过；
5. `VehicleBedrockModel.applyPose/blend` 对该动画文件的兼容性。

**历史**：本类曾实现"运行时出弹队列 + 拉取式应用器"方案（PENDING/ensureApplied/MISS_RETRY/S2C 整表同步），因配置/队列表就绪时序竞态导致"放置后不应用/重进回退挂点"而废弃。
