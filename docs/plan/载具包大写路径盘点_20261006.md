## 五、为什么现在"能跑"，风险在哪

1. RVP 的 `display.getTexture()` 返回 `ResourceLocation`，但**单参构造 `ResourceLocation(String)` 不做大小写校验**（只做 `decompose`）⇒ **大写不会报错**，只按原样去找文件。
2. **Windows 文件系统大小写不敏感** ⇒ 本地开发、Windows 服务端表现正常。
3. **Linux（服务端 / CI / 打包发布）大小写敏感** ⇒ `052D.png` 找不到 `052d.png`，**贴图静默丢失**（无异常日志，很难排查）。
4. 规范层面：MC 资源 ID 只允许 `[a-z0-9/._-]`，大写属越界写法；将来若上游改用严格校验（`assertValidPath`）会**直接抛异常**。
