## 0.1 历史教训对照（纯 Forge 服务端启动崩溃红线自查）

> 依据：`docs/修复方向/修复方案总结.md`（39 个公共 Mixin 改脏本体带毒类 → 服务端
> `COMPUTE_FRAMES` 全类重算帧 → 常量池里的 `@OnlyIn(CLIENT)` 类型被
> RuntimeDistCleaner 拦截 → 启动崩）。本节为本计划的红线自查结论。

**红线规则**：
1. 带毒黑名单本体类（含 `RadarUnit`、`WeaponUnit`、`AbstractVehicle`、`MissileEntity`、
   `Radar` 等 46 类）**永不打任何新 Mixin**（`@Inject`/`@Accessor`/`@Overwrite` 一律禁）；
2. 公共代码禁止引用任何 `@OnlyIn(CLIENT)` 类型（如 `LocalVehiclePlayer`、`Minecraft`）；
3. 纯客户端行为放 client 总线/客户端类，经桥接（`RVP_ClientActionsAccess`）暴露给公共层。

**本计划自查结果（全部合规）**：

| 计划项 | 触及方式 | 判定 |
|---|---|---|
| 照射检测 | 挂 `RVP_RadarScanService`（RVP 自有事件类，非 Mixin） | ✅ 合规。**特别警示：旧版 EW 正是亡于 `RadarUnitMixin`（`RadarUnit` 在带毒黑名单）**，实施时严禁以任何理由给 `RadarUnit` 加 accessor/inject——对雷达的读写只允许调用其既有 public 方法（`detect()`/`getDetectedEntities()` 等，现有 `tickRadarContactHold` 已有先例） |
| 假目标实体 | 标准实体注册（DeferredRegister + DistExecutor 挂 renderer），无 Mixin | ✅ |
| NCTR/icon 分支 | 改 `RVP_RadarContactHelper`/`RVP_ExternalRadarSyncService`（RVP 自有）/战术地图（client 类） | ✅ |
| gunner 攻击假目标 | 改 `GunnerTargeting`/`GunnerBrain`（RVP 自有类，非 Mixin） | ✅ |
| 爆炸反馈 | 服务端 `ServerLevel.sendParticles` 广播 + 音效，公共代码零客户端粒子类 | ✅（实现时注意）|
| `ywzj_rvp.mixins.json` | **本计划全程不新增任何条目** | ✅ |

**已知局限（第三轮批示后收窄）**：本体自带雷达小 HUD 无法过滤触点——己方仍会**看到**
自己的假目标点位。但通过 §7.4 服务端看门狗，假目标对归属方与友方**不可选中、不可锁定**
（锁定即被下一 tick 清除并短暂禁锁）；BVR 超视距框因候选仅遍历 `AbstractVehicle`
而结构上永不显示假目标（§7.5）。即：友方最多"看到一个点"，无法与之交互。

### 7.4 友方禁选禁锁看门狗（新增，回应第三轮批示）

复用箔条干扰的服务端清锁先例（`RVP_ChaffJamHelper.tryJamLock` / 清外置锁定）：
`RVP_EcmPassiveManager` 每 tick 轮询各开启雷达的 `lockedEntity`：

- 锁定目标是假目标、且 `RVP_EcmIff.isFriendly(雷达载具, 假目标ownerVehicleId)` →
  `radar.setLockedEntity(null)` + `RVP_WeaponLockStateTable.clearExternalRadarLockedEntityId/
  clearExternalRadarRequestedEntityId`（若挂在该站）+ 该雷达短暂禁锁；
- 敌对方锁定假目标**不清除**（正是欺骗目的，任其打幻影耗弹药）；
- gunner 候选扫描直接排除"非敌对"假目标（§7.3 过滤点 3）。

### 7.5 BVR 超视距框天然不显示假目标（新增）

`RVP_RemoteVehicleVisualSyncService` 的 BVR 候选仅遍历 `AbstractVehicle`（载具列表），
假目标是普通实体 → 结构上进不了候选，**对所有观察者（含归属方）都不画超视距框**，
无需任何过滤代码。

## 1. 背景与旧版回顾

项目早期（2026-06）曾实现过一套完整的**电子战假目标干扰系统**（前缀 `Ew*`，约 1500 行，
见 `E:/ywzj_rvp/ywzj_rvp`），核心机制：

- 载具**被敌方雷达照射时自动生成一批"假目标"诱饵实体**；
- **距离分段强弱**：远档假目标多且散布大，近档少而集中；
- **烧穿（burn-through）**：照射源距离近于阈值后假目标失效——形成"诱骗锁定 ↔ 拉近烧穿"博弈；
- **锁定欺骗**：雷达锁定解析时可能误锁假目标（旧版经 Mixin 挂本体 `RadarUnit` 实现）；
- 服务端权威判定，激活 2s / 冷却 1s。

该代码未被迁移到重构后的仓库，现仓库仅剩 `RVP_JammingDeviceType.ELECTRONIC` 占位枚举。
本方案在**当前架构（骨块模块 + 无新增 Mixin）**下重新实现，并更名为**被动电子战防御措施**
（Passive Electronic Countermeasures）；后期另做"主动电子战干扰"（Active EW），本方案不含。

## 2. 目标与非目标

### 目标（本方案范围）

1. 新增**状态级骨块模块** `ECM_PASSIVE`，与 APS/DIRCM/JAMMER 同级：挂在 `bone_modules`
   骨块条目上，可被打坏失效，支持叠加与独立失效。
2. **触发时机**：载具（含模块的骨块存活）被**敌方**雷达扫描/照射到时，自动在载具周围
   生成分档假目标，注入照射源雷达的探测表——敌方雷达屏幕出现虚假触点、可能误锁。
3. **敌我识别（IFF）门控**（用户硬性要求，参考 GunnerBrain CIWS 的敌我判定）：
   - **无主中立雷达不触发**；
   - **友方雷达不触发**：同阵营玩家、同阵营 gunner、友好（FRIENDLY）gunner；
4. **重新充能期**：激活期结束（或烧穿）后进入冷却，冷却期间再次被照射不生成。
5. 距离分段 + 烧穿沿用旧版数值作为默认配置。
6. **假目标带随机 NCTR 标识**（见 §6.2），在敌雷达触点/锁定信息/战术地图上以飞机型名
   与**飞机 icon** 呈现，提高欺骗效果。
7. **假目标可机动**：随机航向缓慢移动（§6.3），雷达触点呈现真实速度。
8. **gunner AI 攻击假目标**：优先级仅次于导弹（用户批示），敌方 gunner 会优先拦截/攻击
   假目标——消耗其弹药与注意力。

### 非目标

- 不做"雷达屏蔽完全隐身"；
- 不做频谱/噪声功率等拟真电磁计算；
- **不做主动电子战干扰**（后续独立方案）;
- 不新增任何 Mixin（AGENTS.md 默认拒绝）。

## 3. 状态级骨块模块设计

对齐 DIRCM/JAMMER 的既有模式：

- `BoneModuleType` 新增枚举项 **`ECM_PASSIVE`**（被动电子战防御措施）；
- `bone_modules` 骨块条目新增子对象 `ecm_passive`：

```json
"TOWER0": {
  "damage_factor": 1.0,
  "min_damage": 40.0,
  "modules": ["ecm_passive"],
  "ecm_passive": {
    "active_duration_ticks": 140,
    "cooldown_ticks": 300,
    "burn_through_distance": 250.0,
    "nctr_names": ["F15", "S27", "J10", "B52", "F16", "RAF", "H6K", "F18", "F14"],
    "decoy_speed_min": 0.8,
    "decoy_speed_max": 1.5,
    "bands": [
      { "max_distance": 1500.0, "decoy_count": 6, "radius": 300.0 },
      { "max_distance": 1000.0, "decoy_count": 4, "radius": 200.0 },
      { "max_distance": 500.0,  "decoy_count": 3, "radius": 150.0 },
      { "max_distance": 250.0,  "decoy_count": 2, "radius": 100.0 }
    ]
  }
}
```

- 配置 record：`BoneEcmPassiveConfig`（仿 `BoneDircmConfig`/`BoneJammerConfig`），
  由 `bone_modules` 解析链加载；
- `nctr_names`：NCTR 假标识池（用户指定默认值），每枚假目标生成时随机抽取一个；
- 消费点统一走 `RVP_BoneModuleStateTable.isModuleActive(vehicleId, boneName, ECM_PASSIVE)`：
  骨块被打坏后该设备失去能力（多骨块可叠加，任一存活即工作，数量取存活骨块最高档配置）；
- 多雷达同时照射：共享同一份激活/冷却状态（先到先得，冷却期内不被其它雷达重复触发）。

## 4. 敌我识别（IFF）规则

参考 `GunnerTargeting.isFriendlyAmmoOwner` / `isAllied`（CIWS 敌我判定同源语义）。
设照射源为携带 `RadarUnit` 的载具 `radarVehicle`，被照载体为 `ewVehicle`：

| # | 条件（按序短路） | 判定 |
|---|---|---|
| 1 | `radarVehicle == ewVehicle` | 友方，不触发 |
| 2 | 雷达载具**无驾驶者**，或驾驶者既非 Player 也非 GunnerEntity | **中立，不触发**（用户要求）|
| 3 | 驾驶者为 GunnerEntity `g`：<br>· `g.faction == FRIENDLY`<br>· `ewVehicle` 也是 gunner 驾驶且**同 faction**<br>· **双方均 ENEMY faction（ENEMY 之间互不触发，已批示）**<br>· `g.isOwnedBy(ewVehicle 放置玩家)`<br>· Team 联盟（`g.getTeam()` 与 `ewVehicle.getTeam()` 任一 isAlliedTo） | 友方，不触发 |
| 4 | 驾驶者为 Player `p`：<br>· `p` 是 `ewVehicle` 乘客<br>· Team 联盟 | 友方，不触发 |
| 5 | 其余（ENEMY gunner、敌对阵营玩家等） | **敌方，触发** |

实现为独立工具类 `RVP_EcmIff.isHostileIllumination(radarVehicle, ewVehicle)`，
规则注释对齐 `GunnerTargeting` 语义，便于后续与 CIWS 敌我判定同步演进。

> 待确认：ENEMY 阵营 gunner 的雷达互相之间——按上表第 5 行互视为敌方会互相触发；
> 若希望"ENEMY gunner 照射 ENEMY gunner 的 EW 载具不触发"，需在第 3 行加
> `双方均 ENEMY faction → 友方`，默认不加（ENEMY 无差别语义）。

## 5. 触发与状态机

每台装备 ECM_PASSIVE 的载具一份服务端状态（`RVP_EcmPassiveState`，运行期 Map，不入存档）：

```
[空闲] --被敌对雷达照射--> [激活] --active_duration_ticks 耗尽--> [充能] --cooldown_ticks 归零--> [空闲]
           |                    |
           +--照射距离 < 烧穿距离---> [烧穿清场]（立即清除现存假目标并进入充能）
```

- **照射刷新**：激活期内被任何敌对雷达继续照射 → 刷新最后照射时间与距离档位
  （档位变化时重排假目标分布，沿用旧版 `bandChanged → repositionDecoys`）；
- **烧穿**：照射源水平距离 `< burn_through_distance` → 视为被烧穿，立即清场进充能
  （对齐旧版 `band == BURN_THROUGH` 语义）；
- **充能期**：期间被再次照射**不生成**（用户要求"进入重新充能期"），仅刷新最后照射时间；
- **超时清理**：空闲且超 200 tick 无照射 → 清除残余假目标并移除状态（对齐旧版 200t 清理）。

### 默认数值

| 参数 | 默认值 | 说明 |
|---|---|---|
| active_duration_ticks | **140（7s）** | 激活时长（批示调整，原旧版 40） |
| cooldown_ticks | **300（15s）** | 充能时长（批示调整，原旧版 20） |
| 烧穿距离 | 250m | 小于该值照射直接烧穿清场 |
| 远档（>1000m） | 6 枚 / 半径 300m | 距离越远信号越弱，假目标越多越散 |
| 中远档（500~1000m） | 4 枚 / 半径 200m | |
| 中档（250~500m） | 3 枚 / 半径 150m | |
| 近档（≤烧穿边界前） | 2 枚 / 半径 100m | |

## 6. 假目标实体设计

新实体 `RVP_EcmDecoyEntity`（替代旧 `EwDecoyEntity`）：

- 纯服务端逻辑实体，`persist = false`（不入存档），寿命 = 激活期 + 缓冲；
- **AABB 设为小型载具量级**（约 1×3×1），保证被本体 `Radar.scanTargets` 当作有效目标扫描；
- `ownerVehicleId` 记录归属，供清理、IFF 过滤与调试。

### 6.1 渲染：隐形（已批示）

完全不渲染——纯雷达幻影。世界内看不到任何东西，只有雷达触点。

### 6.2 NCTR 假标识（新增需求）

现有触点链路已原生支持 NCTR：`S2CExternalRadarSnapshot.Entry.nctrLabel` 由
`RVP_ExternalRadarSyncService.resolveNctrLabel` → `RVP_RadarContactHelper.resolveShortNctr`
生成，战术地图/准星 UI 直接显示该文本。

接入方式：

- 假目标实体持有 `nctrName` 字段：生成时从配置池 `nctr_names` 随机抽取
  （默认池 `F15,S27,J10,B52,F16,RAF,H6K,F18,F14`，用户批示）；
- 在 `resolveShortNctr` 增加**最优先分支**：
  `entity instanceof RVP_EcmDecoyEntity decoy → return decoy.getNctrName()`——
  EARLY/MODERN 两种 NCTR 模式下敌雷达触点都显示该机型名；
- **战术地图 icon**：icon 解析按实体数据类型选择（`FixedWingVehicleData → JET_ICON`），
  假目标非载具会落到地面 icon。需在 icon 解析处增加分支：
  `entity instanceof RVP_EcmDecoyEntity → JET_ICON`（飞机 icon，用户要求）。
  触点速度取自假目标真实 `deltaMovement`，与机动联动自然可信。

### 6.3 机动与区块加载（已解决，复用热焰弹成熟方案）

**结论：不会冻结、也不会拖垮 TPS——直接复用热焰弹诱饵已验证的区块保活方案。**

用户批示指出：若不主动加载区块，假目标漂移远离玩家后会因区块卸载而"卡在原地不动"，
欺骗效果失效。该问题项目里已有生产级解法：

- **每 tick 区块保活**：现有热焰弹 `RVP_DecoyEntity.tick()` 即调用
  `EntityUtil.keepChunkLoaded(this, this.position())` 保持自身与漂移方向区块加载
  （注释原话："避免飞出视距后区块卸载导致实体冻结不消失"）。假目标完全照搬此调用；
- **全局票据预算兜底**：所有路径票经 `RVP_ChunkPathLoadManager` 统一调度——
  本体同参数 `TicketType.POST_TELEPORT` 临时票、全局每 tick 新增上限 64 票、
  停止提交后自然过期。6 枚假目标 × 每 tick 1 次保活远低于预算；
- **实际加载成本极低**：假目标出生在 EW 载具周边（载具自身必然处于活动区块——
  它正被雷达扫描/驱动），周边区块大概率已被玩家票据或 gunner 载具强载器
  （`AbstractVehicleGunnerChunkLoadMixin`）加载；漂移途中偶发进入未加载区块时
  才产生少量新票，且寿命约 10s 后随实体销毁自然卸载；
- **机动实现**：每枚假目标随机水平航向 + 速度（默认 0.8~1.5 block/tick ≈
  58~108 km/h，可配），`tick()` 里匀速直线漂移 + 微小航向抖动，无寻路/无碰撞/无重力；
- **数量与寿命**：单载具同屏最多 6 枚（远档上限）、寿命 = 激活期 + 缓冲（约 10s）、
  不入存档；
- 战术地图上触点自带 `velocityZ/X/Y` → 显示为有速度的空中目标，欺骗观感完整。

### 6.4 假目标被击中的爆炸反馈（新增需求）

- 假目标覆写 `hurt()`：受到任何伤害即触发**小型爆炸视觉/音效反馈**
  （复用本体/项目现有爆炸粒子 + 音效，无实义伤害或按配置给微量伤害）；
- 反馈后立即 `discard()` 销毁该枚假目标（被"击落"的幻影）；
- 敌方 gunner 高优攻击假目标（§2 目标 8）时，爆炸反馈让拦截显得真实，
  达到消耗弹药与注意力的设计意图；
- **服务端安全约束（教训红线）**：粒子/音效一律经 `ServerLevel.sendParticles` /
  `level.playSound(null, ...)` 服务端广播，公共代码不得引用任何客户端粒子/渲染类
  （对齐 §0.1 红线 2）。

## 7. 与雷达系统对接（零 Mixin）

### 7.1 照射检测（挂现有服务端雷达遍历）

`RVP_RadarScanService` 已有服务端全量雷达遍历（`tickAllContactHold` 高频保活 +
`scanLevel` 低频补扫/炮手全量扫）。新增一步（对齐 Option A）：

- 对每颗开启的 `RadarUnit`，遍历其**服务端探测表**中的 `AbstractVehicle` 条目；
- 目标载具存在存活的 `ECM_PASSIVE` 模块 → `RVP_EcmIff.isHostileIllumination(...)`；
- 敌对 → `RVP_EcmPassiveManager.onRadarIlluminated(ewVehicle, radarVehicle, distance)`；
- 延迟评估：玩家驾驶雷达的服务端表由 DETECT 回写 + 1s 补扫维护，照射感知最多滞后约
  1s（对被动箔条类对抗可接受）；如需即时可在补扫处改为基于当帧 `Radar.scanTargets`
  结果判定（增强项，Phase 2 再评估）。

### 7.2 假目标进入敌雷达探测表

- 假目标是真实实体 → 各雷达（含客户端自扫的玩家雷达）常规扫描自然发现；
- 为保证**首照即时出现**，触发时对该照射源雷达直接调 `radar.detect(decoy)`
  （先例：`RVP_RadarScanService.tickRadarContactHold` 即如此保活）；
- 注意 `scan_vehicle_only` 雷达会过滤非载具目标——假目标 AABB 按载具量级设置即可通过
  `getBoundingBox().getSize()` 类过滤（实现时以 `RVP_RadarScanHelper` 实际过滤条件为准）；
- 锁定链路无需改动：假目标出现在探测表后，本体雷达 UI 可选中、`ClientRadarAction` 锁定、
  远程可见性同步（读服务端表）自然生效。

### 7.3 归属方可见性过滤（防"自己骗自己"）

假目标是世界实体，若不过滤会出现在**所有人**（含 EW 载具自身与友方）的雷达上。
需在三类读取点统一过滤：

1. `RVP_ExternalRadarSyncService.shouldIncludeTarget`（远程触点同步）；
2. 客户端自扫路径（`RVP_ClientRadarTickHandler` 的扫描结果，若其独立于同步包）；
3. gunner 目标候选扫描。

过滤规则：假目标 `ownerVehicleId` 等于观察方载具 → 剔除；观察方与归属方
`RVP_EcmIff.isFriendly(...)` → 剔除。**仅敌对方雷达能看到假目标**，
与 §4 IFF 规则保持同一套判定，避免两套标准。

## 8. 服务端权威 / 同步 / 存档

- 全部状态机与生杀判定在服务端；假目标实体经 Forge `PlayMessages.SpawnEntity` 正常同步；
- 激活/充能状态仅服务端（客户端无需感知；后续可加 HUD 提示，列为增强项）;
- 不入存档：状态 Map 运行期持有，实体 `persist=false`，载具卸载即清理（对齐旧版）。

## 9. 分阶段实施计划

- **Phase 1（核心闭环）**：`BoneModuleType.ECM_PASSIVE` + `BoneEcmPassiveConfig` 解析 +
  `RVP_EcmPassiveManager`（状态机/分档/烧穿/充能）+ `RVP_EcmIff` +

  归属方可见性过滤 + gunner 攻击假目标（优先级仅次于导弹，用户批示升级为核心）+
  单元测试（分档/烧穿/IFF 矩阵/NCTR 抽取）。
- **Phase 2（体验校验）**：敌雷达 UI 触点显示/可锁定验证（NCTR 名与飞机 icon）、
  首照即时性调优、（可选）即时照射检测增强、调试命令（仿 `RvpEwDebugCommands`）；
  回归验证含纯 Forge 服务端启动冒烟 + 客户端双端检查（对齐当年 Forge/Mohist 双端回归纪律）。
- **Phase 3（锁定欺骗，机制已考证补全）**：对 **RVP 自家 ARH/SARH 导引头**的截获欺骗——
  在 `RVP_RuntimeSeekerSupport.acquireEntity` 处掷骰：
  `偏转概率 = min(diversion_chance_max, 距离档基础概率 + diversion_count_bonus × 现存假目标数)`，
  默认基础概率按档 FAR 0.82 / MID_FAR 0.65 / MID 0.48 / NEAR 0.28、加成 0.03/枚、上限 0.92
  （即旧版定义但从未接线的公式，本次正式落地）；成功则导引头截获改判到最近假目标。
  该概率仅影响 RVP 导弹；SBW 导弹的欺骗继续走 §7.2 的雷达表诱锁路径。
- **明确不做**：主动电子战干扰（后续独立方案）。

## 10. 风险与对策

- 本体雷达客户端自扫与服务端表的差异 → 以服务端表做触发权威，接受 ≤1s 感知延迟；
- 假目标被 `scan_vehicle_only` / 高度限位 / 扇区过滤误杀 → AABB 量级 + 实测校准；
- 性能：假目标数最多 6 枚/载具、寿命约 10s、不加载区块（§6.3），状态机 tick 并入现有
  ServerTick 事件，不新增高频遍历；
- gunner 高优攻击假目标可能让敌方 gunner "无脑打幻影" → 这正是设计意图（消耗弹药与注意力），
  但需在 Phase 1 观察假目标被击中是否应产生小型爆炸特效反馈（增强项）。
