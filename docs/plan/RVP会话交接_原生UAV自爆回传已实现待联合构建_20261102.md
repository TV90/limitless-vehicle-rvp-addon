## 根因与新增时序问题

1. 自爆服务原先只保护 `isDeployableUavInstance`，把 `uav:true && !deployed` 的玩家版误当作普通有人载具。
2. 原生下车链会清空 `fakeOperatorPosition` 和驾驶员，且 `ServerPlayer.dismountTo` 仅设服务端坐标，不是明确的客户端传送同步。
3. `FakePlayer.hurt` 会先把真人拉回假玩家位置，再把伤害转发给真人；不能在真人回传后留着这个假玩家等下一 tick 自动清理。

## 实现与文件

- 修改 `src/main/java/org/ywzj/rvp/weapon/core/RVP_VehicleSelfDestructService.java`：
  - 用 `RVP_NativeUavReturnService.classify` 显式分为普通有人载具、母车部署实例、原生 UAV，部署身份优先，兼容旧 `uav:true` 部署模板。
  - 原生 UAV 在任何下车动作之前构建回传快照；回传失败不能短路成普通载具成功。
  - 返回动作成功后立即按本车记录的 UUID 清理假操作员，再进入现有扣弹/终结提交、爆炸、移除事务。
- 新增 `src/main/java/org/ywzj/rvp/uav/RVP_NativeUavReturnService.java`：
  - 使用 Forge `EntityJoinLevelEvent`（自动订阅，无新 Mixin）记录本体生成假玩家的时刻。此时原生 `Entity.startRiding` 已设置真人的 vehicle，且本体已为 FakePlayer 设置玩家名与放飞位置；绑定到该车的玩家 UUID、假玩家 UUID、放飞维度、位置、朝向。
  - 绑定时通过玩家名查在线玩家以确定生成上下文；清理只用此前绑定的实体 UUID，不按名字搜索/删除世界中的假玩家。
  - 同一玩家重新进入同一车生成新假玩家时，先移除本车上一次明确绑定的旧假玩家，防同 tick 切换留下伤害转发。
  - 记录存于载具 Forge 持久数据 `rvpNativeUavOperators`，没有全局逐 tick 表，也不需要另建生命周期扫描。
  - 回传优先快照已绑定且仍存活的假玩家当前位置，覆盖假玩家自然下落；否则使用记录的放飞点。
  - 未有 RVP 记录的既有实例，通过本体公开 `addAdditionalSaveData` 提取完整的 `fakeOperatorPositionX/Y/Z`。不调用会清除返回点的 `getDismountLocationForPassenger` 来做预检。
  - 本体旧坐标不含维度，兜底沿用本体同维语义；新绑定记录有明确维度。
  - 所有返回点和玩家状态先检查，全部 `stopRiding` 回调返回后核对已脱离，再调用 `ServerPlayer.teleportTo(ServerLevel, ..., Set.of(), yaw, pitch)` 建立客户端传送同步和返回区块加载票。
  - 最后回读存活状态、维度、无乘坐关系、位置误差（距离平方 ≤0.25）及爆炸安全距离；清零坠落距离与残留速度。
  - 同维返回点在爆炸半径+2 格内、缺少/损坏返回点、离机被取消或传送未生效时返回失败，不扣弹、不起爆。
- 新增 `src/test/java/org/ywzj/rvp/uav/RVP_NativeUavReturnServiceTest.java`：9 项测试声明，覆盖入口分类、失败不回退、NBT 快照不被下车清除、缺失/非有限值、操作员绑定、爆炸区门禁、全员离机优先、取消离机、传送 API 假成功。
- 修改 `src/test/java/org/ywzj/rvp/weapon/core/RVP_SelfDestructSequenceTest.java`：新增 2 项，将原生路由接入现有事务的失败阻断和回传/清假玩家优先顺序。
- 普通有人载具仍按用户明确指定的 MCH 语义不保护乘员；部署版仍走已有 RVP 母车返回队列。
