# RVP HITL 电视制导速度脱锁反制（2026-09-21）

## 意图

人在回路电视制导（HITL_TV）原本可无限跟踪任意速度的锁定目标，高速载具（>72 kph）对电视制导导弹无逃逸优势。本次加入速度脱锁反制：**被锁实体速度超过阈值即脱锁**，锁定位置从持续截获实体坐标变为**最后一次持续跟踪实体的坐标**（冻结点）；操作手仍可继续吊舱操作与重新锁定，但**再锁超速目标会立刻再脱锁**（冻结点更新为当时的最后跟踪坐标）。

## 改动点

| 文件 | 改动 |
|---|---|
| `config/RVP_Config.java` | 新增 common 配置 `guidance.hitlTvBreakLockTargetSpeedKph`（默认 72.0，0=关闭反制；`getHitlTvBreakLockTargetSpeedKph()`） |
| `entity/projectile/RVP_MissileEntity.java` | 新增 `rvp$markHitlSpeedBreak(lastTrackedPos)`：清除实体锁并把跟踪点设为最后持续跟踪坐标 |
| `guidance/runtime/RVP_RuntimeHitlTvGuidanceSource.java` | evaluate 实体分支加速度闸门：`validateEntity` 通过后 `getDeltaMovement().length()×72`（格/tick→km/h）超阈即 `markHitlSpeedBreak(bbox中心)` + 操作手 action-bar 提示；点分支冻结态优先，压制实时指定点 |
| `assets/ywzj_rvp/lang/zh_cn.json / en_us.json` | 新增 `ui.hitl_target_speed_break`（目标速度过高，锁定解除 / Target too fast - lock broken） |

## 机制要点

- **速度口径**：实体三维 `getDeltaMovement()`；格/tick × 72 = km/h（72 kph 恰好 = 1 格/tick）。俯冲/坠落的高速实体同样触发。
- **闸门位置**：服务端权威（制导 tick 仅服务端运行），单点收口于 HITL_TV 源的实体跟踪路径；点跟踪（纯吊舱指哪打哪、无实体锁）不受影响。
- **脱锁后操作手完全自由**：脱锁即转点制导飞向最后跟踪坐标，下一 tick 起吊舱实时指定点（指方块/地面/新目标）恢复正常接管——**不压制点指定**；重锁入口 `rvp$setHitlDesignatedEntity` 只把实体放回，闸门每 tick 复查，再锁超速实体立刻再脱（冻结坐标更新为当时的最后跟踪点）。
- **范围**：仅 HITL_TV（DESIGNATE 模式有实体锁）；HITL_CLOS_TV 为纯点制导无实体锁，不涉及。与烟雾/遮挡反制链（validateEntity / queryPoint）叠加生效，互不冲突。

## 预期影响

- 高速载具（>72 kph，约 1 格/tick）对 HITL 电视制导导弹获得明确逃逸手段；低速/静止目标行为不变。
- 配置 0 可整体关闭回到旧行为。
- 操作手脱锁瞬间收到 action-bar 提示，可辨识"脱锁原因 = 目标超速"。

## 验证方式

- `gradlew build` 通过（2026-09-21，57s）。
- runServer 冒烟 `Done (2.135s)!`、runClient 冒烟 62 个 client mixin 全应用零错误（jps+taskkill 收尾干净）。
- 实机项（待用户验证）：用 HITL 电视导弹锁静止/慢速目标正常跟踪；锁 >72 kph 目标立刻脱锁并报提示、导弹飞向冻结点；冻结点上再锁同目标反复脱锁。
