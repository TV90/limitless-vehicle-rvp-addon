## 问题二：客户端启动 Mixin apply 失败（refmap 缺失）

### 崩溃现象

```
Mixin apply for mod ywzj_rvp failed ... MinecraftReloadResourcePacksMixin ...
InvalidInjectionException: @Inject ... could not find any targets matching
'reloadResourcePacks()Ljava/util/concurrent/CompletableFuture;' in net.minecraft.client.Minecraft.
No refMap loaded.
```

`ywzj_rvp.mixins.json` 声明 `"refmap": "ywzj_rvp.refmap.json"`，但部署 jar 里**没有这个
文件**。Mixin 注入 `Minecraft.reloadResourcePacks()`（MCP 方法名）在生产混淆环境必须靠
refmap 映射到 SRG 名才能命中，缺失 → critical failure。

### 为什么之前没爆

- `.bak`/`.bak2`/`.prebak` 旧 jar 里 `MinecraftReloadResourcePacksMixin` 这个 class
  **不存在**（该 mixin 是 `233738d 修无人机bug` 新增），且旧 jar 的 mixins.json 不引用
  refmap → 一直没触发。
- rvp 开发/测试走 dev 环境（`build/classes`+`build/resources`，不混淆），MCP 名直接可用。
- 部署到正式混淆客户端后，缺 refmap 就炸了。

### 根因

构建时 Mixin AP（0.8.5）已正常产出 refmap：`build/tmp/compileJava/ywzj_rvp.refmap.json`
（2876B，含 `reloadResourcePacks` 映射），且 `mixin { add sourceSets.main, "ywzj_rvp.refmap.json" }`
配置在。但**增量编译缓存下 refmap 未被纳入 jar**。

### 处理（构建层，未改任何源码）

用 `--rerun-tasks` 强制完整重建后，`ywzj_rvp-1.20.1-0.5.8-all.jar` 与普通 jar 均含
`ywzj_rvp.refmap.json`。已重新部署。

> 注意：事后 `build`（增量）可能再次产出缺 refmap 的 jar。若后续发现部署 jar 里没有
> `ywzj_rvp.refmap.json`，用 `./gradlew build --rerun-tasks` 重新构建即可。

## 问题三：放置本体载具（AH-64D）渲染 NPE

### 崩溃现象

```
java.lang.NullPointerException: Rendering entity in world
    at ConcurrentHashMap.computeIfAbsent(ConcurrentHashMap.java:1693)
    at net.minecraft.Util$10.apply(Util.java:706)
    at ModRenderTypes.cubeTransparent(ModRenderTypes.java:82)
    at VehicleBedrockModel.renderSpecialBones(VehicleBedrockModel.java:600)
```

实体 `ywzj_vehicle:ah64d`，放置即崩（渲染）。NPE 来自 `Util.memoize`（底层
`ConcurrentHashMap.computeIfAbsent`）——**传入了 null 的 ResourceLocation**。

### 根因链

1. 本体 AH-64D display：`assets/ywzj_vehicle/display/vehicle/ah64d.json` 中
   `special_bone_effects[0] = { type: transparent, bone: body2, texture: null }`
   ——座舱玻璃/透明骨**没配独立纹理**，靠渲染参数 `texture`（display 顶层
   `texture: .../ah64d.png`）兜底。
2. 本体在 `1e2ca8a 支持独立渲染载具座舱模型`（2026-08-15）里给 `renderSpecialBones`
   增加了 `ResourceLocation texture` 参数与兜底逻辑：
   ```java
   if (entry.effect.texture != null) {
       texture = entry.effect.texture;
   }
   ```
   并放宽 `SpecialBoneEffect.isValid()`（不再强制 `texture != null`）。所以 AH-64D 这种
   null 纹理 special bone 在本体新逻辑下合法走"继承参数纹理"路径。
3. rvp 的 `VehicleBedrockModelCockpitRenderMixin @Overwrite`（`5b72c18`/`7d9cfa8`
   「优化渲染问题」，2026-07-24 加入）**完整覆写**了 `renderSpecialBones`，但实施的是
   旧语义：各处直接 `cubeTransparent(effect.texture)` 等，**漏掉了 1e2ca8a 的 texture
   兜底** → `effect.texture == null` 泄漏进 `Util.memoize` → NPE。

### 修复（已提交）

`src/main/java/org/ywzj/rvp/mixin/VehicleBedrockModelCockpitRenderMixin.java`：
在效果循环内（OPERATOR 座舱跳过判定之后）恢复本体的纹理继承兜底：

```java
// 与本体 renderSpecialBones 保持一致：无显式纹理的效果继承渲染参数里的载具整体纹理，
// 否则 effect.texture 为 null 时 Util.memoize 的 ConcurrentHashMap.computeIfAbsent 会拒收 null key 抛 NPE。
if (effect.texture != null) {
    texture = effect.texture;
}
```

五种材质分支（muzzleFlash / cubeCutout / polyMeshCutout / cubeCockpitTransparent /
cubeTransparent / polyMesh* ) 全部改用兜底后的 `texture` 参数，语义与本体一致。

已构建（`--rerun-tasks`）并部署。

> 设计提醒（未改动）：该 mixin 用了 `@Overwrite` 整体覆写本体方法，违反
> `AGENTS.md`「禁止 @Overwrite 整方法」纪律。后续建议评估能否改造为最小注入
> （`@Inject` + 复用本体逻辑），减少与本体演进耦合。

## 同类问题扫描结论（仅记录，未修改）

对 rvp 所有 mixin 与本体 `1e2ca8a` 重构（座舱独立渲染）的交汇面做了排查：

| 位置 | 结论 |
|---|---|
| `VehicleBedrockModelNoCullRenderMixin` | `@Inject(renderToBuffer HEAD)`，用参数 `texture`（调用方保证非 null），安全 |
| `VehicleRenderCockpitPassengerContextMixin` | HEAD 建乘客上下文 + `initDisplayData(VehicleDisplay)`（新签名），安全 |
| `VehicleRenderCustomMountMixin` | 挂 `getPartUnits()` 前，用 `display.getModel()`，仍存在，安全 |
| `VehicleRenderLodMixin` | `@Redirect` target（`VehicleDisplay.getModel/getTexture`、4 参 `applyAnimationPose`）与本体字节码一致 |
| `RVP_CustomMountRenderLogic` | `config.texture()` 有 null 校验，不进入渲染，安全 |
| `LocalVehiclePlayer`/`Camera` 等 mixin | 全挂在本体未改动的 `handlePlayerTurn`/`tickAim` 等方法上，安全 |
| rvp 调用的本体 API | `getCabinDisplay`/`getCabinModelInstance`/`getVehicleModelInstance`/`getCabinAnimationInstance` 全为 1e2ca8a **纯新增**，无删除/改名 |

### 未处理的功能隐患（不崩溃，仅记录）

**LOD × 座舱共用：** 本体 `VehicleRender.render` 新增 cabin 分支后用
`getCabinDisplay().getModel()`（仍是 `VehicleDisplay.getModel()` 常量池 #98 调用点）。
`VehicleRenderLodMixin` 的 `@Redirect(getModel)` 会同时命中主体与座舱两个调用点——
若某载具**配置了 `lod_models`** 且切 OPERATOR 座舱视图，座舱模型可能被替换成 LOD
简化模型（表现为座舱显示成低模，不会崩溃）。当前无载具因它崩溃；如需修复，应在
`RVP_LodModelManager.resolve` 或 `@Redirect` 里感知 `isCabinView` 并放行。

## 结论摘要

1. rvp 服务端可跑：本体基准须用 d4db35b（无 AUI）一类构建。
2. 部署到正式客户端前必须确认 jar 内含 `ywzj_rvp.refmap.json`（缺则
   `--rerun-tasks` 重建）。
3. 修复的 `@Overwrite` texture 兜底问题源于 rvp mixin 未跟上本体 `1e2ca8a` 语义，
   已对齐本体的「显式纹理优先 + 参数兜底」。
