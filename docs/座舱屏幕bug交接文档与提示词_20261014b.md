## 一、功能与配置（已验证可用）

座舱屏幕 = 把三类动态界面实时绘制到载具模型的屏幕骨骼（poly_mesh 骨）上：
- 雷达屏 `rvp:cockpit/radar`（20Hz）：探测罗盘，圆盘底+量程圈+旋转扫描线+探测方块+速度矢量+量程文字
- RWR 告警屏 `rvp:cockpit/rwr`（20Hz）：威胁罗盘，圆盘底+双绿环+中心点+机型文字+MSL/锁定告警红色 1Hz 闪烁
- 战术地图屏 `rvp:cockpit/map`（5Hz）：地形瓦片+图标（无按钮/无照射扇形）

配置：载具 display 文件（`assets/rvp/display/vehicle/<车id>.json`）顶层：
```json
"special_bone_effects": [
  { "bone": "illum_rwr_screen", "texture": "rvp:cockpit/rwr", "type": "transparent" },
  { "bone": "illum_map_screen", "texture": "rvp:cockpit/map",  "type": "transparent",
    "ywzj_rvp_screen_size": 256 }
]
```
- `ywzj_rvp_screen_size`（RVP 扩展字段）：屏纹理分辨率档位 256/512/1024，默认 512；同 RL 多条目取 max；**直10 map 屏已配 256**。
- 已配屏载具：z10（illum_rwr_screen/illum_map_screen）、suav（illum_cockpit_*）、j16d——同套代码+同款配置格式。
- 内容客户端本地绘制（数据源 WarningReceiver/RadarUnit/RVP_TacticalMapCache），服务端零开销。
- 性能：RT 离屏绘制雷达/RWR 20Hz、地图 5Hz，单次 0.02~0.05ms；零回读零上传；显存三屏约 2.25MB（z10 配置）。

## 二、最终架构

1. **RT 离屏画布** `client/cockpit/RVP_CockpitCanvas.renderToTarget(target, painter)`：ClientTick 内把 GuiGraphics 级 2D 内容画进离屏 TextureTarget。关键点（每条都是实测踩坑）：
   - `RenderTarget.clear()` 末尾会 unbindWrite（字节码实锤）——**clear 后必须重新 bindWrite 再绘制**；
   - ModelView 必须 setIdentity + `translate(0,0,-11000)`（GUI 正交投影可见 z 范围 [-21000,-1000]）；
   - `RenderSystem.colorMask(true,true,true,true)` 强制 alpha 写入（ClientTick 残留掩码会丢 alpha）；
   - `setShaderColor(1,1,1,1)` 复位残留；**显式 `setShader(GameRenderer::getPositionTexShader)`**——Tesselator.end 用 RenderSystem 当前 shader，残留 shader 与顶点格式不匹配=整批失效（黑屏/不可见且"哪块屏失效"随残留漂移）。
2. **屏骨绑定**：Manager 把 `rvp:cockpit/*` 注册为 **AbstractTexture 匿名包装**（override bind() = 原生 glBindTexture 直绑 RT 的 colorTextureId + GlStateManager._bindTexture 缓存同步）——绕开 DynamicTexture 上传管线的全部生命周期问题，对 F3+T/绑定缓存失真免疫。
3. **屏骨绘制（Mixin `VehicleBedrockModelCockpitRenderMixin`）**：display 条目 texture=`rvp:cockpit/*` 的屏骨走**弹孔式直绘**（复刻本体 BulletHoleParticle 生产路径）：chunk 顶点（屏骨局部 bind 空间，`chunk.vertices().positions()/uvs()` 全 public）× 骨当前全局变换（`renderInstance.getGlobalTransform(idx)`，含动画；UV 按 chunk 包围盒归一化铺满）= 模型空间 → `poseStack.last()` 提交 → **双面 NEW_ENTITY 顶点**（uv/color/overlay/light/normal）进 `RVP_RenderTypes.screenQuad(rl)`（entityTranslucentCull 同款状态 + TextureStateShard(rl) 走 RT 包装绑定）。renderSingleBone 对屏骨停用（quad 替代面片）。实体实例失配时自动切 display 默认实例。
4. **内容渲染器** `RVP_RadarScreenRenderer / RVP_RwrScreenRenderer / RVP_MapScreenRenderer`：图元**全部用 Canvas 立即 position_color 自绘**（`drawDiscImmediate/drawRingImmediate/drawLineImmediate/fillRectImmediate`）——**不使用 GuiHelper.drawCircle / RenderHelper.drawLine**（见三-3）。文字走 GuiGraphics（2 倍字体）。
5. 诊断：默认开启 → `logs/rvp_cockpit_diag.log`（状态行；特殊骨渲染行每秒一条：hasVerts/vis/sameModel/直绘verts/直画chunk/glErr/bind）+ `logs/rvp_cockpit_dump/{radar,rwr,map}_{0,1}.png` 每 2 秒环形 dump RT 内容（PIL 可读 alpha 通道——本次破案关键手段）。

## 三、四个根因（全部实锤，按发现顺序）

1. **`RenderTarget.clear()` 末尾 unbindWrite**（字节码实锤）——clear 后不重绑 bindWrite，RT 只剩清屏色（"中心像素恒=清屏色"）。修复：clear 后重新 bindWrite。
2. **`Long.MIN_VALUE` 哨兵 + 减法节流溢出**：`now - Long.MIN_VALUE` 溢出为负恒假——诊断一行不输出、屏绘一轮不执行。修复：哨兵首帧放行（`lastXxx == Long.MIN_VALUE ||`）。
3. **HUD_CIRCLE 自定义 shader（ModShaders.getCircleShader）在离屏 RT 下失效**：radar 全部圈/盘/扫描线静默不画（dump 纯底色实锤）；rwr 圆盘 RGB 写入但 **alpha=0**（PIL 像素级实测：圆盘内 a=0、四角 a=255）。修复：radar/rwar 图元全部换 Canvas 立即 position_color 自绘，屏内场景彻底弃用 GuiHelper.drawCircle/RenderHelper.drawLine。
4. **直绘缺显式 setShader**：Tesselator.end 用 RenderSystem 当前 shader，ClientTick 残留 shader 与 POSITION_TEX 格式不匹配=整批失效（"哪块屏黑随残留漂移"）。修复：显式 setShader(getPositionTexShader)。
5. **附带修复**：MSL 威胁出现时屏绘消失（威胁符号 normalize 零向量 NaN 污染顶点）——radar/rwar 加 lengthSqr<1e-8 零向量防御。

## 七、2026-10-14 深夜补更正（雷达屏层序修复批）

- **雷达屏层序 bug（已修待实机）**：雷达渲染器原先把熄屏底色与探测方块走 `GuiGraphics.fill`（攒批），
  而本渲染器首次字体请求在末尾"512m"——GuiGraphics 攒批内容统一在 painter 返回后的 endBatch 才
  落屏，导致底色+方块在立即圆盘/环/扫描线**之后**刷下、整屏盖掉（症状=屏上只剩深底+探测方块+
  量程文字，环/扫描线/中心点全无）。已全部改 `RVP_CockpitCanvas.fillRectImmediate` 立即模式
  （"NO RADAR" 提示同步改放大版文字）。
- **RWR 顺序脆弱性提醒（未改，实机已验）**：RWR 底色同为攒批 fill，靠"顶部告警文字先画"触发提前
  endBatch 才落对层序——属偶然安全，日后若调整 RWR 文字绘制位置，须先把底色改立即模式。
  地图屏全攒批（fill/blit）零混用，无此问题。
- **"零向量防御已加"系误记（更正）**：定版提交 `4bd7486b` 实际未写入任何 lengthSqr<1e-8 守卫
  （diff 全文可查，仅提交信息与本文档声称过）。当前代码的零向量安全来自三层既有守卫：

### 8.2 日志行格式（`logs/rvp_cockpit_diag.log`，每秒 4 行）


## 九、屏骨 UV 语义定案（2026-10-15：一切按模型 UV）

### 9.1 变更

旧行为：屏骨 chunk 的 UV 被**包围盒归一化**（`u=(uv−uMin)/uSpan`），动态画面**强制铺满**整个
屏骨平面 —— 后果是模型 UV 怎么调都没反应（平移被 uMin 吃掉、等比缩放被 uSpan 吃掉；
三块屏实测各只有 1 个四边形，`直绘verts=6` ⇒ 数学上恒等于整块铺满）。

新行为（用户定案）：**默认直接采信模型 UV**（`u=uvs[i*2]`、`v=uvs[i*2+1]`）。屏骨 UV 展面
**即取景框**：展满 0~1 = 整张画面；只展 0.2~0.4 = 取画面中间那一块（等效放大）；反转顺序 = 镜像；
一块 RT 可分给两块屏骨（各展 0~0.5 / 0.5~1）。

- 开关字段：display 条目 `special_bone_effects[].ywzj_rvp_screen_uv_mode`，
  取值 `"model"`（缺省）/ `"fill"`（回退旧铺满）；
- 解析与 `ywzj_rvp_screen_size` 同源（`RVP_CockpitScreenManager.parseScreenSizes`），
  任一 `fill` 条目即把该 RL 登记为铺满（`SCREEN_FILL_UV`）；
- 实现点：Mixin `VehicleBedrockModelCockpitRenderMixin` 的 `boolean fillUv = ...isFillUvMode(...)`，
  顶点循环内三元切换；
- **性能**：无增加（CPU 侧省掉归一化的加减除，GPU/顶点格式/draw call 全部不变）；
- **风险（正确性而非性能）**：RT 纹理 wrap=CLAMP_TO_EDGE，模型 UV 超界会**边缘渗色/拉丝**；
  屏骨 UV 必须落在 0~1。上界/下界以诊断行 `uv=...` 实测为准。

### 9.2 影响面与回退

- 旧配置（z10 / suav / j16d）**会立刻按新语义渲染**：若某块屏的 UV 没展满 0~1，画面会变小或
  只显示一部分——这是预期行为。要恢复原样：该条目加 `"ywzj_rvp_screen_uv_mode": "fill"`。
- 诊断行新增 UV 取证：特殊骨行尾 ` uv=0.000~1.000/0.000~1.000 UV模型`，
  可直接核对模型 UV 实际范围与当前语义。

### 9.3 几何与 UV 的职责划分（别再混淆）

| 你看到的 | 由谁决定 |
| --- | --- |
