# j15 自定义挂架"衔接点 / 出弹点分离"新旧写法对比（预期文档）

> **目的**：给 j15 增加"出弹骨"配置，使**弹丸实际射出的位置**可以和**挂架模型衔接位置**
> 分开，并与弹药消失渲染的骨骼严格对齐。
> **示例基准**：载具包 `limitless_vehicle/rvp/data/rvp/vehicles/j15.json` 真实配置
> （`variable_aam` 武器站 + `rvp:pl_12`，4 挂架 × 单弹，RIPPLE 逐发）。
> `pl_15` / `yj_91` / `kd_88a` 与之同构，不再重复。
> **骨骼命名**：`*_shoot_barrel` 为伪名占位，落地时换成结构模型真实骨骼。
> 关联：[调研文档](../../plan/研发调研_自定义挂架衔接点与出弹点分离.md) ·
> [条目级示例](j15_rafale_shoot_bone_entry_level_example.jsonc)

---

## 一、现状写法（旧）

### parts 片段（不变，出弹点由这里推算）

```jsonc
{
  "id": "variable_aam",
  "structure_bone": "variable_aam_1",
  // 出弹点来源：结构模型这 4 根 _barrel 骨的 Cube，逐 Cube 一根炮管
  "rvp_structure_bolt_bones": [
    "variable_aam_1_barrel",
    "variable_aam_2_barrel",
    "variable_aam_3_barrel",
    "variable_aam_4_barrel"
  ]
},
{ "id": "variable_aam_mount_1", "structure_bone": "variable_aam_1" },
{ "id": "variable_aam_mount_2", "structure_bone": "variable_aam_2" },
{ "id": "variable_aam_mount_3", "structure_bone": "variable_aam_3" },
{ "id": "variable_aam_mount_4", "structure_bone": "variable_aam_4" }
```

### rvp_custom_mounts（现状 pl_12 全部 4 条）

```jsonc
[
  {
    "part_unit_id": "variable_aam",
    "attach_part_unit_id": "variable_aam_mount_1",
    "weapon_id": "rvp:pl_12",
    "model": "rvp:entity/weapon_mount/weapon_mount_pl12",
    "texture": "rvp:textures/entity/weapon_mount/pylon_pl12.png",
    "rack_bones": ["pylon"],
    "missile_bones": ["missile1"],
    "replace_weapon_display": true,
    "ammo_slot": 1
  },
  { "…mount_2，其余同上", "ammo_slot": 2 },
  { "…mount_3，其余同上", "ammo_slot": 3 },
  { "…mount_4，其余同上", "ammo_slot": 4 }
]
```

### 现状行为（两条线各走各的）

| 维度 | 行为 | 数据来源 |
|------|------|----------|
| 出弹位置 | 从 `_barrel` 骨 Cube 打出（与挂架衔接同一处） | `rvp_structure_bolt_bones` → WeaponUnit.bolts |
| 开火顺序 | RIPPLE 从 bolts[0]（mount_1）开始**升序**逐发 | `doClientShoot` → `getCurrentBolt()` |
| 消失顺序 | **高 slot 先消失**（第 1 发打完，mount_4 的弹隐） | `hideMissile = visibleAmmo < slot` |
| 衔接位置 | 挂架模型锚在 mount 部件 `_barrel` 首 Cube | `attach_part_unit_id` → `bolts.get(0)` |

**现状问题**：出弹骨 = 衔接骨，弹体模型贴多近就得从哪打；且开火（升序）与
消失（降序）方向相反——第 1 发从 mount_1 出，视觉上消失的却是 mount_4 的弹。

## 二、新写法（预期）

### parts 片段：**原样保留，一个字不用改**

`rvp_structure_bolt_bones` 继续承担"未配置新参数时的出弹回退"。

### rvp_custom_mounts：每条加一个可选字段 `shoot_structure_bones`

```jsonc
[
  {
    "part_unit_id": "variable_aam",
    "attach_part_unit_id": "variable_aam_mount_1",
    "weapon_id": "rvp:pl_12",
    "model": "rvp:entity/weapon_mount/weapon_mount_pl12",
    "texture": "rvp:textures/entity/weapon_mount/pylon_pl12.png",
    "rack_bones": ["pylon"],
    "missile_bones": ["missile1"],

    // ★ 新增字段：本挂架的出弹骨（Cube = 发射点）
    //   与 missile_bones 一一对应：missile_bones[i] 的弹从 shoot_structure_bones[i] 打出
    "shoot_structure_bones": ["variable_aam_1_shoot_barrel"],

    "replace_weapon_display": true,
    "ammo_slot": 1
  },
  {
    "part_unit_id": "variable_aam",
    "attach_part_unit_id": "variable_aam_mount_2",
    "weapon_id": "rvp:pl_12",
    "model": "rvp:entity/weapon_mount/weapon_mount_pl12",
    "texture": "rvp:textures/entity/weapon_mount/pylon_pl12.png",
    "rack_bones": ["pylon"],
    "missile_bones": ["missile1"],
    "shoot_structure_bones": ["variable_aam_2_shoot_barrel"],   // ★ mount_2 的出弹骨
    "replace_weapon_display": true,
    "ammo_slot": 2
  },
  {
    "part_unit_id": "variable_aam",
    "attach_part_unit_id": "variable_aam_mount_3",
    "weapon_id": "rvp:pl_12",
    "model": "rvp:entity/weapon_mount/weapon_mount_pl12",
    "texture": "rvp:textures/entity/weapon_mount/pylon_pl12.png",
    "rack_bones": ["pylon"],
    "missile_bones": ["missile1"],
    "shoot_structure_bones": ["variable_aam_3_shoot_barrel"],   // ★ mount_3
    "replace_weapon_display": true,
    "ammo_slot": 3
  },
  {
    "part_unit_id": "variable_aam",
    "attach_part_unit_id": "variable_aam_mount_4",
    "weapon_id": "rvp:pl_12",
    "model": "rvp:entity/weapon_mount/weapon_mount_pl12",
    "texture": "rvp:textures/entity/weapon_mount/pylon_pl12.png",
    "rack_bones": ["pylon"],
    "missile_bones": ["missile1"],
    "shoot_structure_bones": ["variable_aam_4_shoot_barrel"],   // ★ mount_4
    "replace_weapon_display": true,
    "ammo_slot": 4
  }
]
```

（`pl_15` / `yj_91` / `kd_88a` 的 8/8/… 条同构：只在自己条目里补各自的
`shoot_structure_bones`，如 `variable_aam_1_shoot_barrel` 对 PL-15 换成 PL-15 弹位骨。）

### 新行为：一条队列管开火和消失

```
出弹队列 = 命中当前武器的条目按 (ammo_slot, 配置顺序) 排序，
          依次拼接 shoot_structure_bones 的 Cube 发射点：
          [ mount_1_shoot, mount_2_shoot, mount_3_shoot, mount_4_shoot ]

RIPPLE 第 k 发  → 队列第 k 项位置出弹
第 k 发打出后   → 队列第 k 项对应的 missile_bones 隐藏
```

- 第 1 发：从 `variable_aam_1_shoot_barrel` 出，消失的也是 mount_1 的弹 ✅
- 打完 4 发：4 根出弹骨用尽，4 枚弹全隐，`rack_bones`（pylon）常显；
- 衔接位置不受影响：挂架模型仍锚在 mount 部件 `_barrel` 首 Cube。

## 三、新旧对照总表

| 维度 | 旧（现状） | 新（预期） |
|------|-----------|-----------|
| 出弹点配置处 | parts 的 `rvp_structure_bolt_bones`（隐式，与挂架条目无关联） | 挂架条目 `shoot_structure_bones`（显式，紧跟 missile_bones） |
| 出弹位置 | = 衔接骨 `_barrel` 的 Cube | 任意指定骨的 Cube（可与衔接点分离） |
| 消失骨骼 | 条目 `missile_bones` | 条目 `missile_bones`（不变） |
| 开火 ↔ 消失对齐 | 两套数据两个方向（升序开火、降序消失，存在错位） | 同一条队列，构造性对齐 |
| 衔接位置 | mount `_barrel` 首 Cube | 不变（仍 `_barrel` 首 Cube） |
| 每武器独立出弹骨 | 不可能（部件级一份） | 可以（同一 mount 在不同 weapon_id 条目下配不同骨） |
| 未配置新字段 | — | 与现状逐字节等价（存量包零迁移，可逐武器渐进启用） |
| parts 旧参数 | 出弹唯一来源 | 保留为回退；条目配了 `shoot_structure_bones` 的武器站不再使用它出弹 |

## 四、配置约定与注意

0. **命名约定**：字段定名 `shoot_structure_bones`（而非 `shoot_bones`）——条目里
   已有三类骨骼：`attach_bone` 是载具模型骨、`rack_bones` / `missile_bones` 是
   **挂架渲染模型**骨，而出弹点取自**载具结构模型**骨；`structure` 前缀显式区分，
   防止误当作挂架模型骨骼。
1. **对应关系**：`shoot_structure_bones[i]` ↔ `missile_bones[i]`；单弹挂架各 1 项即可。
2. **多 Cube 骨**：一根出弹骨上多个 Cube = 多个发射点，按模型声明顺序展开
   （三联挂架可只写 1 根骨，也等价拆成 3 根单 Cube 骨）。
3. **刚体链约束**：出弹骨应挂在锚定骨同一刚体链下（如同为 `variable_aam_1`
   的子骨），跨独立动画部件时发射位置不跟随那部分动画。
4. **双端一致**：`rvp_custom_mounts` 在服务端（datapack 加载）与客户端
   （`S2CVehicleRvpConfig` 同步）都有完整数据，出弹点双端计算结果一致。
5. **同一 mount 不同武器**：storm_shadow 与 aasm 挂同一 mount 但弹体位置不同时，
   各自条目的 `shoot_structure_bones` 各配各的，互不影响——这是旧写法做不到的。
6. **⚠️ 结构模型铁律（agents.md L20）**：`shoot_structure_bones` 指向的骨骼必须真实
   存在于 `data/rvp/models/bedrock/vehicle/j15.structure.json`。优先**复用既有骨骼**；
   确需**新增骨骼**（如 `*_shoot_barrel`）时，必须先向用户请示获确认，动手前备份原文件
   （复制为 `*.structure.json.bak`），禁止擅自改骨层级/枢轴/cube。
