# HITL 离轴准星对准未加载区域按 R 锁定卡顿修复记录（2026-08-08）

> 对应规范：`../调试与修复规范.md` 第 3 节（文档记录规范）
> 状态：代码已修复，编译待验证，实机待复测

---

## 0. 现象（用户报告）

人在回路电视（HITL TV）导弹的离轴瞄准准星可在
`max_off_axis_lock_angle: 40` 度范围内移动，准星对准的位置按 R 即可设为目标点。
**但当准星对准视距外未加载区域再按 R 锁定时，游戏会卡住 1-2 秒；对准视距内的方块或实体则正常。**

---

## 1. 修复意图

消除「HITL TV 离轴准星指定目标点 → 服务端制导链路」在目标点位于**未加载区块**时的
主线程同步区块加载导致的游戏冻结，同时**保持已加载区域内原有遮挡判定行为不变**。

---

## 2. 根因（调试证据）

### 2.1 调用链

```
按 R → RVP_ClientHitlState.redesignateTargetAtCrosshair（客户端射线 1200 格）
     → C2SHitlDesignate 网络包 → 服务端 missile.rvp$setHitlDesignatedTarget(targetPos)
→ 之后每 tick：RVP_RuntimeHitlTvGuidanceSource.evaluate()
     → RVP_SaclosDesignation.resolveDesignationPoint()
     → RVP_CountermeasureState.queryPoint()
     → hasSightObstruction(seeker, targetPos)
     → seeker.level().clip(ClipContext(...))   ← 卡顿源
```

### 2.2 卡顿机制（javap + client_mappings.txt 反混淆验证）

- 原版 `Level.clip` 每一步射线采样走 `Level.getBlockState`，服务端实现内部调用
  `ServerChunkCache.getChunk(x, z, ChunkStatus.FULL, allowLoading=true)`。
- `ServerChunkCache.getChunk` 在缓存未命中且 `allowLoading=true` 时调用
  `CompletableFuture.join()`，**在主线程同步等待区块生成完成**。
- 单人游戏 = 客户端进程内嵌服务端：R 键后导弹制导每 tick 对弹目连线做 clip，
  一旦连线进入未加载区块即触发同步区块生成 → 冻结整个游戏 1-2 秒。
- 客户端 `ClientChunkCache` 对未加载区块返回 emptyChunk 不阻塞，故纯客户端侧不卡、
  只有服务端卡——与「对准视距内正常、对准视距外卡」的现象完全吻合。
- 弹目最大距离 1200 格（`DESIGNATE_AIM_RANGE=1200`，离轴 40° 内），远超视距，必会触达未加载区块。

### 2.3 旧代码对比结论（用户要求对照 `ywzj_rvp - 副本`）

| 项目 | 结论 |
|---|---|
| 副本 git HEAD | `130af86`（攻顶战斗部、指令线人在回路与 HITL 增强） |
| HITL 链路 8 个关键文件（`RVP_ClientHitlState` / `RVP_ClientHitlUtil` / `RVP_ClientHitlCamera` / `RVP_HitlDesignateOverlay` / `RVP_RuntimeHitlTvGuidanceSource` / `RVP_RuntimeLaserGuidanceSource` / `RVP_SaclosDesignation` / `C2SHitlDesignate`） | 与当前代码 **SHA256 完全一致（IDENTICAL）** |
| 副本 `RVP_CountermeasureState.java` 的 `hasSightObstruction` | 正是**未裁剪的原始 `level.clip`**（= 本次修复前的当前代码） |
| HITL 运行链引入提交 | `78b2b66 迁移激光与人在回路制导运行链`，早于副本 HEAD |

**结论：旧副本与当前的 HITL 制导链路代码完全相同，卡顿根因代码在旧副本中同样存在。**
「旧代码没有这个 bug」与代码事实不符——推测为记忆偏差，或旧版本测试时

## 3. 改动点

文件：`src/main/java/org/ywzj/rvp/countermeasure/RVP_CountermeasureState.java`

1. 新增导入：`net.minecraft.core.BlockPos`、`net.minecraft.util.Mth`、
   `net.minecraft.world.level.Level`、`org.jetbrains.annotations.Nullable`。
2. 两个 `hasSightObstruction` 重载中的 `seeker.level().clip(...)` 替换为
   `isLineOfSightBlocked(seeker, targetPos)`。
3. 新增 `isLineOfSightBlocked`：先把射线终点**裁剪到已加载区块边界内**
   （`clampRayToLoadedChunks`），再用原版 `Level.clip` 做遮挡判定；
   射线起点即位于未加载区块时直接视为视线通畅（返回 false）。
4. 新增 `clampRayToLoadedChunks`：沿射线每 1 格步进，用 `level.isLoaded(BlockPos)` 检测，
   越过最后一个已加载区块时回退到该区块内的最后一个点；起点未加载返回 null。
   射线全部在已加载区块内时返回原终点（行为与修复前完全一致）。
5. 其余逻辑（`query` / `queryPoint` / 实体遮挡 / 诱饵 / 拦截 / `Result`）未改动。

关键代码：

```java
private static boolean isLineOfSightBlocked(Entity seeker, Vec3 targetPos) {
    Level level = seeker.level();
    Vec3 clampEnd = clampRayToLoadedChunks(level, seeker.position(), targetPos);
    if (clampEnd == null) {
        return false;
    }
    return level.clip(new ClipContext(seeker.position(), clampEnd,
            ClipContext.Block.COLLIDER, ClipContext.Fluid.NONE, seeker)).getType() != HitResult.Type.MISS;
}

@Nullable
private static Vec3 clampRayToLoadedChunks(Level level, Vec3 start, Vec3 end) {
    Vec3 dir = end.subtract(start);
    double dist = dir.length();
    if (dist <= 1.0E-4) {
        return null;
    }
    Vec3 unit = dir.scale(1.0D / dist);
    int lastCx = Integer.MIN_VALUE;
    int lastCz = Integer.MIN_VALUE;
    double lastLoaded = -1.0D;
    double d = 0.0D;
    while (d <= dist) {
        Vec3 p = start.add(unit.scale(d));
        int cx = Mth.floor(p.x) >> 4;
        int cz = Mth.floor(p.z) >> 4;
        if (cx != lastCx || cz != lastCz) {
            lastCx = cx;
            lastCz = cz;
            if (!level.isLoaded(BlockPos.containing(p))) {
                break;
            }
        }
        lastLoaded = d;
        d += 1.0D;
    }
    if (lastLoaded < 0.0D) {
        return null;
    }
    return lastLoaded >= dist ? end : start.add(unit.scale(lastLoaded));
}
```

## 4. 预期影响

- **修复**：HITL TV 离轴准星对准视距外未加载区域按 R 锁定不再卡顿
  （服务端 clip 永不进入未加载区块，杜绝同步区块加载）。
- **连带受益**：激光制导（`RVP_RuntimeLaserGuidanceSource`）同样调用
  `queryPoint`，服务端激光对未加载区域目标不再触发同步加载。
- **行为不变**：弹目连线完全在已加载区块内时，遮挡判定与修复前一致
  （返回原终点后 clip）。
