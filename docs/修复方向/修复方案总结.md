# 修复方向总结：纯 Forge 服务端启动崩溃

> 状态：根因已确认，修复方向待用户拍板
> 日期：2026-08-06
> 关联文档：[纯Forge服务端启动崩溃排查.md](../纯Forge服务端启动崩溃排查.md)（证据与机制细节）

---

## 1. 问题

在纯 Forge 1.20.1 专用服务端（`D:\ywzj\Forge-test-server`）启动时，`ywzj_rvp` 与 `ywzj_vehicle`
两个 Mod 容器构造即崩溃：

```
java.lang.RuntimeException: Attempted to load class org/ywzj/vehicle/vehicle/LocalVehiclePlayer
for invalid dist DEDICATED_SERVER
    at org.ywzj.rvp.all.RVP_Entities.<clinit>(RVP_Entities.java:27)
    at org.ywzj.vehicle.all.AllEntities.<clinit>(AllEntities.java:160)
```

## 2. 根因（已确认）

- 本体 `ywzj_vehicle` 的**公共类**（`AmmoEntity`、`AbstractVehicle`、`WeaponUnit`、`RadarUnit`、
  `MissileEntity`、`InputHandler`、`ServerHitVehicleEvent` 等 20+ 个）在**公共方法**里直接引用
  `@OnlyIn(Dist.CLIENT)` 的 `LocalVehiclePlayer`（例：`AmmoEntity.readSpawnData` 用
  `LocalVehiclePlayer.instance.getPlayer()`）。
- 本体公共类自身**没有任何 `@OnlyIn` 成员** → 单独加载时不脏、不做帧重算 → `LocalVehiclePlayer`
  只是惰性引用（死代码），服务端永不解析 → **单独跑本体不崩**。
- RVP 的**公共数组 mixin**（约 39 个直接打带毒本体类：`AbstractVehicle` ×9、`WeaponUnit` ×22、
  `MissileEntity`/`RocketEntity`/`Radar`/`RadarUnit`/`InputHandler`/`ServerHitVehicleEvent` 等）
  使这些类变 dirty → Forge **强制重算栈映射帧** → 算帧解析到 `LocalVehiclePlayer` →
  RuntimeDistCleaner 拦截 `@OnlyIn(CLIENT)` 类加载 → **崩**。本体 `AllEntities.<clinit>:160`
  也是同一个机制（加载被 RVP mixin 改脏的实体类）。

## 3. 关键约束

- **本体 `ywzj_vehicle` 不能修改**（第三方 mod，仅作参考）。只能改 `ywzj_rvp`。
- 新纪律：非必要禁止 Mixin、禁止 `@Overwrite`（见 `agents.md`）。与下述方案 B 存在冲突，需特批。
- 服务端目标：纯 Forge 可启动，不依赖 Sinytra Connector。

## 4. 修复方向对比

| 方向 | 做法 | 效果 | 代价 / 冲突 |
|---|---|---|---|
| A. 修本体（作废） | 把本体公共字节码里的 `LocalVehiclePlayer` 引用挪进 `@OnlyIn(CLIENT)` 方法/桥接 | 根治，怎么改脏都安全 | **本体不能改，不可行** |
| B. 定向去毒（可行） | 对「被打脏 ∩ 带毒」的 8-10 个本体类中**引用 LVP 的方法**用 `@Overwrite` 替换为双端安全实现：服务端安全逻辑/NOOP，客户端经公共接口桥接（`RVP_IClientActions`/`ClientActionsImpl`）走真实逻辑 | 能修好、功能全保、范围有界 | 必须用 `@Overwrite`（`@Inject`/`@Redirect` 都会在 handler 签名里残留 LVP 类型引用，照样崩）；违背禁 @Overwrite 纪律，需特批；需补全 client bridge |
| C. 渐进解绑（长期） | 按新纪律把功能从 mixin 改为事件/接口/网络/数据层，减少公共 mixin 对带毒本体类的依赖 | 符合纪律、长期稳健 | 工程量≈重做 RVP 大半功能，且部分功能无事件替代，**短期内服务端仍跑不了** |
| D. 不改 | 继续依赖 Sinytra Connector 跑服务端 | 零改动 | 服务端无法纯 Forge |

**结论**：本体不能修的前提下，能"修好崩溃 + 保留功能"的唯一现实路线是 **B（定向去毒）**；
C 是长期架构方向，不能作为本次修复手段。

## 5. 修复范围清单（方案 B 待细化）

「被 RVP 公共 mixin 改脏」∩「引用 LocalVehiclePlayer」≈ 8-10 个类，每类只需处理**引用 LVP 的
那几个方法**：

- `AbstractVehicle`（9 个公共 mixin 目标）
- `WeaponUnit`（22 个公共 mixin 目标）
- `MissileEntity`、`RocketEntity`
- `Radar`、`RadarUnit`
- `InputHandler`、`ServerHitVehicleEvent`
- （待确认：`ControlUnit`、`VectorUtil`、`PartUnitData` 等访问器目标是否带毒）

## 7. 技术要点备忘

- 替换带毒方法**只能用 `@Overwrite`**：handler 签名里不得出现 `LocalVehiclePlayer` 类型。
- handler 内也不得直接引用任何 `@OnlyIn(CLIENT)` 类型（mixin 类被改脏重算帧时同样会崩）；
  客户端逻辑必须经**公共接口桥接**（`RVP_IClientActions`，实现类 `ClientActionsImpl` 仅在
  客户端 setup 时挂载，服务端永不加载）。
- 公共数组 mixin 的目标类必须双端安全；纯客户端行为放 `client` 数组。
- 本仓库调试禁止 HTTP 遥测；运行时证据用服务端日志/命令输出收集。
