# 弹体运动学开发与测试

说明 RVP 扩展包中 `projectile_data` 在运行时的行为、与本体 `ywzj_vehicle` 的对应关系，以及如何设计可对比的测试武器。

字段逐项说明见 [RVP包新增参数字段说明.md](./RVP包新增参数字段说明.md) 的「`projectile_data` 弹体运动学」章节。

---

## 1. 配置写在哪里

所有弹体运动学参数写在武器 JSON 的 **`projectile_data`** 对象里（不要散落到已废弃的顶层 `acceleration` 等键）。

```json
{
  "type": "rvp:rocket",
  "velocity": 10,
  "projectile_data": {
    "velocity": 6,
    "gravity": -0.005,
    "drag": 0.01,
    "has_rocket_engine": false
  }
}
```

- **`projectile_data.velocity`**：弹体初速；若写了且 > 0，优先于武器顶层 `velocity`。
- 推进参数（`mass`、`thrust` 等）推荐写在 `projectile_data`；未写的键在 `has_rocket_engine: true` 时，加载阶段会从 JSON **顶层**同名键补全（与本体 `VehicleMissileWeaponData` 字段名一致）。

## 2. 运行时走哪条弹道

实体类：`RVP_BaseBullet`（及子类）。每 tick 在服务端调用 `tickMotion()`，按下面顺序**只进入一条分支**：

```
                    tickMotion()
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   rvp:machinegun   usesPropulsion()   其余
         │          == true             │
         ▼               ▼               ▼
 tickCannonMotion   tickPropulsion   tickBallistic
 (≈ BulletEntity)   Motion           Motion
                    (≈ MissileEntity  (gravity + drag
                     tickMove)        + 可选 constant_speed)
```

### 2.1 机炮弹道（`rvp:machinegun`）

- **实现**：`RVP_BulletEntity`，与本体 `BulletEntity` 相同思路。
- **客户端**：本地按 spawn 速度积分（`setShouldReceiveVelocityUpdates(false)`），不依赖网络速度包。
- **每 tick**：`位置 += 速度` → `速度 *= (1 - friction)` → `速度.y -= gravity`。
- **`projectile_data`** 常用：`velocity`、`gravity`、`drag`、`rotate_to_motion`。
- **不生效**：`has_rocket_engine`、`mass`、`constant_speed`、`max_speed`（机枪专用逻辑忽略这些）。

### 2.2 推力弹道（`has_rocket_engine` 且参数有效）

`usesPropulsion()` 为 true 的条件：

- `has_rocket_engine == true`
- 且 `mass > 0`、`motor_burn_time > 0`，且推力有效（`thrust > 0` **或** 配置了非空 `thrust_curve`；解析后的最终值）

**每 tick（点火后）** 近似：

1. 解析本 tick 的推力与质量（A1 变质量 / A2 推力曲线）：
   - `thrust(tick)`：配置 `thrust_curve` 时按点火后 Tick 区间查表，区间外为 0；否则用标量 `thrust`。
   - `mass(tick)`：配置 `fuel_mass > 0` 时随燃烧线性递减 `mass(tick) = (mass − fuel_mass) + fuel_mass × (1 − tick/燃烧时间)`；否则恒为 `mass`。
2. 沿朝向加速：`Δv += lookDir * (thrust(tick) / mass(tick))`（燃烧时间内）
3. 二次阻力：`Δv -= 速度方向 * (drag_coefficient * |v|² / dragMass) * altitude_drag_factor`，其中 `mass < 1` 时 `dragMass = mass * 1000`，否则 `dragMass = mass`（沿速度反方向）
4. 重力：默认 `PhysicsEngine.G`；若写了 `projectile_data.gravity` 则用该值
5. `位置 += 速度`；可选 `max_speed` / `min_speed` 钳制

> **单位约定（RVP 游戏单位，A3）**：`thrust / mass` 直接作为每 tick 加速度（格/tick²），**不**像本体 `MissileEntity#tickMove` 那样再除以 400（`TICKS_PER_SECOND_SQUARED`）。燃烧阶段的推力、质量解析与速度增量统一由 `RVP_PropulsionMath` 计算；实体链（`tickMissileMove`/`tickHitlTvMove`）、火箭弹道预测（`RVP_RocketBallistics`）与虚拟中段积分（`integrateForces`）共用同一实现，避免推进模型漂移。

**高度倍率默认值**：`altitude_drag_factor` 缺省或为 JSON `null` 时，按世界 Y 使用压缩大气密度表：Y64 为海平面 `1.000`，Y320 约为 `0.316`，Y550 约为 20 km 高度的 `0.073`；表内锚点线性插值。显式 `{}` 保持全高度 `1.0`，显式非空表仍按区间取值，不插值。气动转向启用时也复用该倍率作为密度因子；完整锚点及边界见 [武器参数说明](./plan/RVP武器数据模型/RVP包新增参数字段说明.md)。

**速率状态语义（2026-09-27）**：实体分开维护当前速率基准 `currentFlightSpeed` 与已完成航程历史峰值 `peakFlightSpeed`。普通弹体及未启用恒速的导弹，运动与制导按当前速率处理，历史峰值只用于统计和虚拟中段快照。`constant_speed=true` 的导弹是明确例外：运动与制导按已达到的历史峰值回填速度，仍受 `max_speed` 限制；基础阻力、转向等导致的速度下降会在运动结算后恢复。虚拟段恢复时当前基准仍取末 Tick `velocity.length()`，同时保留虚拟状态的峰值；恒速导弹恢复到实体运动后按该峰值回填。

**与本体**：`RVP_ProjectileMotion` 对齐 `MissileEntity#tickMove()`（推力沿 `getLookAngle()`，`rotate_to_motion` 时先对齐速度）与 `BulletEntity#tick()` 的 `atan2` + `lerpRotation`；制导朝向用 `VectorUtil.vecToRot`。

**客户端**：运动在服务端计算，客户端通过实体同步插值显示（与 `MissileEntity` 一致，不在客户端跑 `tickMotion`）。

#### 2.2.1 冷发射与 GPS PRESET 制导交接

冷发射参数来自载具 `WeaponUnit` 的 `cold_launch_time_tick` 和 `cold_launch_velocity`；发动机点火门仍取
`max(cold_launch_time_tick, ignition_delay_tick)`。需要注意制导和运动的 Tick 顺序：服务端先执行
制导，再执行 `RVP_ProjectileMotion` 的速度积分。

当 GPS 导弹启用 PRESET 且 `cold_launch_time_tick >= ignition_delay_tick` 时，插件会记录冷发射窗口内
“PRESET 已写入制导速度”。冷发射运动层检测到该标记后保留制导速度，避免每 Tick 重新覆盖为载具速度加竖直
冷发射速度；即使下一 Tick 制导源短暂失败，也沿用上一有效制导速度。没有获得过有效制导结果时仍走普通
冷发射分支，因此不会把冷发射参数变成无效配置。

另外，带终端段的 PRESET 弹在发射时若已经处于终端距离门内，会延后终端阶段切换到冷发射/点火窗口结束。
这是为了让主段先完成一次方向接管：终端 ARH 的角度门不能从纯竖直冷发射速度直接把导弹转向 GPS 目标。

这正是 YJ-20（20/20）与 9M723 伊斯坎德尔-M（10/20）表现不同的关键：前者必须在重叠窗口内完成制导
接管，后者的冷发射窗口已在点火延迟前结束。

### 2.3 简化弹道（默认）

未开机炮分支、且 `usesPropulsion()` 为 false 时使用。

- **每 tick**：`速度.y += gravity` → MCH 式水平阻力（`motionX/Z -= (motion/|v|)*drag`，不减 `motionY`）→ 可选 `constant_speed` → `位置 += 速度`。
- `constant_speed=true` 的导弹以历史峰值作为回填基准；非导弹弹体仍以当前速率维持恒速。未设置该字段的导弹允许阻力、穿透或转向造成的减速持续生效。本次规则同步后的构建与服务端冒烟尚未重新执行。
- 适用于：无发动机火箭、滑翔弹、以及 `has_rocket_engine: true` 但缺少 mass/thrust/燃烧时间（会打日志并退回简化弹道）。

子弹药可在 `projectile_data` 配置正数 `deployment_horizontal_half_life_ticks` 与 `deployment_vertical_half_life_ticks`，由生成器分别把速度散布/母弹水平继承形成的 X/Z、速度散布形成的 Y 拆为部署分量。分层圆锥的三个轴可分别阻尼；其 `cone_azimuth_mode` 默认为按序号黄金角，显式 `spawn_radial` 时仅把 X/Z 散布方位改为最终出生点相对释放中心向外，不改变向下 Y 层级。`cloud_radial_horizontal` 的 Y 恒为 0，纵向仍由基础弹道重力独立积分。此时服务器使用：

```text
外部改速并入基础速度
→ 部署 X/Z 按 2^(-1/halfLifeTicks) 衰减
→ 部署散布 Y 按自己的 2^(-1/verticalHalfLifeTicks) 衰减
→ 基础速度执行 gravity/drag
→ 独立风偏贡献收敛
→ 四分量合成并统一限速、移动
```

水平部署分量的 Y 恒为 0，纵向部署分量的 X/Z 恒为 0；基础 `drag` 和风速收敛都不会急刹它们。`gravity`、`payloads_velocity`、碰撞和穿透属于基础速度。两个字段缺省均为 0，未启用时完全保持普通简化弹道顺序；任一字段为正即可启用分量链路。

## 3. 与本体对照

| RVP | 本体（只读参考） | 说明 |
| --- | --- | --- |
| `RVP_BulletEntity` | `BulletEntity` | 机炮积分、双端预测 |
| `tickPropulsionMotion` | `MissileEntity#tickMove` | 推力 + 二次阻力 + 重力 |
| `tickBallisticMotion` | 部分火箭/导弹简化配置 | RVP 统一入口 |
| `RVP_ProjectileData` | `VehicleMissileWeaponData` 顶层 mass/thrust… | 名同；RVP 推荐放进 `projectile_data` |

## 4. 加载期自动处理

`RVP_WeaponTypes` 在反序列化前会归一化 JSON：

| 旧/辅助逻辑 | 行为 |
| --- | --- |
| `projectile_data.acceleration` | 合并为 `velocity` |
| `speed_factor` + `speed_factor_end_tick` | 换算为 `mass` / `thrust` / `motor_burn_time` 并打开 `has_rocket_engine` |
| 顶层或弹体存在 mass/thrust/motor_burn_time | 若未写 `has_rocket_engine`，自动设为 `true` |
| `resolvePropulsionFallback` | `has_rocket_engine` 时，弹体未写的推进键从武器 JSON 顶层补全 |

## 5. 调试建议

### 5.1 先固定变量

对比弹道时，建议一次只改一类参数，其余保持一致，例如：

- 同一 `gravity`、同一 `drag`
- 只改 `velocity` 或只改 `thrust`

对比时可自建临时武器 JSON（复制现有武器改 `projectile_data.velocity`），挂载到测试载具的 `weapons` 列表。

### 5.2 机炮仍「抽搐」时检查

- 顶层 `velocity` 是否为默认 **10** 且与 `projectile_data.velocity` 冲突（非默认顶层会覆盖弹体初速）。
- `spread` / `inaccuracy` 是否过大。
- 载具包是否改在 `run/client_1/limitless_vehicle/rvp/`（当前开发唯一维护路径）。

### 5.3 火箭/导弹轨迹异常时检查

- `has_rocket_engine` 是否为 true 但 mass/thrust/燃烧时间未配齐（会走简化弹道）。
- 推力模式下 `rotate_to_motion` 是否与制导同时改朝向（制导改 `deltaMovement`，推力沿 `lookAngle`）。
- GPS PRESET 导弹发射后持续竖直上冲：先对照 `cold_launch_time_tick` 与 `ignition_delay_tick`，再确认近距离目标是否触发了终端距离门；当前插件会在发射窗口内延后终端切换并保持已接管的 PRESET 速度，不要按武器 ID 增加特判。
- 客户端勿依赖速度同步包；实体类型已设 `setShouldReceiveVelocityUpdates(false)`。

### 5.4 日志

`has_rocket_engine: true` 且推进参数不齐时，服务端会 warn：

`has_rocket_engine=true but missing mass/thrust/motor_burn_time; using simplified ballistics`

## 6. 最小配置示例

**机炮（初速 16）**

```json
"projectile_data": {
  "velocity": 16,
  "gravity": -0.005,
  "drag": 0.01,
  "rotate_to_motion": true
}
```

**无发动机火箭（初速 6，简化弹道）**

```json
"projectile_data": {
  "velocity": 6,
  "gravity": -0.005,
  "drag": 0.01,
  "rotate_to_motion": true
}
```

**有发动机火箭（低初速 + 推进）**

```json
"projectile_data": {
  "has_rocket_engine": true,
  "velocity": 3,
  "gravity": -0.005,
  "rotate_to_motion": true,
  "mass": 0.01,
  "thrust": 0.0012,
  "motor_burn_time": 200,
  "drag_coefficient": 0.008
}
```

**有发动机导弹（推力曲线 + 变质量，A1/A2）**

```json
"projectile_data": {
  "has_rocket_engine": true,
  "velocity": 1.5,
  "rotate_to_motion": true,
  "mass": 0.05,
  "fuel_mass": 0.02,
  "motor_burn_time": 100,
  "thrust_curve": {
    "[[0,20]]": 0.06,
    "[[20,100]]": 0.02
  },
  "drag_coefficient": 0.003,
  "max_speed": 6.0
}
```
