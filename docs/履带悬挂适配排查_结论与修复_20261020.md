## 二、T-90M 全套症状的机理（已确证）

代码链：

1. `TrackUnitData.initStructureModel()`（`TrackUnitData.java:45-84`）
   ```java
   for (BedrockBone trackBone : trackBones) {                 // 结构里 track_link 的 2 个子骨
       String trackName = trackNames.get(trackBone);           // "track_link_L"（大写 L）
       ...
       definitions.add(new TrackDefinition(trackName, List.copyOf(points),
               suspensions.get(trackName)));                   // 数据键写的是 track_link_l ⇒ **null**
   }
   ```
2. `TrackUnit` 构造（`TrackUnit.java:30-33`）→ `createPaths()`（`:50-55`）→ `new TrackPath(points, suspensionUnitIds)`
3. `TrackPath` 构造（`TrackUnit.java:180-189`）：
   ```java
   this.suspensionUnitIds = List.copyOf(suspensionUnitIds);    // List.copyOf(null) ⇒ NullPointerException
   ```
4. 该异常发生在 `BaseVehicleData.createBasePartUnits()`（`BaseVehicleData.java:176-198`），
   而 `AbstractVehicle` 在 **`vehicleData.createPartUnits(this)` 之后** 才
   `partUnits.addAll(...)` / `suspensionUnits.addAll(...)` / `seats.addAll(...)`（`AbstractVehicle.java:456-475`）
   ⇒ **异常抛出后部件表、座位表全空**：

   | 缺失 | 表现 |
   |---|---|
   | 座位表空 | 上不去、无法行驶 |
   | 炮塔部件没建 | 炮塔 OBB 丢失 |
   | 悬挂部件没建 | 负重轮 OBB 丢失、轮子不渲染 |
   | 履带部件没建 | 链板不渲染 |

   ⇒ 与用户报的 T-90M 四个症状**一一对应**，且日志里**没有任何 rvp 相关报错**（`VehicleDataManager`
   的 catch 只覆盖数据 build 阶段，实例创建阶段抛出的异常不会打印"Failed to load vehicle data"）。

**修复**：数据键改为与骨名逐字一致的 `track_link_L`。

> 顺带：日志里 `dragonrise_reforge_ywzj:*` **64 台车全部** `Failed to load vehicle data`，
> 报的正是 `IllegalArgumentException: Track and suspension counts must match`（`TrackUnitData.java:52`）。
> 那是别的模组没适配新履带系统，**不是本次目标**，但说明这条新校验会让不符合新规范的整台载具直接消失。

## 四、链板不渲染：新代码的"静默失效"机制（待一次二分）

### 4.1 关键代码差异（`715c8e9` 履带单元与悬挂联动）

**旧**（`git show 715c8e9^:...TrackUnitData.java`）：
```java
VehicleCubeGroup trackGroup = vehiclePartGroups.get(trackBone);
if (trackGroup == null) { continue; }        // 取不到组 ⇒ 直接跳过这条履带
...
if (!points.isEmpty()) { parsedTracks.add(...); }
```
**新**（当前 `TrackUnitData.java:67-82`）：
```java
VehicleCubeGroup trackGroup = vehiclePartGroups.get(trackBone);
List<Vec3> points = new ArrayList<>();
if (trackGroup != null) { ... }              // 取不到组 ⇒ points 保持空
definitions.add(new TrackDefinition(trackName, List.copyOf(points), ...));  // 照样产出"空路径定义"
```

`TrackUnit.createPaths()` 用 `TrackPath::isValid` 过滤（`TrackUnit.java:491-493`）：空点集 ⇒ `segments` 空 ⇒ 被丢弃；
`TrackUnit.render()` 第一行 `if (isDetached() || tracks.isEmpty()) return;`（`TrackUnit.java:60`）
⇒ **完全没有日志、没有报错、链板不渲染**。

> 因此"链板完全不渲染 + latest.log 干净"这件事，在机制上只可能是
> **`track_link_r/l` 没有拿到 `vehiclePartGroups` 里的 OBB 组（点集为空）**，
> 或者第一行之后的 `display/config/model/texture` 为空。前者是数据问题，后者与 ztz99b 共用同一份
> `track_config`（`rvp:effect/rvp_track`，文件三处均在、md5 一致），可能性低。

### 4.2 OBB 组的生成条件（`BaseVehicleData.java:200-215`）

```java
if (bone.parent != null && bone.parent.parent == null) {   // 只给「根骨的直接子骨」建组
    buildPartUnitsOBBs(bone, group, ...);                  // 递归把组写进 vehiclePartGroups
}
```
即 `track_link` 必须是**根骨**、`track_link_r/l` 必须是它的**直接子骨**（当前 5 台车的 JSON 都满足：
`track_link` 无 `parent`，两个子骨 `parent="track_link"`，且父在子之前）。

### 4.3 一次二分（无需改代码 / 无需重打 jar）

把**任意一台**（建议 bmpt72）的 `display` 里 `track_config` 临时换成本体自带的链板模型：

```json
"track_config": {
  "model": "ywzj_vehicle:effect/track_link",
  "texture": "ywzj_vehicle:textures/effect/track_link.png",
  "module_length": 0.35,
  "track_width": 3.0
}
```

- **链板出现** ⇒ 问题在 RVP 的 `rvp:effect/rvp_track`（加载/渲染），后续查 effect 模型注册与 v1 直渲染路径；
- **仍然没有** ⇒ 点集为空（`vehiclePartGroups` 里没有 `track_link_r/l`），需要给 `TrackUnitData` 加一条
  "点集为空"的告警（RVP 侧可用 mixin/日志补，或请本体作者补），再据日志定位。

另可同时观察：**该车开动时轮子转不转**。
- 轮子转 + 链板无 ⇒ 停留在 `display/config/model` 分支（模型问题）；
- 轮子不转 + 链板无 ⇒ 路径为空（`TrackedVehicleContext.getLeft/RightWheelDegrees` 依赖
  `TrackUnit` 的 `lateralOffset`，路径空则位移恒 0）。
