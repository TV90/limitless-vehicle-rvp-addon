## 0. 铁律（责任边界）

1. **所有问题的责任都在 RVP 侧**。本体 `ywzj_vehicle` 是被引用方，任何
   兼容 / 崩溃 / 功能问题，先假设是 RVP 侧引入，**禁止往"本体有问题、需要修本体"
   的方向思考**。历史上已多次因此走偏。
2. **永不修改本体**。`ywzj_vehicle/` 目录及其构建产物（jar）一律只读；
   需要本体配合时，用 RVP 侧的 mixin / 事件 / 接口 / 网络包 / 数据层解决。
3. 只允许修改 `d:\ywzj\ywzj\ywzj_rvp\` 内的文件（含本规范、docs、src、build 配置）。
4. 服务端运行测试在 `D:\ywzj\Forge-test-server` 执行（运行态产物，非源码修改），
   该目录不做任何源码级改动。

## 1. Mixin 纪律（默认拒绝）

新增任何 Mixin（含 `@Inject` / `@Redirect` / `@Overwrite` / `@Accessor` / `@Invoker`）
前必须逐级排除替代方案，有任一可行即不得用 Mixin：

1. **JSON 数据字段**：`RVP_*Data` 数据模型可表达的行为，优先在数据层配置。
2. **继承 / 接口 / 组合**：本体的可覆写方法、接口实现、`DistExecutor` 分端。
3. **Forge 事件总线**：`MinecraftForge` / `ModBus`（渲染 / Tick / 输入 / 网络注册事件）。
4. **网络包 + 独立管理类**：S2C / C2S 包 + `RVP_*` 独立系统。
5. **`@Accessor` / `@Invoker` 访问器**：仅需读私有字段 / 调 protected 方法时，
   放 `org.ywzj.rvp.accessor`，不新建 mixin 类。

只有确需修改本体 / 原版字节码且上述全不可行时才允许 Mixin，且：

- 改动面必须最小化：只允许最小 `@Inject`（HEAD / RETURN 转发），
  **禁止 `@Overwrite` 整方法、禁止整段 `@Redirect`**；确需改写核心逻辑时先向用户提出非 Mixin 替代。
- **服务端 dist 安全**：公共数组（`mixins`）的 Mixin 会把目标类改脏 →
  Forge 重算栈映射帧 → 目标类方法中若含 `@OnlyIn(CLIENT)` 类型引用
  （`LocalVehiclePlayer`、`Minecraft`、客户端粒子等）会触发服务端加载崩溃。
  精确判定（2026-08-06 与本体作者确认后）：危险的是"**非 `@OnlyIn(CLIENT)` 方法**中
  的客户端类型引用"——这类方法不被服务端 dist cleaner 剥离，LVP 引用留在字节码里，
  帧重算必崩；引用在 `@OnlyIn(CLIENT)` 方法里的类（如 `AmmoEntity`）会被剥离，安全。
  因此：公共数组 mixin 的目标类必须双端安全；`@OnlyIn(CLIENT)` 类型必须经
  `org.ywzj.rvp.client.bridge` 桥接（服务端 NOOP / 客户端真实现）。
- **RVP 侧 `@OnlyIn` 标注纪律**（作者建议落实）：RVP 公共类（非 `client` 包）方法引用
  任何 `@OnlyIn(CLIENT)` 类型（`LocalVehiclePlayer` / `Minecraft` / `ClientLevel` /
  `org.ywzj.vehicle.client.*` / `org.ywzj.rvp.client.*`）时，该方法**必须标注
  `@OnlyIn(Dist.CLIENT)`**，让服务端 dist cleaner 剥离；服务端会执行到的公共方法
  （`tick`、事件监听、网络包 handler）**绝对禁止**引用客户端类型。
- Mixin 类禁止持有共享状态、禁止非私有静态方法；业务逻辑放非 `mixin` 包辅助类。

## 2. 调试证据纪律

- **禁止任何 HTTP / 网络遥测**：不用 debug server、loopback、socket、webhook；
  运行时证据一律通过 Minecraft 命令或日志收集。
- 专用日志优先：`logs/<问题>.log`，不污染 `latest.log`。
- 每次复现必须记录：复现时间、mods 组合（哪些 jar）、启动命令、日志 / 崩溃报告路径、
  崩溃签名（首屏异常类型 + 前 3 帧）。
- 证据归档在 `docs/` 对应调研文档，供后续会话直接恢复上下文。

## 3. 文档记录规范（自动记录）

- 每个阶段的关键结论必须写入 `docs/` 下对应文档，**不能只留在对话里**。
- 变更（代码 / 配置 / 打包）前，先想清楚"这会导致什么功能丢失 / 降级"，并记入第 4 节。
- 每个修复步骤：`意图 → 改动点 → 预期影响 → 验证方式`，随做随记。
- 会话过长或上下文可能丢失前，优先把当前进度落盘。

- 现象：纯 Forge 1.20.1 专用服务端，本体 + RVP 同时加载即崩；
  仅本体正常（`Done (5.307s)!` 已验证）。

  for invalid dist DEDICATED_SERVER`

## 7. 经验教训（2026-08-06 沉淀）

1. **崩溃根因是"帧重算时解析 `@OnlyIn(CLIENT)` 类型"**，不是本体 bug。
   排查先看 `RuntimeDistCleaner` 拒绝的类，再反查谁改脏了它，禁止先怀疑本体。
2. **公共数组 mixin = 服务端毒药**：目标公共类只要含 `@OnlyIn(CLIENT)` 类型引用
   （哪怕在惰性死代码分支），被任何 mixin 改脏就炸。新写 mixin 前先扫目标类常量池。
3. **`@Accessor` 同样改脏目标类**——"只加接口不改方法"也不行，照样全类重算帧。
4. **修复分层**：先"让系统跑起来"（可逆配置改动）→ 再"逐项恢复功能"（每次记录）。
5. **`instanceof` 降级 vs 强转**：对扩展接口一律 `instanceof` 判断，禁止强转
   （mixin 缺失时强转抛 ClassCastException，instanceof 仅静默失效）。
6. **交接 > 聊天**：关键中间产物（中毒方法清单、对照表、命令、日志路径）必须落盘。
7. **用户已否决 `@Overwrite`**：恢复带毒类功能只能用非 mixin 路径
   （继承覆写 / 事件 / 网络包 / 数据层），不允许再提 mixin 重写方案。
8. **本体作者确认（2026-08-06）**：本体公共方法引用 LVP 是设计如此（客户端专用方法，
   如 `readSpawnData`，服务端不执行、dist cleaner 会剥离 `@OnlyIn` 方法）；责任仍在 RVP
   侧——① mixin 帧重算触发不该发生的解析；② RVP 自身公共代码引用客户端类型必须补标
   `@OnlyIn(CLIENT)`（发现 `RVP_ExternalRadarLinkHelper` 3 个方法未标，列为阶段 1.5）。
