# RVP HBM 特效参数迁移视觉工厂框架调研

日期：2026-09-03
范围：**只调研 + 产出方案文档，不改任何 Java 代码、不改任何武器 JSON**。
背景：视觉工厂特效参数（`visual_effect_data[]`）与 HBM 特效参数（`detonate_data.hbm_effect_data`，经
`RVP_HbmEffectData`）同属"爆炸视觉"参数，却写在两套位置、两套加载链路、两套网络通道。用户有意向把
HBM 特效参数并入视觉工厂框架。本文梳理两侧现状、差异冲突、迁移方案（推荐 + 备选）、分端带毒风险与
实施拆分。

---

## 1. 两侧现状

### 1.1 视觉工厂参数框架（`visual_effect_data[]`）

**位置（数据模型）**
- `src/main/java/org/ywzj/rvp/weapon/data/RVP_VisualEffectData.java` —— 单个视觉配置项（公共 schema，无客户端类型）
- `src/main/java/org/ywzj/rvp/weapon/data/RVP_VisualEffectExperimentalData.java` —— 实验开关（当前仅 `dynamic_particle_budget`）
- 归属：`RVP_DetonateData.visualEffectData`（`List<RVP_VisualEffectData>`，`@SerializedName("visual_effect_data")`）

**字段清单（`RVP_VisualEffectData`）**

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 总开关；还要求 `effect_type` 合法 |
| `effect_type` | string | 空 | 客户端工厂类型资源 ID（如 `rvp:thermobaric`） |
| `preset` | string | `rvp:default` | 客户端预设资源 ID |
| `scale` | float | `1.0` | 视觉尺寸倍率（≥0，无业务上限） |
| `density` | float | `1.0` | 服务端允许视觉密度倍率（≥0，无业务上限） |
| `duration_ticks` | int | `-1` | 寿命覆盖（tick），`-1` 用预设 |
| `broadcast_range` | double | `1536.0` | 同维度网络广播距离（格） |
| `sound` / `flash` / `shake` | bool | `true` | 声音 / 闪光 / 镜头震动 |
| `suppress_native_explosion_effect` | bool | `true` | 发布成功后屏蔽本体普通爆炸视觉（不改伤害/方块破坏） |
| `suppress_rvp_default_explosion` | bool | `false` | 屏蔽 RVP 内置 MCHR 默认爆炸视觉（读取不受 enabled 门控） |
| `experimental` | obj | `{}` | 实验配置（`dynamic_particle_budget`） |
| `preset_data` | obj | `{}` | 与 `preset` 同 schema 的稀疏覆盖（≤8 KiB） |

**服务端协调与解析**
- `weapon/visual/RVP_VisualEffects.java` —— 公共协调门面；持解析器列表（默认含
  `RVP_DefaultDetonationVisualResolver`），未安装发布端时 NO_OP；`publishDetonation(context, list)`
  逐项 `resolve` + `publisher.publish`，返回 `RVP_VisualPublishResult(publishedCount, suppressNative)`
- `weapon/visual/RVP_DefaultDetonationVisualResolver.java` —— 首版通用解析器：只校验公共字段
  （`enabled && effectType present && radius finite`），`preset_data` 经 `RVP_VisualPresetDataCodec.canonicalize`
  排序压缩，产出不可变 `RVP_VisualEffectEvent`
- `weapon/visual/RVP_VisualPresetDataCodec.java` —— `preset_data` 深拷贝 + 键排序 + 8 KiB 上限校验
- `weapon/visual/api/RVP_VisualEffectEvent.java` —— 不可变公共领域事件（无客户端类型）
- `weapon/visual/api/RVP_DetonationVisualContext.java` —— 服务端权威上下文（level/position/最终半径/kind/owner/gameTime）

**加载与生效链路**
1. 加载：`all/RVP_WeaponTypes.deserialize` → `GsonUtil.GSON.fromJson(..., RVP_WeaponData.class)` →
   `RVP_DetonateData.visualEffectData`（`List<RVP_VisualEffectData>`）
2. 生效（服务端）：`entity/projectile/RVP_BaseBullet.triggerExplosion` → `RVP_VisualEffects.publishDetonation(
   context, detonateData.getVisualEffectData())`
3. 网络：`RVP_NetworkVisualEventPublisher`（`server/visual/`）→ `PacketDistributor.NEAR` 按 `broadcast_range` +
   维度分发 `S2CVisualEffectEvent`（`network/visual/`，PLAY_TO_CLIENT，schema v1）
4. 客户端：`S2CVisualEffectEvent.handle` → `RVP_VisualEffectEndpoint.accept`（公共门面，专服 NO_OP）→
   物理客户端 `RVP_ClientBootstrap` 安装的 `RVP_ClientVisualEffectDispatcher::accept`
5. 客户端工厂：`RVP_ClientVisualEffectDispatcher`（注册表 + 实例生命周期，同时活动上限 24）→
   `RVP_ClientVisualEffectFactory.create` → `RVP_ClientVisualEffect`（tick/render/close）→
   `RVP_ClientVisualEvents` 推进 tick 与渲染。已注册工厂：`rvp:thermobaric`
   （`RVP_ThermobaricEffectFactory`）、`rvp:mchr_explosion`（`RVP_DefaultExplosionEffectFactory`，MCHR 风格默认烟雾）

### 1.2 HBM 特效参数（`detonate_data.hbm_effect_data`）

**位置（数据模型）**
- `src/main/java/org/ywzj/rvp/weapon/data/RVP_HbmEffectData.java` —— 单对象（非数组）
- 归属：`RVP_DetonateData.hbmEffectData`（`@SerializedName("hbm_effect_data")`）

**字段清单（`RVP_HbmEffectData`）**

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 总开关 |
| `real_explosion` | string | `none` | `none` / `vnt`（HBM 标准爆炸，自带视觉）/ `nuclear`（核爆）——**伤害/方块破坏型** |
| `visual_preset` | string | `none` | `none` / `nuclear`（或 `nuke`）/ `shell` / `bomb` —— 视觉型 |
| `visual_scale` | float | `1.0` | 视觉规模倍率（≥0.1） |
| `visual_density` | float | `1.0` | 数量密度（0.1–1.0 钳制） |
| `visual_backend` | string | `auto` | `auto` / `hbm` / `rvp`（桥接反射 / 自研回退） |
| `visual_sound` | bool | `true` | 视觉音效总开关 |
| `suppress_native_explosion_effect` | bool | `true` | 是否抑制原版爆炸特效 |
| `nuclear_sound` / `nuclear_flash` / `nuclear_shake` | bool | `true` | 核爆音效/闪光/震动（仅 nuclear preset 消费） |
| `effect_yield` | float | `0.0` | 当量（≥0，伤害型） |
| `spawn_frag` | bool | `false` | 抛撒破片（实体型） |
| `white_phosphorus` | bool | `false` | 白磷燃烧（实体型） |
| `chlorine_yield` | float | `0.0` | 氯气当量，>0 启用（实体型） |
| `destroy_block` | bool | `true` | 是否破坏方块 |

**加载链路**
- 同 `RVP_VisualEffectData`：`RVP_WeaponTypes.deserialize` → Gson → `RVP_DetonateData.hbmEffectData`
- 现网使用：仅 `m142_atacms.json`（`visual_preset=nuclear`、`effect_yield=100`、`visual_scale=1.0`、
  `visual_density=0.5`、`real_explosion=none`）与 `m142_rocket.json`（`real_explosion=vnt`、
  `visual_preset=bomb`、`effect_yield=1`、`visual_scale=0.3`、`chlorine_yield=1`、`destroy_block=false`）

**生效路径（服务端）**
- `RVP_BaseBullet.triggerExplosion`（L3477-3490）→ `RVP_HbmEffectBridge.apply(serverLevel, pos,
  hbmEffectData, owner)`：
  - `RVP_HbmEffectBridge`（`weapon/effects/`，**纯反射、软依赖 hbm_ntm_rebirth**）：
    - `applyRealExplosion`：`vnt` → `WeaponExplosionUtil.explodeStandard`；`nuclear` → `spawnNuclearCore`
      /`spawnNuclear` + `NukeTorexEntity.createStandard` + `setCloudDensity`（伤害/方块破坏型）
    - `applyVisualPreset`：`shell`/`bomb` → `ParticleUtil.spawnExplosionSmall/Large`（含全部几何/数量参数推导）
    - `spawnVisualNuclear`：`NukeTorexEntity.createStandard`（蘑菇云）
    - `applyShrapnel` / `applyWhitePhosphorus` / `applyChlorine`（实体型）
  - `RVP_HbmVisualService.spawn`（`weapon/effects/`，自研回退后端）：把 `visual_preset` + 参数打包为
    `S2CNuclearVisualEffect`，**向 `level.players()` 全量广播（无 range 裁剪）**
- 返回 `Result(anyApplied, realExplosionApplied, visualApplied)`；`realExplosionApplied()` 时 `triggerExplosion` 直接 return

**网络通道（S2CNuclearVisualEffect）**
- `network/S2CNuclearVisualEffect.java`：record（preset/x/y/z/groundY/effectYield/visualScale/visualDensity/
  seed/startGameTime/sound/flash/shake）；`RVP_Network` L183 注册（未限定 PLAY_TO_CLIENT direction）
- `handle` → `RVP_NuclearVisualEndpoint.accept`（公共门面，专服 NO_OP）
- 客户端安装：`RVP_ClientBootstrap` L46-52 —— `nuclear` → `RVP_NuclearVisualManager.spawn`；
  `shell`/`bomb` → `RVP_ExplosionVisualManager.spawn`

**客户端渲染体系**
- `client/nuclear/RVP_NuclearVisualManager.java`（核爆蘑菇云，自绘 torex）
- `client/nuclear/RVP_ExplosionVisualManager.java`（shell/bomb 自研烟云 + 冲击波 + DebrisChunk 立体碎块）
- `client/nuclear/RVP_NuclearShockwaveRenderer.java` / `RVP_NuclearShaderRegistration.java`

## 2. 差异与冲突点

| 维度 | 视觉工厂（`visual_effect_data[]`） | HBM 特效（`hbm_effect_data`） | 冲突/影响 |
| --- | --- | --- | --- |
| 数据形态 | 数组（可多效果叠加、可只作屏蔽标记） | 单对象（一个武器一份） | 并入后需决定数组项粒度 |
| 命名 | `scale` / `density`（顶层） | `visual_scale` / `visual_density` | 前缀不一致；并入需统一 |
| 默认值 | `density=1.0`（≥0 无上限）、`broadcast_range=1536` | `visual_density=1.0`（0.1–1.0 钳制）、全量广播无 range | 密度钳制与广播范围语义不同 |
| 伤害/实体能力 | 纯视觉（约定不改 `explosion_data` 伤害/半径/方块破坏） | `real_explosion`/`effect_yield`/`spawn_frag`/`white_phosphorus`/`chlorine_yield` 是**伤害/实体型** | 不能原样并入"纯视觉"框架，需拆分视觉型与伤害型 |
| 特殊效果 | `sound`/`flash`/`shake` 通用 | `nuclear_sound`/`nuclear_flash`/`nuclear_shake`（仅 nuclear preset） | 需映射或扩展通用开关 |
| 分端职责 | 事件协议通用（`S2CVisualEffectEvent` + `RVP_VisualEffectEndpoint`） | 专有通道（`S2CNuclearVisualEffect` + `RVP_NuclearVisualEndpoint`） | 两套网络通道、两套客户端渲染体系 |
| 屏蔽关系 | `suppress_native_explosion_effect` / `suppress_rvp_default_explosion` | HBM 生效（`anyApplied`）→ 屏蔽 MCHR 默认 + 本体 + **视觉工厂**（本批任务1新增） | 并入后需保持"HBM 视觉优先、工厂其余效果被屏蔽"的互斥语义 |
| 软依赖 | 无 | `hbm_ntm_rebirth` 软依赖（反射路径 + 自研回退路径） | 并入后仍须保持软依赖可编译可运行 |
| 广播 | `PacketDistributor.NEAR` + `broadcast_range` | 全 `level.players()` | 需统一裁剪策略 |

## 3. 迁移方案（推荐 + 备选）

### 3.0 红线约束（agents.md）
- 禁止 `legacy*` / `migrate*` 兼容层代码；`RVP_WeaponTypes` 等加载器只接受**当前 schema**；
  改历史 JSON 一律用 `scripts/` 一次性转换，不要塞进 Java。
- 禁止硬编码武器 ID；禁止修改 `ywzj_vehicle` 本体源码；禁止新增 Mixin。
- 因此旧 `hbm_effect_data` 键**不能**在 Java 侧做别名兼容，只能：加载器直接接受新 schema（新键），
  旧 JSON 靠 `scripts/` 转换。

### 3.1 推荐方案：视觉参数并入 `visual_effect_data[]` + scripts 一次性转换

**核心思路**：HBM 特效按"伤害型 / 实体型 / 视觉型"拆分：

1. **视觉型**（`visual_preset`、`visual_scale`、`visual_density`、`visual_backend`、`visual_sound`、
   `nuclear_sound`/`nuclear_flash`/`nuclear_shake`）→ 并入 `visual_effect_data[]` 的一个新效果类型
   `rvp:hbm_explosion`，字段映射到通用 `scale`/`density`/`sound`/`flash`/`shake` + `preset`（
   `rvp:shell` / `rvp:bomb` / `rvp:nuclear`）+ `preset_data` 稀疏覆盖（`visual_backend`、核爆专用开关等）。
2. **伤害型**（`real_explosion`=vnt/nuclear 的真实爆炸、`effect_yield`）与**实体型**（`spawn_frag`、
   `white_phosphorus`、`chlorine_yield`）→ **不并入纯视觉工厂**（违背"不改爆炸数据"的工厂约定），
   迁移到 `RVP_DetonateData` 既有的伤害/实体机制（`explosion_data` 当量换算、`fire_data`、
   `ignite_entity_data`、新 `chlorine_data` 等）或保留独立的 `real_explosion_data` 键（仍走
   `RVP_HbmEffectBridge` 反射，软依赖不变）。
3. **数据模型改造点**：
   - `RVP_VisualEffectData` 或新 `RVP_HbmVisualPresetData`（client preset schema）增加
     `visual_backend` 等字段的 preset 级覆盖；
   - `RVP_DefaultDetonationVisualResolver` 扩展识别 `effect_type=rvp:hbm_explosion`；
   - 移除 `RVP_HbmEffectData` 中的视觉字段（或整体退役该键）。
4. **生效链路改造点**：
   - `RVP_BaseBullet.triggerExplosion`：HBM 视觉改走 `RVP_VisualEffects.publishDetonation`（复用
     `S2CVisualEffectEvent` + `RVP_VisualEffectEndpoint` 通道）；删除 `RVP_HbmVisualService` 的
     `S2CNuclearVisualEffect` 广播与 `S2CNuclearVisualEffect` 通道（或保留给核爆伤害型）。
   - 客户端：新增 `RVP_HbmExplosionEffectFactory`（`client/visual/`），按 `preset` 把
     `RVP_VisualEffectEvent` 翻译成 `RVP_ExplosionVisualManager`（shell/bomb）或 `RVP_NuclearVisualManager`
     （nuclear）实例；注册到 `RVP_ClientVisualEffectDispatcher`。`RVP_ExplosionVisualManager` /
     `RVP_NuclearVisualManager` 从"网络消息入口"改为"工厂实例入口"，渲染逻辑不动。
   - 屏蔽互斥：`triggerExplosion` 中 `hbmApplied`（本批任务1）改为按 `visual_effect_data` 中
     `rvp:hbm_explosion` 条目的发布结果判定；HBM 视觉发布成功时仍屏蔽 MCHR 默认 + 本体 + 工厂其余效果。
5. **旧 JSON 迁移（scripts/，选这条）**：写 `scripts/` 一次性转换脚本，把现网 2 个武器 JSON
   （`m142_atacms.json`、`m142_rocket.json`）的 `hbm_effect_data` 拆成
   `visual_effect_data`（视觉型 `rvp:hbm_explosion` 条目）+ 伤害/实体型字段迁移；`RVP_WeaponTypes`
   加载器**只接受新 schema**，Java 侧零 legacy 逻辑。转换前备份原 JSON（`*.bak`），转换后人工核对。

### 3.2 备选方案 A（最小侵入，暂不迁数据）
保留 `RVP_HbmEffectData` 数据模型与 `S2CNuclearVisualEffect` 通道不动，仅在视觉工厂框架侧注册一个
"适配解析器 + 客户端工厂"，把 HBM 视觉参数翻译成 `RVP_VisualEffectEvent` 协议，复用 `RVP_ClientVisualEffect`
生命周期。优点：改动面小、软依赖与现网 JSON 零变化；缺点：数据仍两套、通道仍两套，未达成"参数并入
视觉工厂框架"的目标，只统一了客户端渲染接口。

### 3.3 备选方案 B（全量并入，含伤害型）
把 `real_explosion` 等伤害/实体型也做成 `effect_type=rvp:hbm_real_explosion`，客户端只渲染、服务端
`RVP_HbmEffectBridge` 照旧反射。缺点：违背视觉工厂"纯视觉、不改爆炸数据"的既定契约，且把服务端反射
伤害逻辑与纯视觉事件协议耦合，不推荐。

**推荐结论**：采用 3.1（视觉并入 + 伤害型留原机制 + scripts 转换）。旧 JSON 迁移选 **scripts/ 一次性
转换**（红线允许的两条之一），Java 加载器直接接受新 schema、零兼容层。

## 4. 分端与"服务端带毒"风险分析

| 类 | 归属 | 说明 |
| --- | --- | --- |
| `RVP_VisualEffectEvent` / `RVP_DetonationVisualContext` / `RVP_VisualEffectData` / `RVP_HbmEffectData` / `RVP_VisualPresetDataCodec` / `RVP_VisualEffects` / `RVP_DefaultDetonationVisualResolver` | 公共/服务端安全 | 仅引用公共类型（`Vec3`、`ResourceLocation`、`ResourceKey<Level>`、Gson），无 `@OnlyIn(CLIENT)` |
| `S2CVisualEffectEvent` / `S2CNuclearVisualEffect` / `RVP_VisualEffectEndpoint` / `RVP_NuclearVisualEndpoint` / `RVP_NetworkVisualEventPublisher` / `RVP_HbmEffectBridge`（反射） / `RVP_HbmVisualService` | 公共/服务端安全 | `handle` 一律经公共门面（`Endpoint.accept`）消费，网络类不解析客户端类型；桥接层纯反射不直接引用 HBM 类 |
| `RVP_ClientVisualEffectDispatcher` / `RVP_ClientVisualEffectFactory` / `RVP_ClientVisualEffect` / `RVP_DefaultExplosionEffectFactory` / `RVP_ThermobaricEffectFactory` / `RVP_ClientVisualEvents` / `RVP_NuclearVisualManager` / `RVP_ExplosionVisualManager` / `RVP_NuclearShockwaveRenderer` / `RVP_NuclearShaderRegistration` / `RVP_MchrSmokeParticle` | **必须留在 client 包** | 引用 `Minecraft`、`ClientLevel`、粒子、渲染、相机等 `@OnlyIn(CLIENT)` 类型 |
| 客户端工厂注册 | 只在 `RVP_ClientBootstrap`（FMLClientSetupEvent） | 专服不执行，不触达客户端类 |
| 跨端调用 | 需走 `org.ywzj.rvp.client.bridge.RVP_ClientActionsAccess` / `RVP_IClientActions`（服务端 NOOP） | 迁移若需客户端侧判定/回调，须经桥接 |

**带毒风险点**
1. `RVP_VisualEffectData` / 新 preset schema 若引入 `@OnlyIn(CLIENT)` 字段 → 专服反序列化即崩；
   必须在公共类中保持零客户端类型（与现有 `RVP_VisualEffectData` 同纪律）。
2. 新解析器 `RVP_DefaultDetonationVisualResolver`（公共）若引用客户端工厂 → 专服加载崩溃；解析器只做
   schema 校验，客户端工厂注册只在 `RVP_ClientBootstrap`。
3. `S2CNuclearVisualEffect` 若被删除，需全仓排查引用（`RVP_HbmVisualService`、`RVP_NuclearVisualEndpoint`、
   `RVP_ClientBootstrap`、`RVP_Network`），避免专服残留。
4. `RVP_HbmEffectBridge` 反射路径一旦改为直接引用 HBM 类型（`com.hbm.ntm.*`）→ 纯 RVP 环境（无
   hbm_ntm_rebirth）编译/运行失败；迁移必须保留"反射 + 自研回退"双路径。
5. `RVP_VisualEffectEvent` 的 `dimension` 用 `ResourceKey<Level>` 作网络字段（S2C encode 用
   `writeResourceLocation`），迁移后 HBM 视觉走该通道，`RVP_HbmVisualService` 全量广播需改为按
   `broadcast_range` 裁剪，否则事件规模放大。

## 5. 实施步骤拆分与风险清单

### 实施步骤（建议顺序）
1. **数据模型**：新增 `rvp:hbm_explosion` 客户端 preset schema（`shell`/`bomb`/`nuclear`），
   `RVP_VisualEffectData` 的 `preset_data` 增加 `visual_backend` 等字段；公共类保持零客户端类型。
2. **服务端解析**：`RVP_DefaultDetonationVisualResolver`（或新增 `RVP_HbmVisualResolver`）支持
   `effect_type=rvp:hbm_explosion`，把 HBM 视觉参数翻译成 `RVP_VisualEffectEvent`。
3. **生效链路**：`RVP_BaseBullet.triggerExplosion` 中 HBM 视觉改走 `publishDetonation`；`hbmApplied`
   判定改为基于 `rvp:hbm_explosion` 条目的发布结果；保持对 MCHR 默认 + 本体 + 工厂其余效果的屏蔽互斥。
