# RVP炮火支援终端使用与配置指南

> 适用版本：Minecraft 1.20.1 Forge / `ywzj_rvp` 阶段 E（2026-09-06）  
> 正式配置：`limitless_vehicle/rvp/data/rvp/fire_support_profiles/default.json`  
> Schema：[fire_support_profile.schema.json](./schemas/fire_support/fire_support_profile.schema.json)  
> 作者示例：[default.json](./examples/fire_support_profiles/default.json)

## 1. 玩家操作

1. 从 `ywzj_vehicle:tab_rvp` 创造栏取得“RVP炮火支援终端”。
2. 主手或副手持有终端，右键或按 K 打开战术地图炮火工具。
3. 依次选择弹种、射击模式与落区；在地图左键设置锚点。
4. 条状/徐进弹幕可拖动方向手柄；侧栏可调整半径、长度、宽度与步长。
5. 检查非权威弹数/呼叫时间预估，点击“确认呼叫”。服务端会重新校验全部选择。
6. 呼叫阶段可换手、换快捷栏或把绑定终端移入背包；死亡、断线或终端离开物品栏会取消。
7. 进入打击阶段后任务与玩家生存、连接和 `/reload` 解耦。只有任务所有者再次主手或副手持有同一终端实例时才能请求停火；停火默认 80 Tick 后生效，已生成弹体不会删除。

不持终端按 K 时仍保持普通战术图/载具炮兵图分流。终端上下文不会借用载具 `ARTILLERY` 射击链。

## 2. 正式 profile

首个正式 profile 为 `rvp:default`，只引用阶段 B 探针和载具路径已实机验收的非制导武器 `rvp:f14d_mk84`。该武器作为真实 RVP 炸弹模板，保留碰撞、引信、爆炸、模型、声音与归属；Java 中没有按武器 ID 分支。

| 选项 | 正式值 |
| --- | --- |
| 一基数 | 4 发 |
| 急促射 | 6 发，40 秒呼叫，60 Tick 主射，散布 ×1.5 |
| 效力射 | 2～3 发试射 + 8 发主射，60 秒呼叫，180 Tick 主射 |
| 监视射 | 2～3 发试射 + 8 发主射，60 秒呼叫，600 Tick 主射 |
| 点状弹幕 | 半径 4～32 米 |
| 条状弹幕 | 长 24～96 米、宽 4～32 米 |
| 徐进弹幕 | 长 32～112 米、宽 4～32 米、步长 4～32 米 |

正式配置限制为单玩家 1 个、全服 4 个活动任务，单任务最多 16 发、最多 12 个唯一落点 Chunk。落点实际跨越超过 12 个唯一 Chunk 时任务以 `CHUNK_LIMIT` 失败，而不是继续扩大加载范围。

## 3. 配置作者流程

复制 [作者示例](./examples/fire_support_profiles/default.json)，放到：

```text
limitless_vehicle/<包名>/data/<namespace>/fire_support_profiles/<path>.json
```

资源 ID 为 `<namespace>:<path>`。配置只接受 `schema_version: 1`，不兼容旧键、不迁移旧版 JSON。先用 Draft 2020-12 Schema 做编辑器校验，再以服务端 reload 日志为最终结论；运行时解析器还会检查跨字段约束、武器索引、有限数、步长、任务持续时间与性能预算。

新增弹种时：

- `weapon` 必须解析为真实 `RVP_WeaponData`；
- 首版 `vertical_projectile` 拒绝 `LASER`、`TARGETING_POD`、HITL 和依赖持续操作手/武器站目标点的武器；
- 只选择已通过无载具探针的武器；
- 不把 `fire_data.fire_mode`、`burst_count` 或 `canister_count` 当成任务弹数；
- 新几何或新投送方式应注册类型化工厂，不在任务管理器里按 ID 分支。

## 4. 资源与本地化

物品模型使用 `minecraft:item/generated`，贴图位于 `assets/ywzj_rvp/textures/item/fire_support_terminal.png`。贴图为 32×32 RGBA 像素风资源，不涉及任何 Bedrock 载具结构模型。

终端名称、tooltip、三种射击模式、三个阶段、三类落区、动态参数、任务状态以及所有服务端拒绝原因均有 `zh_cn` / `en_us` 对应键。配置中的 `translation_key` 只负责显示，不参与权限判断。

## 5. 性能与安全预算

系统同时应用 profile 限制和不可配置硬上限：

| 预算 | 硬上限 / 正式 profile |
| --- | --- |
| 顶层炮火弹体生成 | 8 发/服务器 Tick |
| 新增预加载 Ticket | 24 个/服务器 Tick |
| Chunk 等待 | 200 Tick |
| 全局活动任务 | 硬上限 64；正式 profile 4 |
| 单任务顶层弹 | 硬上限 512；正式 profile 16 |
| 武器生命期 | 2400 Tick |
| 单发直接子实体 | 256 |
| 单任务顶层+直接子实体 | 4096 |
| 主爆炸半径 | 64 格 |
| 主爆炸伤害 | 100000 |

预算解析使用饱和整数运算，避免恶意 `release_events × payload.count` 溢出。首版拒绝 `allow_submunition=true` 的多级子母弹链，因为仅凭单一武器快照无法证明跨武器链的全局上界；一层子母弹仍可在上述直接展开预算内使用。

正式 MK-84 的审计结果为：`life=1200` Tick、直接子实体 0、主爆炸伤害 1200、半径 18。正式 profile 最坏为 4 个并发任务 × 11 发 = 44 个顶层弹体；不存在子体放大。低 TPS 只延后游戏 Tick，调度器不会用墙钟补发，且每个实际 Tick 仍受 8 发全局预算约束。

## 6. 验证与排障

构建：

```powershell
$env:JAVA_HOME='对应本地java路径'
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=自设定临时目录'
./gradlew build
```

专服冒烟运行 `./gradlew runServer`，每 10 秒检查 `run/server/logs/latest.log`，出现 `Done (Xs)!` 才通过。日志检索必须按 [调试与修复规范](./调试与修复规范.md) §5.1 只判断新增错误。

载具包不会由 Gradle 自动复制到 `run/*`。测试正式 profile 前需把仓库 `limitless_vehicle/rvp` 全量同步到对应运行目录；不要只复制单个 JSON 后误把版本差异当成炮火故障。

客户端最终人工回归至少覆盖：主/副手入口、K 键原分流、三类预览和拖柄、小分辨率裁剪、旧 revision、生命周期、停火、重连、`/reload`、宽落区 Chunk 上限，以及原 GPS/雷达/载具 `ARTILLERY` 与类型化弹体渲染。
