# RVP 全类型导弹虚拟中段接入

日期：2026-11-04。实现对象为 `RVP_MissileEntity`；保留每把武器的显式开关，不批量开启载具包配置。

## 1. 现在允许哪些导弹

不再按制导类型或载荷设置准入白名单。当前武器 schema（JSON 配置格式）接受的导弹类型均可申请：

| 制导配置 | 人话说明 |
| --- | --- |
| `NONE` | 无制导，按当前运动继续飞行 |
| `GPS` | 飞向指定坐标，可带 PRESET 预设曲线 |
| `MCLOS`、`SACLOS`、`LBR` | 手动指令、瞄准线指令、沿光束飞行 |
| `SALH`、`LH` | 激光照射或激光点引导 |
| `TV`、`HITL_TV`、`HITL_CLOS_TV`、`ATV` | 电视观察、操作手指定、电视指令和自动电视制导 |
| `IR`、`AIR` | 红外及主动红外导引头 |
| `ARH`、`SARH` | 主动雷达及半主动雷达导引头 |
| `ARM` | AntiRadiation，追踪雷达辐射源 |

末段换导引头、攻顶曲线、动态实体目标、近炸/近地引信、跳弹、子母弹布撒和线导不再导致整个弹种被拒绝。内部枚举 `IOG` 是惯导回退标识，仍不能直接写入武器 JSON，本次不增加旧键或别名。

武器仍须配置：

```json
"virtual_midcourse_data": {
  "enabled": true
}
```

未写或设为 `false` 时保持关闭。仍检查最小飞行时间、离开发射点距离和距目标距离；默认分别为 0 刻、800 格、1600 格。没有目标点的导弹跳过目标距离检查。Tick 是游戏刻，正常速度下每秒 20 刻。

冷发射/延迟点火未结束、正在等待区块、当前在水中、部署运动或智能引信已接管时，暂时保留实体；恢复实体后另留 20 个飞行刻的切换冷却。保留现有恢复超时和配置校验。

## 2. 怎样保持制导和操控连续

转虚拟时把**原来的导弹对象**移出世界索引、追踪和逐刻调度，交给虚拟记录持有；不再创建只保存 GPS 状态的替身。原版公开的非销毁移除接口完成移出，已有雷达、拦截弹、武器站和电视会话继续持有同一对象。恢复时重新加入原对象。

虚拟阶段继续调用正式实体的制导和运动方法。位置、速度、机头、角速度、发动机、导引头、输入序号、反制状态、引信航程和布撒进度保持连续。配置重载必须重建对象时，交接已有目标引用和电视会话；等待期间新收到的指定目标也会在存档/重建前采集，不能被上一飞行刻的快照覆盖。

服务端电视输入、指定、退出和引爆使用真实/虚拟统一查找，继续执行原有射手与远程会话权限校验。客户端镜头和已有发射跟踪可读取已授权的显示对象；对象不入世界，也不因显示而进入雷达目标表。显示消息新增制导阶段，操作提示不再因缺少实体 Tick 退回主段；已建立的电视操控可沿用原控制距离接收画面位置。

主动电子干扰 ECM、定向红外反制 DIRCM 的目标查询包含虚拟导弹，不能靠虚拟化躲开反制。

## 3. 什么时候恢复实体

保留接近目标的恢复门。另在下列世界交互到来前暂停飞行并申请恢复：已加载的实体/障碍/水体进入预检范围、近地引信、定时引信、测距空爆、距离自毁、布撒到期、跳弹后计时、已触发攻顶引信、反制自毁或已授权的手动引爆。

预检只决定提前交回实体，实际碰撞、引爆、伤害和子体生成仍走原实体链。子母弹在虚拟段只推进未到期的倒计时，不生成子体、不消耗释放次数。

地形射线仅使用 `getChunkNow` 读取已存在的区块，方块形状查询邻块也受同一边界保护。即使路径两端未加载，中间已加载的墙体/水体仍参与预检。单条射线超过 4096 格直接请求恢复，避免无限遍历。

**未知地形仍然未知**：虚拟飞行不模拟未加载区域的山体、玩家建筑或水体。目标实体查询也只看已加载实体和现有虚拟记录。未知高度不能冒充有效高度参与制导。恢复时按原全局预算申请区块票据（请求世界准备恢复区域），区块就绪后才重新入世；等待期间暂停，超时按现有配置丢弃。

转换依然由开关与时间/距离条件触发，不是“即将踏入未知区块”事件。进入一个已加载的空区块也不保证立即恢复；恢复由目标距离及上述交互预检决定。

## 4. 存档和网络

单条记录格式保持 2，轨迹实现保持 `rvp_entity/1`；增加可选的 `runtimeData`，内部版本为 1。原有 GPS 记录没有该扩展仍可读取，不迁移武器 JSON。扩展保存导引头/反制计时、控制输入、引信航程、布撒波次和待恢复武器站名称；来源、目标和命中历史用 UUID（长期身份编号）重绑，不能把重启前的整数编号误认成新实体。

读档先建立全部虚拟目标的对象身份，再统一重绑运行态；虚拟拦截弹不会因为被拦截弹创建得晚就丢掉指定目标。配置重载仍迁移已有对象引用。

GPS RADAR 上行标记随运行态保存，重建后按当前配置读取间隔。原实施文档提及的上行管理器首次间隔溢出是既有独立问题，本次未改其调度算法；本次验证直接收到更新点后的交接与飞行连续性。

网络协议 **44**，客户端与服务器需一起更新。没有新增 Mixin 类、注入点或访问器；只把既有电视镜头注入中的查找转到统一入口。没有修改本体源码、武器 JSON 或结构模型。
