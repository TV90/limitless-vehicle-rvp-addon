# RVP 攻角双轴有效惯量降阶模型实现

> 状态：2026-10-20～21 已完成代码、自动化测试及专用服务端冒烟；客户端实射尚待验收。
> 本次在现有攻角分支增加无滚转、双轴、有效转动惯量响应，不新增或修改 JSON 配置项，不改资源、本体源码或 Mixin。

## 1. 结论与适用范围

原攻角模型已经把机头轴与速度轴分离，但机头每 Tick 只按固定比例球面插值，没有跨 Tick 角速度。本次增加俯仰、偏航角速度，使机头转向具有加速、制动及反向滞后，并让质量、现有动压参与响应。

这仍是游戏化降阶模型，不是完整刚体 6DOF：

- 只有俯仰、偏航两个姿态通道，没有滚转状态。
- “有效惯量”是质量派生的经验响应系数，不是单位为 kg·m² 的真实转动惯量。
- 不计算几何惯量张量、实际气动力矩、陀螺耦合、独立侧滑状态或真实升阻力表。
- 总攻角仍由机头与速度的夹角派生，不新增独立攻角积分变量。

沿用原门控：RVP 导弹、非智能引信精确追点接管、`rvp_aero_steering=true`、有限的 `rvp_attack_angle_limit_deg∈(0,90)`，并且显式配置 `rvp_maxg` 或当前有效 `turning_factor<1`。未配 factor 时运行时仍回退 0.5；未配 G 的瞬转弹继续豁免。

已有开启攻角的导弹会直接使用新响应，没有独立的“惯量开关”。未开启攻角的分支不接入本执行器。显式 0 G 仍允许机头动作和沿机头推力，只禁止气动法向速度转向。

## 2. 状态与单位

`RVP_AttackAngleState` 是不可变数学快照：

| 字段 | 含义与单位 | 约束 |
| --- | --- | --- |
| `pitchDeg` | 机头俯仰，度 | Minecraft 向下为正，限制在 [-90,90] |
| `yawDeg` | 机头偏航，度 | Minecraft 旋转约定；误差按最短角环绕 |
| `pitchRateDeg` | 俯仰角速度，度/Tick | 安全限幅 ±90 |
| `yawRateDeg` | 偏航角速度，度/Tick | 安全限幅 ±90 |

执行器按一个完整游戏 Tick 积分，不按真实墙钟时间补偿卡顿。双精度三角函数重建机头方向；实体和虚拟状态的姿态边界仍使用既有 float 旋转字段。竖直方向换算保留参考偏航，避免方向极点的无意义翻面；这不等同于无奇点的完整刚体姿态积分。

## 3. 质量、动压与推进公式

### 3.1 质量来源

`RVP_PropulsionMath.resolveAttitudeMass` 统一提供实体和虚拟攻角路径的惯量质量：

- 点火前，包括冷发射延迟覆盖点火延迟的窗口：使用满载质量，不提前扣燃料。
- 有效主发动机燃烧中：沿用既有 `resolveMassAt` 变质量公式。
- 主燃尽、滑翔及二脉冲：沿用既有主燃尽质量口径，不在读取质量时触发二脉冲。
- 无有效推进时保留数据访问器返回的满载质量；未启用火箭发动机时，该访问器返回 0，执行器随后使用基准质量。

有效惯量采用与现有阻力层相同的质量量级约定：

```text
mass 非有限或 <= 0   → massKg = 100
0 < mass < 1         → massKg = mass × 1000
mass >= 1            → massKg = mass
Ieff = clamp(sqrt(massKg / 100), 0.6, 3.0)
```

100 kg、0.6 和 3.0 均为代码内常量，不是新配置。此换算不改变推力除以原始质量的既有公式，也不是 JSON 单位迁移；小于 1 的约定具有历史兼容性质，不应据此把该系数解释为真实惯量。

### 3.2 双轴离散响应

先将制导期望方向限制在当前速度轴周围的攻角锥内，再换算为目标俯仰/偏航。

```text
qp = 共用气动模型的归一化动压因子
baseResponse = 显式 rvp_maxg 时取 0.5，否则 clamp(turning_factor, 0, 1)
response = baseResponse × sqrt(qp)
k = 1 - exp(-1 / Ieff)

pitchError = targetPitch - pitch
yawError   = wrapDegrees(targetYaw - yaw)
每一轴：
  targetRate = clamp(error × response, -90, 90)
  nextRate   = rate + (targetRate - rate) × k
  nextAngle  = angle + nextRate
```

`qp` 通常为 `clamp(densityFactor×(speed/referenceSpeed)²,0.05,1)`；参考速度关闭或非法输入的处理完全复用现有气动工具。

采用指数松弛，而不是直接使用 `1/Ieff` 更新增益，避免 `Ieff<1` 时出现离散更新增益大于 1 的数值过冲。这只保证角速度松弛增益有界，不代表整条闭环弹道完全无瞬态过冲。

### 3.3 约束与退化

- 某轴本步会沿误差方向跨过目标时，只走到目标并将该轴角速度归零。
- 反向指令不直接翻转角速度；可能先沿原方向继续转动，再制动回转。
- 俯仰碰到 ±90° 限位时清理该轴角速度。
- 实际机头超过总攻角锥时做球面裁剪，并投影移除朝锥外增长的角速度分量，保留锥面切向运动；必要时等比例限速。
- 零速或攻角门控关闭时清零角速度，不凭空生成速度。实体离开攻角区间或被智能引信接管时也会清理残留角速度。
- 无目标时以当前速度轴为目标继续推进；不能再要求每个回正 Tick 的攻角严格单调下降。

硬约束只作用于制导阶段。后续重力、推力、干扰等仍可能使运动结束时的机头—速度夹角超出控制锥。

## 4. 气动力与能量契约

新执行器只替换机头响应环节，保留：

1. `λ = clamp(sin(α)/sin(α_limit),0,1)`。
2. 法向过载为 `availableGs×λ`，继续受原 G、动压、`rvp_turn_rate_limit` 约束；速度最多转到机头方向。
3. 气动转向保持速率；推力仍沿机头，阻力、重力、速度钳制仍由运动阶段处理。
4. 诱导阻力按 `rvp_induced_drag×λ²×speed` 只结算一次；恒速豁免保持不变。

“公式不变”不代表数值弹道不变：机头建立攻角的时间改变后，实际 λ、转弯半径、阻力损失及交会误差都会随之变化。

### 4.1 冷发射攻角导弹的机头初始化

冷发射攻角导弹在生成时存在两个不同的方向来源：发射瞄准方向和
`cold_launch_velocity` 指定的冷发射方向。攻角模型允许机头轴与速度轴分离，且攻角导弹不会
使用 `rotate_to_motion` 把机头强行贴回速度；如果直接继承发射瞄准姿态，发动机点火后推力会沿
旧的机头方向施加，造成垂发导弹先产生错误的前向速度分量，再逐步转向目标。

当前实现的冷发射交接规则如下：

1. `RVP_ProjectileMotion.finalizeSpawnOrientation` 在弹体入世前检查冷发射时长和攻角门控；
   只有同时满足 `cold_launch_time_tick > 0` 且启用攻角模型的导弹进入该初始化。
2. `cold_launch_velocity` 仍按 `WeaponUnit` 的局部 X/Y/Z 语义解释，再使用载具主 OBB 的世界轴
   转换为当前世界方向。即 `[0, 2, 0]` 表示“沿载具自身 Y 轴向上”，不是固定世界 `+Y`。
3. 转换后的方向归一化后写入 `RVP_AttackAngleState`，并把俯仰/偏航角速度置零；因此导弹以冷发射轴
   作为初始机头，而不是继承初始瞄准轴的攻角状态。
4. 该步骤只校准机头状态，不修改 `deltaMovement`、冷发射速度大小、发动机点火时刻、正式制导起始 Tick
   或推力/阻力公式。HQ9B 的 20 Tick 冷发射和 `guidance_tick_range=[[20,inf]]` 仍然有效。
5. 如果没有载具、主 OBB 或有效冷发射向量，初始化安全跳过，保留原有发射姿态；普通弹、非冷发射导弹
   和未启用攻角模型的导弹不受影响。

该规则仍是无滚转模型：OBB 只提供冷发射方向，最终仅写入俯仰和偏航两个机头通道，不新增滚转状态。

## 5. PIP 适配

PIP 几何相遇点及旧 factor/G 外环预算不改。`RVP_PIPAttackAngleController` 改为显式读取本 Tick 的双轴状态、冻结的动力快照和惯量质量：

1. 保留最多 10 次二分，试算所需机头偏角；`evaluateBody` 只计算指定姿态的气动力，再计入沿机头推力，不积分角速度。
2. 以目标姿态误差反解两轴指令，扣除 `(1-k)×旧角速度`，不再使用旧 slerp 响应反解。
3. 解析逆解超出可达域时，补试同转弯平面的锥边指令，选择实际机头更接近目标姿态的结果，避免欧拉角外推跨半球后反向控制。
4. 所有前向试算读取同一个不可变初始状态。只提交所选结果一次，不能把候选试算串成多 Tick 积分。
5. `responseLimited` 根据实际机头与理想姿态的偏差报告不可达，不代表突破 G 或惯量限制。正式运动才施加推力及诱导阻力。

无解 PIP 的原追踪回退不变；虚拟 GPS/PRESET 不因此新增 PIP。四参数 `RVP_AttackAngleModel.solve` 只是“零初始角速度、基准质量”的单步便捷入口，连续实体/虚拟/PIP 必须显式传递状态。

## 6. 实体、虚拟态和存档

| 环节 | 当前实现 |
| --- | --- |
| 实体连续 Tick | `RVP_BaseBullet` 保存 `attackPitchRateDeg/attackYawRateDeg`；`xRot/yRot` 仍负责姿态同步 |
| 提交 | `applyAttackAngleSolution` 写回姿态、角速度、载荷及单步标记；无目标兜底不重复积分 |
| 区块等待 | 沿用既有等待门；暂停 Tick 不推进执行器 |
| 虚拟状态 | `RVP_VirtualTrajectoryState` 增加 `pitchRateDeg/yawRateDeg`；原构造器默认两者为 0 |
| 虚实交接 | 创建及恢复轨迹快照同时交接角速度，不能从速度轴重建机头或把角速度重新置零 |
| 实体 NBT | `rvpAttackPitchRateDeg`、`rvpAttackYawRateDeg` |
| 虚拟快照 NBT | `pitchRateDeg`、`yawRateDeg`，原有 `xRot/yRot` 保留 |
| 远距显示 | 不新增角速度网络字段；视觉克隆只消费既有姿态，不承担权威惯量积分 |

恢复时仅校验角速度，不额外环绕已有姿态角，避免影响非攻角弹或旧帧旋转插值。虚拟快照会拒绝非有限姿态/角速度；缺失角速度 NBT 键读零只提供安全默认值，不代表旧积分器状态兼容。

### 升级警告

`RVP_RvpTrajectoryIntegrator.VERSION` 从 **9 升为 10**，实现 ID 仍为 `rvp_current`，快照 schema 仍为 1。

管理器会以 `INCOMPATIBLE_INTEGRATOR` 终止版本不匹配的在途虚拟记录，不会迁移、重建或自动恢复；该检查不只影响已启用攻角的旧记录。部署或回退前应确保没有在途虚拟弹。本次没有扩大虚拟化准入条件，也未补齐第二脉冲触发、载机冷发射、风场/水中、GPS 特殊阶段的全链路等价性。

## 8. 诊断与验证结果

生命周期快照新增：

- `attackPitchRateDeg`：俯仰角速度，度/Tick。
- `attackYawRateDeg`：偏航角速度，度/Tick。
- `attackEffectiveInertia`：有效惯量系数，无量纲；不是 kg·m²。

应结合 `attackAngleActive`、`bodyVelocityAngleDeg`、`aeroLoadFactor`、`aeroAvailableG` 与 PIP 的 `responseLimited` 阅读。关模时存在质量派生诊断值不表示惯量参与了飞行。

### 8.2 PIP 精度与测试预算调整

以下是实际 Java 数学层的四组恒速、匀速横穿、首次相对线段交会测试，不是实机命中率。弹速/参考速度 5.5 格/Tick、factor 0.1、攻角上限 60°、惯量质量 100 kg，目标横穿速度 2 格/Tick；不包含世界碰撞、引信、重力和推力。

| 密度倍率 | 初始距离（格） | 原无攻角外环基线（格） | 双轴惯量 + PIP（格） |
| --- | --- | --- | --- |
| 1.00 | 300 | 0.231910 | 0.273421 |
| 0.50 | 300 | 0.231910 | 0.381363 |
| 0.25 | 600 | 0.000974 | 0.017977 |
| 0.25 | 1000 | 0.000003 | 0.017497 |

最大额外误差约 0.149453 格。原测试要求比基线最多增加 0.05 格，本次明确调整为同时满足 **绝对首次交会误差 <0.5 格、相对基线增量 ≤0.2 格**，以容纳新惯量滞后；没有提高 G 预算，也没有把不可达请求伪装成可达。96 组动力/目标运动组合仍主要验证有界性，不代表全部命中。

## 9. 回退与关联文档

本次没有独立 JSON 惯量开关。经用户确认后关闭某弹的现有攻角配置，只会退回“无攻角”路径，不能恢复为“有攻角但无惯量”的旧模型。若需要后者，必须成组回退执行器、PIP、状态交接与版本契约，不能只删除两项角速度字段；不要用伪造积分器版本号强行续算存档。
