# RVP 导弹攻角：阶段1实现

## 范围与启用

本阶段落地 Java 数据字段、共用数学模型、实体制导/运动、虚拟中段、姿态恢复及回归测试。默认关闭；未修改任何载具包武器 JSON、模型、贴图、音效或本体源码，没有新增 Mixin/访问器。数值选型与各弹种实机调参留到后续阶段。

在武器 `projectile_data` 中显式设置 `rvp_aero_steering=true` 和有效 `rvp_attack_angle_limit_deg` 才可开启。后者单位为度，有限范围 `(0,90)`；缺省、null、0、负数、90 及以上或非有限值都关闭。仅导弹使用；普通炮弹/火箭不接入。

- 仍使用已有 `rvp_maxg` / `turning_factor` / `rvp_ref_speed` / 高度密度 / `rvp_turn_rate_limit` / `rvp_induced_drag`。
- 显式 `rvp_maxg` 优先，包含 0 G；未配 G 且 `turning_factor>=1` 的瞬转弹继续豁免。
- `rotate_to_motion` 不能覆盖已开启攻角的机头姿态。
- `constant_speed` 继续豁免诱导阻力；有发动机时仍按既有峰值速率规则补速。
- 智能引信精确追点接管阶段沿用原来的单调收敛速度及姿态，不使用攻角模型。

## 游戏化数学模型

采用无滚转、无角动量、无侧滑独立状态的准三自由度近似，不是六自由度空气动力学。速度轴暂以世界速度近似相对气流方向，不引入环境风速场、升阻力表或真实武器参数。

每个飞行 Tick：

1. 原有制导算法生成期望方向；开启攻角时跳过旧速度预插值，避免双重限转。
2. 机头以球面插值转向期望方向。未配 G 时响应比例取 `turning_factor`；显式 G 时固定为 0.5，以保持 G 高于 factor 的既有优先级。
3. 把受控机头限制在当前速度轴周围的攻角锥内。载荷 `λ=sin(α)/sin(α_limit)`，范围 0～1。
4. 以 `availableGs × λ` 计算法向转角，继续受绝对转角限制，最多转到机头轴，保持速率不变。
5. 运动阶段沿机头施加推力，执行原有基础阻力/重力与速率限制，再扣 `rvp_induced_drag × λ² × speed`。诱导阻力不额外执行第二次。

0 G 仅禁止气动法向转向，不禁止机头动作，也不禁止沿机头的推力改变速度。攻角锥在制导阶段约束姿态；运动阶段的重力、风偏、干扰可能令最终瞬时夹角超过上限，下个 Tick 再收敛。无目标/丢锁时以当前速度为期望方向，残余攻角逐步回正并继续结算载荷。强制干扰形成的实际夹角按饱和载荷记录，与本 Tick 制导载荷取最大值，避免漏记阻力。

## 代码落点

| 部位 | 实现 |
| --- | --- |
| 配置与门控 | `RVP_ProjectileData`、`RVP_AeroSteeringLimits` |
| 纯数学 | `RVP_AttackAngleModel`、`RVP_AttackAngleSolution` |
| 常规/PRESET 制导 | `RVP_GuidanceRuntimeMath` |
| HITL/线导 | `RVP_WireGuidanceSteering`；攻角分支不再把速度强投到机头方向 |
| 实体推进与姿态 | `RVP_ProjectileMotion`、`RVP_BaseBullet`，利用现有 xRot/yRot 同步，不增加网络状态 |
| 干扰记账 | `RVP_RuntimeSaclosGuidanceSource`、`RVP_JamDeflectionHelper` |
| 虚拟中段 | 参数工厂携带新字段；积分器使用同一攻角模型；GPS/PRESET 提供未限转的期望方向 |
| 恢复/远距显示 | 快照姿态原样恢复；远程弹药渲染不再强制对齐速度 |

虚拟攻角分支改为“制导 → 推力/阻力/重力 → 平移”，推力沿机头，重力为 0 时不再套旧虚拟分支的默认重力。未开启攻角仍走原来的积分顺序。虚拟化准入条件未扩大，也没有在此阶段补齐既有虚拟链对第二脉冲触发、载机冷发射、风场/水中或实体 GPS 特殊阶段的全部模拟；因此不宣称两条完整弹道逐 Tick 等价，后续启用具体弹种前需实机比较。
