# 远距渲染代理武器锁定修复（2026-11-04）

## 现象与根因

服务端实体范围为 32、客户端画面视距为 2 区块时，远处载具仍由 RVP 显示，但红外等武器无法正常捕获或持续锁定。

“显示代理”是客户端用于绘制服务器载具的本地对象，不加入客户端世界，也不执行载具每刻更新。因此“画出来了”不代表世界实体查询可以找到它。原链路有四处断开：

1. 本体红外搜索和 RVP 红外/光电头瞄只遍历世界实体；电视导弹选点也只查世界实体。
2. 红外驻留候选、保锁、授权目标读取和头瞄缓存均通过 `ClientLevel.getEntity(id)` 查找。即使先补搜索，下一次读取仍会把代理当作目标消失。
3. 代理只在创建时应用位置，绘制时临时应用插值姿态后恢复；用于锁定的原始对象可能停留在创建点。本体 `remote` 对象的默认包围盒又只有一格，完整结构受击盒也没有持续更新。
4. 客户端未加载目标附近地形时，按本地高度图计算离地高度不可靠；同时普通红外搜索还带有本体固定 512 格候选上限，可能早于武器配置把目标丢弃。

## 修复行为

- `RVP_ClientWeaponTargets` 合并真实实体和服务端已授权的远距代理，以服务器实体 ID 去重，同 ID 优先真实实体。普通红外、红外/光电头瞄和电视导弹选点共用这个入口。
- 搜索、驻留、保锁、客户端授权读取及头瞄缓存统一按 ID 解析。真实实体与代理双向交接只替换对象引用，保留原驻留累计与 armed 状态；armed 指导引头已经完成连续跟踪、允许发射的状态。
- 代理目标沿用远距绘制时间线，只更新内存中的位置、部件姿态和结构受击盒，不执行物理、武器或声音 Tick。OBB 是随车体旋转的结构受击盒；外包围盒由这些实际受击盒计算。渲染临时姿态恢复时也恢复目标包围盒。
- 红外高度门和空地 HUD 分类优先使用当前服务器快照的 `heightAboveGround`。RVP 普通红外按武器的锁定距离配置搜索；光电既有 512 格范围保持原值。
- 普通光电 R 键通过既有 `fireControlLock` HEAD 补充代理受击盒命中，火控既有 TAIL 完成表示交接。未增加 Mixin 类、注入点或访问器；公共代码通过 `RVP_ClientActionsAccess` 分端，专用服务端不加载客户端世界或相机类型。

目标资格不依赖当帧绘制预算、视锥或 Billboard 预热；Billboard 指远处代替复杂模型绘制的平面图。完整快照撤权、25 Tick 超时、损毁或换维度后，代理不再作为锁定目标。服务器仍按真实实体 ID 接收锁定，继续使用真实地形和实体进行原有红外距离、离轴、高度和视线复核。

未改网络协议、载具包配置、结构模型文件或本体源码。
