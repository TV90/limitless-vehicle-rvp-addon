# RVP 导弹速度相关数据统计

> 统计日期：2026-10-08  
> 数据范围：`limitless_vehicle/rvp/data/rvp/weapons/` 下直接存放的 84 个 `type: "rvp:missile"` 文件。目录内 `_backup/` 另有 4 个历史备份，放在文末附表，不计入活动配置结论。  
> 本文只读统计，没有修改武器 JSON。

## 1. 结论速览

- 活动导弹共 **84 枚**；按当前加载器的自动补全规则，84 枚均能解析为有效火箭推进链（配置了 `mass`、`thrust`、`motor_burn_time` 的文件，即使省略 `has_rocket_engine`，加载阶段也会自动补为 `true`）。
- **82 枚**配置了正数 `max_speed`，其中 **81 枚**在本统计口径下可以达到硬上限；`9k720_9m723` 的 `max_speed=9.0` 因主发动机结束后进入弱二脉冲，理论峰值约 **1.95 格/Tick**，达不到 9.0。
- `agm_114`、`pl_8` 没有配置 `max_speed`，因此没有有限的“理论满速 Tick”；它们只有持续推力与阻力共同决定的平衡速度，而且主发动机燃烧结束后会进入滑翔减速。
- 最短达标时间是 **发射后 1 Tick**；最长的可达硬上限是 `f14d_aim54c` 的 **67 Tick**（其中点火延迟 20 Tick，点火后推进 47 Tick）。
- `ignition_delay_tick`：66 枚为 0，1 枚为 10，17 枚为 20；`inherit_vehicle_velocity=true` 共 55 枚，实际发射初速可能高于表中单独列出的武器初速。
- 当前活动配置中 `constant_speed=true` 为 0 枚；所有 84 枚都显式启用了 `rvp_aero_steering` 与 `rvp_attack_angle_limit_deg=60`，但本表的达速计算采用无转向、无诱导阻力损失的直飞基准。

## 2. 计算口径

### 2.1 初速度与单位

- 速度单位为 **格/Tick**；Minecraft 约定下 20 Tick = 1 秒，因此：
  - `1 格/Tick ≈ 20 格/秒 ≈ 72 km/h`；
  - `max_speed=6` 相当于约 120 格/秒，或 432 km/h。
- `v0` 的解析顺序与代码一致：`projectile_data.velocity` → 武器顶层 `velocity` → 本体 `BaseVehicleWeaponData.velocity` 默认值 **10**。因此 `agm_114` 与 `pl_8` 虽然没有写 `projectile_data.velocity`，表中初速仍是 10.00；显式写 `velocity: 0` 的弹则确实从 0 开始。
- 表中的 `继速=True` 表示 `inherit_vehicle_velocity=true`。计算时没有假定某一台载具的速度，所以 `v0` 只表示武器自身配置初速，不含载机速度。

### 2.2 每 Tick 推进模型

本统计按 `RVP_ProjectileMotion.tickMissileMove`、`RVP_PropulsionMath` 与 `RVP_QuadraticAirDrag` 当前实现计算：

```text
发动机加速度       a = thrust / mass
阻力质量           dragMass = mass >= 1 ? mass : mass × 1000
速度平方阻力损失   Δv_drag = drag_coefficient × v² / dragMass × altitudeFactor

每 Tick：
  若 flightTick < ignition_delay_tick：不加发动机推力
  否则 motorTick = flightTick - ignition_delay_tick
       motorTick ∈ [0, motor_burn_time]（含端点）时加 thrust / mass
  再扣除速度平方阻力
  再应用 min_speed / max_speed 钳制
```

表内的“达满速”使用以下格式：

```text
发射后总 Tick / 点火后推进 Tick
```

例如 `31 / 11` 表示包含 20 Tick 点火等待后，第 31 个运动更新结束时首次达到 `max_speed`，实际发动机只推进了 11 Tick。这里统计的是“状态更新次数”，不是把 `flightTickCount` 的 0 起始索引直接当作人类 Tick 序号。

### 2.3 理论平衡速度

`v_eq` 是在 `altitudeFactor=1`、推力持续存在、方向不变时的连续平衡速度：

```text
v_eq = sqrt((thrust / mass) × dragMass / drag_coefficient)
```

表中 `v_eq` 第一项是主发动机，第二项是有效二脉冲的平衡速度。它不是现实型号的 Mach 性能，也不是外部资料中的峰值速度；它只是当前 RVP 配置在游戏动力学中的参考量。显式 `altitude_drag_factor` 的导弹在低空会有更大阻力，实际 `v_eq` 还要除以 `sqrt(altitudeFactor)`。

达速模拟的共同假设是：初始高度使用 `altitudeFactor=1`、弹体沿发动机方向直飞、不转弯、不碰撞、不叠加载具速度、不受风影响。真实制导飞行还会受到重力、气动攻角、诱导阻力、目标方向改变和区块/碰撞事件影响。

## 4. 三个需要特别注意的速度结果

### 4.1 `9k720_9m723`：配置上限 9，但动力学达不到

`9k720_9m723` 的主发动机只有 `63.333 / 3800 ≈ 0.0167 格/Tick²` 的初始轴向加速度，主燃烧结束后虽触发二脉冲，但二脉冲的推力仅 `0.025`。在当前速度平方阻力实现下：

- 主脉冲的基准平衡速度约 `63.92 格/Tick`，因此主脉冲不会被阻力限制；
- 主燃烧结束时的直飞峰值只有约 `1.95 格/Tick`；
- 二脉冲平衡速度约 `1.27 格/Tick`，远低于 `max_speed=9.0`；
- 所以表中“达满速”是 `—`，不是需要等待更多 Tick，而是**在当前推进配置下不可达**。

该弹还使用了显式高度阻力表：`Y∈[0,80]` 的阻力倍率为 1.5，低空真实平衡速度会比表中 `altitudeFactor=1` 基准再低；表中结果已经是偏乐观的理论直飞值。

### 4.2 `agm_114` 与 `pl_8`：没有 `max_speed`

两枚导弹均有有效发动机，但 JSON 没有正数 `max_speed`：

| 文件 | `v0` | 主燃烧 | 基准 `v_eq` | 模拟峰值 | “达到理论满速” |
| --- | ---: | ---: | ---: | ---: | --- |
| `agm_114` | 10.00 | 600 Tick | 76.68 | 75.86 @ 601 | 无有限 Tick；没有硬上限，平衡速度只能渐近逼近，且发动机随后关机 |
| `pl_8` | 10.00 | 60 Tick | 155.56 | 69.26 @ 61 | 无有限 Tick；主发动机太早关机，实际峰值远低于持续推力假设下的平衡速度 |

这里的默认初速 10 来自本体通用武器字段，不是导弹 JSON 中隐含的另一个 RVP 速度键。

### 4.3 `min_speed` 的含义

活动导弹中只有 `052d_yj20`、`9k720_9m723`、`ddg51_rgm109` 配置了 `min_speed=0.01`。它只在速度已经非零且低于下限时把速率抬回 0.01，不会替代发动机加速，也不会把无法达到 `max_speed` 的导弹自动推到满速。
