# RVP 实体 PPN 自适应前置前馈时间窗方案

日期：2026-11-07
状态：**方案，未改代码**。当前实现是固定 `ppn_lead_feedforward_ticks = 10`；本方案把它升级为按“可用 G / 机头响应 / 目标机动”逐 Tick 自适应的时间窗。

前置实现与 HQ-10/HQ-9B 对照见 [实体PPN前置追踪不足：根因与改进方案](RVP实体PPN前置追踪不足_根因与改进方案_20261107.md)。

---

## 1. 为什么固定 10 Tick 需要升级

同一套 HQ-10/HQ-9B 工况里，最优退坡窗口并不固定：

| 工况 | 纯 PPN | 纯 PIP | 最优窗口倾向 |
| --- | ---: | ---: | --- |
| HQ-10 快速横穿 | 2.939 | **1.818** | 接近纯 PIP（1~5 Tick） |
| HQ-9B 慢速横穿 | 0.990 | **0.584** | 接近纯 PIP |
| HQ-9B 变向（30/72 刻） | 2.600 / 2.971 | 7.832 / 11.027 | 10~45 Tick（PPN 末段） |
| HQ-10 变向（30 刻） | 2.498 | **0.856** | 接近纯 PIP |
| HQ-10 变向（72 刻） | 2.531 | 4.144 | 45 Tick 左右 |

固定 10 Tick 是这些工况的折中：它保住了 HQ-9B 变向，但恒定横穿没有拿到 PIP 的末段精度。**窗口应该由“还剩多少时间修正”和“需要多少时间修正”共同决定，而不是一个常数。**

## 2. 升级目标

每一 Tick 用三个物理量决定 `T_far`（前馈保持全额的剩余相遇时间）：

1. **可用 G / 转角速率**：低动压、低过载的弹需要更长时间修正，窗口应更大。
2. **机头响应时间**：攻角/惯量建立越慢，越要提前交给 PPN。
3. **目标机动**：目标横向加速度造成的“预测相遇点偏移”越大，PIP 预测越不可靠，越要提前交给 PPN；目标不机动时回到 PIP 基线。

保持现有 `t_go` 的 smoothstep 退坡结构不变，只让 `T_far` 动态化。

## 3. 输入量（全部是现有量，无新增物理模型）

| 符号 | 来源 | 单位/含义 |
| --- | --- | --- |
| `t_go` | `RVP_PredictiveInterceptMath.Solution.timeTicks` | Tick，剩余相遇时间 |
| `R` | 弹目距离 | 格 |
| `G_avail` | `RVP_AeroSteeringModel.availableGs(speed, limits)` | G，当前动压下的可用过载 |
| `ω_max` | `RVP_AttackAngleInertiaModel.maxTurnDeg(speed, limits)` | 度/Tick，当前可用机头/航迹转角；换算成弧度/Tick |
| `t_resp` | `1 / RVP_AttackAngleInertiaModel.response(speed, limits)` | Tick，机头响应时间常数，钳 2~30 |
| `a_⊥` | `targetMotion.effectiveAcceleration()` 相对视线的横向分量 | 格/Tick²，已乘置信度 |
| `Δψ` | `atan2(0.5·a_⊥·t_go², R)` | 弧度，目标机动造成的相遇点角偏移 |
| `m` | `clamp(Δψ / Δψ_ref, 0, 1)` | 无量纲机动门控，`Δψ_ref` 默认 3° |

说明：

- `a_⊥` 只取相对视线的横向分量；径向加速度主要改变相遇时间，不改变前置角。
- `Δψ` 是解析近似：目标以 `a_⊥` 加速 `t_go` 后横向偏移 `0.5·a_⊥·t_go²`，在当前距离上对应角偏移。它直接衡量“PIP 预测有多容易被目标机动改写”。
- 不新增第二次 PIP 求解；`t_go` 和 `a_⊥` 都已在现有链路里。
- `G_avail`、`ω_max`、`t_resp` 与执行器同源，低动压时自动变差，窗口自动变大。

## 4. 公式

```text
T_turn = Δψ / ω_max                 // 把角偏移转回来需要的 Tick
T_corr = t_resp + T_turn            // 机头建立 + 转角修正
T_far  = clamp(T_base + m·T_corr, T_base, T_max)
T_near = T_far / 3
w      = smoothstep((t_go - T_near) / (T_far - T_near))
```

行为：

- **不机动目标**：`a_⊥=0 → Δψ=0 → m=0 → T_far=T_base`，回到 PIP 基线（`T_base` 默认 2 Tick）。恒定横穿重新拿到 PIP 的末段精度。
- **机动目标**：`m→1`，`T_far` 随 `t_resp + Δψ/ω_max` 增长，PPN 更早接管，有足够时间修正 PIP 的预测误差。
- **低 G / 低动压**：`ω_max` 小、`t_resp` 大，`T_far` 自动变大；高 G 弹则更小。
- **上限**：`T_max` 默认 45 Tick，防止极低动压或超大机动把窗口拉到“还没建立前置就交权”。

典型量级（HQ-9B 2.3 G 变向、`t_go≈100`、`R≈500`）：`Δψ≈25°~30°`，`ω_max≈5°/Tick`，`T_turn≈5~6`，`t_resp≈10~13`，`T_far≈17~21`；恒定目标 `T_far=2`。

## 5. 数据字段

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `ppn_lead_feedforward_ticks` | 现有字段，改作 **T_base**（非机动基线；0 关闭前馈） | `2` |
| `ppn_lead_feedforward_max_ticks` | 自适应窗口上限 T_max | `45` |
| `ppn_lead_feedforward_maneuver_ref_deg` | 机动门控参考角 Δψ_ref，度 | `3` |

- 三个字段都可缺省；缺省即默认值，不需要改武器 JSON。
- 现有 `ppn_lead_feedforward_ticks=0` 仍是总关闭开关，改默认值只影响未显式配置的武器。
- 末段沿用主段值，不新增末段字段。

## 6. 预期结果（按现有 HQ 数据推算）

| 工况 | 固定 10 Tick（现状） | 自适应预期 | 依据 |
| --- | ---: | ---: | --- |
| HQ-10 慢速横穿 | 0.997 | ≈0.95（PIP 基线） | 不机动，T_far=2 |
| HQ-10 快速横穿 | 2.913 | ≈1.82（PIP 基线） | 不机动，T_far=2 |
| HQ-9B 慢速横穿 | 0.977 | ≈0.58（PIP 基线） | 不机动，T_far=2 |
| HQ-9B 快速横穿 | 3.123 | ≈3.10（PIP 基线） | 不机动，T_far=2 |
| HQ-9B 变向 30/72 | 2.332 / 2.341 | ≈2.3~2.7 | 机动，T_far≈17~21 |
| HQ-10 变向 72 | 2.106 | ≈2.1~2.3 | 机动，T_far≈17~21 |
| HQ-10 变向 30 | 2.460 | ≈2.46（仍为 PPN 型） | 机动，T_far 增大；PIP 的 0.856 拿不到 |

最后一行是本方案已知的边界：HQ-10 30 刻变向时纯 PIP 反而最好（0.856），但目标确实在机动，解析量无法判断“PIP 这次会预测得很准”。自适应方案只能保证不差于固定 10 Tick，不能保证拿到 PIP 的全部优势；如果 1728 组矩阵显示该类退化，再考虑加“PIP 预测稳定性”门控或按武器覆盖，而不是在公式里硬塞特判。

## 7. 验证计划

1. **单元**：`T_far` 的端点与钳制；`a_⊥=0` 时严格 `T_base`；`Δψ` 超参考时到 `T_max`；`ω_max`、`t_resp` 为 0/NaN/无穷时安全退化。
2. **实体**：恒定目标断言 `T_far=T_base` 且轨迹与旧 PIP 一致；机动目标断言 `T_far` 随 `a_⊥` 单调增大；低 G 与高 G 两个配置断言低 G 的 `T_far` 更大。
3. **HQ-10/HQ-9B 8 工况**：与固定 10 Tick、纯 PPN、纯 PIP 对照；目标是没有工况比 `max(纯PPN, 纯PIP)+0.15` 更差，且恒定工况回到 PIP 水平。
4. **1728 组矩阵**：总体中位/P90 不劣于纯 PPN；横穿类向 PIP 靠拢；变向类保留 PPN 优势。
5. **实机**：`/rvpdebug projectilelife on` 追加输出 `leadWindowTicks`、`maneuverDpsiDeg`、`targetLateralAccel`、`leadBlendWeight`；观察窗口是否随目标机动平滑变化、有无抖动。

## 8. 风险与回退

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 目标加速度估计滞后/噪声 | `effectiveAcceleration` 是 0.25 EMA，机动刚发生时 `Δψ` 偏小 | 置信度已乘入；必要时对 `Δψ` 做短窗平滑（需要 1 个 float 的跨 Tick 状态，默认不加） |
| 窗口抖动 | `Δψ` 逐 Tick 变化会让 `T_far` 波动 | `a_⊥` 已滤波；`T_far` 再过 smoothstep 输出；实机/矩阵确认后再决定是否加限速 |
| 低动压钳制 | `ω_max`、`t_resp` 极端时 `T_far` 触顶 | `T_max=45` 上限；`t_resp` 钳 2~30 |
| 启发式不是最优 | HQ-10 30 刻变向的 PIP 优势拿不到 | 矩阵验证；必要时保留逐武器覆盖或回退固定 10 Tick |
| 额外计算 | 每 Tick 多一次 `availableGs`/`maxTurnDeg`/`response`，无额外 PIP 求解 | 均为纯数学，可忽略；不新增网络或实体状态 |

**回退**：`ppn_lead_feedforward_ticks=0` 关闭前馈；或把 `ppn_lead_feedforward_max_ticks` 设为与 `T_base` 相同，退化为固定窗口。代码回退点仍是 `RVP_GuidanceRuntimeMath` 的 `resolveLeadWeight`。

## 9. 明确不做

- 不用“已飞行距离百分比”作为主相位量：终端能力按 Tick 计，`t_go` 已含闭合速度；距离百分比在长射程会把交权提前到几秒前，正是 45 Tick 的失效模式。
- 不新增第二套制导律、不按武器 ID 分支、不新增 Mixin、不改 G/攻角/机头转速预算。
- 不在本轮处理导引头截获前的中段点制导。
