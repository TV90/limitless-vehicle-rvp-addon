## 1. 接入范围

PPN 是纯比例导航：根据导弹看向目标的那条视线在世界中转得多快，要求相应的侧向修正。
PIP 是预测拦截点：先估计未来相遇点，再追那个点。本轮限定在已有自动实体拦截分支内替换制导律。

| 条件 / 路径 | 本轮行为 |
| --- | --- |
| `rvp:missile`，当前生效类型为 IR / AIR / ARH / SARH，意图提供存活目标实体 | 通过原门控后使用 PPN |
| 主段 GPS 转入上述末段，末段已实际产生实体意图 | 同样允许 PPN；不被原 GPS 静止点分支提前截走 |
| 原 `predict_target_pos=false`、起始 Tick 未到、诱饵保持期、二脉冲等待期 | 保留原回退，不进入 PPN |
| GPS/PRESET 坐标、失锁记忆点、反辐射、激光寻的、电视、SACLOS 辅助、驾束、人工直控 | 原路径不接入 PPN |
| 炸弹、火箭等其他弹体，即使有 IR 实体意图和预测开关 | 不接入 PPN |
| `top_attack_height` 攻顶分支 | 保持原行为；高抛与攻顶同配时继续沿用原优先规则 |

不新增 JSON 字段、武器 ID 特判、Mixin、网络消息或客户端类型引用。`max_lateral_accel` 没有被启用，转弯能力继续由现有气动参数统一限制。

## 2. 计算与执行

核心位于 `RVP_ProportionalNavigationMath`：

```text
r = 目标瞄准点位置 - 导弹位置
v相对 = 目标当前速度 - 导弹当前速度
omega = (r × v相对) / |r|²
a = N × (omega × 导弹当前速度)
```

`×` 是向量叉乘。位置用格，速度用格/Tick，加速度用格/Tick²，角速度用弧度/Tick；一秒为 20 Tick。
采用 PPN 的速度法向形式，参见 [Johns Hopkins APL 原文式 21](https://www.jhuapl.edu/sites/default/files/2024-09/29-01-Palumbo_Principles_Rev2018.pdf)。
PPN 只消费当前真实目标位置与速度，不读取目标估计加速度，也不调用 PIP 预测未来相遇点。

`predict_target_pos_gain` 在本轮接入 PPN 比例系数 N；默认仍为 3.0，末段继承主段。增益不提高 G、攻角或机头转速上限。
开关和起始时间仍复用 `predict_target_pos`、`predict_target_pos_start_tick`，后者按总飞行 Tick 计时，切段不重新等待。

侧向加速度转换成保持当前速率的一刻航迹请求，再交给 `RVP_PIPAttackAngleController.solveVelocityRequest`。
这个已有入口也供固定点制导使用；它接收的是已经形成的航迹请求，不会再乘一次 PIP 的外环 `turning_factor`。
实际机头与速度继续受原动压、G、攻角锥、双轴惯量和转角上限限制。候选试算不写实体，最终只调用一次姿态/载荷提交；推力、重力和诱导阻力继续由原运动流程结算。

气动关闭且未配显式 G 的兼容分支，保留原 `turning_factor` 执行器响应；PPN 请求与 PIP 路线分别应用一次，再进行请求衔接，避免高抛时重复缩小响应。

退化处理：零速、重合、非有限输入保持安全速度；已经越过一刻运动范围内的目标时不要求奇异掉头。
目标恰在后方且没有视线转动时标记 `CAPTURE`，只提出受原执行器限制的初始追点请求；它不绕过原角度包线。
径向接近速度允许为负，低速发射尚未追上目标时不会仅因此停导。没有新增跨刻滤波历史。

## 3. 高抛衔接

沿用原 `loft_height_above_target`、`loft_end_distance`、`loft_blend_distance` 及 smoothstep 退坡曲线。

| 原路线权重 | 控制请求 |
| --- | --- |
| 1 | 完整沿用原 PIP 高抛路线及原响应补偿 |
| 0～1 | 在原路线航迹请求与真实目标 PPN 请求之间做球面插值，再交给同一执行器 |
| 0 | 只执行 PPN，不计算 PIP 相遇点 |

PPN 始终看真实目标；抬高的辅助点只参与原 PIP 路线计算，不把辅助高度的变化冒充目标速度。
距离退坡中的请求连续，且插值前先归一化方向，不能把速度长度当成球面夹角计算。

ARH/AIR 自主捕获后，沿用原规则立即撤销高抛请求。这个事件可以造成请求变化，实际机头仍由原惯量与转速上限完成过渡；没有声称事件前后的理想指令完全连续。
新增的 4 项捕获交接回归在权威配置的开机距离写入正式捕获状态，随后继续检查实际机头转角和首次交会。

虚拟中段直接运行同一实体制导与运动入口，没有第二套 PPN。新增 IR 实体寻的虚实对照，覆盖存档重建及恢复后的连续飞行；不增加快照字段或网络协议变更。

## 5. 复现与诊断

项目根使用仓库指定环境：

```powershell
$env:JAVA_HOME='C:\Users\FishKing0721\.jdks\ms-17.0.16'
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=D:\WgameProject'
./gradlew build
```

生成新场景的当前 PPN 回放：

```powershell
./gradlew projectileSimulation "-PprojectileScenario=src/test/resources/projectile-ppn-simulation" "-PprojectileOutput=build/projectile-ppn-new"
```

本轮合并对照目录包含原 8 个惯量场景和新增 6 个场景，可重跑当前结果及比较：

```powershell
./gradlew projectileSimulation "-PprojectileScenario=build/projectile-ppn-comparison/scenarios" "-PprojectileOutput=build/projectile-ppn-comparison/ppn"
python scripts/compare_ppn_replays.py build/projectile-ppn-comparison/pip build/projectile-ppn-comparison/ppn build/projectile-ppn-comparison/comparison.json
```

`pip/` 是改动前保存的实测基线；用当前代码重跑不能冒充原 PIP。`clean` 会清除本地 `build/` 对照材料，执行前可自行保存。
`scripts/compare_ppn_replays.py` 只读回放，不运行第二套制导；恢复图形底部锚点到目标真实中心后计算相对运动段距离。

实机诊断沿用 `/rvpdebug projectilelife on`。`GUIDANCE` 事件新增：

- 分支 `PPN_ATTACK_ANGLE`、`LOFT_PIP_ATTACK_ANGLE`、`LOFT_PIP_PPN_BLEND_ATTACK_ANGLE`；未开攻角时没有相应后缀。
- `ppnStatus`、`ppnGain`、`losRate`、`closingSpeed`、`requestedNormalAcceleration`、`ppnRequestedVelocity`、`loftRouteWeight`。
- 原机头指令、实际转角、攻角、载荷和响应限幅继续保留；PPN 末段 `pipStatus=NOT_EVALUATED` 表示没有求相遇点。
