# 教训：履带 / 悬挂的「左右映射」（2026-10-20）

> ⚠️ **强制阅读**：任何涉及 `track` / `suspension` / 负重轮 / 履带采样 / `render_bone` / `suspensions` 的改动，**动手前必须先读完本文，并跑一遍 §6 的自检脚本**。

## 1. 事故现象

`t90m` / `ztz100` / `t84bm` 三台车：

- **左侧**负重轮错位，左前两个轮子直接不渲染；
- **左侧**履带前端不下垂 / 采样不跟随；
- **右侧完全正常**。

「右边正常」是这次最误导人的一点 —— 它让人以为整套配置是对的，实际上是**右侧恰好全对、左侧系统性偏移**。

---

## 2. 根因（两条，互相独立，都只作用于左侧）

### 2.1 左轮绑到了错误的臂骨（编号在每台车上都不一样）

> ⚠️ **先纠正一个错误定性**：这里**没有**「渲染臂编号 = 结构轮编号 + 固定偏移」这种规律，本文旧版写的「少了 +2 偏移」是**错的说法**，已作废。
> **不同载具的轮组编号方式本来就不同**，唯一可行的办法是**把该车的渲染模型和结构模型都读出来，逐台按几何配对**。

本批模型只是"恰好"出现下面这种编号（**仅代表这笔数据，不能推广**）：

| | 右侧 | 左侧 |
|---|---|---|
| 结构模型轮骨 | `track_roller1-6` | `track_roller7-12` |
| 渲染模型臂骨 | `xuangua1-6` | **`xuangua9-14`**（`xuangua7/8` 是空骨，`t90m`/`ztz100` 连骨都没有） |

**为什么这批会差两个号**：建模时**右侧最后一对主动轮、左侧第一对诱导轮没有算进"负重轮"**，所以结构轮的编号把这两对挖掉了，而渲染臂把主动轮/诱导轮也编进了同一套 `xuanguaN` 序列 —— 于是同一根轴在两侧拿到的是不同的号。**这是本批的建模习惯，不是引擎规则**；换一台车完全可能是连续编号、倒序编号、左右各自前缀，或者主动轮单独一根骨。

错误写法：`roller7-12 → xuangua7-12`（**按编号恒等映射** —— 这才是错误的本质，不是"少加了 2"）。后果：

- `roller7 → xuangua7`、`roller8 → xuangua8`：**空骨 / 不存在** ⇒ 两个轮子不渲染、不随悬挂动作；
- `roller9-12 → xuangua9-12`：绑到了**左臂第 1~4 根**（应为第 3~6 根）⇒ 整串轮子前移两位。

正确写法（与正常工作的 `ztz99b` 一致，按几何 z 配对得出）：`roller1-6 → xuangua1-6`、`roller7-12 → xuangua9-14`。

### 2.2 `suspensions` 分侧写成 7 + 5

```jsonc
// 错：右履带里混进了一个左轮，左履带少一个
"track_link_r": [ "track_roller1", ... "track_roller7" ],   // 7 个
"track_link_L": [ "track_roller8", ... "track_roller12" ]   // 5 个
```

正确：右 `1-6`（6 个）、左 `7-12`（6 个）。

为什么**只有左边有事**：

- 左路径少掉 z 最大的那个采样轮 ⇒ `TrackPath.setSuspensions` 算出的 `floatingMinZ` 往后缩 ⇒ **前端那段没有悬挂点接管，继续用结构模型的刚性路径** ⇒ 履带前端采样不跟随；
- 右路径多出来的 `roller7` 是左轮，但 `SuspensionUnit.getTrackFloatingReference(trackAxisX)` 会把 x **替换成路径轴 x**，只取 y/z；而左 7 与右 1 的 z 完全相同 ⇒ 对右侧是一个重复点，**等于没加**。

## 3. 为什么会犯（思维教训）

1. **按编号推左右**：默认「编号小的在右、编号大的在左」，而不是去看几何。
2. **把一台车的编号规律当普适规律**：更糟的写法是「渲染臂 = 轮号 + N」。轮组编号是**逐台车建模时自己定的**（本批因为主动轮/诱导轮没算进负重轮才差了 2 个号），换一台车可能连续、可能倒序、可能左右不同前缀 —— **任何固定偏移都会在下一台车上翻车**。
3. **拿「另一侧正常」当验收通过**：只看了一侧就认为整体 OK，没做左右对称性校验。
4. **没跑交叉校验**：`render_bone` 是否指向**有几何**的骨，一条脚本就能查出来。

---

## 4. 判定规则（照做，不要靠猜）

1. **左右看几何，不看编号**：取结构模型轮骨 cube 的**中心 x 符号**判定（JSON/BB 空间 **+x = 右**、`−x = 左`）。
   ⚠️ 不能只看 `pivot.x` —— 这批模型里 `ztz99b`/`ztz100` 的 12 个轮骨 `pivot.x` **全是 0**，左右只体现在 cube 的 x 上。
2. **轮 ↔ 臂用「同侧 + z 最近」配对**：臂骨的几何中心 z 与轮骨 cube 中心 z 一一对应。
   ⚠️ **禁止用编号差/固定偏移换算** —— 必须两台模型都读出来实际配对；配完再看编号，通常会发现各车差异来源不同（主动轮、诱导轮算不算负数号，两侧编号是否共用一套序列…）。
3. **条数必须左右均分**：`suspensions` 两侧条数 = 该侧实际轮数（本次 6+6）；总数必须等于结构里该侧的轮骨数。
4. **每个 `render_bone` 必须指向有顶点的骨**（`poly_mesh.positions` 非空，或 `cubes` 非空）。
5. **键名必须逐字等于结构模型 `track_link` 的子骨名**（大小写敏感，`track_link_L` ≠ `track_link_l`）。

## 6. 自检脚本（粘到 `limitless_vehicle/rvp` 下直接跑）

```python
import json, re

def wheels(v):
    """结构轮：编号 -> (cube 中心 x, z)，JSON 空间 +x=右"""
    d = json.load(open(f'data/rvp/models/bedrock/vehicle/{v}.structure.json', encoding='utf-8'))
    out = {}
    for b in d['minecraft:geometry'][0]['bones']:
        if not re.fullmatch(r'track_roller\d+', b['name']):
            continue
        cs = b.get('cubes') or []
        if cs:
            o, s = cs[0]['origin'], cs[0]['size']
            out[int(re.sub(r'\D', '', b['name']))] = (o[0] + s[0] / 2, o[2] + s[2] / 2)
    return out

def arms(v):
    """渲染臂：名字 -> (几何中心 x, z, 顶点数)"""
    d = json.load(open(f'assets/rvp/models/bedrock/entity/{v}.json', encoding='utf-8'))
    out = {}
    for b in d['minecraft:geometry'][0]['bones']:
        if not re.fullmatch(r'xuangua\d+', b['name']):
            continue
        xs, zs = [], []
        for c in (b.get('cubes') or []):
            o, s = c['origin'], c['size']
            xs += [o[0], o[0] + s[0]]; zs += [o[2], o[2] + s[2]]
        pos = ((b.get('poly_mesh') or {}).get('positions') or [])
        xs += [p[0] for p in pos]; zs += [p[2] for p in pos]
        out[b['name']] = (((min(xs) + max(xs)) / 2 if xs else None),
                          ((min(zs) + max(zs)) / 2 if zs else None), len(pos) + len(b.get('cubes') or []))
    return out

for v in ['ztz99b', 't90m', 'ztz100', 't84bm', 'bmpt72', 'bukm3']:
    W, A = wheels(v), arms(v)
    veh = json.load(open(f'data/rvp/vehicles/{v}.json', encoding='utf-8'))
    st  = json.load(open(f'data/rvp/models/bedrock/vehicle/{v}.structure.json', encoding='utf-8'))
    kids = {b['name'] for b in st['minecraft:geometry'][0]['bones'] if b.get('parent') == 'track_link'}
    tp  = [p for p in veh['parts'] if p['type'].endswith(':track')][0]
    err = []
    if set(tp['suspensions']) != kids:
        err.append(f'键≠结构子骨 {list(tp["suspensions"])} vs {sorted(kids)}')
    for k, lst in tp['suspensions'].items():
        sign = 1 if k.endswith('_r') else -1
        bad = [x for x in lst if x in W and (W[x][0] > 0) != (sign > 0)]
        if bad:
            err.append(f'{k} 混入另一侧轮 {bad}')
    for p in veh['parts']:
        if p['type'].endswith(':suspension'):
            rb = p.get('render_bone')
            if not rb or A.get(rb, (0, 0, 0))[2] == 0:
                err.append(f'{p["id"]}→{rb} 指向空骨')
            else:
                # 左右一致性：结构轮与臂骨必须在同一侧
                n = int(re.sub(r'\D', '', p['id']))
                if n in W and A[rb][0] is not None and (W[n][0] > 0) != (A[rb][0] > 0):
                    err.append(f'{p["id"]} 左右错配 ({W[n][0]:.1f} vs {A[rb][0]:.1f})')
    print(f'{v:8s} {"OK" if not err else "ERR: " + " | ".join(err)}')
```

输出必须**全部 OK** 才算通过。

## 8. 一句话总结

> **左右和"轮↔臂"的对应都是几何属性，不是编号属性。** 每台车的轮组编号可以完全不同（本批因主动轮/诱导轮不计入负重轮，两侧编号被挖掉了不同的号），所以**永远不要套固定偏移、也不要按编号推左右** —— 只能把渲染模型和结构模型都读出来，按 x 定侧、按 z 配对。「另一侧正常」也永远不能作为验收依据。
