## 1. 外观与参数

喷焰沿弹体尾轴喷出，喷口细、随后膨胀、末端收尖，具有白热核心、橙色外焰与光晕。轴向明暗结节和小幅波动近似喷流中的激波结构，是视觉近似，不是流体/燃烧物理模拟。

不采样本体尾焰贴图，不新增图片、模型或动画。原始 HDR 核心峰值上限 60000，上屏核心可达到白点；HDR 是显卡内部保存的高亮数值，不代表 Minecraft 方块光等级。

| 既有 JSON 或运行事实 | 当前用途 |
| --- | --- |
| `projectile_data.has_rocket_engine` 与实际燃烧窗口 | 决定喷焰是否存在 |
| `projectile_data.engine_nozzle_offset` | 喷口局部位置，默认 `[0,0,-0.5]` 格 |
| `projectile_data.flame_scale` | 统一缩放长宽，默认 0.3，非法值回退默认 |
| 既有 `effects_data.caliber` | 毫米口径，只为环境照明与广域光晕计算共同的 20～500 格半径 |
| 二脉冲、剩余燃烧时间、有效远端燃烧快照 | 控制启停和阶段亮度，不改变几何缩放 |

代码基准长度 10 格、最大半径 1.5 格。因此 `flame_scale=0.3` 对应长 3 格、最大直径 0.9 格；`0.6` 对应长 6 格、最大直径 1.8 格。轮廓在此范围内收尖，整条喷流并非一样粗。

不按武器 ID、速度或粒子数量改变大小，不增加武器光源 JSON。颜色、峰值、光晕和动画细节均由 Java/GLSL 代码控制。Shader JSON 只声明程序接口。

## 3. 喷口与生命周期

[RVP_RocketEngineLightQuery](../../src/main/java/org/ywzj/rvp/client/light/RVP_RocketEngineLightQuery.java) 统一查询燃烧事实。远端克隆只接受有效服务端燃烧快照，不沿用尾烟宽限。

局部喷口偏移和尾轴 `(0,0,-1)` 都按 X 俯仰→Y 负朝向旋转，与弹体模型一致。观瞄伪装期间，模型、新喷焰和环境光共用 `RVP_SightFireDisguiseRender.renderOffset` 的平移与平滑合流。远端先应用本帧模型朝向，再登记喷焰，防止用上次快照方向喷出。

每枚实体用 UUID（稳定唯一标识）登记一条喷流；两 tick 无心跳淘汰，明确燃尽/实体移除立即取消。换世界、重连和时钟回退清空；暂停不使用真实时间继续播放。没有改推进、命中或网络协议。

2026-11-04 起，正式喷焰在首次连续登记后用 3 tick（0.15 秒）展开，在当前燃烧窗口结束前用 6 tick（0.3 秒）收束；淡出在燃尽之前完成，清理边界保持上述规则。逐帧登记仅更新位置和倒计时，不会反复重置点火过渡。

## 4. 三维形状与 DH/光影遮挡

程序先求相机射线与有限圆柱的相交区间，再沿区间采样 20 次，计算收尖轮廓、核心和橙焰。采样终点由当前像素的最近可见表面限制。

近景和 DH 使用各自的深度、投影与观察变换，重建到同一空间后选择最近表面；不直接比较两张深度图的 0～1 数字。光影提前绘制的手持物继续作为遮罩。新程序不写场景深度，避免尾焰自遮挡。

不再因喷口中心被挡就整条删除：喷口在弹体内或墙后、尾段实际露出时，只绘制露出部分；前景墙挡住整条喷流时没有直接喷焰贡献。Bloom 是可见亮部的图像扩散，可能跨过局部轮廓，不等同于火焰几何穿墙。

极远处小于像素的喷流只补足屏幕亮点覆盖，遮挡仍使用实际几何前缘。普通透明烟没有完整深度；当前没有读取烟尘真实密度，不具备精确的透烟衰减或体积自阴影。

DH 原生与 DH+光影沿用既有公开输入桥，不因检测到 DH/光影而禁用。绘制仍在光影世界最终合成之后、CRT/TV/HUD 之前。

## 5. 预算与光晕

环境光仍最多 8 盏，发动机照亮方块/实体与广域光晕的共同半径为 `clamp(20 + 口径毫米数 × 0.1, 20, 500)` 格，未配置明确口径时为 20 格。二脉冲及临近燃尽只改变颜色/亮度，共同半径保持不变。

**喷焰独立于八灯预算和环境光默认 256 格观察距离。** 最多保留 256 条输入、绘制 128 条可见喷流，优先附近；远程实体本身的授权范围仍由原远端系统决定。关闭环境照明或将 `maxLights`/环境光 `intensity` 设为 0，不取消喷焰；`bloom=false` 只关闭光晕，核心仍高亮。

同帧共用一次近景深度、可选的一次 DH 深度和一次最终颜色复制。每条喷流只绘制其屏幕包围矩形，不为每枚导弹复制背景，也不要求喷口本身位于屏幕内。

- 核心显示使用最高 60000 原始 HDR，映射到显示白点，保留原场景 Alpha（透明度）。
- 光晕输入保持橙色色相，以 `BLOOM_INPUT_PEAK=12` 软压缩；核心显示不降低峰值。这样避免 60000 直接模糊后把有限核外沿也烧成方框。
- 多条喷流以最大值合并，避免重叠齐射累加造成半精度纹理溢出。
- 有喷焰时共用光晕使用连续标准采样步长 1，避免细长亮部被稀疏采样拉成条纹；只有旧爆炸/炮口光时仍用原步长 2。
- 在原局部亮部扩散之外，追加按世界半径投影的橙色广域光晕；使用一像素可见发光比例，避免把完全被遮住的尾焰扩大成穿墙光团。

裁剪矩形、RGB/Alpha 混合方程和其它外部显卡状态由现有 `State` 作用域恢复。

## 8. 20～500 格广域光晕与环境照明

### 8.1 同一口径、同一半径

按用户确认，发动机持续环境光和程序尾焰光晕一起扩大，使用同一个 [engineRadius](../../src/main/java/org/ywzj/rvp/light/RVP_LightParameters.java) 计算入口：

`R = min(500, 20 + max(0, 口径毫米数) × 0.1)`

| 毫米口径 | 光晕半径 | 方块、实体、烟雾、炮口贴图的环境照明半径 |
| --- | --- | --- |
| 未配置 | 20 格 | 20 格 |
| 100 | 30 格 | 30 格 |
| 300 | 50 格 | 50 格 |
| 4800 及以上 | 500 格 | 500 格 |

半径是从喷口中心向外的距离，直径为两倍。边缘均平滑衰减到零，不能把半径内每个位置理解为同样亮。口径沿用现有 `effects_data.caliber`，不读取 `tracer_caliber`，不新增 JSON 光源对象，不按武器 ID 区分。本地与远端克隆共用相同解析和推进状态。

原环境光强度仍为 4、表面权重 0.8；新范围不改变 P5，真实 Minecraft 方块光继续关闭。二脉冲及燃尽包络仅减弱亮度，不再把共同半径缩到最小值以下。喷焰长度、宽度仍只受原 `flame_scale` 控制，60000 核心和 16 橙焰参数保持。

现有观察预算已经按 `观察距离 + 光源半径` 剔除，因此 500 格范围能照到相机附近表面，不会仅因源中心超过默认 256 格就被提前丢弃。环境照明仍遵守八灯预算和实际遮挡。

### 8.2 世界半径怎样变成屏幕光晕

新增的是可见尾焰的光晕，属于画面中的柔和扩散。它在喷口深度的相机朝向平面上使用世界半径 R，再由当前投影转换成屏幕范围。因此距离翻倍时像素尺寸约减半；缩小视野角、放大观察时，像素覆盖随之增大。改变窗口分辨率不会改变对应的世界尺寸。

用 `r² = 平面内距喷口的距离² / R²` 表示归一化距离：

- `r² ≥ 1`：新增广域层严格为零。
- 范围内衰减为 `exp(-6×r²) × (1-r²)²`，即中心较强、边缘平滑收敛。
- 亮度取橙焰强度、当前燃烧倍率和实际可见发光比例，使用共同峰值的指数映射保持 `[1,0.38,0.07]` 橙色色比。
- 沿用 `ONE_MINUS_DST_COLOR, ONE` 的 RGB 混合，只加亮现有画面；Alpha 原样保留，不写深度。

原半分辨率亮部提取及局部 Bloom 仍保留，新增世界尺度层不靠把几次固定像素模糊的步长拉大实现。关闭 `bloom` 同时关闭广域层；白热喷流仍可显示。

### 8.3 先确认真实发光部分，再扩大范围

不能直接把一个 500 格大球与相机射线相交后画亮：大球在墙前可能有一部分，即使整条小喷焰实际在墙后，也会误漏出光团。

正式 `rocket_plume` 程序增加两个模式：

1. **模式 3，一像素可见度**：沿真实喷流选七个轴向位置、每处三个横向样点。每条样点视线复用原来的二十步辐射计算、实际喷流尺寸和同帧近景/DH 深度。每处取最亮横向样点，再平均七处贡献。完全遮住时为零，露出尾段时仍有贡献。
2. **模式 4，广域扩散**：读取上述一个像素的可见发光比例，再按世界半径画橙色光晕。每个广域像素不再重复完整喷流采样，避免几百格范围放大计算开销。

所有喷焰顺序复用同一个 1×1 浮点目标，没有新增逐弹体纹理或数量上限。写入模式绑定另一张有效纹理作为未使用采样器，读取模式先切回主目标，避免同一附件边写边读。新增资源在换世界、资源重载和窗口重建时释放；仍只使用三组采样器。

近景/DH 独立矩阵、正反深度、不同分辨率和光影手持物遮罩继续使用同一输入桥。烟雾及炮口特效不进入该遮挡快照。完全被墙、实体或 DH 地形挡住时，新增光晕为零；源可见时，光晕可以跨过邻近物体轮廓扩散，这是画面光晕的行为。源完全离屏、没有可见样点时，广域层不凭空生成，环境照明仍按世界范围计算。

## 9. 点火与燃尽自然过渡（2026-11-04）

此前正式喷焰直接以完整长宽出现，临近燃尽的阶段亮度最低仍约为七成，结束时直接删除。现在由 `RVP_RocketPlumeParameters` 的 `IGNITION_TRANSITION_TICKS=3`、`BURNOUT_TRANSITION_TICKS=6` 控制显示过渡，单位 tick，20 tick 为 1 秒。

- 点火从喷口逐渐伸长、展开并变亮；燃尽前逐渐收短、变细并淡出。短燃烧期的两段过渡可以重叠，不会突然跳到满亮。
- 过渡比例采用两端平滑的曲线，长度乘该比例、半径乘其平方根；稳态仍是原有 `flame_scale` 尺寸。光晕范围不随过渡扩大或缩小，光晕亮度同步变化。
- 核心原始亮度最高 60000，单纯降低这个数值仍会使显示长时间饱和为白色。因此新增 `PlumeTransition`，在高亮数值转换成最终颜色之后乘过渡比例；局部光晕在软压缩后应用，广域光晕在响应映射后应用。实际生产资源为 `rocket_plume_ranges`，描述 JSON 与 Java 上传同步登记该参数。
- 本地弹体使用新增只读出口 `ticksUntilCurrentMotorStopsBurning()`，只取当前窗口，一级燃尽不被未来二脉冲拖后。远端倒计时扣除收包后已过去的游戏刻；虚拟显示复用既有权威时间线。熄火删除后再次点火会重新渐入，正常逐帧续期保留同一开始时间。
- 暂停时过渡随游戏时钟冻结；明确燃尽、销毁、失去心跳、换世界仍按原规则清理，不在原地追加一团脱离导弹的残焰。原有两秒命令预览保持原来的衰减方式。
