# RVP 火箭世界轨迹体积尾烟

日期：2026-10-30。`effects_data.missile_native_trail_particle_style = "rvp_rocket_flame"` 现在使用世界轨迹体积烟：把烟的位置留在世界里，再按屏幕像素计算视线穿过多少烟。没有增加或替换任何烟雾图片。

## 1. 代码开关与接入

入口：[RVP_RocketTrailParameters](../../src/main/java/org/ywzj/rvp/weapon/visual/RVP_RocketTrailParameters.java)。

| 开关 | 当前值 | 作用 |
| --- | --- | --- |
| `VOLUME_ENABLED` | `true` | 新的世界轨迹、体积尾烟和程序贴地烟浪 |
| `ORIGINAL_PARTICLES_ENABLED` | `false` | 停用 `rvp_rocket_flame` 原来的 TRAIL 贴图粒子生成 |

原来的 `RVP_RocketFlameParticle`、粒子构造入口、贴图、动画曲线和原补点循环都保留。新分支在旧循环前返回；旧近距桥和远距粒子发射器也有开关。切回旧效果需把新通道设为 `false`、旧粒子设为 `true` 后重新构建，不应同时打开两种表现。

`rvp_smoke`、原版粒子和 `rvp_kerosene_black_smoke` 保持各自的实现；其它风格显式开启的旧贴地烟浪也保留。独立的高亮程序喷焰继续由 `RVP_RocketPlumePass` 负责，体积烟不再生成旧橙色火焰片片。

近距入口位于 [RVP_BaseBullet](../../src/main/java/org/ywzj/rvp/entity/projectile/RVP_BaseBullet.java)，经 `RVP_IClientActions` / `RVP_ClientActionsAccess` 转交客户端。服务端实现为空操作，不加载客户端类。

远距入口位于 [RVP_RemoteAmmoVisualRenderer](../../src/main/java/org/ywzj/rvp/client/render/remotevisibility/RVP_RemoteAmmoVisualRenderer.java)，直接转交同一个 [RVP_RocketTrailEmitter](../../src/main/java/org/ywzj/rvp/client/light/RVP_RocketTrailEmitter.java)，跳过原来的粒子补点队列。近远两种实体的 Java 对象或 UUID 可能不同，因此缓存按同一世界的**同步实体编号**去重，每个游戏 tick 最多一份空中采样，本地来源优先。

## 2. 世界烟段与生命周期

[RVP_RocketTrailManager](../../src/main/java/org/ywzj/rvp/client/light/RVP_RocketTrailManager.java) 保存烟段两端的出生位置、年龄、尾喷速度和出生时配置。

- 转弯只追加新烟段；不会把旧烟转到当前导弹方向。
- 烟按自己的出生速度做有阻力的缓慢后抛，并做低频水平漂移和小幅浮升。这里没有读取真实风场，也没有求解空气动力学流体。
- 导弹燃尽或关闭开关时不再追加并断开未来连接，旧烟继续消散。实体因同步距离退出时保留最新端点，下一 tick 的远距克隆可立即接上；没有后续采样则自动超时断链。
- 暂停使用冻结的游戏时钟；同一 tick 的多帧不重复生成。
- 换世界、重连、世界时钟回退清空缓存。
- 超过 512 格的位置跳变，或超过当前生成间隔允许的断包时间，重新播种，避免连接跨地图烟柱。
- 空中尾迹与贴地烟浪分别去重；冷发射阶段仍沿用原有的贴地生成条件。

## 3. 现有配置的含义

无需修改武器或载具包 JSON。所有字段仍从当前 schema 读取，不增加旧键别名或迁移代码。

| `missile_native_trail_density_scale` / `densityScale` | 控制空间烟密度，上限 16，零停止新增 |

| `missile_native_trail_spawn_interval_tick` / `spawnInterval` | 按统一客户端世界时钟决定生成间隔，至少 1 tick |
| `missile_native_trail_step` / `step` | 换算烟段细分长度：`clamp(step × 8 / max(density, 0.05), 4, 32)` 格；不再逐颗生成图片粒子 |

## 4. 逐像素绘制与遮挡

[RVP_RocketTrailPass](../../src/main/java/org/ywzj/rvp/client/light/RVP_RocketTrailPass.java) 使用新增的 `rocket_trail_volume.{vsh,fsh,json}`。

程序先计算视线与有界烟段的交区，再沿可见区间分段采样。这种做法叫光线步进：每一步累积烟对背景的吸收和散射，视线穿过的烟越厚就越不透明。烟的翻滚由数学噪声函数生成，噪声在世界坐标中保持稳定，不随相机转动而贴着屏幕移动。

复用 `RVP_ScreenLightPass` 已有的同帧近景/DH 深度、各自配对的观察/投影矩阵和光影手持物遮罩。先把两份深度还原到同一空间，再选最近的可见表面；不能直接比较两张图的 0～1 数字。视线采样到墙或实体表面就停止，相机进入烟内部时仍能正确从眼前开始积分。

深度只读，烟不写世界深度，不成为发动机光和其它尾烟的固体遮挡。颜色使用“预乘透明度混合”：输出颜色已乘烟的遮盖比例，剩下部分保留背景；目标画面的 Alpha 保持不变。没有加入发光提取，因此灰烟本身不会产生 Bloom 光晕。

每段最多接受附近四盏当前实际活动灯，沿用 `/rvplight` 的烟雾亮度倍率。烟受光的位置来自烟自身，光路使用当前屏幕深度做近似遮挡。关闭环境照明、灯数量为零或没有仍燃烧的喷口，都不取消基础尾烟和 DH 深度捕获。

远处不足一个像素的烟使用保能量的覆盖近似。扩展只用于像素覆盖；真实烟前缘在墙后时仍拒绝绘制，避免扩展后“抹到墙前”。

## 5. 预算与效果边界

- 最多 128 个来源、总计 16384 段缓存、每来源 1024 段；单次更新最多拆 32 段。
- 每帧先按来源公平挑选，最多 512 段，不受环境光八灯或 256 格距离预算限制。
- 远处只合并相接且几乎共线的烟段；不把真实弯道拉直。
- 投影由两端共同求矩形，不拿长烟的长度作为矩形高度。即使两端都离屏，横穿画面的烟仍保留。
- 绘制面积总预算为三张屏幕；超额优先附近烟。大面积烟的采样数从 24 步降低，最低 8 步，限制身处密烟时的重复计算。
- 透明烟段按中心距离由远到近合成。相交烟段、玻璃、其它透明特效的精确逐像素前后关系仍是近似。
- 程序喷焰和光晕先合成，体积烟后合成；没有实现烟与火焰之间完整的逐层透过率，也没有真实烟内阴影、多次散射或空气流体模拟。
- 现有热成像、TV 后处理和各种光影包的实机场景仍需分别验收；隐藏窗口不能替代游戏验证。
