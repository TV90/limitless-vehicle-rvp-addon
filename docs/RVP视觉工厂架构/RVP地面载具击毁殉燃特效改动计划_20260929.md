# RVP 地面载具击毁殉燃特效改动计划

日期：2026-09-29。状态：已按用户审阅后的修订实施。用户已确认：地面载具自身被击毁后触发，攻击来源不限。

> **实施时的最新要求优先**：用户明确“不使用每车单独配置该特效”。因此以下原计划中逐车 display 配置、JSON 数据类、首台配置差异等设计已取消，改为履带/轮式载具默认自动适配。所有现有 display、载具 JSON、结构模型均未修改。实际实现、自动定位的近似边界、调试命令与验证记录见 [自动适配实施说明](../RVP视觉工厂架构/RVP地面载具自动殉燃实施与调试_20260929.md)。下文保留原审阅稿作为设计依据，出现不一致时以上述最新要求及实施说明为准。

> **2026-10-06 口径更新**：接缝与火星两项已再次改版——接缝由“固定 8 点环绕向上”改为“沿炮塔底缘按弧段随机采样、每座炮塔同时 12 点、单点持续 3～6 tick 后各自换点、俯仰在水平 0°～+30° 随机”（§1 表格中“沿接缝多个点向外、向上喷火，形成断续环状喷焰”已不适用，现在是同一时刻 12 点分散喷射）；火星由原版 `ParticleTypes.FLAME` 改为 RVP 自实现的“重力下坠 + 落地弹跳”粒子。粒子预算随接缝点数由单车 48/全局 160 上调到单车 96/全局 320。仍以上述实施说明为准。

## 1. 目标表现

采用两层效果：连续的橙黄色火柱负责主体形状，Minecraft 原版 `ParticleTypes.FLAME` 负责喷散的火焰粒子。原版粒子不更换贴图、不注册替代版本。

| 出口 | 火柱与运动 | 原版火焰粒子 | 初始调参建议（待实机校准） |
| --- | --- | --- | --- |
| 舱盖 | 黄色亮芯、橙色外缘，根部贴合舱盖；始终沿世界 +Y 竖直喷出，顶部轻微翻卷 | 大量，沿柱身上升并向外散开 | 主柱高 5～8 格、宽 0.5～0.9 格；每车每 tick 8～12 枚 |
| 炮塔接缝 | 沿接缝多个点向外、向上喷火，形成断续环状喷焰 | 大量，分散到接缝多个点 | 喷出约 0.4～1.2 格；每车每 tick 8～12 枚 |
| 炮口 | 根部固定炮口，沿炮管轴线向外喷出橙黄色火柱 | 中等数量，顺炮口方向扩散 | 柱长 2～4 格、宽 0.25～0.5 格；每车每 tick 3～5 枚 |

数量是近距离、每车各类出口的总预算，多舱盖、多炮口之间分摊，不能随挂点数量无限增长。所有尺寸和数量均可配置；不是已经验证的最终效果。

效果维持到残骸移除或不再被客户端追踪；不另设伤害、弹药消耗、方块着火、炮塔飞离或声音。现有近处烟和长程烟继续运行，避免再叠一套浓烟遮住火柱。火柱使用全亮材质，不代表动态照亮周围方块。

## 2. 已核实的接入依据

- `RVP_WreckSmokeEmitter` 已通过 Forge `ClientTick END` 遍历受追踪的击毁整车，排除 `VehiclePart`；它不经过单次爆炸视觉工厂。
- `AbstractVehicleClientMixin` 已屏蔽本体的整车残骸烟。本需求无需增加或修改该注入。
- 本体有 `TrackedVehicle`、`WheeledVehicle` 类型，适合作为地面载具类型门控；不能以 `onGround()` 判断，否则落地飞机也会进入效果。
- `PartUnit.getStructureGroup()` 与 `VehicleCubeGroup.globalTransform(...)` 提供现有部件变换；本体 `WeaponUnit.aimContexts()` 返回炮口起点与方向，包含炮管长度。
- `RVP_DisplayTransparentModeManager` 已通过客户端资源重载扫描 `display/vehicle`。同样的加载方式可承载纯视觉殉燃配置，不需添加数据类 Mixin。
- 贴图资产已有 `RVP_AmmoCookoff_20260928`。已阅读说明并查看逐帧总览，其中高温喷焰适合本需求；翻卷火团后段带烟，不作为主要火柱。

## 3. 推荐实现

### 3.1 客户端控制与生命周期

新增 `client.visual.cookoff` 模块，以客户端 Forge Tick 和世界渲染事件维护持续效果。优先复用击毁烟现有遍历，在其烟雾周期判断之前转交殉燃更新，避免再加一次全实体扫描；烟雾自身发射周期保持独立。

仅处理：地面载具类型、已击毁、未移除、存在启用的殉燃配置。飞机、舰船、脱落残件、仍存活但部件受损的载具均不触发。

实例按世界与实体 UUID 管理，防止实体数字 ID 复用串车。暂停不推进；移除、退出、换维度、资源重载时清理实例和挂点缓存。原版粒子停止新增后自然消散。

首版采用持续喷燃与缓慢随机起伏，不采用需要权威击毁时间的“击毁瞬间爆发→固定秒数衰减”分段。后来进入追踪范围的玩家直接看到持续喷燃，不补播击毁爆发；客户端随机波动无需跨玩家逐粒同步。因此首版不增加网络包，也不读取本体受保护的 `destroyedTick`。

### 3.2 出口定位

- 舱盖：配置所属部件 ID 与局部偏移。位置跟随车体/炮塔变换，喷射方向固定世界向上。
- 接缝：配置所属炮塔部件 ID 与若干局部采样点，每点带局部喷射方向，随炮塔和车体姿态转换。优先显式点集，避免把不规则接缝猜成圆环。
- 炮口：显式选择武器站 ID 与炮口索引，读取现有出弹起点/方向。需校验武器站与结构组有效，不能接受本体缺失结构时回退到车体中心的结果；特殊武器站允许显式部件偏移作为配置替代。
- 缺失挂点：跳过该出口并限次提示，其他合法出口继续运行；无炮塔、无火炮的地面车辆只配置实际存在的出口。
- 使用当前/上一 tick 的变换做渲染插值，分别验证车体倾斜、炮塔转动和炮管俯仰。不能沿用屏幕坐标或静态模型坐标。

结构模型仅只读，不添加骨骼、不移动 pivot、不调整 cube。车辆/武器/模型 ID 均不写进 Java 白名单。

### 3.3 火柱绘制

新增独立火柱渲染器，沿出口轴线分段排列重叠的动画火焰片，通过交叉面、宽度收缩、亮芯与外层错相形成连续火柱；不把一张完整火团贴图直接拉长充当整根火柱。舱盖高柱与炮口横柱共用绘制实现，仅轴线与参数不同。

动画直接按 16 帧横条取 UV，保留素材固有橙黄色。控制透明边缘和深度测试，近处避免十字面暴露与穿模；缺贴图时保留原版 FLAME 层并给出一次提示。火柱使用渲染事件绘制，粒子按 tick 发射，避免 FPS 高时粒子倍增。

### 3.5 性能与调试

- 近处（建议 0～64 格）完整效果；64～128 格减少粒子；128～256 格保留简化火柱和少量原版火焰；更远停止殉燃绘制，继续沿用现有长程烟策略。
- 设置全局每 tick 原版火焰生成上限，建议先以 160 枚为调参起点；每车基准约 19～29 枚/tick，密集残骸场景按距离分配预算。同时限制渲染火柱数和每柱片数。
- 尊重游戏粒子设置，不用强制粒子绕过预算；全局上限不应被单个多炮塔车辆耗尽。
- 增加客户端 `/rvpcookoff` 调试入口：显示配置、准星载具预览、停止、临时调整高度/长度/密度；预览不需要真实击毁，不改变载具状态。
- 本轮不承诺远距代理载具或未追踪实体也生成喷燃；它们需要单独核对代理状态与去重路径。
