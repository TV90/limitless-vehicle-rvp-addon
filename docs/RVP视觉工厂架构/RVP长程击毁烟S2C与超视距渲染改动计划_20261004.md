# RVP 长程击毁烟 S2C 与超视距渲染改动计划

日期：2026-10-04。状态：待用户审阅；本轮仅调研和编写计划，未实施功能。

## 1. 建议方案与目标

将长程击毁烟改为「服务端持续烟源完整快照 → 客户端独立烟源管理 → 专用远距半透明绘制」。复用 RVP 网络通道、公共 endpoint 分端方式和远距投影计算；烟源独立于载具模型代理与雷达目标授权。

目标：客户端没有残骸实体、没有加载残骸所在区块时，仍能根据服务端同步持续生成并绘制长程烟。近处通用烟、部件损伤烟及殉燃保持原来的职责；长程烟的贴图、核心/外层、上升、东风、错相和调试参数沿用当前效果。

适用范围仍为已击毁整车 `AbstractVehicle`，排除 `VehiclePart`，不增加车型或武器 ID 判断。

## 3. 服务端烟源与 S2C 协议

### 3.1 独立持续源

新增 `RVP_WreckSmokeSyncService`，使用 Forge 服务端 Tick END 与退出/停服事件，无新增 Mixin。

- 每个同步周期按维度收集一次已加载整车，筛选已击毁且未移除的实体；不能每名玩家重新全实体扫描。
- 主 OBB 的世界中心、水平半径和高度使用与现有发射器相同公式，缺失时回退 AABB；只读取结构，不修改模型。
- 烟源由「维度 + 载具 UUID」标识；实体 ID 仅辅助诊断/近处位置匹配，防止实体 ID 复用串源。
- 按同维度、距离、数量预算向玩家发送烟源。推荐所有玩家均可接收，不依赖是否乘车或雷达是否发现残骸；不改变载具模型原有授权规则。
- 不为烟源追加区块强加载。服务端区块卸载或实体移除后撤销烟源；客户端已生成的烟自然衰减。这一版支持客户端超视距，不承诺服务端卸载区块后继续燃烧。
- 已存在的载具租约可能间接维持区块加载，但烟源系统自身不申请或扩大租约。

### 3.2 完整快照

新增 `S2CWreckSmokeSnapshot` 与服务端安全的 `RVP_WreckSmokeEndpoint`，走现有 `RVP_Network.CHANNEL`，方向固定为 `PLAY_TO_CLIENT`。

| 内容 | 用途 |
| --- | --- |
| `dimension`、连接内递增 `sequence`、`serverGameTime` | 世界校验、拒绝旧包、建立服务器时间采样基准。 |
| 当前距离策略与有效期 | 客户端使用服务端批准值，避免客户端 common 配置覆盖服务器规则。 |
| 每源 UUID、辅助 entity ID | 稳定识别、去重和调试。 |
| 主结构中心、水平半径、高度 | 客户端没有实体、display 或模型时仍可生成烟。 |
| 该烟源首次被服务端管理器观察到的 tick、随机种子 | 保持发射相位与随机序列稳定；该 tick 不是本体真实击毁时刻。 |

采用完整集合语义：缺项即停止对应源的新烟，空集合撤销全部源。只发送源状态，不逐粒子发送位置或运动数据。首个有效快照即可让中途进入范围的玩家开始看到烟。

收包严格校验条目数、重复 UUID、有限坐标、正尺寸和数值上限；禁止按包内长度无限分配。连接序号在换维度时继续递增，在断线重连后重置；客户端绑定实际 ClientLevel/连接生命周期，并保留连接级序号门槛，防止返回同一维度时旧包重新生效。

新增包后同步递增协议版本（调研时为 `21`），双端须使用同版模组。默认 endpoint 为 NOOP，只在 `RVP_ClientBootstrap` 安装客户端消费者，公共层不引用客户端类型。

## 4. 客户端管理与近远一致性

新增 `RVP_ClientWreckSmokeState` 保存烟源状态，新增 `RVP_LongWreckSmokeManager` 统一推进长程烟。

1. 所有真实残骸的长程烟都由同一个 S2C 管理器发射，包括近处残骸；原 `RVP_WreckSmokeEmitter` 移除真实残骸的长程发射分支，保留近处烟和殉燃调度。
2. 本地真实实体可提供更平滑的当前发射中心，但必须按 UUID 匹配有效 S2C 源；实体进出追踪范围不会创建第二份烟源、清空既有烟团或重置相位。
3. 长程烟的存活对象由独立管理器持有，不再加入原版 ParticleEngine。优先复用 `RVP_WreckSmokeParticle` 的运动和逐面片绘制；只抽取需要的渲染数据接口，不重写一套不同运动公式。
4. Tick 推进与 render 分开，同一客户端 tick 只发射一次；暂停、重复帧和重复快照不加速生成。依据服务器时间采样推进发射节拍，不直接依赖可被时间命令跳变的客户端世界时钟差值。
5. 快照缺项或超时停止发射，存活烟团按各自寿命继续飘散；换世界、断线立即清空源与烟团。资源重载释放并重建 GPU 状态。
6. `/rvpwrecksmoke preview` 仍为本地预览，以独立预览标识接入相同模拟/绘制流程；`show/set/reset` 的现有参数语义保留，并补充源数、烟团数、距离和淘汰统计。

**首版中途加入策略：**收到快照后开始正常发射，不回放过去 23 秒全部烟团；因此刚进入范围时烟柱会逐渐形成。这样不会用当前残骸坐标伪造移动残骸的历史烟迹。若需要进入范围立刻出现成熟烟柱，应另加有预算的历史采样/重建方案，不能把它描述为首版已支持。

**生命周期边界：**烟源停止以服务端实际撤销为准，不在客户端假定「首包后再烧 60 秒」。残骸移除后，默认最后一批烟最多再存活约 23 秒。客户端断流有效期只是停止新生的安全上限，不是残骸寿命。

## 5. 远距渲染：必须和网络改动一起完成

新增 `RVP_WreckSmokeRenderer`，通过现有 Forge 渲染事件接入。不能以「包收到、粒子生成了」作为超视距完成条件。

- 基于实际相机位置与朝向生成烟团面片；第三人称、观瞄缩放下正确定位。服务器授权距离首版按玩家位置计算，不宣称覆盖相机远离玩家的任意远程观察场景。
- 复用远距投影数学，按烟团当前位置及膨胀后的面片范围构造专用视锥；不能用原世界短远平面视锥先过滤掉远烟。
- 绘制按相机视深度由远到近排序，启用 alpha 混合，深度只测不写；保持核心/外层现有视觉参数。
- 普通空气仅在烟雾批次内调整雾距离；水下、熔岩、细雪、失明和黑暗继续遵循原限制。退出绘制后完整恢复矩阵、shader、混合、深度、纹理及 framebuffer 状态。
- 扩展投影的深度不能直接与原世界深度作未经转换的比较。推荐烟雾专用 shader：读取安全的世界深度副本与对应逆投影，还原视空间深度后逐片元判断遮挡。
- DH 开启时，通过现有兼容层捕获有效 DH 深度副本、矩阵与当帧标识，在烟雾 shader 中加入 DH 地形遮挡。不可在同一纹理上同时采样和写入，也不能复用上一帧深度。
- 烟雾使用透明批次，不塞进现有载具离屏颜色/单层深度合成结果；这样避免用最前一层烟的深度代表整根透明烟柱，或把半透明烟写成挡住后方地形的实体表面。
- 渲染顺序必须通过现有 DH 回调和 Forge 事件确定，在地形有效输出后、适当的后处理之前提交。只复用/扩展 RVP 侧兼容代码，不新增本体/原版注入。
- DH 深度不可用时应有明确诊断和降级：普通世界范围内仍按可用世界深度绘制，依赖 DH 地形遮挡的范围外烟暂不绘制；禁止静默采用穿山可见作为成功结果。
- 未安装 DH 时，已渲染的地形应正确遮挡；客户端没有的远处地形无法凭 S2C 烟源恢复，不承诺不存在地形数据时仍有完整远山遮挡。

热成像需要回归普通观察、观瞄和 HITL 场景，但本期不额外把长程烟改成热源：当前 `RVP_WreckSmokeParticle` 未注册 `RVP_ThermalParticleChannel`，该通道还存在 512 格筛选；不能以「迁移到独立管理器」为由顺带改变白热语义。

## 6. 建议默认值与性能边界

以下为待审阅的设计值，不是已经测得的性能结论。

| 项目 | 建议值 | 说明 |
| --- | ---: | --- |
| `wreckSmoke.enabled` | true | common 服务端开关；不依赖远距载具模型开关。关闭后停止源，已有烟自然结束。 |
| `wreckSmoke.maxDistance` | 4096 格 | 独立可调；与现有远距载具默认上限一致，比当前发射器 1536 格门槛更远。按玩家到烟源三维距离授权。 |
| `wreckSmoke.syncIntervalTicks` | 10 tick | 每秒 2 次源快照，残骸慢速运动足够；位置在客户端插值。 |
| `wreckSmoke.maxSourcesPerPlayer` | 32 | 超额按距离选取，加入小幅滞回维持选择稳定；载具模型与烟源预算独立。 |
| 客户端源超时 | 至少 40 tick，且不小于同步间隔的 4 倍 | 以客户端单调 tick 计数衡量断流；服务器随包给有效期。 |
| 常态每源长程烟数量 | 约 92 枚 | 每 10 tick 发射 2 枚、寿命 460 tick；32 源约 2944 枚。 |
| 客户端烟团硬上限 | 初始建议 4096 枚 | 包括已停源但未消散的烟和预览；调试改大发射频率/寿命也受保护。 |

配置放 `RVP_CommonConfig`，取值范围有硬边界，不新增载具/武器 JSON schema。所有新字段与方法按项目中文注释规范补齐。

烟团预算超额时优先淘汰低屏幕贡献/远处旧烟，避免在同一帧反复创建后立即删除。保持核心/外层成组管理，远距降采样应平滑，不能让烟柱闪烁。发射停止后仍按活烟团计算渲染包围范围，考虑上升和风漂移，避免只按地面源点裁掉可见烟顶。

按单源约 80～120 字节估算，32 源、每秒 2 包约 5～8 KB/s/玩家（不含网络封装，最终以实际编码统计为准）；带宽主要与烟源数量相关，不随粒子总数增长。

## 8. 实施顺序与验收

1. **源同步与管理**：实现协议、服务端收集、客户端状态及生命周期测试；检查专服安全。此时只代表链路成立，不宣称超视距完成。
2. **统一长程模拟与普通远距绘制**：近远同一来源，预览共用，预算、远平面、雾和世界深度遮挡生效。
3. **DH 透明烟遮挡**：接入有效当帧 DH 深度，验证无穿山、无烟团写深度挡景、无载具双层保护回归。
4. **联机和回归**：通过以下矩阵后再更新完成状态。

| 验收场景 | 通过标准 |
| --- | --- |
| 128 / 512 / 1024 / 1536 / 4096 格，低客户端渲染距离 | 采用默认或明确设置的 4096 格配置；授权内可见长程烟，超范围按策略撤销新生；记录实际边界。 |
| 观察者从未追踪到目标实体；服务端目标区块由另一玩家保持加载 | 确认客户端无真实实体仍收到烟源并绘制；不能仅测试先近后远。 |
| 近远往返、客户端实体加载/卸载 | 长程只有一份，烟柱不断代、不突然翻倍；近烟和殉燃维持原行为。 |
| 玩家步行、乘车；雷达未发现；载具模型远距开关关闭 | 烟源依独立规则继续工作，模型授权未被扩大。 |
| 中途进入范围/登录 | 一个同步周期内开始发射；首版渐进形成烟柱符合 §4 边界。 |
| 残骸到期、手动移除、服务端区块卸载 | 下一份完整快照停止新生，末批烟自然消散，无永久烟柱。 |
| 空包、旧包、重复包、断流、entity ID 复用、返回原维度 | 正确撤销/拒绝/去重；断线与换世界无残留。 |
| DH 开/关、山脊前后、世界深度遮挡、不同缩放、资源重载 | 正确遮挡且无错误裁剪；不可用路径有诊断；既有远距模型和 512 格内载具保护不退化。 |
| 水下/失明、热成像、不同画质与 framebuffer 路由 | 保留对应环境限制，无错位、重复绘制或渲染状态泄漏。 |
| 1 / 8 / 32 / 超过 32 个源，连续击毁和极端调试参数 | 源/烟团数量有界；记录包大小、客户端 Tick/帧耗时与淘汰次数。 |

自动验证覆盖编解码边界、完整集合替换、UUID/维度/序号、源超时、单 tick 发射、预算上限和投影/状态恢复，不以重复实现的断言代替行为测试。

实施后在项目根目录按仓库规定执行：

```powershell
./gradlew build
```

服务端冒烟后台启动 `./gradlew runServer`，每 10 秒轮询日志，出现 `Done (Xs)!` 才算启动通过；`rg -a` 检查新增错误，噪音基线按 `docs/调试与修复规范.md` §5.1。客户端可见距离、半透明遮挡和性能必须实机验证，不能由 build/专服启动推定。

## 9. 本轮审阅重点

建议确认的设计取向为：独立烟源快照；默认 4096 格、32 源、10 tick 同步；所有同维度范围内玩家可见；服务端卸载区块后停止新生；首版中途进入时渐进形成烟柱。

推荐渲染方案还涉及另名新增三份 shader 资源，需显式确认该资源创建范围。贴图、模型、本体源码与新增 Mixin 均不在本计划改动范围内。

本轮未编译或启动游戏，因为没有修改运行代码；现有工作区已有其他暂存改动，本计划不调整这些改动，也不执行 Git 提交。
