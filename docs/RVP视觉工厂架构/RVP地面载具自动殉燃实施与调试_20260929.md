# RVP 地面载具自动殉燃实施与调试

2026-09-29。用户审阅后明确：**不使用每车单独配置该特效**。本实现默认适用于所有被客户端追踪的履带/轮式载具，攻击来源不限，无需修改任何载具 JSON。

## 1. 当前表现

- 已击毁地面载具：舱盖/顶部高柱、炮塔接缝喷焰、真实炮口轴向火柱，叠加 RVP 自实现的"受重力下坠 + 落地弹跳"火星（`RVP_WreckSparkParticle`，2026-10-06 起替代原版 `ParticleTypes.FLAME`）。
- **火星只从舱盖与接缝喷出**：用户定版 2026-10-06 取消炮口火星，炮口只保留轴向火柱。
- 舱盖：**每个实际舱盖 1 根火柱，至少保底 1 根近似火柱**；每个舱盖另外保留 3 个火星采样点，位置固定在舱盖顶部（沿局部 X 轴等分错开），火星方向沿**世界 Y 轴向上做 30° 圆锥随机采样**，单点停留 3～12 tick 后换向。**舱盖顶部高柱仍按原行为固定世界向上**（默认高 6 格、根部宽 0.5～0.9 格），柱向与火星锥向已解耦。
- 接缝沿炮塔最大 OBB 底缘随机采样：**每座炮塔同时 12 个采样点**在喷火，每个点持续 3～12 tick 后独立换到新的随机点；采样点只喷火星、不再自绘短焰柱。方向为采样点的水平外法线，抬升角在 **0°～+30°** 区间随机取样（水平偏上、绝不向下），另有 ±8° 方位抖动。
- 炮口柱长默认 3 格、宽 0.4 格，使用本体 `WeaponUnit.aimContext(Bolt)` 的真实出弹起点和方向，包含炮管长度；**不喷火星**。
- 每车近距火星生成尝试数按出口权重分配：舱盖 10、接缝 10、炮口 0，同类出口共同分摊。
- 效果持续到残骸移除、卸载、离开 256 格范围或不再满足击毁/预览条件；结束时进入可调时长的火柱收缩，收缩完成后清理。收缩完成前重新进入范围会恢复持续喷燃，不补播击毁瞬间爆发。
- 原有近处烟/长程烟继续运行；本功能没有伤害、方块着火、声音或弹药消耗。

## 2. 自动适配规则与边界

1. 只接受 `TrackedVehicle` / `WheeledVehicle`。不使用 `onGround()`，所以飞机落地不会触发；脱落残件也不参与。
2. 通过现有部件 ID/结构骨名称中的通用 `hatch`、`cupola`、`舱盖` 语义寻找实际舱盖部件，以对应最大有效 OBB 顶部作为出口；每个舱盖登记 **3 个火星采样点**，但只用中心采样点绘制该舱盖的 **1 根火柱**。
3. 若无独立舱盖部件，在最大有效火炮塔 OBB 顶部近似 **1 个舱盖火柱**（火星仍登记 3 个采样点）；没有可识别火炮塔时，以主车体 OBB 顶部作为至少 1 个近似泄压口。**这属于自动几何近似，不能保证对应每个模型画出的真实舱盖。**
4. 火炮识别先检查武器行为：RVP `MACHINEGUN` 或本体 `VehicleCannonWeaponData`。再读取已有 reload 配方中 `AmmoItem.AmmoType.AUTO_CANNON/ARTILLERY`，兼容一站多弹种；机枪、导弹等其它明确弹药类型排除。
5. 第三方装填物没有可识别类型时，才以已有口径 ≥20 的字段回退。包内 BMPT/LAV 机炮虽把可视口径设为 19.05，也能通过 AUTO_CANNON 装填类型识别。不得按武器 ID 匹配。
6. 最多两座有效炮塔生成接缝、四个炮口参与绘制火柱；没有有效炮口结构时不使用车体中心伪装炮口。炮口只画火柱、不喷火星。原车部件脱离后相应出口停止。
7. 接缝轮廓是 OBB 矩形近似（用户 2026-10-06 定版选 (a) 保持矩形，不做并集/真实点集轮廓）；每座炮塔同时有 12 个采样点**按环绕方位**均匀铺开（槽内抖动居中，相邻方位差恒 ≥ 半个槽，俯视看是均匀绕一圈）、各自独立换点。接缝只喷火星、不自绘火柱。结构缺失时跳过，已有几何不做写入。

当前没有车型/模型 ID 白名单、逐车参数表、display 新字段、旧 schema 兼容逻辑或新增 Mixin。主体算法适配所有地面车，但特殊模型的精确出口位置仍需实机检查。

## 3. 技术链路

```text
RVP_WreckSmokeEmitter 的现有 ClientTick END 实体遍历
  → RVP_WreckCookoffController.begin / consider / end
  → 自动解析并缓存现有部件/OBB/炮口；接缝每 tick 现采样（3～6 tick 换点）
  → 以世界 + 实体 UUID 管理实例，按近到远公平分配预算
  → RVP_WreckSparkParticle.spawn（RVP 自重物理：重力下坠 + 落地弹跳，2026-10-06 起）

RenderLevelStageEvent.AFTER_WEATHER
  → RVP_WreckCookoffRenderer
  → 插值前后 tick 世界锚点
  → 有色横条分段交叉片组成火柱，全亮、深度测试、只写颜色
```

控制器基于世界 tick 去重，暂停不会重复发射。世界退出/换维度、资源重载清理实体引用和预览；相同 UUID 对应新实体对象也会重建挂点。首轮缺失结构且没有有效绑定时，每 20 tick 重试。远距代理载具不在本轮新增支持范围内。

渲染沿轴线分段铺设重叠火焰片，每根近处 12 段、远处 6 段，亮芯与外层错相。主体使用横条第 3～8 帧循环，顶部第 9～12 帧衰减；不是将完整火团一张拉成长条。

### 2026-09-29 视角转动导致火柱漂移修复

已核对本地 Minecraft 1.20.1 `LevelRenderer` 字节码及 Forge 47.4.13 的渲染阶段补丁：进入 `AFTER_WEATHER` 前，原版已将事件 PoseStack 的视图变换乘入 `RenderSystem` 的 ModelView。旧火柱又通过 `VertexConsumer.vertex(Matrix4f, ...)` 乘了一次事件矩阵，实际产生双重视图旋转，喷口随玩家转头漂移。

修复后 CPU 仅以双精度计算 `worldPosition - cameraPosition`，使用不带矩阵的顶点重载。着色器保留现有 ModelView 的一次变换，因此保留原版视角旋转、摇晃与载具相机效果。未修改模型挂点、火柱参数、纹理、现有载具资源或 Mixin。

新增回归覆盖不同 yaw/pitch/roll 下同一世界锚点的还原、相机绕车移动以及大世界坐标下的小位移精度，并以旧双重矩阵路径作为反例。客户端仍需用 `/rvpcookoff preview start` 确认绕车、转头、俯仰时喷口贴合。

### 2026-10-06 火星改为 RVP 自重物理（重力下坠 + 落地弹跳）

原实现直接把速度交给原版 `ParticleTypes.FLAME`：其 `RisingParticle` 固定 `friction = 0.96`、`gravity = 0`，且 `FlameParticle` 覆写 `move()` 为**只平移不自碰撞**，所以火星严格沿出口轴直线滑出，没有下坠与触地。现改为 RVP 自建粒子 `RVP_WreckSparkParticle`（`client/particle`），运动完全由本类实现。

**贴图不动**：仍复用现有 `assets/ywzj_rvp/textures/nuclear/flare.png`，经本类私有 `ParticleRenderType` 直接绑定 + 0~1 自算 UV，与 `RVP_MchrFlareParticle` 同路径、同加法混合配色；**未新增、未替换、未覆盖任何贴图文件**。未新增粒子类型注册、未新增粒子定义 JSON、未新增 Mixin。

**为什么不用 `Particle.move`**：该方法命中即把三轴速度清零并置 `stoppedByCollision`，无法反弹。本类改用轴分离 AABB 扫掠（判据沿用原版粒子的 `BlockState.isSolidRender`），只对受阻轴做响应，再由包围盒回写位置。

| 物理量 | 取值 | 说明 |
| --- | --- | --- |
| 重力 | `0.04/tick²` | 与爆炸飞溅火星同级 |
| 每 tick 顺序 | 先 `yd -= g`、水平 `×0.96` → 基类 `Particle.move` 碰撞位移 → 触地响应 | 与本体粒子"先受力后位移"一致 |
| 位移 | 复用基类 `Particle.move` | 它按运动扫掠求交并**只推进到接触点**，遇方块/水才清零对应轴速度；本类只在其后反射速度，所以不会"离地近 1 格就弹"或越过接触面 |
| 出生盒对齐 | `setSize(w,h)` 后紧跟 `setPos(x,y,z)` | `setSize` 字节码沿用**旧 `minY`** 重建包围盒、不重新居中 Y；不补 `setPos` 会让盒底落在出生点上，粒子一出生就处于触地状态（实测缺陷，已修） |
| 沿轴抛射速度 | `0.45 + rand×0.5`（0.45～0.95 格/tick） | 竖直分量即沿轴分量，喷出与下坠是同一物理过程 |
| 竖向恢复 | `×0.35`，最低触发 `0.05` 格/tick | 每次弹跳约衰减到 1/3 高，低于阈值只贴地滑行 |
| 触地水平摩擦 | `×0.6` | 落地后迅速趴住，不再远滑 |
| 横向撞墙 | 交给基类 `move` 处理 | 本类不再单独判墙，避免"三轴同时位移 + 分轴扫掠"导致的假阳性撞墙吞水平速度 |
| 弹跳上限 | 3 次 | 之后只滑行，由淡出收尾 |
| 寿命 | `16/(rand×0.8+0.2)` → 16～80，下限 24 tick | 保底长于"初速 0.95/重力 0.04 ≈ 24 tick 才开始下落"，否则看不到弹跳 |
| 淡出 | 寿命末 25%（进度 0.75 起）alpha 线性降到 0、体积收 50% | 避免在空中瞬灭 |
| 数量预算 | 不变：舱盖 10、接缝 10、炮口 4 枚/tick，仍走 `RVP_WreckCookoffBudget` | 仅"原版 FLAME"换成"RVP 火星"，未放大粒子数 |

**可见性边界（与既有 MCHR 火星一致）**：火星经 `ParticleEngine.add` 直加，不经 `ClientLevel.addParticle`/`LevelRenderer`，因此**原版那两道门（32 格距离裁剪、`ParticleStatus.MINIMAL` 直接丢弃）对火星不生效**；本功能自己按 `RVP_WreckCookoffBudget.distanceScale`（≤64 格 1、≤128 格 0.4、≤256 格 0.1）与"粒子选项倍率"控制**生成次数**，再远不生成。火星的可见范围因此仍是 256 格档位，而不是原版的 32 格。未覆写 `getParticleGroup()`，故引擎的"每组数量上限"同样不生效。将来若要严格跟原版一致，需要把火星改成注册粒子类型并走 `ClientLevel.addParticle`。

物理常量与碰撞响应函数 `respondToContact(...)`、`launchSpeed(...)`、`rollLifetime(...)` 均为 `public static` 纯函数，供 `RVP_WreckSparkParticleTest` 直接断言。距离 LOD 仍由既有分配额与火柱段数负责，寿命不随距离缩短（否则远处火星会落地前淡出）。

### 2026-10-06 接缝改为"随机采样 + 分段换点 + 多点同时喷 + 水平 0°～+30°"

**行为变更**：旧实现把接缝写成炮塔 OBB 底缘 8 个固定方向角、方向 `(x, 1.1, z)` 归一化（约 42° 上仰），因此每次殉燃的火星位置与朝向完全固定。现改为按需求动态采样：

- **采样位置**：沿炮塔 OBB 底缘取点（`RVP_WreckCookoffGeometry.seamSample`），但**按"绕塔方位"等分，而不是按底缘弧长等分**：把一周 360° 等分为 12 个方位槽，采样点序号决定它在哪个槽、种子决定槽内方位（抖动居中展开，相邻点方位差恒 ≥ 半个槽）。
  - **修掉的真实缺陷（用户实测 T-90M / BMPT 上"喷口集中在左后/左前/右前"）**：底缘是**矩形**，四条边从炮塔中心张开的角差别很大（宽而浅的炮塔，前/后边张角远大于侧边）。按弧长等分时，短边一侧的点在俯视图上挤成一团、长边一侧拉稀。探针量化对比（12 点，最好情况）：宽浅盒 `3.2×1.1` 的方位间距**最大/最小 = 14.85**，`2.6×3.4` 为 9.16，窄深盒 `1.1×3.2` 为 14.54——即最挤处与最疏处差近 15 倍，正是"集中在一侧"的成因。改为按方位等分后，同样三种盒型在**最差情况**下也只要 1.38。
  - 之前两轮还修掉了两个同方向的缺陷：`seedRandom` 用"乘黄金比例取小数"，在 `seed*13+point*7` 上只散出 0～0.4 的窄带（改为 Murmur3 finalizer）；弧段号 `index×2 (mod 24)` 让 12 个点只落偶数弧段、整圈恒空一半。
  - 教训：前两轮的测试按"底缘周长位置"断言均匀性，因此**看不见"俯视角度上不均匀"**；现在改为按 `azimuthOf(x, z)` 断言，这才是观感对应的量。
- **多点同时喷**：每座炮塔 `SEAM_POINTS_PER_TURRET = 12` 个采样点，同一时刻 12 处在喷（双炮塔车 24 处）。
- **分段换点**：每个采样点持续 **3～12 tick**（`SEAM_BURST_MIN/MAX_TICKS`）后换点；段号由"整周期除法 + 周期内查表"（`seamSamplingSeed`）O(1) 求出，且各点用 `sampleIndex × 3` 的相位错开，所以 12 个点不会同时换点。
- **方向**：以采样点水平外法线为基准，俯仰在 **0°～+30°** 随机取样，再叠加 **±8°** 方位抖动。
  - **符号约定坑**：本体 `VectorUtil.rotToVec(pitch, yaw)` 的 `pitch` 是"抬头为负"（`rotToVec(p, y).y == -sin(p)`，与 `WeaponUnit.aimContext.direction.x` 同约定）。要得到"向上 0°～+30°"必须传入 `-pitchUp`；传正值会变成向下的倒喷（该 bug 由 `seamDirectionPitchStaysWithinZeroToThirtyDegrees` 断言抓到）。
- **接缝不画柱**（用户定版 Q2=a）：24 根接缝柱会互相重叠，且占满自绘火柱 96 根配额的四分之一，收益低；接缝出口只喷火星。
- **距离 LOD 放宽**（用户定版 Q6=b）：满额距离由 64 格放宽到 `FULL_DETAIL_DISTANCE = 96` 格，随后仍是 0.4 / 0.1 / 0 三档。
- **火星与火柱同源**：控制器每 tick 为每个采样点算一次种子、记在 `Column` 上，渲染与发射都读同一个值，避免两处各算一份导致火星脱离（接缝与舱盖共用该机制）。
- **跳变不插值**：换采样点/换向的那一 tick 把 `previous` 直接置为 `current`，喷口在新位置原地出现，而不是从旧位置滑过去。
- **确定性**：采样、方向、抖动全部由 seed 经整数混合器（Murmur3 finalizer）导出，不使用 `RandomSource`，因此可复现、可自动测试。
- **预算同步上调**：接缝点从 6 到 12 后基础需求曾高于旧的单车上限 48，新点会被静默压掉；因此 `PARTICLES_PER_VEHICLE` 48 → 96、`PARTICLES_PER_TICK` 160 → 320。权重表从控制器里的三元表达式提到 `RVP_WreckCookoffBudget.weightOf(kind)`，发射与需求估算共用一张表。

### 2026-10-06 取消炮口火星 + 舱盖火星改为 3 点 / 30° 圆锥

**行为变更（用户定版）**：

1. **取消炮口喷火星**：`WEIGHT_MUZZLE` 由 4 改为 **0**，`emit()` 直接跳过 `Kind.MUZZLE`。炮口只保留轴向火柱，因此：
   - 炮口从"参与火星的出口"改为独立的 `MuzzleAnchor`（`Discovery.muzzles()`），不再进 `Column`/火星预算；
   - `resolveMuzzle()` 用本体 `aimContext` 给出与开火一致的出膛点与炮管轴向；
   - 火柱渲染改为统一的 `RenderColumn` 视图（舱盖/接缝出口 vs 炮口各一个实现），炮口柱长取 `settings.length`；
   - 由测试锚定"炮口权重为 0 且不再占用火星预算"。
2. **舱盖 3 点火星采样 + 30° 圆锥**：每个舱盖登记 `HATCH_POINTS_PER_HATCH = 3` 个采样点（沿 OBB 局部 X 轴等分错开 -0.22/0/+0.22 半宽）；只有中心采样点（`HATCH_COLUMN_SAMPLE_INDEX`）绘制该舱盖唯一的一根火柱，三个点共同参与**火星**方向采样。火星方向由 `RVP_WreckCookoffGeometry.hatchConeDirection` 在**世界 Y 轴** 30° 圆锥内随机采样，单点停留 3～12 tick 后换向。
   - **锥内均匀性**：半径用 `sinθ = √u · sin30°`（圆盘均匀采样的开方分布）。若直接对极角线性取样，方向会向锥轴聚集，火星会"直上直下一根"而不是散开成锥；测试按方位角分箱验证各箱计数均衡。
   - 采样点序号参与方向种子（`samplingSeed * 31 + sampleIndex`），因此同一舱盖的 3 个火星采样点不会同向；火柱仍只取中心采样点。
   - **柱向与火星锥向解耦**（2026-10-06 修正）：`RenderColumn` 新增 `columnDirection()`/`previousColumnDirection()`，舱盖恒返回世界向上，只有火星读圆锥方向。此前两者共用一个采样 Pose，导致舱盖高柱跟着随机锥角歪掉——这是用户要求的"柱固定向上、只有火星呈锥形散开"。由测试 `hatchColumnStaysWorldUpWhileOnlySparksUseTheCone` 锚定。
3. **分段换点时长统一为 3～12 tick**：`SAMPLE_BURST_MIN/MAX_TICKS`（原 3～6），舱盖与接缝共用同一套段号规则，各点仍按 `sampleIndex × 3` 错开相位。
4. **接缝轮廓口径定版**：用户选 (a) 保持炮塔最大 OBB 的矩形轮廓，不做 cube 并集或真实底缘点集轮廓；接缝方位分布问题（按弧长等分导致的 9～15 倍角度不均）已在上一轮修复并由用户实机确认"已均匀绕一圈"。

## 4. 性能预算

| 项目 | 当前规则 |
| --- | --- |
| 粒子全局上限 | 320 次生成尝试/tick（2026-10-06 由 160 上调） |
| 粒子单车上限 | 96 次生成尝试/tick（2026-10-06 由 48 上调） |
| 出口权重 | 舱盖 10 : 接缝 10 : 炮口 0（炮口 2026-10-06 取消火星）；两类同时存在时权重之和为单车基础需求 |
| 距离倍率 | ≤96 格 1；≤128 格 0.4；≤256 格 0.1；更远 0（满额距离 2026-10-06 由 64 放宽到 96） |
| 粒子选项倍率 | 全部 1；减少 0.5；最少 0.2 |
| 全局火柱上限 | 96 个出口，各车轮流分配 |
| 远处简化 | >128 格每车最多前 4 个出口，每柱减少为 6 段 |

**为什么曾上调**：每座炮塔的接缝采样点由 6 增到 12（双炮塔车接缝出口达 24 个），而单车上限 48 已低于"每出口一枚/tick"的基础需求，新加的点会被预算静默压回。现在单车 96、全局 320，且取消炮口火星使基础需求不再包含炮口。**注意**：当前双炮塔车基础需求 = 10（舱盖）+ 10（接缝）= 20，已远低于单车上限 96，因此满配车的火星密度不再受单车额度限制，而是由"每出口每轮一枚"决定——若 12×2 个接缝点全部同屏，实际发出量会接近基础需求×轮数的上限。这是有意保留的口径，若实机过密可下调 `SEAM_POINTS_PER_TURRET` 或 `PARTICLES_PER_VEHICLE`。

“生成尝试”是**本功能自己的**计数上限，不等于屏幕实际粒子数。粒子选项倍率只作用于生成次数；火星不经原版 `addParticle`，因此不受原版 32 格距离裁剪与 `MINIMAL` 丢弃约束（详见 §3 的可见性边界）。粒子设置不会取消自绘火柱。全亮材质也不等于动态照亮周围方块。

**2026-10-06 火星物理改动后的预算影响**：距离倍率与粒子选项倍率未变，仅把每次生成的原版 FLAME 换成 `RVP_WreckSparkParticle`。变化在于火星寿命由原版 FLAME 的 4～44 tick 变为 24～80 tick（平均约 52），加上本次额度翻倍，同屏存活火星数约为改动前的 2 倍多；位移复用基类 `Particle.move`（一次扫掠求交，与原版 FLAME 同量级），另加最多 3 次落地弹跳的速度反射。实机 1/5/10 台残骸的帧耗时是本次最需要复核的一项。

`RVP_WreckSmokeEmitter` 是殉燃的唯一实体遍历接入点。它先调用 `begin`，再在同一轮已有的 `entitiesForRendering()` 遍历中把普通 `AbstractVehicle` 交给 `consider`，最后调用 `end` 完成预算和发射；因此殉燃没有再增加一次全世界实体扫描。该遍历中的 `VehiclePart` 会被排除，脱落部件继续使用本体/既有击毁烟逻辑。

### 8.4 挂点解析与姿态数据结构

`RVP_WreckCookoffResolver` 先建立一次 `Discovery`，之后由控制器缓存，避免每帧重复扫描结构：

1. 遍历载具现有 `PartUnit`，跳过已脱离部件；部件 ID 或结构骨名称包含 `hatch`、`cupola`、`舱盖` 时，取该部件最大有效 OBB，并为每个舱盖创建 3 个火星 `Anchor`，其中中心 `Anchor` 才是该舱盖的火柱代表。
2. 从具有结构组、炮塔转向组且包含可识别机炮/火炮武器的 `WeaponUnit` 中按 OBB 体积排序，最多取 2 座炮塔；每座炮塔创建 12 个 `SEAM` `Anchor`，最多收集 4 个真实炮口 `MuzzleAnchor`。
3. 若没有独立舱盖，则使用首座有效炮塔顶部作为 1 个近似舱盖火柱；若连炮塔也没有，则使用主车体 OBB 顶部保底生成 1 个近似舱盖火柱。没有有效炮口结构时不伪造车体中心炮口。
4. `Anchor` 保存出口类别、OBB、局部坐标/宽度、所属部件和采样序号；`MuzzleAnchor` 单独保存武器和炮口序号。炮口被拆出，是因为它只画火柱、不参加火星预算。
5. 控制器每 tick 由 `samplingSeed(worldTick, sampleIndex)` 生成确定性采样种子。`Resolver.resolve` 生成舱盖/接缝 `Pose`，`resolveMuzzle` 调用本体 `WeaponUnit.aimContext(Bolt)` 获取真实出弹起点和轴向。部件脱离或炮口失效时返回 `null`，对应出口停止。

控制器的 `Column` 同时保存前后两帧姿态，使渲染器能在正常移动时插值；换采样点的 tick 会把 `previous` 直接置为新 `Pose`，避免喷口从旧位置滑向新位置。舱盖的火星方向和火柱方向通过 `RenderColumn.columnDirection()` 分开：三个火星采样点走世界 Y 轴 30° 圆锥，舱盖火柱仍由每个舱盖的中心代表点提供且固定世界向上；接缝只保留火星，炮口只保留本体轴向火柱。

### 8.5 预算、渲染和粒子之间的边界

- `end()` 只为当前有效的舱盖/接缝出口申请火星额度；炮口虽存在于 `Kind` 枚举和渲染视图中，但 `WEIGHT_MUZZLE = 0`，不会进入火星发射预算。
- 火星的生成位置沿当前出口柱身随机取点，速度沿当前采样方向；真正的下坠和触地响应完全在 `RVP_WreckSparkParticle.tick()` 中完成，不由渲染器模拟。
- 火柱由 `RVP_WreckCookoffRenderer` 单独绘制：舱盖使用 `height`，炮口使用 `length`，接缝不绘柱；渲染器按距离把火柱分为 12 段或 6 段，并受 `MAX_COLUMNS` 控制。`growthTicks` 控制从小到完整尺寸，`shrinkTicks` 控制从结束时尺寸平滑收缩到零。
- 残骸在当前 tick 不再被追踪时，控制器保留最后姿态进入收缩阶段；收缩阶段不再生成新的火星，只保留逐渐缩短、变窄的火柱，完成后移除实例。
- 火柱顶点在 CPU 侧只做 `worldPosition - cameraPosition`，交给当前 `ModelView` 完成一次视图变换；这正是 `RVP_WreckCookoffViewTransformTest` 所覆盖的相机旋转/大世界坐标边界。
- `RVP_WreckSparkParticle` 带 `@OnlyIn(Dist.CLIENT)`，调用方仅位于客户端视觉包；没有把客户端粒子类型引入公共或服务端注册路径。

### 2026-09-29 舱盖火柱数量修正

- `HATCH_POINTS_PER_HATCH = 3` 只表示每个舱盖的火星采样点，不再等于火柱数量。
- `HATCH_COLUMN_SAMPLE_INDEX` 选取每个舱盖的中心采样点作为唯一火柱代表，因此火柱数量为“可识别舱盖数”，没有可识别舱盖时由炮塔顶部或车体顶部保底为 1 根。
- 舱盖发现改为独立维护 `hatchCount`，不再用已经展开后的采样点总数限制舱盖数量；因此多个真实舱盖不会因第一个舱盖生成 3 个采样点而被错误截断。
- `/rvpcookoff preview start` 现在分别显示“舱盖火柱”和“火星采样点”，避免把 3 个火星采样点误读成 3 根舱盖火柱。

### 2026-09-29 火柱增长与结束收缩

- 每个 `Instance` 在首次被客户端观察到时记录 `startedAt`，火柱生命周期倍率由 0 通过平滑插值增长到 1；该倍率同时缩放火柱长度和宽度。
- 残骸被移除、离开 256 格追踪范围、恢复非击毁状态或结束预览后，实例不立即删除，而是记录 `endingAt` 和结束时的当前倍率，按 `shrinkTicks` 平滑收缩到 0。
- 收缩倍率使用“结束时当前倍率 ×（1 - 平滑曲线）”，起点保持结束时的现有尺寸，随后单调变小；不能复用增长曲线，否则会出现重新升起后消失的错误观感。
- 收缩阶段停止火星发射，只保留火柱视觉；实例重新被观察到时取消尚未完成的收缩，不重复播放一次新的增长动画。
- 游戏内调参：`/rvpcookoff set grow <tick>` 修改增长时长，`/rvpcookoff set shrink <tick>` 修改收缩时长；默认分别为 10 tick 和 20 tick，范围均为 1～120 tick。
