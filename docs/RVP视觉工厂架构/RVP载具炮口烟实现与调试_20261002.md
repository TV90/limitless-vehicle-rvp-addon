# RVP 载具炮口烟实现与调试

> 记录时间：2026-10-02。本文记录 `limitless-vehicle-rvp-addon` 当前载具炮口烟的实现、数据判定、限频规则、T-90M 125 mm 主炮适配与验证结果。代码只位于本 Submod；`ywzj_vehicle` 本体源码未修改。

## 1. 功能边界

炮口烟是载具**成功开火后的客户端视觉**，不属于爆炸视觉工厂、整车击毁烟、损坏部件烟或烟雾弹系统。

- 只消费本体已经确认成功的 `VehicleFireEvent.Post`。
- 不创建服务端实体，不增加网络包，不写入服务端状态。
- 小口径旧路径仍从成功开火事件立即生成，单枚粒子寿命随机为 **15～25 tick**。
- 45 mm 及以上火炮由独立延迟管理器处理：开火后等待 **10～20 tick**，再从**实时炮口位置**持续 **15～20 tick**，每 **1 tick** 调用一次 `RVP_MchrSmokeParticle.ofWhiteMuzzle`；每枚白烟寿命为 **40～60 tick**。
- 当前 `effects_data.caliber` 语义为**弹体口径**：`<45 mm` 走灰色即时烟，`>=45 mm` 走白色延迟烟；两条路径互斥。`effects_data.tracer_caliber` 只供曳光宽度/弹体视觉口径使用。
- 两条路径均向世界竖直方向上浮；延迟白烟默认沿当前炮管出膛方向以 **0.12～0.15 格/tick** 的小初速度逸出，并叠加水平扰动。
- 复用已有 `assets/ywzj_rvp/textures/boom/smoke.png`，本次实现没有覆盖或新增贴图资源。

## 2. 调用链

```text
VehicleFireEvent.Post（客户端）
  → RVP_MuzzleSmokeEmitter
      → RVP_WeaponResolveHelper.unwrap
      → 读取类型化武器数据与弹药类别
      → WeaponUnit.aimContext(s) 取得实际炮口位置和方向
      → RVP_MchrSmokeParticle.ofMuzzle
      → Minecraft.particleEngine.add

VehicleFireEvent.Post（客户端，大口径）
  → RVP_DelayedMuzzleSmokeEmitter
      → 保存武器站与炮口骨索引
      → 每次生成时重新解析实时炮口坐标与方向
      → 客户端 Tick 延迟队列
      → 每 1 tick 调用 RVP_MchrSmokeParticle.ofWhiteMuzzle
      → Minecraft.particleEngine.add
```

小口径入口为 `org.ywzj.rvp.client.visual.vehicle.RVP_MuzzleSmokeEmitter`，大口径入口为独立的
`org.ywzj.rvp.client.visual.vehicle.RVP_DelayedMuzzleSmokeEmitter`；两者均通过 Forge 客户端事件总线订阅，业务逻辑位于普通客户端辅助类，没有新增 Mixin。

## 3. 武器与口径判定

### 3.1 通用类型筛选

开火事件中的武器可能被本体 `VehicleWeaponAgent` 或 `VehicleMultiWeapons` 包装。入口先调用本项目 `RVP_WeaponResolveHelper.unwrap`，取得实际弹种，再按数据类型处理：

- RVP 武器只接受 `weapon_kind=MACHINEGUN` 作为炮口烟候选。
- 本体武器只接受 `VehicleCannonWeaponData`。
- 不使用 `weaponId.getPath().equals("...")` 等武器 ID 或路径名分支。

### 3.2 45 mm 规则

两条路径均对普通 RVP 机枪/机炮弹读取 `effects_data.caliber`，按以下边界互斥分档：

```text
0 < caliber < 45.0 mm
```

烟团尺寸使用次线性平方根映射：

```text
particleSize = 2.0 × clamp(sqrt(caliber / 7.62), 0.8, 2.5)
```

因此 7.62 mm 的基准尺寸为 2.0，尺寸上限为 5.0。非法或非正口径仅作为尺寸计算的 7.62 mm 回退值，不会绕过小口径路径的 45 mm 生成门槛。

大口径延迟路径使用 `caliber >= 45.0 mm`；大口径有效口径至少按 45 mm 参与尺寸映射。

### 3.3 RVP `caliber` 与 `tracer_caliber` 的消费分工

RVP 的 `effects_data.caliber` 当前表示**弹体口径**。炮口烟与殉燃炮口喷火都直接按这个数值判断，弹药类型不能绕过 45 mm 边界；不依赖具体武器 ID，也不需要修改载具包 JSON。

`effects_data.tracer_caliber` 是独立的曳光口径/弹体视觉口径，仅在 RVP 弹体 Renderer 计算曳光宽度时生效；缺省时回退到 `caliber`，再回退到 7.62 mm。

- 炮口烟：`0 < caliber < 45 mm` 为灰色即时烟，`caliber >= 45 mm` 为白色延迟烟。
- 曳光宽度：使用 `tracer_caliber`；曳光长度继续使用 `tracer_length_scale`。
- 殉燃炮口喷火：仅 `caliber >= 45 mm` 的弹道火炮出口保留；45 mm 以下即使弹药类别为 `AUTO_CANNON` 或 `ARTILLERY` 也不喷火。

## 4. T-90M 125 mm 主炮数据适配

T-90M 主炮使用的以下 RVP 弹种均存在相同数据语义：

```text
type                    = rvp:machinegun
reload.ammo             = ywzj_vehicle:ammo_artillery
effects_data.caliber    = 45.0 或更高
```

当 `effects_data.caliber` 达到 45 mm 时，弹种进入白烟延迟路径；若配置值低于 45 mm，则按弹体口径语义走灰色即时烟，且不会触发殉燃炮口喷火。

同轴 `mbt_762` 等非火炮弹药仍由旧的小口径路径按自身口径即时生成炮口烟。

## 5. 炮口定位与每炮口限频

- `RIPPLE` 使用本体当前 `Bolt` 索引和 `aimContext()`，只处理当前轮射炮口。
- `SALVO` / `FULL_SALVO` 使用本体 `aimContexts()`，按 `bolts` 顺序处理齐射炮口。
- 限频键为“载具对象 + 武器站对象 + 武器站内炮口索引”。
- 同一载具的同一炮口在同一客户端游戏 tick 最多生成 1 个炮口烟。
- 同一载具的不同炮口互不限流，因此齐射时每个炮口都可以各生成 1 个。
- 限频表使用载具弱引用，载具卸载后不会永久保留状态。
- 距离客户端相机超过 256 格时跳过生成，避免绕过粒子引擎裁剪产生无效开销。
- 大口径延迟任务保存武器站与炮口骨索引，每次生成重新读取炮塔/载具变换；切换世界、离开游戏或队列超过 512 条时清理/丢弃最早任务。

## 6. 粒子与资源

小口径炮口烟复用 `RVP_MchrSmokeParticle.ofMuzzle`；大口径延迟烟使用独立的
`RVP_MchrSmokeParticle.ofWhiteMuzzle`。两者均使用 `smoke.png` 的 8 帧动画和深度只测不写的渲染类型，避免半透明烟团写入深度后遮挡载具模型。

## 8. 实机回归清单

- T-90M 使用 3BM59、3OF26、3BK18M 开火：延迟 10～20 tick 后生成白烟，每 1 tick 一枚，持续 15～20 tick。
- T-90M 同轴 `mbt_762` 开火：按 11.43 mm 小口径规则生成炮口烟。
- 同一炮口连续开火：同一 tick 不超过 1 个粒子。
- 同一载具多个炮口齐射：每个炮口同一 tick 最多 1 个粒子，互不误限流。
- 炮塔旋转、俯仰或载具移动后：延迟烟应从当时的实时炮口位置生成，而不是开火点。
- 检查小口径 15～25 tick、大口径白烟 40～60 tick 生命周期、上浮方向和口径尺寸差异。
- 使用 `/rvpmuzzlesmoke show/set/reset` 调整延迟、连续喷烟时长、单枚寿命和出膛方向初速度；初速度参数为 `axialSpeedMin` / `axialSpeedMax`，单位格/tick。
- 距离客户端相机超过 256 格时不生成。
