# RVP 视觉系统当前架构与击毁烟现状

> 记录时间：2026-09-30。依据本次工作区中的 Java、资源和载具包 JSON 编写，包含尚未提交的工作区改动；不代表某个已发布版本。本文是**实现现状快照**，新增视觉类型的详细步骤见同目录的 [开发指南](./RVP%20visual_effect_data视觉效果开发指南.md)。

## 1. 范围与结论

2026-09-29 增补：已新增独立的地面载具持续殉燃，复用击毁烟的客户端实体遍历，自动定位顶部/接缝/炮口，默认开启且无需逐车 JSON。详见 [自动殉燃实施与调试](./RVP地面载具自动殉燃实施与调试_20260929.md)。下文原有烟系统与爆炸工厂说明仍适用。

当前 RVP 同时有两种视觉入口：

| 入口 | 触发方式 | 是否经过 `visual_effect_data` 工厂 | 当前实现 |
| --- | --- | --- | --- |
| 弹体爆炸 | 服务端爆炸结算，单次 S2C 事件 | 是 | `rvp:thermobaric`、内置 `rvp:mchr_explosion` |
| 整车击毁后冒烟 | 客户端观察到已击毁载具，持续按 tick 发射 | 否 | 近处烟 + 长程烟；`/rvpwrecksmoke` 只调长程烟 |
| 未击毁载具的损坏部件冒烟 | 客户端按部件状态表和 OBB 轮询 | 否 | 黑烟、引擎瘫痪火焰；与整车击毁烟分流 |

`RVP_ClientVisualEffectDispatcher` 管理的是**单次爆炸视觉实例**。整车击毁烟直接进入客户端粒子引擎，由载具实体状态维持发射；它没有工厂注册类型、网络视觉事件或 `visual_effect_data` 配置。相关代码虽同在 `client.visual` 包中，生命周期并不由该 dispatcher 管理。

## 2. 爆炸视觉工厂调用链

```text
武器 detonate_data.visual_effect_data[]
  → RVP_VisualEffectData
  → RVP_BaseBullet 爆炸结算，构造 RVP_DetonationVisualContext
  → RVP_VisualEffects.publishDetonation
      → RVP_DefaultDetonationVisualResolver
      → RVP_VisualEffectEvent（不可变、双端安全）
  → RVP_NetworkVisualEventPublisher
  → S2CVisualEffectEvent（schema 1，同维度 NEAR 广播）
  → RVP_VisualEffectEndpoint（专服默认 NO_OP）
  → RVP_ClientVisualEffectDispatcher
      → 按 effect_type 选择工厂
      → RVP_ClientVisualEffect 实例
      → ClientTick END / AFTER_WEATHER / close
```

公共初始化在 `RVP_MOD.onCommonSetup` 安装网络发布端；客户端初始化在 `RVP_ClientBootstrap.onClientSetup` 安装消费端，并注册两个工厂。`S2CVisualEffectEvent.handle` 只转交公共 endpoint，不直接加载客户端类。`RVP_ClientVisualEffectDispatcher` 校验世界和维度，未知类型只警告一次，并把同时活动的实例限制为 24 个；超额时关闭最旧实例。世界退出、切换时由 `RVP_ClientVisualEvents` 清理实例。

事件携带效果类型、预设、规范化覆盖 JSON、维度、爆心、最终爆炸半径、视觉倍率与密度、持续时间、广播距离、随机种子、服务端开始时间及声音/闪光/震动许可。`preset_data` 在服务端深拷贝、排序并限制为 UTF-8 8 KiB；具体字段由对应客户端工厂解析。广播范围决定**哪些客户端收到事件**，不保证该范围内的每一格都实际绘制粒子。

## 3. 当前两种工厂

| 类型 | 来源与参数 | 客户端创建结果 | 生命周期 |
| --- | --- | --- | --- |
| `rvp:thermobaric` | 武器 `visual_effect_data[]`；`assets/rvp/visual_effects/thermobaric_standard.json` 与类型化 `preset_data` | `RVP_ThermobaricEffectFactory` 合并预设，创建 `RVP_ThermobaricEffectInstance` | 根据 `startGameTime` 补偿传输延迟；实例推进声音、屏幕反馈与世界几何，`renderThermal` 另绘入热成像缓冲；LOD 和粒子预算由温压类型自身控制 |
| `rvp:mchr_explosion` | 无自定义视觉时由 `RVP_DefaultExplosionVisualService` 内置发布；按最终半径、武器类别和可选 `explosion_sound` 推导 | `RVP_DefaultExplosionEffectFactory` 立即向粒子引擎加入烟、火光、火星、方块碎屑等 | 返回的轻量实例主要维持声速延迟的近/远音；粒子加入引擎后不再由 dispatcher 逐枚管理 |

温压资源预设通过 `RVP_ThermobaricPresetManager` 在资源重载时更新，新爆炸采用最新快照。`experimental.dynamic_particle_budget` 默认关闭，当前仅温压效果解释这个开关。现有载具包可见的温压配置见 `limitless_vehicle/rvp/data/rvp/weapons/9k720_9m723.json`、`bmpt_9m120_f.json`；`_backup` 下的文件不应视为运行配置。

### 爆炸视觉的抑制关系

1. HBM 特效已生效时，弹体跳过通用视觉发布及内置 MCHR 默认视觉，避免叠加。
2. 一条启用且有效的 `visual_effect_data` 成功由服务端发布后，`publishedCount > 0` 会屏蔽内置 MCHR 默认视觉；其 `suppress_native_explosion_effect` 决定是否抑制本体普通爆炸视觉。
3. `suppress_rvp_default_explosion=true` 可单独阻止 MCHR 默认视觉，即使该条目没有启用 `effect_type`；本体视觉是否显示仍由其它抑制条件决定。
4. 没有上述条件时，服务端发布一次 `rvp:mchr_explosion`，并抑制本体普通爆炸视觉。抑制窗口只作用于本体视觉包，不改伤害或地形结算。

这里的“成功发布”指服务端发送调用没有抛异常，**不表示客户端已注册对应工厂或确实绘制成功**。客户端若缺少该 `effect_type`，dispatcher 会安全忽略，但服务端已经做出的抑制判定不会回滚；自定义类型需要同步注册客户端工厂并实机验证。

## 4. 整车击毁烟：独立的客户端持续效果

```text
AbstractVehicle.tickParticle
  → client 数组中的 AbstractVehicleClientMixin：已击毁整车取消本体烟，保留水面气泡

ClientTick END
  → RVP_WreckSmokeEmitter：筛选仍被客户端追踪、已击毁且未移除的 AbstractVehicle
      → 主结构 OBB，缺失时回退实体 AABB
      → 近处：每 5 tick，2～4 枚，寿命 42～65 tick
      → 长程：默认每 10 tick，同一生成点的一枚核心 + 一枚错位外层
  → Minecraft.particleEngine.add(RVP_WreckSmokeParticle)
```

发射器明确排除 `VehiclePart`；脱落残件继续使用本体路径。`RVP_DamagedPartSmokeEmitter` 则排除已击毁整车，只对未击毁载具的损坏部件冒烟。服务端 `RVP_LinkedUavEventHandler` 按 common 配置执行残骸提前清除，配置文件为 `config/ywzj_rvp-common.toml`：

```toml
[vehicleLifecycle]
	wreckLifetimeSeconds = 60
```

`wreckLifetimeSeconds` 单位为秒，默认值为 **60**，`0` 表示在检测到残骸后立即清除。由于本体 `AbstractVehicle` 仍有不可修改的 60 秒自动销毁上限，当前 RVP 配置可以缩短实际残骸时间，但不能在不修改本体逻辑的情况下延长到超过 60 秒。长程烟粒子默认寿命 **460 tick**（约 23 秒）；它在残骸消失前仍持续新生，所以最后生成的烟可能在残骸移除后继续飘动。

近处烟使用 `assets/ywzj_rvp/textures/wreck_smoke/` 下三张 16 帧贴图。长程核心与外层共用 `assets/ywzj_rvp/textures/boom/smoke.png` 的 8 帧横条；先从第 3 帧成团到第 1 帧，成熟后固定第 1 帧，仅在寿命末段降低透明度，不播放末段消散帧。贴图以粒子渲染类型进行半透明绘制，深度只测不写。

长程烟高度以粒子出生 Y 为基准；目标上升速度、东向基础风、随高度增强的风、随高度放大的面片共同形成拖尾。东为世界 `+X`。默认 `updraft=0.25`、`lifetime=460` 是当前代码配置，**100 格上升是设计目标，实际到达高度会受初速度与逐 tick 收敛影响**，需以游戏内观察为准。发射器的 `EMIT_RANGE=1536` 只是额外距离门槛；真实可见性还受载具实体追踪、粒子引擎和客户端渲染范围约束。

## 5. `/rvpwrecksmoke` 当前调试入口

该指令在 `RegisterClientCommandsEvent` 注册，只影响本地客户端当前会话；重启后恢复代码默认值，不写 JSON、不向服务端同步。它修改的是**长程击毁烟**，近处烟和脱落残件不随之改变。

```text
/rvpwrecksmoke show
/rvpwrecksmoke set <参数> <数值>
/rvpwrecksmoke reset [参数]
/rvpwrecksmoke preview start
/rvpwrecksmoke preview stop
```

`show` 列出当前值与默认值；`set` 校验范围和整数要求；`reset` 可恢复单项或全部。`preview start` 在准星命中位置开启最长 1200 tick 的独立长程烟预览，未命中时取视线前方 6 格；`preview stop` 仅停止新粒子，已发射粒子自然结束。退出或切换世界时预览会清理。

| 参数 | 当前代码默认值 | 单位/意义 | 生效对象 |
| --- | ---: | --- | --- |
| `emitPeriod` | 10 | tick，每轮一组核心和外层 | 后续发射 |
| `lifetime` | 460 | tick，单枚粒子寿命 | 新粒子 |
| `horizontalOffset` | 1.0 | 格，单生成点水平错相半径 | 后续发射 |
| `phasePeriod` | 80 | tick，水平位置完成一周的周期 | 后续发射 |
| `zPhase` | 90 | 度，Z 相对 X 的相位 | 后续发射 |
| `sizeScale` | 1.75 | 核心及外层初始尺寸倍率 | 新粒子 |
| `sizeGain` | 0.05 | 每升高一格增加的初始尺寸比例 | 存活中的长程烟 |
| `updraft` | 0.25 | 格/tick，目标上升速度 | 存活中的长程烟 |
| `eastWind` | 0.057 | 格/tick，出生高度的东向基础风 | 存活中的长程烟 |
| `windGain` | 0.04 | 每格东向风增益比例 | 存活中的长程烟 |
| `sway` | 0.0005 | 格/tick²，横向微摆增量 | 存活中的长程烟 |
| `formationTicks` | 48 | tick，成团动画时长 | 存活中的长程烟 |
| `fadeStart` | 0.85 | 寿命比例，从此开始变淡 | 存活中的长程烟 |
| `outerSizeScale` | 1 | 外层相对随机尺寸的倍率 | 新粒子 |
| `coreAlphaScale` | 1 | 核心初始透明度倍率 | 新粒子 |
| `outerAlphaScale` | 1 | 外层初始透明度倍率 | 新粒子 |

参数范围以 `RVP_WreckSmokeDebugSettings.Parameter` 为准。例如 `/rvpwrecksmoke set windGain 0.05` 会影响正在飘升的长程烟；`/rvpwrecksmoke set lifetime 600` 只影响此后生成的烟。预览和真实残骸共用同一套参数，但预览模拟半径与高度固定为 2 格，并不等同于某台具体载具的主结构尺寸。

## 6. 扩展边界与验证

- 新增**单次爆炸视觉**时，优先复用公共事件、网络包、endpoint、dispatcher 和 Forge 生命周期事件；在客户端注册新 `effect_type` 工厂，单独解析其类型化预设。不要按武器 ID 分支，也不要为普通新视觉复制 S2C 包。
- 新增**持续依赖实体状态的效果**时，先判断能否按现有客户端实体与同步状态直接发射。当前击毁烟就是这种实现，不应在文档或配置中声称它已经是 `visual_effect_data` 工厂实例。
- 专服安全边界：公共、网络和服务端视觉类不直接依赖 `Minecraft` 或客户端粒子类；仅客户端 bootstrap 安装真实消费端。当前击毁烟本体行为拦截位于 mixin 配置的 `client` 数组，业务发射留在独立事件类。
- 资源写入、替换之前必须按根目录 `agents.md` 检查 mod 与载具包两处资源命名空间，并取得用户确认；本快照只读取资源，没有写入贴图。

本次文档依据工作区静态代码和既有资源；`./gradlew build` 在前一轮击毁烟指令实现后通过。本文未进行游戏内视觉回归，也未验证 1536 格实际可见距离或默认长程烟的真实最高点。后续实机建议分别检查：单机与远程服指令注册、近/远处烟层次、载具离开实体追踪范围后的停止发射、残骸清除后最后一批粒子的自然结束、温压与默认爆炸的互斥和专服启动。
