- 判断基线：进服/放车/开火不崩，日志无 mixin/ClassCast/运行时空指针异常

## 1. 通用测试方法

1. 单机（集成服务端）测试大多数功能；纯服务端逻辑（同步/持久化/扫描）用专用服务器验证。
2. 每项测试记录：功能名 → 操作步骤 → 实际结果 → 结论（通过/失败/降级）。
3. 失败时附 `logs\latest.log` 中该操作前后 20 行异常。
4. 重启客户端/服务端后再测下一轮，避免缓存影响。

## 4. 推荐执行顺序

按依赖链：基础 → 武器 → 锁定 → 挂架 → 炮手 → 防护 → 雷达

```
S1 → C1/C2 → S2-S6+C3（武器链路） → S7-S9+C4（切换/弹舱） → S10-S11（锁定）
   → S12-S13（组合挂架） → S14-S16+C5（炮手） → S17-S22+C6-C9（载具防护）
   → S23-S24+C10（雷达） → C11（ERA 动画回归） → C12（炮兵地图偏航优先）
```

## 5. 通过标准

- 双端启动无 mixin/ClassCast/运行时异常；
- 表内功能逐项通过或已确认永久降级；
- 结果在 `调试与修复规范.md` 功能丢失表对应行追加"实机验证通过"结论，闭环。
