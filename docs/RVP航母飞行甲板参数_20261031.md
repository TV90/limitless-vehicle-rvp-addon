# RVP 航母飞行甲板（`rvp_flight_deck`，2026-10-31）

> 给载具加一块"航母甲板"：载具停上去不掉、不被撞爆、跟着母舰走，但**不锁控制**，玩家随时能推油门起飞。
> 与 {@code RVP_HeliDockManager} 的锁定式着舰是两套独立机制，可共存。

## 一、参数

写在载具 JSON 顶层（与 `rvp_helipads` 同级），骨骼必须是**结构模型**（`rvp_structure_model` 指向的
`*.structure.json`）里的具名骨，该骨的 cube 顶面即停靠面。

```json
"rvp_flight_deck": {
  "bone": "deck_main",
  "friction": 0.35,
  "carry_linear": 1.0,
  "carry_angular": 1.0,
  "max_relative_speed": 0.4,
  "position_spring": 0.08,
  "immune_impact": true
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `bone` | 必填 | 甲板骨骼名；为空等于没配（不占 `isEnabled`） |
| `friction` | 0.35 | 水平速度向母舰速度收敛的每 tick 比例（0~1）。越大越"粘"，1 = 立刻同步 |
| `carry_linear` | 1.0 | 母舰线速度继承系数 |
| `carry_angular` | 1.0 | 母舰角速度继承系数（按 ω × r 给切向速度） |
| `max_relative_speed` | 0.4 | 与期望速度之差超过该值即解除停靠（格/tick）；这是"能起飞"的关键阈值 |
| `position_spring` | 0.08 | 相对位置回拉强度，0 = 只给速度不纠偏（转弯会整机滑出去） |
| `immune_impact` | true | 停靠期间免疫载具间动能碰撞伤害 |

## 二、行为

- **停靠判定**：脚底落在甲板顶面 `[-0.9, +1.2]` 格内、竖直射线命中朝上的甲板面，且附近有配了甲板的母舰。
- **速度耦合**：期望速度 = 母舰线速度 × `carry_linear` + 切向速度（`ω × r`）× `carry_angular`
  + 位置回拉；实际速度按 `friction` 向期望速度收敛。垂直分量直接跟母舰，甲板升降不会浮空/下陷。
- **起飞**：玩家推油门后与期望速度之差超过 `max_relative_speed`，立即解除停靠，之后完全由玩家控制。
- **撞击豁免**：`AbstractVehicle.impact` 在"本车是对方的甲板母舰"时直接 cancel（见第三节）。

## 三、实现落点

| 件 | 作用 |
|---|---|
| `RVP_VehicleExtendedConfigManager.FlightDeckConfig` | 参数解析（含"全空即 EMPTY"早退判定） |
| `flightdeck/RVP_FlightDeckManager` | 停靠判定、速度耦合、`deckOBBs()`、`isDockedOnDeck()` |
| `mixin/PhysicsEngineFlightDeckMixin` | **追加甲板 OBB 到 `getVehicleCollisionBoxes`**，绕过"只有 mainCubeOBB 才有物理接触" |
| `mixin/AbstractVehicleFlightDeckImpactMixin` | 停靠期间的动能伤害豁免 |
| `flightdeck/RVP_FlightDeckPlacement` | 右键生成物品把载具放到甲板顶面（纯 Forge 事件） |

甲板 OBB 用本体公共 API `OBB.getOBBsFromBone(bone, ship, namedBones)` 现算（直升机着舰同款），
因此母舰倾斜、转向都能跟上，不需要 `vehiclePartGroups`（那是 protected）。

**为什么能直接改速度**：本体 `PhysicsEngine:102-104` 每 tick 开头都会
`velocity = vehicle.getDeltaMovement()` 读回速度，所以 RVP 侧 `setDeltaMovement()` 会被下一 tick 采纳，
不需要碰物理内部字段，也不需要额外 mixin。

## 四、停靠判定（重要）

判定**不用 AABB**。轴对齐包围盒在甲板倾斜时会框住一大片空气，载具能"停"在悬空角落上——
这正是本体 `findVehicleSupport` 逐 OBB 求交的原因，这里照同一套做法：

1. 取载具 AABB 的脚底高度 `minY`，以及中心 + 四个内缩 30% 的采样点（防止机翼/履带探出板外时漏判）；
2. 每个采样点从 `minY + 1.2` 向 `minY - 0.9` 打一段竖直短射线；
3. 对甲板骨骼的**每个** OBB 求 `OBB#clip`；
4. 命中后取 `embeddingFace` 的法线，只有 `axis.y × sign > 0.25`（朝上的顶面）才算踩在甲板上。

射线长度同时约束了"高度接近"和"水平落在实心板面上"，所以倾斜甲板、缺口、边缘外都不会误判；
甲板底下的机库也不会被当成停靠面（底面法线朝下，被第 4 步过滤）。

## 五、右键把载具放到甲板上

原版 `VehicleSpawnItem.use` 有两道门会把甲板挡死：

1. `getPlayerPOVHitResult` 只打方块：射线穿过母舰，落到甲板下方（甚至几十格外的海床/空气），落点不在甲板上；
2. `VectorUtil.hitEntity` 查遮挡：射线必然先撞到母舰本体，命中实体就直接 `pass`。

所以站在航母上右键只会「手臂挥一下、什么都不发生」。

`flightdeck/RVP_FlightDeckPlacement` 监听 `PlayerInteractEvent.RightClickItem` 接管（Forge 在
`ItemStack#use` 开头就抛这个事件，取消即跳过物品原生 `use`，因此**不需要 mixin**）：

1. 视线射线长度 5.0 格，对**甲板骨骼的每个 OBB** 求 `OBB#clip`；
2. 只认 `axis.y × sign > 0.25` 的朝上顶面（从甲板下方、船体侧壁瞄过来不算）；
3. 取最近命中点作为生成位置（+0.02 格避共面抖动），**朝向用母舰艏向**，不用玩家朝向；
4. 遮挡仍然生效：别的载具（停着的飞机、另一艘船）挡在更近处就不放，避免把飞机塞进飞机里；
5. 生成后立刻 `RVP_FlightDeckManager.dockNow()` 登记停靠——否则新生载具会先走一 tick 物理，
   那一 tick 的相对速度足以触发上千点撞击伤害。

客户端不处理（原版客户端 `use` 只挥手臂、不生成实体），所以不存在两端各生成一次。

> 朝向若要改成跟随玩家，把 `construct` 的第 4 个参数从 `hit.ship().getYRot()` 换成 `player.getYRot()`。

## 六、为什么载具还要额外"回正"（2026-10-31 实测）

本体给**实体**和给**载具**找支撑走的是两套判据，差异很大：

| 对象 | 入口 | 判据 | 已经陷进去能否拉回 |
|---|---|---|---|
| 实体（人/生物） | `AbstractVehicle.support()` → `OBB.calculateMTV` | OBB 与 AABB 相交就算接触 | ✅ 能，按 MTV 推出来 |
| 载具 | `PhysicsEngine.findVehicleSupport` | `box.embeddingDepth(start) > 0.002` 直接 `continue` | ❌ 不能，没有回拉路径 |

甲板是 6.5 格厚的大板，落舰一 tick 就扎进去几厘米，此后每次查询都被这道 `0.002` 的闸门跳过，
载具只能一路沉穿整块板——实测表现就是**人站得住、飞机停不住**。

`RVP_FlightDeckManager.settleOnDeck()` 在 `tryDock` 与 `tickDocked` 里补一次回正：
用实体那条路同一个 `calculateMTV` 求最小平移量，只接受"向上且纵向占主导"的推出
（水平占主导说明擦着甲板边缘，仍交给本体物理），并把向下速度清零。

## 七、已知限制 / 待实测

- 角速度用**每 tick 偏航增量**（`getYRot() - yRotO`），只覆盖 Y 轴转向；横摇/纵摇没有对应继承。
- `rotateY` 的旋转符号是 MC 口径推导的，若实测发现甲板跟随方向反了，把 `rotateY` 里的 `-yaw` 改成 `+yaw`。
- 子载具在甲板上被豁免撞击，但**未被承载的载具**（比如两艘航母互相撞）仍按原公式结算。
- 每台载具通过 `VehicleMoveEvent` 检查一次，附近搜索半径 96 格；大舰队场景可考虑缓存母舰列表。
- `deckBounds()` 仍保留，但**只用于调试/粗筛**，不要拿它做停靠判定。
